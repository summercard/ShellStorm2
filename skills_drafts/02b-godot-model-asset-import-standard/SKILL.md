# 02b Godot 场景、关卡组件与设施导入规范

## 链路定位：02b 导入补丁阶段

作为 02 组件规划与 Blender 制作之后、03 正式 Godot 布局与 04 最终装配之前的导入补丁阶段执行。本次改名只为明确顺序，保留场景、关卡组件、基地设施等原适用范围与完整导入规范，不限定为战局房间。

新组件、未导入组件或源文件更新时，先确认源美术验收通过，再执行本规范；导出、正式重导入、稳定 PackedScene 包装、登记与组件验收全部通过后，才交给 03/04。复用组件必须另有可追溯的独立优化文件、优化执行记录与保真验收，且源/优化文件/运行版本、哈希和稳定引用一致，才允许记录复用核查、不重复优化与导出；只有旧 GLB 或旧导入验收不构成优化豁免。可选 Blender 参考布局可提前制作，但不得冒充导入验收。

组件更新仅更新稳定组件资产并核查接口兼容；禁止重生成正式房间来覆盖作者手改。00/03/04 必须将本阶段作为前置门禁，不得只在最终接入时补查。

## 适用边界

此 skill 处理场景、可拼接关卡组件和固定设施的运行时包装。固定设施可有交互，但其主体不应被角色拾取、装备、抛掷或作为手持物动画。

枪械和近战武器使用 `game-weapon-model-pipeline`，它定义手持锚点、武器局部动画和挂点；独立道具使用 `game-prop-model-pipeline`，它定义拾取、手持、掉落和物理包装。设施中出现的这些对象必须作为独立资产被引用，不能直接烘入设施 GLB。

把已经完成美术验收的模型转换为可独立加载、可替换、可登记、可回滚的 Godot 资产。先读取目标项目自己的资产文档和现有约定，再执行本规范；项目契约优先于通用默认值。

## 范围边界

- 负责导出、导入、坐标、比例、材质、场景封装、版本、引用、登记和验收。
- 不负责重新设计物件造型，不内置桌高、桌深、宽度或某个项目的一次性美术数值。
- 比例目标必须来自项目文档、角色参照、模块尺寸或用户明确要求，不能从旧场景缩放反推为永久规范。

## 标准流程

1. 阅读项目资产规范、目录命名、坐标轴、单位、版本、台账和验收入口；检查工作区已有修改，避免覆盖用户内容。
2. 从 Blender 的游戏输出集合导出，不从零散制作组件、展示集合或整屋场景直接导出。
3. 检查主体、自发光和语义独立附件。椅子、凳子、武器、可移动附件等需要独立控制的物件必须导出为独立资产。
4. 使用二进制 `.glb` 作为默认交换格式；保留 `.blend` 在 `source/`，GLB放在 `components/`，Godot包装场景放在 `runtime/`。
5. 统一单位、原点和正面方向。设施通常底面贴地、局部正面朝 `-Z`；武器通常以握把为原点、枪口朝 `-Z`。若项目另有契约，按项目执行并写入元数据。
6. 对所有场景组件执行下节“全组件优化与独立另存门禁”：从原始文件派生独立优化文件，仅在优化文件中处理冗余几何、面数、轴向转换、变换烘焙和三角化；保存并重新打开优化文件后才导出 GLB。原始文件及其外链源保持不变，导出前确认法线、切线、UV和材质索引。
7. 颜色贴图使用唯一渲染UV通道；色盘贴图采用最近邻采样、无损压缩并禁用MipMap。ShellStorm2所有场景与固定设施统一使用`res://assets/art/shared/palette/设施低亮多巴胺色盘_10x10_512.png`，GLB不得内嵌图片；Godot导入设置`gltf/embedded_image_handling=0`并通过`res://tools/asset_pipeline/scene_facility_shared_palette_post_import.gd`把全部材质绑定到该唯一资源。公共色盘`.png.import`必须保持`compress/mode=0`和`mipmaps/generate=false`，防止块压缩或MipMap在纯色色块内部制造网格、条纹和串色。承载这些参数的场景/设施`*.glb.import`和公共色盘自身的`.png.import`属于可复现导入契约，必须通过项目`.gitignore`白名单进入版本控制，不得仅留在本机缓存。设施通常不超过四个材质角色，武器通常不超过三个非自发光材质。
8. 为每个单位建立独立 PackedScene。根节点稳定，视觉模型置于明确的 `Visual` 或 `ImportedModel` 节点；碰撞、挂点、标签和交互脚本由包装场景拥有，不塞进GLB。
9. 组件 `components/` 与 `runtime/` 路径恒定，文件名与目录名不含版本号；重导只更新对应组件资产，保持稳定 PackedScene 引用及房间实例覆写。核查包装场景、关卡引用、代码映射与测试是否兼容，不把“同步引用”当成重生成正式房间布局的许可。几何、包络、原点、节点路径、碰撞和挂点接口变化须先做受影响房间核查。
10. 更新资产清单、资产台账、来源、版本、哈希、包围盒、方向、用途和状态；同步相关设计文档。
11. 运行 Godot 正式重新导入，然后执行结构验证、独立加载验证、比例与方向验证、材质验证和实际场景截图验证。
12. 报告原始文件与独立优化文件路径/版本/哈希、源不变核查、执行的优化操作、前后三角面数及减面率、保真对照、运行时引用（替换前后必须是同一稳定路径）、独立场景、尺寸、材质数、测试结果和回滚提交。

## 全组件优化与独立另存门禁（强制）

对本 Skill 范围内所有场景组件与固定设施执行，包括墙、地板、楼板、楼梯、栏杆、门墙、终端、工作台和基地设施；不得只对基地母版执行，不得只评估后跳过，也不得将三角化本身宣称为减面优化。以下是执行要求，不声明已有自动优化器或验证器实现。

### 原始文件保护与优化文件另存

1. 记录原始文件绝对路径、源版本与 SHA-256；源存在已授权但未保存的编辑时先确认其正式输入，不替用户保存或覆盖原始文件。
2. 按资产边界复制游戏输出集合到独立派生文件；Mesh、材质及待修改的数据在优化文件中独立化，不修改 Library Link 的外链母版、不回写原始文件、不做原始文件的重命名或覆盖。优化过程涉及的外链源同时记录修改前后哈希。
3. 另存持久的优化 `.blend`，明确使用 `optimized` 标识，绝对路径不得与原始文件相同。默认落在该资产源包的 `export/v###/<asset_id>_optimized_v###.blend`；沿用已登记的版本化 `export/v###/` 时可保留原派生命名，但清单须明确 `role=optimized`。优化文件不是临时文件，交付后必须保留，禁止写入稳定 `components/` 或 `runtime/`。
4. 在优化文件内完成下述优化与轴向/变换/三角化处理；先保存，再重新打开该优化文件，核对路径、版本、输出集合和实际几何，最后逐组件导出稳定 GLB。禁止从原始源直接导出，也禁止只在内存中优化、不落盘，或先导出再补存优化文件。可用一个明确资产包优化文件包含多组件，但每个组件必须有独立记录与 GLB，不以整屋优化文件替代模块化资产。
5. 完成后断言 `source_sha256_before == source_sha256_after`、全部受保护外链源哈希不变、`source_path != optimized_path`、优化文件存在且可重开。任一失败立即阻止导出/接入；不得自动覆盖原文件来修复。

### 必须执行的几何与面数优化

- 逐组件清理经确认的重复面、零面积面、孤立点/边和无效几何；仅在不破坏拓扑、UV、材质边界与硬边时合并重复顶点或溶解冗余共面细分。检查项无命中时记录零处理量，不伪造优化结果。
- 删除经可见性、投影和模块复用范围证明不会参与表现的内部/封闭面；**不得仅凭法线朝下就删除**。底面、背面、双面墙、悬挑和楼梯底部可能可见或参与阴影；用途不明的面保留并说明。
- 按组件轮廓与实际镜头距离减少冗余倒角段数、曲面分段和无贡献细分，必要时局部 Decimate；锁定拼接端带、门洞、锚点与焦点细节，禁止全库固定比例一刀切。不能破坏模块接口、尺寸、法线、PaletteUV、材质索引、自发光边界和阴影。
- 每件都执行适用的清理/简化操作并记录实际结果；预算来自项目规范或明确批准的逐组件目标，缺少预算不得编造数值或以“未超预算”为由跳过优化。没有可安全减少的几何时，仍须执行完整清理流程、另存优化文件、记录零变化和证据，交由美术保真验收确认；不强求非零减面，也不允许只写“已低模”就通过。超预算且保真无法达标时报告阻塞，不擅自损坏造型。

### 统计、保真与交付证据

- 使用相同导出对象集合、相同轴向/单位、相同修改器求值口径，统计优化前后**三角面**，不得把原始 polygon 数与导出 triangle 数比较。单组件计数不乘房间实例数；实例成本可另列。
- 必须在优化/导出清单记录：`asset_id`、源/优化文件路径与版本、源前后哈希、优化文件哈希、执行操作与参数、`triangles_before`、`triangles_after`、`reduction_ratio`、预算及来源（未提供则明确空值）、保留面/零变化原因、保真验收结果和 GLB 哈希。减面率 `R = (T_before - T_after) / T_before`；`T_before = 0` 时记空值，不除零。导出/导入实际三角面数另核对，差异必须解释。
- 固定相机、光照、材质与尺度做优化前后对照，至少覆盖正面、背面、侧面及实际游戏视角；验证轮廓、开口、接缝、阴影和细节，按项目已有容差检查 bbox/原点/挂点，不编造通用容差。
- 缺少独立优化文件、源保护证据、实际优化记录、面数统计或保真验收时，02b 不通过，不得设置 `runtime_integrated=true` 或以旧验收自动复用。原始源更新时须重做对应优化输出；已有优化证据完整一致时只复用核查，不因多个房间引用而重复优化。

## ShellStorm2 基地母版的版本化导出

`source/art/blender/base_facility_layout/` 的基地母版必须按“当前文件即正式来源、后续最高版本优先”的规则导出。2026-09-12 的当前正式母版为 v026；后续创建 v027 或更高版本后，最高数值源自动成为新的正式来源。禁止将 v017、v021 或任何历史版本写死为后续导入的输入。当前运行资产可以是 v021-v025 的增量组合，但运行资产路径不再携带版本号，账本与导出清单必须记录每件资产实际采用的源版本与当前母版来源。

1. 在 `source/` 中解析 `base_facility_runtime_layout_hq_v###.blend`，默认选择数值最高的版本；只有用户明确指定历史版本时才允许覆盖此选择。
2. 为选中的源版本建立 `export/v###/`。派生文件必须与源版本一致，例如 v021 的派生文件只能落在 `export/v021/`，并采用 `base_facility_runtime_layout_hq-v021-<scope>.blend` 命名。
3. 只复制授权资产包内的 `02_游戏输出_整合模型`。制作组件、展示相机、灯光、整屋母版和空集合不得进入派生文件或 GLB。
4. 在另存的派生优化 Blend 内执行“全组件优化与独立另存门禁”；删除已证实不可见且不参与必要投影的冗余面，世界空间法线朝下仅作为检查候选，不能作为自动删除判据。保留法线/材质索引/PaletteUV/世界摆放。任何额外 Decimate 必须按资产包预算显式启用并写入清单；不得使用全局固定比例损伤文字、工具或焦点轮廓。
5. 先保存派生 Blend，再重新打开该 `export/v###` 文件导出 GLB。禁止从可维护源 Blend 直接导出，也禁止导出后才保存派生文件。
6. 每个 GLB 更新其既定稳定路径（不含版本号），不派生组件版本副本；源版本递增只发生在 `source/` 与 `export/v###/`，不据此删除或重建正式总装配/房间 TSCN。组件碰撞由 Prefab 拥有，依据优化输出核查；几何或碰撞包络变化时按授权调整组件碰撞并做影响验证，不能盲目沿用旧包络或整包重生清掉组件接口。
7. 在导出清单记录：源 Blend 路径与 SHA-256、派生 Blend 路径、资产包键和中文集合名、删除朝下三角面数、优化前后面数、GLB 路径与 SHA-256、包围盒、正面方向、碰撞策略及 Godot 引用。
8. Godot 阶段只能消费该导出清单所列 GLB：定点更新独立组件 PackedScene 与资产台账，检查总装配仍引用同一路径。不得重生成正式房间清掉实例覆写。完成正式重导入和运行测试后，才可把 Blender 资产包的 `exported` 与 `runtime_integrated` 标为真。

基地地板视觉与剩余设施可以使用不同的 `<scope>` 派生文件，例如 `floor_visuals` 与 `remaining_facilities`，但二者必须共享相同的源版本号和导出目录。

## 模块化建筑与玩法包装

- 一组相接的墙、楼板、楼梯、门和栏杆必须先声明高度与接口契约，再逐个建立独立GLB和PackedScene。关卡布局只实例化包装场景，不直接实例化裸GLB。
- 可见踏步只负责表现；包装场景负责连续斜坡、平台承重和栏杆阻挡。所有碰撞节点跟随包装根移动，根缩放保持1。
- 改变平台高度时同时验证楼梯起点、落地平台、终点、外梯到目标楼层的高差、栏杆缺口和完整视觉包络。不得把单段旧碰撞复制为不完整的新高度碰撞。
- 低净高结构应使用项目既有镜头碰撞/净空标记，不修改玩家摄像机通用规则来迁就单件模型。
- 建筑视觉默认 `cast_shadow=ON` 并接受光照；导入后检查GLB网格、包装补充网格和关卡实例三层均未关闭投影。
- 楼层、房间、安全区和存档位置判定属于运行时空间逻辑，不得依赖某扇门或某条固定路线的触发器。模型替换不能改变这些功能接口。

## Prefab资产台账最小契约

每个正式PackedScene至少登记：资产ID、类别、显示名、Prefab路径、视觉GLB路径、功能脚本路径（纯表现可空）、碰撞开关与方式、版本、源Blend、使用场景和状态。优化前后三角面数、实际优化操作、原始源不变证据与独立优化文件路径/哈希必须记录于优化/导出清单；台账不必新增面数列，但须能追溯该清单与优化文件。替换流程必须是：覆盖既定路径 GLB → 重新导入 → 包装场景与关卡引用保持不变 → 关卡验证 → 台账与文档同步。这里的「台账」是**该资产所属域的分账本**（`assets/registry/ledgers/`，路径经 `assets/registry/ledger_index.json` 解析），不是总目录 —— 见文末「账本落位」。

## 目录与命名默认值

```text
assets/art/<类别>/
├─ source/<资产名>/<资产名>_source_v###.blend        ← 原始制作文件，优化不得改写
├─ source/<资产名>/export/v###/<资产名>_optimized_v###.blend  ← 独立另存、持久保留的优化文件
├─ components/<资产名>/<资产名>_visual_<视角>.glb      ← 稳定路径，替换即覆盖
└─ runtime/<资产名>/<资产名>_root_<视角>.tscn          ← 稳定路径，替换即覆盖
```

- `components/` 与 `runtime/` 内不得出现版本号（文件名与目录名皆然）；`v###` 只允许出现在 `source/` 与已登记的优化派生 `export/v###/`（含基地母版）。
- 环境使用 `env_`，道具和设施使用 `prp_`，角色使用 `chr_`，敌人使用 `enm_`，武器使用 `wpn_`。
- 文件名使用英文稳定ID；Godot节点名、资产显示名和编辑器集合名可以使用中文。
- 一个资产单位对应一份GLB和一份包装场景。合集只用于预览，不得代替独立运行资产。

## 坐标、变换与比例

- 导出前记录DCC坐标、Godot坐标、单位和轴向转换。
- 设施：底面位于地面，原点可预测，正面朝项目约定方向。
- 武器：根原点、握把、枪口和通用挂点保持统一；禁止依赖玩家脚本逐枪修正旋转。
- 包装场景根节点保持 `scale = 1`。需要修改美术基准时回到源文件或明确记录导出比例，不把临时场景缩放伪装成正式尺寸。
- 使用包围盒和参照物验收，不只凭编辑器截图判断。

## 材质与贴图

- GLB内材质名称使用稳定语义角色，避免带Blender复制后缀。
- 主体和自发光模型独立；自发光强度保持颜色可读，不允许泛白。
- 场景/设施GLB必须不含`images/textures`；导入后的每个`BaseMaterial3D.albedo_texture`必须指向唯一公共色盘，采样为最近邻且不重复。`components/`及单件`source/`目录出现色盘PNG即判定失败。
- Godot导入后再次统计材质和表面数量，不能只相信Blender文件。

## PackedScene职责

- Blender 拥有源几何材质，GLB 只承载组件视觉，不承载整屋布局。
- 稳定组件包装场景负责根节点、视觉节点、碰撞、交互、标签、组件挂点和资产元数据。
- 正式房间/变体 TSCN 引用稳定组件 Prefab，拥有模块实例摆位/增删/启用、房间级挂点及灯光等参数，允许在 Godot 编辑；禁止把组件内部几何与碰撞展开复制为房间自有资产。
- 按房型 → 房间变体 → 具体房间管理；固定房型不禁止作者变体，可用 Godot 场景/明确资源路径表达，不强制每房 Blender 差异布局。战局链路 `block_id` 兼容 `battle/expedition`，组件 50/3/5 预算与实例数分开统计。
- 白盒约束原型尺寸、端口、连接和可走空间；JSON/Blender 实例清单仅用于初始化与追溯，不能自动回灌正式 TSCN。
- 当前静态生成器没有自动合并/手改保护。正式房间禁止未审查全量生成；任何回填先备份并输出差异、提出保留/回填计划，取得授权后仅改批准范围。
- 当前 `room_03/04` 仍需代码注册，轻量 override 仅 `remove` 已实现；不把新增通用注册、add/transform/enable JSON 解析写成完成状态。
- 纯装饰资产不得意外注册玩法组、添加交互碰撞或继承设施脚本。
- 设施主体不得夹带需要独立移动的座椅或附件；在清单中记录类似 `chair_embedded: false` 的可验证语义。

## 版本与引用替换

- 版本号只属于原始 `source/`、优化派生 `export/v###/`、源与优化清单、`asset_manifest.json`、资产台账版本列和 Prefab 根节点 `metadata/asset_version`；稳定 GLB/PackedScene 路径不带版本号。
- 组件替换 = 定点更新 `components/` 与组件 `runtime/` 的同路径同名文件；保留稳定组件引用和房间实例覆写，不覆盖正式房间 TSCN。几何、材质接口、原点、包络、节点路径、碰撞和挂点变化先列影响范围，再按授权适配并回归。正式房间自身布局编辑不受“组件替换路径不变”规则禁止。
- `.import` 与 `.uid` 留在原路径不重建；替换后必须确认清单与节点元数据已写入新的源版本号——GLB 不带版本号后，这三处是唯一的溯源入口。
- Godot 运行资产回滚由版本控制系统承担，运行目录不新增旧版副本。原始制作文件与独立优化文件属于两类必须并存的正式交付，不能当成 `*.bak_*` 或临时文件清理；原始源历史与优化派生版本按项目版本约定保留，Godot 侧路径仍保持稳定。

## Godot重新导入与验收

优先使用编辑器支持的正式导入命令：

```powershell
godot --headless --import --path "<项目目录>"
```

至少验证：

- 全组件优化门禁通过：独立优化文件可重开、源及外链源哈希不变、实际优化操作和前后三角面统计齐全、保真对照通过，GLB 明确从优化文件导出。
- GLB生成 `.import` 且无导入错误。
- 每个 PackedScene 可独立加载和实例化。
- 材质数量、贴图、色盘采样、自发光和透明度正确。
- 包围盒、底面、正面方向、握把或挂点符合项目契约。
- 语义独立附件确实不在主模型中，并能作为独立节点移动。
- 正式关卡引用同一稳定组件路径且外观已更新；逐项核对实例 Transform、增删、启用、灯光和自定义节点等手改未丢失，组件内部路径与挂点仍兼容；模型不重叠、不穿地。
- 自动测试通过，并生成至少一张资产墙或实际场景验收图。

需要精确检查表、清单字段和常见故障处理时，读取 [references/acceptance-checklist.md](references/acceptance-checklist.md)。

## 账本落位（分册化后，2026-09-18 起）

资产条目按**大类**路由到 `assets/registry/ledgers/` 下的分账本；域 / 大类 / 文件 / 分页的映射只由
`assets/registry/ledger_index.json` 声明（说明见 `assets/registry/README.md`）。
**不得写死账本文件名，也不得假定 `3D-*` 分页还在总目录里。**

```python
from ledger_registry import LedgerIndex            # scripts/ledger_registry.py
index = LedgerIndex.load(project_root)
index.path_for_category("<大类>")                  # -> 该大类的分账本路径
index.domain_for_sheet("3D-<分页>")                 # -> 拥有该分页的域
index.rewrite_ref("<旧引用>")                       # 旧 master#分页 -> 分账本#分页（幂等）
```

- 本 skill 涉及的分账本：按大类路由 —— 场景 / 场景道具 / 基地资产包 → 场景账本；道具 → 道具账本；角色 → 角色账本；敌人 → 敌人账本；武器 → 武器账本；特效 → 特效账本；UI / 音频 → 表现资源账本。

- 旧批次 `asset_manifest.json` / QA 脚本里的 `…美术资产台账_v001.xlsx#3D-<分页>` 是**产出记录**，不要批量重写；`resolve_ref()` 会解析到正确的分账本。
- 写完必查：`python scripts/check_asset_registry.py --ledger <域>`（结构 + 跨文件契约：每个 AssetID 全库恰好出现一次）。
