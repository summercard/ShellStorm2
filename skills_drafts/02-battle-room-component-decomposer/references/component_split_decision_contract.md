# 组件拆分判断契约

## 为什么需要这一步

实测（2026-09-26 远征01 四批 506 包）：采用「一个源对象一个包」的拆法后，683 个包只对应 149 个尺寸簇 ——
组件数虚高约 4 倍，命名全部带位置，互用性为 0。根因不是命名，是**缺一步「实例聚类」**。
本文件定义这一步的判据、产物与验收。

## 1. 归并键

```text
merge_key = (
  bounds_size_m 四舍五入到 3 位,
  ( origin_contract, front_axis 归一化, sorted(allowed_rotations_y_deg) ),
  sorted(material_roles),
  object_shape          # 对象构成：对象数 / 网格数 / 层级深度
)
```

**不含**：`source_world_origin_m`、任何方位词、槽位号、序号、所在房间。

### 1.1 几何指纹校验（包络相同 ≠ 几何相同）

归并键第 4 项必须是**几何指纹**，不能只写「对象构成」：

```text
fingerprint = sha256( sorted( round( 归一化顶点, 4 ) ) )
归一化      = 平移到 ( bbox x/y 中心, bbox z 底 )
```

先算指纹，再决定能否归并：

| 情况 | 判定 | 动作 |
|---|---|---|
| 尺寸同 ＋ 指纹同 | 真·同一件 | 直接归并；位置全部进实例清单 |
| 尺寸同 ＋ 指纹不同 | **不是同一件** | 按 `variant_axis/value/reason` 自动判：有意状态变体按 3–5 上限保留；无契约差异按相似度收敛到最多 3 个 |

实测（办公室 30×40 / `common_components/v004`，2026-09-26，Blender 4.5 逐包顶点比较）：

| 簇（尺寸） | 成员 | 不同指纹 | 顶点数 | 最大顶点偏移 | 判定 |
|---|---|---|---|---|---|
| `[30.0, 5.0, 0.393]` 天花 | 8 | **1** | 384 | **0.000 m** | ✅ 已正确复用 |
| `[0.635, 5.0, 11.9]` 墙 | 8 | 6 | 3024 | 0.465 m | 需裁定 |
| `[0.615, 5.0, 11.9]` 墙 | 7 | 5 | 2928 | 0.485 m | 需裁定 |
| `[5.0, 0.635, 11.9]` 墙 | 6 | 4 | 3024 | 0.465 m | 需裁定 |
| `[5.0, 5.0, 0.407]` 地砖 | 36 | **36** | 1431 | **4.344 m** | 各自独立 |
| `[5.8, 2.44, 1.67]` 工位 | 4 | **4** | 8512 | **6.285 m** | 各自独立 |

⇒ 该库 106 包里**只有天花真正在复用**；其余「同尺寸」是包络巧合，几何各自独立建模。
⇒ **归并必须两段判**：先包络聚类（候选），再指纹校验（确认）。只做前者会产生错误的合并。

### 1.2 房型组件预算与变体上限（50 / 3–5，硬约束）

新清单必须显式填写 `component_family`。下列 slug 归一化只用于兼容历史清单并生成待回写建议：

```text
族名 = slug
  .lower()
  去掉 方位词 (north|south|east|west|front|rear|inner|outer|left|right)
  去掉 纯数字段与坐标小数 (_00 / -1 / −4.8)
  去掉 尾部单字母序号 (_a / _b)
```

| slug | 族名 |
|---|---|
| `wall_east_-1` | `wall` |
| `tile_-1_-3` | `tile` |
| `ceiling_deck_-1` | `ceiling_deck` |
| `work_cluster_a` | `work_cluster` |
| `door_wall` | `door_wall` |
| `wall_top_service` | `wall_top_service` |

**房型总预算**：单个房型引用的唯一 `component_id` 总数 `<= 50`，实例数不限。计划写：

```json
"component_budget": {"limit": 50, "planned": 32, "remaining": 18}
```

`planned > 50` 时不得进入正式建模。先归并位置型拆分、复用共享件、收敛变体；不能提高预算。

**同族规则**：

- `<= 3`：常规目标，无显式状态轴的近似件必须收敛到此范围；
- `4–5`：仅允许概念图明确要求的破损、配色、结构状态等有意变体；族内每件都填写同一语义的 `variant_axis`，以及各自的 `variant_value`、`variant_reason`；
- `> 5`：绝对违规，必须收敛；
- 纯配色变化优先同一几何＋PaletteUV/材质参数，不应复制几何组件。

**收敛算法**：

```text
SIM_TOL = 0.10 m
比较键 · 结构件 = ( min(x,y), max(x,y), z )
比较键 · 陈设件 = ( x, y, z )
1. 先按真实 variant_axis/value 分组；未声明者进入默认组
2. 默认组收敛到 <=3；合法状态轴合计收敛到 <=5
3. 每簇代表 = 该簇内实例数最多的成员
4. 其余实例改指代表件，位置/旋转进 component_instances.json
5. 仍无法合理收敛时细分真实语义族，但细分后的组件仍计入 50 总预算
```

**实测（办公室 30×40 / v004，2026-09-26，由 `scripts/plan_components.py` 产出）**

| 族 | 收敛前 | 收敛后 | 动作 |
|---|---|---|---|
| `tile` | 48 包 / 5 种尺寸（0.407 / 0.424 / 0.4345 / 5.022×0.407 / 5.077×0.424） | **1** | 平面 5.077、5.022 的边角砖并入 5.0 |
| `wall` | 27 包 / 6 种尺寸（0.635 / 0.615 / 0.63 / 0.635 / 1.11 / 0.97） | **3** | 四个薄墙并成 1；1.11 与 0.97 各自保留 |
| `ceiling_deck` | 8 | 1 | 已是 |
| `work_cluster` | 4 | 1 | 已是 |
| 其余 19 族 | 各 1 | **19** | 不变 |

⇒ 办公室 **106 包 → 25 个组件**。

全库同口径横向：

| 库 | 包数 | 收敛后组件数 | 降幅 |
|---|---|---|---|
| battle v006 | 25 | 22 | 1.1:1 |
| expedition v001（boss） | 214 | 105 | 2.0:1 |
| expedition v002（l_corridor） | 121 | 63 | 1.9:1 |

## 2. 命名规则

```text
禁止（slug 与 component_id 都要过）：
  (?i)(north|south|east|west|front|rear|inner|outer)   方位词
  (?i)slot[_-]?\d+                                      槽位号
  -?\d+\.\d+                                            坐标小数（-4.8 / -12.5）
  (^|[_-])\d{1,3}($|[_-])                               纯数字段（_00 / -1）
```

允许：语义词 ＋ 语义维度 —— `wall_standard_5m`、`wall_standard_10m`、`door_single_5m`、`server_rack`。

`_5m` / `_2u` 这类**带单位**的后缀不算违规（数字后紧跟字母）。

## 5. 拼装还原判据

```text
A 覆盖：sum(instance_count) == source_object_count
B 逐实例：重建后的 position_m / rotation_y_deg 与源对象世界变换一致（容差 1e-4）
C 包络：重建集合的 bounds 与源房间 bounds 一致（容差 1e-3）
D 目视：重建渲染与概念图/效果图比对 —— 唯一可被接受的“高保真”证据
E 包围盒（防旋转错）：按实例清单拼装后总 bbox == 房间边界（含墙厚），越界实例 = 0
```

A/B/C/E 可由脚本与运行时探针判定；D 必须人看。

### 5.1 实例旋转（🔴 实测坑 2026-09-26）

- 组件几何**自带朝向**：源对象旋转通常全 0，朝向烘焙在顶点里。按「朝向无关尺寸」归并时，
  **必须给每条实例记录它相对代表件的旋转角**；漏记 ⇒ 拼装时那一半实例躺倒。
- **轴 = Blender Z**（世界垂直轴，房间平面为 XY）。`rotation_y_deg` / `allowed_rotations_y_deg`
  是历史命名（源自 v005 的 `allowed_rotations_blender_z_deg`），语义就是绕 Z。
  拼装写入 `rotation_euler.z`；写成 `.y` ⇒ 墙直接躺倒（实测 18/36 块）。
- **判定用「主轴方向」**：平面两维中较大者所在轴 —— 同轴 0°、异轴 90°；
  平面长短比 > 0.87（近正方形）视为无主轴、不旋转。
  **不得用点集 Hausdorff 猜**：成员几何本身有差异时会被带偏 —— 实测把 29 m 纵向腰梁误转 90°，
  捅出房间 4 根长刺。
- 90° 与 270° 不区分（中心对称件无差）；不对称件应改「朝向敏感归并」拆成两个组件。
- 实测修复：office v006 **9 条**、bridge v007 **18 条**。修复后两库拼装 bbox 精确等于
  30.3 × 40.3 与 30.3 × 60.3，越界 0。

## 7. 两种错法

| 错法 | 症状 | 被哪条判据拦下 |
|---|---|---|
| 未归并 | 组件数 ≈ 场景对象数；名字带位置 | 归并门禁 ＋ 命名门禁 |
| 过度归并 | 不同材质或不同拓扑的件被合成一个组件，导致某房间拼不出来 | 必要性自检（删掉还能拼 ⇒ 多余；拼不出 ⇒ 该拆） |

## 8. 与「批量拆解实操口径」的关系

SKILL.md 末节记录的三段式脚本口径解决的是「**分**」——把源对象切成独立包。它**不含归并**。
按它跑完会得到「一个源对象一个包」；必须再用本文件的归并键聚类一次，才算符合交付判据。
