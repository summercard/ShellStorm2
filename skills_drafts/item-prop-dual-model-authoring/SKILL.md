# 物品道具双模型制作

用户在2026-10-14明确要求：每件物品有高精度预览模型和地面模型，地面版从现有模型减面，每件100–200面，按实际结构处理。

## 契约与分工

- 先读取工程 `docs/v0.1/design/物品道具双模型制作规范.md` 和 `assets/registry/ledger_index.json`。同一内容ID、同一AssetID对应两种表现角色，不因高低模重复分配资产ID。
- 使用 `godot-runtime-probe` 从真实物品工厂、地面包装及配件装配读取尺寸、父级倍率、朝向和挂点。记录源空间与世界空间，避免把地面倍率二次烘焙。旧箱体占位只提供尺寸基准，不能替代参考图形体。
- 高模用于预览，低模用于世界地面显示。只要求制作源时不自动接入Godot；导入阶段再使用07/08链路，分别注册预览与地面用途，禁止一个默认工厂悄悄同时替换两种用途。

## 制作

1. 先查已有源、状态和哈希。保留现有高模，低模另存为 `<逻辑名>_ground_source_v###.blend`，与高模一起放在 `art_source/items_weapons/<props|weapons>/<slug>/source/`。两者都是当前必要源，不把高模当旧版本移除。
2. 地面版必须从已有高模网格或其制作组件派生；先去除小螺钉、压线和不可见内部，再减少圆周段数、倒角及曲线采样，最后按结构适量Decimate。保留轮廓、标志、开孔及接口；不能仅凭减面百分比通过验收。
3. 每件输出统计合计100–200面。为避免四边面/N-gon钻预算空子，交付地面输出三角化，**求值后三角面总数也必须100–200**；隐藏制作组件、相机和灯光不计入，但不能把可见细节隐藏来伪造通过。
4. 沿用场景四标准材质角色与唯一公共色盘；颜色仅由PaletteUV驱动，Closest、相对外链、不内嵌图片。减面后修复UV：每面岛有面积且位于单一色格安全内区；不得平均跨颜色边界后形成错误颜色。
5. 根缩放1，保留高模原点、朝向、尺寸及挂点。消失的细节不应改变主轮廓；尺寸差异需记录并修正，不能靠运行时额外缩放掩盖问题。
6. 保存可编辑组件和一个整合输出；自发光若使用须独立输出，合计预算仍为200三角以内。没有本体可动结构时不新增骨架或动画。

## 验收与登记

- 从磁盘重新打开两份源：高模哈希不变；低模面数/三角数、包围盒、根变换、挂点、材质、外链和逐面UV通过。
- 同镜头高低模对照，并检查游戏视角。面数达标但标志、孔洞或轮廓损坏时继续修正。
- `asset_contract.json`、`source_manifest.json`明确 `preview` / `ground` 两角色路径、哈希、面数、尺寸和派生关系。更新当前源索引，同时保留两份。
- 使用 `shellstorm2-asset-ledger-row-authoring` 更新对应分账本同一行，写两份路径与各自面数/哈希；新增源角色不新增AssetID。道具归道具账本，子弹和配件归武器账本，物品道具调用账本只更新引用与制作进度。
- 状态区分“Blender源已完成”和“正式美术已接入”。不存在PackedScene时不得往3D Prefab分页添加虚假行。同步无损基线，保留非目标资产指纹。
- 实测日志与预览写工程外 `ShellStorm2-work`；长期规范与交付记录写设计/开发文档。运行源专项、账本结构/无损门禁及文档检查，分别报告历史问题与本次问题。

现成示例：工程 `tools/asset_pipeline/build_reference_ground_models.py` 是8件参考道具的派生脚本，按资产逐件审图后使用，不视为适合所有资产的通用减面参数。
