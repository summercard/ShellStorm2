# Blender 场景、关卡组件与固定设施制作与交付规范

本规范不处理枪械、近战武器、可拾取道具或角色手持物。它们分别使用 `game-weapon-model-pipeline` 与 `game-prop-model-pipeline`。

## 验收目录

1. 输入与范围
2. 色盘与UV
3. 材质节奏
4. 结构与合并
5. 中文管理
6. 场景组件与目录归类
7. 参考图高还原与局部锁定
8. 美术检查
9. 技术检查

## 1. 输入与范围

- 从原始 `.blend` 或用户明确指定的源模型开始。
- 识别固定主体、固定附件、UI、灯带、玻璃、展示地面、相机和灯光；确认可移动附件是否应拆为独立道具资产。
- `DISPLAY_Ground`、`Display_Plinth`、Backdrop 等展示物不得进入游戏输出。
- 不因删除展示底盘而删除物件自身承重底座、柜脚或桌腿。
- 若输入含整屋场景而任务只要求物件，排除整屋场景。
- 用户给出参考效果图时，先区分“图片中明确可见的视觉事实”和“文字对功能/不可见结构的补充”。两者冲突时优先保持图片中明确可见的结构、比例、位置、形状、颜色、材质和细节关系。
- 局部任务开始前生成范围表：`可修改`、`直接附着且可随宿主修改`、`只允许重新归类`、`完全锁定`。未列入可修改范围的内容默认锁定。
- 保存原始版本，不覆盖；记录参考摄像机及渲染设置，避免用不同视角掩盖还原偏差。

## 2. 色盘与UV

- ShellStorm2场景与设施的唯一运行/制作色盘路径为`assets/art/shared/palette/设施低亮多巴胺色盘_10x10_512.png`。所有Blend材料节点必须外链此文件且`packed_file`为空；不得在`source/<资产>`、`components/<资产>`或GLB中保存副本。
- 场景/设施导出GLB必须使用`export_image_format="NONE"`。GLB保留材质角色、PBR参数、UV和面材质索引，但`images/textures`必须为空；Godot导入阶段负责绑定公共色盘。
- PNG尺寸：512×512。
- 网格：10×10，共100个纯色格。
- 每格允许51或52像素，以整数边界覆盖整张贴图。
- UV层固定命名为 `PaletteUV`。
- 每个面保留为一个有面积的小型UV岛；不得把所有loop压成单点，否则难以在UV编辑器中选择和移动。
- 同一面的所有loop必须位于同一个色格，UV岛建议占色格宽高的45%–65%，并与色格四边至少保留约10%色格宽度的安全边距，避免采样到相邻色。
- UV岛允许在所属色格安全内区移动、缩放和旋转；不得跨格，也不得仅把传统大岛缩小后跨越多个色格。
- `PaletteUV` 必须同时设置为 `uv_layers.active` 和 `active_render`。打开UV编辑器时默认看到的必须是分布在色格内的可编辑面岛。
- 纯色色盘输出默认只保留 `PaletteUV`。若法线、烘焙或其它明确贴图需要第二UV，必须在资产台账记录用途，且第二UV不得成为活动编辑层或活动渲染层。
- 贴图节点使用 `Closest` 插值。
- PSD按色域分组并保留可新增色块的独立图层。
- 第10列为固定冷调灰阶栏：R1至R10从深蓝灰到浅蓝灰，推荐依次为 `#1B2533`、`#263242`、`#324052`、`#3F4F62`、`#4D5E72`、`#5D6E82`、`#718195`、`#8998AA`、`#A5B2C1`、`#C5CED8`；后续如调整明度，也必须保持冷色相和单调递增的明度关系。
- 颜色选择应形成主色、辅色、强调色和灯光色层级，不平均使用所有颜色。

## 3. 材质节奏

推荐共享材质名：

- `01_精工金属_紫色骨架`
- `02_细腻哑光_青绿大面`
- `03_清漆反光_紫粉点缀`
- `04_柔和自发光_UI灯光`

语义映射：

- Metal/Silver/Steel/Gunmetal/Frame/Edge/Bolt/Trim → 金属。
- Paint/Rubber/Vinyl/Wood/Worktop/大面积外壳 → 哑光。
- Screen/Glass/Tinted/Lens/Glossy accent → 反光。
- 明确的 EM/Emission/Glow/Neon/LED/Light strip → 自发光。
- `screen`、`display`、`UI` 名称本身不足以判定自发光。

避免以下问题：

- 金属度1.0且环境无反射，导致整片发黑。
- 所有粗糙度集中在0.25–0.40，导致统一塑料感。
- 自发光强度4–7导致颜色泛白、细节消失。
- 为每种颜色建立材质球，导致单个设施或场景出现大量重复材质。
- 源组件继续引用旧材质，使下拉列表残留无效材质。
- 材质 UV Map 节点没有显式读取 `PaletteUV`，导致 Blender 与 GLB 导出读取不同UV层。

## 4. 结构与合并

- 先对修改器求值，再创建游戏输出网格。
- 记录每个面的材质分类，再清空/重建材质槽；清空材质槽会重置面索引，必须恢复。
- BMesh合并前保存面材质计划，`to_mesh` 后按面恢复。
- 主体删除自发光面；自发光网格只保留自发光面并重映射到槽0。
- 删除无连接顶点。
- 主体最多三个非自发光槽；自发光模型只保留一个槽。
- 合并后检查顶点数、面数、UV层和材质索引是否一致。
- 输出模型中心对齐X/Y，底部位于Z=0。

## 5. 中文管理

- 文件、顶层集合、源组件集合、游戏输出集合和主要对象使用中文。
- 原始制作组件与游戏整合模型放在不同集合。
- 原始制作组件默认隐藏；游戏输出默认显示。
- 自发光输出必须能单独隐藏、选择和导出。
- 集合名必须能表达“分类层”“独立资产包”“源组件/游戏输出”三种不同职责，禁止用一个含糊的区域总集合替代独立设施包。

## 6. 场景组件与目录归类

### 6.1 独立资产包判定

满足任一条件即应建立独立资产包：

- 可独立导入、替换、隐藏、复用、LOD、碰撞或版本升级。
- 具有独立功能、明确轮廓或独立游戏语义，例如主门、医疗柜、工具柜、终端、自动补给机、全息平台。
- 在未来导入时需要单独定位、实例化或维护。

不要按“阁楼下方全部物品”“南面全部设施”“杂项”建立最终总包。区域集合可以保留为浏览层，但其下必须继续拆到独立设施。

### 6.2 宿主附着规则

- 结构不可分割且只服务于一个设施的零件归宿主包：门轨、门机、柜门、把手、内置屏幕、按钮、标签、警示灯、固定螺栓和设施自带底座。
- 一块地砖的压边、内阴影唇、固定件、检修盖、格栅、端口、地面标识和局部磨损归该地砖包。
- 横跨多个设施或服务整个场景的管线、电缆桥架、全局吊灯、尘埃、蒸汽等归独立环境支持包。
- 可拾取、可装备、可库存、可独立物理移动的物品不得塞进固定设施包；改走相应道具或武器管线。仅作为不可交互展示几何时，必须在清单中明确 `fixed_display_attachment`。

### 6.3 Blender 与磁盘镜像

Blender 游戏输出的每个末级资产包必须对应一个磁盘目录。推荐：

```text
component_packages_v###/
├─ architecture/<asset_slug>/asset_manifest.json
├─ floor/tile_r##_c##/asset_manifest.json
├─ facilities/<asset_slug>/asset_manifest.json
├─ loft/<asset_slug>/asset_manifest.json
├─ warehouse/<asset_slug>/asset_manifest.json
└─ support/<asset_slug>/asset_manifest.json
```

分类名称可按场景调整，但同一版本中必须稳定。磁盘目录使用稳定 ASCII slug；Blender Collection 和对象可使用清晰中文名。一个末级包不得为空，一个对象不得同时归属两个游戏输出资产包。

每个 `asset_manifest.json` 至少记录：

- `asset_id` 或场景内稳定 `package_id`
- 中文名与英文/ASCII slug
- 类别、版本、源 `.blend`
- Blender Collection 名
- 对象清单与根对象
- 世界坐标、局部原点、正面方向、包络尺寸
- 材质角色、动画/灯光、自发光状态
- 依赖包及附着关系
- 预期导出文件、碰撞状态与当前是否已导出

总目录另生成可审阅的 JSON catalog 与文本 tree。Collection、磁盘清单、catalog 三方包数及名称必须一致。

### 6.4 地面系统

- 地面只设一个一级分类；每一块可替换地砖是独立末级资产包。
- 地砖包包含原始地砖及直接依附其上的深化内容，不把全部深化件集中放入“地面装饰总包”。
- 跨砖设施不得复制到多个地砖包；放入独立设施或支持包，并显式记录依赖和锚点。
- 验收必须核对地砖数量、行列编号、尺寸、朝向、拼缝、高程和唯一归属。

## 7. 参考图高还原与局部锁定

### 7.1 参考图是真值，不是灵感图

用户明确要求还原时，验收必须同时覆盖：

- 一级结构：建筑轮廓、楼层、平台、门洞和大型设施。
- 二级结构：门轨、柜门、支架、护边、面板分区和机械连接。
- 三级细节：按钮、螺栓、标签、图标、警示条、磨损和小装饰。
- 空间关系：模型比例、位置、朝向、间距、可通行动线和视觉密度。
- 表面与灯光：材质类型、颜色、粗糙度关系、纹理、发光区域、灯光颜色与明暗层次。

功能一致不等于视觉还原。若参考图已有明确设备外形，必须沿用其宽高比例、主体轮廓、屏幕/操作区位置、底座和配色，不得另设计一件功能相同的设备。发生物件误读（例如门被做成电视墙）时，应先用参考图轮廓、分缝、导轨、开启结构和邻接关系重新判定，再修改。

### 7.2 固定参考镜头

- 保存命名明确的参考摄像机，不在最终对比前改变其构图。
- 前后渲染保持相同焦距或正交尺度、分辨率、渲染引擎、采样、曝光、View Transform 和关键灯光。
- 至少交付参考镜头全景、俯视结构图、修改区域近景；必要时增加接口特写。
- 参考图比较优先检查剪影和大型色块，其次检查空间关系、二级机械结构和三级细节，最后检查材质与灯光微调。

### 7.3 局部修改锁区

局部修改必须对原版与新版建立可重复的锁区签名。签名至少覆盖完全锁定对象的：

- 对象名、类型、父子关系
- 世界位置、旋转、缩放和尺寸
- 网格顶点/边/面及坐标摘要
- 材质槽与面材质索引
- 修改器参数
- 动画数据和关键帧

如果任务明确允许 Collection 重组，Collection 归属从几何锁定签名中排除，并单独验收归类结果。浮点数据应按项目容差量化；报告必须同时输出旧/新签名以及 `locked_match`。任何非预期差异均为失败，不能用“画面看不出来”放行。

### 7.4 关键接口和包络

- 对主门、楼梯、平台、全息平台、柜体等关键设施记录中心、包络和对接面。
- 楼梯每一跑、转角平台和顶层平台必须逐边、逐高程对接；不得穿插、悬空、错位或用遮挡掩盖。
- 门体必须与门框、轨道、墙面和地面完成面匹配；设备不得因深化越出原有通行边界，除非用户明确允许。
- 修改后报告实际测量值，而不是只写“与参考一致”。

## 8. 美术检查

- 近景检查金属高光是否清晰但不过曝。
- 哑光大面应有柔和渐变，不出现镜面硬亮斑。
- 反光材质只作为边框、玻璃和焦点装饰，不覆盖所有主体。
- UI灯光保留原色，不变白，不吞掉图形边缘。
- 深紫结构在常规Material Preview和正式灯光中都应可读。
- 大面积主色控制在2–3种；高饱和暖色仅用于小面积焦点。
- 从合集视角检查比例、重叠、裁切和完整显示。
- 从固定参考镜头进行第一眼对比：大型轮廓、主色块、焦点标识和灯光关系必须先成立，再接受局部细节。
- 不得用增加大量复杂机械件掩盖主体比例或设备位置错误；细节密度必须服从参考图的Q版造型语言。

## 9. 技术检查

- 文件总材质数默认4，硬上限12。
- 单体设施主体通常最多3个非自发光材质角色；有真实灯光几何时增加共享自发光材质。
- 不存在整份 `.blend` 都未引用的旧材质；源组件仍引用、但整合输出暂未引用的材质不算废弃。
- 游戏输出每个网格都有 `PaletteUV`。
- 游戏输出每个面均为具有非零面积的UV岛，且全部loop位于同一个10×10色格的安全内区。
- `PaletteUV` 是当前编辑层和活动渲染层；材质 UV Map 节点只读取 `PaletteUV`。
- 除资产台账明确登记的第二UV外，不存在活动的 `UVMap/UV贴图` 旧层。
- 不存在 `DISPLAY_Ground`、`Display_Plinth`。
- 主体和自发光网格独立。
- 外部公共色盘未打包，所有色盘节点解析到唯一固定路径；资产私有目录不存在色盘PNG副本。
- GLB不含`images/textures`，模型目录不会因Godot导入再次生成色盘PNG。
- `.blend` 能用目标Blender版本后台打开。
- 总合集所有交付集合默认可见。
- 总合集必须对全部网格执行逐面色盘UV与材质检查，不能因为没有单一 `02_游戏输出` 集合而跳过验收。
- 验证报告必须输出：有效色格内UV岛数/总面数、单点或跨格面、活动层、渲染层、额外UV、材质UV节点、Closest插值、已用/未用材质和输出集合；不得仅凭存在同名UV层判定通过。
- 场景总合集还必须输出：一级分类数、独立资产包数、每类包数、地砖包数、空包数、多包归属对象数、磁盘清单数、旧误读对象数、锁区旧/新签名、关键中心/包络和范围内新增或修改对象数。
- 独立包验收要求：每包非空；每个游戏输出对象恰好属于一个末级包；Collection、磁盘目录、manifest、catalog一致；源组件集合不得误计为第二个游戏输出归属。
- 局部任务只有在锁区签名相同、范围内设施通过关键坐标/包络检查、参考镜头人工复核通过、全部网格严格PaletteUV检查通过后才能标记完成。
- 验收报告区分“Blender源场景完成”和“游戏运行时已接入”。未生成独立GLB、碰撞、LOD或PackedScene时必须明确说明，不得因已有目录和Collection而宣称完成引擎导入。
