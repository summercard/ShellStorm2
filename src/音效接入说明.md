## 2. 源母版与运行资产

| 层级 | 格式 | 规格 | 用途 |
|---|---|---|---|
| 源母版 | WAV PCM | 44,100Hz / 16-bit / mono | 后续剪辑、重新混音和转码 |
| 正式运行 | OGG Vorbis | 44,100Hz / stereo / `*_v001.ogg` | Windows、macOS、Linux与Android统一加载 |

资源目录统一为`res://src/assets/audio/sfx/`。命名示例：

```text
pistol_fire.wav          # 母版，不被AudioManager引用
pistol_fire_v001.ogg     # 正式运行资产
```

版本号是移动端缓存隔离的一部分。替换音频内容时使用`_v002`等新文件名并同步`AudioManager.SFX`，不要在已发布文件名下覆盖后继续依赖旧导出缓存。

## 3. 事件清单与实际接入

| 事件组 | 事件键 | 当前所有者 |
|---|---|---|
| 枪械 | `pistol_fire`、`rifle_fire`、`shotgun_fire`、`smg_fire`、`sniper_fire`、`laser_fire`、`ammo_empty`、`reload` | 武器/AudioManager辅助方法 |
| 战斗 | `enemy_hit`、`enemy_die`、`crit_hit`、`player_hit`、`player_dash`、`melee_swing`、`melee_impact` | 玩家、敌人和近战动作反馈层 |
| 命运/撤离 | `fate_card`、`extraction_start`、`extraction_done`、`extraction_abort` | 命运与撤离流程 |
| UI | `ui_hover`、`ui_click`、`ui_error` | `UIStyleFactory`统一按钮绑定；失败分支显式播放error |
| 拾取 | `item_pickup`、`soul_pickup` | `GroundItemPickup`、`GroundLootPickup3D`、`SoulOrb` |
| 环境交互 | `door_open`、`door_locked`、`container_open` | `RoomDoor3D`与容器完成搜索时 |
| 战斗流程 | `wave_start`、`wave_clear`、`boss_intro`、`boss_phase`、`boss_defeat` | `Dungeon3D` 状态变化点 |
| 交易 | `merchant_purchase` | 贩卖机/商人成功事务；失败使用`ui_error` |

调用保持简单：

```gdscript
if AudioManager != null:
    AudioManager.play_sfx("container_open", -3.0)
```

射击仍可使用分类入口：

```gdscript
AudioManager.play_fire_sfx(fire_rate, projectile_count)
```

分类顺序为霰弹（投射物≥5）→冲锋枪（射速≥10）→步枪（≥5）→手枪（≥2）→狙击；能量武器显式调用`laser_fire`。

近战使用分类入口，让动作机而不是敌人拥有主反馈：

```gdscript
AudioManager.play_melee_swing_sfx(weapon_content_id, combo_step)
AudioManager.play_melee_impact_sfx(weapon_content_id, combo_step)
```

`melee_swing`在每段进入`active`时播放一次，挥空也播放；`melee_impact`仅在至少命中一个目标后播放，一次攻击命中多个目标仍只播一次。连段编号和武器内容ID只调整音高/响度，不新增重复事件键；目标原有`enemy_hit / crit_hit`继续逐目标播放。

## 4. 单一播放所有者

同一个状态变化只允许一个节点播放：

- 门成功开启只由`RoomDoor3D`播放；关卡层只负责失败时的`door_locked`。
- 容器在搜索计时完成后播放一次，按E开始搜索时不播放开启声。
- 魂球与普通物品由实际拾取成功的节点播放，生成时不播放。
- Boss阶段音只在阶段编号变化时播放，不在每帧血条刷新中播放。
- 通用按钮声音由`UIStyleFactory`绑定；单个菜单不要重复连接相同hover/click。
- 近战动作机拥有`melee_swing / melee_impact`主层：每段一个挥砍声、每次攻击最多一个接触主声；敌人只拥有自身`enemy_hit / crit_hit`层，多目标不得让动作机重复播放主声。

## 5. Android防旧音效规则

Android出现老音效通常不是混音问题，而是旧文件名、回退逻辑或增量包缓存仍可命中。本工程采用以下硬规则：

1. `AudioManager.SFX`只登记版本化OGG。
2. 不加载未登记WAV，不调用`SynthSfx`。
3. 新音频内容升级文件版本名，避免覆盖同名缓存。
4. 导出前先让Godot完成OGG导入，再执行运行资产校验。
5. Android复验使用清理旧安装后的全新包；不能用旧增量包结果判定资源是否替换。

运行校验：

```gdscript
var result := AudioManager.validate_runtime_assets()
# 当前：event_count == 36
#      missing == []
#      non_ogg == []
#      mobile_safe == false
# 发布期望：36项全部存在且 mobile_safe == true
```

近战本轮专项验收不把已明确登记的手电筒待办误算为近战失败，但会硬性检查`melee_swing / melee_impact`两条路径存在、以`.ogg`结尾并可由Godot导入。

自动化入口：

```bash
/Applications/Godot.app/Contents/MacOS/Godot \
  --headless --path /path/to/ShellStorm2 \
  tests/verification/verify_requested_experience_upgrade_flow.tscn
```

## 6. 混音和性能

- 自动武器使用短音频并复用`AudioStream`缓存，避免连射时重复加载。
- `sfx_volume`统一叠加到单次调用的`volume_db`。
- UI悬停推荐`-8`至`-5dB`，点击/拾取`-5`至`-2dB`，门/容器`-5`至`-2dB`，枪械与Boss关键提示`-3`至`0dB`。
- 随机音高建议控制在`0.96–1.04`，枪械不得超过`0.93–1.07`。
- 近战按动作语义允许更宽的固定变调：三段空气层约`0.94 / 1.03 / 0.86`，战斧整体再降低`0.08`；冲击层第三段最重。固定参数可复验，不使用每次随机抖动。
- 当前使用全局`AudioStreamPlayer`；后续若把敌人、门和容器改为空间音频，应替换播放节点而不是改变事件键。
