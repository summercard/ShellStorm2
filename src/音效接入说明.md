# 未来科幻废土顶视角射击游戏：音效重制与接入说明

## 1. 本次处理结果

- 已检查项目内全部音频调用与资源引用。
- 原压缩包中**没有实际 WAV、OGG、MP3 或 FLAC 文件**；`src/core/AudioManager.gd` 的 16 个音效路径全部为空，运行时依赖 `src/core/SynthSfx.gd` 临时合成。
- 本次保持原有 16 个事件键名和调用方式不变，为它们制作了正式 WAV 文件，并将 `AudioManager.gd` 改为从固定路径加载。
- 新增 15 个适合科幻废土射击玩法的音效，并登记到 `AudioManager.SFX`。新增音效没有强行修改玩法代码，建议接入位置见第 4 节。
- `SynthSfx.gd` 仍保留：正式文件丢失时自动降级，避免静音或崩溃。
- `AudioManager.gd` 新增音频流缓存，减少自动武器连续射击时的重复加载；`sfx_volume` 现在会实际作用于播放音量。

## 2. 统一资源规格与路径

- 格式：WAV / PCM
- 采样率：44,100 Hz
- 位深：16-bit
- 声道：Mono
- 总路径：`res://src/assets/audio/sfx/`
- 命名规则：事件键名与文件名完全一致，例如：
  - 键：`pistol_fire`
  - 文件：`res://src/assets/audio/sfx/pistol_fire.wav`

Mono 便于后续把战斗音效迁移到 `AudioStreamPlayer2D` / `AudioStreamPlayer3D` 做空间定位；当前项目使用全局 `AudioStreamPlayer`，也能直接播放。

## 4. 新增音效与建议接入位置

所有新增文件已登记在 `AudioManager.SFX`，接入时只需：

```gdscript
if AudioManager != null:
    AudioManager.play_sfx("事件键")
```

### 4.1 UI 与操作反馈

| 事件键 | 建议使用位置 | 接入建议 |
|---|---|---|
| `ui_hover` | 所有主要按钮 `mouse_entered` | 只用于主菜单、商店、命运卡等重要按钮；普通格子大量滑过时建议节流 |
| `ui_click` | 按钮 `pressed`、面板打开、确认操作 | 可在 `BaseMenu.gd`、`MerchantUI.gd`、`InventoryUI.gd` 中统一连接 |
| `ui_error` | 背包满、购买失败、条件不足、无效操作 | 与红色提示或禁止动画同步 |

推荐的集中式按钮连接方式：

```gdscript
func bind_button_sfx(button: Button) -> void:
    button.mouse_entered.connect(func(): AudioManager.play_sfx("ui_hover", -6.0))
    button.pressed.connect(func(): AudioManager.play_sfx("ui_click", -3.0))
```

### 4.2 武器与拾取

| 事件键 | 建议脚本 / 函数 | 触发条件 |
|---|---|---|
| `ammo_empty` | `src/weapon/WeaponController.gd::fire()`；`src/combat3d/WeaponModel3D.gd` 的射击失败分支 | 玩家按下射击但弹匣为 0，且本次没有成功开火；建议做 0.12–0.18 秒节流 |
| `item_pickup` | `src/items/GroundItemPickup.gd::_try_collect()`；`src/world3d/GroundLootPickup3D.gd::accept_pickup()` | 物品实际进入背包后播放；背包满时改播 `ui_error` |
| `soul_pickup` | `src/items/SoulOrb.gd::_collect()` | `collected.emit()` 前后均可，建议与紫色涟漪同步 |

2D 地面物品示例：

```gdscript
var added := int(_game_mode.call("collect_ground_item", item_data))
if added <= 0:
    AudioManager.play_sfx("ui_error", -4.0)
    return
AudioManager.play_sfx("item_pickup", -3.0, randf_range(0.96, 1.04))
```

### 4.3 门、容器与环境交互

| 事件键 | 建议脚本 / 函数 | 触发条件 |
|---|---|---|
| `door_open` | `src/world3d/RoomDoor3D.gd::set_open()`；`src/world3d/Dungeon3D.gd::_try_open_room_door()`；`src/game/RoomGameMode.gd::try_open_room_door()` | 门状态由关闭变为开启，且 `immediate == false` |
| `door_locked` | `Dungeon3D::_try_open_room_door()` 和 `RoomGameMode::try_open_room_door()` | 未清场、无钥匙、命运卡未选择等导致开门失败时播放；建议 0.3 秒节流 |
| `container_open` | `src/game/ContainerInteraction.gd::_play_open_animation()` | 容器确认打开、发放掉落后播放 |

3D 门动画示例：

```gdscript
func set_open(opened: bool, immediate := false) -> void:
    var changed := is_open != opened
    # 原逻辑……
    if changed and opened and not immediate and AudioManager != null:
        AudioManager.play_sfx("door_open", -2.0)
```

注意：如果一扇门同时在 `Dungeon3D` 和 `RoomDoor3D` 播放，会产生双响。建议最终只保留在门节点 `RoomDoor3D::set_open()`，失败音效则留在门逻辑层。

### 4.4 波次与 Boss

| 事件键 | 建议脚本 / 函数 | 触发条件 |
|---|---|---|
| `wave_start` | `src/game/RoomGameMode.gd::_on_wave_started()` | 每波敌人正式开始时，与“第 X/Y 波”提示同步 |
| `wave_clear` | `src/game/RoomGameMode.gd::_on_all_waves_cleared()` | 房间全部波次完成，且不是撤离防守中的中间波 |
| `boss_intro` | `src/game/RoomGameMode.gd::_on_boss_spawned()`；`src/world3d/Dungeon3D.gd::_show_boss_hud()` | Boss 入场动画或名称条首次出现时，只播放一次 |
| `boss_phase` | `RoomGameMode::_on_boss_phase_changed()`；`Dungeon3D::_on_boss_phase_changed()` | 阶段发生变化时播放，不要在每次刷新血条时播放 |
| `boss_defeat` | `RoomGameMode::_on_boss_defeated()`；3D 模式 Boss 死亡确认逻辑 | Boss 结算确认时播放，建议压低其他 SFX 0.5–1 秒突出胜利反馈 |

示例：

```gdscript
func _on_wave_started(wave: int, total: int) -> void:
    AudioManager.play_sfx("wave_start", -2.0, randf_range(0.98, 1.02))
    _update_room_info_label("第 %d/%d 波袭来！" % [wave, total])
```

## 5. 射击音效分类逻辑说明

当前 `AudioManager.play_fire_sfx(fire_rate, projectile_count)` 根据投射物数量和射速自动判断类型：

1. `projectile_count >= 5` → `shotgun_fire`
2. `fire_rate >= 10.0` → `smg_fire`
3. `fire_rate >= 5.0` → `rifle_fire`
4. `fire_rate >= 2.0` → `pistol_fire`
5. 其余 → `sniper_fire`

`laser_fire` 当前不会被自动选中。能量武器应依据武器 ID、伤害标签或行为标签显式调用，例如：

```gdscript
if "energy" in bullet_tags or gun_id == "bp_laser":
    AudioManager.play_sfx("laser_fire")
else:
    AudioManager.play_fire_sfx(fire_rate, emitted_count)
```

## 6. 混音与性能建议

- 自动武器：枪声必须短；当前 SMG/Rifle 已按高射速设计。若仍过密，可在武器层做最大同时声数或 30–50 ms 冷却。
- 暴击：当前代码可能在 `Enemy3D.gd` 与 `HitEffects.gd` 同时触发命中音效。实际运行时若听到双响，应只保留伤害确认层的一次播放。
- 2D/3D 空间化：目前所有音效通过全局 `AudioStreamPlayer` 播放，不随距离衰减。玩家自身、UI、撤离提示适合全局播放；敌人死亡、门、容器更适合后续改成 `AudioStreamPlayer2D/3D`。
- 总线：确认 Godot 项目中存在名为 `SFX` 的 Audio Bus。否则 `player.bus = "SFX"` 会回落或出现警告。
- 导入：首次在 Godot 编辑器打开项目时会自动生成 `.import` 缓存，不需要手工提交 `.import` 文件。
- 变化感：重复事件可使用轻微随机音高，推荐范围 `0.96–1.04`；枪械不要超过 `0.93–1.07`，否则武器识别度会下降。

## 7. 建议的基础音量参数

调用参数是相对调整，不会修改源文件：

| 类型 | 建议 `volume_db` |
|---|---:|
| 玩家枪械 | `-2` 至 `0` dB |
| 敌人命中/死亡 | `-5` 至 `-2` dB |
| 玩家受伤/暴击 | `-3` 至 `0` dB |
| UI 悬停 | `-8` 至 `-5` dB |
| UI 点击/拾取 | `-5` 至 `-2` dB |
| 门/容器 | `-5` 至 `-2` dB |
| 波次/Boss/撤离 | `-3` 至 `0` dB |

## 8. 验收清单

1. 打开项目后确认 31 个 WAV 全部被 Godot 正常导入。
2. 检查 `AudioManager` 是否作为 Autoload，路径名为 `/root/AudioManager`。
3. 检查 Audio Bus 中是否存在 `SFX`。
4. 逐一测试五种自动分类枪声，确认 SMG 连射不爆音、霰弹和狙击有足够重量。
5. 测试普通命中与暴击，确认没有 `Enemy3D` + `HitEffects` 双重播放。
6. 测试换弹、闪避、玩家受伤、敌人死亡和命运卡。
7. 测试撤离开始、成功和中断三种状态。
8. 接入新增事件时一次只改一个触发点，避免门、Boss、拾取等事件双响。
