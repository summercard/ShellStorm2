# base_facility_layout · 使用说明

> 这份文档说明 base_facility_layout 目录里两个文件夹（source/ 和 export/）该怎么用。
> 命名规则和目录结构总览见 `README.md`，本文档专讲**操作流程**。

## 🎬 场景 1：我拿到了这堆文件，要怎么打开？

### 路径1：我想看完整布局（含全部内容）
打开 `source/base_facility_runtime_layout_hq_v017.blend`

### 路径2：我只想引用某个分组（比如只导入"墙体内容"）
打开 `export/v017/base_facility_runtime_layout_hq-v017-wall_contents.blend`

## 🔧 场景 2：源文件要升级（v017 → v018），怎么操作？

1. 复制 `source/base_facility_runtime_layout_hq_v017.blend` → `source/base_facility_runtime_layout_hq_v018.blend`
2. 在 v018 上做修改（不要在 v017 上原地改）
3. 同步重建导出：
   ```
   mkdir -p export/v018
   # 把 export/v017/ 三个文件用 v018 源重新导出
   ```
4. 命名严格用 `...-v018-<类型>.blend`（版本号跟着源走）
5. 删除 `export/v017/` （v017 的导出随 v018 源替代而废弃）

## ♻️ 场景 3：源不变，但要重新做导出（修导出 bug、分组调整）

- **覆盖 `export/v017/` 下的3 个文件**
- 命名保持 `...-v017-<类型>.blend`（**不要升 v022/v023 这种版本号** —— 导出没有自己的版本号）
- 文件名后缀不要带日期、不要带 iter1/iter2 后缀

## 📦 场景 4：我要从 source 重新导出分组文件

最简单的方法（Blender 手动）：
1. 打开 `source/base_facility_runtime_layout_hq_v017.blend`
2. `File → Append` 或 `File → Link`，按需把 collection 拎出来
3. 保存到 `export/v017/base_facility_runtime_layout_hq-v017-<类型>.blend`

## ⚠️ 常见错误（看到就改）

| 错误 | 正确 |
|---|---|
| `export/v022/wall_contents.blend` | `export/v017/wall_contents.blend` ← 导出版本号绑源，不自己升 |
| `export/v017/v017_wall_contents.blend` | `export/v017/...-v017-wall_contents.blend` ← 连字符，不是下划线 |
| 主目录放 `xxx_v018.blend` | 必须落到 `source/v018/` 或 `export/v018/` |
| `export/v017/` 下留 `iter01/` `iter02/` 子目录 | 直接覆盖，不分子目录（迭代记录由 git 负责） |
