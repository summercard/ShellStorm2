# 场景工坊 · Godot组件场景编辑器

项目启用 **ShellStorm Component Scene Builder** 后，右侧完整栏目显示 **场景工坊**。新版面板标记为 **r7**。若面板被其他标签遮住，点击右侧“场景工坊”标签；可用Godot原生停靠菜单移动或浮动。

## 从打开场景到拼装

1. 顶部 **打开**：直接浏览游戏采用的正式房间文件，按关卡和房型检索；同一个TSCN只显示一次。无需输入地图种子或启动Python。双击后编辑、保存的就是详情里显示的那个正式文件，不为某局另存一份“种子房间”。多个游戏内实例可以共用同一文件。
2. 顶部 **新建**：搜索白盒模板，例如“远征03”，选择后另存为新的美术TSCN，保留原白盒。rt房间、cr通道及EGT共享参考只出现在新建/关联参考选择器，不混入正式房间打开列表。新建文件还需关卡模块完成运行绑定，保存本身不会自动接入。
3. 选择组件套件和类型，点图片卡片。下方3D预览可拖动旋转、滚轮缩放和复位；卡片区与预览区之间可拖动分隔条，关闭“3D”可扩大卡片区。
4. 顶部八个小按钮选择 **选择 / 放置 / 笔刷 / 矩形 / 直线 / 擦除 / 点光 / 聚光**，当前模式高亮。操作模式使用按钮，不使用下拉菜单。
5. 在3D视图左键放置或拖刷；矩形、直线各点击两点。Q/E旋转90°，Esc返回原生选择，Alt+鼠标保留原生导航；Ctrl+Z撤销整笔。
6. 顶部 **保存** 或Ctrl+S。工作台的美术场景采用原生保存并跳过场景缩略图生成，避免Godot4.7.2已复现的缩略图保存错误。脚本编辑器或其他Godot弹窗中的快捷键仍交给原生编辑器。更多“···”提供另存为、刷新组件、重新载入工作台和操作提示。

## 常用设置

底部 **吸附** 关闭时保留真实鼠标落点，可自由摆放。打开后按间距吸附；**选项 → 放置** 可以调整间距、标高、角度、笔刷大小、格心/墙边相位、碰撞表面贴合、房内裁切与门口保护。铺满地面和检查布局也在此页。5m地砖通常使用5m间距与0.08m标高，按具体组件原点调整。

**选项 → 参考** 显示白盒已加载、隐藏、未关联或路径错误的状态；提供显示开关、透明度、关联/更换及重载。关联可撤销，保留原有组件摆位。

**选项 → 灯光** 调整创建时的能量、范围和阴影。用顶部点光/聚光按钮放下灯后，使用原生移动工具与检查器修改位置、颜色等属性；检查器与工作台可通过右侧标签切换。

远征03固定陈设按全部合法门位保护门前净空，不只检查某个种子的已用门。工坊保存/另存前会用实际碰撞检查，冲突时拒绝该工具命令并显示对象与门位；请在正式文件修正。此检查不覆盖所有原生编辑器保存路径，外部Ctrl+S等未接入守卫的操作可绕过，不是引擎级强制门禁。

组件轮廓绿色表示可放，红色表示越界或占用受保护门口。连续笔刷是组件式铺放，支持同格地砖替换、防重复及单批4096预算；不包含地形雕刻或纹理权重绘制。

组件套件里的 **共享 / 易碎陈设**（易碎罐子、散落书本堆、易碎花瓶、易碎椅子、易碎木箱）是可打碎陈设，不是建筑构件：它们不挡玩家，子弹可打碎。摆的时候注意两点 —— 标高按 **0** 摆（原点在底面中心，不要套地砖那套 0.08），以及**不要和已经随机撒点的房间重复摆**（房间建好时会读这批手摆件做避让，两批共用同一本 `breakable_clutter` 房间账，砸碎进度一起存）。详见[场景可交互低模物件设计 r5](../../docs/v0.1/design/场景可交互低模物件设计.md)。

## 读取反馈与恢复

打开场景和组件资源时，底部先显示进度/阶段与耗时；只有原生编辑器切换到目标场景后才显示打开成功。读取失败会给出原因和 **重试**；读取阶段可取消工具后续处理，保留当前场景。Godot开始原生实例化后不显示可强制取消的承诺。

场景列表先显示扫描状态，再后台读取元数据。缩略图按当前可见页生成，显示完成数量；切换组件只应用最后一次选择的结果。编辑器空闲时缩略图也会推进，不需要晃动鼠标。若Godot另有未处理弹窗，工作台说明原因并提供重试。

脚本更新后会检测控件树的构建标记并重建旧面板，同时保留场景、画笔参数与原生撤销。也可用“··· → 重新载入工作台”手动恢复。

## 保存、来源与维护

唯一组件目录为共享catalog。正式TSCN保存组件实例引用、作者摆位及灯光；同路径迭代Prefab后沿引用生效。画笔和参考预览辅助不进入存盘，工具代码不进入发行包。缩略图缓存位于`.godot/editor/scene_builder_thumbnails/`。

正式房间列表只读投影当前游戏资源绑定：固定蓝图读取正式设计源；远征03候选通过共享`RuntimeRoomArtSource`现行身份/路径规则验证，再按路径去重。旧门位文件、派生缓存和未接入的新美术文件不会成为第二套打开列表。目录存在不代表游戏采用；路径详情是当前编辑对象的依据。

关卡骨架、种子、动态连接及门墙装配由游戏模块拥有；r8经用户确认将陈设（含历史 `Furn_*`）与作者灯光的编辑权固定给同一正式TSCN，运行时禁止删除重摆，空陈设无生成兜底。制作时需检查全部合法门位前净空，冲突在正式文件里定点修正。该修订的实际落地与验证状态见本轮开发记录，不以“列表唯一”代替运行保持验收。

设计：[组件场景编辑器设计 r8](../../docs/v0.1/design/组件场景编辑器设计.md)；入口实测：[唯一正式房间列表](../../docs/v0.1/development/2026-11-01_scene_workshop_unique_rooms.md)；固定陈设与结构兼容的本轮实现/验证：[开发记录](../../docs/v0.1/development/2026-11-01_fixed_room_furnishing.md)。r6按种子采集保留为历史排查入口，不再参与默认打开流程。

## 验收入口

使用工程外隔离项目，并在Autoload启动前隔离用户目录；仅设置场景内test_mode不够。Windows可隔离APPDATA与LOCALAPPDATA，macOS需验证实际user目录独立。输出目录使用工程外ShellStorm2-work。

```text
godot --headless --path . --script res://tools/scene_builder/test_layout_model.gd -- <测试输出目录>
godot --headless --path . --script res://tools/scene_builder/test_fixed_furnishing.gd
godot --headless --path . --script res://tools/scene_builder/test_workbench.gd
godot --headless --editor --path . res://tools/scene_builder/examples/component_room_demo.tscn -- --scene-builder-test
godot --editor --path . res://tools/scene_builder/examples/component_room_demo.tscn -- --scene-builder-test --scene-builder-capture <截图绝对路径>
```

编辑器专项会真实切换到独立测试场景，验证打开/失败/取消/重试和UI重建；建议在隔离工程运行。验收结果与原工程其他并行任务的错误分别见开发记录，不能把专项断言通过等同于整工程通过。
