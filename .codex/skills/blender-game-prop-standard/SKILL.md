# Blender 场景、关卡组件与设施制作规范

## 适用边界

此 skill 仅处理三类资产：

- **场景与关卡组件**：地板、墙、楼板、门洞、楼梯、栏杆和可拼接建筑模块。
- **固定设施**：自动贩卖机、储物柜、工作台、终端和固定在场景中的大型装置。
- **设施的固定展示附件**：不需要独立拾取、装备、物理移动或手持动画的组成部分。

枪械和近战武器使用 `game-weapon-model-pipeline`；可拾取、库存、可投掷、可手持或可独立物理移动的道具使用 `game-prop-model-pipeline`。不要把武器、座椅、独立道具或角色可交互附件焊进设施输出。

为一个物件制作可维护源文件和游戏输出。颜色只由色盘 UV 控制，金属、哑光、反光和自发光质感只由材质角色控制。

## 必须执行的流程

1. 检查参考图、源集合、对象层级、实际尺寸、修改器、材质、PBR参数、自发光强度和展示专用几何体。
2. 保留有意义的结构细节；只删除非物件组成的展示地面、底台、背景、相机和灯光。
3. ShellStorm2的场景、关卡组件与固定设施只允许引用项目级公共色盘`assets/art/shared/palette/设施低亮多巴胺色盘_10x10_512.png`。不得在资产目录新建、复制、打包或改名保存色盘；Blender图片数据块必须外链该文件，所有色盘节点使用同一数据块和`Closest`插值。导出GLB时设置`export_image_format="NONE"`，禁止每个GLB再次内嵌色盘。贴图固定为512×512、10×10纯色格；第10列固定为冷调灰阶，按第1行至第10行由深蓝灰连续过渡到浅蓝灰，不得混入暖灰。每个面的 `PaletteUV` 必须保留为有面积的小型UV岛，完整放在单一色格的安全内区，不能压成点。`PaletteUV` 必须同时设为当前编辑层和活动渲染层；纯色色盘资产默认删除输出网格上的 `UVMap/UV贴图` 等旧层，确需保留时必须记录用途且不得成为活动层。
4. 默认仅使用四个共享材质角色：精工金属、细腻哑光、清漆反光、柔和自发光。颜色变化不得增加材质球。
5. 先给制作组件统一材质并清除废弃材质，再生成游戏输出，避免材质列表残留旧球。
6. 对修改器求值后合并输出：非自发光面合成一个主体网格，自发光面合成一个独立网格；保留面材质索引和 `PaletteUV`。
7. 游戏输出在X/Y居中，底面位于Z=0；应用或记录展示变换和正面方向。
8. 制作组件保持可编辑并默认隐藏；游戏输出默认显示。语义独立的椅子、附件、武器或小道具必须成为独立资产，不得因画面组合而焊进主设施。
9. 渲染近景材质预览和完整物件预览，修正发黑、塑料感、过曝、自发光泛白、重叠、比例或结构缺失。
10. 保存新版本，不覆盖原始文件；最后运行 `scripts/validate_game_prop.py`。验证必须逐面确认UV岛具有面积、全部 loop 位于同一个色格安全内区，并检查活动层、渲染层、材质 UV Map 节点、Closest 插值、废弃材质和输出集合；单点UV或只检查UV层名称均不算验收。

## 模块化建筑与楼梯附加流程

当资产是地板、墙、楼板、楼梯、栏杆或门洞模块时，必须把连接关系当成同一资产包验收：

1. 先记录楼层基准、平台顶面、目标楼层、门洞、入口缺口、水平包络和对接坐标，再修改几何。不得只凭视图缩放。
2. 高度改变时联动楼板、所有相接楼梯、落地平台、栏杆和出口；保留踏步厚度、栏杆高度和结构截面。禁止对整件资产做纵向非等比缩放来凑高度。
3. 墙体高度契约固定为9m：墙体模块的逻辑高度、原点/基准点和游戏阻挡（碰撞）均保持原规则不变。阻挡使用9m高度，底部仍位于原基准点，不得为了视觉避让而移动或缩短阻挡。视觉墙体网格按8.9m制作，底部与原基准点对齐，顶部停在基准点上方8.9m，顶部预留0.1m空隙以避免与上层地板共面闪面；不得用整件纵向缩放替代该尺寸契约。
4. 游戏碰撞与可见踏步分离：可见模型保留踏步细节，游戏包装使用连续简化斜坡和独立栏杆阻挡。逐级盒碰撞不得作为角色主行走面。
4. 栏杆碰撞只覆盖真实栏杆，入口必须保留明确缺口；坡脚、平台和坡顶应轻微重叠，不能留下角色胶囊会撞住的竖边或缝隙。
5. 对低于项目镜头净高的楼板/楼梯标注 `camera_clearance` 或同等元数据，供游戏包装采用专用镜头规则；不得依靠删除遮光面解决镜头问题。
6. 建筑组件、栏杆和屋顶默认真实投影。只有明确的编辑器参考、预览辅助或纯UI几何可以关闭投影。
7. 同一母版同时保留制作组件与独立输出根；每个模块有稳定资产ID、局部原点、尺寸、方向和版本。渲染整包预览，并分别核对每个输出根包围盒。

## 材质角色基线

| 角色 | 金属度 | 粗糙度 | 清漆 | 用途 |
|---|---:|---:|---:|---|
| 精工金属 | 0.80–0.92 | 0.22–0.32 | 0.10–0.25 | 框架、护边、螺栓、轨道、工具 |
| 细腻哑光 | 0.00–0.05 | 0.62–0.78 | 0 | 大面积喷漆板、橡胶、桌面 |
| 清漆反光 | 0.10–0.25 | 0.10–0.18 | 0.55–0.80 | 屏幕玻璃和焦点装饰 |
| 柔和自发光 | 0 | 0.30–0.45 | 0 | UI图形与灯带，通常强度1.0–1.6 |

不要仅凭对象名称中的 `screen`、`display` 或 `UI` 判断自发光；必须存在明确自发光材质或非零发光强度。

## 美术方向

- 使用深紫金属作为结构骨架，青绿或湖蓝哑光作为大面，紫粉反光作为小面积点缀，青色、橙色或黄色用于灯光焦点。
- 大面积主色控制在2–3种；高饱和暖色只作焦点。
- 参考面积比例：哑光45–60%、金属20–35%、反光8–18%、自发光不超过10%。根据物件结构调整，不机械套用。
- 避免近黑金属在常规环境中失去结构，避免自发光强度过高导致图形变白。

## 中文集合与命名

```text
物件名_中文资产管理
├─ 01_制作组件_已统一材质        （默认隐藏）
├─ 02_游戏输出_整合模型          （默认显示）
│  ├─ 物件名_主体_金属哑光反光
│  └─ 物件名_UI灯光_柔和自发光
└─ 90_展示环境_灯光相机          （可选）
```

多武器文件必须在源组件和游戏输出下分别建立每把武器的中文子集合。每把武器通常使用三个非自发光材质；只有真实灯光几何体才增加共享自发光材质。

## 交付内容

- 可维护 `.blend` 源文件。
- 含整合输出集合的 `.blend`。
- 公共512×512色盘只交付一份固定路径引用；单件资产不得附带色盘PNG。用户要求维护色盘时更新公共色盘及其分层PSD，不复制到模型目录。
- 近景和完整物件预览PNG。
- 材质数、输出对象数、删除的展示几何和验证结果。

实施或审核精确验收标准时，完整读取 [references/specification.md](references/specification.md)。

验证命令：

```powershell
blender --background "asset.blend" --python "scripts/validate_game_prop.py" -- --max-materials 12 --shared-palette "<项目>/assets/art/shared/palette/设施低亮多巴胺色盘_10x10_512.png"
```

多资产总合集没有单一 `02_游戏输出` 集合时，使用 `--all-meshes` 对合集内全部网格执行同等严格验收。
