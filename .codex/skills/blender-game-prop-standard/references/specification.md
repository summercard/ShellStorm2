# Blender 场景、关卡组件与固定设施制作与交付规范

本规范不处理枪械、近战武器、可拾取道具或角色手持物。它们分别使用 `game-weapon-model-pipeline` 与 `game-prop-model-pipeline`。

## 验收目录

1. 输入与范围
2. 色盘与UV
3. 材质节奏
4. 结构与合并
5. 中文管理
6. 美术检查
7. 技术检查

## 1. 输入与范围

- 从原始 `.blend` 或用户明确指定的源模型开始。
- 识别固定主体、固定附件、UI、灯带、玻璃、展示地面、相机和灯光；确认可移动附件是否应拆为独立道具资产。
- `DISPLAY_Ground`、`Display_Plinth`、Backdrop 等展示物不得进入游戏输出。
- 不因删除展示底盘而删除物件自身承重底座、柜脚或桌腿。
- 若输入含整屋场景而任务只要求物件，排除整屋场景。

## 2. 色盘与UV

- PNG尺寸：512×512。
- 网格：10×10，共100个纯色格。
- 每格允许51或52像素，以整数边界覆盖整张贴图。
- UV层固定命名为 `PaletteUV`。
- 每个面保留为一个有面积的小型UV岛；不得把所有loop压成单点，否则难以在UV编辑器中选择和移动。
- 同一面的所有loop必须位于同一个色格，UV岛建议占色格宽高的45%–65%，并与色格四边至少保留约10%色格宽度的安全边距，避免采样到相邻色。
- UV岛允许在所属色格安全内区移动、缩放和旋转；不得跨格，也不得仅把传统大岛缩小后跨越多个色格。
- `PaletteUV` 必须同时设置为 `uv_layers.active` 和 `active_render`。打开UV编辑器时默认看到的必须是分布在色格内的可编辑面岛。
- 纯色色盘输出默认只保留 `PaletteUV`。若法线、烘焙或其它明确贴图需要第二UV，必须在资产台账记录用途，且第二UV不得成为活动编辑层或活动渲染层。
- 贴图节点使用 `Closest` 插值。
- PSD按色域分组并保留可新增色块的独立图层。
- 第10列为固定冷调灰阶栏：R1至R10从深蓝灰到浅蓝灰，推荐依次为 `#1B2533`、`#263242`、`#324052`、`#3F4F62`、`#4D5E72`、`#5D6E82`、`#718195`、`#8998AA`、`#A5B2C1`、`#C5CED8`；后续如调整明度，也必须保持冷色相和单调递增的明度关系。
- 颜色选择应形成主色、辅色、强调色和灯光色层级，不平均使用所有颜色。

## 3. 材质节奏

推荐共享材质名：

- `01_精工金属_紫色骨架`
- `02_细腻哑光_青绿大面`
- `03_清漆反光_紫粉点缀`
- `04_柔和自发光_UI灯光`

语义映射：

- Metal/Silver/Steel/Gunmetal/Frame/Edge/Bolt/Trim → 金属。
- Paint/Rubber/Vinyl/Wood/Worktop/大面积外壳 → 哑光。
- Screen/Glass/Tinted/Lens/Glossy accent → 反光。
- 明确的 EM/Emission/Glow/Neon/LED/Light strip → 自发光。
- `screen`、`display`、`UI` 名称本身不足以判定自发光。

避免以下问题：

- 金属度1.0且环境无反射，导致整片发黑。
- 所有粗糙度集中在0.25–0.40，导致统一塑料感。
- 自发光强度4–7导致颜色泛白、细节消失。
- 为每种颜色建立材质球，导致枪械拥有几十个材质。
- 源组件继续引用旧材质，使下拉列表残留无效材质。
- 材质 UV Map 节点没有显式读取 `PaletteUV`，导致 Blender 与 GLB 导出读取不同UV层。

## 4. 结构与合并

- 先对修改器求值，再创建游戏输出网格。
- 记录每个面的材质分类，再清空/重建材质槽；清空材质槽会重置面索引，必须恢复。
- BMesh合并前保存面材质计划，`to_mesh` 后按面恢复。
- 主体删除自发光面；自发光网格只保留自发光面并重映射到槽0。
- 删除无连接顶点。
- 主体最多三个非自发光槽；自发光模型只保留一个槽。
- 合并后检查顶点数、面数、UV层和材质索引是否一致。
- 输出模型中心对齐X/Y，底部位于Z=0。

## 5. 中文管理

- 文件、顶层集合、源组件集合、游戏输出集合和主要对象使用中文。
- 原始制作组件与游戏整合模型放在不同集合。
- 原始制作组件默认隐藏；游戏输出默认显示。
- 自发光输出必须能单独隐藏、选择和导出。
- 多件武器时，每件武器拥有独立中文集合。

## 6. 美术检查

- 近景检查金属高光是否清晰但不过曝。
- 哑光大面应有柔和渐变，不出现镜面硬亮斑。
- 反光材质只作为边框、玻璃和焦点装饰，不覆盖所有主体。
- UI灯光保留原色，不变白，不吞掉图形边缘。
- 深紫结构在常规Material Preview和正式灯光中都应可读。
- 大面积主色控制在2–3种；高饱和暖色仅用于小面积焦点。
- 从合集视角检查比例、重叠、裁切和完整显示。

## 7. 技术检查

- 文件总材质数默认4，硬上限12。
- 枪械整合模型通常每把3个材质；有灯光时最多4个。
- 不存在整份 `.blend` 都未引用的旧材质；源组件仍引用、但整合输出暂未引用的材质不算废弃。
- 游戏输出每个网格都有 `PaletteUV`。
- 游戏输出每个面均为具有非零面积的UV岛，且全部loop位于同一个10×10色格的安全内区。
- `PaletteUV` 是当前编辑层和活动渲染层；材质 UV Map 节点只读取 `PaletteUV`。
- 除资产台账明确登记的第二UV外，不存在活动的 `UVMap/UV贴图` 旧层。
- 不存在 `DISPLAY_Ground`、`Display_Plinth`。
- 主体和自发光网格独立。
- 外部色盘已打包，同时PNG/PSD保留在交付目录。
- `.blend` 能用目标Blender版本后台打开。
- 总合集所有交付集合默认可见。
- 总合集必须对全部网格执行逐面色盘UV与材质检查，不能因为没有单一 `02_游戏输出` 集合而跳过验收。
- 验证报告必须输出：有效色格内UV岛数/总面数、单点或跨格面、活动层、渲染层、额外UV、材质UV节点、Closest插值、已用/未用材质和输出集合；不得仅凭存在同名UV层判定通过。
