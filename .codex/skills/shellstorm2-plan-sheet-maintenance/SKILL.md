# ShellStorm2 关卡平面图纸维护

图纸不是手画的 SVG。**设计文档是数据源**，SVG 每次重跑生成。改图纸 = 改文档表格 + 重跑脚本。

## 管线原理（必须先理解，否则会改错地方）

```
docs/v0.1/design/远征关卡01设计.md
  §3.1 总表      → 房间尺寸 / 定位 / 房型       ┐
  §4.2 坐标草案  → 中心 (x,y) / 父房            ├→ scripts/render_expedition01_plan_sheet.py
  （支线坐标表）  → 支线房坐标（可选）           ┘        ↓
                              refs/expedition01/plans/*.svg + 总平面图.svg + 图集 HTML
```

- **禁止手改任何 SVG/HTML**（下次重跑就没了）。
- 改图纸的**唯一正路**：改设计页表格 → 重跑脚本。
- 几何真源是设计源 `source/art/whitebox/tower_zones/<id>/v001/data/floors/floor_00.json`，
  图纸只是**示意稿**（画的是 §4.2「示例版图」= 兜底样例）。实跑几何按种子现算。

## 五步流程

### 第 1 步 · 改设计文档表格

在 `docs/v0.1/design/远征关卡01设计.md` 里改：

| 要改什么 | 改哪里 | 脚本解析锚点 |
|---|---|---|
| 房间尺寸 | §3.1 总表「尺寸 宽×深」列 | `_table_after(md, "### 3.1 总表", ("编号","尺寸"))` |
| 房间坐标 / 父房 | §4.2 坐标草案表 | `_table_after(md, "### 4.2 坐标草案", ("编号","中心"))` |
| 支线坐标 | §4.2 同名表 | 仅 `SHOW_BRANCH_ROOMS=True` 时必需 |

**改尺寸时的连带**：非矩形房的 `variant_footprints` 顶点在脚本里（`build_details()` 内），
是真源 `room_templates/*.json` 的镜像 —— **改尺寸必须同时改脚本里的顶点**，否则图与表不符。

**改坐标想平移整版图**：平移量取「新版图包络中心 → 场地中心 (2.5, 2.5)」。
- ✅ 平移量必须是 **5 m 的整数倍** ⇒ 所有中心相位不变（奇数格宽房仍落 `5k+2.5`、偶数格宽落 `5k`）。
- ✅ 平移是刚体变换，**只改绝对坐标**：主路各段的**净距与共轴偏移逐段不变**，不影响机制
  （实跑首房锚点 `_snapped_origin_for(size)` 与 §4.2 样例无关，样例只在生成失败回退时用）。
- 平移后 `_overview_bounds()` = 包络 ∪ 场地框；若场地完全包住包络，并集恰 = 场地框 ⇒ 三者同心。

### 第 3 步 · 三重核验

**① 几何**（自己写核验脚本，从脚本切数据层）：
`exec` 脚本到 `"# ---- 总平面图"` 之前（数据层，不执行渲染），注入 `g={"__file__":…, "__name__":…}`，
然后逐项核对：全部落 5 m 网格 / 两两不重叠 / 相邻净距 / 包络 / 轮廓面积（鞋带 `poly_area`）/
设计页 §3.1 vs 脚本尺寸一致。取轮廓顶点用 `g["OUTLINES"][key]`（**不是** `r["verts"]`）。

**② 行尾**：产物必须全 CRLF、无孤立 LF/CR、无 BOM。
⚠️ 用 Python 数 bytes，**别用 `grep -c $'\r$'`**（本机 shim 下会假绿）。

**③ 目视**：Chrome headless 渲染后逐张看图。

```bash
chrome.exe --headless=new --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=3 --window-size=W,H \
  --screenshot=D:\ss2_plan_shot\out\NN.png file:///D:/ss2_plan_shot/svg/NN.svg
```
- W/H 取 SVG 的 `viewBox` 尺寸（先正则读出来）。
- ⚠️ **截图路径与 SVG 文件名必须纯 ASCII**：本机 Bash 下中文名 `cp` 会因编码报
  `No such file or directory`。做法是先 `shutil.copyfile` 到 ASCII 名再渲染。

| 节 | 要同步什么 |

| §4.2 | 坐标表；包络；若平移了要写**版本变化**段（说明平移量与「不影响机制」的理由） |

非矩形房**真面积**另用鞋带公式算，单列一行（`poly_area(OUTLINES[key])`）。

## 已知坑

1. **CRCRLF 陷阱**：脚本里 `XML_HEAD` 若自带 `\r\n`，再经 `write_text(..., newline="\r\n")`
   会把 `\n` 二次换成 `\r\n` ⇒ 拼出 `\r\r\n`。**XML 声明行只准用 `\n` 收尾**。
   自检要**同时查孤立 CR**，只查 LF-only 抓不到。
2. **画幅裁字**：详图画幅若按房宽定，窄房（30 m）装不下底部说明行 ⇒ 会被裁。
   解法：文字宽度粗估（全角 `size`、其余 `0.56*size`）登记进 `_FOOT` 列表，
   `detail_svg()` **先空跑一次 `inner`** 取回说明行，再定画幅 = `max(房宽, max(文字宽)+18)`。
3. **详图配色按「房型类别」定，不按「主路 / 支线」定** —— 支线是**一条边的属性**，不是房型属性，
   同一详图只能一色。图例按**实际绘制集合**过滤（不绘支线就别列支线色块）。
   （注：支线已于 2026-09-25 裁定取消、本关已无支线房；该规则对**将来复用本脚本的关卡**仍成立。）
4. **`verify.py` 的「共轴偏移」列是主轴距离**（沿连接轴的房间间距，量级 30~50 m），
   **≠** 设计页 §4.2.1 的「共轴偏移」（垂轴错位，0 或 2.5 m）。同名不同义，别混用。
5. **`floor_00.json` 与 §4.2 不同步是常态**：`floor_00.json` 只提供拓扑蓝图（key/role/parent_key）
   + 兜底样例，实跑几何按种子现算。**改图纸不要顺手改它**，除非本轮就是要落设计源。
6. **房型 id 名嵌旧尺寸**（`db_70x50` / `office_60x70`）：缩尺后名不符实，但
   **id 是锁定集合、非主人明示不得改名/新增/删除**。「同一房型的另一摆法」用 `template_rotation_deg`。

## 场景 · 删掉一整类房间（实例：2026-09-25 支线取消）

**先跟主人确认改动边界**：只动文档，还是连设计源 / 代码 / 验收一起删？本轮裁决是
「**先处理文档内，实际制作时再删**（很多房间的数据要重新整理）」⇒ 于是
`floor_00.json` / `level_plan.json` / `verify_*.gd` / `room_templates/*.json` **一律不碰**，
文档改成 **「目标值 vs 现状值」成对写**，并保留一段**裁定块**说明为什么本页与设计源暂时不一致。

**① 设计页连带清单（漏一处就是自相矛盾的文档）**

| 节 | 要改什么 |
|---|---|
| §2 顶部 | 新增裁定块（谁定的 / 改什么 / 只动文档 / 哪些文件暂时不动） |
| §2 读法 · 流程图 · 主路段 · 命运卡段 | 房数、门数、构筑次数、旧口径标注 |
| §3.1 | **删该类房间的表行**；抬头注；面积合计与占用**重算** |
| §3.1.1 | 「实例次数」注（按剩下的房间重数） |
| §3.2 | 每间房的「本关作用」里去掉对该类房间的引用 |
| **该类房间的专节** | ⚠️ **不删标题、不重编小节号** —— 压成「…（已取消）」短节（理由见 ②） |
| §3.4 / §4.1~§4.6 | 抽取口径 / 边数 / **门表** / 内容分配 / 随机性边界里的该类房间 |
| §4.7 | 参考数字表（面积 / 轮廓 / 内墙 / used / 占用比）**全部重算** |
| §5 · §5.1 | 「不做什么」表行 + 专节改「已取消」 |
| §6 · §7 | 注意事项；§7 各条改「目标 vs 现状」 |
| 历史「版本变化」段 | **保留**（是留痕），但加一句「本段记的 X 变化已于 … 失效」 |

**② 为什么整节删除时「保号不重编」**
`§3.4` / `§5.1` / `§7.1` 这些编号被正文交叉引用几十处。删掉 §3.3 会让后面全部顺移、
原来指向 §3.4 的引用静默指到错节 —— **没有任何门禁能抓到**。做法：**标题留号**，
内容压成 3~5 条要点（取消依据 / 次数不变 / 池子不变 / 指向裁定块）。

**③ 图纸脚本的连带（20+ 处，极易漏）**
设计页表格变了脚本固然要重跑，但**脚本里硬编码的输出文案不会有任何解析器提示**：
SVG `<desc>`、meta 结构行、图例过滤、各段 `lede`、**门数段**、明细表 cap、面积 cap、
「待确认项」列表、页脚 —— 外加**死代码**（该类房间的绘制函数、别名、`extra` 文案、未用的 HTML 表）。
漏掉它们，图集里就还留着「4 间支线房…」这种话。

## 批量改文档的稳妥范式（54 处一次过）

逐条手工 `Edit` 匹配长段落极易漏字/错字，且失败一次就要重来。改用**带命中断言的替换脚本**：

```python
raw  = io.open(MD, "r", encoding="utf-8", newline="").read()  # newline="" 保住原始行尾
text = raw.replace("\r\n", "\n")                              # 折成 \n 再匹配
assert "\r" not in text
bad = [(l, text.count(o)) for l, o, _ in EDITS if text.count(o) != 1]   # 每条恰好命中 1 次
if bad:
    raise SystemExit("未命中，不写盘")                          # 全中才动笔
for _, o, n in EDITS:
    text = text.replace(o, n)
io.open(MD, "w", encoding="utf-8", newline="\r\n").write(text)  # 回写即全 CRLF，天然不出 CRCRLF
```

写完再跑一次「**残留自检**」：列出仍含该关键词的行并逐行打印，确认剩下的**全是**
「已取消 / 已失效」的留痕，而不是漏改的正文。
