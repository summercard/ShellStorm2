# 竖直构件做双面装饰（镜像派生）

## 适用边界

- **适用**：竖直构件只有一面有装饰、但**两侧都会被玩家看到** —— 门墙夹在房间与走廊之间、走廊两侧的墙、房间之间的隔断。目标是**把「一面是素板」这个视觉缺陷从资产层消除**，不是把它藏起来。
- **不适用**：新建或重制资产本身（→ `blender-game-prop-standard` / `godot-model-asset-import-standard`）；房间从白模起做正式美术（→ `scene-full-pipeline`）；把房间装饰剥离并入通用组件（→ `scene-art-merge-into-shared-component`）。
- **先判需求，再动手**：只有两侧都会被看到的件才需要双面。**不夹在走廊两侧的件（只朝房内的实心墙、L 墙角）保持单面** —— 无脑双面会白翻一倍面数。范围先和主人确认（本先例主人原话：「是门墙要做成双面的，其它先不用」）。

## 第 0 步：先证明「缺陷真的存在」

**不要凭猜认定「另一面是素板」。** 用两层只读探针量出来：

1. **几何分层侦察**（Blender 侧只读脚本）：把网格按「相对结构面的位置」分类统计 —— 结构面前侧装饰面 / 背侧与隧道面 / 跨平面面。这一步同时回答「镜像的切割平面该设在哪」。
2. **画面取证**（Godot 侧，真渲染器）：从正面与背面两个机位各拍一张，量**局部细节能量**。素结构背与装饰面的能量差通常是数量级（本先例实测 0.0004 vs 0.0015，约 4 倍；侧向镜面后两侧都回到 0.0015/0.0018）。

> ⚠️ **若既有探针里已经写着「单侧能量 ≫ 另一侧」这类判据，它本身就是一张「一面可以是白板」的许可证** —— 那是给缺陷留位置，不是验收合格。见到它要主动提出改向。

## 第 1 步：只镜像装饰面，**绝不镜像整物体**

在派生脚本里新增 `mirror_decoration()` 阶段，位置**排在朝向烘焙（yaw）与三角化之后、朝下剔面之前**：

1. 复制网格；
2. 在副本上删掉 `y > −(结构面 + 2mm 容差)` 的面，**只留结构面前侧的装饰面**；
3. 在副本上加 **Mirror 修改器**，绕**基准面**（网格中心线）翻转；
4. 应用后与原网格 `join`。

三条硬约束：

- **整物体镜像不可行。** 门洞隧道、背壳这类几何横跨基准面，整物体镜像会 ① 与保留的几何**共面闪烁**（z-fighting）② 把门洞/开口**复制成两条**。必须先按结构面切掉，只翻装饰那一份。
- **Mirror 必须 `use_mirror_merge = False`、`use_clip = False`。** 开合并会把横跨基准面的面粘到基准面上；开裁剪会把它们钉死在平面上。两项都关掉之后，**修改器自己会翻转绕向**，镜像面法线朝外 —— **不要手工 `flip_normals`**。
- **镜像阶段必须排在朝向烘焙之后。** 这样镜像是在已经对齐运行时朝向约定（例如塔楼 A 套 `forward_axis = +Z`）之后发生的，结果是**真镜像（z → −z）**，而不是旋转 180° 复制一份。顺序颠倒会得到「看起来对、实则旋转」的资产，朝向闸查不出。

## 第 2 步：开口绝不能被镜像面堵死 —— 射线从两向扩到三向

镜像有可能把开口盖住，所以开口判据要**加一条贯穿厚度的射线**：

| 射线 | 方向 | 期望 |
|---|---|---|
| `±X`（或开口内水平两向） | 开口内部水平 | 命中于半净宽处 → 净宽 |
| `+Z`（或开口内部向上） | 开口内部向上 | 命中于净高处 → 净高（有门楣就是门楣底） |
| **`±Y`（贯穿厚度）** | **沿墙体厚度方向** | **两向都 `null`** → `clear_through_thickness = true` |

第三条专门证明「厚度方向没有任何面横在开口里」。把净宽/净高与运行时的开口常量（如 `TowerGeometry3D.DOOR_CLEAR_WIDTH_M` / `DOOR_CLEAR_HEIGHT_M`）及脚本碰撞代理**逐值比对** —— 一致就说明**运行时代码一行都不用改**。

## 第 3 步：对称性验证 —— **禁用「面色心」**

这是本流程最容易踩死的地方。

**症状**：断言报几百条「不对称」。本先例中：按面色心排序后逐项 `zip` 比 → 误报 **911 条**；改成容差桶贪心匹配 → 仍误报 **29 条**；逐条对拍才发现**两侧顶点位置的多重集完全相同（差异 0）**，那些「未匹配」行的最近邻 `dpos = 0.000000`。

**根因**：镜像后的顶点存 **float32**，色心与法线会与「原面」差约 **1e-5**。

- 差值只要在末位处翻转，**排序后的逐项 `zip` 就会整体错位** —— 那是排序错位，不是真的不对称；
- 容差桶的贪心匹配**本身不保证传递性**，遇到本来就存在的完全相同的孪生面时会假阳性。

**改用两个对 float32 逐位稳定的不变量**：

| 不变量 | 定义 | 为什么稳定 |
|---|---|---|
| **顶点位置键多重集** | 把每个面的顶点位置打包成键，比较两侧多重集 | 镜像只翻 `abs(y)`，键**逐位精确** |
| **有向面积（向量面积和）相对偏差** | 比较两侧的面有向面积和 | 抓「面反了」：绕向没翻正 → 法线朝内、背面渲染不可见，但面积**绝对值**不变，只有**有向**面积能抓到 |

判据：`position_key_mismatches == 0`、`area_delta <= MIRROR_AREA_REL_TOL`（1e-3 量级）。

**外加一条硬判据：跨侧共面孪生 ≈ 0。** 镜像面只要与保留几何共面就会闪烁。注意源本身可能就有共面孪生（薄片双面写法很常见，本先例 132 组），镜像后应恰好 **2×**（264 组），**新增必须为 0** —— 判据要比的是「新增」而不是「总数」。

## 第 4 步：零面积退化面会让计数类断言摇摆

源文件里常混着**零面积面**（`area < 1e-9`，本先例 24 个）。零面积面的**法线是数值垃圾**，用它做「朝下面」分类时，这些面在**存盘/重载之间会来回跳** —— 实测朝下面计数在 **1367 / 1368** 间摆动，让保留类断言偶发假红。

处理：

- 统计前加 `DEGENERATE_AREA_M2 = 1e-9` **跳过退化面**并单独报告 `degenerate_zero_area_faces`；
- 计数类断言加小容差（本先例 `DOWN_FACE_COUNT_TOLERANCE = 4`）；
- ⚠️ **关键结构件（门楣等）的存在性不要靠计数证明** —— 用开口射线测出的净高（`clear_height_m = 2.5`）**精确证明**：没有门楣底面就测不到这个高度。

## 第 5 步：包络与 prefab 声明 —— 只动「可视」字段

- `bounds_size_m`（结构/阻挡）**不动**；`visual_bounds_size_m` 由单面深度改为双面全深（本先例 `0.4915 → 0.683`，`z ∈ ±0.3415`，关于基准面对称）。
- prefab 补 `metadata/double_sided = true`，并复核 `asset_version` 与稳定 GLB 路径（路径不带版本号，原地覆盖）。
- 核对「可视包络关于基准面对称」：`|z_min + z_max| ≈ 0`。

## 第 6 步：探针判据**必须跟着改向**

改完资产不改判据 = 留着假绿。把既有探针里所有「单侧强于另一侧」的判据换成**双侧可比**：

| 旧口径 | 新口径 |
|---|---|
| `DETAIL_RATIO_MIN = 1.5`（房内侧 ≫ 外侧） | `SIDE_DETAIL_MIN`：**两侧都**必须达装饰级（用素背与装饰面的实测值夹出阈值） |
| 「外侧应当是一块平整的板」 | `SIDE_RATIO_MIN / MAX`（如 0.5 / 2.0）：两侧能量比必须回到 1 附近 |

同时把其余探针的期望包络、以及新增的「关于基准面对称」「prefab 声明 `double_sided`」两条断言一起补上。

## 第 7 步：画面取证（两张表 + 一次对拍）

1. **亮/细节表**：四机位各重拍一次，与改前的数值并列。关键行是「另一侧」从素背级跳到装饰级，以及**两侧比值回落到 1 附近**（本先例 4.247 → 0.829）。
2. **像素比对表**（`scripts/png_diff.py`，中央 3/4 区域）：① 「原装饰侧」改前 vs 改后 → 应当**几乎同一画面**（证明没伤到原有那面）② 「镜像侧」改前 vs 改后 → 应当**不同画面**。
3. **镜像性对拍**（自写小脚本）：把镜像侧的图**水平翻转**后与正面图比。镜像正确时翻转后的差异应显著变小；对照组（改前的素背板）翻转前后应当**毫无变化**（素板翻转等于没翻）。本先例：`1.59 → 0.96/255` vs 基线 `2.75 → 2.73/255`。
4. **肉眼铁证**：图上带文字/图标的位置会**左右翻转**（标牌、警示三角、警示条）—— 这是「镜像」而非「两面各画一遍」的直接证据。
   > 翻转后仍会有小残差，来自**照明不对称**（键光/补光强度与角度不同），不是几何差异。别把残差当失败。

## 第 8 步：台账 —— **升级既有行，只动变化的格**

- AssetID 已存在 ⇒ **升级那一行**，新增行会报 `duplicate_asset_id`。
- 只改真正变化的列（版本 / 规格 / 派生链路 / 哈希 / 来源性质 / 备注）。
- **稳定路径没变就原样回写**：这样该格字节相同、**不会出现在「变化单元格」清单里**。复核脚本要把这写成**预期**，否则会被误判成漏改。
- 补丁用**外科式 XML**（只替换 `xl/worksheets/sheetNN.xml`，其余 zip 条目逐字节复制），先 `--dry-run`；补丁后复核：`zip testzip` 干净、`dimension` 与行数不变、目标行哈希与磁盘文件**逐字符一致**、范围引用公式原样。
- 分账门禁的预期增量：**某行第一次被改**才 +1 条 `row_content_mutated`；**重复改同一行不再累加**。所以若这一行在上一轮已经改过，本轮应当是 **+0**。

## 环境与跑法（Windows + Godot 本机）

- 门禁**一律按场景跑**：`--scene res://tests/verification/<名>.tscn`。
  ⚠️ 用 `--script res://.../<名>.gd` 跑**引用了 autoload 的项目脚本**会报一串 `Compile Error: Identifier not found: AudioManager/RuntimePerformanceManager/...` —— 那是 `--script` 模式下 autoload 未注册，**不是脚本坏了**，别顺着这个错误去查 autoload。
  （`_scratch/` 下 `extends SceneTree` 的**临时探针**不碰 autoload，可以用 `--script` 跑。）
- 前置 `export PATH="/c/Program Files/Git/usr/bin:$PATH"` 后 coreutils 就齐了，`scripts/run_verification_suite.sh scene <名>` 可直接跑（它自己注入 `use_custom_user_dir` 做隔离并清理）。
- ⚠️ **手动注入过 `config/use_custom_user_dir` 后必须确认 `project.godot` 没留残留**（`git diff project.godot`）—— 残留会让**下一次**直跑行为异常，排查时极易误判。`project.godot` 是 **LF**，其余 `.gd/.tscn/.md` 是 **CRLF**，改完要复核行尾纯度。
- 用 Python 跑表格工具（openpyxl）请**在项目根**用项目 venv：本项目上级目录有一个 `inspect.py` 会**遮蔽 stdlib `inspect`**，在它下面跑 openpyxl 会炸 `ModuleNotFoundError: bpy`；且只有项目 venv 装了 openpyxl。
- 画面验收**必须** `scripts/png_diff.py` 像素比对，**别只信 `*_OK`** —— 包络 / 面数 / 材质角色 / 原点约定四类断言对「一面是白板」全都全绿。
