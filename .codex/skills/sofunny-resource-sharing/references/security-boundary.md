## 链接是什么

发布结果是**内网能力链接**：拿到完整 URL 的人都能读取或下载，没有登录、没有鉴权、没有访问名单。

- 公开域名走 HTTPS（443），传输加密并下发一年 HSTS；明文 80 端口只做 301 跳转。
- 加密不等于鉴权：URL 一旦转发出去（含转发到内网之外），内容就等于对那个人开放。
- 链接里的 Site ID 是可读的「项目名-日期-时间戳」，**不含随机串、可以被猜**。不要靠 ID 保密来保护内容。

因此**不得发布**密码、客户隐私、商业机密、生产数据或任何需要权限控制的材料。

## 发布链路不做内容检查

客户端与服务端**都不读内容做判定**（2026-10-08 起连「扫描后写审计日志」也已移除）。这意味着：

- 文本里的 API key、token、连接串不会被识别；
- 压缩包里的 `.env`、签名文件、内部资料不会被识别；
- 不会有任何提示、拦截或「覆盖度告知」。

发布内部构建产物（APK、安装包、内部文档）就等于**对链接可达的所有人开放该产物**。

保留的只有四条**非内容类**约束：后缀与文件名白名单、路径安全、归属校验、包体限额。它们保护的是服务器与其他人，不是替发布者审内容。

## 会被排除的文件

打包时按**后缀与文件名白名单**跳过（宁可漏发也不误传）：

- 隐藏文件与隐藏目录（`.` 开头）
- 符号链接、版本库目录（`.git` 等）、依赖缓存（`node_modules`、`__pycache__`、`.venv` 等）
- `.env` 及 `.env.*`、`credentials`、`id_rsa`、`.npmrc`、`.netrc` 等按文件名排除
- `*.key`、`*.pem`、`*.p12`、`*.pfx`、`*.db`、`*.sqlite` 等按后缀排除
- 不在允许后缀列表内的文件（会被跳过并在结果里以「已跳过」列出）

这条白名单只挡得住「文件名和扩展名」，挡不住内容：改名为 `.txt` 的私钥照样会被上传。

## 上限

| 项 | 默认 | 说明 |
|---|---|---|
| 单次文件数 | 5000 | `--max-files` 可在服务端调整 |
| 单次总体积 | 2 GiB | `--max-upload-mib` 可在服务端调整 |

上限由服务器通过 `/api/v1/health` 公布，客户端取本地与服务端的较小值，**上传前**就拦下超限的包。上传分块流式，两端内存占用与包体积无关。

## 归属隔离管什么、不管什么

**管**：站点部署时把 token 的 label 记为 owner。`server-sites` 只列出自己部署的站点，`remove-server`、原地更新与单站点查询只对自己的站点生效，非 owner 一律 404（不泄露存在性）。

**不管**：读取。归属隔离只约束管理操作，站点通过 `/<site-id>/` 或 `/<site-id>.<后缀>` 对外提供，任何拿到完整链接的人都能访问。所有站点共享同一 Origin，不是租户隔离。

## 发布前自查

1. 这个包/页面能不能给全公司看？如果不能，不要用本方式分享。
2. 目录里有没有 `--root` 之外的无关内容？（单文件发布默认只发那一个文件；整目录发布要人工确认）
3. 资源用相对路径了吗？`/assets/app.css`、`<base href="/">` 会绕过 `/<site-id>/`，在分享链接上打不开。
4. 需要控制传播范围时，找 IT 在防火墙/网关限制来源网段，而不是依赖链接保密。

## 服务端细节

服务器安全模型与剩余风险见服务端仓库 [sofunny-resource-sharing-server](https://git.sofunny.io/skill-libs/sofunny-resource-sharing-server) 的 `references/server-security.md`（部署 API 鉴权、管理后台、TLS、运维建议）。

要点：部署 API（`10.41.0.2:41740`）与静态服务（`10.41.0.2:41739`）的内网 IP 直连路径是**明文**，同网段可嗅探；分享链接一律用公开域名（HTTPS）。
