# 11 远征03｜场景工坊布局与陈设

只处理 `block_id=expedition / level_id=expedition_03` 的已登记正式房间。先定位ShellStorm2项目根；本文工程路径均相对该根，不相对Skill安装目录。用户新指示优先，既有授权内持续完成。

## 从哪里开始

读取 `docs/v0.1/11_远征03场景工坊布局与陈设流程.md`，它是此流程的项目文档；设计规则以 `docs/v0.1/design/远征关卡03设计.md` §7.5.2–7.5.4为准。另读项目AGENTS约定、`docs/README.md`、`docs/DOCUMENTATION_STANDARD.md` 与 `docs/ART_SOURCE_LAYOUT.md`。

读取流程中的当前引用链、范围表和验收段。按实际任务选择房间；没有指定房间、但授权自行选房时可以选，向用户说明。不能把“18份资源”当单局房数，也不能把“上一轮已通过”当当前结果。

## 必须保持的边界

开工先读场景账本《房间运行登记》的“本轮制作状态、后续维护策略、保留登记日期”。已制作完成且标记默认保留的文件，自动选房、美化、批量布置、重烘焙一律跳过；仅用户本次明确指定该文件返修时才修改并更新记录。当前入口15×15、事件25×25、大堂45×40三份默认跳过。“继续任务/再选几间/全部美化”不视为返修授权。若保留快照与原验收SHA不同，保留两者并标注待核对，不覆盖当前文件或批量接受新哈希。未读到账本先只读核查，不猜测可覆盖范围。

- 工坊列表与游戏加载的是同一正式TSCN。用 `tools/scene_builder/scene_index.gd` 的 `game_rooms()` 和 `RuntimeRoomArtSource` 反查当前路径，不复制种子房间，不改旧文件名中的历史指纹。
- 编辑前运行本Skill的 `scripts/check_room_scope.py --project-root <root> <目标TSCN...>`。它只准远征03运行房间目录且metadata归属为03；其他关卡不能套用。不要修改远征01资源/配置或00–04通用Skill。
- 作者保存组件实例、父子Transform、启用、灯光、碰撞；门位/门墙和当前底层地砖由既有装配器负责。地砖会重建，不能声称只改静态地砖就能改变游戏。需要改生产逻辑时先说明具体缺口、影响和独立范围，本Skill不授予这类代码修改权。
- 复用已验收稳定PackedScene，默认单位缩放；原点/材质/碰撞定义归组件。缺组件或导入证据时按已有02b导入规范处理，不临时造几何、整屋GLB或复制共享资产。
- Godot直接编辑原正式TSCN。先备份，保留未授权节点与并发手改，不调用整屋烘焙器覆盖布局；设置新增组件根owner，不展开Prefab内部节点。

## 构图与摆放

以“墙边有层次，中部能走能战斗”为起点：书架/柜体形成高低节奏，窄桌、画框、黄铜灯饰、植物衔接；沙发/扶手椅/圆几/花器组成会客岛；红毯组织功能区和视线。按参考图与实际房型设计，不把整幅套间参考硬塞进单间。

易碎件使用“共享 / 易碎陈设”的五种现有Prefab：罐、瓶、书本堆、椅、木箱。沿墙无门段和非通道角落成组，穿插柜架旁；当前用户偏好约90%在外围，中部少。24/48/96件、8/12/20组柜架是上一批大中小案例，不是所有房间配额。按可用净空调整，宁可减少或换组合，不能塞进门口。

用 `RoomArtLayoutContract` 查询全部合法门位净空，不只查样本种子的门。逐件校验视觉包络、真实碰撞树/完整父变换、家具互穿和射击角度。易碎件虽不挡玩家，也不能覆盖门口或被家具封住。地面按实际走行面贴合，当前公馆地砖顶面0.10m；不要把旧夹具的0标高机械套用。易碎件优先落地，叠到台面会受现有碎片落地方式限制。

## 验收入口与数据保护

测试前读 [references/verification.md](references/verification.md)。通过 `scripts/prepare_isolated_project.py` 建立工程外测试工程：显式写入两个用户目录设置，先运行生成的guard，核对 `OS.get_user_data_dir()` 和 `BaseManager.save_path`，guard成功才运行测试。`test_mode`、创建目录或字符串替换未命中都不等于隔离；并发case各自独立。

至少完成：正式资源/原布局保留检查、全部合法门位与家具碰撞检查、跨种子加载/流送、真实子弹破碎及房间状态账/新实例恢复、原生游戏内玩家开火与接触、破碎前/飞散/落定和完整构图截图。不得直接调用shatter后声称玩家枪击验收通过。物理帧与墙钟时间分开，headless不能替代画面。

## 收尾

仅更新本批房间在场景账本《房间运行登记》的路径/数量/SHA和布局页摘要，易碎受击体不混算家具阻挡碰撞；共享模型未变就不改组件AssetID/版本/哈希。账本定位用 `assets/registry/ledger_index.json`。写独立开发记录、更新索引，列退出码、断言失败、脚本/渲染ERROR、未执行项与用户数据事故；整关状态不因美术专项通过而转完整。

当前流程、命令与验收细节均见项目流程文档和本Skill的验证参考。安装同步只处理本Skill目录，逐文件SHA一致，运行 `python3 scripts/check_expedition03_layout_skill.py --installed` 核查五处（单独clone默认不加--installed只查项目三处）；不全量覆盖其他Skill。
