# 基地 99 层美术场景编辑说明

日常关卡美术编辑请直接在 Godot 编辑器中打开主场景：

`res://scenes/TowerDescent3D.tscn`

在主场景树展开 `美术可编辑层/基地99层_美术布置层` 即可。运行时，代码会先隐藏该编辑层，再把基地实例重新挂到程序生成的 99 层房间。

`runtime/env_base_facility_art_layout_top3d_v001.tscn` 仍是可复用子场景，一般不需要单独打开。

## 可以安全调整

- `设施交互节点_可移动旋转`：移动、旋转现有设施。保留每个设施的 `facility_id`，不要改变根节点类型。
- `基地结构组件_可移动旋转`：直接摆放楼中楼楼板、L型楼梯、外门小楼梯，以及完整的100层上层围护与封顶组合Prefab。每个实例自带局部结构碰撞，移动或旋转时碰撞会同步。
- `场景装饰_可自由增删`：添加或删除纯视觉模型、贴花、粒子和无玩法用途的小道具。
- `基地美术灯光_可编辑`：保留旧版3盏美术灯的位置和参数作为历史参考，运行时默认停用。99F正式照明只允许代码生成的一盏中央主灯；不要重新启用或增加照射地板的OmniLight，设施状态使用自发光材质表现。
- `玩法锚点_只移动不删除/99层电梯锚点`：可移动或旋转，以改变 99 层电梯的位置与朝向。

## 编辑器参考

`编辑器参考_运行时自动隐藏` 提供 30×30 米地面和四面墙边界，只用于摆放参考。代码桥接在运行时会自动隐藏它，不会生成碰撞，也不会进入正式画面。

## 结构模块

基地外圈和地面由 `DungeonRoom3D.gd` 按稳定Prefab组合；室内楼板和楼梯则放在可编辑美术布置层：

- 地面：6×6个5米单元，普通板与铆钉铁皮板各18个，棋盘式交错。
- 99层外墙：14个普通墙、0个窗墙、2个带门墙；东、西门洞保持原玩法连接。窗墙只登记给100层上层围护，禁止放入99层外圈。
- 100层上层围护：从本地高度9米延伸到18米，共19个普通墙、4个北侧窗墙、1个东侧门墙。北墙严格为“两端普通墙＋中间四块窗墙”，其余墙面不放窗墙。
- 18米封顶：复用两种5×5米基地地板Prefab组成6×6、共36块屋顶；它属于独立组合Prefab，不恢复此前移除的99/100层中间36块楼板。
- 门扇：2个独立滑升门模型，只挂到既有 `RoomDoor3D` 动画节点下。
- 二层：一个约20×10米、完成面7米高的楼中楼楼板，Blender母版初始坐标为 `(5, 0, -10)`。
- 楼梯：L型楼梯初始坐标约 `(-9.58, 0, -9.15)`；外门小楼梯初始坐标约 `(12.74, 7, -7.5)`，不再附加90度旋转。
- 99/100层贯通：100层位于基地正上方的6×6、共36块地砖及对应承重碰撞已移除；99层自己的36块地面保留。

所有正式场景组件都接收光并产生投影：地面、墙体、门、楼板、楼梯、封顶及基地设施模型必须保持 `GeometryInstance3D.cast_shadow=ON`。阴影与物理碰撞仍是两套独立职责：一层地面、墙体、门使用原有Godot碰撞；楼板和两套楼梯由各自Prefab生成简化承重面。L梯使用两段斜坡加转角平台，外门小梯使用一段斜坡，避免逐级三角网格把角色卡住。

100层围护与封顶统一封装在 `ENV-BASE100-UPPER-SHELL-30X30-H9`。24块围墙和36块封顶仍是可单独移动、旋转或替换的子Prefab；组合根脚本只生成连续墙碰撞、东侧门洞框与18米屋顶碰撞，并统一启用投影。侧向门墙目前只登记并保留门洞，不新增门状态机；未来需要可开门功能时，再实例化现有Godot门组件进行组合。

低于9米的楼板和楼梯底部统一设置 `camera_stair_slab` 语义。角色从下方经过时，摄像机沿用99→98层楼梯间规则立即降低到结构底面以下；离开覆盖区后平滑恢复。不得用普通不可见大盒子代替这套规则，也不得把该标签放进GLB。

## 不要直接修改

- 不要删除或改写设施的 `facility_id`；菜单、存档和设施状态通过该 ID 桥接。
- 不要在装饰节点中加入看不见的碰撞盒；需要玩法碰撞时应建立正式组件并登记。
- 不要在该局部场景中加入 `WorldEnvironment`；塔楼全局环境仍由原架构管理，基地风格通过局部灯光、模型、贴花和粒子完成。
- 不要删除 `99层电梯锚点`；代码找不到时虽然会使用旧坐标回退，但编辑器布局将失去控制权。

## 运行时桥接

`TowerDescent3D._install_facilities()` 实例化该场景，自动发现八个 `BaseFacility3D`，连接原有激活信号，并隐藏编辑器参考节点。设施业务仍由 `BaseFacilityCatalog`、`BaseManager` 和既有菜单场景负责。

正式模型映射中，`保险柜` 复用赛博储物站模型，`命运卡收藏室` 复用复古游戏电视站模型。两者位于 `设施交互节点_可移动旋转`，允许在编辑器中调整位置和朝向，但不得移入纯装饰集合或清空 `facility_id`。

结构模型的正式入口位于 `assets/art/environments/base_facility_3d/runtime/`。后续美术只需更新干净Blender母版并运行 `scripts/blender/export_base99_runtime_modules.py`；保持GLB路径不变即可更新表现，设施、碰撞和门功能无需重新拼接。
