# 21:25 枪族弹体几何档位：每把枪的子弹大小做出区分

## 业主原话
「每把枪的子弹大小要做出区分，散弹枪要从小到大 有个过程动画 榴弹枪要大一点 狙击枪要长，其它可以暂时不变，完成后记录在账本里和设计文档里」

## 核心决策：加「第二层」，而不是改 8 个弹种 profile

改动前尺寸 = `弹种倍率 × 命运倍率`，**与枪身无关** ⇒ 同一发穿甲弹装任何枪都同一尺寸。若把枪的差异塞进 `_bullet_profile()`，就会破坏「弹种 = 唯一视觉源」的正交性（子类无法按枪返回不同 profile）。因此新增第二层：

```
最终尺寸 = 弹种 profile（长什么样）× 枪身族档位（多大 / 多长 / 有没有生长过程）
```

## 档位真源按「族」而非 gun_id

`WeaponModel3D.BULLET_GEOMETRY_BY_GUN_TAG`，键取枪身 `tags` 的族标识。理由：本仓已有 `if gun_id == "bp_launcher"`、`0.28 if gun_id == "bp_sniper"` 这类逐 id 硬编码，而武器账本已登记 16 把枪 —— 那套写法扛不住。按族登记后，未来系列的霰弹/狙击/榴弹只要打对 tag 就自动继承。

## 三条档位（其余枪中性，逐帧外观与改动前一致）

| 键 | 枪 | scale | axial | grow_from → 1.0 |
|---|---|---|---|---|
| `shotgun` | 散射喷壶 | 1.00 | 1.0 | **0.42 → 1.0 / 0.30s** |
| `launcher` | 反胃榴弹筒 | **1.55** | 1.0 | 不启用 |
| `sniper` | 弹弓狙击 | 0.95 | **2.0** | 不启用 |

- **「长」≠「大」**：`axial` 只沿飞行轴拉，横向不放大；狙击档横向同时收到 0.95（净长 1.90 倍），免得拉长后臃肿。
- **霰弹基准尺寸没动** —— 主人说的是「其它可以暂时不变」，霰弹本来一次 5 发散射，只加过程动画。
- 榴弹/狙击**没加**过程动画（主人只对霰弹提了）。

## 两个容易踩的坑（都避开了）

1. **轴向拉伸不写父级 scale**。父级非均匀缩放 × 子级旋转 = **剪切变形**，黑洞弹的 `spin` 尾迹旋转会立刻暴露。所以 `axial` 落各件**自己的局部长轴**（capsule 局部 Y＝长轴，节点自身转 −90° 后才指 Z），尾迹段距同步乘 `axial`（基准偏移记进 meta，否则段与段脱节）。同源问题见 14.6 §5.5.1 坑 3（弹壳）。
2. **生长包络必须确定性**。只读累计飞行时间，脚本内无 `randf()` —— 与弹壳随机化同一条纪律：被逐帧断言驱动的视觉对象必须确定。

## 追加轮次（23:05）：弹体减面到 100 面以内

主人原话：「减面，减到100个面以下先」

### 先实测再定档（这次没估算）

`CapsuleMesh` 的**圆头来自 `rings`**：`rings=0` 的「胶囊」= 平盖圆柱，24 面；同轮廓的 `CylinderMesh` 只要 16 面。而真圆头（`rings=1`）要 **48 面/件** —— 弹芯+外壳两件就 96 面，预算吃光。

⇒ **弹芯/外壳改 4 边棱柱**（`CylinderMesh` rs=4）：轮廓与 `rings=0` 的胶囊完全一致，只是更省。尾迹锥 rs=4（12 面），滴珠 `SphereMesh` → `BoxMesh`（16→12 面；滴珠世界尺寸仅 0.011~0.018m，球与方块不可分辨），黑洞/气球球核 `SphereMesh(12×6)` → `(4×1)`（16 面）。
