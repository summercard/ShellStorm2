# 12:35 远征01「安全屋被墙堵死 / 门洞封死」定位：`_backfill_rehomed_door_spot` 把活门位补成实墙

## 业主报障
「远征关卡01 无法正常游戏，安全屋直接被一个墙面挡住」；补充口径：**不是单纯首房错位，
而是有时可以有时不可以，后面房间也会错位**。截图 `关卡种子 286648852`。

## 结论（先给答案）
**不是版图错、不是种子错，是今天 11:39 的换房提交 `d6d3145b` 新增的补墙逻辑把活门位焊死了。**

- `d6d3145b` 在 `DungeonRoom3D._rehome_static_layout_door()` 末尾新增
  `_backfill_rehomed_door_spot()`：门墙件被搬到新门位后，**把原位用同侧实墙件复制一段补回**。
  意图是「搬走 = 原位留一个 5m 洞，可走出房间」。
- 但补墙**没有判断原位是不是本局的活门位**。实测补出来的墙
  （节点名尾缀 `_RehomeFill`）正好压在相邻两房共享的那扇门上 ⇒ **门被永久焊死**。
- 该机制在 `d6d3145b` 之前**不存在**（`git show HEAD~2:...| grep -c` = 0），
  所以是**今天新引入的回归**，与业主「之前能玩、现在不能玩」的时间线吻合。

## 修复（已实施并实测通过，**未提交**）
`_backfill_rehomed_door_spot()` 补墙前加一条守卫：原位是本局活门位就不补。

```gdscript
if not _authored_wall_connection_side(
	static_layout.transform * previous_position, half
).is_empty():
	return
```

判据用 `_authored_wall_connection_side`（「本局 doors + 门槽偏移命中」），**故意不看
`owns_door_endpoint`** —— 共享边由另一端持有时本端同样不能补，否则一样压住那扇共享门。

复测同样四个种子：被堵数 **7/6/5/3 → 1/1/1/1**，回到回归前基线。
剩下那 1 扇四个种子都是同一处 `room_09 → room_10`（被 room_10 自己的
`GenericShell_WALL_north_yp160_m42_5` 压住）——**旧版就有**，是另一条独立老问题，不在本次回归内。

## 教训
- **跨种子不变量要有一条会失败的断言盯着**：这套「预烘焙静态壳 + 运行时刚体对齐 + 门墙件搬家」
  链路已连续三次在「静默 + 只在某些种子现形」上翻车（09-27 首房包络、09-29 开口池、
  10-14 补墙压门）。门禁应加一条**逐种子门洞通行实测**（`probe_exp01_door_block` 可直接收编）。
- 搬走一件墙，**不能默认原位该变成墙** —— 原位可能正是另一扇门。
- 写「补墙」这类兜底时，必须先问：**这个位置在本局是不是本来就该有东西**。
