# 僵尸受击特效：换成「击中其它物体」那件同形 + 绿色 + 大 10%，命中点贴回模型（FX01-20 v002）

## 业主口径（本轮，逐句）

> 「小僵尸和警察僵尸的受击特效太大了，**使用击中其它物体的那个特效**，然后**改成绿色**即可，放大大概 10%」

紧接着补充：

> 「**而且会悬空**，受击的盒子没有贴着模型，碰撞盒里陷进去坐标大概 **0.2 米**」

这两条**各自独立**，都要落地：前一条管「造型与大小」，后一条管「出生点位置」。

## 改了什么

| 项 | v001 | v002（本版） |
|---|---|---|
| 造型 | 12 枚绿方块爆开（从死亡件抽出的 A 段） | **= FX01-21 金属火星那套**：5 颗方块 + 2 根长条火星 |
| 颜色 | 方块亮绿 | 方块亮绿 + **长条深一档绿**（两处都绿才是「改成绿色」） |
| 寿命 | 0.26s | 0.32s（跟 FX01-21 走，因为就是同一段身体） |
| 尺寸 | 独立定档 0.50 / 0.60 | **= 金属火星同档位 ×1.10**（0.374 / 0.462） |
| 朝向 | 全向对称、**刻意不消费** `normal` | **消费 `context.normal`**（与 FX01-21 同形） |
| 命中点 | 用物理相交点（落在碰撞壳表面） | 先过 `hit_effect_anchor()` **沿外法线反向收 0.2m** |

## 两个「不抄一份」的决定

### ① `VfxMetalSparkHit3D` 抽成共享父类，而不是拷一份改颜色

业主说的是「**使用**那个特效，然后改成绿色」—— 是**同一件东西换色**，不是「再做一个像的」。
如果各写一份，调火星长度时会出现「打墙的细长、打僵尸的又缩回一截」这种漂移，而且没人会立刻发现。

做法：父类只暴露 5 个覆盖点，子类写这 5 个就完了。

```
_asset_id()            -> "VFX-GOO-HIT-3D"
_asset_version()       -> "v002"
_cube_base_color()     -> GOO_GREEN_LIGHT
_streak_base_color()   -> GOO_GREEN_SPARK
_caller_color_blend()  -> 0.18
```

形状 / 件数 / 方向 / 尺度包络 / 外推曲线 / 长条拉伸**全部继承** ⇒ 逐字相同。

⚠️ 子类**不能**把 `CALLER_COLOR_BLEND` 重名声明 —— GDScript 不允许子类重新声明父类已存在的成员，
直接解析失败。所以子类里叫 `GREEN_CALLER_BLEND`。

### ② 尺寸不在特效里，由调用方按档位给

「放大大概 10%」写在调用方，不写在特效内部：

```gdscript
// Projectile3D
const METAL_SPARK_SIZE_TARGET := 0.34
const ZOMBIE_HIT_SIZE_RATIO := 1.10
const GOO_HIT_SIZE_TARGET := METAL_SPARK_SIZE_TARGET * ZOMBIE_HIT_SIZE_RATIO   // 0.374
```

这样以后调金属火星的档位，僵尸那条自动跟着走；也保住「1.0 = 规格尺寸」这条唯一口径。

## ⚠️ 近战那条才是「太大」的真正根因

近战命中件的 `size` 是 `(0.88 + 0.18 × 连段) × 暴击 1.18`，**0.88 ~ 1.6**。
那套数是按 **FX01-05 `VFX-MELEE-IMPACT-3D`** 的内部基准定的 —— 直接喂给**方块基准 0.16** 的火星造型，
方块边长会到 `0.88 × 0.16 × 1.15 ≈ 0.16m` 峰值，**糊住半个怪**。这正是业主说的「太大」。

修法：僵尸分支换自己的档位 `ZOMBIE_HIT_BASE_SIZE = 0.42`（+ `ZOMBIE_HIT_COMBO_STEP = 0.18`），
连段 / 暴击倍率不变。**枪击那条本来就没问题**（0.34 系），所以「太大」主要是近战在喊。

## 「悬空」的根因与修法

弹体是在**碰撞壳表面**判定命中的，而怪的碰撞柱是**玩法口径**、比模型胖不少：

```
EnemyAvatar3D.FOOTPRINT_PROFILES
  melee_chaser   r = 1.02, h = 1.30
  ranged_caster  r = 1.10, h = 1.62
  fat_zombie03   r = 1.10, h = 3.142857
```

源码注释写得很清楚：「碰撞 FOOTPRINT 仍由各 kind 的既有玩法口径提供，**不随美术替换自动收紧**」
（避免穿模）。所以特效从壳表面对面退 0.2m，很可能仍然离模型有一段距离。

修法（唯一旋钮）：

```gdscript
// Enemy3D
const HIT_EFFECT_INSET_M := 0.20
func hit_effect_anchor(hit_point: Vector3, surface_normal: Vector3) -> Vector3:
	# 沿**外**法线的反向收进去 0.2m；外法线缺省退回「怪体中心 → 命中点」
	return hit_point - outward.normalized() * HIT_EFFECT_INSET_M
```

`Projectile3D._spawn_hit_effect()` 里对 `Enemy3D` 一律先收；**墙面 / 掩体不收**（那里收了会钻进墙里）。

### ⚠️ 实测更正（2026-10-15 复查）：0.2m **不够**，初版是错的

> **本文件初版写的「退 0.2m 后离模型只剩 1cm，业主估得很准」是错的结论，已作废。**
> 那个数是在**斜前机位**下量出来的假象 + 拿**整只怪**的包围盒当「模型」量出来的。
> 侧视真渲染 + 按命中高度切片重测后，0.2m **仍然明显悬空**。

**根因：碰撞壳是玩法口径的圆柱（各向同性），模型是各向异性的。**

```
              碰撞壳世界半径   模型半宽 X / Z        正背面打时壳面比模型多出
小僵尸         0.714            0.448 / 0.334        0.27 ~ 0.38 m
警察僵尸       0.770            0.449 / 0.602        0.17 ~ 0.32 m
胖子僵尸       0.770            1.839 / 0.712        ← 反过来：壳面已在模型「里面」
```

⇒ **一个常数不可能同时满足三只怪 × 各个方向。** 胖子僵尸 X 向要求「往外推」，
小僵尸 Z 向要求「往里收」，两者的符号相反。

### 最终实现：按模型实测几何现算

`Enemy3D.hit_effect_anchor()`：

1. 取「**命中高度那一层的横截面**（X/Z）+ **全高 Y**」的世界包围盒；
2. 沿外法线反向射线，用**逐轴 slab 夹逼**求它**进入**盒子的距离 `travel`；
3. 退让 = `travel + 0.03`（摆到盒面上再咬进肉里 3cm）；
4. `travel == 0`（命中点已在模型内，胖子僵尸 X 向）⇒ **不推**。

实测（小僵尸正面，真渲染现读）：
```
壳半径 0.714 → 落点 0.302     退 0.412     落点在模型半宽 0.332 之内
画面：爆点从「圆柱壳外圈」移到「僵尸手臂上」
```

### 踩过的四个坑（都写进代码注释了）

| # | 坑 | 后果 |
|---|---|---|
| 1 | 用**整只怪**的包围盒 | 头顶丸子头 / 脚边件把 Z 半宽从 0.332 撑到 **0.622**，退让少算 0.29m。**解析读数说「距模型 0.000」，画面里明显在圆柱壳外圈** —— 判据与观感对不上就是这里来的 |
| 2 | 包围盒**做缓存** | 正式模型**异步挂载** ⇒ 缓存锁到「只有占位件」的那一版，之后永不重算。表现为「单测对、真渲染错」，两边永远对不上 |
| 3 | 用「盒心支撑函数」近似求退让量 | 支撑平面在盒子**角上**相切；命中点偏离盒心（命中高度 ≠ 怪体中心 Y）时，落点只在平面上、不在范围内 ⇒ 残留 **0.32~0.54m** 悬空 |
| 4 | 给退让量加「下限 0.20」 | 在「壳比模型窄」那一侧**继续往深处推** ⇒ 胖子僵尸 X 向被推深到 **0.912**，读成「从肚子里炸」。这个「下限」正是初版悬空的直接原因，也是初版埋人的原因 |

**另一个必须先修的前置 bug**：机位。第一版预览用**斜前机位**，0.2m 的深度差正好落在视线方向上
⇒ 两张对比图**肉眼看不出区别，等于没验**。改**侧视**（沿 +X 看回原点）才把 0.2m 摆到屏幕横轴上。
**教训：验「某个方向上的一小段位移」时，机位必须垂直于那段位移。**

### 判据必须双向

只判「落点在模型内」是**单向**的：把包围盒算大、或把退让量调大，落点埋得更深反而更容易判过 ——
**实测把包围盒故意算大 2.6 倍（去掉隐藏件过滤），单向判据照样全绿**。
所以验收两侧都钉：① 距模型 ≤ 0.05m（不再悬空）；② **不许比原始壳面命中点更深**（±0.05m）。

### 已知容差（如实记录）

模型包围盒按**轴对齐**算，而躯干是斜的 ⇒ 背面打时仍差约 **0.25m**。
下一轮可考虑改用「命中高度处的**水平最近顶点**」——顶点数很小（小僵尸 1543 / 胖子 1513 / 警察 16468），
逐顶点做一次变换完全付得起，且能彻底摆脱 AABB 的轴对齐误差。

## 验收

`verify_hit_routing_vfx` `samples 26 → 27`，五条新判据：

1. **两件同形双向对照** —— 同一 `size` 下 `cube_count` / `streak_count` / `node_count` /
   `cube_scale_max_x` / `streak_length_max` / `cube_pos_max_y` 逐项相等，且颜色**必须不同**。
   只比一边的话，两件一起漂移（例如都缩 20%）不会被发现。
   ⚠️ 绿色判据直接看颜色通道，**不读**被测脚本自报的 `green_dominant` 字段 —— 那个字段能被写死成 `true`，
   拿它断言等于自印证。
2. **贴肉落点三向判定** —— 给定法线 ⇒ 退 0.20m 且方向朝怪体内；换法线 ⇒ 落点必须跟着换；
   零法线兜底与给定法线一致。
3. 枪击路由里断言借出的那件**真的落在**「弹体位置 − 0.2 × 外法线」。
4. 静态门禁：`Projectile3D` 必过 `hit_effect_anchor` 且尺寸派生自 `1.10`。
5. 静态门禁：近战必用 `ZOMBIE_HIT_BASE_SIZE`。
