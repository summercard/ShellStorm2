## 本机 LFS 基线（重要，长期有效）

- macOS 这端**没有 git-lfs**，也没有 Homebrew/sudo；全局与仓库级 `filter.lfs` 全空。
- 但 `.gitattributes` 声明 `art_source/**/*.blend|*.psd filter=lfs` ⇒ 工作区里 **1284 个 .blend/.psd 全是 131 字节指针占位**
  （`git cat-file -s` 与文件尺寸相等，说明索引里本来存的指针，不是 smudge 失败）。运行资产走 `assets/`（普通文件），跑游戏不受影响，但本机打不开 Blender 母版。
- 判据：别用 `git lfs ls-files`（LFS 未安装时**静默返回 0 行**，会被当成"没有 LFS 文件"）；用 `head -c 20 <file> | grep git-lfs`。
  注意 `head -c 20` 只出 `version https://git-`，grep 完整串会漏判（本轮踩过的假负）。
- 要真取母版须先装 git-lfs（release tarball 解到用户目录 + `git lfs install --local`），`git lfs pull` 会一次性 smudge 1284 个文件，按 GB 排窗口，属独立任务。

## 14:4x 更正：走路"抽一下"的真因是光照阶跃，不是动画数据（上一段结论作废）

业主补了条件「在阴影下、受到手电光照时」。改判后的根因链与判据：

- `get_effective_move_speed()` 在 `artificial_light` 下**阶跃**乘 `ARTIFICIAL_LIGHT_MOVE_MULTIPLIER=0.40`；
  `Enemy3D._process()` 每帧把它当 `base_speed` 传给表现层当归一化**分母**。
- 分子 `get_real_velocity()` 由 `_steer_planar()` 以 `delta*3.2`（巡逻）/`delta*5.5`（追击）**指数衰减**。
  分母阶跃、分子衰减 ⇒ 手电扫到的那几帧比值冲过 `RUN_SPEED_RATIO=0.62`（实测 0.32→**0.77**）再落回 **0.61**。
- 段名翻两次（walking↔running，相隔 8 帧≈0.13s）；换段时 `_sample=fmod(_clock,段长)` 且无混合
  ⇒ 1.6s 走路段与 0.8s 跑步段把同一时刻映射到不同姿势 ⇒ **一帧硬拽骨骼**。
- 实测（手电每 1.5s 扫一次、15s）：每只各 **8 次**切换、全部落在光照翻转那一刻及其后 8 帧；
  单帧跳变最大 69.4°(小僵尸)/82.6°(警察)，中位 1.6° ⇒ 43~50 倍。这就是"朝一个方向抽一下"。
- **上一段"髋部锯齿"是同一症状的另一处，不是根因**；`running` 段干净、胖子走路干净这条对照仍然成立。

修法（已完成，未提交）：两份表现脚本加 `BASE_SPEED_SMOOTH_SEC=0.30` + `_smooth_base_speed()`
（`1-exp(-step/0.30)`，0.30 取自巡逻 1/3.2≈0.3125s），分母跟着分子一起回溯；稳态读数逐字不变。
**刻意不改**成"分母用不含光照惩罚的满速"——那会让被照着的追击怪改播走路段，属业主观感判断。
`get_presentation_snapshot()` 增 `base_speed` / `speed_ratio` 便于断言。

（8 帧跑步 + 54.9°）。`_egt_presentation_probe` 全绿。两只旧表现用例改前改后**逐项同红**（既有债务）。

## 15:1x 第二轮：第一轮没修好，真因是「换段硬切」（上一段的分母平滑只是其中一环）

业主："还是会这样啊，受到光照正常来说只会缩短角色的移动速度，和动画播放速度。"
⇒ 判据应改为「**根本不该换段**」，不是「比值要不要平滑」。

三条独立原因（第一轮只碰到①的表层）：
1. **相位被重置**：`_sample = fmod(_clock, 段长)` 用绝对时钟。走路 1.6s / 跑步 0.8s
   ⇒ 同一时刻映射到相差 35~67° 的姿势（中位 1.6°），`play()+seek()` 无混合 ⇒ 换段必硬拽。
2. **相位对齐不够**：走路手臂垂摆、跑步抬起，对齐后仍差 35~67°（落在 `L/R_Upperarm`）
   ⇒ 必须淡入。实测 `AnimationPlayer.play("running", 0.20)` 把换段当帧从 **60.4° 压到 0.0°**。
3. **警察僵尸全部段 `loop_mode=0`**（GLB 无 post-import 脚本，`import_script/path=""`）
   ⇒ 表现层 `_looping=false` ⇒ 相位恒 0 ⇒ **画面定格**（顺带修）。

改法（两份表现脚本同口径）：
- `_phase ∈ [0,1)` 归一化相位，跨段保留；
- 循环移动段之间 `play(name, CLIP_BLEND_SEC=0.16)` 交叉淡化；攻击/受击/死亡**不参与**
  （它们靠 seek 钉判定帧）；
- `_playback_rate() = 实际速度 ÷ 进段标称速度`（0.25~2.0 钳制）让**动画随减速变慢**（稳态 0.42×）；
- 迟滞 `RUN_EXIT_RATIO=0.50` vs `RUN_SPEED_RATIO=0.62`；
- `_ready()` 里把循环段 `loop_mode = LOOP_LINEAR`，不依赖导入配置。

实测：手电阶跃 8 次/69.4° → **0 次/2.48°**；强制 walking↔running 67.2° → **11.7°**；
真渲染逐帧像素差无单帧尖峰、开灯后 10 帧为平滑过渡。
验收：`verify_enemy_illumination_states` 新增「换段不许抽」断言（间隔须 > BLEND，12 帧=假红 21.3°），
改后 exit 0；回退 HEAD 三条同红（8 帧切跑步 / 56.4° / 63.7°）。`_egt_presentation_probe` 全绿。

### 三条硬坑（务必记）
- **`callback_mode_process = MANUAL` 下单独 `seek()` 不驱动骨架**！必须 `play()+seek()` 成对或 `advance()`。
  这一条让我一度以为修好了，实际画面定格（髋部高度恒定 0.3980）才发现。
- **同段时不能每帧 `play()`**：会重启动画并打断正在进行的交叉淡化（跳变 60°→64°）。
- **淡化期不能 `seek()`**：一 seek 就把姿势钉到新段，淡化白做；淡化期必须 `advance(delta)`。
