## 2026-10-31 打中怪物卡一下：材质 shader 变体开关代价

- 根因：受击闪白 `emission_enabled = _flash_time > 0` 是 **shader define（USE_EMISSION）不是 uniform**，每翻一次重建 GPU 管线（实测 +98~107ms），而闪白每次受击翻两次。改法＝常开 + 只推 `emission_energy_multiplier`（能量 0 与关闭出图逐像素等价）。命中帧差值 +82~107ms → 0.00ms。
- 同价属性表（真渲染 `--disable-vsync` 量出）：emission_enabled 107 / transparency 107 / vertex_color_use_as_albedo 109 / no_depth_test 105 / billboard_mode 94 / depth_draw_mode 86 / receive_shadows 77 / shading_mode 19；cull_mode 与实例级 transparency/cast_shadow 全 ≈0。规律＝进 `MaterialKey` 的位才是变体，不能按名字猜。
- 顺线查出：`EnemyAvatar3D._apply_formal_tint()` 旧实现无条件新 `duplicate()` override，把表现层 `_ready()` 收集的 `_materials` 顶成孤儿 ⇒ **有染色项的怪闪白一直完全不可见**（远征03 五只远程怪全中）。既有验收查的正是那份孤儿所以全绿。判据要落在「`_materials` 的 instance_id == 渲染面 `get_active_material()` 的 id」。
- 已改三处运行时翻转：三份 `_formal_visual.gd`、`WastelandLight3D._update_lens_state()`（**每次房间流送逐灯调用**）、`BaseLampDynamics3D._set_self_owned_emission()`。开关语义换成授权位 `_self_owned_allowed`（屏幕面常态能量本来就是 0，拿能量当判据恒 false）。

## 怪物朝向 vs 移动方向（同日第二轮）
- 根因：`_physics_process` 末尾**无条件朝玩家转**，而复刻怪的位移方向常与玩家无关（逃跑沿墙 90° / 游荡随机点 / 后撤 / 搜索归家巡逻）。
- 修法：`_commit_motion()` 在 `move_and_slide()` **之后**用位置差记 `_last_move_direction/_last_move_speed`（**不能用 velocity**，撞墙时它仍指墙外）；`_update_facing()` 按夹角分模式，55° 进 /40° 出 + 0.28s 保持迟滞；<55° 的侧移刻意保留朝玩家（边瞄边挪）。
- 锁定朝玩家的状态：telegraph/attack/recovery/stagger/dead/dormant。
- **坑**：`_physics_process` 在 `_target == null` 时提前 return，到不了转向代码 ⇒ `_tick_search`/`_tick_return`/`_tick_patrol` 内部各补一次，否则沿旧朝向一直横走。
- **探针假绿陷阱**：`move_and_slide()` 在 `set_physics_process(false)` 的 `_ready` 同步循环里**不推进位置**（8 帧 global_position 纹丝不动）⇒ 必须直接注入位移方向，别指望造出真位移。
- 验收 `tools/_egt_facing_probe`：3 怪 × 5 情境 = 15 档，负控（阈值改 200）能红 6 项。
