# 2026-10-21 远征01 room_03 手摆布局围出死区，怪刷在玩家到不了的地方

业主原话：「我远征关卡 room03 的房间，手动调整了布局 把四个角落围起来了。但是中间还有一些
我角色去不了的地方。刷怪会刷在这个位置。帮我在里头增加怪物不会刷的区域。」

## 结论

不是「再补一层刷怪盒排除」的问题 —— 是**旧的落点判据里没有「玩家走不走得到」这一条**。

`_spawn_floor_contains()` 只查「地砖是否满铺 + 离墙净距」，`_spawn_obstacle_free()` 只查
「有没有家具 AABB」。这两条对**被家具围出来的封闭空腔**全部放行：空腔里的地砖是满铺的，
家具是「障碍」而不是「围墙」，只要腔体内部还剩 ≥ 净距的空地，怪就刷得进去。

所以做法不是加一份需要人肉维护的禁刷矩形，而是**把可达性做成闸门**，接在所有落点路径的
唯一收口处 —— 布局以后再怎么手改都自动跟随。

## 实现（`src/world3d/DungeonRoom3D.gd`）

```
_ensure_spawn_reach()
├─ 只在 _detail_built 之后算（家具碰撞没进树时算出来是假的，不落锁、下次重试）
├─ BOSS / EXTRACTION 直接跳过（深井跨楼层，0.5m 单层网格会把井口井底糊成一片）
├─ 0.5 m 网格：障碍 AABB 在 XZ 上膨胀玩家半径 0.34
│   └─ 底面 ≥ 1.55 m 的构件（头顶横梁/吊管）不算挡路
├─ 种子 = 每个 connection_port 内侧 2 m（门洞格常被门扇占着）
│   └─ 一个门都给不出种子 ⇒ 取最大连通分量（玩家能进房就站在最大那块空地上）
├─ 4 邻接洪泛 → _spawn_reach_cells
└─ 覆盖率 < 35% ⇒ 判定闸门自己算错，退回收起（绝不能把整房判成不可刷 = 门永远不开）
```

收口点只有一处：`_spawn_floor_contains()` 开头 `_ensure_spawn_reach()` + `_spawn_reach_contains()`。
三条落点路径（索引落点 `spawn_point_for_index` / 盒内采样 `_box_sample_points` / 剧情落点
`resolve_narrative_floor_positions`）全部经过它，不用各写一份判定。

闸门首次生效时 `_build_spawn_points()` 重算一次候选池（`_ready()` 那次家具还没建）。
同一 `room_seed` ⇒ 除被剔掉的点外逐点不变。

### 性能

`_spawn_reach_probe_frame` 做同帧短路：未落锁时（家具还没进树）同一帧只试一次，
否则 `_build_spawn_points()` 的每个候选点都会触发一次 `_collect_spawn_blockers()`（4800 遍扫描）。
整关 13 间房逐房审计（含加载）12 秒。

room_03 的死区（房间局部坐标，物理网格 0.5 m 实测）：

- `x∈[5.0, 13.5], z∈[-18.5, -7.0]` ≈ 82.5 m²（东北角）

西北角**没有**死区 —— 那里家具没围死，玩家走得进去。业主说「四个角落」，实测是三个半。

闸门启用后：`probe_room03_reach` 报「候选点 130 个，仍落在物理死区的 = 0 个」。

## 踩过的坑

- **Boss 房强开闸门 = 盒心漂移**。第一版对所有房生效，`verify_expedition01_spawn_ramp` 立刻
  多出三条红：`boss#1` 漂 20.8 m、`boss#2` 漂 14.4 m、`boss#0` 从 11.07 变 13.18。
  原因是深井房的可达集只覆盖井口那圈，候选池骤减 ⇒ `_resolve_box_pool` 排不下就挪盒心。
  ⇒ 显式排除 BOSS / EXTRACTION，并把这条写进代码注释。
- **`_spawn_reach_evaluated` 不能在函数开头就置真**：家具碰撞晚一帧进树时会把「算了个空」
  永久锁死。改成「判定成立才落锁；覆盖率判负也落锁；blockers 为空不落锁」。
- **AABB 是绕 Y 旋转后的保守盒**（`shelving_south3` 那种带倾斜的家具尤其大）⇒ 闸门比物理实测
  略保守（可达 1597 vs 物理 1931 格）。方向是安全的：宁可少刷一只，也不刷在打不到的地方。

## 遗留 / 待业主确认

1. **远征01 room_03 设计源里 0 个刷怪盒**（`floor_00.json` 的 `spawn_placements: []`），
   而 `spawn_boxes_only=true` ⇒ 按「没盒子就不刷」规则，这间房**一只怪都不刷**
   （`probe_room03_live_spawn` 实测 `_spawn_room_enemies → true`、场内敌人 0 → 0）。
   业主看到的怪，更可能是 **room_02**（2 盒、外增援补到 12 只、77 个死区候选点）。
   若要 room_03 真正出怪，得先布盒 —— 那是改数据，本次没动。
2. **boss#1 / boss#2 盒子取到 0 个点**（`probe_spawn_deadzone_audit`）—— 与本次改动无关，
   基线同样为 0；说明这两个盒子落在排不下 13 只的位置，靠漂移落地。
