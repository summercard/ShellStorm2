`dda47512` 这一批 126 文件 / +11033，混了**六个主题**：
掉落拾取、HUD 换弹环、塔罗卡接线、自动装备、换弹 v034-037、Boss 血量与移速。

原因：`src/world3d/Dungeon3D.gd`（+548）与 `src/player3d/Player3D.gd`（+56）
被这些主题**同时修改**，而 git 暂存是**文件粒度**，无法把同一个文件拆进两个提交
（除非用 `git add -p`，但那种情况下拆出来的两个提交都编译不过）。

**处置**：合并为一批，提交信息里分六节、各节独立写清。**这是唯一诚实的做法** ——
强行拆开会产生"改了 Player3D 一半"的中间提交。

**可复用的判据**：分批次前先跑
`git diff --name-only | sort` 与 `git diff --stat`，找出**被多个主题碰过的文件**；
只要有一个这样的文件，相关主题就必须合并。

## 五、新坑

1. **`rm -f .git/index.lock` 被 safe-delete 拦截**：这个环境把删除重定向到回收站，
   `genie-trash` 对 `.git/index.lock` 报
   `Error during a trash operation: Some operations were aborted`，
   命令 exit 1。若后接 `&&` 会把整条链断掉。
   **修法**：改成 `ls .git/index.lock` 先判断是否存在（因为通常本来就没有）；
   真需要删时用 `git` 自己的行为（git 会在需要时自己处理）。
2. **全库 `find -newermt` 在 6 万+ 文件仓库必然超时**（本会话又踩两次 SIGTERM）。
   改用「对 `git status` 列出的文件逐个 `stat`」——只处理几百个文件，秒级完成。

## 六、本轮值得记的设计推导

**命运卡接线修复**（上一轮遗留的功能 bug 收口）：
`Dungeon3D._create_reference_fate_card_view()` 把 `tarot_button` meta 挂在**按钮**上
就返回「卡片列」容器，调用处却从**列容器**读 ⇒ 取到 null ⇒ **翻牌动画整个不执行**；
而 `disabled = true` 只在翻牌完成回调里解除 ⇒ **卡片在游戏里根本点不动**，
玩家看到一排无法交互的卡背。三个入口全中招、不报错不崩溃。
**教训：独立探针验证通过 ≠ 功能可用** —— 探针覆盖「组件渲染对不对」，
覆盖不到「调用方有没有把它接上」。补跑真实游戏流程断言后 48 项失败 → 0。

**Boss 血量 52000 的公式口径**（符合"数值必须给公式"这条操守）：
`PROFILES.boss.hp = 5200`，经 `BOSS_HP_MULTIPLIER(10)` 得第 1 层实测 52000；
更高楼层由 `MonsterInjector.FLOOR_SCALING.hp_mult` 与 `boss_scale` 比例还原放大
（第 2 层 109200 / 第 3 层 128700 / 第 4 层 168480）。**改单层要改 FLOOR_SCALING，别动基准。**

**持枪移速**：`v = max(0.5, 4.5 − 惩罚) × 命运与词条移速倍率`，
惩罚 短枪 0.5 / 长枪 0.8 / 机枪 1.1（基础速度的**减法项**）。
**不变量**：三类枪实际速度 4.0 / 3.7 / 3.4 全部 > 表现层的 3.2 慢走阈值 ——
初版机枪惩罚 1.5 会让速度掉到 3.0 而误播慢走动画，这条已写进常量注释与 03 文档。
