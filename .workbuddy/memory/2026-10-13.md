### 一、静默判定：指纹法（这次 stat 遍历超时了）

12:56 最后写入（隔 6 分钟）⇒ 写入活跃。**想用 stat 遍历取最大 mtime，
但 1302 个文件逐个 stat 在 I 盘上直接超时（SIGTERM）**。

改用**整表指纹**：`git -c core.quotePath=false status --porcelain -uall > /tmp/x;
md5sum /tmp/x`，两轮（20:41 / 20:48）指纹完全一致 + `diff` 无输出 ⇒ 判定静默。

**为什么指纹法比 stat 更可靠**：`git status` 会比较 mtime 并按需重算哈希，
所以「指纹一致」= 内容真的没变；而 stat 只看 mtime，会被 touch 干扰。
**1300+ 项时优先用指纹法，不要逐个 stat。**

### 二、分级依据：`core.quotePath=false` 是中文路径的前提

本仓库大量中文路径。`git status --porcelain` 默认会把中文转义成
`"\346\226..."` 形式，导致 `grep`/`awk` 全部对不上。

**必须**：`git -c core.quotePath=false status --porcelain -uall`
（`-uall` 展开未跟踪目录；默认会折叠成目录行、项数虚低）。

### 三、音效 53 MB **不走 LFS** —— 判断依据

`.gitattributes` 只覆盖 `art_source/**/*.blend` 与 `*.psd`；
`art_source/audio/sfx` 是 **603 wav + 145 json = 53 MB**（最大单件 0.76 MB）。
53 MB 远低于仓库单文件限，且 wav 是成品不是频繁变更的大源，
**加 LFS 规则反而增加拉取成本** ⇒ 直接普通对象入库。
**判据**：单件是否接近限制 + 总量是否可接受；不是「音视频就该进 LFS」。

## 事务：Boss房02 地面碰撞合成一体网格（修「楼梯/走道卡人」）

业主原话：「boss房的楼梯的阻挡 从下往上走因为台阶高度会卡人，还有两边走道到台子也会卡人，

### 一、先量，再改（这条链决定了整个改法）

写了 `scripts/probe_boss_room02_walk_surface.gd`：对同一批采样点**同时**取两个数 ——
① 现存碰撞面的顶高（向下射线）；② 可见网格的顶高（对走面组件**逐三角**竖直求交）。
⚠️ 两个坑：**(a) 射线不能从天上射**（会先命中壳体顶盖，实测撞出 `coll=36.4` 的假数），
起止点必须卡在目标带内；**(b) AABB 法对斜坡无效**（斜坡段 AABB 顶 = 整段最高点，不是该 z 处的高度），
求可见面必须逐三角。

实测结论（房间局部 y）：

| 段 | 现存碰撞 | 可见面 | 差 |
|---|---|---|---|
| 平台 | `0.0000` 平 | ≈ `0`（局部浮雕 −0.0155..−0.1295） | 正常 |
| 东西走道 | `-0.1815` 平 | ≈ `-0.0315` | **到平台 0.18 m 竖面** |

| 梯脚 z=−10 | 从 0 跳 `0.1205` | `0.105` | 进梯第一脚 0.12 m |
| 高台 | `11.965` 平 | ≈ `11.965` | 梯顶 12.105→11.965 的 0.14 m |

**关键发现**：可见楼梯面是**一条 0.24 斜率的直线坡**（0.12 踏高 / 0.5 m 踏面 × 100 踏），
根本没有台阶；业主说的「台阶高度」其实是**碰撞自己造出来的**（0.216 段坡 + 1.2 m 摆放间距 = 0.12 缺口）。

  不是世界 X。这样「右」才真的对应屏幕上往右，相机绕到侧面时也不会反。
- **平移总位移按长度收敛**（不是每轴独立夹）—— 否则斜着按能到 `(6,6,6) = 10.4 m`。

### 二、俯仰圆轴算子（唯一需要推导的地方）

`TowerDescent3D._orbit_point_about_pivot(point, pivot, delta_deg)`：把相机位置绕**角色水平轴**
旋转，半径守恒。用极角表示比直接套旋转矩阵更好夹边界：

```
polar = clamp(atan2(offset.y, horizontal_len) + delta, 3°, 88°)
new_pos = pivot + (cos(polar)·radius·planar_h, sin(polar)·radius, …)
```

- **正角 = 抬高**（镜头变高 + 水平距离变近 = 更俯视），负角 = 压低趋近平视。
  与业主的「向下拉抬 / 向上」直觉一致（视角往下压 = 相机往上抬）。
- 极角**必须夹在 3°~88°**：到 90° 就是正上方（水平距离 0），`look_at` 会因上向量退化而抖动；
  到 0° 就与目标点重合。夹住的代价只是「压不到纯俯视」，比抖动好。
- 平移时 **pivot 与相机一起平移**（两者同加 pan），否则平移会变成「相机挪走而视角转向别处」。

### 七、🔴 踩到的坑（三条，下次直接用）

1. **`godot --check-only --script` 不能用来做编译校验。** 它**不加载 autoload**，
   于是所有引用了 autoload 单例（`GraphicsSettingsManager` / `BaseManager` / `BlueprintRegistry` /
   `InputSettings` / `GameEntryFlow`…）的脚本一律报 `Compile Error: Identifier not found`。
   本次四个文件全中招，看着像全炸了，其实一条真错都没有。**校验要靠跑 tscn 场景**（会加载 autoload）。
2. **验收套件 `run_verification_suite.sh` 在本机起不来**：卡在**第一步**
   `verification_workspace.py stale`，26 分钟零进展，最后只能 SIGTERM（`exit=143`）。
   现场：临时工作区建出来是 0 字节空目录，`ps` 显示 python 收到的路径是乱码
   `I:/å·¥ä½œé¡¹ç›®/shellstorm2/...` —— **中文路径经 Git Bash 传给原生 python 时编码坏掉**。
   与本次改动无关（我改的四个 .gd 在套件里还没被读到）。本轮结论靠直跑 tscn 建立。
   ⇒ **套件跑不动时不要怀疑自己的改动，先直跑 tscn。**
3. **Edit 的 `old_string` 末尾换行不能少写。** 想给注释加一行时把 `## …\n func xxx(` 一并作为
   old_string，结果新文本把 `func` 声明**并进了注释行**（`## …。func _add_button_row(...)`）。
   这种错误 GDScript 会报 Parse Error，但**手写 diff 时极易看漏**。
   规矩：改动紧贴函数声明时，old_string 末尾必须带上它前面那个换行。

### 八、顺带修正一条旧认知（行尾）
