## 实测教训 A：陈旧 `.git/index.lock` 会拦住 `git add`
- 现象：`git add` 报 `Unable to create '.git/index.lock': File exists`。
  锁文件时间戳是当天 08:44，比操作时间早 11 小时。
- 判据（两条都成立才可删）：① 无 `git` / `git-lfs` / `ssh` 进程在跑；
  ② `git status --porcelain` 的第一列全空（index 里没有残留暂存）。
- 只读操作（`status` / `diff` / `fetch`）**不会**撞这个锁，所以它会一直潜伏到第一次写操作才暴露。

## 实测教训 B：`Uploading LFS objects: 100%` ≠ 推送成功
- 现象：首次 `git push` 日志出现
  `Connection to github.com closed by remote host.` +
  `Uploading LFS objects: 100% (90/90), 498 MB | 46 KB/s, done.`
  看起来成功了，但 `git fetch` 后 `origin/0.1.2` 仍停在旧提交 `01c0c674`，本地 `ahead 4`——
  **LFS 对象传完了，commit 一个都没上去**。
- 复核硬动作（不可省）：`git fetch origin` 后比对
  `git rev-parse HEAD` 与 `git rev-parse origin/<分支>`，**两者必须逐字相同**才算推送成功。
- 恢复：直接重跑 `git push origin <分支>`。已传的 LFS 对象在远端，第二次
  `Uploading LFS objects: 100% (90/90), 498 MB | 0 B/s`，31 秒完成。
