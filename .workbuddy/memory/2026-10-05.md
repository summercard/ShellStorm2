### 根因

`_ready()` → `_bind_existing_city_material.call_deferred()`，`call_deferred` 至少隔一帧才执行。
地基要轮询最多 120 帧等程序城市 `CityBuildingSilhouettes`。

带**未完成续局**的存档启动时：`StartupLoadingScreen` → 引导用的 `TowerDescent3D` 整栋建起来
→ 同一帧里 `TowerDescent3D._resume_expedition_runtime_scene()` 又 `change_scene_to_file` 一次
→ **引导场景在第 1 帧被顶掉**。此时地基已出树，轮询刚醒 → `get_tree()` 返回 null → `.root` 抛错。

探针实测：`tree null at frame=1 inside_tree=false`。

### 修法（关键点：只判返回值不够）

```gdscript
for _frame in range(BIND_POLL_FRAMES):
    if not is_inside_tree():   # ← 必须先用这个挡
        return
    var cities := get_tree().root.find_children(...)
    ...
    await get_tree().process_frame
```

**`Node::get_tree()` 自身带 `ERR_FAIL_NULL_V`** —— 出树时哪怕只读返回值，它也会先打一条
`ERROR: Parameter "data.tree" is null.`。所以不能写成 `var tree := get_tree(); if tree == null: return`。
`is_inside_tree()` 是纯读标志位，无副作用。

改动文件：`assets/art/environments/open_world/runtime/open_world_landscape_foundation/landscape_visual_material_binding.gd`

## 换弹环返工：从「平铺地面」改成「正对镜头 + 画在角色之上 + 离地」

主人原话：「这个变成脚底了，不是这个意思，是要在角色的下方的、面对镜头的，层级还是在角色上方。」

上一轮（10-04）我把环绕 X 转 −90° 铺在地上，主人否了。三条口径重新定：

1. **正对镜头** —— `PlayerAvatar3D._face_reload_ring_to_camera()` 每帧把环的局部基写成相机基。
   **不走 `billboard_mode`**：着色器 billboard 会归一化模型基向量 ⇒ 锚点的 `BUNNY_LINEAR_SCALE`
   连同 `node.scale` 一起被吃掉，环的世界尺寸就错，而 visible / 快照 / AABB 全绿。
   实现用「父节点正交化旋转的逆 × 相机旋转」反解局部 basis，**不是**每帧写 `global_basis`
   —— 带缩放的矩阵反复分解会累积浮点漂移，反解则是幂等的。
2. **画在角色之上** —— 两材质 `no_depth_test = true`。环心在角色下半身，正对镜头时上半圈
   必然压在腿上。代价：也会盖住墙（短时 HUD 信息，可接受）。
3. **离地** —— 锚点 `(0, 0.08, 0)` → `(0, 0.25, 0)`。

### 一条被纠正的旧口径

10-04 记的「相机视轴离竖直 20.6°」是**错的** —— 那是拿 `CAMERA_HEIGHT_M / CAMERA_DEFAULT_TRAILING_M`
直接算的，漏了注视点偏移（`CAMERA_LOOK_HEIGHT_M 0.45` 抬、`CAMERA_LOOK_AHEAD_M 0.75` 前送）。
实算：`atan((4.038 + 0.75) / (10.719 − 0.45)) = atan(4.788 / 10.269) = 25.0°`，`sin` 从 0.352 → 0.423。

离地判据就是这么反算的：正对镜头的环面在竖直方向铺开 `±r·sin(倾角) = ±0.42 × 0.4226 = ±0.1775`，
所以**环心低于 0.18，下半圈就插进地板**。锚点 0.08 时实测最低点 **−0.078 m** —— 难怪被读成「脚底」。

### ⚠️ 给后续会话的一条自觉

相机离竖直只有 25°，所以「平铺地面」与「正对镜头」在世界空间里**只差 25°**：对齐度是
cos(25°) ≈ **0.906 而不是 0**。屏幕上的差别主要来自「正圆 vs 竖直压扁 0.906」＋「画在角色之上
vs 被腿遮挡」。别指望这是一次大角度翻转，也别把断言注释写成「平铺时约等于 0」。
