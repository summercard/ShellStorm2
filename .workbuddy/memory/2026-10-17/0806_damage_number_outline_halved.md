# 伤害飘字描边减半（26 / 30 / 34 → 13 / 15 / 17）

用户指令（原文）：「**描边太粗了，缩小一半**」。承接上一事务（[0140](0140_damage_number_outline_pixel_range.md)）：
那轮刚把 `msdf_pixel_range` 从默认 16 提到 64，描边**第一次真正足额渲染**（此前一直被截断成 1px 细丝），
实机看下来偏粗 ⇒ 本轮把字高占比 22% → **11%**，即尺寸减半。

## 一、为什么是"减半"而不是"重新定档"

上一事务的关键结论是「**这组描边值此前根本没渲染出来过**」（被 MSDF 距离场截断），所以
26 / 30 / 34 **从未被眼睛验证过**。业主看到的是修好 range 之后的第一次真实观感 ——
**这次的反馈才是对这组值的第一次评价**。⇒ 不存在"推翻旧数据"，只是把首次真实观感上偏粗的比例收一半。

## 二、改动（真源一处）

`src/vfx/DamageNumberStyle.gd`：

```gdscript
const NORMAL_OUTLINE_SIZE := 13     # 13 / 116 ≈ 11.2% 字高
const HEAVY_OUTLINE_SIZE := 15      # 15 / 134 ≈ 11.2%
const CRITICAL_OUTLINE_SIZE := 17   # 17 / 152 ≈ 11.2%
```

三档都在同一文件同一段 ⇒ 一处改动覆盖三条链路（`VfxDamageNumber3D` / `VfxHealNumber3D` /
兜底 `CombatDamageNumber3D` 都经 `DamageNumberStyle` 取样式）。描边色 `OUTLINE_COLOR`、
淡出通道（`transparency`，2026-10-10 业主口径）**均未动**。

## 三、距离场宽度为什么**不跟着降**（本轮唯一需要判断的地方）

需求公式 `range ≥ 2 × max(描边 × msdf_size / 字号)`：

| 时点 | 最紧档 | 需求 | 取值 |
|---|---|---|---|
| v003.10（描边 26 / 30 / 34） | 34 @ 152 | 57.4 | 64 |
| v003.11（描边 13 / 15 / 17） | **15 @ 134** | **28.7** | **仍 64** |

两个要点：

1. **最紧的档不一定是暴击档。** 15/134 = 11.19% 略高于 17/152 = 11.18%，纹素需求是**重击档**更高
   （28.66 vs 28.63）—— 差值无所谓，但"默认看最大字号"这个直觉是错的，必须按公式算。
2. **不把 64 压到 28.7**：64 可支持描边到约 38 @ 字号 152，为后续微调留余量，不必每改一次描边就重定档；
   同时远离实测崩坏点 **96**（range 过大时距离场精度不够 ⇒ 描边**左右不对称**，一侧整条丢失）。
   实测 48 对当时的 26 属轻微截断、对现在的 17 则足额 —— 48 也够，但余量更薄，无收益。

## 四、验收

`tests/verification/verify_damage_number_style_flow.gd`：

- 硬编码期望 `EXPECTED_NORMAL / HEAVY / CRITICAL_OUTLINE` 同步为 **13 / 15 / 17**
  （期望值一律留在验收侧，不引用被测常量）；
- 下界不等式 `_required_msdf_pixel_range()` 由验收侧期望值重算 ⇒ 自动变成 `needs >= 28.7`，
  64 依旧覆盖 ⇒ **验收逻辑一行没改，只改了期望常量**；
- 上界护栏 80 与逐档「实例真带该值」断言不变。

**反向对照两组**（均精准变红后还原复绿）：

| 对照 | 期望 | 实测 |
|---|---|---|
| `MSDF_PIXEL_RANGE = 16` | 下界红 | ✅ `needs >= 28.7` |
| 真源描边偷偷改回 26（验收期望已是 13） | 常量钉子红 | ✅ `NORMAL_OUTLINE_SIZE drifted` |

**实机距离 A/B**（同相机、同散布，`_scratch/preview_damage_number_style.gd`，1280×720）：
同一帧里**红色字形像素恒为 5,105**（⇒ 字形本身没变，是干净的对照），近黑描边像素
**12,613 → 6,392（×0.507）**，正好减半；`12 / 48 / 137 / 96 / +24` 勾线仍清晰可辨。
证据 `outputs/outline_thick_*.png`（减半前）vs `outputs/damage_number_style_*.png`（减半后）。

⚠️ 量测口径：`t0_pop`（弹出 / 淡入帧）不能用"红像素"阈值统计 —— `FADE_IN_TIME = 0.08` 期间字形被 alpha
稀释，红像素骤降到十几个，"字形高 12 px"是**假读数**。要量就用 `t_mid`。

## 七、可迁移的教训

1. **"减半"这类反馈只改比例，别顺手动总量。** 距离场 64 是"能不能渲染"的开关、不是风格量；
   描边减半后需求降到 28.7，64 仍够且留余量 ⇒ 不动它，避免"改一处牵动两处契约"。
2. **最紧档不一定是你以为的那一档。** 按公式算，别按字号排序（本轮重击档比暴击档紧）。
3. **并发工作区里，幂等守卫要防"别人占号"。** 判重命中 ≠ "我写过了"。
