## 可复用的操作经验

- **工作区根不是仓库**：正本在 `I:/工作项目/shellstrom2/ShellStorm2`。
- **`git add -A` 在大仓库上要 4 分钟以上**，前台 120 s 超时会被 SIGTERM 杀掉，
  **并留下 `.git/index.lock`** —— 之后所有 git 写操作静默失败（`git diff --cached` 恒为空）。
  遇到「暂存数莫名是 0」先查 `.git/index.lock`，确认无 git 进程后删锁重跑。
  长 add/add 相关的命令一律用后台跑。
- **推送前先量**：`git diff --cached --name-only -z` + `os.path.getsize` 扫一遍
  （脚本在 `%TEMP%/check_staged.py`），确认没有 `.blend` 与 >100 MB 文件再 push。
  大文件一旦推上去，删历史很麻烦。
- 单个 `.blend` 涨到 GB 级的根因：塔4 每版几何都在同一文件里累积重建，
  版本号递增但文件体积不回落。**下一版若继续涨，源不入库这条口径要接着用。**
