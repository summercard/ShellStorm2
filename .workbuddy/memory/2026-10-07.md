### 1. git 的段内 `*` **不匹配空串**（实测 git 2.55.0.windows.3）

原规则 `_scratch/*_before_*.blend` 看着能覆盖 `boss029_before.blend`，实测漏网：

```
_scratch/x_before_y.blend      -> 命中（_before_ 前后都非空）
_scratch/boss029_before.blend  -> 未命中
```

原因：文件名里是 `_before.`，规则要的是 `_before_`（尾部带下划线）。补
`_scratch/*_before.blend`。**教训：写 gitignore 的 `*` 时不能假定它能匹配空串。**

## 工作方法上的两个教训

1. **全库 `find` 在 Windows 上必然超时**（这个仓库 6 万+ 文件）。改用
   `git diff --cached --raw --abbrev=40 | awk '{print $4}' | sort -u | git cat-file --batch-check='%(objectsize)'`
   —— 只对暂存区对象算大小，秒级出结果。
   ⚠️ 注意 `--raw` 默认给的是**缩写 sha（8 位）**，必须加 `--abbrev=40` 才能拿去 batch-check。
2. **`git commit -- <paths>` 可以绕过 "reset 后重新 add 3 分钟"**：先把全部 `git add -A`，
   再用 `git commit -- <paths>` 按主题逐批提交，未列出的路径留在索引里，下批继续。
   代价：commit 仍可能超时（2430 文件），老老实实后台跑。
