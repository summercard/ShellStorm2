WeaponDisplay.gd 命运视觉刷新完整性修复（root.children → 槽位遍历）

### 问题分析
轮次 191 方向（轮次 189 遗留）：命运卡片枪械视觉刷新完整性 — WeaponDisplay 挂载枪多边形同步刷新。

审查 `_refresh_fate_visual()` 发现三处代码使用了不存在的 `AssemblyNode.children` 属性：

```gdscript
for child in root.children:           # ← children 不存在
    if child.node_type == "Bullet":     # ← 应比较 NodeType 枚举，不是字符串
```

AssemblyNode 只有 `slots: Dictionary` 槽位属性，没有 `children` 数组。这导致命运卡片"变大了""加眼睛""加脚"三种视觉在玩家将子弹挂到枪身后（BULLET 槽位）无法正确刷新到枪械多边形上。

### 本轮改动

| 文件 | 改动 |
|---|---|
| `src/weapon/WeaponDisplay.gd` | `_refresh_fate_visual()` 中 3 处 `for child in root.children` 替换为正确的槽位遍历：通过 `AssemblyNode.SlotType.keys()` 枚举 `root.slots`，用 `root.slots[AssemblyNode.SlotType.get(slot_type)]` 取子节点，比较 `slot_child.node_type == AssemblyNode.NodeType.BULLET` |

## 轮次 192 — 2026-05-26 03:47 UTC+8

### 维度
FateCardEngine.gd 重复 case 清理（SCALE_UP/ADD_EYES/ADD_LEGS 重复分支）

### 问题分析
在轮次 191 修复 WeaponDisplay.gd 命运视觉刷新完整性后，轮次 192 的下一个逻辑步骤是"加眼睛"和"加脚"卡片的效果执行。

审查 `FateCardEngine.gd` 发现 `apply_card()` 的 match 分支表中存在 3 对重复 case：

```gdscript
# 第一次添加（位置正确）
FateCard.EffectAction.SCALE_UP:
    result = _apply_scale_up(card, tree, target_nodes)
FateCard.EffectAction.ADD_EYES:
    result = _apply_add_eyes(card, tree, target_nodes)
FateCard.EffectAction.ADD_LEGS:
    result = _apply_add_legs(card, tree, target_nodes)
# ...后面 MULTIPLY_FIRE_RATE 之后又残存了...
FateCard.EffectAction.SCALE_UP:        # ← 重复！
    result = _apply_scale_up(card, tree, target_nodes)
FateCard.EffectAction.ADD_EYES:        # ← 重复！
    result = _apply_add_eyes(card, tree, target_nodes)
FateCard.EffectAction.ADD_LEGS:        # ← 重复！
    result = _apply_add_legs(card, tree, target_nodes)
```

GDScript 中重复的 case 会导致后面的分支永远无法到达，且编译器不会报错（仅第一个匹配生效）。这意味着 `SCALE_UP`、`ADD_EYES`、`ADD_LEGS` 三个效果实际上只能通过 `SCALE_NODE` 的 fallback 路径（`_apply_scale_node`）执行，而不是各自独立的视觉处理方法。

### 本轮改动

| 文件 | 改动 |
|---|---|
| `src/weapons/FateCardEngine.gd` | 删除 CRIT_ON_KILL 之后残存的 3 个重复 case（SCALE_UP/ADD_EYES/ADD_LEGS），match 表恢复正常唯一性 |

### 验证
- Godot headless --quit：EXIT 0 ✅

### 剩余风险

- `playable_presets()` 仍不含"加眼睛"和"加脚"卡片，局内工作台不会出现这两种卡（需要人类决策是否加入可玩牌池）
