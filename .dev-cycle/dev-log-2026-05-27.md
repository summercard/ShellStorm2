### 维度
EnemyBase._ensure_state_marker() 函数体缺失修复（运行时Bug修复）

### 问题分析
从轮次252完成后的代码审查中发现 EnemyBase.gd 存在一个关键Bug：

**症状**：`EnemyBase` 定义了 `_state_marker_label: Label = null` 实例变量，并在至少3处调用了 `_ensure_state_marker()`，但整个类中没有 `_ensure_state_marker()` 函数定义。这导致：
1. `_state_marker_label` 始终为 null
2. 精英名字标签永远无法创建和显示（`_set_elite_name_label()` 中的 `_state_marker_label.text = name` 等于空操作）
3. 警觉AI的 ❓/❗ 状态标记也无法显示

**根本原因**：很可能是早期开发过程中函数声明被创建但忘记实现函数体，后续代码全部引用了它但从未触发编译错误（因为调用处只有方法调用没有访问不存在的符号）。

**验证**：`godot --headless --quit-after 3` 仍然通过编译，说明 Godot 的脚本编译器不把方法缺失当作语法错误（方法调用是动态的）。

**影响**：这是"能被人类试玩验证出来的Bug"，即玩家会看到精英没有名字标签，无法感知系统是否正确。

### 修复方案
实现 `_ensure_state_marker()` — 延迟创建 Label 节点：

```gdscript
func _ensure_state_marker() -> void:
    if _state_marker_label != null and is_instance_valid(_state_marker_label):
        return
    _state_marker_label = Label.new()
    _state_marker_label.name = "StateMarker"
    _state_marker_label.z_index = 3
    _state_marker_label.horizontal_alignment = HORIZONTAL_ALIGNMENT_CENTER
    _state_marker_label.vertical_alignment = VERTICAL_ALIGNMENT_CENTER
    _state_marker_label.add_theme_font_size_override("font_size", 13)
    _state_marker_label.modulate = Color(1.0, 0.88, 0.15, 1.0)
    _state_marker_label.visible = false
    add_child(_state_marker_label)
```

同时设置 `_state_marker_offset_y: float = -58.0` 变量，控制名字标签位于 emoji 上方的偏移量，并在 `_update_emoji_display()` 和 `_set_elite_name_label()` 中通过 `position = Vector2(-label.size.x * 0.5, _state_marker_offset_y)` 动态居中定位。
