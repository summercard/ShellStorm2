### 核心问题分析
**宝箱/容器开启后背包UI不刷新** — 这是一个真实存在的链路断裂：

1. `ContainerInteraction.container_opened` 信号在 `_try_open_container()` 成功时正确 emit
2. `LootModule.grant_loot_to_inventory()` 内部确实调用了 `inventory.add_item()` → `add_item()` 触发 `inventory_changed.emit()`
3. `InventoryModule.inventory_changed` → `RoomGameMode._on_inventory_changed` → `GameUIManager._on_inventory_changed` → `_refresh_inventory_ui()`

**但实际问题在于：** `RoomGameMode` 在容器实例化时**没有持有容器引用**，也**没有连接任何容器的信号**。`RoomFactory.create_room()` 把 `inventory_module` 传给每个 `ContainerInteraction.set_inventory()`，但没有把容器注册到 `RoomGameMode`。

**这意味着：** 理论上 `inventory_changed` 信号链路是完整的，问题可能出在其他地方。

### 验证思路
1. `ContainerInteraction._grant_loot()` 调用 `inventory.add_item()` 后 → `add_item()` 末尾 `inventory_changed.emit()`
2. `RoomGameMode` 在 `_setup_extraction_modules()` 中 `inventory_module.inventory_changed.connect(_on_inventory_changed)`
3. `_on_inventory_changed` 调用 `set_beacon_count` 并通过 `_call_ui_manager_method("set_beacon_count", ...)` 刷新 UI
4. `GameUIManager.set_inventory_module()` 中 `module.inventory_changed.connect(_on_inventory_changed)` → `_refresh_inventory_ui()`

**信号链路本身是完整的**。问题可能是：
- `Container.tscn` 根节点是 `Area2D`（即 `ContainerInteraction` 本身），而 `_create_container_from_config` 在找不到 `Container` 子节点时会把整个场景当 `ContainerInteraction` 用
- `LootModule.grant_loot_to_inventory` 实际未被调用（`_loot_module == null` 或掉落表为空）
- `add_item` 返回 0（背包已满）
