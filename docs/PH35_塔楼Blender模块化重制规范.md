# PH35｜塔楼 Blender 模块化重制规范

## 状态与边界

- 本阶段只制作 Blender 源资产和评审图，不导出 GLB、不建立 Godot 场景引用，也不修改当前塔楼运行时尺寸。
- 用户确认 `.blend` 中的比例、结构和组件接口后，再单独执行 Godot 导入、碰撞替换、楼层流送和玩法回归。
- Blender 与 Godot 均以 1 单位 = 1 米；Blender 使用 Z 轴向上，组件正向为本地 +X。

## 新尺寸冻结

“面积增加 5 倍”按面积严格乘 5 计算，而不是边长乘 5：

| 模块 | 旧尺寸 | 新尺寸 | 新面积 |
|---|---:|---:|---:|
| 楼顶 | 50×50m | 111.803×111.803m | 12,500㎡ |
| 基地层 | 30×30m | 67.082×67.082m | 4,500㎡ |
| 战斗层 | 30×30m | 67.082×67.082m | 4,500㎡ |

- 层高由 6m 提高 50% 至 9m。
- 楼板厚度原型统一为 0.30m；墙厚统一为 0.30m。
- 楼梯、门厅和折角走道净宽统一为 6m，避免角色、武器模型和镜头剖切状态在接缝处互相挤压。

## 标准楼梯间组件

### 1. 门口走道 `MODULE_DOOR_LANDING`

- 可走顶面：6×6m 长方形。
- 原点：门洞中心、走道顶面、靠门一端；组件沿本地 +X 延伸。
- 上层入口与下层出口使用同一组件，不允许为上下层制作两个尺寸版本。
- 接口：
  - `SOCKET_DOOR`
  - `SOCKET_FLIGHT`

### 2. 固定斜坡楼梯 `MODULE_STAIR_FLIGHT`

- 水平投影：15×6m。
- 单跑下降：4.5m。
- 斜面长度：15.660m。
- 坡度：16.699°，与旧 3m/10m 坡度一致。
- 原点：上端中心、可走顶面；沿本地 +X 前进并向本地 -Z 下降。
- 承重使用连续斜坡；踏步只作为视觉构件，不承担角色碰撞。
- 两侧护栏高 1.2m，坡道两端保留完整 3m 开口区，不把护栏延伸进平台转角。
- 接口：
  - `SOCKET_FLIGHT_TOP`
  - `SOCKET_FLIGHT_BOTTOM`

### 3. 折角走道 `MODULE_TURN_LANDING`

- 可走顶面：6×14m 长方形。
- 同时覆盖两条 6m 净宽梯跑与中间 2m 结构缝，两跑中心距固定为 8m。
- 原点位于第一跑出口端的中心线；第二跑接口位于横向 +8m。
- 接口：
  - `SOCKET_TURN_IN`
  - `SOCKET_TURN_OUT`

### 标准双跑总成 `ASSEMBLY_STAIRWELL`

- 组成顺序：上层门口走道 → 第一跑 → 折角走道 → 第二跑 → 下层门口走道。
- 总高差：9m；两跑各下降 4.5m。
- 计划占地包络：27×14m；门口上下平台规格完全一致。
- 所有组件只能在接口点相接，不允许平台穿过坡道中段，也不允许用非整米位移补缝。

## 三类楼层 Blender 原型

### 楼顶 `FLOOR_ROOFTOP`

- 111.803×111.803m 楼板。
- 四周连续女儿墙/护栏，楼梯门洞与标准 6m 门口走道对齐。
- 外立面向下延伸完整 9m，保证俯视镜头能读出建筑体量。

### 基地层 `FLOOR_FACILITY`

- 67.082×67.082m 室内壳体。
- 设施沿墙分区，中部保留至少 12m 主通道。
- 上下楼梯门口分别占用固定的 6m 对齐带，任何设施不得进入门口走道和楼梯接口净空。

### 战斗层 `FLOOR_COMBAT`

- 67.082×67.082m 室内壳体。
- 隔间使用可替换墙段，保留至少 12m 环形/中央战斗通道。
- 上下楼梯口随机位置只改变总成挂接方向，不改变楼梯组件尺寸、坡度或接口。

## 光标与跨层遮挡验收规则

代码复核确认这两项都属于运行时层选择问题，不通过移动 Blender 网格掩盖：

1. 当前 `Player3D._update_aim_from_mouse()` 把鼠标射线固定投影到世界 `Y=0` 平面，因此玩家下楼后光标仍停留在楼顶高度；它目前甚至没有读取当前房间或楼梯高度。导入阶段改为由 `TowerDescent3D` 提供当前层/当前梯段的瞄准表面高度，禁止继续使用固定零平面。
2. 承重碰撞、瞄准查询和渲染可见性拆成三个独立状态：
   - `support_collision_enabled`：隐藏层仍保持，防止遗留物体下坠；
   - `aim_query_enabled`：只有当前层和当前楼梯间开启；
   - `render_visible`：只显示当前层与正在通行的楼梯间。
3. 光标高度投影到当前层或当前楼梯路径；若后续改为物理射线，也必须过滤非当前层楼板。
4. 当前楼梯剖切只在 `_current_room_id` 仍等于上层且角色超过门平面/高度阈值时隐藏上层；房间触发器切换与剖切更新之间存在短暂过渡帧，所以偶尔会先看到上层楼板。后续引入明确的 `transition_from_room_id`，跨门平面时先锁定隐藏来源层，再允许 `_current_room_id` 切换。
5. 切层使用门平面与高度双条件并增加短滞回，避免角色站在坡道接缝时上下层反复闪烁；上一层恢复必须等角色明确回到上层门内。
