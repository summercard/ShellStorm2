# PH30 · 3D 角色与遭遇预览场

## 目标

建立独立运行的 `Player3DStateGallery.tscn`，让角色、阿凡达、怪物、Boss 与 NPC 能在不进入完整副本的情况下被快速验收。预览场必须直接实例化游戏运行时实体，不能做仅用于展示的状态机、枪械计时器或角色替身。

## 角色验收契约

- 预览场实例化 `scenes/Player3D.tscn`，继续使用 `Player3D` 的六个顶层状态：`idle / moving / dashing / hurt / locked / dead`。
- 状态按钮通过真实 `StateMachine`、`take_damage()`、`set_input_locked()` 与 `request_dash()` 触发；不复制状态逻辑。
- 换弹按钮只把真实 `WeaponModel3D` 调整到非满弹，再调用 `request_reload()`；头顶进度条、唯一握持手与 `weapon_socket` 继续读取同一计时器。
- 低血、无敌、沉默是叠加层，必须在状态读数中可见，且不新增第七个互斥顶层状态。
- 鼠标仍可控制玩家真实瞄准；预览场只固定站位，防止循环移动把阿凡达移出镜头。

## 遭遇与 NPC 验收契约

- 怪物和 Boss 一律实例化 `enm_ecosystem_kit_root_top3d_v001.tscn`，调用 `Enemy3D.apply_profile()`；类型、AI 开关、受击和 Boss 阶段都走正式实体。
- NPC 采用 `ThemedNPC3D`：将已有 `ThemedNPC` 的 `id / name / role / text / color / 交互范围` 契约迁移到 `Area3D`，并用运行时原始体作为临时 3D 表现。它不是新的可登记美术根资产。
- 预览场不生成房间、掉落或波次，不改变存档；退出后销毁全部临时实体。

## 控件

| 分区 | 控件 | 验收内容 |
| --- | --- | --- |
| 玩家状态 | 待命、机动、突进、受创、锁定、死亡、重置 | 六态白名单、动作、终态守卫 |
| 玩家叠加 | 换弹、低血、无敌、沉默、三种枪身 | 真实换弹、头顶进度、单手挂点与叠加层 |
| 敌人与 Boss | 类型选择、生成、AI 开关、受击、待机/巡逻/预警/攻击、Boss、阶段推进 | 七类轮廓、九态 AI、血量/碰撞与 Boss 阶段 |
| NPC | 角色切换、对话 | 3D 名称/职业/台词与互动反馈 |

## 验收

运行：

```bash
godot --headless --path . --editor --quit
godot --headless --path . verify_player3d_state_gallery_flow.tscn
```

通过条件：场景可解析；界面可找到全部指定控制；玩家保持六顶层状态且换弹为覆盖层；怪物/Boss 使用 `Enemy3D`；NPC 是 `ThemedNPC3D` 并能切换配置与对话。

## 结果

- 新增 `src/player3d/Player3DStateGallery.gd` 与 `scenes/Player3DStateGallery.tscn`：玩家左侧六态、覆盖层和枪械按钮，怪物/Boss/NPC 右侧生成与控制按钮，底部持续显示真实状态、HP、弹药、覆盖层和 Boss 阶段。
- 新增 `src/world3d/ThemedNPC3D.gd`：复用现有 NPC 的配置字段、进入范围、`E` 交互与台词切换语义，用程序化原始体保持可替换。
- `verify_player3d_state_gallery_flow.tscn` 和 `verify_player3d_state_gallery_visual.tscn` 均通过；后者在 Apple M1 OpenGL 1280×720 实机渲染下保存预览图。
- 资产台账未新增美术根 AssetID：更新 `CHR-PLY-CAPSULE01-3D` 的预览场/验收记录，并在“原型角色”页登记入口。
