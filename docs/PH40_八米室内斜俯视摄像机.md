# PH40｜八米室内斜俯视摄像机

## 一、问题与目标

PH38 为彻底取消摄像机驱动的楼板、墙体剖切，把塔楼镜头改成了角色正上方
`(0, 8, 0)` 的90°垂直俯视。它解决了9米层高内镜头越墙的问题，但同时丢失了
原镜头的透视角度和前后纵深，画面更接近平面地图，角色也显得离镜头过近。

PH40 保留“镜头物理高度位于本层内”的约束，但不再把8米误解为完整镜头距离：

- 摄像机相对角色的垂直高度始终为8米；
- 增加朝画面下方的5.5米水平后移；
- 视线落点从角色中心向画面上方前推0.75米、抬高0.45米；
- 基准俯角约51°，恢复角色、地板、墙面和门的纵深关系；
- FOV由43°调整为55°，在不升高镜头的前提下扩大可见范围；
- 不恢复任何墙、楼板或楼梯模型的摄像机剖切。

## 二、室内自适应收镜

固定斜镜头在15米房间或楼梯间靠近南侧墙时，5.5米后移点可能落到墙后。运行时
从角色上身向期望镜头位置检测实体碰撞：

1. 路径无遮挡时使用完整5.5米后移。
2. 路径被墙、关闭门、楼梯墙或实体家具阻挡时，以二分搜索求出墙前可用后移距离，
   并保留0.35米安全余量。
3. 收镜立即执行，避免镜头短暂穿墙；障碍离开后以平滑速度恢复完整后移，避免跳变。
4. 自适应只改变水平后移量，摄像机相对角色Y始终为8米。
5. 镜头旋转每帧重新朝向固定玩法落点，因此收镜后仍保持斜俯视，不切回垂直顶视。

## 三、坐标与玩法契约

- 塔楼层高：9米。
- 角色完整视觉与碰撞高度：1米。
- 摄像机垂直高度：8米。
- 期望水平后移：5.5米。
- 视线落点：角色局部坐标`(0, 0.45, -0.75)`。
- 基准FOV：55°。
- 近裁剪面：0.1米；远裁剪面继续由楼顶/室内状态分别控制。
- 鼠标瞄准继续投影到角色当前物理楼层，不受摄像机倾斜影响。
- 上下层楼板、外墙、房间墙和楼梯墙继续完整渲染，只由真实几何关系遮挡。

## 四、验收条件

- 空旷位置的镜头相对角色Y严格等于8米、Z后移为5.5米，FOV为55°。
- 空旷位置镜头为斜俯视，不能回退为90°垂直顶视。
- 在镜头后方靠近满高墙时，水平后移会收短且镜头不穿到墙外；离墙后平滑恢复。
- 收镜全程垂直高度保持8米，不以降低镜头方式绕过墙体。
- 楼顶、99层基地、98层战斗房和楼梯间四类画面均能看到地面纵深和竖直墙面。
- 现有纯物理遮挡、完整楼板显示、真实上下楼、当前层鼠标瞄准、最多5层流送、
  命运门、电梯、怪物/Boss和性能预算均不回退。

## 五、实施与验收结果

- `TowerDescent3D` 已将塔楼镜头改为相对角色`(0, 8, 5.5)`，以
  `(0, 0.45, -0.75)`为视线落点，空旷位置实测俯角约50.4°，FOV为55°。
- 新增实体碰撞收镜：满高墙进入角色—镜头路径后，二分搜索墙前安全位置并预留
  0.35米；收镜即时、回位按7米/秒平滑执行，整个过程相对Y严格保持8米。
- 收镜没有控制任何Mesh、楼板、房间墙或楼梯墙的`visible`状态；PH38建立的
  纯物理遮挡和最多5层流送规则保持不变。
- `verify_tower_descent_flow.tscn`通过：空旷镜头位置/角度/FOV、人工满高墙收镜、
  收镜时8米高度、五段楼梯双向通行、当前层鼠标瞄准、命运门、电梯、怪物、
  95层Boss和3252节点预算全部成立。
- Apple M1 OpenGL已重新采样楼顶、99层基地、98层战斗房和楼梯间四张PH40画面；
  楼梯踏步、房间竖直墙面与楼顶边缘立面均形成明确透视，角色屏幕占比接近旧斜镜头。
- 360°物理遮挡/输入回归、运行安全回归通过；性能实测生成162.6ms、最重房间
  7.5ms、全探索2950节点、持续帧段6.90ms、稳定视野重绘0次。
