## 0 主轴：链路每一段默认用谁

| 链路环节 | 默认模型 | 为什么 |
|---|---|---|
| 核心体验搭建 | **GPT** | 要一句话立住体验，靠判断不靠检索 |
| 设计文档 | **DeepSeek** | 规则、数值语义、失败语义，属结构化写作 |
| 工程文档 | **GPT** | 模块边界、契约、索引，要跨文件建立一致性视图 |
| 工程执行 | **DeepSeek** | 写代码、探针、批量脚本，可验证、量大 |
| 复杂功能 | **GPT（上浮）** | 命运卡、枪械组装这类跨模块深绑定 |
| 3D 场景 / 动画 / 音效 | **GPT** | 空间判断与质感判断 |
| 测试 / 打包 / 数据脚本 | **DeepSeek** | 机械重复、结果可验 |

### 升级判据（任一命中，就从 DeepSeek 换 GPT）

1. 需要跨 3 个以上模块推理（如命运卡：规则 + 经济 + UI + 存档）
2. 需要穷举失败分支且分支互相影响（枪械组装：配件 × 弹药 × 状态）
3. 需要看图 / 判空间 / 判风格（建模、动画、UI、渲染打分）
4. **同一件事返工两次还不对** —— 不是执行问题，是理解问题，必须换更强模型

## 3 现在最该补的四件事（按性价比排）

1. **打包**：写 build skill，固化导出 + 包体记账（全链路最薄）
2. **测试**：探针结果统一标 L1–L4，回归接到定时任务，不靠人记得跑
3. **音效**：建素材库索引 + 混音基线，不然永远停在「能响但糙」
4. **特效**：45 个文件偏碎，性能预算落表后再谈品质

## 4 模型分工的两条观察

**观察一：GPT 集中在「不能机械验证」的地方。** 看图上 GPT 出现的位置——3C 手感、3D 空间、动画握点、音效质感、UI 可读性、核心体验——全是"没有标准答案、只能看图听声判断"的活。DeepSeek 集中在"有唯一正确答案、结果能跑一遍验证"的活。**这跟模块划分无关，跟任务性质有关。**

**观察二：复杂功能的上浮是暂时的。** 命运卡、枪械组装现在必须用 GPT，是因为多模块状态互相牵制。等这两个功能的规则文档写完整（失败分支穷举到没有遗漏），它们会退回 DeepSeek。**上浮说明文档不够，不说明模型不够。**
