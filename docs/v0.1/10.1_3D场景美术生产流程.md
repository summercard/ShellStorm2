# 3D 场景美术生产流程

状态：`ASSET-SCENE-3D r4`，适用工程版本 `0.1.0`。本流程用于场景、关卡组件和固定设施；通用资产规则见[资产与内容规范](10_资产与内容规范.md)。

## 流程

通用场景资产沿用本页总流程；塔楼战斗区与独立远征房间采用“建模前组件规划 → 组件母版与房型默认实例 → Godot 组件导入 → 房间维护”链路。阶段衔接与历史替代记录见[战局房间美术制成与导入链路](development/2026-09-18_战局房间美术制成与导入链路.md)。旧“先做整屋再拆、Godot 只能重放”不再作为新任务要求。

```text
关卡设计 / 白盒契约：房号、房型、尺寸、门洞、连接、净空
  ↓ 02 在正式建模前冻结组件计划（不超过 50 个组件）
01 Blender 房型源：组件母版 + 链接实例，产出默认 component_instances.json
  ↓ 组件拥有几何、材质、原点、接口与 AssetID，不拥有具体房间世界坐标
组件 GLB / 稳定 Godot PackedScene 导入并逐件验收
  ↓ 03 按需要选择：直接继承默认 / Godot 房间变体 / Blender 差异布局
04 首次装配：默认或差异 JSON 初始化，或白盒 + 已转正组件直装
  ↓ 正式模块化房间 TSCN：允许在 Godot 维护布局、灯光、组件启用与实例参数
分开登记源完成 / 组件转正 / 房间接入，完成对应验收后由关卡调用
```

### 分支隔离与预算适用范围

- `battle` 战局与 `expedition` 远征是独立的关卡系统分支，不是同一拓扑的别名。先按 `block_id / level_id` 读取各自主设计与白盒，禁止互套楼层编号、房间表、模板尺寸、门连接或推进规则。可显式引用同一已验收组件及其稳定 Prefab；复用资产不转移关卡身份或拓扑所有权。
- **50 / 3 / 5 不变，仅约束后续新资产生产**：新房型计划计入自有与引用的唯一组件定义（最多50），同族常规最多3、有明确状态轴最多5，实例数另计。
- **历史例外限于已有资产基线**：保留既有 AssetID、源版本、组件集合及正式房间，不因历史超限强制删件、归并、改名、重导或重生成。例外须能定位到具体既有路径/版本和超限事实，不等于历史门禁已通过，也不豁免碰撞、资源完整性等其他检查。
- 新建房型、新增组件/变体或新增几何定义仍按现行预算先规划；借用历史目录、改名复制、追加旧库版本或把新定义标为“历史”都不能获得豁免。单纯调整既有房间实例与灯光不触发历史资产整改；若新生产范围与历史基线无法分清，先明确范围，不自动扩大例外。

### 房间编辑权与更新边界

- Blender 原始源拥有**组件几何、材质、原点与接口**；组件通过稳定 GLB / PackedScene 引用更新。禁止整屋 GLB，房间只持有组件实例，不展开复制组件内部网格。
- Godot **正式房间 TSCN**拥有房内实例布局、灯光、启用状态及实例参数的编辑权；导入后允许直接手改，不要求每次返回 Blender 重建整屋。运行中的开关状态、门状态机、刷怪、导航与存档仍归玩法层。
- `component_instances.json` / `room_layout.json` 用于首次初始化、来源追溯或经审查的再导入，**不是唯一运行布局源**。L1/L2/L3 仍拥有关卡拓扑、房间身份和结构端口契约，不与房内陈设所有权混淆。
- 组件更新不得覆盖房间编辑：通常只更新组件稳定资源，保留房间 TSCN 的实例变换和覆写。原点、包络或接口变化必须先审查受影响房间，不以重生成掩盖冲突。
- **现有生成器尚无自动合并保护。** `scripts/generate_expedition01_room_static_scenes.gd` 会关闭静态场景加载、重新装配并直接保存同路径；`SS_STATIC_ROOMS` 仅缩小覆盖范围，不能保留选中房间的手调。禁止未审查重生成正式 TSCN；确需重建时，先保全现有差异，再审阅候选、人工合并并复验，不宣称工具已自动保护。
- 预留**房型 → 房间变体 → 具体房间**三层：变体可直接继承默认，也可在 Godot 维护；是否随机选择由关卡策略决定，不要求每局随机。统一的数据登记与解析仍是目标、尚未实现，当前 `room_03` / `room_04` 的代码硬编码绑定尚未迁出。

这条链路只处理场景美术和视觉装配。角色、敌人、武器、道具、战斗、存档、任务、导航、门状态机和撤离结算仍由各自功能/规则流程负责。

## 全过程固定挂钩

每个 3D 场景生产批次从开始到正式接入都必须持续携带同一组定位信息：

- `block_id`：塔楼为 `rooftop / base / battle / stairs`，独立关卡为 `expedition`（`Blocks/Expedition`），不能强塞进塔楼四区块；归属见[关卡区块设计](05.1_关卡区块设计.md)。独立关卡同时携带 `level_id`。
- `floor_range` 与 `design_scope`：具体到楼层、房间、楼梯、设施或模块范围。
- `scene_design_docs`：以对应关卡主设计为首，并挂接[版图规范](05.2_关卡版图白盒与生成规范.md)和[区块归属](05.1_关卡区块设计.md)；塔楼另读[关卡生成与爬楼](05_技术施工_关卡生成与爬楼.md)，基地设施另读[基地设施](07_技术施工_基地设施.md)。
- `asset_ledger`：指向**场景账本** [ShellStorm2_场景账本_v001.xlsx](../../assets/registry/ledgers/ShellStorm2_场景账本_v001.xlsx) 的 `3D-场景通用` 表及对应 AssetID 条目。账本路径由 [ledger_index.json](../../assets/registry/ledger_index.json) 声明，**不要写死文件名**；总目录只放索引，不含资产行。

这些信息不是只写在概念稿里：白盒 JSON 写入字段；风格稿标注范围和引用；Blend 资产包、GLB、PackedScene、导出清单和验收记录均保留 `block_id / AssetID / 场景设计文档 / 台账定位`。缺少任一定位信息的资产不能进入下一阶段。

### 1. 概念稿 / 场景需求

- **规范：** 先明确塔楼四区块或独立远征 `expedition`，范围写到 `level_id`、具体房间、楼梯或设施。区块名称和边界以[关卡区块设计](05.1_关卡区块设计.md)为准；远征01另读[主设计](design/远征关卡01设计.md)，不能套用旧塔楼房数、尺寸或层号。
- **白模数据：** 关卡版图采用[05.2](05.2_关卡版图白盒与生成规范.md) 的 L1/L2/L3；历史 `tools/3Dgame-design` v3 输入保留兼容（`coordinateSystem=blender-z-up`、米/角度、`groups[] / components[]`、`projectMetadata`），不强制把远征设计源改写为该格式。各格式须明确坐标转换和来源，不建立平行几何真源。
- **数据：** `scene_id`、中文名、`block_id`、目标楼层、设计范围、涉及的房间/楼梯/设施 ID、用途、目标平台、风格关键词、参考图路径、禁止项、场景设计文档和资产台账定位。
- **挂钩：** 使用上方“全过程固定挂钩”；此处只建立首次范围说明，后续阶段不得丢失或另造一套定位。
- **Skill：** 暂无固定专用 Skill；以用户概念稿和场景主设计为准。

### 2. 白盒规范快照

- **规范：** 只从当前游戏设计和工程契约提取尺寸，不从旧模型或效果图猜数值。每项数据记录来源文档、章节和读取日期。
- **数据：** 平面网格、场景长宽高、层高、墙高/墙厚、地板厚度、门洞、楼梯起终点、平台高度、玩家/镜头净空、碰撞、导航、拼接插槽、坐标轴和单位。
- **当前塔楼示例：** 5m 平面网格、12m 逻辑层高、11.9m 可见墙高；正式制作仍以任务开始时的[关卡主设计](05_技术施工_关卡生成与爬楼.md)为准。
- **交付：** `whitebox_<scene_id>_v###.json`。
- **Skill：** 暂无固定专用 Skill；使用项目设计文档。

### 3. 白盒组装与顶视图

- **规范：** 白盒设计源定义结构尺寸、连接与净空；先验证网格拼接、门洞、楼梯、路线、碰撞、导航和镜头净空，再交给美术设计。此处的结构约束不把房内视觉布局永久锁在 JSON；正式房间编辑权见上方边界。
- **模块数据：** `module_id`、实例名、中文名、类型、尺寸、位置、旋转、所属组合、连接插槽。
- **组合数据：** `assembly_id`、组合名、用途、包含的模块实例、组合总尺寸。
- **图片：** 至少输出一张带场景总尺寸、网格、组合边界、组合名字、模块名字、门洞和楼梯标注的顶视图；另输出一张同机位无文字顶视图，供风格稿直接叠画。复杂多层场景补立面或剖面图。
- **目录：** `source/art/whitebox/<scene_id>/v###/` 固定分为 `data/`、`blender/`、`renders/` 和 `validation/`。`data/` 保存可编辑 JSON，`blender/` 保存根据同版本 JSON 输出的白盒 Blend，`renders/` 保存顶视图、无文字图、立面、剖面和效果图，`validation/` 保存白盒门禁结果。白盒是过程输入，不进入 Godot 导入。
- **Skill：** 暂无固定专用 Skill；由对应场景的白盒验证入口检查。
- **Blender入口：** 新场景优先使用 `tools/blender_addons/shellstorm_level_builder/` 在 Blender 原生视口完成组件添加、吸附摆放、参数冻结、Collection 归类和资产包清单同步。`.blend` 只拥有该阶段的组件源编辑，关卡结构仍与设计源对齐；正式房间 TSCN 拥有导入后的房内编辑。网页工具只保留旧白盒数据迁移和兼容读取。插件不替代本阶段的尺寸、路线、碰撞、导航与镜头净空验收。

### 4. 基于白盒顶视图的风格设计稿

- **规范：** 直接在无文字白盒顶视图上设计，保留可核对的白盒轮廓。可以改变颜色、材质、灯光、标识和表面细节，不得私自改变尺寸、门洞、楼梯、路线和净空。
- **数据：** 风格稿版本、使用的白盒 JSON 路径、顶视图路径、色彩、材质、灯光、视觉焦点、资产拆分名称和参考图。
- **图片：** 顶视风格稿为必需；需要说明高度和造型时补关键立面、近景或透视稿。
- **Skill：** 暂无固定专用 Skill；需要生成或修改风格稿图片时可使用 `$imagegen`。

### 5. Blender 独立资产包制作

- **规范：** 正式建模前由 02 冻结不超过 50 个组件的计划，同族常规最多 3 个、有明确状态轴最多 5 个；01 按白盒尺寸用组件母版与实例完成房型源，不先造整屋再拆。历史整屋源可整理迁移，不作为新生产顺序。每个可独立替换的模块/设施建立独立包，不把整片场景焊成一个模型。
- **数据：** AssetID、白盒 JSON 路径和版本、资产包名、尺寸、原点、方向、包围盒、材质角色、公共色盘、输出集合、Blend版本。
- **统一过程目录：**
  - 房间种类源：`assets/art/environments/tower_zones/<block_id>/source/room_types/<room_type>/v###/`；
  - 共享组件源：`assets/art/environments/tower_zones/<block_id>/source/common_components/v###/`；
  - 具体房间编号布局源：`assets/art/environments/tower_zones/<block_id>/source/room_instances/<room_id>/v###/`；
  - 组件 GLB：`assets/art/environments/tower_zones/<block_id>/components/<component_slug>/`；
  - Godot PackedScene：`assets/art/environments/tower_zones/<block_id>/runtime/common_components/<component_slug>/`。
- **交付：** 可维护 `.blend`、游戏输出集合、组件计划、catalog、默认 `component_instances.json`、预览图与 Blender 验收结果。03 默认可直接继承；有差异时可维护 Godot 房间变体或正式 TSCN，也可制作只含链接实例的 Blender 差异布局与 `room_layout.json`，不强制重建整屋，不生成房间专用 GLB。
- **Skill：** `02-battle-room-component-decomposer` 在建模前规划，`01-battle-room-type-art-authoring` 制作房型组件源，沿用 `$blender-game-prop-standard`；`03-battle-room-instance-layout-authoring` 负责选择房间继承/差异维护路径。

### 6. 优化、GLB 导出与 Godot 导入

- **规范：** 从已通过美术验收的游戏输出制作优化派生文件；导出稳定路径 GLB，建立独立 PackedScene（版本记在源、manifest、账本与 metadata，不写入运行路径），并配置碰撞、材质、交互、标签和正式引用。不得靠 Godot 临时缩放修复上游尺寸错误。
- **数据：** 源 Blend、优化派生 Blend、GLB、PackedScene、版本、尺寸、方向、材质数、碰撞方式、使用场景、正式引用、上一版本回滚路径。
- **交付：** 优化 Blend、GLB、`.import`、PackedScene、导出清单、资产台账更新、独立加载结果和正式场景截图。
- **Skill：** **`$02b-godot-model-asset-import-standard`（Godot 模型资产导入规范）**。

### 7. 登记正式可用

- **规范：** 只有独立加载、正式场景、玩法通行、性能和真实渲染验收均完成，才登记为正式可用。旧版本保留用于回滚。
- **数据：** AssetID、正式版本、源文件、运行路径、SHA-256、验收命令、退出码、错误、未执行项和回滚版本。
- **Skill：** 沿用 `$02b-godot-model-asset-import-standard`，并执行项目对应的资产与场景专项测试。

发现结构尺寸、门洞或连接错误时回到关卡/白盒契约；组件几何材质错误回到 Blender 源；房内摆位、灯光与启用调整留在 Godot 正式房间 TSCN。不得用一律退回 Blender 的旧规则覆盖房间手调。插件同步的 manifest/catalog/tree 只用于目录与来源追溯，不等于组件转正或房间接入。状态必须分列“源完成 / 组件转正 / 房间接入”：例如标准房的82实例源已完成，但该布局未转正；当前 `room_07` 只是通用壳体接入。
