## 1. 权威时间

`GameTimeManager`是唯一运行时权威，算法放在无节点依赖的`WorldTimeDomain`。游戏从`2075-01-01 17:00`开始，20个真实分钟推进一个完整24小时；暂停时默认不推进。场景只读取时间快照或订阅信号，不自行累计小时。

存档只记录`elapsed_game_seconds`，不读取设备墙钟制造离线进度。累计值每10秒和应用生命周期边界写入`BaseData`；日期、HUD、太阳和基地能源都从同一累计值派生。

## 2. 昼夜与太阳

- 日出06:00、日落20:00；太阳方向按权威时间连续从东向西变化。
- 同一盏正式`DirectionalLight3D`实时读取太阳快照中的角度、亮度和颜色：清晨偏橙、正午偏白、黄昏偏红；12:00峰值严格为`1.0`，夜间能量为0。
- 下午使用延长黄昏曲线，17:00仍保留约0.68太阳能量；`TowerAtmosphere3D`与`BaseWorld3DEnvironment`都直接应用权威太阳快照，不建立第二套场景时钟。
- 环境背景与环境光随同一昼夜因子同步变化；屋顶、墙和楼板仍可通过真实投影遮挡直射太阳。
- HUD在右上雷达下方显示`YYYY-MM-DD  HH:MM`，不另建第二个计时器。

## 3. 基地能源的时间输入

`BaseEnergyService`按每游戏小时4点恢复。同步只使用世界累计游戏秒，因此暂停、倍速和存档恢复保持一致，且没有离线收益。容量、消费、恢复舱与未来基地用电负载读取[电力系统](15.1_技术施工_电力系统.md)。

状态恢复舱按实际缺失比例计费：满HP恢复成本25，满手电恢复成本25，两项相加并向上取整。能源不足时事务拒绝且不部分恢复；成功后同时更新玩家状态、基地能源和基地存档。

手电进入基地后只停止耗电，不自动充电。电池道具仍可按原流程使用；基地恢复舱是恢复HP与手电的统一设施入口。

## 4. 扩展边界

未来天气、作物、生产设施或事件周期通过`register_cycle_extension(callback)`注册，回调只接收`delta_game_seconds`和只读时间快照。扩展模块不得修改世界时钟累计值，也不得各自读取设备日期。

## 4.1 命令、查询、事件与数据单位

| 类型 | 当前接口 | 数据与生命周期 |
|---|---|---|
| 唯一写者 | `GameTimeManager` | `_elapsed_game_seconds: float`，单位是**游戏秒**；`WorldTimeDomain` 只按累计值计算日期和太阳，不保存状态。`BaseManager` 独占长期档写盘。 |
| 命令 | `set_clock_running(bool)`、`advance_real_seconds(real_seconds,persist=false)`、`advance_game_seconds(game_seconds,persist=false)`、`set_elapsed_game_seconds(value,persist=false)`、`restore_from_persistence(snapshot,persist=false)` | 负增量按0处理；`persist=false` 先更新内存并发事件，不表示磁盘已提交。暂停默认停止 `_process` 推进，`advance_while_tree_paused` 是显式例外。 |
| 查询 | `get_elapsed_game_seconds()`、`get_time_snapshot()`、`get_solar_snapshot()`、`get_persistence_snapshot()` | 快照含日期/分钟键/太阳投影；持久化快照含 `elapsed_game_seconds`、`clock_running`、`real_seconds_per_game_day=1200`，长期权威数值仍为累计游戏秒。 |
| 事件 | `time_advanced(delta_game_seconds,snapshot)`、`minute_changed(snapshot)`、`day_changed(snapshot)`、`solar_state_changed(solar)`、`cycle_extension_tick(delta_game_seconds,snapshot)` | 正增量推进后按条件发；显式恢复/设值发完整分钟、日期、太阳状态。订阅者只读快照；基地能源以同一游戏秒值同步，不自建时钟。 |
| 扩展 | `register_cycle_extension(callback)->bool` / `unregister_cycle_extension(callback)` | 无效或重复回调拒绝；当前接口已存在，天气/作物等消费者仍属未来目标。 |

## 4.2 失败与重载边界

启动从 `BaseManager` 读取累计值；`flush_to_profile(reason)->bool` 把时间与基地能源同步后调用 `save_base()`。自动每约10真实秒及应用暂停/关闭通知尝试写盘；返回 `false` 不能宣称新时间已落档，正式运行下次启动仍以最后一次有效长期档为准。当前不存在独立“时间写盘失败重试队列/领域完成事件”；需要严格保证某个周期行为只发生一次时，消费者应自己持有事务 ID，不把 `time_advanced` 信号当成持久化确认。设备墙钟不参与离线补时。

- [x] 基地能源按游戏小时恢复，存档往返不产生离线收益。
- [x] 恢复舱按缺失比例恢复HP和手电，能源不足无半笔结果。

- [ ] `flush_to_profile()` 强制失败、跨重启回退到最后有效时间/能源、订阅者不重复结算的故障专项；目标设备的太阳与 UI 真渲染另验，不由上述逻辑勾选代签。
