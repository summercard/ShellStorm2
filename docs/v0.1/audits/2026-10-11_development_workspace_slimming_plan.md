# ShellStorm2 开发目录瘦身与管理计划

日期：2026-10-11；关联 ASSET-PIPELINE / WORLD-BLOCKS。工程版本0.1.0，分支0.1.2。本页保留实施前估算；两阶段已经实施，当前结果与限制见[执行记录](../development/2026-10-11_workspace_slimming.md)。旧源迁至上层备份，旧缓存永久删除被自动审批拒绝而保留。

## 1. 目标和预计收益

把 `ShellStorm2/` 管理成“正式开发所需代码 + 正式运行资产 + 当前完整设计源 + 文档 + 必要工具测试”的目录。临时验证工程、可再生缓存、旧成品和过期制作批次不再长期堆在工作树里。

本轮目录统计基线 **59.48 GiB**，来自工程结构审计的普通文件清单。体积不是文件系统原子快照，执行前须重新统计。目录链接单独登记，不重复计算链接目标；不把链接删除当作释放目标文件空间。

| 阶段 | 可转出/清理的体积上限 | 工程根预计剩余 | 含义 |
|---|---:|---:|---|
| 第一阶段：临时产物、验证残留、旧成品、缓存 | 37.52 GiB | 理论下限 21.95 GiB；实际略高 | outputs/_scratch中要先提取唯一设计源、编辑器交接数据和最小证据；缓存重建会回涨 |
| 第二阶段：旧版源与备份候选 | 再约 7.15 GiB | 理论下限 14.80 GiB | 数字按文件名分组估算；正式旧版源、外链与未完成设计可能增加保留量 |
| 推荐长期目标 | — | 无导入缓存约15–18 GiB；日常导入后约22–25 GiB | 暂定预算，待源依赖核对后收敛；继续保留完整Git历史 |

**先达到约22 GiB的冷目录，再推进15–18 GiB目标。** 不承诺直接压到5 GiB：Git约5.92 GiB、最新Blender候选约4.72 GiB，加上运行资源、文档与工具，本身有合理保留成本。`.godot` 当前约6.86 GiB，删除仅是一次性释放，重开编辑器会重建；减少无用资源导入后才有机会长期降低缓存。

工程根变小与整盘释放不同：转移到同一I盘的归档仅减少开发工作树负担，不减少I盘总占用。整盘释放来自删除已证实可再生的副本/缓存、或者把历史归档转存其他磁盘或备份介质。归档压缩率先实测，不预报收益。

## 2. 保留文件的判定规则

必须保留四类内容：

1. **正式工程**：project.godot、导出预设、图标、入口场景、src、scenes、data、正式GLB/贴图/音频/着色器、必要.import导入契约、必要UID文件、依赖与插件配置。
2. **设计原始源**：每个独立资产/房型/布局的最新完整可编辑版本，包含未接入游戏但已经制作的设计；模型和动画各自保留母版，组件源与整屋布局源分别保留。
3. **当前正式版本的可重建源**：若最新设计尚未接入，额外保留当前正式版本对应的模型/动画源和导出配方。它不因版本号较旧而自动归档。
4. **文档和工程治理**：全部设计文档（含未实现设计、v0.2计划）、开发记录、审计摘要、资产总目录及九分账本、必要台账基线、核心制作工具与测试。文档本身仅约0.01 GiB，收益很小，全部保留。

“最新”按 **AssetID + 资产角色 + 变体/状态轴** 判定，不是每个文件夹只留一个.blend，也不是整个房型只留最高版本。角色model和animation、各房型、不同楼栋、破损变体、尚在制作的设计不能互相替代。

为每个资产记录：AssetID、用途/变体、设计当前版、正式使用版、可编辑源、外链库/贴图、导出工具/参数、正式GLB/Prefab、账本状态、哈希、验证证据。现有分账本继续拥有资产事实；清理清单只是本批操作记录，不能另造第二套长期账本。

Blender的链接库、贴图/音频路径必须解析到实际文件。跨版本外链指向旧组件时，先把需要的库与最新母版一并保留，或受控迁移并验证；不能直接删除旧目录。未编号源、编号与台账不一致、同版多份内容、不可打开的最高版本，一律列待核对。

自动分组得到 **1087个文件家族 / 1087份最高编号候选，4.72 GiB**；较旧编号候选465份 / 5.86 GiB。这里同时检查assets与顶层source，未把tools/outputs/_scratch里的源自动认作废物。候选清单不能直接输入删除命令。

## 3. 最终目录职责

```text
ShellStorm2/                          正式开发目录
├─ project.godot / export_presets.cfg 工程与发行配置
├─ src/                              游戏逻辑与表现代码
├─ scenes/                           游戏入口/关卡/UI/必要编辑场景
├─ data/                             正式运行读取的JSON等数据
├─ assets/                           正式运行资源及其登记
│  ├─ art/<域>/<套件>/components/     正式视觉模型、贴图、动画输出
│  ├─ art/<域>/<套件>/runtime/        正式PackedScene及必要运行数据
│  ├─ audio/、shaders/、world3d/      正式音频、着色器与相关资源
│  └─ registry/                      总目录、分账本、必要基线
├─ source/                           当前可编辑设计源与制作依赖
│  ├─ art/                           按域/AssetID组织的当前源套件
│  └─ ...                            白盒、布局、原始音乐/图像等设计源
├─ docs/                             所有文档和最小长期验收证据
├─ tools/                            仍使用的制作/导出工具及配置
├─ scripts/                          工程门禁、导入、验证与维护入口
├─ tests/                            开发验收场景/脚本（发行排除）
├─ AGENTS.md、.gitignore 等           工程治理配置
├─ .git/                             保留版本历史
└─ .godot/                           本地再生缓存，不入Git

ShellStorm2-work/                     工程外工作区
├─ sessions/<日期_任务>/             临时制作/探针/运行日志
├─ verification/<运行ID>/            验证工作区，结束回收
├─ renders/<任务>/                   大量渲染帧和预览
└─ build/<平台>/                     临时导出与设备安装包

ShellStorm2-archive/                  工程外历史归档（可转存其他盘）
└─ <日期_批次>/                      历史源/必要回滚包 + 清单/哈希
```

这是职责目标，**按批收敛，不先全仓重命名**。正式components/runtime的现有路径先保持；2026-09-17用户冻结的存量版本命名继续尊重。把assets内部source移入统一source时，必须同批修复Blender外链、导出工具、清单与账本，再验证；没有必要为瘦身强制一次移动所有当前源。

source只承载制作源；游戏真正读取的JSON应落在data或runtime，保留其设计来源映射。不能在游戏中把source的绝对磁盘位置作为依赖。source中仍被运行读取的文件迁移完成后，再统一导入/导出边界。source的最高版本目录可以保留版本号，正式资源新路径遵守稳定命名规范。

根目录最终不再长期保留outputs/output/_scratch/_scratch_logs/build等临时产物家族；相关工具须改为工程外工作目录，不是仅删一次文件。已有工具不能在过渡期因输出目录变化失效。

## 5. 必须先处理的四个依赖

1. **运行数据漏包**：顶层source的expedition_01 level_plan、battle_level01 level_plan、办公室layout已实测在发行包中缺失。将关卡数据/布局依赖闭包迁至data/runtime，更新加载器与设计来源映射；不能只迁一个level_plan而遗漏floors、room_templates或它们引用的文件。
2. **编辑器交接数据**：`scenes/open_world_layout_edit/read_chunk_layout.gd` 仍读取 `outputs/open_world_chunk_layout_20261004/chunk_handoff.json`。把当前定稿交接数据迁到明确的设计/编辑数据位置，更新读取器；TSCN中的source_snapshot元数据及文档链路要保留溯源或归档说明。
3. **动画回退**：`CharacterMotionLibrary3D.gd` 正式读取稳定动画库，仍可能回退production/v009的JSON。先检查所需剪辑并迁到明确稳定位置、保持实际回退语义，再归档旧production。不能只靠直接静态路径扫描裁掉动态版本选择。
4. **Blender源外链**：最新办公室/景观等源可能链接较旧组件库。通过Blender实际枚举库、图像等依赖，验证新位置下打开/导出成功；同路径名称相同不等于内容可替换。

## 6. 执行顺序与每批交付

### 批次A：保护与清单

- 重新扫描工作区；记录Git跟踪状态、当前未提交修改、文件大小/哈希与链接目标，保护当前用户改动。
- 从分账本和源清单确定每个资产的最新设计版/正式使用版，标出尚未接入的设计。把tools/outputs/_scratch里的.blend、图纸和设计JSON纳入唯一源审查。
- 输出逐文件决定：保留、迁移、历史归档、再生清理、待核对，并附理由/目标位置/依赖/验证入口。待核对项不进入删除批。
- 必要历史源先复制归档，逐项校验SHA-256后移除工作树副本；归档成功不以“目录存在”判定。归档目标空间与可恢复性实测。

### 批次B：修复运行/编辑数据边界

- 按第5节迁移运行数据、编辑器交接数据及动画回退数据；设计源与运行投影之间保留明确所有者/生成方法。
- 专项验证远征进入与续档、98F办公室布局、开放世界编辑读取、角色动画回退；用户存档隔离。
- 台账、清单和文档路径同批更新。旧路径只在新路径验证通过后撤下。

### 批次C：回收最大产物

- 优先两大outputs任务的隔离工程和重复快照；提取唯一源与最小定稿证据。
- _scratch按任务核对，工具save内源单独保护；root散件日志/截图移出。
- 关闭Godot后清导入缓存；把验证runner、截图器、渲染器、导出器的默认输出改到ShellStorm2-work，防止重新生成同样负担。
- 每批记录归档量、真实删除量、链接量和剩余量；不把“移出工程”累计成“磁盘释放”。

### 批次D：当前源收敛

- 一个资产套件一批，保留最新设计源+正式源+依赖闭包，模型/动画/变体分别判断。
- 归档旧编号、过期export和大帧序列；备份正本打开/导出通过后才处理.blend1。
- 统一源目录迁移是可选的后续步骤：路径、外链、制作工具、分账本、manifest同批落地并验证。不把历史命名清零塞进本轮瘦身。

### 批次E：发行与最终验收

- 为测试、开发工具、预览/渲染/参考图和纯制作源建立发行排除；保留实际动态加载的JSON/动画数据。测试目录仍保留在开发环境。
- 不以all_resources自动等同正式资源，不把exclude_filter当文件删除；先出候选清单再实导出PCK。
- 包外独立挂载，确认所有必要数据可读；检查预览/测试/工具等候选确实退出发行集合。当前约1.93GiB的包不设未经验证的压缩后硬目标。
- 重导入后运行正式场景与相关资产验收；文档/命名/台账门禁记录既有失败、新失败、未执行项。当前已有文档断链、验证登记和命名门禁问题，不能把整理后“没有新增失败”写成全项目通过。
- 更新工程内独立开发记录和资产/文档导航；给出最终工作树体积、缓存体积、归档体积、PCK体积及保留源清单。

## 7. 防止再次膨胀的规则

- 任务开始使用work/sessions独立目录；验证完成当轮清理隔离工程，只保留摘要和必要截图。
- source每个资产保留当前设计源与正式可重建源；定稿后旧制作批次转归档。过程自动备份在work，避免在正式源目录累积.blend1。
- 新增模板和资产导入工具默认把渲染/QA/临时exports写work；components/runtime只接受正式输出。
- 文档保留摘要、定稿截图和证据索引；大帧序列/整工程副本不进docs。
- .gitignore阻止临时产物入库；.gdignore/导出预设管扫描和发行；三个边界分别检查。已跟踪文件不会因为新增gitignore自动停止跟踪。
- 日常预算：无缓存开发文件15–18GiB；导入后22–25GiB。超过预算先审查大目录增量，不能自动删除源。任务残留按完成状态清理，不按时间盲删。
- Git保留完整历史，去除旧文件工作树副本不意味着历史空间同步消失。重写历史会影响协作者与远端，仅在单独明确目标下讨论。
