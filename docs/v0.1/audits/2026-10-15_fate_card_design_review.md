# 命运卡三作用域与78张牌设计评估

日期：2026-10-15。FeatureID：`FATE-RULES`。工程版本：0.1.0。

**性质：设计评估与改版提案。** 本文记录用户最新明确方向，并逐张评估既有78张牌的正逆位；具体重做、数值、投放和顺序执行方案均为建议，尚未冻结或实施。运行定义仍为48张，另30张待施工；未跑游戏体验测试，不把静态分析写成实测平衡结论。

## 1. 用户已明确的新方向

| 分类 | 影响对象 | 生命周期 | 叠加与顺序 |
|---|---|---|---|
| ★ 星星 | 明确选中的枪械实例 | 沿用枪械永久构筑；随枪带出、转移和保存 | 有构筑顺序，沿用线性追加 |
| ☀ 太阳 | 玩家本次副本的属性与能力 | 到本次副本撤离或失败离开结束 | 可叠加、有顺序 |
| ☾ 月亮 | 下一房间 | 只作用于下一房的一次性房间规则 | 同次购买多张如何组合需定义，建议共同绑定同一目标房 |

太阳和月亮的**分类名称互换**是用户明确要求；星星不变。用户说的“下一房间”优先于旧文档混用的“下一敌对房”“下三房”“整局世界增益”。本评估按房间而非整层/整个远征解释“单次关卡”。塔罗牌本名“太阳”“月亮”与天体分类是两层概念，不自动交换这两个稳定ID或卡面。

仅交换分类名后的牌数仍为星星36、太阳21、月亮21；运行定义对应星星22、太阳12、月亮14。逐卡改域建议尚未执行。

当前源码 `FateCard.scope_special_name()` 仍为 CHARACTER=月亮、WORLD=太阳，内容表和旧牌表也尚未迁移。建议显示层按新分类切换，内部仍用 WEAPON/CHARACTER/WORLD；旧 `fate_moon_*`/`fate_sun_*` 是历史稳定ID，不能批量重命名。具体卡改作用域/时长须单独做版本迁移，保留存档中已承诺的效果或提供明确补偿。

## 2. 总体判断：方向成立，当前内容尚未围绕三个时间尺度收敛

星星让玩家决定“我要带走什么枪”；太阳让玩家决定“这局我要怎样活着打下去”；月亮让玩家决定“下一扇门值得冒多大风险”。三类能自然对应长期资产、本局成长、眼前战术，但前提是购买者能辨认效果落在哪里、活多久。

当前最需要先解决的七件事：

1. **月亮边界混乱。** 旧世界牌有立即钥匙、下一箱、三房悬赏、整局魂倍率、整局撤离时间等，换名字不能自动变成单房牌。21张世界牌需逐张收口。
2. **购卡改变了好坏牌的标准。** 玩家可全买也可不买，纯惩罚牌更可能变成无人买的空卡位。皇帝、星币王牌、星币四应提供明确额外回报；逆位也要有适用构筑。
3. **顺序保存不等于顺序有玩法。** +12%与+20%相乘可交换，先后购买不会产生区别。应让转换、派生、触发改变组合结果，而非强迫所有普通加成出现难懂的数学差异。
4. **有限槽位与有限机会。** 普通枪8格不可逆；远征01设计与L1数据为10间内容房、无支路，最多10次门后购卡机会。三个牌位至多看见30个候选，但不等于能买30张，且只有部分是星星。核心玩法宜在2—3张牌形成，不应要求五张指定稀有牌才能工作。
5. **基础单卡重叠。** 星币二/五都是升品，皇后/星币三都写多掉落，权杖王牌/国王都变大。应分别承担重投、确定品质、物资数量、局部弹体、发射模式等不同职责。
6. **内容承诺不一致。** 皇后/星币三的旧表是额外物品，当前定义为追加候选后仍落一件。权杖二的“过热”在预设中是累计受伤倍率。评估先标明差异，不以任一版本冒充已确认体验。
7. **空转和无限资源组合。** 打空蓄力、回已清房回血、反复拾放回血、换枪印弹、子弹携枪再携枪都可能让最优策略变成拖时间或制造无穷触发。限制应落在明确事件和资源来源，而不只把数值调低。

远征01设计索引摘要仍留有“5主路+6支线”的旧文字，与关卡正文和L1不符；本评估采用正文及L1的10内容房/无支线，并把这一不一致视为证据限制。塔楼与其他远征的路线不同，条件投放按实际关卡能力判定，不能全局删除支路类设计。

## 3. 顺序怎样变成玩家能理解的玩法（建议）

### 3.1 星星：先造形态，再处理产物，但必须明确每张卡作用的节点

建议把每张卡说明补为“输入是什么 → 改变什么 → 输出是什么”，界面以可读动作展示，例如“主枪射击 → 复制一波 → 两波都获得反弹”。

- 普通数值牌允许交换后结果相同；这是正常的，不需刻意制造先后陷阱。
- 结构牌让顺序真正不同：若复制器只复制到当前阶段的弹体，先添加携枪再复制，会复制携枪产物；先复制再仅给主分支挂枪，则复制分支不自动得到挂枪。**这一差异取决于目标节点规则，是拟议规则，不是当前已经实现的结论。** 若后续卡默认作用全部分支，两种顺序就应等价并如实显示。
- 命中、反弹、回程、落地都各自只发生在明确阶段，结束事件有优先级。例如首撞爆炸与穿透不能靠“最后一张把前一张覆盖掉”解决。
- 每个原始攻击保留家族身份；复制、炮台、携枪共享可读的派生上限，防止同一效果自我递归。上限由压力测试确定，超限按预先声明的方式退化，不能随机丢命中。
- 永久刻印前显示当前枪与新效果的实际作用目标和冲突；无需在卡面堆技术字段，可在现有构筑预览中解释。

### 3.2 太阳：有序的角色规则链，而不只是属性列表

建议所有太阳卡按获得顺序形成一个局内序列，普通加成汇总、转换牌只改变明确的上游结果；不允许后来获得的卡偷偷重写过去已经结算的治疗、伤害或魂。

一个有实际差别的候选例子：圣杯侍从提供治疗×1.2，圣杯王后把溢出治疗转盾。假设一次基础治疗20，缺血10，护盾上限15：

- 先侍从后王后：治疗24 → 补血10 → 剩余14变护盾。
- 先王后后侍从：基础治疗20先拆成补血10与护盾10；后续治疗放大只作用于剩余治疗分支，新增溢出不再回流已执行的王后 → 护盾10。

这个模型能解释顺序，但对玩家的学习负担明显高于统一先加成后转盾。建议先用少数转换牌做灰盒试验；预览直接显示“此顺序预计治疗10、护盾14/10”，不要求玩家读公式。若选择统一处理阶段，则这两牌顺序应等价，另外用圣杯十“只强化前一张”等明确邻接牌承载顺序玩法。两种方案尚待选择，不能混着实现。

叠加另有两条底线：普通减伤/冷却须有最终下限；免死等离散次数不适用通用百分比放大。触发链一旦处理过某张卡，同一事件不能回头再触发自身。退出本次副本后规则与临时进度清空；中途续档则保留顺序、次数与冷却。

### 3.3 月亮：下一房的门前契约

建议门后本次购买的所有月亮卡都绑定**同一个即将进入的房间ID**，不是第一张管下房、第二张偷偷排到再下一房。

- 房间加载/敌人生成前锁定规则；退出选卡并进入该房后生效。加载失败时保留同一目标契约，不能重复扣费或重复生成奖励。
- 一次性指“只服务这一房”：减伤可贯穿这一房，首箱奖励只触发一次；离开该房时剩余规则失效。清房后仍在搜箱，搜索规则可以继续，不能清房瞬间全部删除。
- 房间资源是适用性条件。下一房无Boss/无容器/无撤离点时不投对应牌，避免花钱买空气。不能静默跳过无效房并延长到更后面，那违反用户要求。
- 若允许回头离开再进入，房间效果不刷新、奖励不重复；主动离开导致未用收益作废应预告。这里建议首次离开结束，尚未作为正式契约冻结。
- 钱和物品在本房合法获得后仍按普通资源规则保留；“效果仅一房”不等于离房销毁已经拿到的战利品。
- 情报牌可以提前揭示目标房，但不查看后续房。未来占卜屋/工作台若无明确下一房，只登记待绑定卡或不投月亮牌，需与入口体验一起定稿。

## 4. 经济评估：不能只沿用旧兑换价乘1.5

现价普通30、稀有60、史诗110、传说180、禁忌270魂，按稀有度定价，不区分正逆位。本轮不修改价格；以下是平衡方法建议。

- 星星有8格的机会成本与带出价值；太阳随剩余房数贬值；月亮只买一个房间的收益。相同稀有度不代表三类相同购买价值。
- 月亮经济牌净收益近似“额外魂 + 可用物资价值 − 卡价 − 额外弹药/治疗支出”；风险成本还包括失败概率与携带战利品价值。不能仅看奖励面额。
- 已确认的静态倒挂：星币七为EPIC，110魂买3×35=105魂，未计任何其他叠加时已亏5；逆位120魂还取消后两房掉魂。乘上其他增益可能改变收益，但不能靠必须配套另一牌才掩盖基础问题。
- 正义若基础房魂为B、买价P，翻倍只多B，需B>P才有裸经济利润；这还没算敌伤提高造成的风险。建议用真实房间的B分布定价。
- 可测试“同稀有度按作用域设置不同价格系数”，或保持价表而提高单房确定收益。两者是备选方案，不能一边改价一边改奖励后无法分辨效果来源。
- 保留正逆50/50；在身份抽取阶段过滤完全无效的卡，不借适用性过滤偷偷重投已抽到的逆位。若某方向本身不适用，要么两方向都定义最低有效效果，要么在抽方位前排除该身份。
- 只需2—3张就能形成可玩小构筑，强协同作为惊喜升级；不建议未经用户确认强制每门固定一星一日一月。

## 6. 建议先打磨的组合与优先级

先修意义和边界，再扩充30张新牌。以下组合只列体验目标，不声称当前已全部可用。

| 组合 | 想获得的体验 | 主要检查 |
|---|---|---|
| 魔术师 + 权杖二 | 副枪同步压制与热量管理 | 子枪是否独立耗弹、热量是否只属于刻印枪 |
| 战车 + 星星 + 宝剑王牌逆 | 慢速追踪飞行火力平台 | 驻空射击次数与派生预算，不因无限寿命失控 |
| 命运之轮逆 + 高塔 + 宝剑五逆 | 短弹匣、近身换弹爆发 | 有效换弹条件与取消重触发 |
| 权杖八 + 宝剑王后 + 权杖七 | 借墙弹射并在敌群间传播 | 反弹/连锁阶段、几何适配、派生伤害总量 |
| 圣杯二 + 圣杯侍从 + 圣杯王后 | 推进时回血、溢出转盾 | 太阳顺序方案是否可解释，不鼓励回头刷房 |
| 隐者逆 + 圣杯王牌 + 圣杯骑士 | 长冲刺、进退选择 | 无敌覆盖上限和空房刷盾 |
| 正义 + 星币骑士 | 下一房高风险高收入 | 同房叠加、净利润、失败损失，离房后清除 |

**第一优先级：** 分类与时长收口；纯惩罚付费牌；星币七经济倒挂；额外掉落/候选抽取文案差异；空房刷资源；下一房无效目标。

**第二优先级：** 明确星星作用节点与太阳顺序模型；正逆位分别形成策略；分离重复卡身份；补购卡预览与局内状态查询。

**第三优先级：** 在上述规则稳定后逐批开发新增30张，先补能完成现有构筑的牌，再做需要新弱点/关卡结构/弹体机制的牌。

## 7. 后续实施边界与验收建议

本轮只交付评估及方向记录。若推进实施，FATE-RULES统一负责申请与路由；枪实例拥有星星有序刻印，角色局内规则拥有太阳有序序列，房间规则拥有月亮目标房契约。UI只读三者，奖励由既有奖励服务发放，不复制另一套状态。

需要在施工前补齐：`run_id / target_room_id / card_instance_id / apply_sequence / effect_version / effect_snapshot / remaining_charges`，以及应用、查询、进入房间、离开房间、结束副本、导入快照的命令与事件。失败不扣费或原额退费；恢复存档不重新抽正逆、不重发首次进入奖励。

名称迁移应覆盖卡面分类文字、颜色图例、收藏、K页、购卡、来源选择、HUD、数据库显示字段和测试预期；牌面若已烘焙天体符号需逐张检查。旧稳定ID可保留，效果改域/改时长的迁移不能只靠改显示字符串。

验收分两层：

1. 规则专项：相反顺序应不同的组合确实不同，应等价的组合等价；同牌重复、致命伤一次消费、单房跨门/回头/清房搜索、暂停续档、入房失败退款、回弹/多枪/炮台的触发预算。
2. 真实游玩：记录购卡率、购买后触发率、死牌率、到成型所需房数、净资源变化、战斗耗时和撤离率。按正逆、枪型、关卡、剩余房数分组；比较等条件与玩家操作熟练度，避免把强玩家偏好误当牌强。重点观察是否停下来刷空枪/回血，是否能说出两种顺序的区别。

测试须在Autoload前隔离用户数据。数值最终采用真实枪械、房间敌群和弹药压力实测；本报告没有给出未经验证的“最终平衡值”。
