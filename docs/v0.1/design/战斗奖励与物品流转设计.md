# 战斗奖励与物品流转｜功能设计 v0.1

功能ID：`WEAPON-COMBAT`、`WEAPON-OWNERSHIP`、`INVENTORY-SLOTS`、`REWARD-SERVICE`、`WORLD-LOOT`。工程版本：`0.1.0`；设计修订：r5（2026-11-11）。本页是这些功能的**玩法规则与验收意图主设计**；[04 技术施工](../04_技术施工_战斗与局内成长.md)记录当前接口、schema、实现差距，不改变本页目标。数值和具体内容以[内容数据库](../01_内容数据库说明.md)为准。

## 玩家目标与范围

- **[用户设计]** 每把获得的枪是独立物品，永久 `weapon_instance_id` 随装备、背包、地面、商店、保险、结算和存档流转；命运槽、弹药、配件和子弹模块跟随原枪。普通枪基础8个线性、不可逆的武器命运槽；可更换装配不占槽。三类命运作用域分属武器、角色和世界，不能因换枪互相串值。
- **[用户设计｜2026-10-18] 掉落枪械带三档随机品质：蓝 / 紫 / 金。** 蓝色=基础数值；紫色=基础数值上伤害 +10%、命运卡格子 +2；金色=伤害 +15%、命运卡格子 +4。品质在**掉落那一刻**逐把掷骰（同一箱里两把同名枪可以一蓝一金），随实例永久保存，拾取、换装、保险、撤离与存档全程跟随。品质与"这是哪把枪"（物品稀有度 common/rare/epic…）是两个维度：稀有度决定基础数值，品质决定这一把额外的加成。掉落地面物必须能看出品质（名牌写「紫｜步枪」并按品质着色）。
- **[用户设计｜2026-10-18；2026-10-19 加严] 掉落的枪械随机自带一个弹药模块，且该槽不可拆卸。** 远程枪在掉落那一刻按权重掷定弹种（标准 34%、黏黏 15%、回旋镖 13%、穿甲 11%、爆炸 10%、气球 8%、蜂卵 6%、黑洞 3%），随实例永久保存；玩家可在背包/装备页看到具体弹种，但不能更换。**2026-10-19 起手动更换机制整体关闭**：不只是掉落枪，非掉落来源（出厂保底枪、蓝图合成、商人、训练场借枪）也不能从背包、装备界面、局内快捷装配或基地改造台换弹；后续只能通过枪械工坊的特殊流程更换（未实现）。近战武器没有弹药槽，不配弹也不锁。理由：弹种是这把枪的身份，与品质同类；若随时可换，"随机自带"就退化成一次免费自选。模块物品本身仍可掉落、拾取、存放、出售与带入，不能手动装配不等于物品失效。
- **[现行方向]** 战斗、搜索、清房和剧情产出先确定奖励，再按目标发放；玩家能从命中反馈、掉落实体、拾取提示和背包变化判断结果。奖励报告与实际发放一致，不把一次尝试显示成已获得。
- **[用户设计｜2026-10-09，范围调整 21:17]** 怪物掉落和搜索产出的物品必须先以明显的抛物线弹出：从落点抛高，落地后连续弹跳两次；第二次弹跳结束前不可拾取。落点使用以原落点为中心的约 `2m × 2m` 确定性随机散布，X/Z 各自不超过 `±1.0m`，但必须经过房间边界、支撑面和净空校验。角色进入物品约 `2.0m` 的获取距离后才发起拾取；该距离必须可动态调整，不要求角色整个碰撞体接触物品。拾取事务确认成功后，物品沿带弧线的短动画飞入角色身体目标点，再回收地面实体。背包满、装备失败或其他事务失败时，物品不进入飞行动画且继续留在地面。
- **[用户设计]** 基础背包24格；装备背包占专用装备槽，提供扩展格。换成较小背包或卸下时保留基础格与低索引物品，高索引溢出物应落到当前世界，不能静默删除。成功撤离带回原物及原格位；死亡按保险规则处理。

## 所有者与衔接

| 事实 | 唯一写者/协调者 | 下游 |
|---|---|---|
| 伤害结果 | 战斗/受击领域，具体组件见技术施工 | 敌人死亡与反馈；奖励不得直接从 VFX 判定 |
| 奖励解析与发放结果 | `RuntimeRewardCoordinator` 协调 `RewardService/RewardSink` | 地面物、拾取、任务结果；报告只表达已确认的 `grants[]` |
| 背包/保险格位 | `InventoryModule/InsuranceModule` | UI、商人、结算读快照，不另存平行集合 |
| 武器换装 | `EquipmentTransactionService` 协调完整实例 | 装配树是所持枪的运行投影，不是第二把枪 |
| 世界地面物 | 所属关卡场景/房间 | 拾取后转入背包；房间快照负责跨重载恢复 |

正式链路：`攻击意图 → 命中/死亡 → 奖励解析 → 发放口 → 房间地面物 → 拾取 → 背包/武器实例 → 结算/长期档`。剧情刷物和商人购买分别从自己的内容源进入同一物品身份规则。`weapon_content_id` 是枪型，`weapon_instance_id` 是具体枪，`attack_instance_id` 是一次攻击；不可混用。

### 远征01十三房清房奖励契约（2026-11-11 批准实施）

本节冻结远征01的 `clear_drops` 数据契约；它是能力段，不在通用服务内按关卡 ID 分支。`ClearDropService` 在计划生成阶段读取 `room_overrides`，把该房的确定性奖励、拟态概率、命运机会和追加武器一次冻结进本局房间计划；读档、流送重建只恢复冻结结果，不重新抽取或补发旧局奖励。

- `room_overrides.<room_id>.grants` 是清房小包，沿原地面奖励出口消费；清房小包与宝箱解析分账，不替换普通箱原有随机奖励，也不发金币。
- `room_overrides.<room_id>.mimic_chance=0` 仅覆盖该房，不改变全局拟态概率。关键箱禁拟态只由房间 override 生效。
- `room_02`、`room_07` 的 `fate_card_chance=1.0` 替代普通箱的30%一次判定，不额外叠发；`room_02.fate_common_offer=true` 只约束正常购买报价至少含既有普通正位 `fate_scale_node` 或 `fate_bounce_bullet`，不强制弹窗、不改全局价。
- `room_07.additional_weapon` 为一把 `weapon_rifle`、`grade=purple`、绑定 `bullet_module_id=mod_bullet_standard` 的额外武器。它不自动装备、不继承旧枪命运槽或卡片，也不迁移旧存档；普通随机掉落枪仍按原有弹种权重随机。
- `room_guarantees` 的教学保底继续只在候选房中稳定挑一间，追加一把蓝色 `weapon_shotgun`/`weapon_rifle` 与 `item_ammo_pack×100`；新增 `bullet_module_id=mod_bullet_standard` 后由 `ClearDropService → TreasureChest3D → ChestRewardService → RewardService` 传递并绑定。无新物品 ID，不修改资产 XLSX。
- 固定弹药按拆栈/留物规则交付，禁止超过999时静默截断。若背包出口无法承接分拆或留物，报告给主线程，不在本次服务权限内修复。

**13房运行交接**：主线程只在新计划生成阶段调用 `ClearDropService.roll_room_drop()`，将完整返回值冻结为房间 `clear_drop_plan`，清房消费其中 `grants`、`additional_weapon` 和 `chest`。旧计划没有此字段时不按最新配置补造；`Dungeon3D` 负责清房幂等、pending、地面生成和实际拾取。`grants` 是 `{item_id,count}` 描述，逐项转为 `RewardService.resolve()` 的 `kind=item` 条目；`additional_weapon` 单独传给 `ChestRewardService.resolve_additional_weapon(drop,seed,room_id,event_id,floor)`，不得再塞进箱子或重复消费。普通箱 `resolve()` 不解析该追加分账。

`TreasureChest3D.get_save_data()/from_snapshot()` 完整往返箱 ID、档位、池、拟态、`guaranteed_items`、`source_room_id`、可选 `fate_card_chance`、`fate_common_offer`、明确奖励及外观；缺少命运概率时保留普通30%/高级100%的原默认，不能在高级箱上补普通默认。追加武器与清房小包属于房间计划/交付账而不是宝箱账。命运凭据 grant 与内层 item 都携带 `source_room_id/source_chest_id/fate_common_offer`，落地与读档不得丢失。主线程在新 offer 创建时用 `FateEconomyService.price_index_for_room(source_room_id)` 映射价格基准，未知源返回-1并拒绝新报价；不能用已清房数或报价次数替代来源。标记要求普通候选时，在原关卡白名单过滤后、报价冻结前调用 `FateEconomyService.ensure_common_offer()`，没有合法普通卡则保留凭据并拒绝创建。已冻结 offer 的序号、候选、价格、已购位沿原快照恢复，不重算；offer ID 仍由购买事务持有，不归宝箱。

### 宝箱奖励与命运卡专用凭据（2026-11-08 收口）

宝箱是独立的世界奖励系统，不持有命运卡候选、报价、支付或卡牌效果。`ChestRewardService` 只按宝箱档位、局种子、房间/宝箱稳定ID解析标准 `item` grants，并使用独立确定性随机流；`TreasureChest3D` 只负责交互、开箱状态和表现；关卡协调者负责 pending、地面散落、快照恢复及认领后的统一购买事务。

- 普通宝箱：独立 30% 生成 1 枚 `item_fate_card_drop`，另生成 2—3 件消耗品。
- 高级宝箱：固定生成 1 枚 `item_fate_card_drop`，另生成 5—8 件非枪物品和 1 把非近战枪；Boss 宝箱显式使用高级档，品质不改变奖励档位。
- `item_fate_card_drop` 是不进背包的世界交互凭据。靠近不得自动拾取，必须主动点击/按键后复用统一三选一购买事务；创建 offer 失败时保留世界凭据，offer 成功建立并完成认领后才销毁。后续支付失败或取消按冻结 offer 与统一退款规则处理，不重生世界凭据；重复请求仍拒绝且保持幂等。
- 开箱奖励必须从箱体爆点飞出并在箱体周围经过净空、支撑面、箱体和其他奖励的间距校验后落地；不得与箱体重叠、堆在同一点或拥挤到无法辨认。箱体爆点前的 pending 账、流送卸载和重载恢复必须不重发。
- 命运卡凭据的当前生产表现为悬浮、慢速旋转、流光扫描，并在普通掉落基线之外使用 `1.45` 倍视觉放大；落地稳定后开启无阴影紫色局部光，并发射 12 个、寿命约 `0.95s` 的上升发光方块粒子，认领成功立即关闭粒子与局部光。Forward+ 真实窗口已完成命运卡特效与宝箱奖励弧线取证；该证据覆盖生产模型、动画和生命周期，不等同于所有真实关卡奖励数量、摄像机和构图的完整验收。

### 表现层口径（2026-11-10 更新）

业主三条口径：「宝箱出来的时候不要很突兀」「宝箱上面的 E 开启宝箱去掉，和靠近后的文字重复了」「宝箱上方加一个灯，和宝箱模型绑定，不然宝箱在里头根本看不见」。三条都落在 `TreasureChest3D` 一侧，**不改奖励、不改交互协议、不改存档**：

| 项 | 口径 | 所有者 |
|---|---|---|
| 出现反馈 | `VFX-TELEPORT-IN-3D`（FX01-35），暖金 `Color(1.00,0.78,0.32)`、尺寸 `2.0`（= 救援箱消失那档 `1.6 × 1.25`）、贴地抬 `0.05 m` | `TreasureChest3D.play_appear_effect()`；由 `Dungeon3D._on_room_entered()` → `DungeonRoom3D.play_chest_appear_effects()` 与 `spawn_runtime_chest()` 触发 |
| 聚光灯 | 直接复用主角菜单聚光灯的光柱 + 地面光斑 + 真实灯三件套；普通箱鲜亮黄色 `Color(1.0,0.78,0.08)`，高级箱鲜亮酒红 `Color(0.72,0.08,0.16)`；不另造新光效，适度放大沿用主页面尺寸；开箱时按同一 `0.30s` 收灯曲线缩小并消失 | `TreasureChest3D._build_chest_spotlight()` / `_dismiss_chest_spotlight()` |
| 交互反馈 | 不显示宝箱上方任何「开启宝箱」文字；只保留与椅子、灯、可搜索组件一致的 `InteractionDot3D` 圆点。`prompt` 仅作为动作词协议来源，隐藏 `ChestPrompt` 不负责画面反馈 | `TreasureChest3D` |
| 自带地面光 | `OmniLight3D` 挂在 `_visual_root` 下（跟着模型走），暖白 `Color(1.00,0.87,0.64)`、能量 `1.1`、半径 `3.0 m`、**不投影** | `TreasureChest3D._build_loot_light()` |

三条的理由（写在这里，免得后人"顺手优化"回旧样）：

- **出现特效必须用 IN 不能用 OUT**。两者是同一个脚本（`VfxTeleport3D`，`mode = out|in`）的配对：OUT 的环向内收拢，播在"凭空出现"上读作"被吸走"。业主说的是"用那个消失特效"，指的是那套视觉语言，不是那条曲线。
- **尺寸 2.0 的来历**：箱子碰撞宽 1.45 m、本体 1.28 m，1.6 只够把箱子"包住"；出现时环要超出箱子一圈才能先把视线拽过去。再大（≥2.6）会盖到隔壁家具的交互圆点。
- **提示牌是让位不是删除**。没靠近时交互圆点还没聚焦、功能词不显示，玩家仍需要远远就看得出"那是个能开的箱子"；一旦聚焦，近处交给圆点、远处交给牌子。判定用"有没有被聚焦"而不是"距离多少" —— 聚焦与圆点功能词本来就是同一个条件（`provider == _focused_provider`），本类另算一条距离阈值迟早漂开，会出现"牌没了、白字也没出来"的空档。
- **灯必须绑模型、必须不投影**。绑模型是因为箱子会抖动/上跳/被演出 despawn，灯留在原地就成了"箱子跳了、光没动"。不投影是因为本作的阴影只给真正改变空间明暗的顶灯/路灯 —— 2026-11-08 帧时归因那轮实测过：27 盏灯里 24 盏 `light_energy == 0` 却仍每帧渲一张完整阴影贴图，纯浪费 35% 帧时。
- **浅灰救援箱的光跟身板色走**。业主 2026-11-08 专门要求救援箱是浅灰色；给它打一团暖黄光会把它打回彩箱。平涂箱（`body_tint` 生效）的灯色 = `body_tint.lightened(0.5)`。

验收：`tests/verification/verify_chest_appear_fx_prompt.tscn`（core）。详见 [特效规范 §3.10.6](../14.6_特效系统与制作规范.md) 与[开发记录](../development/2026-11-09_chest_appear_fx_light_prompt.md)。

## 数据与生命周期

物品表现遵循[物品道具双模型制作规范](物品道具双模型制作规范.md)：同一物品身份拥有高精度preview与100–200三角面的ground两种模型，分别服务预览和世界地面显示。双源生产不改变拾取事务或库存身份；运行时用途选择尚待正式接入验收。

枪械实例除内容ID外还带 `drop_grade`（蓝/紫/金）：内容ID 决定基础数值与命运槽基线，`drop_grade` 在其上叠加伤害倍率与命运槽格数。**加成只在掉落时落盘一次**（命运槽），伤害倍率由运行时按标签折算 —— 快照里不存倍率，反复读档不得复利。不经奖励链的来源（出厂保底枪、蓝图合成、商人购买、训练场借枪）保持蓝色基线。

内容ID只定义类型；`item_instance_id/weapon_instance_id` 定义可流转实物；奖励事件ID定义一次产出。创建、移交、地面化、拾取、撤离/死亡、重载都保持实例身份。共享物品在一个时刻只能有一个有效所有者。全局所有权账本**[设计方向一致、未实现]**；现阶段的集合去重不能声称跨所有场景/长期档闭环。

## 弹药消耗口径（2026-11-10）

业主口径：「散弹枪，需要改成弹夹为2发，然后每次打出去多少发子弹，每次装配弹药的时候，消耗的普通子弹数量就是多少个。例如散弹枪一次打出去5发，那一次装弹就消耗10发备弹。」

- **弹匣以「轮」计数：1 轮 = 一次扣扳机。** 一次打出的弹丸数（`bullet_count`）只决定这一轮出几个弹体，不进入弹匣读数 —— 散射喷壶是「弹匣 2 轮、每轮 5 发弹丸」，HUD 显示 `2 / 2`，不是「10 发弹丸」。
- **装填按弹丸计价**：`一次换弹消耗备弹 = 装填轮数 × 该枪一次扣扳机的弹丸数`。散射喷壶满匣 = `2 × 5 = 10` 发通用弹药。单发武器弹丸数为 1 ⇒ 成本 1，本规则对它是**恒等变换**，不改变任何单发枪的弹药经济。
- **成本跟随实际弹丸数，不跟枪身静态值**：命运/配件把弹丸数加上去，装填成本同步上涨。否则同一把枪会出现「多打一发不多花钱」的口子，而读数上完全看不出来。
- **只按整轮成交**：备弹凑不满一轮时**拒绝换弹**，而不是把零头扣走只填半格。备弹是背包里的实物（`item_ammo_pack`，1 单位 = 1 发），被扣走却没有装进枪里等于凭空消失。
- **弹药仍是有限资源**（备弹无限的枪是显式例外，见 [04 §6.1](../04_技术施工_战斗与局内成长.md)）：本规则让「弹丸数」成为战力与消耗的双刃 —— 任何抬高弹丸数的构筑必须同时接受更高的弹药支出，不允许只吃收益。

验收：`verify_shotgun_shell_ammo_flow`（内容 / 折算 / 交易三层）+ `verify_finite_ammo_flow`（单发枪旧行为不变）。施工口径与逐枪现值见 [04 §6.1](../04_技术施工_战斗与局内成长.md)。

### 三类近战输入与动作差异（2026-10-16用户要求）

棒球棍是普通近战：按下攻击即挥棒，维持普通三击、单帧命中停顿和现有简洁风痕。大剑点按松开打出左右交替横扫，连点排队三连；按住0.35秒进入旋风，持有期间每0.55秒转一圈、每0.25秒结算一轮360°扇区伤害（基础伤害×0.55），同轮每个敌人一次、保留逐目标墙体遮挡，松开0.3秒收势，旋转时45%移速。大剑蓄势阶段松开即普通攻击；普通连段期间点击继续排队，避免点击被吞。旋风视觉是蓝白双层断续环带，不能形成遮住玩家的实心光盘。

大斧按下开始举斧蓄势，松开执行下劈；不足0.3秒为普通重劈，1.0秒满蓄力，超过上限保持姿势与提示直到松开。普通三段预备0.48/0.52/0.65秒、有效0.14/0.16/0.20秒、收势0.40/0.46/0.65秒，明显慢于棍与剑；每段以头顶下劈为主，第三段预备与回收更慢。蓄力释放时使用独立charged动作，伤害倍率1.2→2.0、击退倍率1.4→2.6随蓄力增长，击退接口上限提高至20m/s但只由蓄力斧提供高值，普通攻击沿用原值。蓄力期间55%移速，满蓄力保持举斧；橙金收缩蓄力环、竖向斧刃拖尾、触地冲击环与碎屑相互区分。普通斧命中停顿2帧，蓄力斧4帧，其他近战1帧；这些是局部固定物理帧，不冻结整个游戏。

状态Owner仍为PlayerMeleeCombat3D，在原四阶段上增加charging/spinning，快照增加attack_mode/charge_ratio/spin_progress；新增阶段不改变Player3D十个移动状态。表现按源动作消费，旋风整身转圈由Blender chest/head/hands/feet动作完成，不改玩法根瞄准。受击、死亡、冲刺、输入锁、收武器、换装、静默必须取消蓄力/旋风并回收持续特效，松开不会误释放已取消攻击。持续特效由动作机借出并显式归还；跟随玩家，场景退出清理。

新增特效为独立Prefab及AssetID，通过VfxPool3D借还；素材无碰撞、无伤害逻辑。全部参数为本次工程补充初值，必须在逻辑和真实渲染验收后记录，不声称已完成数值平衡。
