# 胖子僵尸03运行配置

内容ID `fat_zombie03`，兼容资产ID `ENM-NORMAL-FAT-ZOMBIE03`。本配置复用 Enemy3D 的12态有限状态机。生命、移动、碰撞、伤害、掉落、持久化由 Enemy3D 唯一拥有，动画结束不反写状态。现行视觉映射到 `ENM-NORMAL-FAT-ZOMBIE21` v007，六段源动作加表现层世界支撑锚；旧03的13段动作仅对应保留资源与借皮入口，不代表当前正式胖子视觉，详见“现行2.1视觉契约”。

## 基础规格

运行视觉网格三角面须低于2000。旧03保留资源为512贴图、66骨、13段动作及BellyGroundCompression腹部接地形态键；该规格不外推到现行2.1。现行2.1为597制作顶点/1180三角、41原骨/29原权重组，必须保持原静止骨架、绑定、权重及几何指纹；不得重绑、清洗权重或以运行纠偏冒称源骨架改变。以源级形变采样及Godot真实渲染验收正式视觉。

标准站立高2.2米，显示缩放0.7；圆柱碰撞源半径1.10米、高3.142857米，世界半径0.77米、高2.2米。圆柱覆盖躯干，张开的手臂不扩大移动碰撞。第一层无主题倍率时生命696、伤害19，生命为普通近战怪的4倍。追击速度0.60米/秒，巡逻0.30米/秒；人工光和减速仍走共用规则。旧注入器基线生命100、伤害8、速度20.5714286，用于还原楼层/主题倍率，不直接覆盖3D基线。

> ⚠ **远征01 的实际值高于上述基线**（2026-10-14 业主口径，生命 2026-11-08 下调）：该关通过 `monster_rules.stats.per_kind`
> 做**关卡级绝对覆盖** —— 生命 **500**（原 800）、伤害 **35**、速度 **1.5 米/秒**。基线（696/19/0.60）**未被修改**，
> 仍是其它关卡的取值；两者是「基线 ↔ 关卡覆盖」关系，不是两套真源。
> 见 [远征关卡01设计](远征关卡01设计.md) §4.5.3。

抱扑范围1.55米，前向半角60度，并要求共用视线检查通过；只在 attack 状态结算一次，不能隔墙或攻击背后的玩家。F0—36为1.2秒前摇，F30以后锁定朝向；F36双掌拍合结算伤害，随后1.3秒收势。命中时启动1.3秒冷却，完整攻击最短约2.5秒加状态切换物理帧；人工光额外延长冷却。根节点无突进，错过目标不追踪补拍。

普通子弹仅闪白并覆盖0.3秒上半身 hit_light，保留腿部基础动作。明确要求打断且暴击、击退≥0.8米/秒或单次伤害达到最大生命8%时进入0.8秒 stagger；轻击不能反复锁死厚血怪。现行死亡不留尸体、不播倒地：无预爆配置时立即爆开回收；启用预爆时先走下述待结算阶段，再爆开、结算掉落并回收。资产保留的2.6秒dead动画仅供独立动作预览，不作为正式死亡时序。

### 死亡自爆（2026-10-14 新增，仅远征01）

业主口径：*「胖子僵尸被打死后需要能自爆，会影响所有单位，包括敌对单位和玩家，伤害是 180」*。

配置在**关卡级** `level_plan.json` 的 `monster_rules.death_explosion.fat_zombie03`：

```json
{ "enabled": true, "damage": 180, "radius_m": 5.0, "sfx_radius_m": 20.0, "warning_sec": 1.0 }
```

### 预爆目标规则与快照契约（2026-11-16）

- 来源：用户最新要求；Owner仍为Enemy3D。仅普通胖子及MonsterVariants登记的强化胖子，且已有启用的`death_explosion`能力时读取`warning_sec`；缺省0保持立即死亡自爆，其它怪（包括exploder及仅借用胖子模型的怪）不改变。
- `warning_sec=1.0`：致死后HP保持0，进入`death_warning`待死亡结算态；原地停止，禁用物理移动和碰撞、拒绝后续伤害/治疗及非死亡状态切换。保留房间成员及清房计数，不提前发`killed`、掉落、解封或清房。表现保持idle站姿并颤抖，身体使用自身实例已有材质，不播倒地。预爆额外自发光采用后段提亮的二次曲线：`p=clamp(elapsed/duration,0,1)`，`E_added=0.35*p²`，材质能量为原基线加`E_added`，暖绿`Color(0.32,0.55,0.10)`；1秒内0/0.25/0.75/0.95/1.0秒对应额外能量0/0.021875/0.196875/0.315875/0.35。普通/强化共用此曲线，仅表现变化，不改变预爆时长、伤害与快照；目标是前段保留身体体积明暗，后段逐渐变亮而不成为纯色平片。
- 满1秒后只调用原死亡流程：原180伤害、半径、敌我过滤、地面持续伤害场不变；爆炸之后再发`killed`，清房和掉落各恰好一次。级联被炸死的每只胖子均从自己的致死时刻独立等1秒，反向爆炸不能重复引爆待结算者。
- 快照沿用`export_runtime_state/import_runtime_state`，新增`death_warning_remaining_sec`（秒，缺省0）、`death_warning_duration_sec`（冻结本次总时长，缺省0）。`ai_state=death_warning/hp=0`仍保存于原房间enemies数组，不能因HP为0被丢弃；终态dead仍沿原过滤不保存。剩余时间只由Enemy3D表现帧推进，不受AI休眠影响；流送卸载/暂停/离线不推进，恢复按剩余时间继续，不重置1秒、不重新发致死伤害。重复导入不能延长当前待结算时间，也不能将已死亡实例复活。
- 独立验收必须覆盖预爆中真实房间捕获/恢复、流送、重复调用、级联、能力缺省和exploder不变；实际网格材质及站姿颤抖用真实渲染器核对，不能仅以诊断字段代签。

- **伤害是固定值**，不走 `contact_damage` ⇒ 不受楼层缩放与主题倍率影响（写 180 就是 180）。
- **敌我通吃**：半径内**所有单位**（相邻敌对怪 ＋ 玩家）都吃 180。
- **可级联**：隔壁残血胖子被牵连炸死 ⇒ 它走自己的死亡流程并自爆；反向炸回已被
  `take_damage` 的 `ai_state == "dead"` 挡掉 ⇒ **不无限递归**。
- **同房过滤**：`query_radius` 带 `room_filter` —— 门关着时跨房的怪不被炸、也不被顺带激活。
- **不转移仇恨**：怪物 AI 目标只从 `player_3d` 组取 ⇒ 「怪炸怪」只掉血、不互殴。
- 触发点在 `Enemy3D._die()` 内、`killed.emit` **之前** ⇒ 被自爆炸死的怪也各自走完掉落结算。
- **不复用** `exploder._explode()`：那是炸弹果的**主动贴近**自爆，只伤玩家、用 `contact_damage`、
  半径硬编码 3.0 m —— 三条语义都不同。实现见 `Enemy3D._detonate_death_explosion()`。

⚠ `radius_m = 5.0`（= 一个 5 m 砖格）与 `sfx_radius_m = 20.0` 是**默认取值**（业主只指定了伤害 180），
调整只改这一个 JSON 字段。

## 现行2.1视觉契约

FeatureID：`ENEMY-AI / ASSET-PIPELINE`；工程0.1.0；视觉修订v007。来源：用户批准的原骨架/原权重约束与滑步修复要求。只替换普通及强化胖子的视觉，不改 `fat_zombie03` 玩法ID、AssetID、投放、碰撞、伤害、掉落、预爆和存档；三种远征03借皮怪仍用旧03资源。稳定入口为 `assets/art/enemies/normal_enemy_3d/fat_zombie21/runtime/enm_normal_fat_zombie21_root_top3d.tscn`。

- **制作源与缩放**：模型v002、动作v007；源高0.7983404m，包装缩放3.936738、外层基础倍率0.7，参考总视觉缩放 `2.7557166`，世界高约2.2m。六段60fps源动作为idle F0—192/3.2s、walking F0—120/2.0s、running F0—72/1.2s、move_start F0—24/0.4s、move_stop F0—36/0.6s、attack F0—150/2.5s。idle与已确认attack曲线保持不变；起停源保留，不把它们当本次源锁脚验收对象。
- **distance phase**：从 `CharacterBody3D` 祖先真实 `global_position` 的水平位移取 `actual_distance_game_m`，不从预爆颤抖的视觉根取距离。`stride_length_game_m = reference_stride * actual_total_visual_scale / 2.7557166`，walking参考stride=0.6m、running=0.72m；等比强化按总缩放同比标定。`phase = fposmod(phase + actual_distance_game_m / stride_length_game_m, 1.0)`，`sample_time_s = phase * clip_duration_s`；内部保留unwrapped phase用于跨循环支撑段。停止/堵墙/重复同步且无位移时不推进；不使用速度变化后重算整个elapsed相位的方式。
- **速度契约**：0.30/0.60m/s仍是巡逻/追击设计基准和步幅标定参考，不能以修滑步擅改。无关卡覆盖时现行基础实际速度为 `0.30/0.60 * PACE_SCALE(0.85) = 0.255/0.51m/s`；人工光、关卡覆盖及强化仍由原玩法规则计算，视觉只消费实际位移。
- **局部世界锁脚**：`procedural_pose=true`，明确是源曲线采样后对原支撑骨组施加世界刚体锚纠偏，不是纯曲线、无补偿或严格等长IK。Lfoot/Rhand相位偏移0，Rfoot/Lhand偏移0.5；walking完整stance duty=0.60、running=0.61，以 `floor(unwrapped_phase+offset)` 识别自然连续支撑段，不能按漂移大小反复重锚以规避阈值。先恢复上次源局部pose再采样，从同一未纠偏世界pose快照父先子后写入支撑骨；移动pose scale为1，非移动保留源曲线。
- **起停与切换**：moving状态直接采walking/running，不再播放旧move_start；停到idle时才允许原move_stop，非移动出现实际位移则取消补充事件。同相位walking/running切换采用0.08phase pose混合和支撑锚，swing纠偏在0.12phase消退；堵墙时混合随相位冻结。非movement、death_warning、离树、垂直离地、大瞬移或跨完整周期清锚。以上仅表现，不写CharacterBody位置/速度、玩法状态或碰撞。
- **攻击不改玩法边界**：旧03 F36是原动作的历史帧号；现行2.1使用源 `F78/60fps=1.3s` 接触姿态，前摇按比例映射到玩法1.2s，attack保持接触帧，恢复1.3s采到源F150。砸地VFX每轮一次、无伤害；伤害仍由Enemy3D原流程结算。攻击不叠步态pose混合。
- **动作覆盖**：dormant/stagger/dead回退idle首帧；alert回退idle；patrol用walking，chase/search/return用running；telegraph/attack/recovery用attack；预爆沿原idle站姿/颤抖/材质反馈。没有hurt/dead/awaken/alert/turn_l/turn_r/hit_light独立剪辑，受击仅闪白，不宣称沿用旧03的13段动作验收。
- **验收要求与入口**：`tests/verification/verify_fat_zombie21_gait.tscn`；使用工程外隔离Runner，在Autoload之前隔离APPDATA/LOCALAPPDATA，不触碰正式存档。对原48个支撑顶点按实际Mesh骨权重、Skin bind和Skeleton pose蒙皮到世界，测完整stance、跨循环全pairwise直径；支撑漂移、切换跳变目标均≤0.01m（1cm）。至少两循环、实际巡逻/追击/人工光/关卡覆盖/强化体型、加速刹停、真实墙堵墙、转弯、双向动作切换与攻击回归；真实Forward+连续视频不得由headless或骨中心度量替代。限定转角、非等比缩放、台阶/动态平台等未覆盖条件不能外推为通过。

本节只定义现行契约；变更过程、实际结果与风险见[滑步修复独立开发记录](../development/2026-11-17_fat_zombie21_gait_fix.md)，历史替换证据见[2.1入口替换记录](../development/2026-11-17_fat_zombie21_replacement.md)。

## 状态表现

以下旧03动作状态表仅适用于保留的旧资源；正式2.1视觉按上节六段映射，不得将本表13段动作当成当前能力。

预爆`death_warning`保留在原房间成员及视野组（否则既有快照只保存非dead实体会漏掉待结算者），但物理AI停止、碰撞关闭；计时由Enemy3D表现帧推进，AI休眠不重置。暂停/流送卸载不计时，恢复继续剩余时间。满时转dead并沿既有无尸体死亡路径爆开回收；`enemy_death_visual_3d`仅用于其它确有尸体的敌人，不新增胖子尸体。

| 状态 | 动作与时间 |
|---|---|
| dormant | idle首帧，暂停表现预算 |
| idle | idle循环；从休眠激活播放awaken 1.2秒；巡逻停止播放move_stop 0.6秒；原地实际转向触发turn_l/r 0.8秒 |
| patrol | move_start 0.4秒接walking 2秒循环 |
| alert | alert 0.6秒，与状态时间同步 |
| chase / search / return | running循环；实际速度影响采样步频，状态决定选段 |
| telegraph / attack / recovery | 同一attack连续采样0—1.2 / 1.2 / 1.2—2.5秒 |
| stagger | hurt 0—0.8秒 |
| death_warning | idle首帧站姿，表现根颤抖、暖绿自发光额外能量`0.35*p²`（0→0.35）；时间来自Enemy3D剩余秒数 |
| dead | 正式死亡即爆开回收；资产dead 0—2.6秒仅保留动作预览 |

补充动作会被更高优先级战斗状态取消。hit_light是局部替换轨道，采用导入骨骼旋转的权重混合，不生成程序姿势；攻击、硬直和死亡期间不覆盖主动作。

## 正式调用

独立实体场景：`res://scenes/enemies/fat_zombie03.tscn`。实例添加到世界后可直接使用标准默认属性；按关卡生成时先调用 `MonsterInjector.generate_box_enemy("fat_zombie03", floor, floor_level)`，再交给 Dungeon3D 既有生成路径。固定波次可写 `{"monsters":[{"type":"fat_zombie03","count":1}]}`；触发盒`spawns[].type`白名单已接纳该type。通用接口`generate_enemies({"type":"fat_zombie03","count":1,"floor":1})`也可点名生成。按用户最新指令，胖子僵尸接替壳甲卫兵：远征纵列与桥心盒、默认随机池、锈炉与深渊主题池、守卫缺省类型均使用fat_zombie03，原数量、延迟和权重保留。shielded退出新刷怪白名单及编辑器选项，旧存档兼容代码保留；未实装的壳甲精英设计继续保留，不作为现行普通怪投放。

可玩展示场景：`res://tests/verification/preview_fat_zombie03.tscn`，用于查看姿势、攻击与死亡。专项门禁：`verify_fat_zombie03.tscn`；预爆专项`verify_fat_death_warning.tscn`（必须由工程外Runner在Autoload前隔离APPDATA/LOCALAPPDATA，`--integration`覆盖正式房间快照/写盘回读/流送，`--render`采集真实材质截图）。未知种类返回空配置；现有通用类型的默认行为保持原值。保存/恢复沿用 Enemy3D 的enemy_data、状态时间、位置和旋转协议。

动作美术设计仍以《胖子僵尸03动作设计.md》为主，本文仅登记运行契约。修改数值时同步该文档和专项断言；不通过复制第二套状态机修复表现。
