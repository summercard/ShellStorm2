## 1. 三份文档的分工

| 文档 | 回答的问题 | 改它的时机 | 不写什么 |
|---|---|---|---|
| 本文（节点表） | 主线在哪几个节点演、演什么、多久、锁不锁操作 | 增删节点、挪触发点、改时长或锁操作 | 台词原文、分镜逐秒、触发引擎语义 |
| [剧本](主线剧情剧本.md) | 玩家具体看到什么：地点、动作、台词、镜头、操作交还 | 改表演内容 | 触发条件、接口、验收 |
| [08 剧情触发](../08_技术施工_剧情触发.md) | 系统怎样执行：触发源、时间轴、指令、占用归还、失败语义 | 改系统能力或契约 | 剧情正文 |

三份文档按剧情编号一一对应；同一改动同时影响两份以上时，必须一次改完，不允许只改一份。

### 1.1 表达方式定位｜方式A / 方式B

定义唯一来源为[主线剧本·方式A / 方式B](主线剧情剧本.md#story-presentation-modes)：A为真实场景角色演绎与运镜、头顶三点示意，文字可共用底栏但无侧边立绘；B为底部对话框＋两侧人物立绘（只有一侧出场仍属B）。二者叠加明确记A+B，不能因有底栏就判B。以下是当前静态实现分类，**不是本次切换方式的指令**；无运行字段或开关随本轮落地。

| 本表节点 | 表达基础 / 明确用途 | 当前方式与B混入范围 |
|---|---|---|
| 01、02第二房/第四房、2.1、2.2、2.3、03、04 | 方式A的现场演绎基础；短反应可无独立运镜 | 当前A+B：共用底栏按主角身份请求右侧立绘 |
| 2.5 | 关灯前置，无对白现场事件 | 不自行请求B |
| 3.1 | A：双人现场说明、运镜指情报室 | 当前A+B：绿苔11句＋主角4句，双侧发言后留场 |
| 3.2 | A：坡道/显示器对峙与真实激活 | 当前A+B：11条显式Boss身份字幕＋主角1句 |
| 3.3 | A：真实跑动、钥匙交接与斜插 | 当前A+B：绿苔3句左侧立绘；主角无对白，不自动出右侧 |
| 05天台怪群 / 吊桥前 | 无对白现场事件 / A的聚焦运镜 | 两段均无文字cue，不自行请求B |
| 命运教学drop / open / assembled | 明确采用方式B的引导 | 绿苔左侧全息＋主角右侧普通半身像；不迁移绿苔本体 |

原主线14份脚本中11份有B请求路径，28条 `actor.say` 加3.2的11条Boss字幕，共39条直接请求人物立绘。12份01—04及插段中只有2.5无对白；另外05两份亦无对白。逐段证据见[剧本核对表](主线剧情剧本.md#story-presentation-current-audit)及[独立记录](../development/2026-11-17_narrative_presentation_ab_audit.md)。本次不改节点、台词、时长、操作锁、JSON与存档，不代签真实渲染或新档贯通；旧主线是否改回纯A另行决定。

## 3. 编号体系现状

`01 → 02 → 2.1 → 2.2 → 2.3 → 2.5 → 03 → 3.1 → 3.2 → 3.3`；原 `04 → 05` 保留为天台支路，不在主线演出期间抢播。

- 02 与 05 各含两个地点，仍共用一个主编号，靠「·第二房 / ·第四房」「·天台怪群 / ·吊桥前」区分子段。

## 6. 维护流程

1. **加一个节点**：先在本表登记一行（楼层 / 节点 / 编号 / 时长 / 锁操作 / 副作用）。
2. 在[剧本](主线剧情剧本.md)写对应章节（地点、动作、台词、镜头、操作交还）。
3. 在 `data/narrative/` 落 JSON，并在 `src/narrative/NarrativeCatalog.gd` 登记 `narrative_id`。
4. [08](../08_技术施工_剧情触发.md) 只在该节点带来新接口、新触发源或新失败路径时更新。
5. 跑 `python scripts/check_documentation_contracts.py`；涉及运行行为时另跑对应 `verify_*` 专项。
