# 新关卡设计表

> **怎么用：** 说「准备生成一个新关卡」，这份表会发给你。你只填**第一部分**，填完发回，技能按它产出关卡并校验。
>
> **读法：**
> - 第一部分 —— 你要填的，没有默认值
> - 第二部分 —— 可以改的，不改就按默认跑
> - 第三部分 —— 全项目固定，不能改，列出来只是让你知道边界在哪
> - 第四部分 —— 工具自己算的，不用填
> - 第五部分 —— 填错会被直接拒的硬规则，填之前扫一遍

## 1.7 房间刷怪（可选，大多数关卡不用填）

不填 → 每间房的敌人数、波数、出什么怪，由游戏按这张关卡的情况自动算。这是默认行为，也是推荐做法。

只有当你要求**某一间房必须固定刷法**（波数固定、每波数量固定、每波出什么怪固定）时才填：

| # | 房间标识 | 第几波 | 这一波出什么（种类 × 数量） |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

| 列 | 说明 |
|---|---|
| 房间标识 | 引用 1.4 里的房间标识。**只能填会刷怪的房**（内容类型是 `COMBAT` / `ELITE` / `TRAP` / `STORAGE` / `SCAVENGE` / `BASEMENT` 的那几间，**Boss 房除外**）；安全房、撤离房这类不刷怪的房写了不生效，Boss 房写了也不算数，都会被直接报错退回 |
| 第几波 | 出场顺序，从上往下依次出。同一间房最多 6 波 |
| 这一波出什么 | 写「种类 × 数量」，一波可以写多个种类。种类只能从下面 6 个里选 |

**可选的怪物种类（只能填这 6 个）：**

| 填什么 | 叫什么 |
|---|---|
| `melee_chaser` | 小菌猪（近战冲撞） |
| `ranged_caster` | 孢子射手（远程） |
| `summoner` | 蜂巢怪（召唤） |
| `shielded` | 壳甲卫兵（护盾） |
| `exploder` | 炸弹果（自爆） |
| `ambusher` | 地刺虫（伏击） |

**限制：** 一波最多 24 只，同一间房所有波加起来最多 64 只。Boss **不能**填在这里 —— Boss 有它自己的出场规则。

你只填「要谁、几只」。**怪的强弱（血量 / 伤害 / 速度）不用填，填了也不生效** —— 那是游戏统一口径，填了会造成两处数字打架。

> 填了某一间房，**只影响那一间房**。同一张关卡里没填的房继续按自动算法出怪，可以拿它做对照。
>
> 填法在数据里长这样（技能会替你写，你不用管格式）：
> `"enemy_spawn_plan": { "waves": [ { "monsters": [ { "type": "melee_chaser", "count": 2 } ] } ] }`

> ⚠️ **Boss 房不要填这一节。** Boss 房不是「不刷怪」，而是**不归这张表管** —— 它要出首领，
> 只是归属「1.8 房间首领」那一节。填在这里会让游戏跳过首领生成，表现为「Boss 房没有 Boss」。

## 1.9 房间掉落（可选，大多数关卡不用填）

不填 → 每一间房的掉什么，由游戏按这张关卡的情况自动算（房间有多深、是不是精英房、有没有怪物）。这是默认行为，也是推荐做法。

只有当你要求**某一间房必须固定掉什么**时才填。三个触发点各填各的：

| # | 房间标识 | 触发 | 掉什么 |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

| 列 | 说明 |
|---|---|
| 房间标识 | 引用 1.4 里的房间标识 |
| 触发 | `clear` 清房奖励 / `search` 搜箱子 / `kill` 打死怪。**只能填这三个** |
| 掉什么 | 写「池名字」或「固定物品」。池名字从《掉落池》表里选；固定物品从《掉落物品》表里选 |

三个触发的适用范围不一样。**下表第 4 列是游戏真的会拦你的地方，前三列是「写在哪里才有意义」**：

| 触发 | 什么时候生效 | 写在什么房上有意义 | 填错了会怎样 |
|---|---|---|---|
| `clear` | 这间房被打通、门锁解开的那一刻 | 会刷怪的房 | 不拦截（但可能永不触发） |
| `search` | 玩家搜完一个容器的那一刻 | 会有容器的房 | 不拦截（但可能永不触发） |
| `kill` | 这间房每只怪被打死的那一刻 | 会刷怪的房 | **直接报错退回**（Boss 房 / 安全房 / 撤离房写 `kill` 一律退回） |

**「会有容器的房」怎么算：** 容器（以及家具）是**每间房各 50% 随机生成**的，所以战斗房、拾荒房、仓库房都可能出现容器，拾荒 / 仓库 / 地下室还会**多给 2 个**。只有**天生不放道具的房**永远没有容器可搜 —— 设施房、楼梯厅、Boss 房、天台。写在那种房上不会报错，但那个 `search` 槽位永远等不到触发，等于白写。

**怎么算「掉什么」——两种写法，别混着用：**

| 写法 | 你写什么 | 结果 |
|---|---|---|
| 池 | 池名字，比如 `loot_floor_3_4` | 从池里按池自己定的规则挑 |
| 固定物品 | 物品名字，比如 `item_health_potion` | 必给这一件 |

池自己定的规则有两种，**在《掉落池》表里定，不在这里定**：

- **加权抽签**：池里每个物品有一个权重，按权重归一抽。**一定会出货**（抽几次就是几件）。
- **逐件独立**：池里每个物品各写一个概率，**互不影响**。可能一件都不掉，也可能同时掉好几件。

> ⚠️ **逐件独立时，掉率不能相加。** 池里有 A（20%）和 B（50%）两件时：
> 「至少掉一件」是 **60%**，不是 70%；「两件都掉」是 **10%**；一件都不掉是 **40%**。
> 这个数你不用自己算 —— 《掉落池》表会直接把折算好的概率和空手率显示给你看，照着读就行。

**限制：**

- **一次最多掉几件，由池决定，不在这里写。** 默认最多 1 件（和现在的玩法一样）；想让某个池能掉多件，要去《掉落池》表里提高那个池的上限。
- 池名字 / 物品名字**写错不会被随便换一个顶上**，而是这一格干脆不生效、并报错退回。发现「我明明写了却没掉」，先检查拼写。
- 池名字必须已经在《掉落池》表里登记过；没登记的一律退回。**不要在这里现造一个新池名字** —— 池要先登记。
- 出现在同一池里的物品，字段必须统一：加权池写权重，独立池写概率，混着写整池作废。

> 填了某一间房，**只影响那一间房**。同一张关卡里没填的房继续按自动算法掉落，可以拿它做对照。
>
> 填法在数据里长这样（技能会替你写，你不用管格式）：
> `"reward_plan": { "clear": { "pool_id": "loot_floor_3_4" }, "search": { "pool_id": "scavenge_floor_1" }, "kill": { "pool_id": "loot_floor_1_2" } }`

> ⚠️ **Boss 房不要填 `kill`。** Boss 掉什么由首领名册统一决定，不归这张表管 —— 和第 1.8 节同一个道理。`clear` / `search` 写在 Boss 房上同样会被退回。

| 生成重试上限 | 24 | 生成的容错次数，通常不用动 |

| 项目 | 值 |
|---|---|

| 墙厚 | 0.30 m |
| 层高 | 12.0 m |
| 可视墙高 | 11.9 m |
| 场地尺寸 | 250 × 250 m |
| 场地中心 | (2.5, 2.5) |
| 核心筒尺寸 | 65 × 65 m |
| 核心筒中心 | (2.5, 2.5) |

## 「运行时数据驱动」为什么现在关着

打开它，游戏才会**真的改用这张表**来生成关卡；现在游戏跑的仍然是内置的老生成器，这张表做出来的东西只有校验器在看。

之所以先不打开 —— 切过去会改变关卡的内部指纹，而玩家存档是靠这个指纹认领自己那一层的关卡的。**指纹一变，玩家手上的存档就对不上，直接打不开。**

所以：设计表可以先做、可以先校验，但**不要因为校验通过就把它打开**。要不要切、旧存档怎么办，得先定下来再说。

# 第四部分 · 工具自动算的（不用填）

| 算什么 | 怎么来 |
|---|---|
| 房间的运行时编号 | 层号 + 房间标识 |
| 关卡指纹 | 按整份设计数据算出来，进存档 |
| 每个门的方位与门槽位置 | 由父子房间的中心坐标推导 |
| 门所在墙的长度 | 取房间在延展方向上的尺寸 |
| 楼梯保留区 | 塔楼按出入口方向自动生成 20×30 m；单层关卡没有 |
| 面积预算 | 按房间面积与占用率算 |
| 走廊记录 | 由两端门中心距推导 |

**关于门方位：** 平面图上的 +y 方向对应世界坐标的**南**。这条约定全项目只有一处实现。历史上它曾经整体写反过，而没有任何检查能发现 —— 因为门槽位置仍然是对的，几何校验不会失败。现在校验器会逐条比对，写反即报错。

# 第六部分 · 填完之后会怎样

技能按顺序做四件事：

1. 补全所有自动算的量，产出关卡设计数据
2. 跑校验 —— 不通过就逐条报错，指出是哪一行哪一列
3. 通过后登记这张关卡的标识
4. 报告产出清单与校验结果

**校验命令**

```bash
Godot_v4.6.3-stable_win64_console.exe --headless --path . \
  res://tests/verification/verify_level_plan_design_source.tscn -- --level=<关卡标识>
```

省略 `--level=` 时校验全部已登记关卡。

**判据：** `LEVEL_PLAN_VALIDATE_OK levels=N checks=K rooms=R templates=T`
　　　　　`LEVEL_PLAN_RUNTIME_GUARD_OK levels=N rooms=R checks=K plans=P rewards=W`

两条都会打印。第一条查设计数据本身自不自洽；第二条**真的调一次生成器**，查产出里每一间房的类型、尺寸、计数对不对 —— 功能房（入口 / 出口 / 撤离房 / Boss）的类型必须正确，内容房必须被分到内容类型。

末尾的 `plans=P` 是「1.7 里填的刷怪计划，有几间房真的带到了运行时」。**你在 1.7 填了几间，这里就该是几**；填了却显示 `plans=0`，说明没接通，要回来查。

`rewards=W` 同理，是「1.9 里填的掉落计划，有几条真的带到了运行时」。**你在 1.9 填了几条，这里就该是几**；填了却显示 `rewards=0`，说明没接通。
