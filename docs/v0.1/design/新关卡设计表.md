# 新关卡设计表

> **怎么用：** 说「准备生成一个新关卡」，这份表会发给你。你只填**第一部分**，填完发回，技能按它产出关卡并校验。
>
> **读法：**
> - 第一部分 —— 你要填的，没有默认值
> - 第二部分 —— 可以改的，不改就按默认跑
> - 第三部分 —— 全项目固定，不能改，列出来只是让你知道边界在哪
> - 第四部分 —— 工具自己算的，不用填
> - 第五部分 —— 填错会被直接拒的硬规则，填之前扫一遍

---

# 第一部分 · 你要填的

## 1.1 关卡本身

| 项目 | 填 | 说明 | 可选值 |
|---|---|---|---|
| 关卡标识 | | 这张关卡的唯一名字，也是存档里认领它的凭据 | 小写字母、数字、下划线 |
| 关卡中文名 | | 界面上显示的名字 | 任意 |
| 所属区块 | | 决定玩家从哪儿进这张关卡 | 远征线填 `expedition`；塔楼楼层填 `battle`；`rooftop` / `base` / `stairs` 一般不用 |
| 版图来源 | | 这张表的布局就是最终版图（每次一样），还是只给约束、由工具自己生成 | `authored`（表即最终版图，推荐）/ `constrained`（约束内生成） |
| 生成规则版本 | | 记录这张关卡用的是第几代生成规则，会写进存档 | 新关卡一律填 `2` |

| 列 | 填什么 | 可选值 |

| 房间标识 | 这间房在这一层里的短名，连通关系靠它引用。**不要用 `start` / `floor_01_*` 这类老的运行时名字**，那是自动生成的 | 小写字母、数字、下划线 |
| 房间种类 | 决定这间房用哪套美术和玩法口径 | `SAFE_ROOM` 安全房 / `COMMON_ROOM` 通用房 / `BOSS_ROOM` Boss 房 / `EXTRACTION_ROOM` 撤离房 |
| 角色 | 这间房在路线里的身份 | `stair_entry` 入口 / `hub` 中枢 / `main` 主路 / `branch` 支线 / `boss_prep` Boss 前厅 / `boss` Boss / `stair_exit` 出口 / `extraction` 撤离 |

| 内容类型 | 这间房刷什么。**留空 = 每局从这个关卡的内容池里随机抽（推荐留空）**；填了就固定不变 | `COMBAT` 战斗 / `EVENT` 事件 / `STORAGE` 仓库 / `SCAVENGE` 拾荒 / `ELITE` 精英 / `TRAP` 陷阱 / `UPGRADE` 升级 / `BOSS` |

> **老存档的事，你不用管。** 如果这张关卡已经上线、玩家存过档，技能会自动把老版本里这间房的运行时编号记进设计数据的兼容位，玩家老存档不会因为改名而打不开。已上线的关卡上，这栏也不许手动改。
>
> **内容池怎么分：** 留空的房间按你写的顺序依次从池里取；填死了的房间不占池子名额。

## 1.7 房间刷怪（可选，大多数关卡不用填）

不填 → 每间房的敌人数、波数、出什么怪，由游戏按这张关卡的情况自动算。这是默认行为，也是推荐做法。

只有当你要求**某一间房必须固定刷法**（波数固定、每波数量固定、每波出什么怪固定）时才填：

| # | 房间标识 | 第几波 | 这一波出什么（种类 × 数量） |
|---|---|---|---|
| 1 | | | |
| 2 | | | |
| 3 | | | |

| 列 | 说明 |
|---|---|
| 房间标识 | 引用 1.4 里的房间标识。**只能填会刷怪的房**（内容类型是 `COMBAT` / `ELITE` / `TRAP` / `STORAGE` / `SCAVENGE` / `BASEMENT` 的那几间）；安全房、撤离房这类不刷怪的房写了不生效，会被直接报错退回 |
| 第几波 | 出场顺序，从上往下依次出。同一间房最多 6 波 |
| 这一波出什么 | 写「种类 × 数量」，一波可以写多个种类。种类只能从下面 6 个里选 |

**可选的怪物种类（只能填这 6 个）：**

| 填什么 | 叫什么 |
|---|---|
| `melee_chaser` | 小菌猪（近战冲撞） |
| `ranged_caster` | 孢子射手（远程） |
| `summoner` | 蜂巢怪（召唤） |
| `shielded` | 壳甲卫兵（护盾） |
| `exploder` | 炸弹果（自爆） |
| `ambusher` | 地刺虫（伏击） |

**限制：** 一波最多 24 只，同一间房所有波加起来最多 64 只。Boss **不能**填在这里 —— Boss 有它自己的出场规则。

你只填「要谁、几只」。**怪的强弱（血量 / 伤害 / 速度）不用填，填了也不生效** —— 那是游戏统一口径，填了会造成两处数字打架。

> 填了某一间房，**只影响那一间房**。同一张关卡里没填的房继续按自动算法出怪，可以拿它做对照。
>
> 填法在数据里长这样（技能会替你写，你不用管格式）：
> `"enemy_spawn_plan": { "waves": [ { "monsters": [ { "type": "melee_chaser", "count": 2 } ] } ] }`

# 第二部分 · 可以改的（不改就用默认）

| 项目 | 默认 | 改了会怎样 |
|---|---|---|
| 主路最少内容房数 | 10 | 调低会让关卡体量缩水 |
| 支线数量区间 | 2 ~ 5 条 | 决定支路多少 |
| 生成重试上限 | 24 | 生成的容错次数，通常不用动 |
| 目标面积占用率 | 0.42 | 房间总面积占场地的比例 |

| 内容池 | 塔楼默认 8 项 | 留空房间从这里随机抽。远征推荐用 战斗、战斗、拾荒、仓库、事件 |

# 第三部分 · 固定的（不能改）

这些是全项目的几何基准，只有一处定义。改了等于改整个引擎的尺寸口径，不属于关卡设计的范围。

| 项目 | 值 |
|---|---|
| 网格单位 | 5.0 m |
| 墙厚 | 0.30 m |
| 层高 | 12.0 m |
| 可视墙高 | 11.9 m |
| 场地尺寸 | 250 × 250 m |
| 场地中心 | (2.5, 2.5) |
| 核心筒尺寸 | 65 × 65 m |
| 核心筒中心 | (2.5, 2.5) |
| 运行时数据驱动 | **关闭** |

## 「运行时数据驱动」为什么现在关着

打开它，游戏才会**真的改用这张表**来生成关卡；现在游戏跑的仍然是内置的老生成器，这张表做出来的东西只有校验器在看。

之所以先不打开 —— 切过去会改变关卡的内部指纹，而玩家存档是靠这个指纹认领自己那一层的关卡的。**指纹一变，玩家手上的存档就对不上，直接打不开。**

所以：设计表可以先做、可以先校验，但**不要因为校验通过就把它打开**。要不要切、旧存档怎么办，得先定下来再说。

# 第四部分 · 工具自动算的（不用填）

| 算什么 | 怎么来 |
|---|---|
| 房间的运行时编号 | 层号 + 房间标识 |
| 关卡指纹 | 按整份设计数据算出来，进存档 |
| 每个门的方位与门槽位置 | 由父子房间的中心坐标推导 |
| 门所在墙的长度 | 取房间在延展方向上的尺寸 |
| 楼梯保留区 | 塔楼按出入口方向自动生成 20×30 m；单层关卡没有 |
| 面积预算 | 按房间面积与占用率算 |
| 走廊记录 | 由两端门中心距推导 |

**关于门方位：** 平面图上的 +y 方向对应世界坐标的**南**。这条约定全项目只有一处实现。历史上它曾经整体写反过，而没有任何检查能发现 —— 因为门槽位置仍然是对的，几何校验不会失败。现在校验器会逐条比对，写反即报错。

# 第五部分 · 硬规则（填错会被拒）

## 5.1 房间摆位

| # | 规则 | 判据 |
|---|---|---|
| 1 | 宽和深都是 5 的整数倍 | 除以 5 没有余数 |
| 2 | 房间之间不重叠 | 任意两房重叠面积不超过 0.01 平方米 |
| 3 | 不超出场地 | 都在 `|x| ≤ 125`、`|y| ≤ 125` 之内 |
| 4 | 除入口房和楼梯厅外，不压核心筒 | 不与 65×65 核心区重叠 |
| 5 | 不压楼梯保留区 | 不与出入口方向的 20×30 m 保留区重叠 |
| 6 | 连走廊的两间房必须同轴 | 横向偏移不超过 5.01 m |
| 7 | 走廊净距至少 5 m | 沿轴距离减去两房半长 ≥ 5.0 |
| 8 | 走廊长度是 5 的整数倍 | 门到门距离除以 5 为整数 |

> 唯一例外：1.6 里声明过的「共墙直接对接」允许净距为 0。

## 5.2 连通结构

| # | 规则 |
|---|---|
| 1 | 每个「父房间」都必须存在，且父子之间能修出合法走廊（过 5.1 的第 6/7/8 条） |
| 2 | 主路内容房数不少于设定下限 |
| 3 | 支线条数落在设定区间 |
| 4 | 主路里写到的每个房间，都必须在房间表里存在 |
| 5 | 房间总面积不超过 场地面积 × 占用率 |
| 6 | Boss 层必须有 Boss 房，且出口的父房间必须是 Boss 房 |

# 第六部分 · 填完之后会怎样

技能按顺序做四件事：

1. 补全所有自动算的量，产出关卡设计数据
2. 跑校验 —— 不通过就逐条报错，指出是哪一行哪一列
3. 通过后登记这张关卡的标识
4. 报告产出清单与校验结果

**校验命令**

```bash
Godot_v4.6.3-stable_win64_console.exe --headless --path . \
  res://tests/verification/verify_level_plan_design_source.tscn -- --level=<关卡标识>
```

省略 `--level=` 时校验全部已登记关卡。

**判据：** `LEVEL_PLAN_VALIDATE_OK levels=N checks=K rooms=R templates=T`
　　　　　`LEVEL_PLAN_RUNTIME_GUARD_OK levels=N rooms=R checks=K plans=P`

两条都会打印。第一条查设计数据本身自不自洽；第二条**真的调一次生成器**，查产出里每一间房的类型、尺寸、计数对不对 —— 功能房（入口 / 出口 / 撤离房 / Boss）的类型必须正确，内容房必须被分到内容类型。

末尾的 `plans=P` 是「1.7 里填的刷怪计划，有几间房真的带到了运行时」。**你在 1.7 填了几间，这里就该是几**；填了却显示 `plans=0`，说明没接通，要回来查。
