## 0. 设计结论

ShellStorm2 的音效不是“给每个按钮配一个文件”，而是一套**战术信息系统**：

```text
领域事实
  → 语义音频事件
  → 播放配置 / SoundSet
  → 变体、层、空间和混音策略
  → 玩家听觉反馈
  → 可选的 AI 声音刺激
```

本设计的五个硬原则：

1. **先有事实，后有声音。** 交互按下、子弹生成、伤害结算、门真正打开、结算真正提交，必须区分；声音不为猜测中的状态播放。
2. **事件键表达语义，不表达文件。** 调用方请求 `combat.weapon.fire`，不能直接加载 `pistol_fire_v001.ogg`。
3. **玩家听见和敌人听见是两条输出。** 两者可以来自同一个事件，但传播半径、遮挡、记忆和优先级分别管理；玩家听见不等于敌人一定获得目标。
4. **一个事实只有一个主播放所有者。** 其他系统只能提供参数或订阅结果，不能重复播放同一主层。
5. **复用的是声音角色，不是强行复用文件。** 同一材质、同一动作、同一听觉功能才允许复用；身份不同但只改音高，不足以掩盖错误的攻击质感。

### 0.1 当前结论与旧口径的关系

当前工程有 `AudioManager.SFX` 和 36 个正式 OGG 运行文件。这些是**兼容资产基线**，不是最终音效设计上限。

已确认的当前事实：

- 远程武器、近战、受击、拾取、门、容器、波次、Boss、撤离、UI、交易和手电筒已有部分事件键。
- 玩家脚步目前主要作为 AI 声音刺激广播，玩家听觉脚步尚未形成完整链。
- `laser_fire`、`ammo_empty`、`door_locked`、`flashlight_low_battery` 虽有资源或登记，但不能仅凭登记判定正式玩法已经闭环。
- 怪物 AI 已有声音位置、半径、遮挡、记忆和去重概念；玩家端 `AudioManager` 目前主要是全局 `AudioStreamPlayer`，空间音频目标尚未完整落地。
- 音乐由 `MusicManager` 管理；本文件只管理短时音效、环境声和声音反馈，不接管 BGM 的播放栈。

## 1. 游戏的听觉身份

### 1.1 游戏声音要服务的体验

ShellStorm2 是顶视角 3D 动作射击、搜刮、构筑和撤离游戏。玩家每一局都在判断：

- 这是什么声音？
- 声音来自哪里？
- 它是在提醒我、暴露我，还是告诉我某个动作已经成功？
- 我现在应该继续战斗、搜刮，还是撤离？
- 这次构筑真的改变了武器和战斗方式吗？

音效必须让玩家在不盯着 HUD 的情况下，仍能听出关键事实；但不能用声音替代必要的视觉信息，也不能用过多提示声把危险层级抹平。

### 1.2 五个声音支柱

| 声音支柱 | 目标 | 禁止事项 |
|---|---|---|
| 战术可读 | 玩家能区分开火、命中、受击、敌人前摇、撤离中断和门锁拒绝 | 所有事件都用同一个“啪”或同一个 UI 错误音 |
| 材质可信 | 金属、机械、能量、肉体、玻璃、电子设备有稳定质感 | 用音高随机代替材质差异 |
| 空间可信 | 门后、房间内、远处枪声、收音机和环境声有位置感 | 所有世界声源都像贴在屏幕中心 |
| 反馈克制 | 重要事实突出，普通重复动作不疲劳 | 每颗子弹、每个伤害数字、每个 UI 刷新都满音量播放 |
| 资产可维护 | 一个声音可以被多个合适语义复用，替换时有稳定映射和版本追溯 | 调用方散落路径、复制同一文件、覆盖已发布版本 |

### 1.3 质感方向

声音整体采用：

- **废墟科技 + 末世工业**：机械、电气、冷硬金属、短促故障脉冲。
- **卡通化但不廉价**：轮廓清楚、瞬态明确、层次干净；不追求写实血腥，不使用持续刺耳噪声掩盖信息。
- **战斗有重量，UI有秩序**：重武器与Boss声音有低频重量；UI和确认声保持中高频清晰，避免与战斗低频争抢。
- **暗处靠声音建立纵深**：环境底噪、远处机械、灯具嗡鸣和敌人预警形成层次，但不把随机噪声伪装成玩法提示。

## 2. 音频范围与所有权

### 2.1 本文管理的声音域

| 声音域 | 本文是否负责 | 说明 |
|---|---:|---|
| 短时 SFX | 是 | 射击、近战、受击、交互、UI、流程反馈 |
| 世界环境声 | 是 | 房间底噪、机械、灯、电流、风、撤离信号塔等循环或半循环声音 |
| 角色和敌人声音反馈 | 是 | 脚步、攻击前摇、命中、死亡、技能、Boss阶段 |
| BGM | 否 | 由[音乐播放清单](音乐播放清单.md)和[音乐系统与配乐资产](../14.8_音乐系统与配乐资产.md)负责 |
| 对话文本和语音 | 仅保留接口 | 对话载体由剧情与对话系统负责；音效只提供确认、切换和演出反馈 |
| VFX 内部音频 | 不允许自有一套 | 特效可以携带 `audio_event_id` 请求音效，但不得直接加载文件 |

### 2.2 功能 Owner

| 能力 | 唯一 Owner | 其他系统能做什么 |
|---|---|---|
| 事件注册和播放调度 | `AudioManager` | 接受语义事件、播放配置、空间上下文和调试查询 |
| 事件事实 | 对应领域系统 | 在事实成立时发出稳定事件；不关心文件路径 |
| 音乐播放生命周期 | `MusicManager` | 与 `AudioManager` 分开，不把 BGM 推入 SFX 播放器 |
| AI 声音刺激 | `MonsterAIManager` | 接收 `ai_signal`，按半径、遮挡、听觉倍率和记忆处理 |
| 音频资产映射 | 音频资产账本 + 运行时映射 | 维护 AssetID、SoundSet、源文件、OGG、哈希、许可和验收入口 |
| UI 通用反馈绑定 | `UIStyleFactory` / UI 所属页面 | 通用 hover/click 只绑定一次；业务成功/失败由业务 Owner 发出 |

## 3. 事件模型

### 3.1 事件不是文件名

目标事件 ID 使用稳定的语义命名。推荐格式：

```text
<domain>.<subject>.<action>.<result_or_variant>
```

示例：

```text
combat.weapon.fire
combat.weapon.reload_start
combat.weapon.empty
combat.melee.swing
combat.melee.impact
combat.enemy.telegraph
world.door.open
world.door.denied
run.extraction.completed
ui.action.confirm
```

事件 ID 不写武器文件名、不写版本号、不写节点名。武器、敌人、房间和剧情只是事件上下文。

### 3.2 目标事件字段

每个正式事件至少具备以下字段：

```text
event_id                 # 稳定语义 ID
owner                    # 事实所有者
trigger_fact             # 什么事实成立后触发
sound_set_id             # 选择哪组资产
player_audible           # 玩家是否听见
ai_signal                # 是否向 AI 声音刺激链发送
spatial_mode             # ui_2d / world_2d / world_3d / listener_follow
source_position          # 世界位置或监听者位置
intensity                # 0..1，来自事件事实，不是随机音量
priority                 # P0 / P1 / P2 / P3
concurrency_group        # 并发和替换规则
cooldown_or_dedupe       # 去重窗口或合并窗口
variant_policy           # 变体、层和随机规则
mix_profile              # 总线、duck、距离和音量
fallback_policy          # 资产缺失时的处理
acceptance_case          # 自动/人工验收入口
```

### 3.3 触发原则

| 触发方式 | 正确例子 | 错误例子 |
|---|---|---|
| 事实边沿 | 门状态从 `closed` 变为 `open` 时播放开门声 | 玩家按下交互键就播放开门声 |
| 成功结果 | 拾取事务成功后播放拾取声 | 物品生成时播放拾取声 |
| 失败结果 | 门权限拒绝后播放门锁声 | 只要靠近门就播放门锁声 |
| 阶段变化 | Boss 阶段从2变3时播放阶段提示 | 每帧读取Boss血条都播放 |
| 离散阈值 | 手电电量首次跨入低电量阈值时播放一次 | 电量数值每次变化都播放 |
| 命中确认 | 近战至少命中一个目标后播放接触主层 | 进入攻击窗口就播放命中声 |

### 3.4 事件的两条输出

一个事件可以有两个互相独立的输出：

```text
SoundEvent
├─ PlayerFeedback
│  ├─ 播放位置
│  ├─ 玩家可听响度
│  ├─ 混音和遮挡
│  └─ 变体与并发
└─ AISignal
   ├─ 是否产生声音刺激
   ├─ 刺激位置
   ├─ 基线半径
   ├─ 遮挡衰减
   ├─ 合并/去重窗口
   └─ 是否允许升级为战斗目标
```

玩家听见一个门声，不能推出所有怪物都立刻进入战斗；敌人听见一声枪响，也不能跳过 `alert/search` 直接获得玩家实时坐标。

## 4. 声音分层与总线

### 4.1 目标总线

目标结构如下；当前工程已确认 `SFX` 与 `Music` 的部分路径，其他总线需要后续实现和验收，不能把目标写成已完成事实。

```text
Master
├─ Music       # BGM、收音机；由 MusicManager 与收音机按各自规则使用
├─ SFX         # 世界短时音效、战斗、环境事件
├─ UI          # UI hover/click/confirm/error；不受世界距离影响
├─ Ambience    # 环境底噪、机械循环、空间床
└─ Voice       # 未来语音或对话音频；当前可为空
```

### 4.2 音频层级

| 层 | 内容 | 设计目标 |
|---|---|---|
| `AMB` | 房间底噪、灯、电流、风、远处建筑、设施运转 | 提供空间连续性，不抢战斗信息 |
| `FOLEY` | 脚步、落地、翻找、门体机构、拾取 | 让动作有身体和材质 |
| `COMBAT` | 开火、换弹、挥砍、命中、受击、死亡、技能 | 战术识别和重量 |
| `ALERT` | 敌人警觉、搜索、前摇、Boss阶段 | 提前告诉玩家危险正在形成 |
| `UI` | 悬停、确认、拒绝、购买、卡牌、读取错误 | 操作反馈，稳定、短、清晰 |
| `STINGER` | 开场、Boss登场、撤离成功、失败结算 | 一次性叙事强调，不循环 |

### 4.3 混音规则

- 音量按 dB 叠加，不用线性值直接相加：

```text
L_final_db = L_asset_db + L_call_db + L_bus_db + L_duck_db
```

- 关键战斗事件发生时，只压低与它冲突的 `AMB`/`Music`，不把所有声音静音。
- `UI` 反馈不做世界距离衰减；世界声源不能伪装为屏幕中央 UI 声。
- 重要提示优先于重复性装饰声。重复事件超过并发预算时，允许丢弃低优先级声音，但不能丢失 `P0` 的状态结果。
- 目标混音不是“所有声音越大越好”，而是保证以下顺序稳定：

```text
P0 结果确认 / 玩家受击 / 致命危险 / 撤离状态
P1 武器动作 / 敌人前摇 / 门和容器结果 / Boss阶段
P2 普通命中 / 环境交互 / 拾取 / 波次
P3 UI悬停 / 低价值装饰 / 高频重复底噪
```

## 5. 全游戏声音目录

以下是**目标事件目录**。`当前状态`只描述现状，不限制最终资产数量。

### 5.1 玩家移动、受伤和状态

| 事件 ID | 玩家听觉 | AI刺激 | 触发事实 | 目标声音 |
|---|---:|---:|---|---|
| `player.footstep` | 是 | 是 | 玩家完成一次有效脚步落点 | 按地面材质、移动速度和是否冲刺选择脚步组 |
| `player.dash` | 是 | 是 | 冲刺实际开始 | 短促启动、空气切开和位移尾声；当前已有兼容事件 |
| `player.land` | 是 | 可选 | 玩家完成落地 | 按落差和材质分轻/重落地，不覆盖受伤声 |
| `player.hurt` | 是 | 否 | 玩家实际受到伤害 | 方向性受击层、短暂低频冲击；当前已有 `player_hit` 兼容事件 |
| `player.down` | 是 | 否 | 玩家进入倒地/死亡流程 | 区别于普通受击，不能只重复 `player.hurt` |
| `player.death_confirmed` | 是 | 否 | 死亡结算事实确认 | 低频收束 + 结算前停顿，避免和成功撤离混淆 |
| `player.flashlight_on` | 是 | 否 | 手电真正开启 | 轻微开关机械声，不在每帧刷新 |
| `player.flashlight_off` | 是 | 否 | 手电真正关闭 | 短促断电声，可与环境底噪相接 |
| `player.flashlight_charge` | 是 | 否 | 电量恢复事务成功 | 充能上升声；当前兼容事件为 `flashlight_charge_up` |
| `player.flashlight_low` | 是 | 否 | 电量首次跨入低电量阈值 | 周期性提醒由状态机控制，不按电量变化刷声 |
| `player.flashlight_depleted` | 是 | 可选 | 电量归零并自动关闭 | 断电、环境声短暂收缩；当前已有兼容事件 |

脚步基线必须区分两件事：

- **AI听觉链**：脚步向 `MonsterAIManager` 广播声音刺激。
- **玩家听觉链**：脚步作为世界声源或监听者附近的反馈播放。

两条链可以共用同一个 `player.footstep` 事实，但不能让“只广播 AI 刺激”冒充完整脚步音效。

### 5.2 远程武器

| 事件 ID | 触发事实 | 声音层 | 目标规则 |
|---|---|---|---|
| `combat.weapon.fire` | 发射事务成功 | 枪身、机构、枪口、尾音 | 由武器音频配置选择，不再只按射速猜类型 |
| `combat.weapon.fire_energy` | 能量/激光武器发射成功 | 高辨识能量核心 + 短尾音 | 不能被普通枪械分类器吞掉；兼容 `laser_fire` |
| `combat.weapon.reload_start` | 换弹动作真正开始 | 弹匣/机构启动 | 不在按键按下但状态拒绝时播放 |
| `combat.weapon.reload_action` | 换弹中关键动作到达 | 插入、拉栓、闭锁 | 可按武器族共享层，不要求每把枪全套独立录制 |
| `combat.weapon.reload_end` | 换弹完成 | 闭锁确认 | 与 `reload_start` 分开以支持中断和失败 |
| `combat.weapon.empty` | 玩家尝试开火但无法发射 | 空仓点击/机构拒绝 | 仅在一次有效尝试边沿播放；兼容 `ammo_empty` |
| `combat.weapon.swap` | 装备事务成功 | 拿起、挂点、电子确认 | 换枪失败不得播放成功声 |
| `combat.weapon.attach` | 配件或弹药模块事务成功 | 插接、锁定、短电子确认 | 与属性变化或 UI 成功提示错开 |
| `combat.weapon.attach_denied` | 装配事务拒绝 | 短拒绝脉冲 | 复用 UI error 仅作为临时降级，正式配置可独立化 |
| `combat.projectile.impact` | 投射物命中或落地 | 材质冲击、能量、爆炸 | 目标材质和效果类型通过上下文选择 |

武器开火不允许再使用以下单一事实推断所有声音：

```text
fire_rate → pistol/rifle/smg/sniper
```

目标入口应至少使用：

```text
weapon_content_id
weapon_audio_profile
projectile_content_id
projectile_count
fire_rate
charge_state
```

射速和投射物数量可以作为混音参数，但不能代替武器身份。

### 5.3 近战

| 事件 ID | 触发事实 | 目标规则 |
|---|---|---|
| `combat.melee.swing` | 每段 `active` 开始 | 每段一次；挥空也播放；按武器族和连段选层 |
| `combat.melee.impact` | 本次攻击至少命中一个目标 | 一次攻击最多一个接触主层，多目标不重复 |
| `combat.melee.target_hit` | 单个目标实际受击 | 目标层逐目标播放，可按材质/护甲/暴击变体 |
| `combat.melee.heavy_impact` | 重武器或高击退命中 | 加低频和材料断裂层，不单独复制整套事件 |
| `combat.melee.cancel` | 连段被受伤、冲刺、死亡等中断 | 只在需要让玩家理解动作被打断时使用，不每次中断都发声 |

近战声音所有权：动作机拥有 `swing` 和 `impact` 主层；敌人拥有自己的 `target_hit` 层。现有“三把近战、三段动作、挥空/命中去重”的方向保留，但目标资产由 SoundSet 和参数管理，而不是无限增加事件键。

### 5.4 敌人、精英和 Boss

| 事件 ID | 触发事实 | 玩家信息 |
|---|---|---|
| `enemy.alert` | 敌人进入警觉状态 | 玩家知道“附近有东西注意到异常”，但不直接暴露精确位置 |
| `enemy.search` | 敌人开始调查声音/光照/最后已知点 | 低频、方向性、持续不超过调查阶段需要 |
| `enemy.telegraph` | 敌人进入攻击前摇 | 必须比攻击结果更早，让玩家有反应窗口 |
| `enemy.attack` | 敌人攻击动作正式执行 | 只在动作成立时播放，不用来替代前摇 |
| `enemy.ranged_charge` | 远程或技能蓄力开始 | 电子/能量/机械蓄力按敌人族群区分 |
| `enemy.summon` | 召唤事务成功 | 召唤者声音 + 新实体出现声音可分层，但不能重复宣告 |
| `enemy.heal` | 治疗事务成功 | 与普通受击逆向声纹不同，不能只反放受击声 |
| `enemy.shield_raise` | 护盾真正启用 | 金属展开或能量成形，和盾值变化分离 |
| `enemy.avoid_light` | 避光行为进入 | 仅在行为边沿提示一次，不因光照采样抖动重复 |
| `enemy.hit` | 实际扣血 | 受击材质层；当前兼容 `enemy_hit` |
| `enemy.crit` | 实际暴击 | 只加识别层，不替代普通命中事实；当前兼容 `crit_hit` |
| `enemy.death` | 死亡结算确认 | 按敌人族群和死亡类型选组；当前兼容 `enemy_die` |
| `enemy.explosion` | 自爆/爆炸实际发生 | 爆炸本体、碎片和 AI 刺激分开 |
| `boss.intro` | Boss遭遇确认 | 一次性演出层；当前兼容 `boss_intro` |
| `boss.phase_changed` | 阶段编号真正变化 | 每个阶段边沿一次；当前兼容 `boss_phase` |
| `boss.defeated` | Boss死亡和奖励事实确认 | 与普通敌人死亡不同；当前兼容 `boss_defeat` |

敌人声音不能泄露设计上玩家不该知道的信息。例如：

- 敌人处于 `alert`，只能提示异常发生，不直接播放“敌人已经锁定玩家”。
- 敌人 `search` 时可以让玩家判断搜索区域，但不能播放玩家实时坐标。
- `enemy.telegraph` 必须跟随真正攻击前摇；取消攻击时要停止或短收束，不让声音假装攻击已经发生。
- Boss阶段声只由阶段编号变化触发，不由血条百分比每帧触发。

### 5.5 世界交互、房间和设施

| 事件 ID | 触发事实 | 目标规则 |
|---|---|---|
| `world.door.open` | 门完成开启事务 | 门体机构、锁舌、滑轨；当前兼容 `door_open` |
| `world.door.close` | 门完成关闭事务 | 与开门形成同家族，可共享机构层 |
| `world.door.denied` | 门权限或状态拒绝 | 按原因码选择短锁定/电子拒绝；兼容 `door_locked` |
| `world.container.search_start` | 搜索状态开始 | 可选轻微操作层，不播放“已打开” |
| `world.container.search_finish` | 搜索完成并发放结果 | 当前兼容 `container_open`；必须只播放一次 |
| `world.container.search_cancel` | 搜索被打断 | 低价值，必要时复用操作层尾音 |
| `world.pickup.item` | 普通物品拾取事务成功 | 当前兼容 `item_pickup` |
| `world.pickup.soul` | 魂球入账成功 | 当前兼容 `soul_pickup` |
| `world.light.switch_on` | 灯光能量真正开启 | 机械开关 + 电流启动 |
| `world.light.switch_off` | 灯光能量真正关闭 | 机械开关 + 电流断开 |
| `world.facility.activate` | 基地设施进入工作状态 | 远征平台、工坊、恢复舱、档案室等共享电子启动家族 |
| `world.facility.confirm` | 设施业务事务成功 | 不与按钮点击重复 |
| `world.facility.denied` | 设施业务事务拒绝 | 显示层可有文字，声音层按失败等级选择 |
| `world.radio.on` | 收音机开启 | 由收音机自身 3D 播放器持有，不复制全局BGM |
| `world.radio.off` | 收音机关闭 | 停止本地播放器和本地音符效果 |

交互音必须由结果所有者触发。`RoomDoor3D` 可以拥有门体成功开启声音；钥匙不足、清房未完成、场景未生成等拒绝原因仍由门权限/关卡领域决定，不能让门节点猜测所有失败原因。

### 5.6 远征、波次、命运和结算

| 事件 ID | 触发事实 | 目标规则 |
|---|---|---|
| `run.wave.started` | 一波敌群计划正式启动 | 当前兼容 `wave_start` |
| `run.wave.cleared` | 当前波次清除事实确认 | 当前兼容 `wave_clear` |
| `run.fate.revealed` | 门后命运卡正式展示 | 当前兼容 `fate_card`，不在预加载时播放 |
| `run.fate.applied` | 命运事务写入成功 | 可与翻牌声分开，避免“看见”冒充“生效” |
| `run.extraction.started` | 撤离读条真正开始 | 当前兼容 `extraction_start` |
| `run.extraction.interrupted` | 撤离读条被伤害或离开范围打断 | 当前兼容 `extraction_abort` |
| `run.extraction.completed` | 撤离结算事务成功提交 | 当前兼容 `extraction_done`，不得早于保存结果 |
| `run.retreat.confirmed` | 安全房主动弃局事务确认 | 不得与撤离读条中断混为一声 |
| `run.settlement.failed` | 结算保存失败 | 需要明确失败声；可暂时复用 `ui_error`，但事件语义不能消失 |
| `run.loading.failed` | 读取/进入关卡失败 | 与按钮拒绝区别；目标为独立错误事件 |
| `run.generation.fallback` | 生成失败后启用安全兜底 | 只在玩家需要知道时提示，不把开发日志声播放给玩家 |
| `run.return.failed` | 结算后返回场景失败 | 目标为系统级失败反馈，不得只留日志 |

撤离成功的硬顺序：

```text
撤离读条完成
  → 结算事务提交
  → 结算成功事件 run.extraction.completed
  → 播放成功音
  → 返回基地
```

如果产品决定允许“读条完成但保存尚未确认”时先播放提示，也必须另定义 `run.extraction.charge_completed`，不能把它叫作 `run.extraction.completed`。

| `ui.action.focus` | 手柄/键盘焦点改变 | 可与 hover 共用 SoundSet，但事件语义独立 |

## 6. 空间音频与 AI 声音刺激

### 6.1 空间模式

| 模式 | 用途 | 处理 |
|---|---|---|
| `ui_2d` | UI和HUD | 不随世界位置变化、不经过墙体遮挡 |
| `listener_follow` | 玩家自身动作、个人装备 | 跟随监听者，保持清晰但不产生远处位置错觉 |
| `world_3d` | 门、容器、敌人、撤离塔、收音机、环境设施 | 具有位置、距离、方向、遮挡和衰减 |
| `world_bed` | 房间底噪、整区环境 | 可使用区域级混音，不把每个环境层都变成独立实体 |

### 6.2 玩家听觉距离

世界声源的有效响度可按以下设计公式计算：

```text
L_effective_db = L_source_db + A_distance(d) + A_occlusion(o) + A_room(r)
```

其中：

- `A_distance(d)`：由声源距离模型决定，通常为非正值。
- `A_occlusion(o)`：墙、门、楼板遮挡衰减，通常为非正值。
- `A_room(r)`：房间类型、室内外和反射环境的混音修正。
- 不允许调用方自行把距离、墙体和音量重复乘一遍。

### 6.3 AI 声音刺激

当前 AI 已有 `sound_contact`、声音位置、半径、遮挡、记忆和去重方向。目标事件把刺激参数写成显式配置，而不是散落在各调用者里。

基线传播公式：

```text
R_effective = R_base
             × I_event
             × H_listener
             × (1 - O_wall)
             × (1 - O_door)
```

- `R_base`：事件族基线半径。
- `I_event`：声音强度，范围 `0..1`，由事件事实和播放配置决定。
- `H_listener`：敌人听觉倍率。
- `O_wall` / `O_door`：遮挡衰减，范围 `0..1`。

目标基线不是强制当前代码立即修改的数值，而是统一配置的起点：

| 事件 | `R_base` 设计起点 | AI行为 |
|---|---:|---|
| 行走脚步 | 3m | 警觉/调查 |
| 冲刺 | 6m | 更强警觉/调查 |
| 门 | 6.5m | 调查门或事件点 |
| 容器完成搜索 | 8m | 调查事件点 |
| 消音/低声武器 | 8m | 调查，按内容决定是否升级 |
| 普通枪声 | 14m | 调查，真实命中或视觉确认后才战斗 |
| 大型发射/技能 | 20m | 调查或按敌人内容升级 |
| 爆炸 | 20m | 强警戒/调查 |

声音刺激必须满足：

- 只给事件位置、粗略方向和声音类型，不把玩家节点引用传给 AI。
- 连续枪声在合并窗口内合并，禁止每颗子弹都创建长期刺激。
- 墙和关闭门削弱传播；未激活房间可以拒绝接收。
- `alert`、`search`、`combat` 分层，不因一声声音跳过所有状态。
- 同一来源、同一事件族在去重窗口内只保留一次。

## 7. 声音资产的复用设计

### 7.1 三层资产模型

```text
Asset（物理音频文件）
  → SoundSet（可复用声音组）
    → CueProfile（事件播放配置）
      → Event（玩法事实的语义请求）
```

#### Asset

一条可编辑母版、一个正式运行文件、一个许可和一个哈希对应一个物理资产记录。

#### SoundSet

把同一听觉角色的多个层和变体组成一个可复用集合。例如：

```text
SFXSET.FOLEY.METAL.DOOR
  ├─ mechanism_open
  ├─ lock_release
  ├─ body_slide
  └─ tail
```

#### CueProfile

定义事件如何使用 SoundSet：空间化、音量、音高范围、层开关、并发、优先级、混音和 AI 刺激。

#### Event

只说明发生了什么，不绑定某个文件：

```text
combat.weapon.fire
  → CueProfile.WEAPON_FIRE
  → 根据 weapon_audio_profile 选择 SoundSet
```

### 7.2 允许复用的条件

两个行为可以共享音频资产，必须同时满足：

1. 玩家需要理解的语义相同或相近。
2. 物理材质和动作包络不会让玩家误判。
3. 空间模式、持续时间和混音位置兼容。
4. 复用后仍能在连续触发中保持辨识度。
5. 账本能记录“谁复用了谁”，替换时不会产生隐藏依赖。

### 7.3 不允许的伪复用

以下做法禁止：

- 只改音高，把手枪声当成激光声。
- 只改音量，把敌人死亡声当成Boss死亡声。
- 把“门被锁定”和“UI按钮不可用”永远绑定同一文件。
- 为同一扇门、同一容器复制多个内容完全相同的OGG。
- 通过随机播放掩盖一组资产本身材质不一致的问题。
- 调用方自己拼接路径或在缺资源时恢复旧WAV、`SynthSfx`或另一份私有声音。

### 7.4 复用决策树

```text
这个事实和已有事件语义是否相同？
  ├─ 是 → 复用事件ID和CueProfile，只换上下文参数
  └─ 否
      ↓
玩家是否需要把它识别为新的玩法结果？
  ├─ 否 → 复用SoundSet，新增映射备注
  └─ 是
      ↓
是否只是同一动作的材质/武器族差异？
  ├─ 是 → 新增SoundSet或变体，不新增重复事件
  └─ 否 → 新增事件ID，并领取新的资产记录
```

### 7.5 变体数量和重复控制

变体数量由重复速率和可听窗口决定，而不是凭感觉无限增加。设计估算式：

```text
V_required = clamp(ceil(F_repeat × T_audible × K_identity), V_min, V_max)
```

- `F_repeat`：事件每秒可能触发次数。
- `T_audible`：玩家能明显听到重复的时间窗口。
- `K_identity`：事件身份重要性修正。
- 普通高频事件的 `V_min` 取2，关键重复战斗声一般取3–6；最终以真实连射/多目标试听为准。
- 变体不足时优先使用不同起音、层组合和轮换规则，不依赖大幅随机变调。
- 身份性强的事件禁止使用会改变语义的随机音高；普通脚步、金属碰撞可以使用小范围确定性变化。

### 7.6 层复用示例

#### 枪械

```text
weapon_fire = mechanism_layer
             + muzzle_layer
             + material_layer
             + tail_layer
             + optional_energy_layer
```

- 手枪、步枪、霰弹、冲锋枪可以共享机构或尾音家族，但必须拥有足够的枪口瞬态和弹药/枪体识别。
- 激光使用独立能量核心层；不能只从普通枪声变调得到。
- 不同子弹模块若只改变飞行或命中表现，不必复制整条开火声；若改变发射机制，再新增层或配置。

#### 近战

```text
melee_swing = air_body + weapon_weight + optional_material
melee_impact = contact_transient + target_material + heavy_tail
```

- 三段连击共享事件 ID，通过 `weapon_content_id`、`combo_step`、重量和材质选择层。
- 大型武器不必复制三套完全独立文件；只要重量、起音和接触层真正不同。

#### 门和设施

```text
door_open = lock_release + hinge_or_rail + body_tail
```

- 不同门体可以共享 `lock_release`，但滑轨、液压、厚重门板可以选择自己的层。
- 远征情报室、恢复舱、工坊的电子确认声可以共享电子家族，但不能让“失败”和“成功”只靠音量区分。

## 8. 资产管理规则

### 8.1 稳定 ID

| 对象 | 命名示例 | 作用 |
|---|---|---|
| 领域事件 | `combat.weapon.fire` | 玩法调用和契约 |
| CueProfile | `CUE-WPN-FIRE-BASE` | 播放策略 |
| SoundSet | `SFXSET-WPN-PISTOL-FIRE` | 层和变体集合 |
| 物理资产 | `AUD-SFX-WPN-PISTOL-MUZZLE-001` | 账本、源文件、哈希和许可 |
| 运行文件 | `pistol_fire_v001.ogg` | Godot 运行资源 |
| 验收用例 | `verify_audio_weapon_fire_profile` | 自动/人工验收入口 |

AssetID 使用 `AUD-SFX-*`；音乐使用 `AUD-BGM-*`。事件 ID、SoundSet ID 和 AssetID 不能互相替代。

### 8.2 制作源和运行资产

制作源遵循项目美术源布局：

```text
art_source/audio/sfx/<AssetID>/source/
```

运行资产当前路径保持：

```text
res://src/assets/audio/sfx/<runtime_name>_vNNN.ogg
```

管理规则：

1. 母版、工程文件、许可来源和制作说明进入制作源目录。
2. Godot 只加载正式运行资产，不读取 `art_source`。
3. 运行文件替换必须递增 `_vNNN`，禁止覆盖已发布文件名后依赖缓存刷新。
4. 临时导出、预览、QA和日志进入工程外 `ShellStorm2-work/`。
5. 不把凭据、生成平台私密信息或个人路径写进项目。
6. 旧版本移入上层备份，不在运行目录堆叠历史版本。

### 8.3 每条资产账本至少记录

```text
asset_id
asset_subtype             # one_shot / loop / layer / stinger / ui / ambience
sound_set_id[]
event_id[]
source_path
runtime_path
source_format
runtime_format
sample_rate_hz

```

一条物理资产可以被多个 `event_id` 或 `SoundSet` 复用；每个复用关系必须登记，不能靠文件名猜测。

### 8.4 声音类型和声道规则

当前旧运行集统一 OGG 不能成为新设计的唯一技术规则。目标按播放方式区分：

| 类型 | 源母版建议 | 运行资产建议 | 原因 |
|---|---|---|---|
| 世界3D点声源 | 单声道优先 | 单声道OGG优先 | 交给引擎完成方向、距离和遮挡 |
| 玩家自身/监听者跟随 | 单声道或窄立体声 | 由听感决定 | 保持动作清晰，不制造错误空间位置 |
| UI | 单声道或立体声 | 短OGG | 不需要世界衰减 |
| 环境床 | 立体声或多层单声道 | 循环OGG | 需要连续空间和稳定循环 |
| 一次性演出 | 立体声可选 | OGG或项目批准格式 | 服务剧情和情绪，不参与高频并发 |

格式、采样率、声道和压缩质量必须以 `asset_subtype + spatial_mode` 决定。不能为了方便把所有空间音源强制转成立体声，也不能把所有素材都做成单声道。

### 8.5 运行时访问

目标调用方式：

```gdscript
AudioManager.emit_event("combat.weapon.fire", {
    "source_node": weapon_node,
    "weapon_content_id": weapon_content_id,
    "weapon_audio_profile": audio_profile_id,
    "projectile_content_id": projectile_content_id,
    "intensity": 1.0,
    "cause_id": attack_instance_id,
})
```

调用方不得：

```gdscript
load("res://src/assets/audio/sfx/pistol_fire_v001.ogg")
AudioStreamPlayer.new()
AudioManager.play_sfx("some_file_name")
```

兼容期允许保留：

```gdscript
AudioManager.play_sfx("legacy_event")
```

但 `play_sfx()` 应作为旧事件适配器，新的正式链路逐步迁移到语义事件和上下文配置。当前 `play_fire_sfx(fire_rate, projectile_count)` 只能作为兼容入口，不能继续作为武器声音唯一分类依据。

### 8.6 缺失和降级

- 正式资产缺失：记录一次明确错误，保持静音或使用已批准的同语义降级 CueProfile。
- 不允许自动回退旧WAV、`SynthSfx`、调用方私有文件或相似但语义错误的声音。
- 降级必须登记 `fallback_policy` 和验收结果；“听起来差不多”不能作为隐式降级规则。
- Headless 只能验证事件、映射、文件和生命周期；听感、空间、响度和循环接缝必须有真实渲染或真实设备验收。

## 9. 并发、去重和优先级

### 9.1 并发组

| 并发组 | 规则 |
|---|---|
| `weapon_fire` | 高频可丢低优先级尾层；保留枪口主层和关键状态声 |
| `enemy_hit` | 同一目标短窗口合并；暴击覆盖普通命中层或增加识别层 |
| `melee_attack` | 一次攻击一个挥砍主层、最多一个接触主层 |
| `footstep` | 按脚步节奏和动画落点触发，不按帧触发 |
| `ui_hover` | 同一控件进入一次；焦点未变不重复 |
| `ui_result` | 成功、拒绝、失败不能互相覆盖到无法识别 |
| `boss_stinger` | Boss登场/阶段/击败按事务顺序排队或覆盖，不同时堆满 |
| `ambience_loop` | 按区域和声音组限额，离场立即停止并释放 |

### 9.2 播放优先级计算

目标优先级可用以下可解释公式：

```text
P_play = P_semantic + P_state + P_proximity + P_story - P_repeat
```

- `P_semantic`：事件本身的重要性。
- `P_state`：是否处于玩家受伤、撤离、死亡、Boss阶段等关键状态。
- `P_proximity`：声源距离和空间可听性。
- `P_story`：剧情或关卡演出临时提升。
- `P_repeat`：同类近期重复惩罚。

优先级不是让低优先级事件完全无声，而是在资源和并发不足时决定谁保留主层、谁降低音量、谁被合并。

### 9.3 去重窗口

去重由“来源 + 事件族 + 事实 ID”组成：

```text
DedupKey = source_id + event_family + cause_id
```

- `cause_id` 为空时，只允许使用明确的领域实例 ID，不得用当前帧号。
- 多目标命中共享同一攻击实例时，近战接触主层按 `cause_id` 去重；目标受击层仍可按目标实例播放。
- 失败提示按一次命令结果去重，不因 UI 重绘重复发声。

## 10. 设计到制作的资产流程

### 阶段 A：冻结听觉需求

每个新事件先填写：

```text
event_id
trigger_fact
owner
player_information
ai_information
spatial_mode
priority
concurrency
fallback
acceptance_case
```

不先做声音，不先把文件塞进 `AudioManager.SFX`。

### 阶段 B：查重和复用评审

按以下顺序查重：

1. 是否已有同语义事件。
2. 是否已有可复用 SoundSet。
3. 是否只需新增层或变体。
4. 是否必须新建事件和新 AssetID。
5. 是否与当前运行资产同名但语义不同；同名不能自动视为同物。

### 阶段 C：制作与导出

- 源文件进入 `art_source/audio/sfx/<AssetID>/source/`。
- 保留可恢复母版、工程文件、制作说明和许可来源。
- 根据 `spatial_mode` 决定单声道/立体声和循环方式。
- 导出正式 OGG，递增运行版本号。
- 记录路径、哈希、时长、声道、响度参考和 SoundSet 映射。

### 阶段 D：运行接入

1. 在资产账本登记物理资产。
2. 在运行时映射登记 SoundSet/CueProfile。
3. 将事件映射到唯一事实 Owner。
4. 接入 `AudioManager` 语义事件入口。
5. 给 AI 的声音刺激单独核对半径、遮挡和合并。
6. 运行 headless 资源/映射/生命周期校验。

### 阶段 E：听感验收

至少分别验收：

- 单次播放。
- 连续重复。
- 同帧多目标。
- 不同房间和门后。
- 同一场景与 Music/UI/Ambience 叠加。
- 暂停、切图、退出和重新进入。
- Windows 与 Android 正式包。
- 低音量、耳机、外放和高并发。

## 11. 质量验收标准

### 11.1 设计验收

- [ ] 每个事件有唯一事实 Owner。
- [ ] 事件说明了成功、拒绝、中断、失败和重试语义。
- [ ] 玩家听觉与 AI 刺激分别定义。
- [ ] 事件没有把文件名当作 API。
- [ ] 共享资产说明了复用原因和复用边界。
- [ ] 旧事件只作为兼容映射，没有限制目标事件目录。

### 11.2 技术验收

- [ ] 运行资源路径稳定，制作源不进入 PCK。
- [ ] 运行资源全部有版本、哈希和账本条目。
- [ ] 事件调用方不直接加载文件。
- [ ] 缺失资源不会静默回退到旧WAV或合成音。
- [ ] 播放器、循环环境、场景切换和退出不会泄漏。
- [ ] SFX、UI、Ambience、Music 的生命周期边界清楚。
- [ ] 高并发下有并发组、去重和优先级策略。

### 11.3 听感验收

- [ ] 玩家可以区分开火、空仓、换弹、命中、受击和死亡。
- [ ] 玩家可以区分敌人警觉、搜索、前摇、攻击和阶段变化。
- [ ] 门成功开启、门锁拒绝、容器完成搜索、拾取成功不混淆。
- [ ] 撤离开始、撤离中断、撤离成功、主动弃局和结算失败不混淆。
- [ ] 声音位置、距离、墙体/门体遮挡合理。
- [ ] 连射、多目标命中、群怪受击和UI刷屏不造成听觉糊成一团。
- [ ] 近战三段动作的重量和命中反馈可辨。
- [ ] 构筑改变枪械、子弹、配件或命运规则时，声音表现至少有可追溯变化；没有声音变化时必须由VFX/HUD补足，不允许玩家完全听不出差异。

### 11.4 账本验收

- [ ] 每个正式运行文件都能反查到 AssetID、SoundSet、事件和来源。
- [ ] 每个事件都能反查到播放所有者和验收用例。
- [ ] 一条资产被多个事件复用时，账本列出所有关系。
- [ ] 旧版本不被新路径悄悄覆盖。
- [ ] 许可、生成平台任务号或录音来源可追溯。
- [ ] `event_count` 不再作为“音效系统完整度”的唯一指标；完整度必须同时看事件覆盖、资产覆盖、接入覆盖和听感验收。

## 12. 当前实现与目标的差距清单

### P0：先收口事实和声音语义

1. 建立 `AUDIO-SFX` 事件、SoundSet、CueProfile 三层映射。
2. 把 `laser_fire` 从射速分类中独立出来，使用武器音频配置。
3. 明确 `ammo_empty` 的“有效开火尝试但无法发射”触发边沿。
4. 明确 `door_locked` 的拒绝原因所有者。
5. 把 `flashlight_low` 绑定到低电量阈值边沿，而不是电量更新。
6. 分离主动弃局、撤离读条中断、死亡结算和结算保存失败。
7. 撤离成功声绑定结算成功结果，不早于保存事务。
8. 建立读取失败、生成兜底、返回失败的声音语义。

### P1：补全战斗可读性

1. 玩家脚步的可听链与 AI 刺激链并行接入。
2. 敌人警觉、搜索、攻击前摇、技能蓄力、召唤、治疗、举盾和避光声音。
3. 玩家落地、死亡、武器切换、装配和失败反馈。
4. 投射物命中材质、爆炸、碎片和环境反射。
5. 远程武器按 `weapon_audio_profile` 选择声音，不再只按 `fire_rate` 猜类型。

### P2：提升空间和资产质量

1. 世界门、容器、设施和敌人迁移到统一 `world_3d` 播放配置。
2. 完善房间环境床和基地设施底噪。
3. 统一 Music/SFX/UI/Ambience 总线控制和持久化音量。
4. 建立高并发压力、真实设备和空间遮挡验收。
5. 清理重复资产、历史私有映射和未接入的幽灵事件。
