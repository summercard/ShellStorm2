# 对话与战斗信息呈现｜功能设计 v0.1

功能ID：`DIALOGUE-UI`、`UI-HUD`。工程版本：`0.1.0`；设计修订：r3（2026-09-30，新增「物品与武器 3D 图标取景」，r2 为屏幕外怪物指示箭头）。本页定义信息该如何到达玩家；[18 对话技术施工](../18_技术施工_UI与对话系统.md)与[04 战斗技术施工](../04_技术施工_战斗与局内成长.md)记录现行控件、接口和缺口。

## 玩家目标与范围

- **[用户确认]** 对话是独立系统，任何功能都可调用。系统、旁白、无实体播报用屏幕底栏；玩家/NPC/敌人等有实体角色用头顶3D气泡。由内容/调用者确定载体，表现层不自行判定剧情结果，也不改奖励、门或存档。
- **[现行设计]** 底栏逐字显示，确认键在打字中全显、全显后推进行；整场结束要区分自然完成、主动跳过、中止。角色气泡跟随说话者并面向相机。台词与短句由内容侧用稳定ID追溯；即时系统提示允许直接传文字。
- **[用户确认]** 战斗房持续显示当前波数/总波数；整波清空后的2秒间歇和最终肃清有独立波次栏，不被拾取、交互等短消息覆盖。波次状态只读 `Dungeon3D`，不由HUD发起刷怪；运行规则见[05.2 §3.3](../05.2_关卡版图白盒与生成规范.md)。
- **[现行方向]** HUD让玩家看清生命、魂、弹药、武器实例和构筑、地图/互动风险。显示是领域快照的投影，不是物品、生命或武器的另一个状态源。当前仅武器栏已有独立 `HUDPresenter3D`，不能把整个HUD称为独立服务。

## 所有者与衔接

剧情/设施/房间向对话系统发显示请求；`DialogueUI`拥有底栏播放进度，`CharacterBark3D/SpeechBubble3D`拥有角色气泡生命周期。剧情Director拥有“该不该说”和完成历史。HUD各组件只读取玩家、武器、背包、时间、地图等快照；`HUDPresenter3D`仅负责武器栏映射。`剧情事件 → 内容ID/台词 → 载体 → 完成回执 → 剧情继续` 与 `领域状态 → 快照 → HUD` 不反向写领域。

## 命令、查询与事件（设计约束）

底栏播放请求须能被接受或明确拒绝；接受后有可对应请求的完成结果，`completed/skipped/aborted`不能互代。**[未实现]** 目前抢占旧播放不发旧run的 `aborted`，剧情适配器也未检查空run；这两项未收口前，调用方不能把“发了请求”视为“已播完”。气泡目前不是同一请求schema或同一完成事件；统一路由层只是**[待设计]**，不得在新功能中假设已存在。跳过键尚未确定，不能与ESC暂停操作冲突。逐行跳过与当前整场跳过冲突，不列为v0.1规则；立绘、语音、BBCode、多请求队列是可扩展方向，启用前另审设计。

## 数据、失败与验收

正式剧情台词ID由内容侧拥有；底栏临时 `run_id` 只关联当前播放，不进存档。对话失败不得卡住玩法，但必须向需要等待的调用方明确返回失败；HUD缺少字段时降级显示，不得产生虚构余额或武器。验收须覆盖双载体、推进/全显/跳过/抢占、暂停与模态输入、场景卸载、HUD武器实例切换与快照一致性；逻辑入口 `verify_dialogue_ui_flow`、`verify_speech_bubble_3d`、`verify_hud_presenter_3d`，字体、遮挡、层级和移动端仍需真实渲染。

## 屏幕外怪物指示箭头（UI-HUD r2）

**来源**：2026-09-29 用户要求 —— 「画面外的怪物要有目标箭头，在画面四周用小红色箭头指向怪的方向，避免玩家找不到怪物」。

**目标与范围**

- 战斗房内可能还有活着的怪，但它不在屏幕上：相机是挂在玩家身上、俯角约 52° 的透视相机，一屏只看到身边十几米；大房（44×34、65×65）与遮挡后面都看不见。箭头补的就是这一段"找不到"。
- 只在屏幕**外**画：目标已经在画面内就不画箭头。箭头是补偿，不是第二套雷达，也不复制小地图。
- 形态：屏幕最外那条窄带里一支**红色小三角**，尖端指向目标方向；有轻呼吸亮度。**不画背板** —— 与 HUD 其余部分同一口径，只靠深色描边保证在浅色天花板与深色废土上都能读。
- 多目标：同一方向上挤在一起的目标合并成一支箭头（优先保留离玩家最近的），避免边缘糊成一片红。

**Owner 与依赖**

- Owner：`OffscreenEnemyIndicator3D`（`src/ui/` 下的独立 Control）。它只接收 `(世界坐标数组, 相机)` 并投影，**不自己找怪、不判断谁算目标、不写任何玩法状态**。
- 目标筛选的唯一所有者是 `Dungeon3D._get_offscreen_enemy_positions()`：活怪（`current_hp > 0`）＋ **已经醒着**（`Enemy3D.is_runtime_ai_active()`）＋ 与玩家同层（±4.5 m，沿用 `Enemy3D.activate_from_player_proximity` 的楼板口径）＋ 平面距离 ≤ 50 m（最大战斗房 65×65 的半对角线 ≈ 46 m，向上取整到 50）。
- **不给休眠怪画箭头**：门后未进入的房间、未触发的伏击怪都不指示。否则等于隔着墙把潜行/门禁设计全部报出来。潜伏中的伏击怪由 `Enemy3D.is_concealed_in_world()` 显式排除。

**命令、查询与事件**

- 命令：`Dungeon3D` 每 1/20 s 调 `OffscreenEnemyIndicator3D.set_targets(positions, camera)`；无目标时传空数组。
- 查询：`get_snapshot()` 返回 `target_count / marker_count / on_screen_count / edge_margin_px / cluster_radius_px / arrow_color / markers`。纯函数 `project_markers(camera, positions, viewport_size, edge_margin, cluster_radius)` 可脱离场景单测。
- 不产生事件；箭头不进存档、不进战斗日志。

**数据与生命周期**

- 箭头层由 `Dungeon3D._install_offscreen_enemy_indicator()` 在 HUD 安装期创建一次（`$HUD` 下 `OffscreenEnemyIndicator3D`，`z_index = 110`，介于小地图 105 与低血量暗角 220 之间），随战局场景卸载。
- 世界坐标每帧都是新快照，不做缓存、不反写敌人位置。

**拒绝与回滚**

- 相机缺失或视口尺寸非法 ⇒ 返回空投影、不画、不报错。
- 目标正压在画面中轴上（方向退化）⇒ 按"无需箭头"处理并计入 `on_screen_count`。
- 回滚口径：删除 HUD 下这一个节点即可，不影响任何既有 HUD 控件与探针读取的节点结构。

**正式接入与验收**

- 正式入口：`scenes/TowerDescent3D.tscn`（塔楼与远征 01 共用同一 HUD 安装链路）。
- 逻辑验收 `verify_offscreen_enemy_indicator`（注册 `core`）：纯投影的屏内/屏外/身后/合并四类判据，加上 `Dungeon3D` 取数口的"活怪/已唤醒/同层/射程"四条排除规则（用真实敌人对象现场改状态验证）。
- 视觉验收 `verify_offscreen_enemy_indicator_visual`（注册 `visual`，真实渲染器）：箭头真渲染出来、贴在外缘窄带内、屏内的怪不产生箭头，并输出截图。

## 物品与武器 3D 图标取景（UI-HUD r3）

**来源**：2026-09-30 用户要求 —— 「图标栏中，物品如果大于图标尺寸，会被切，而且居中位置不对。修改一下。」

**玩家目标与范围**

- 图标里看到的必须就是**这件东西本身**：世界拾取、背包、快捷栏、HUD 武器栏、贩卖机卡片、保险柜、试衣间都共用同一个渲染者 `ItemModelIcon3D`，它把背包同源模型渲染进一块单帧正交 `SubViewport` 再贴成 `TextureRect`。图标是模型的投影，不是另画一套图。
- **两条硬口径**：图标**永不切边**、模型**永远居中**。这两条与图标格尺寸、模型尺寸、模型造型都无关 —— 换一把更大的枪、换一个更窄的格子、换一件斜置的细长件，都必须仍然成立。任何"按模型种类写死一个展示距离/位移"的做法都违反本条。
- **第三条**：视口长宽比**跟随图标格长宽比**。宽格子（HUD 武器格 51×37）拿宽视口；用正方形视口去填宽格子，模型用不上横向空间，看上去就是"左右各空一条、其实没居中"的假偏心。
- 图标只表达"这是什么"与稀有度色，不承载数量、耐久、弹匣等数值；数值仍由各自的文本控件表达。

**取景规则（唯一算法，Owner = `ItemModelIcon3D`）**

1. **量投影**：逐个 `MeshInstance3D` 取自身局部紧盒（`mesh.get_aabb()`）的 8 个角点，用 `global_transform` 变换到世界，再投到相机的 `right`/`up` 两轴取并集。
   - **不得先把所有网格并成一个世界 AABB 再投影**：斜置细长件的世界 AABB 是个膨胀的大盒子，其投影可达实际轮廓 5 倍以上（2026-09-30 实测：巨剑只填满图标短边 13%，即"看着没居中"的真正来源）。
2. **定相机**：`camera.size = max(span.y, span.x / viewport_aspect) / FIT_FILL_RATIO × multiplier`。`FIT_FILL_RATIO = 0.88` 是留给描边与抗锯齿的安全边距。
3. **居中**：`model.position -= right × dot(center, right) + up × dot(center, up)`。正交投影下深度不影响取景，因此只补横向与纵向。
4. **不复用"缩小模型"这条路**：`set_camera_size_multiplier()` 的定义域是 **[1.0, 2.0]**，语义只有"追加取景余量"（2.0 = 四周多留一倍空白）。**小于 1.0 一律封口在 1.0** —— 那是"把模型放大到出框"的路径，与第一条硬口径冲突。要整体放大/缩小请改 `FIT_FILL_RATIO`，不要从调用点传倍率。
5. **局部特写按归一化坐标表达**：avatar 部位（头/帽/眼镜/身/手/脚）沿用"哪个部位看哪一段"的既有意图，但段以**模型世界外接盒的归一化 y 区间**给出（如头 = `[0.62, 1.00]`），不写死米数与绝对偏移；模型换尺寸也不会切边或跑偏。

**命令、查询与事件**

- 命令：`configure(item)`（背包同源模型）、`configure_custom_model(factory, model_kind)`（试衣间 avatar）、`clear_model()`、`set_camera_size_multiplier(multiplier)`。调用点**不再传**取景倍率。
- 查询：`get_snapshot()` 除既有字段外，回取景实测证据 —— `model_bounds_min/size`、`projected_half_extents`、`frame_half_extents`、`fit_ratio`（≤ 1.0 即完整可见）、`center_error_pixels`、`fit_fill_ratio`。验收直接读这些字段，不需要另建量尺。
- 不产生事件；图标不进存档、不进战斗日志。

**数据与生命周期**

- 视口为 `SubViewport`（`own_world_3d`、`transparent_bg`、`render_target_update_mode = UPDATE_ONCE`）：只在配置或控件尺寸变化时渲一帧，不受射击、弹量、走动影响。空槽**不建立** SubViewport。
- 模型来自 `ItemModelFactory3D`，与世界拾取、贩卖机、保险柜同源；武器走正式武器资产，不复制网格。
- 图标常驻节点数受 `verify_3d_performance_budget` 约束：不为每个图标格预先建视口，按需建、按需丢。

**拒绝与回滚**

- 模型无网格、相机缺失、视口尺寸退化 ⇒ 不取景、不渲染、不报错（`visible = false`）。
- 控件被压到极小 ⇒ 视口短边有 24px 下限，不把渲染分辨率拉成几个像素。
- 回滚口径：取景完全内聚在 `ItemModelIcon3D` 内部，调用点不参与计算；回滚只需还原该文件，并让各调用点重新自行传倍率。

**正式接入与验收**

- 正式入口：`Dungeon3D` 的 HUD 武器栏与快捷物品栏、`InventoryUI`（背包/装备/保险/配件格）、`BaseVendingMenu`/`BaseStorageSlot`、`WardrobeMenu3D`。
- 逻辑验收：`verify_3d_inventory_weapon_flow`（背包格 96×96 视口预算与 `camera_size ≤ 1.9` 可读性下限）、`verify_hud_presenter_3d`、`verify_tactical_inventory_minimap_flow`。
- 视觉验收：`verify_item_model_icon_framing_visual`（注册 `visual`，真实渲染器）—— 4 种真实图标格几何 × 12 种物品（含狙击枪、巨剑、战斧、球棒等"大于图标尺寸"的件），两层口径各查一次：**几何层** `fit_ratio ≤ 1.0`、`center_error_pixels ≤ 2px`；**渲染层**（独立证据，算法算错或曲面凸出外接盒都抓得到）已绘像素 `margin_min ≥ 1px`（不贴边 = 没被切）、已绘像素中心偏差 ≤ 2px、较长边填充 ≥ 0.5。另驱动真实 HUD 武器栏（装巨剑）与真实背包格复核，并输出带标签的联系表截图。
- 既有视觉验收 `verify_wardrobe_layout_visual`、`verify_reference_hud_fate_visual`、`verify_base_vending_visual` 同时作为回归口。
