# 远征墙高与场景资产路由规范

状态：现行规则。功能归属：`WORLD-PLAN` / `ASSET-PIPELINE`。
机器契约：`assets/registry/expedition_scene_height_contract.json`。

## 1. 先看结论

远征01和远征03不是同一套墙高。不能因为两关都属于 `block_id=expedition`，就把墙、门墙、地砖或房间组件互相替换。

| 关卡 | 逻辑/阻挡墙高 | 视觉墙高 | 墙厚 | 结构资产族 | 运行时结构 Owner |
|---|---:|---:|---:|---|---|
| `expedition_01` 非Boss12间正式布局 | **2.8m** | **2.8m** | 0.30m | `expedition_01_low_h28` | 低墙运行Prefab + 原正式布局门位/门扇 |
| `expedition_01` Boss深井例外 | 按 `boss_deep_shaft_80x100` | 按Boss深井/平台坑 | 0.30m | Boss专项包络 | 保留Boss深井、桥坑与桥上路线 |
| `expedition_02` / 历史塔楼 | **12.0m** | **11.9m** | 0.30m | `tower_h12` | 历史、Boss和02保留；不改03资源 |
| `expedition_03` | **2.8m** | **2.8m** | 0.30m | `manor_h28` | `ManorShellPlan` 按本局门位重建 |

远征01非Boss正式布局的公式是：

```text
逻辑/碰撞墙高 = 2.8m
视觉墙高 = 2.8m
楼层间距/垂直标高间隔 = 12.0m（不是房间墙高）
顶部预留 = 0.0m
```

远征03的公式是：

```text
公馆墙高 = 门墙上沿 = 2.8m
视觉墙高 = 2.8m
普通门洞 = 2.2m宽 × 2.5m净高
```

远征03 `level_plan.json` 里的 `floor_height_m=12.0` 只表示独立关卡的垂直分层/场景标高间隔，不得解释成房间墙高。远征03是单层 flow 关卡，房间壳体与公馆结构件按 `2.8m` 走。

## 2. 远征01：非Boss正式布局使用2.8m低墙，Boss保留专项深井

### 2.1 真源

- 关卡计划：`art_source/design/whitebox/tower_zones/expedition_01/v001/data/level_plan.json`
  - `floor_height_m = 12.0` / `floor_spacing_m = 12.0`（垂直标高间隔）
  - `logical_wall_height_m = 2.8`
  - `visible_wall_height_m = 2.8`
  - `wall_thickness_m = 0.3`
  - `asset_family = expedition_01_low_h28`
- 运行投影：`data/level_plans/expedition_01/level_plan.json`
- 12.0m楼层间距仍由统一塔楼常量提供；远征01非Boss房间墙高由`expedition_01_low_h28`模板与Prefab契约提供，不从塔楼`WALL_LOGICAL_HEIGHT_M`/`WALL_VISUAL_HEIGHT_M`常量反推。
- 远征01七个非Boss模板：`data/level_plans/expedition_01/room_templates/*.json`，`wall_height_m=2.8`、`logical_wall_height_m=2.8`、`visual_wall_height_m=2.8`，门墙仍为2.2×2.5m。
- 12间非Boss正式布局（入口、安全屋、01–10号房、撤离屋）保持原正式TSCN、原运行路线、原门位和门扇；Boss不计入低墙数量。

### 2.2 允许资产

远征01非Boss正式布局使用以下独立族：

- `expedition_01_low_h28`
- 运行场景通用前缀：`assets/art/environments/tower_zones/expedition/runtime/expedition_01_low_h28/`
- 各组件使用通用后缀：`*_h28_root_top3d.tscn`
- 组件源与清单：`art_source/environments/tower_zones/expedition/source/expedition_01_low_h28/v001/`
- `tower_h12` 仅保留给历史塔楼、Boss和远征02；不改远征03资源。

历史 `h12` 组件在资产账本中也承担远征02挑高前厅、历史塔楼和Boss的既有用途；本轮不移动、不改名、不删除。它们不再属于远征01非Boss普通布局，也不授权带入远征03。消费前必须同时核对目标 `level_id`、Prefab metadata 和运行布局路径，不能只看AssetID或manifest的历史主用途。

对应路径保持稳定，不移动、不改名、不在 `assets/art/**/runtime` 目录附加版本号：

```text
art_source/environments/tower_zones/expedition/source/common_components/v015/component_packages_v015/wall_standard_5m_h12/
art_source/environments/tower_zones/expedition/source/common_components/v015/component_packages_v015/wall_door_5m_h12/
assets/art/environments/tower_zones/expedition/components/common_components/wall_standard_5m_h12/
assets/art/environments/tower_zones/expedition/components/common_components/wall_door_5m_h12/
assets/art/environments/tower_zones/expedition/runtime/common_components/wall_standard_5m_h12/
assets/art/environments/tower_zones/expedition/runtime/common_components/wall_door_5m_h12/
```

### 2.3 深井例外

远征01桥房坑、Boss深井和桥上路线是低墙族之外的保留例外。桥坑继续使用12.0m下沉深度，Boss继续使用`boss_deep_shaft_80x100`深井包络；这些数值不是普通房间墙高，也不改变`expedition_01_low_h28`。

历史方案曾把桥房坑壁写成11.9m视觉墙沿垂直轴拉伸；本轮只保留坑深/路线语义，不把该历史族重新接回非Boss普通墙。

历史公式（仅作追溯）如下：

```text
坑壁实例高度 = 12.0m坑深 + 0.8m护栏 = 12.8m
实例 scale_y = 12.8 / 11.9
```

这条只属于远征01多层桥房的 `pit_wall` 实例，不得复制到远征03。

## 3. 远征03：公馆2.8m

### 3.1 真源

- 关卡计划：`art_source/design/whitebox/tower_zones/expedition_03/v001/data/level_plan.json`
  - `floor_height_m = 12.0`：垂直标高间隔字段，不能当房间墙高。
  - `visible_wall_height_m = 2.8`
  - `wall_thickness_m = 0.3`
- 运行投影：`data/level_plans/expedition_03/level_plan.json`
- 房间模板：`data/level_plans/expedition_03/room_templates/*.json`
  - 所有模板的 `wall_height_m` 必须为 `2.8`。
  - `door_contract.lintel_bottom_z_m` 必须为 `2.8`。
- 运行时壳体：`src/world3d/ManorShellPlan.gd` + `DungeonRoom3D.gd` 的公馆结构分支。

### 3.3 远征03桥房/下沉装饰

`data/level_plans/expedition_03/room_templates/bridge_60x50.json` 保留了历史模板名和12m下沉深度，但它不改变03墙高：

- `wall_height_m = 2.8` 仍是房间外壳契约；
- `sunken_pit.depth_m = 12.0` 只是不可达的视觉下沉深度；
- 坑壁/护栏属于本房多层装饰结构，不能写成远征01的 `wall_standard_5m_h12`；
- 03桥房当前不进入六张 flow 的实际房型池，模板记录只作为兼容与历史追溯，不能据此把01资产接入03。

## 4. 明确禁止的复用

| 禁止动作 | 原因 |
|---|---|
| 在远征03放 `wall_standard_5m_h12` / `wall_door_5m_h12` | 会在2.8m公馆壳体内生成11.9m高墙和空阻挡 |
| 在远征01非Boss布局把 `manor_wall_standard` 当低墙 | 远征01必须走独立 `expedition_01_low_h28` 族，避免跨关Owner和Prefab语义混用 |
| 用 `floor_height_m=12.0` 推导远征03房间墙高 | 该字段在03表示关卡垂直标高间隔，不是房间壳体高度 |
| 用房间模板的历史 `ENV-EXPEDITION-L01-ROOM-*` AssetID 选择03运行Prefab | 03模板保留历史白盒对位ID，运行结构仍由`manor_h28`路由 |
| 以整件纵向缩放修复普通墙高 | 只能在已声明的远征01 `pit_wall` 多层实例按公式伸长，普通墙禁止缩放凑高 |
| 把“共享组件”理解为“共享尺寸契约” | 共享材质/Prefab技术链不等于跨关卡墙高可互换 |

## 6. 机器验收

本轮机器契约除验证高度外，还验证远征01 12间非Boss正式布局、七个非Boss模板、原门位/门扇保留、room_08内部15围挡、Boss深井/桥坑例外、黑幕纯视觉属性，以及低墙Prefab通用前缀。

本轮新增机器契约：

```text
assets/registry/expedition_scene_height_contract.json
```

专项门禁：

```text
python scripts/check_expedition_scene_height_contract.py
```

门禁至少必须证明：

1. `expedition_01` 的计划字段为 `floor_spacing=12.0 / logical_wall_height=2.8 / visual_wall_height=2.8`；
2. `expedition_03` 的计划字段为 `12.0 / 2.8`；
3. 远征03全部房间模板 `wall_height_m=2.8`；
4. 远征03数据层没有引用远征01 `h12` 墙族；
5. 远征03公馆墙Prefab存在且包络高度为2.8m；
6. 远征03桥房的12m下沉描述不再把11.9m标准墙当作可用墙族；
7. 远征01与远征03的允许资产族不交叉误用；远征01低墙Prefab前缀、12间正式布局、七模板、room_08 15围挡和Boss/桥坑例外均满足专项契约。
