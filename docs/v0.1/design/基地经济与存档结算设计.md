# 基地经济与存档结算｜功能设计 v0.1

功能ID：`BASE-SHOP`、`RUN-MERCHANT`、`SAVE-PROFILE`、`SAVE-RUN`、`RUN-SETTLE`。工程版本：`0.1.0`；设计修订：r1（2026-09-24）。本页定义玩家可依赖的交易与恢复规则；[局内商人玩法](../04.1_玩法系统_局内商人.md)、[基地设施施工](../07_技术施工_基地设施.md)和[存档施工](../09_技术施工_存档结算与复活.md)保留具体接口/文件格式/当前差距。商品ID、价格、上架状态归内容数据库。

## 玩家目标与范围

- **[现行方向]** 基地99F正式自动贩卖机是 `facility_id=base_vending` 对应的 SUPPLY24H 资产；旧 `BaseWorld3D` 长方体不是当前正式99F造型。商店消耗显示名“魂”，可购买当前正式七类无限库存商品，或出售随身背包/保险柜的物品。正式99F购买进入 I 键所见的同一背包；容量不足不能扣款或悄悄改投保险柜。模型不拥有交易规则。
- **[已确定的局内商人规则]** 每个商人房间在本局首次打开时确定报价和实例，关窗重开、同局读档不重抽；成交后该报价消失。首笔成功交易可解锁交易条件撤离。当前正式链见[局内商人玩法](../04.1_玩法系统_局内商人.md)；它不是基地无限库存店。
- **[用户设计/现行方向]** 玩家从战局撤离或死亡后得到一次明确结算。完整武器实例、保险物、魂和长期进度应按结果一次交接；死亡保险物按原格位返还。普通死亡返回99F，不冒充复活。复活次数和代价另行设计。

## 所有者与衔接

`GameManager` 拥有局内魂，`InventoryModule/InsuranceModule` 拥有格位；`RunMerchantService` 协调房间报价交易；`BaseShopService` 提供基地商品/价格/实例规则，`BaseManager` 是长期魂、档案与磁盘提交的唯一写者；`RunPersistenceService` 管行动快照。UI只提交命令并显示确认结果。`行动快照 → 结算ID → BaseManager一次提交 → 基地背包/保险/余额 → 下局`；不能让场景或菜单各写一份长期档。

## 命令、查询与事件（设计约束）

| 操作 | 必备身份与结果 | 失败结果 |
|---|---|---|
| 基地购买/出售/转移 | 商品ID、目标实例ID、事务ID、目标集合、当前修订 → 完整提交结果 | 余额/容量/旧修订/写盘失败时资源与集合不出现半笔变化 |
| 局内商人首开/成交 | 稳定房间ID、报价ID、临时会话ID、完整物品实例 → 行动快照 | 首开写盘失败不展示可交易货架；成交失败恢复魂、背包、报价、撤离条件 |
| 行动保存与结算 | 行动ID、结算ID、validated快照 → 可重载的同一结果 | 重复结算不能复制物品；保存失败允许安全重试，未验证半成品不得落档 |

玩家提示必须区分“请求发出”与“已写盘成交”。稳定事务ID服务于重复请求/读档幂等，临时商人会话ID不当作长期货架身份。基地货架无限、局内货架有限，不能共享一个库存语义。

## 数据与生命周期

当前长期档是单封套，行动快照单独记录运行态；`extraction_points` 是旧档兼容字段名，UI显示“魂”。旧档迁移不可丢原档。多领域根清单/分文件提交是**[工程提案，未冻结为玩家规则且未实现]**，不能据此否定当前单封套。局内商人库存 `merchant_stock` 只属于行动，旧档缺字段按首次未访问处理，字段损坏不能静默重抽。基地商品表不复制进存档，只保存交易结果及独立实物。

## 失败与验收

应分别验证买、卖、保险转移、首开、成交、撤离、死亡结算的正常/容量不足/资源不足/旧修订/写盘失败/重试/跨重启；断言实例仅一份、余额准确、报价不重抽、保险格恢复。当前商店各入口旧修订冲突、文件底层故障与完整结算通知仍有技术缺口，见施工文档；逻辑绿灯不等于界面与资产表现合格。入口：`verify_base_shop_save_flow`、`verify_run_merchant_transaction`、`verify_run_merchant_integration`、`verify_runtime_autosave_flow`、`verify_run_settlement_transaction`。
