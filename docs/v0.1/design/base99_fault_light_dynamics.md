## 1. 现有实现必须先搞清楚的一件事

`src/world3d/BaseFixtureGlow3D.gd` 已经把基地里**所有** `emission_enabled` 的 surface
duplicate 成独立材质，并把 `emission_energy_multiplier` 提到 HDR 值（2.35 或按峰值算）。
实测 155 个面被接管，其中「灯具级」8 个。

这套机制有三个写入口会改同一个属性：

```
set_presentation_lighting_enabled()   → 0 或原值
_set_material_energy_range()          → 启动分批 0 / 0.16 / 1.0
_start_authored_art_light_delay()     → 只动 OmniLight3D，不动材质
```

**新加的闪烁必须收编进同一个写入口**，否则会和开关/启动序列打架（谁后写谁赢）。
方案：把这 6 个对象的材质登记进一个新的动态表，统一走

```
energy_final = base × seq_factor × motion_factor
```

- `base`：`_emission_energy_by_material` 里已存的原始值（不动）
- `seq_factor`：现有启动序列（0 / 0.16 / 1.0）
- `motion_factor`：本次新增的闪烁 / 呼吸 / 流水 / 眨眼

这样「开关关灯」时 `seq_factor=0`，`motion_factor` 再大也不会亮；开灯序列播放期间
`motion_factor` 保持 1（不干扰原有时序），序列结束才接管。

## 2. 七个通道的具体设计（已实现值）

所有强度都写成 `emission_energy_multiplier` 的**倍率**，再乘到 `BaseFixtureGlow3D`
存下的 baseline 上。下表的「实测差异」是在 1100×700 真渲染、目标机位下
「静息帧 vs 极值帧」的像素差与最大通道差，全部来自 `verify_base_lamp_visual.gd`。

### A · BASE CAMP 霓虹标识 —— 间歇抽动

| 项 | 值 | 依据 |
|---|---|---|
| 间隔 | **8~15s 随机** | 业主原话「8-15 秒一次」，不放慢 |
| 单次时长 | 0.62~0.96s | |
| 最低 | **0.72**（-28%，不归零） | 招牌仍完整可读，不读成「断电」 |
| 波形 | 3~4 次抖动，`sin(πt)` 包络 + `cos` 涟漪，smoothstep 抹圆 | 方波边沿会被读成掉电 |

实测（0.72 档，渐变实验）：**25% 像素变化**，差异 max 147/255。这一档完全够明显。

### B · 床头灯 —— 慢呼吸（**向下沉**）

| 项 | 值 |
|---|---|
| 周期 | **5.4s** |
| 值域 | **0.87 ~ 1.00**（只往下，永不超过原亮度） |
| 波形 | `1 - 0.10·(0.5+0.5sin(τ/5.4)) - 0.03·(0.5+0.5sin(τ/2.1))` |

**方向必须是向下。** 这盏灯 baseline 已到 13.97，灯罩在 filmic 下是纯白 `(255,255,255)`
—— 往上加能量在画面上是 **0 变化**（实测梯度：×1.00→×1.10 几乎无差异，×1.00→×0.90
有 32614 px 变化）。第一版写成「只往上」，等于没做。

补光 `PaletteLightSpill.light_energy` 同步乘同一个倍率，否则「罩子在呼吸、桌面光不动」。

### C · 贩卖机屏幕 —— 退级为「整屏眯眼」

原方案（顶点压扁做眨眼）**实测不可行**，原因见 §2-C 的实测表。
落地的是 **C1**：

| 项 | 值 |
|---|---|
| 常态 | 1.00 + 3.4s 周期 ±3%（待机起伏） |
| 眨眼事件 | 间隔 **9~14s**，时长 **0.26s** |
| 深度 | 降到 **0.62**（-38%） |
| 波形 | 快落慢起：`smoothstep(0,0.28,t)` × `1-smoothstep(0.45,1,t)` |

读作「屏幕眯了一下眼」。**代价：嘴也一起暗** —— 眼睛与屏幕共用同一 surface
（9317 顶点 / 2262 个碎岛），做不到局部。

实测差异 **14.9% 像素 / max 107**。差异图（`compare_vending.png` 第三格）里
眼睛与嘴的轮廓同时变淡，正是「眯眼」的读法。

### D · 配电柜三灯 —— 自检流水

| 项 | 值 | 依据 |
|---|---|---|
| 方向 | 01 → 02 → 03（沿 z，从北往南） | |
| 单灯点亮 | 0.70s | 业主「节奏不要太快」 |
| 相位差 | **0.32s** | 重叠形成追光，不是逐个跳 |
| 峰值 | **1.85** | |
| 熄灭态 | **0.18** | 不归零，保留灯珠轮廓 |
| 轮间隔 | **2.8~4.2s** | 整体放慢 |

三灯共用一个时钟、固定相位差 ⇒ 读作「一台机器在自检」，不是三个灯各闪。
实测相位差 0.317s / 0.325s（目标 0.32），同时点亮 ≤2 盏。

### E1 · 东墙红色应急灯 —— 间歇双跳

| 项 | 值 |
|---|---|
| 间隔 | **6.5~12s** |
| 单次时长 | 0.95~1.40s |
| 波形 | 「双跳」：1.00 → 0.15 → 1.00 → 0.15 → 1.00（0.00/0.11/0.21/0.31/0.41s） |
| 最低 | **0.15** |

「连抽两下」是故障灯的典型读法，比单次闪可信，比方波硬灭柔和。

### E2 · 主门警示灯 —— 慢呼吸（双向）

周期 **8.6s**，值域 **0.843~1.157**（±13%，相位固定偏移 2.2rad）。
幅度从 7% 提到 13%：7% 在真渲染里只有 max 6/255（灯小、又在过曝区），读不出来。

与 E1 语义区分：一个是「坏了」，一个是「待机」。

### F · 二楼电脑屏 —— 快速频闪

| 项 | 值 |
|---|---|
| **常态** | **0（完全不发光，= 改动前的原美术外观）** |
| 事件间隔 | **10~16.5s** |
| 事件时长 | 0.26~0.46s |
| 事件内 | 基线 **0.78** + 抖动 ±**0.34**，夹紧 [0.30, 1.15] |
| 抖动频率 | 每次事件重抽 **8~14Hz** |

**常态必须是 0。** 这块屏幕原本是 `03_清漆反光` 面、靠反光显色、`emission_enabled=false`。
若常态就给它自发光，等于把美术的深蓝暗屏改成亮蓝屏 —— 那是「改外观」不是「加动态」。
所以只做「事件里亮起来抖」，其余时间与改动前逐像素一致（实测常态静默占比 98%）。

实测差异 **14.3% 像素 / max 246**。

## 3. 错开规则（业主「节奏不要太快 时间错开」的落地）

六个事件型通道（A/C/E1/F 为事件，B/D/E2 为持续）共用一道闸门：

- **同时进行中的事件 ≤ 2 个**（`MAX_CONCURRENT_EVENTS`）
- **相邻两次事件起始间隔 ≥ 2.9s**（`MIN_EVENT_GAP_SECONDS`）
- 被挡住的**不是丢弃**，而是下一帧继续尝试 ⇒ 表现为顺延，不是跳过
- **霓虹有预约特权**：它的下一次起始时刻一确定，其余通道在 ±2.9s 内让路。
  否则实测有 24% 的霓虹事件被闸门推到 15s 以上 —— 那是在改业主给的节拍
- **三灯流水不计入配额**（它是背景节拍，不是事件）
- **起始时刻硬错开**：进场景后 A=7.5s、E1=10.0s、C=13.5s、F=17.0s、D=1.8s 才首轮

压力测试 300s 结果：**峰值并发 1**、最小起始间隔 **2.90s**、霓虹 25 次、事件总数 83。

## 4. 落地方式（不动美术源）

新增 2 个文件 + 1 处场景挂载：

```
src/world3d/BaseLampDynamics3D.gd          # 7 通道波形 + 事件闸门 + 统一写入口
tests/verification/verify_base_lamp_dynamics.gd(.tscn)   # 结构验收（headless 可跑）
tests/verification/verify_base_lamp_visual.gd(.tscn)     # 视觉验收（必须真渲染）
zone_base.tscn:  [node name="基地灯具动态" type="Node3D" parent="Art"]
```

**写入口不能打架**（这是本节最重要的一条）：

`BaseFixtureGlow3D` 已经是这些材质的唯一所有者 —— 墙面开关写 `0 / 原值`，
4.2s 启动序列写 `0 / 0.16 / 1.0`。所以本脚本只在它**静止**的时段
（`presentation_lighting_enabled && !presentation_starting`）才写
`baseline × motion_factor`，并且：

- 它重新接管时（开灯 / 序列结束），把当时的能量**读回**当新 baseline
- 关灯 / 序列期间 `motion_factor` 一律不写，交还原主
- `self_owned` 的面（显示器屏幕，不在它的受控表里）由本脚本自己开关 `emission_enabled`

**自带 RNG，不用全局 `randf()`**：全局 RNG 会被别的系统消耗，
导致「同一时刻进基地」的节奏每次都不同 —— 真渲染对照无法重现（实测拍到两张一样的图）。

**时钟走 `_process(delta)` 累加**，与 `VfxCloudSea3D` / `PlantSway3D` 口径一致；
暂停即停。不新增任何 `Light3D`（实测场景光源数保持 11）。
