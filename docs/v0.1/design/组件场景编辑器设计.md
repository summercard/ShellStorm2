# 组件场景编辑器

FeatureID：TOOL-SCENE-EDITOR；工程版本：0.1.0；契约修订：r8。
模块归属：`TOOLING`；分类：**工具类 / 场景美术制作**；Owner：`ShellStormSceneBuilder EditorPlugin`。
总设计：[游戏总设计 §20](../README.md)；分类与维护入口：[工具类总索引](../TOOL_INDEX.md)；统一追溯：[模块索引](../MODULE_INDEX.md)、[机器注册表](../feature_registry.json)。

来源：2026-10-29 用户要求在 Godot 内调度共享组件，载入白盒自由拼装、刷地表、移动灯光；2026-11-01 用户要求打开入口只显示游戏采用的唯一房间文件，取消“关卡房间 / 美术场景”双视角，并优先在工具内修正。2026-11-01后续确认：门墙/连接继续由种子和装配拥有，房间陈设与作者灯光固定在同一正式TSCN内。功能状态保持 `partial`；本修订冻结陈设所有权与兼容目标，实现和验收结果另记。

## 目标与所有权

编辑器作为 Godot EditorPlugin 提供右侧组件面板，复用原生 3D 视图、选择、移动、旋转、检查器、保存与撤销。正式 TSCN 拥有摆位；共享 PackedScene 拥有组件模型、材质、碰撞和原点。布局只保存组件实例引用，禁止展开或复制组件内部模型。工具代码不进入发行包。

## 数据与输出

- 组件目录直接读取 `assets/art/environments/tower_zones/shared/runtime/shell_component_catalog.json`，不建立第二套资产表。目录缺项或资源缺失须可见报错。套件/类型标签优先读取显式kit_tag/type_tag，存量按组件目录来源路径、slot_role与slug/category只读投影；不回写另一套资产账本。
- 白盒选择必须覆盖远征03房间rt、通道cr以及可供远征03制作参考的EGT共享白盒，统一按元数据发现并标明来源，支持搜索选择；共享库仍标明共享归属，检索远征03也须能找到。亦可选择任意白盒 TSCN；新建房间保存为独立美术 TSCN，不覆盖参考白盒。复制尺寸、轮廓与连接口声明，额外模板的白盒可视参考仅存在于编辑器中，不入存盘，不携带运行碰撞。历史实际房间场景中的WhiteboxShell按现有资源保留，工具不擅自重建或删除。
- 场景根记录 `template_id`、`variant`、`size_m`、`footprint_polygon_m` 与编辑器 schema。`ArtComponents` 下每个实例根保存 `component_id`、`slot_role` 和稳定资源引用；`Lighting` 保存可原生编辑的 OmniLight3D / SpotLight3D；`ConnectionPorts` 保存白盒参考的 Marker3D。
- 支持编辑现有 Node3D 场景。插件不接管作者原有自定义节点，不自动覆盖 TSCN。Ctrl+S 与另存为使用原生编辑器。
- 默认打开列表只读投影现行游戏绑定的正式房间路径，并按路径去重。参考模板输出仍需由关卡模块登记后才进入运行池；工具保存不等于自动接入。工具不修改关卡拓扑、刷怪、门状态机、存档或经济。

## 工作台与操作

主流程固定为“打开/新建场景 → 选择共享组件 → 在3D视图拼装 → 保存”。顶部是短场景工具栏：打开、新建、保存、更多，以及一行当前场景状态；打开场景不能藏在灯光/参考设置中，也不保留重复入口。场景未就绪时显示清晰引导，放置动作须提示前置条件。

主体面积优先分配给组件缩略图网格和可旋转3D预览，二者可调整比例，默认合计不少于常见900px高面板的60%。搜索、套件大标签、类型小标签与收藏采用紧凑控件；长名称用省略和悬停详情，不撑大面板。场景工具栏下方是选择、放置、笔刷、矩形、直线、擦除、点光、聚光八个小按钮，当前模式高亮，不使用操作下拉；底部仅保留收藏、旋转、吸附和选项。间距、标高、角度、笔刷、裁切、端口保护、参考和灯光在可折叠选项区分组显示，默认收起。工具使用独立深蓝灰底色、青绿色强调和明确的选中/禁用状态，仅影响本工具，不修改Godot全局主题。面板显示可核对的工作台修订号；脚本更新后能识别旧控件树并安全重建，不要求用户反复猜测是否已加载新版。

组件按“资产套件 → 组件类型”检索，支持名称/ID/别名搜索与收藏。卡片提供真实缩略图；选中后在隔离World3D预览中拖动旋转、滚轮缩放、复位。预览占主要空间，可展开或折叠。选中高成本资源、生成缩略图时有即时状态与数量反馈，不同步加载整库；快速换选只显示最后一次请求。加载失败保留可读原因和重试入口。

放置方式包括选择、单件、连续笔刷、两点矩形、两点直线、擦除与点光/聚光。Q/E按90度旋转，Esc返回选择；Alt+鼠标保留原生导航。显式网格吸附默认关闭，关闭时保留真实落点；格心/墙边仅改变已开启吸附的相位。标高与笔刷间距独立，连续笔刷按间距插值，每笔/每片只产生一条原生撤销。地砖支持替换、防重复；擦除仅作用于工具登记的组件。

有轮廓时按组件包络裁切，支持凹多边形；可保护端口净空。实际组件半透明轮廓用绿色/红色表示可放/受限，无scene owner。单批上限4096，超限拒绝而非截断。灯光放下后使用原生选择、移动与检查器编辑。

## 加载、反馈与升级

场景打开、白盒参考及组件预览通过后台资源请求和主线程完成阶段衔接：先绘制反馈，再读取资源；只在加载完成后获取结果，避免在未完成时阻塞等待。场景只有在原生编辑器确实切换到目标根后才显示成功；缺文件、非3D资源、加载失败或切换超时须显示原因、重试和返回入口。新请求替代旧请求，旧结果不能覆盖新选择。取消只取消工具的后续处理，不虚称中止引擎已经开始的读取。

场景列表先显示窗口与扫描状态，再在后台扫描只读文件元数据，主线程建树。索引有刷新、空结果与扫描失败反馈。场景切换期间限制拼装并保持当前场景；原生编辑器最终实例化仍由Godot拥有，显示单独“正在打开”阶段，不假报读取百分比或承诺可强制取消已经执行的原生操作。更新后的旧UI与失效服务需可重建，旧场景、摆位与原生撤销记录不随面板升级丢失。

## 唯一正式房间列表（r7）

“打开”只有一份可搜索的正式房间列表，不再提供“关卡房间 / 美术场景 / 参考模板”切换，也不要求地图种子或启动Python采集器。列表按关卡和房间类型分组；同一正式TSCN路径只出现一次，选中后打开并保存同一个文件，不为本次种子或实例另建副本。

索引由 `tools/scene_builder/scene_index.gd` 只读派生，不能另建一份人工维护的房间登记表：

- 固定蓝图关卡从正式设计源的房间绑定发现其稳定TSCN。
- 远征03的 `runtime_rooms/` 候选须由共享 `RuntimeRoomArtSource` 当前身份/路径契约验证；不把旧门位文件、派生缓存或仅有目录的白盒参考视为当前游戏采用的文件。
- 列表名称和尺寸来自正式资源元数据。来源房间ID只作追溯，不把烘焙时的实例名当成独立资产身份。无法验证的候选不混入正式列表；空列表、缺失资源和扫描失败应显示可读反馈，刷新允许重试。
- 搜索覆盖关卡、名称、模板/原型和路径。详情提供实际打开的唯一资源路径，避免多个实例名掩盖对同一文件的编辑。

顶部“新建”与“选项 → 参考 → 关联/更换”继续使用专用白盒选择器，只列参考白盒。新建另存为时保留原参考文件；EGT来源的美术输出默认进入远征03美术目录，不保存到共享白盒库。参考模板及尚未接入运行池的新文件不因保存就进入默认打开列表。原生文件选择是补充入口，不等于游戏绑定声明。

白盒参考状态包括已加载、已隐藏、当前场景本身为白盒、未关联、路径不存在或资源无效；关联变更可原生撤销，不改已有摆位。白盒透明度可调，显示与透明度独立；参考预览禁用脚本、处理、碰撞、导航、声音与粒子。

### 命令、查询与边界

| 入口 | 输入与结果 | 所有者与失败语义 |
|---|---|---|
| `scene_index.game_rooms()` | 只读返回现行正式房间文件行；同路径唯一 | 运行绑定拥有资源身份，工具只投影；不生成关卡、不建立替代映射 |
| 打开/刷新/搜索 | 选择行的唯一TSCN路径，原生编辑器确认切换后才算打开成功 | 工具管理扫描/加载状态；失败保留当前场景并可重试 |
| 保存/Ctrl+S | 保存当前正式TSCN的作者内容 | Godot原生保存与撤销拥有写入；不生成种子文件、不改游戏绑定 |
| 新建/关联参考 | 选择白盒，另存新场景或可撤销地修改参考关联 | 新建拒绝覆盖已有文件；是否运行采用由关卡模块决定 |

“文件唯一”指编辑入口与现行资源路径唯一，不表示每个拓扑节点都有独占文件。多个游戏实例可以引用同一正式文件；关卡种子仍由 `WORLD-PLAN` 选择骨架、房间与连接。门墙按本局连接装配，不将种子写进陈设资源身份。

### 固定陈设与运行所有权（r8）

来源：用户明确授权门墙归种子/装配，陈设固定由正式编辑器TSCN拥有。

| 内容 | 唯一所有者 | 运行时允许与禁止 |
|---|---|---|
| 门位、连接、门墙及其门状态 | 关卡结构契约与装配器 | 按本局合法连接装配；不借此改陈设 |
| 陈设实例（含历史 `Furn_*`）的节点、Transform、启用、碰撞引用/覆写及作者灯光 | 游戏实际引用的正式房间TSCN | 按原有父子变换实例化；禁止按名字、来源标记或主题配方删除/重建/重摆；空陈设保持空，不生成兜底 |
| 组件模型、材质、原点及组件自带碰撞定义 | 稳定共享Prefab | 沿资源引用更新，保留正式TSCN的实例覆写；不生成房间专用组件副本 |
| 陈设默认方案、全部合法门位前净空 | 制作阶段与工具校验 | 可用于新房初始化或审查候选，不是游戏运行时写入权 |

正式房间中保存的陈设必须避开**全部合法门位集合**的门前通行净空，不能只避开烘焙样本种子使用的门。合法门位及净空查询由共享结构契约提供，制作器、工坊校验和专项验收复用，不各自复制公式。发现陈设冲突时在制作阶段修正具体节点并复验，运行时不得挪动、隐藏或删除陈设以掩盖冲突。

当前共享只读查询位于 `src/world3d/RoomArtLayoutContract.gd`，复用 `RoomDoorLane.lane_offsets()` 和 `ManorFurnishing._door_boxes()`，按实际碰撞树/父链变换作SAT检测。工坊放置保护覆盖全部合法门位；工具保存/另存命令在发现冲突时拒绝写盘并报告对象与门位。此守卫仅覆盖插件命令，未接入的原生编辑器外部Ctrl+S等可绕过，不能称为引擎级强制保存门禁。

既有18份远征03正式资源如需调整，仅逐节点修改冲突陈设，保留其他作者摆位、引用、灯光和碰撞并记录差异；禁止整屋重烘焙覆盖现有文件。工具保存后，正式运行、房间流送重建及读档应保持陈设节点与局部Transform一致，运行态可破坏物件仍由其既有状态账恢复，不改玩法规则。

### TSCN统一范围与兼容

工坊打开的必须是游戏实际引用的同一正式文件，保存不得另造工具专用或种子专用副本。现行序列化契约为Godot文本PackedScene（`format=3`）与Node3D场景根，组件沿稳定Prefab实例引用，并兼容陈设、灯光以及身份/尺寸/来源元数据语义。58份正式文件的格式与引用审计结论见本轮开发记录，不能由格式一致外推分组/schema已完全相同。

分组名、旧schema和关卡玩法包装允许兼容；工具/装配适配现有正式资源，不为分组或格式外观重写远征01、02、99，不把它们复制成远征03风格的新文件。结构一致性须以逐文件审计为准；序列化格式统一不等于运行装配与分组完全相同。

## 失败与撤销

场景非 Node3D、缺少组件、模板无效、不可写或目标已存在时拒绝对应操作并显示原因。新建路径不得覆盖现存文件。切场景、禁用插件、Esc与失焦时结束或取消当前笔画，不能把跨场景操作放进同一撤销历史。编辑辅助、落点预览和白盒参考没有 scene owner，保存时不进入 PackedScene。组件实例仅设置顶层根 owner，不递归改写 Prefab 内部 owner。

## 接入与验收

入口：项目设置 → 插件 → ShellStorm Component Scene Builder；启用后右侧“场景工坊”（原组件拼装），默认占用完整右侧栏目。插件随项目启用，发行预设排除插件目录。

独立验收覆盖：真实目录可解析、凹轮廓裁切、笔刷插值、替换与重复检测、4096预算、Prefab实例存盘与重开、owner边界、辅助节点不入盘、灯光属性保留；编辑器验收覆盖插件启停、场景切换、笔刷输入与原生撤销。真实 GUI 核对面板与3D放置预览，不把纯数据测试算作画面验收。

历史记录见 [2026-10-29 组件场景编辑器](../development/2026-10-29_component_scene_editor.md)；r5工作台与加载流程见 [工作台重构记录](../development/2026-10-29_scene_builder_workbench.md)。


## 兼容与运行接入边界

r6的按种子采集链保留作历史排查工具，不再是正式打开列表的数据源；旧缓存不能覆盖r7的默认列表。历史正式场景及作者编辑保持原路径，工具升级不迁移、重命名或删除资产。旧UI检测到构建标记变化后重建，保留当前场景、画笔设置和原生撤销。

远征03现行运行资源键由 `RuntimeRoomArtSource` 拥有；工具读取同一契约，不复制门位、签名或原型算法。门墙仍可按本局端口装配；陈设与作者灯光按r8固定所有权保留。模板ID透传及旧资源结构兼容另行核查，不因修正陈设写入权顺带更改资源键。目录扫描和列表测试不能代替隔离运行、流送重建及读档验收。

原生保存沿用Godot编辑器与撤销历史，使用 `save_scene_as(path, false)` 跳过场景缩略图生成；工作台场景内Ctrl+S路由同一保存命令，脚本编辑及其他独占窗口保留原生快捷键。

r8在r7专项基础上另验：陈设改动在不同种子、流送重建和读档后保持；全部合法门位前净空；空陈设不生成；组件引用、作者灯光与碰撞不丢；58份正式文件结构审计及旧分组兼容。不得只核对 `manor_furnishing_rebuilt` 等由生成器自己写的metadata。

r7既有验收范围：正式路径唯一、旧门位候选和参考白盒排除、打开无需Python/种子、选择后发出同一正式路径、刷新与空结果、白盒新建/关联仍可用、打开/保存/重开以及旧UI重建。界面、输入和真实渲染分别验收；本轮证据与未执行项见 [唯一房间列表开发记录](../development/2026-11-01_scene_workshop_unique_rooms.md)。

本轮固定陈设实现、结构审计与验证记录见[远征03固定陈设开发记录](../development/2026-11-01_fixed_room_furnishing.md)，未执行项与状态以记录为准。

房间资源路径与文件SHA登记在场景账本《房间运行登记》，由 `ledger_index.json` 的场景域 `room_layout_sheet` 定位；不作为游戏读取的数据源。
