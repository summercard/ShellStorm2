## 1. 目标

包裹改为类似《三角洲行动》/《逃离塔科夫》的**整体棋盘式物品栏**：包裹不是“24 个彼此独立的一格物品槽”，而是一块有固定列数与容量面积的连续棋盘。每件物品有自己的矩形占格尺寸；例如步枪占 `4×2`，它必须覆盖棋盘上连续的 8 个格位。

装备栏不改造成棋盘。主武器、副武器、配件、背包和快捷栏仍是独立装备位；装备操作只判断 `type/subtype` 是否可装备，不读取物品的 `grid_size`，也不因为装备位尺寸不足而拒绝装备。

## 2. 核心概念

| 概念 | 规则 |
|---|---|
| 棋盘 | 默认 8 列×3 行；容量 `C` 表示棋盘总格数，行数 `ceil(C / 8)`；基础背包 `C=24`，装备背包提供扩展面积 |
| 物品锚点 | 物品保存一个线性 `slot` 作为左上锚点，旧存档和旧命令继续可读 |
| 占格尺寸 | 物品定义 `grid_size=[w,h]` 与 `grid_area=w×h`；字典数组保持 JSON 安全 |
| 旋转 | `grid_rotation=0/1/2/3`；奇数次旋转交换宽高；当前首版算法支持 90° 旋转判定 |
| 碰撞 | 物品矩形必须在棋盘边界内，且所有覆盖格为空；不允许重叠 |
| 堆叠 | 同 ID、非武器且未绑定实例的物品可堆叠；一个堆叠块只占一份矩形面积 |
| 整理 | 面积优先（大物品先放），再按类型/稀有度/名称稳定排序；每件物品重新寻找合法锚点 |
| 失败 | 找不到连续区域时拾取失败，地面物保留；不得静默删除或把物品塞进重叠区域 |

公式：

```text
rows = ceil(C / 8)
occupied(item) = {(x + dx, y + dy) | 0 <= dx < w, 0 <= dy < h}
placed(item) iff occupied(item) ⊆ board and occupied(item) ∩ occupied(other) = ∅
```

## 3. 物品占格尺寸首版表

尺寸真源：`src/base/ItemRegistry.gd::GRID_SIZES` 与族默认表 `GRID_SIZE_FAMILY_DEFAULTS`。初始化时尺寸写入物品字典，字段为：

```json
{"grid_size":[4,2],"grid_area":8}
```

| 物品类别 | 占格 | 说明 |
|---|---:|---|
| 手枪 | `2×1` | `weapon_pistol` |
| 普通长枪/霰弹/机枪 | `4×2` | 步枪、散射喷壶、蜂窝机枪、花洒机枪、初始步枪等 |
| 狙击枪/发射器 | `5×2` | 长枪优先保证明显占格体积 |
| 蓄力萝卜炮 | `3×2` | 特殊中型枪 |
| 近战棍/刀刃 | `3×1` | 棒球棍、工业断刃 |
| 攻城裂甲斧 | `2×2` | 近战重型件 |
| 轻型腰包/战术背包/远征背包 | `2×2` / `3×3` / `4×4` | 作为物品放入包裹时占格；装备后只增加容量 |
| 大型电池 | `2×1` | 其它电池为 `1×1` |
| 电芯包/撤离信标 | `2×2` | 高价值、非单格消耗品 |
| 药水/通用弹药/小电池/钥匙 | `1×1` | 可堆叠物优先保持紧凑 |
| 子弹模块 | `2×1` | `mod_bullet_*` 族默认 |
| 枪械蓝图 | `2×1` | `bp_*` 族默认 |
| 枪械配件/手电模块 | `1×1` | 装备位独立处理 |

未登记的新物品使用 `1×1` 兜底，并应在正式内容冻结前补入尺寸表。兜底只保证不崩，不代表该物品的最终设计尺寸。

## 4. 装备栏边界

装备栏继续使用现有独立槽位：

- 主武器 / 副武器：只接受 `type=weapon`。
- 枪械配件：只接受匹配 `subtype` 的 `type=attachment`。
- 背包装备槽：只接受 `type=equipment && subtype=backpack`。
- 快捷栏：只接受存在 `use_action` 的物品。

物品的 `grid_size` 不参与上述判断。装备一把 `4×2` 步枪不需要装备栏提供 8 个格；卸下时才需要在棋盘中找到合法连续区域，失败则回滚装备事务。

## 5. 运行时实现

- 数据定义：`ItemRegistry` 给全部 48 个现有物品补齐 `grid_size/grid_area`。
- 规则模块：`InventoryModule` 保留 `inventory_slots[]` 的旧快照形状，同时把 `slot`解释为棋盘锚点；提供 `can_place_item_at`、`find_valid_placement`、`get_occupied_grid_cells`、旋转和 JSON 快照恢复。
- 表现层：`InventoryUI/InventoryGrid` 改为整体 `GridInventoryBoard`，底层仍保留 `ItemSlot` 信号和索引契约；跨格物品用一个覆盖多个棋盘单元的视觉块呈现。
- 装备层：不改 `EquipmentTransactionService` 的可装备性事务；它不把棋盘尺寸复制成第二套装备规则。
- 存档：不另开背包存档文件；沿用 `runtime_player_state_v2.inventory_slots[]`。旧条目无 `grid_size/grid_rotation` 时由 `ItemRegistry`按 ID补齐，按旧 `slot` 优先恢复；不能原位容纳时自动寻找合法位置并保留实例/数量。

## 6. 拾取、移动、缩容

1. 地面物拾取前调用 `can_add_item_exact`，先检查堆叠余量，再检查矩形连续空间。
2. `add_item` 先合并已有堆叠，剩余数量按合法锚点依次放置。
3. 拖拽移动与交换先清理来源/目标做预检，任一物品无法在目标位置落下就整体回滚。
4. 换小背包或卸下背包时，按面积优先重排；无法容纳的完整物品条目返回地面生成事务，不能只丢掉“超出的格子”。
5. 保险柜仍是独立所有权集合，初始8×2棋盘，复用InventoryModule的几何与原子移动规则。

## 8. 双侧装备界面体验契约（r2）

来源：2026-10-15 用户参考图。视觉采用鸭科夫式深蓝半透明面板、灰白细描边、柔和圆角、浅蓝操作按钮、橙色焦点；不使用全屏科幻边框。左右面板之间保留可辨认的游戏画面，打开期间沿用模态输入锁。

- 左侧：角色全身预览居中，主/副武器及对应配件分列两侧，下方保留背包装备、快捷物品、生命与本局命运信息。未实现的防具显示未开放，不伪造可用槽。
- 右侧：独立显示物品件数和实际占用面积；连续八列棋盘，扩容后区域可滚动，保险柜固定在背包下方，中央游戏留白接受丢弃。1280×720 下中央至少保留 240px，1920×1080 不将面板拉满整个画面。
- 整件物品矩形均可点击、悬停和启动拖拽，不能只命中左上角。名称、数量、占格尺寸不抢占模型主体。悬停卡不得遮住当前物品。
- 拖拽以鼠标所在格作为目标左上锚点，绿/红矩形分别表示合法/冲突；R 旋转，Esc 取消，非法释放保留原位置、数量与旋转。中央游戏留白执行丢弃；面板内非法位置与屏幕边缘释放取消。
- 移动、同格旋转和交换的判定由 InventoryModule 统一提供，只读预检和实际提交使用同一规则。交换后的两个矩形也不能互相重叠。自动整理失败恢复完整快照。
- I 与关闭按钮退出；Esc 优先取消正在拖拽，其次关闭背包。打开期间焦点与鼠标不触发游戏攻击。

验收：保留规则专项，补充真实鼠标在大物品末格点击/拖动、旋转失败回滚、交换重叠拒绝、两种分辨率边界及真实渲染截图。手柄专项和完整远征存读档必须分别记录，不以鼠标专项替代。


## 2026-10-15 补充契约：八列棋盘与基地仓储

背包固定八列，基础24格（8×3），保险柜初始16格（8×2）；共同使用50px格子、跨格物品整块命中与占格校验。背包装备、快捷栏同为50px。两侧面板距屏幕上下各14px，中央保留游戏画面；中央有效拖放丢弃，面板内非法落点与Esc取消均保持原物品。只保留底部返回按钮。保险柜标题仅“保险柜”，删除未装备基础容量、拖入绑定和未开放提示。旧档装载若因几何改变放不下，保留全部物品并临时扩展行数，不静默丢弃。

保险柜规则仍由InsuranceModule负责，矩形占格复用InventoryModule；界面只发送移动/取出命令。基地仓库与贩卖机沿用深蓝半透明圆角、橙色选中、浅蓝操作按钮和两侧布局；交易失败保留原物品与资金，危险出售保留确认流程。
