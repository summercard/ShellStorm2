# 远征关卡03 设计

> **本关一句话：** 前两关的版图是「一张图、一条主路」，本关的版图是「**六张骨架，每局抽一张**」——
>   
> 房间怎么连由骨架决定，骨架本身随机，而每张骨架的房型配额**逐张对照《挺进地牢》第一层的实测数据**。

工程版本 0.1.0。本页是**远征关卡03 作为一张独立关卡的目标设计**：它应该长什么样、每局怎么变、变到什么程度为止。
  
当前实现事实与接口见[关卡生成与爬楼 §3.0](../05_技术施工_关卡生成与爬楼.md)；版图 schema 与门槽公式见[关卡版图白盒与生成规范](../05.2_关卡版图白盒与生成规范.md)；新关卡接入流程见[关卡接入规范](../关卡接入规范.md)。

> **文档归属 —— 本页是设计文档，不是账本文档。**
>
> - **归类**：`docs/v0.1/design/`（v0.1 目标规则主设计区，按关卡编号归类；见[设计区索引](README.md)）。
> - **主设计归属**：FeatureID **`WORLD-PLAN`**（关卡结构）与关联 **`ASSET-PIPELINE`**（房间资产生产）。
> - **资产事实的唯一权威是账本，不是本页。** 本关**不新增任何房型资产** —— 全部复用远征01 的 8 个已登记模板，见 §10。
> - **状态**：`runtime_enabled = false`。设计已冻结、设计源已落、配额门禁已通；**flow 模式生成器与关卡场景未施工**，本关暂不可从选关菜单进入。分阶段见 §8。

## 2. 玩法循环

```text
选关 → 读取界面
  → [生成期] 抽骨架 → 注入特殊房 → 切复合对象 → 拼装 → 总装
  → 入口安全房 15×15（唯一弃局门）
  → 内容房（NORMAL / HUB / CONNECTOR）**按本次抽中的骨架排布**
      · 每间内容房门后都是命运卡购买 ⇒ 构筑次数 = 本次骨架的内容房数
  → 宝箱房 ×2（REWARD，其中一间通常在单向环末端）
  → 商店 ×1
  → Boss 前整备房 → Boss 竞技场 50×40
  → 撤离房 25×25（常驻撤离信标）→ 撤离成功 → 结算
```

**与前两关的结构差异：**

|      | 远征01             | 远征02                   | **远征03（本关）**           |
| ---- | ---------------- | ---------------------- | ---------------------- |
| 版图来源 | 单份 L2 蓝图（13 房固定） | 单份 authored 蓝图（26 房固定） | **6 张 flow 骨架，按种子抽一张** |
| 每局差异 | 只有整房旋转/平移        | 无                      | **房间拓扑本身变**            |
| 房间数  | 13 固定            | 26 固定                  | **16 ~ 18，随骨架**        |
| 宝箱房  | 0（走容器搜索）         | 0                      | **2 间独立宝箱房**           |
| 商店房  | 无（走局内商人）         | 无                      | **1 间独立商店房**           |
| 环    | 无                | 无                      | **每张骨架 1 条单向回连边**      |

> **为什么要这一关：** 01/02 已经把「一条主路的单层关卡」做透了，但**每局重复度只靠旋转解决**。
>   
> 本关要验证的是另一条路线：**用少量手画骨架 + 受约束拼装，换取拓扑级的多样性**，
>   
> 同时把「宝箱要绕路」「商店要找到」这两条空间设计手段引进来。

## 3. 房型库（与《挺进地牢》一一对照）

### 3.1 房型映射表

本关**不发明新房型语义**，而是把《挺进地牢》第一层的 9 类房间节点，逐一映射到 ShellStorm2 已有的房型/内容类型上。
  
映射是**一对一**的：Gungeon 有几类，本关就有几类，不多不少。

| # | Gungeon 节点      | 本关 `kind`    | `room_type`       | `content_type` | `role`        | 是否刷怪  | 说明                   |
| - | --------------- | ------------ | ----------------- | -------------- | ------------- | ----- | -------------------- |
| 1 | `ENTRANCE` 起点   | `ENTRANCE`   | `SAFE_ROOM`       | `STAIR_LOBBY`  | `stair_entry` | 否     | 唯一弃局门                |
| 2 | `EXIT` 通往下一层    | `EXIT`       | `EXTRACTION_ROOM` | `EXTRACTION`   | `extraction`  | 否     | **本关映射为撤离房**（单层无下一层） |
| 3 | `BOSS`          | `BOSS`       | `BOSS_ROOM`       | `BOSS`         | `boss`        | 首领    | —                    |
| 4 | `Boss Foyer` 前厅 | `BOSS_FOYER` | `COMMON_ROOM`     | `EVENT`        | `boss_prep`   | 否     | 战前整备，不放钥匙锁           |
| 5 | `REWARD` 奖励房    | `REWARD`     | `COMMON_ROOM`     | `STORAGE`      | `main`        | **是** | 宝箱房；每张骨架恰好 2 间       |
| 6 | `SHOP` 商店       | `SHOP`       | `COMMON_ROOM`     | `EVENT`        | `main`        | 否     | 商人终端房；每张骨架恰好 1 间     |
| 7 | `NORMAL` 战斗房    | `NORMAL`     | `COMMON_ROOM`     | `COMBAT`       | `main`        | 是     | 数量随骨架 7~8 间          |
| 8 | `HUB` 枢纽房       | `HUB`        | `COMMON_ROOM`     | `COMBAT`       | `main`        | 是     | 多出口；骨架的分叉点           |
| 9 | `CONNECTOR` 连接房 | `CONNECTOR`  | `COMMON_ROOM`     | `TRAP`         | `main`        | 是     | 无专属敌人、常带环境危险         |

**三条映射裁决（改动需重开）：**

1. **`EXIT` → 撤离房，不是下行门。** 远征是单层，没有下一层。Gungeon 的 `EXIT` 是"本层结束、进入下一层"，
     
   本关把它落在"本层结束、结算离场"，语义位置一致、机制按远征口径。**不得**为对齐名字而新增下行门。
2. **`SHOP` 复用 `EVENT` 房型 + 商人终端。**

   <span style="color:rgb(248, 136, 37)">**[待施工]** `GameDesignConfig.ROOM_TYPES_WITH_HOSTILES` 里没有 `SHOP`，
     
   内容类型白名单也没有。本关**不新增内容类型**，改用非敌对的 `EVENT` 房承载商人终端；
     
   终端本体复用既有局内商人设施。若将来要独立的 `SHOP` 内容类型，必须先改 `GameDesignConfig` 白名单并同步 [05 §3.0](../05_技术施工_关卡生成与爬楼.md)。</span>
3. **`CONNECTOR` 用 `TRAP` 而不是 `EVENT`。** `TRAP` 在 `ROOM_TYPES_WITH_HOSTILES` 内，
     
   能带环境危险 + 少量敌人；`EVENT` 是非敌对房、要点终端才结算，语义不符。

### 3.2 房间规格总表（9 类，规格唯一）

**所有房间的尺寸只有这 9 行，没有第 10 种。** 模板全部来自远征01 已登记的 8 个（`bridge_60x50` 本关不使用）。

| `kind`       | 模板 `template_id`   | 尺寸 宽×深 (m)                    |   格数 |                    面积 m² |      门数（典型） |
| ------------ | ------------------ | ----------------------------- | ---: | -----------------------: | ----------: |
| `ENTRANCE`   | `safe_15x15`       | 15 × 15                       |  3×3 |                      225 | 2（前门 + 弃局门） |
| `EXIT`       | `extraction_25x25` | 25 × 25                       |  5×5 |                      625 |           1 |
| `BOSS`       | `boss_50x40`       | 50 × 40                       | 10×8 |                     2000 |           2 |
| `BOSS_FOYER` | `std_25x25`        | 25 × 25                       |  5×5 |                      625 |           2 |
| `REWARD`     | `db_70x50`         | 40 × 30                       |  8×6 |                     1200 | 2~3（环汇聚点 3） |
| `SHOP`       | `office_60x70`     | 30 × 40                       |  6×8 |                     1200 |           2 |
| `NORMAL`     | **4 选 1 池**（见下）    | 25×25 / 40×30 / 30×40 / 45×40 |    — | 625 / 1200 / 1200 / 1800 |           2 |
| `HUB`        | `corridor_45x40`   | 45 × 40                       |  9×8 |                     1800 |         3~4 |
| `CONNECTOR`  | `std_25x25`        | 25 × 25                       |  5×5 |                      625 |           2 |

**`NORMAL` 模板池（`content_template_pool`）：** `std_25x25`（625 m²）/ `db_70x50`（1200 m²）/
  
`office_60x70`（1200 m²）/ `corridor_45x40`（1800 m²）。
  
池子权重均等 ⇒ **同一张骨架，每局内容房的大小也不同**，但它不改变房间数量与拓扑。

### 3.3 房间数量公式（本关的预算式）

```text
N = 固定开销 + NORMAL + HUB + CONNECTOR
固定开销 = 入口1 + 撤离1 + Boss前厅1 + Boss1 + 宝箱房2 + 商店1 = 7
```

验算六张骨架（全部成立，误差 0）：

| 骨架        |  7 | NORMAL | HUB | CONNECTOR |      N | 与游戏实测 |
| --------- | -: | -----: | --: | --------: | -----: | ----- |
| `flow_01` |  7 |      7 |   2 |         0 | **16** | 16 ✓  |
| `flow_02` |  7 |      8 |   1 |         1 | **17** | 17 ✓  |
| `flow_03` |  7 |      7 |   2 |         1 | **17** | 17 ✓  |
| `flow_04` |  7 |      8 |   2 |         0 | **17** | 17 ✓  |
| `flow_05` |  7 |      7 |   1 |         2 | **17** | 17 ✓  |
| `flow_06` |  7 |      8 |   2 |         1 | **18** | 18 ✓  |

**合计 102 间，平均 17.0 间/局** —— 与《挺进地牢》第一层的 6 张 flow 完全一致（16/17/17/17/17/18，均值 17.0）。

> 这条公式是**本关唯一允许的难度旋钮**：想让某张骨架更难，只加 `NORMAL`，不动固定开销。
>   
> 固定开销是「保底内容」（一定有 Boss、一定有 2 个宝箱、一定有商店），改它等于改关卡承诺。

### 3.4 面积区间（不是准入判据）

面积只报数、不设上限（与 01/02 同口径，见 [05.2 §3.7](../05.2_关卡版图白盒与生成规范.md)）。

```text
A = Σ(固定开销房面积) + Σ(NORMAL 面积),  NORMAL ∈ {625, 1200, 1200, 1800}
```

| 骨架        | 固定开销面积 | NORMAL 间数 | 面积区间 m²       |
| --------- | -----: | --------: | ------------- |
| `flow_01` |  10675 |         7 | 15050 ~ 23275 |
| `flow_02` |   9500 |         8 | 14500 ~ 23900 |
| `flow_03` |  11300 |         7 | 15675 ~ 23900 |
| `flow_04` |  10675 |         8 | 15675 ~ 25075 |
| `flow_05` |  10125 |         7 | 14500 ~ 22725 |
| `flow_06` |  11300 |         8 | 16300 ~ 25700 |

**全关区间 14500 ~ 25700 m²，中位数约 19.6k m²。** 对照远征01 的 13 房 ≈ 16675 m²，
  
本关单局面积略大但房间更碎 —— 这是「同面积换更多节点」的必然结果，不是超标。

## 4. 六张骨架

### 4.1 骨架清单

| `flow_id` | 名称       | 设计特征                | 房间 | NORMAL | 环                 |
| --------- | -------- | ------------------- | -: | -----: | ----------------- |
| `flow_01` | 基础版      | 中心双路环 + 宝箱汇聚点       | 16 |      7 | `n06 → reward_02` |
| `flow_02` | 双翼       | 单枢纽扇出两条长翼，中段闭环      | 17 |      8 | `n03 → n07`       |
| `flow_03` | 双路通 Boss | 中段分叉，两条路都通向 Boss 前厅 | 17 |      7 | `n06 → hub_02`    |
| `flow_04` | 四小翼      | 单枢纽扇出四条短支路          | 17 |      8 | `n04 → hub_02`    |
| `flow_05` | 快 Boss   | 主线极短、Boss 提前，两条危险支链 | 17 |      7 | `n05 → n06`       |
| `flow_06` | 标准变体     | 两路汇聚，一条危险死路         | 18 |      8 | `n04 → n06`       |

**六张骨架覆盖了 Gungeon 第一层的全部形态**：`flow_01`≈Flow_01、`flow_02`≈TwoBigWings、
  
`flow_03`≈TwoPathsToBoss、`flow_04`≈FourSmallWings、`flow_05`≈QuickBoss、`flow_06`≈StandardVariant。
  
名称与配额来源见 §11.3。

### 4.2 单张骨架的读法（以 `flow_01` 为例）

```text
entry ── n01 ── hub_01 ─┬─ n02 ── reward_01                     （支链：宝箱在死路尽头）
                        ├─ n03 ── n04 ──┐
                        ├─ n05 ── n06 ──┴─ reward_02            （两路在此汇聚 ⇒ 单向环）
                        │                  │
                        │                  └─ hub_02 ── n07 ── shop ── boss_foyer ── boss ── exit
                        └─（hub_01 共 4 条出边：n02 / n03 / n05）
```

- **树边 15 条 + 回连边 1 条 = 16 条边，16 间房**（树边恒等于 `N − 1`）。
- **`reward_02` 是环的汇聚点**：从 `hub_01` 出发有两条路都能到它，但两条都是有向的，
    
  玩家**必须绕一整圈**才能离开 —— 这正是 Gungeon「宝箱藏在单向环末端」的手法，
    
  且**不多花一间房、不多建一条走廊**。
- `hub_01` 有 4 条出边 ⇒ 它必须是 `HUB` 房型（45×40，多门位），不能退化成 `std_25x25`。

> 每张骨架的**完整节点清单（102 行）**&#x89C1;本页**附录 A**，逐行列 `node_id / kind / 模板 / 尺寸 / 父房`。

### 4.3 环的表达方式

本关采用 Gungeon 的两层拓扑：

| 层 | 字段                            | 谁读它                         | 现状                                                             |
| - | ----------------------------- | --------------------------- | -------------------------------------------------------------- |
| 树 | `parent_key` / `tree_edges[]` | 现有 `FloorPlanGenerator` 摆位器 | **已支持**                                                        |
| 环 | `loop_edges[]`                | 目标：装配层建门                    | <span style="color:rgb(248, 136, 37)">**待施工**，见 §8 阶段 B</span> |

**回连边的三条硬约束**（违反即拒绝生成，不靠人工审）：

1. **不得成为某个节点的唯一入口。** 回连边的终点必须已有树父房（`check_expedition03_flow_quotas.py` 已断言）。
2. **不得跳过 Boss 前厅或 Boss 房。** 回连边两端必须都在 `boss_foyer` 之前，或都在之后。
3. **必须可几何闭合成环。** 拼装期若两端房间不相邻（无法共用墙或无法铺 ≤30m 走廊），
     
   该回连边**丢弃并记 `closure_skipped`**，不得为它强行挪房或拉超长走廊。
     
   丢弃只影响"能不能绕近路"，不影响房间数与主线可达性。

## 5. 生成管线（五段，全部用于本关）

| 段         | 做什么                             | 随机？ | 本关参数                              |
| --------- | ------------------------------- | --- | --------------------------------- |
| 1 抽骨架     | 从 6 张 flow 里等概率抽一张              | ★   | `hash(run_seed, level_id, 0) % 6` |
| 2 变换 + 注入 | 替代链 / 支路二选一 / **注入特殊房** / 选房间模板 | ★★  | 见 §5.1、§6                         |
| 3 切复合对象   | 找最小环切出，剩下是树                     | —   | 每张骨架 1 个环复合对象 + 若干树               |
| 4 分别拼装    | 树 DFS 回溯、环两端往中间合                | 半随机 | 复用现有 `_place_recursive`           |
| 5 总装      | 从连接最多的房间出发拼回整图                  | 半随机 | 环复合对象优先（最紧）                       |

### 5.1 第 2 段的四个操作在本关的取值

| 操作                       | 本关取值                      | 理由                                               |
| ------------------------ | ------------------------- | ------------------------------------------------ |
| **替代链**（把 1 个节点换成 2~3 间） | **关闭**（`expand_rooms: 0`） | Gungeon 只在后期大层用；本关若开启会破坏 §3.3 的配额恒等式，与"一一对照"直接冲突 |
| **支路二选一**                | **关闭**                    | 全游戏只用两次，本关不在其中                                   |
| **注入特殊房**                | **开启**，3 条规则              | 见 §6                                             |
| **选房间模板**                | **开启**，`NORMAL` 从 4 池等权抽  | 这是本关"同骨架不同手感"的来源                                 |

> ⚠️ **替代链与配额是一对矛盾。** 若将来要在本关开启替代链，必须先改 §3.3 的公式，
>   
> 并把 `check_expedition03_flow_quotas.py` 的参照表改成区间而不是定值 —— 那是重新冻结，不是微调。

## 6. 注入规则

注入 = 在骨架已经定下来、但还没有坐标的时候，按 `{类型, 锚点, 概率, 条件}` 往图上插节点。
  
**它只加节点、不改树的边**，所以不影响 §3.3 的房型配额计算基准。

### 6.1 三条规则（本关启用）

| `inject_id`           | 类型        | 锚点                     |                  概率 | 作用域      | 条件 |
| --------------------- | --------- | ---------------------- | ------------------: | -------- | -- |
| `inj_secret_room`     | 普通隐藏房     | **死胡同优先**；1/5 概率挂到任意房间 |             **0.9** | 每层共享     | 无  |
| `inj_npc_secret_room` | NPC 隐藏房   | **开局预抽**（run 级）        | 0.2（`EMPTY` 权重 0.8） | **整局一次** | 无  |
| `inj_fireplace`       | 壁炉房（藏层入口） | 死胡同优先                  |                 1.0 | 每层共享     | 无  |

### 6.2 两条来自 Gungeon 的关键机制

**① 隐藏房分两套抽，互不占用。**
  
普通隐藏房每层独立掷 90%；NPC 隐藏房**整局开局抽一次**、预留给将来某一层，`EMPTY` 权重 0.8。
  
结果：不会出现"五层连着都没刷到"的极端局，也不会一层堆两个。**本关单层，所以 `run` 级规则退化为一次掷骰。**

**② 概率与锚点的分工。**
  
概率回答"有没有"，锚点回答"挂在哪"。死胡同优先这条**同时**解释了 Gungeon 的
  
「壁炉房通常在死胡同」和「隐藏房通常在死胡同」—— 它们是同一套落点偏好的两个消费方。

### 6.3 本关的锚点定义

| 锚点                  | 定义          | 可用房型                           |
| ------------------- | ----------- | ------------------------------ |
| `dead_end`          | 出边数 = 0 的节点 | 任何 `main` 房                    |
| `any_room`          | 任意节点        | 除 `ENTRANCE` / `EXIT` / `BOSS` |
| `run_level_preroll` | 开局抽定，不随层    | 见 ①                            |

### 6.4 注入房**不计入** §3.3 的配额


隐藏房与壁炉房是**附加**节点，不在 `room_quota` 里，也不进 `flow_*.json` 的 `nodes[]`。
  
它们的数量期望是：每层 `0.9 + 0.2 + 1.0 ≈ 2.1` 间（含 NPC 隐藏房的整局摊薄）。
  
⇒ **实际单局房间数 = 16~~18（骨架）+ 0~~3（注入）**。文档与验收断言都必须写这个区间，不要写死 16~18。

## 7. 随机性边界（写清楚"什么变、什么不变"）

### 7.1 每局会变

| # | 随机项             | 自由度               | 约束                        |
| - | --------------- | ----------------- | ------------------------- |
| 1 | 抽哪张骨架           | 6 选 1             | 等概率                       |
| 2 | `NORMAL` 用哪个模板  | 4 选 1             | 只改大小，不改数量与拓扑              |
| 3 | 整房摆位与朝向         | 平移 + 0/90/180/270 | 保持端口世界坐标重合、朝外方向相反         |
| 4 | 环能不能闭合          | 能 / 丢弃            | 丢弃记 `closure_skipped`，不挪房 |
| 5 | 隐藏房 / 壁炉房有没有、挂哪 | 0~3 间             | 见 §6                      |
| 6 | 内容类型在池内分配       | 见池                | `content_type_pool`       |

### 7.2 每局不变（硬约束）

| 项目         | 值                                                |
| ---------- | ------------------------------------------------ |
| 固定开销       | 入口1 + 撤离1 + Boss前厅1 + Boss1 + 宝箱房2 + 商店1 = **7** |
| 每张骨架的房型多重集 | 见 §3.3 表，**逐张定值**                                |
| 房间尺寸       | 只有 §3.2 那 9 行，无第 10 种                            |
| 主路可达性      | 入口 → 撤离恒通，且**必过 Boss 前厅与 Boss**                  |
| Boss 唯一性   | 每局 1 个 Boss，不可被任何支路或回连边绕过                        |
| 宝箱房数量      | 恒 2 间（可能在环上、可能是死路尽头）                             |
| 商店数量       | 恒 1 间                                            |
| 层数         | 单层，无下行楼梯、无电梯                                     |

### 7.3 确定性复现

```text
layout_id = hash(run_seed + level_id + floor_rule_version + flow_id)
flow_id   = hash(run_seed, level_id, 0) % 6
```

同一 `run_seed` 必须复现**完全相同的骨架、模板、坐标与注入结果**。
  
`layout_id` **包含 `flow_id`** —— 否则两张不同骨架会撞同一个存档指纹（01/02 是单骨架，没有这个问题）。
