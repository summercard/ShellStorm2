# 时间日夜与画质｜功能设计 v0.1

功能ID：`TIME-DAYNIGHT`、`GRAPHICS-POSTFX`。工程版本：`0.1.0`；设计修订：r1（2026-09-24）。两功能各自独立，放在同页只因都影响画面；[15 时间技术施工](../15_技术施工_时间日夜与基地能源.md)、[13.1 画质技术施工](../13.1_技术施工_画质设置与后处理.md)分别维护实现细节。

## 时间、日夜：玩家目标与规则

**[用户修订｜2026-10-12]** 新存档从`2075-01-01 09:00`开始；旧存档保留原17:00起点与累计进度，20真实分钟对应24游戏小时；暂停默认不走时，不按设备墙钟补离线进度。日出06:00、日落20:00；太阳东升西落，清晨偏橙、正午偏白、黄昏偏红，正午亮度峰值1.0，夜间为0。HUD在雷达下显示同一权威时间。基地能源每游戏小时恢复4点，但能源容量、消费和恢复舱规则由[电力系统](../15.1_技术施工_电力系统.md)拥有，不能由画质系统改变。

长期档保存世界时间起点；缺少该字段的旧档按2075-01-01 17:00解释，新档写09:00起点。能源只按累计游戏秒计算，兼容处理不增加离线收益。

`GameTimeManager`写累计游戏秒，`WorldTimeDomain`纯计算日期/太阳，太阳、HUD、基地能源只读同一快照。时间写盘失败不等于已落档；重启从最后有效时间恢复，不产生离线收益。未来天气/周期设施接只读时间，不自建第二个时钟。验收覆盖起始时间、暂停/倍速、日出日落、能源同步、写盘失败/跨重启与真实渲染。当前强制写盘失败的跨重启专项和太阳真渲染**未完成**；见技术施工。

## 画质、后处理：玩家目标与规则

**[现行设计边界]** 玩家画质选项用于调整正式画面质量/性能，不改变命中、敌人、能源或存档数值；跨场景与重启保持已确认的选择。画质设置与游戏进度档分开。`GraphicsSettingsManager`拥有正式选项；`PostfxOverlay`拥有全屏颗粒/色相的运行表现；P键调参页目前是**开发调试工具**，并非已批准的正式玩家设置页。调试覆盖和调试JSON不可默认为玩家配置或进入`BaseData`。

**[用户表现规则｜2026-09-29]** 99F 基地的两项环境雾浓度按玩家是否位于基地建筑壳体内连续变化。基地外维持全塔既有值：距离雾 `0.030`、体积雾 `0.009`；基地内默认降低为距离雾 `0.012`、体积雾 `0.0035`。底层西门、底层东门和上层东侧天台门使用同一座 30×30m 建筑体积判定，不为每扇门复制触发器；正常步行跨越壳体时约 1.65 秒收敛至目标值，出生与传送落位可立即同步，避免先显示错误环境。P 键调试工具第三页“基地雾气”可实时修改两项室内值，停止拖动 0.4 秒后自动写入 `user://postfx_tuning.json`，下次启动自动恢复；基地外值不受该页影响。画质开关仍可整体禁用相应雾效，切换画质不得把室内值闪回室外值。

**[待设计裁决]** 哪些调参值要成为正式玩家选项、预设档的具体视觉阈值、调参入口是否随发布保留，尚无用户冻结设计；未来不能仅因当前代码能调就升格。若转正，应先补玩家可见控制、可访问性、默认/重置、保存成功/失败回执与设备性能标准，再修改代码。当前 cfg 与调参JSON写盘都缺明确对外结果，不能提示“已保存”。

## 命令、数据、失败与验收

正式画质配置写`user://graphics_settings.cfg`，调试参数另存`user://postfx_tuning.json`；具体键与schema见技术施工。未知键、坏值、坏文件应拒绝或回退到安全默认且可诊断；未能写盘时运行值与持久值应被明确区分。验收入口：`verify_main_entry_realtime_sun_flow`、`verify_graphics_settings_ui_flow`、`verify_postfx_overlay_runtime`、`verify_postfx_autopersist`；正式画面、HUD/UI隔离、目标GPU与性能预算必须用真实渲染/设备证据，不能由headless断言代签。

## 战败画面过渡（RUN-SETTLE / GRAPHICS-POSTFX r2）

**[用户设计｜2026-11-02]** 致命受击后先播放约2秒蓝白信号干扰，渐变为饱和度系数0.50、对比度系数1.20的战败画面；完成滤镜过渡且倒地动作结束后才出现原结算UI与返回按钮。二者从死亡并行开始，不在倒地之后再额外等待2秒。低血量红色晕影在死亡时退场；蓝白扫描带、短促水平撕裂及细噪点逐渐消退，最终只保留调色；UI与按钮在滤镜之上保持原色清晰。

`Dungeon3D`拥有死亡流程门闩（倒地完成、滤镜完成、行动代际）；场景内`DefeatTransition`唯一拥有2秒时钟与Shader参数，输出一次`finished()`。`PostfxOverlay`仍只拥有既有调参效果，不修改玩家持久画质。过渡期间返回命令拒绝；重复死亡通知不重播、不重复开框。旧行动已被成功撤离覆盖时不得弹阵亡结算；新行动复位或场景卸载清除滤镜与回调。最终色彩相对当前渲染图做亮度混合与围绕0.5的对比变换，不更改存档、保险、奖励、死亡规则和事务幂等。

正式入口覆盖塔楼与继承`Dungeon3D`的远征场景；独立入口`verify_player_camera_defeat_feedback`，结算回归`verify_death_during_extraction_flow`、`verify_run_settlement_transaction`；需真实渲染验证0/0.5/1/2秒画面、滤镜最终像素、HUD分层与按钮延迟。
