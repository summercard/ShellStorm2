# 玩法设计｜战败归航救援与绿苔台词

FeatureID：`BASE-RESCUE`；工程版本 `0.2`；设计修订 r2（2026-11-08）；
来源：<span style="color:#1565C0">**[用户设计]**</span> 主人原话——

> 当我在远征关卡被击败后，我回到 99F 基地的时候，（会进入一个短暂的剧情）是趴着的状态，然后我基地里不是有个绿色的 NPC 吗？会站在我边上，对着我说：『啧啧，太危险了，看我把你捞回来了。感谢我吧，我还帮你捞回了点东西，下次去可要小心了。』分两句说，说完玩家跳起来，可以操作。出现的时候它的边上会放着一个箱子（拿现在的宝箱，做成浅灰色的）。这个宝箱打开后会掉落随机 1-2 个你在上个战局内的物品（包括装备和包裹的，不包含保险箱里的），然后 1-2 个随机的补给物品，可以是血瓶、弹药、手雷、电池。打开后过 10 秒宝箱会消失，消失的特效使用收租人的消失特效。

r2 追加（同日）「对话可以多做几套」，并给出连败台词与随机池，见 §3。

r3（同日，二次澄清）「对话并不是一定要出现『啧啧，太危险了……』这句，这句也是随机出现的选择，不是固定的两句」
⇒ **没有固定台词**：每次归航从候选段里随机挑一整段播，讲几句就播几句。同时补一句硬要求
「这个时候需要玩家无法操作，鼠标旋转也不行」，见 §2.1。

状态：<span style="color:#EF6C00">**[部分完成]**</span> 逻辑链与 headless 专项已通过；真实渲染对照、玩家相机下的气泡观感尚未出图，见 §6。

技术契约：[20 技术施工·基地NPC §14](../20_技术施工_基地NPC.md)；存档字段登记见 [09 §4](../09_技术施工_存档结算与复活.md)。

## 1. 目标

远征阵亡不是「黑屏回基地、东西没了」，而是**被绿苔捞回来**：一段几秒的短演出把损失说清楚，再用一只浅灰箱子把「他还帮你捞回了点什么」兑现。

四件事必须在同一段体验里成立：

| # | 玩家看到 | 规则 |
|---|---|---|
| 1 | 自己趴在地上，绿苔站在旁边 | 归航瞬间锁操作，表现钉在倒地终点帧 |
| 2 | 绿苔说一段（每段 1–2 句，**随机挑**） | 逐句气泡，说完自己起身 |
| 3 | 起身后能立刻操作 | 演出结束即交还全部输入 |
| 4 | 边上摆着一只浅灰宝箱 | 开箱掉「上局物品 1–2 件 + 补给 1–2 件」，10 秒后消失 |

## 2.1 演出期间玩家完全不能操作

业主 r3 口径：「这个时候需要玩家无法操作，鼠标旋转也不行，这个就是剧情过程」。

| 维度 | 处理 |
|---|---|
| 移动 / 翻滚 / 开火 / 交互 | `input_locked`（既有）＋ 每帧把水平位置钉回归航点、清掉水平速度 |
| 鼠标转身 / 准星 | `Player3D.aim_locked`（新增）—— 既有 `input_locked` **按设计不拦瞄准**，那是给剧本 `actor.face` 留的口子 |
| 玩法按键（换枪、快捷物品、大地图、K 展示面板） | `Dungeon3D._unhandled_input` 在演出期间整段返回 |
| 背包（键盘 I / 点 HUD 头像） | `InventoryUI` 与 HUD 点击都用 `is_control_fully_locked()` 挡掉 |
| ESC / 暂停 | **不挡**：万一演出卡住，玩家仍能呼出菜单 |

台词是**逐字显示**的（打字机，30 字/秒，与底栏同速）：一句 26 字约 0.9 秒打完，打完再停留 3.2 秒。
演出期间输入被锁，所以没有"按键跳过"这条路——玩家看完整句。
| 起身之后 | 两个锁一起放开，实测按键能立刻走动（验收 R14b） |

## 2. 触发条件

| 条件 | 说明 |
|---|---|
| 只有**远征关卡**阵亡 | 塔楼（98F/100F/99F 内部）死亡不演；塔楼没有「上一局携带物」这个概念 |
| 必须走**死亡归航**入口 | 入口原因 = `death_return_99f`。冷启动、普通返航、续档不重演（东西照给） |
| 有救援暂存才演 | 结算时抽出来的那份清单为空 ⇒ 只放箱子不放戏（例如空手进图送死） |

**不重演但照给**：玩家开箱前退过游戏、这次是普通启动 → 跳过趴地与台词，只把箱子摆出来。
理由：演出是「刚才发生的事」的补叙，重启后不该假装刚死一次；但那份捞回来的东西必须还在。

## 3. 台词（内容全部在 `NpcCatalog`，代码里没有字面量）

### 3.1 没有"固定台词"

每次战败归航从候选段里**随机挑一整段**，那段讲几句就播几句。四段候选：

| # | 内容 | 句数 |
|---|---|---|
| 1 | 「啧啧，太危险了，看我把你捞回来了。」／「感谢我吧，我还帮你捞回了点东西，下次去可要小心了。」 | 2 |
| 2 | 「别泄气，这点小问题难不住你。」 | 1 |
| 3 | 「世上无难事，只要肯攀登，以前一个很伟大的人说的。」 | 1 |
| 4 | 「这次还不错，零件一个没少。」 | 1 |

第 1 段只是候选之一，**不是必说的开场白**（业主 r3 明确）。

### 3.2 连败专属段（优先于随机）

「连续战败」= 远征阵亡连续次数，成功撤离清零，塔楼死亡不改变。命中下表时**只播专属段**，不再叠随机段。

| 连败次数 | 专属段 | 语气 |
|---|---|---|
| 2 | ①「看见那只僵尸了吗？接下来换你咬它了！」②「但是你首先得先长上牙齿，啧啧。」 | 打趣 |
| 3 | 「…………，你……」 | 无语 |
| 1 / ≥ 4 | 走 §3.1 的随机候选 | 安慰 |

**为什么第 1 段拆成两个气泡**：整段 47 字在气泡的两行口径下会排到五行、顶出画面上缘（与 20 号文档 §13.6 同一条约束）。拆开后每句都在两行内，观感仍是「一口气说两句」。

## 4. 救援箱

| 项 | 规则 |
|---|---|
| 外观 | 现有普通宝箱模型，身板与箱边**平涂浅灰**（摘掉色盘贴图，不是把木色压暗）；内部发光面跟冷白，不带品质橙光 |
| 内容 | 由上局死亡结算那一刻抽出：**本局物品 1–2 件**（背包 + 双手武器 + 背上背包，**不含保险格**）＋ **补给 1–2 件** |
| 补给池 | 治疗药水 / 通用弹药 ×20 / 小电池 / 手雷（都是正式物品 ID，不新增内容） |
| 抽取方式 | 独立随机流（种子 = 本局种子），同种子同结果；同一实例不重复抽到 |
| 武器口径 | **原来那把**（业主 2026-11-09）：枪按实例整体归还 —— `weapon_instance_id`、星命运刻印 `fate_upgrades`、装配快照 `assembly_snapshot` 全部原样带出；不是"同型号新枪"。装备槽是运行态权威，背包里若有同实例的旧字典，以装备槽那份为准 |
| 开箱 | 完全复用普通宝箱链（抖动 → 蓄力 → 砰 → 落地 → 房间账），只是奖励来源换成清单 |
| 消失 | 开箱后 **10 秒**，用 `VFX-TELEPORT-OUT-3D`（收租人撤退同一件）收走，碰撞与交互同时失效 |
| 箱子位置 | 绿苔旁边（离归航点约 2.5m、离绿苔约 1m 的走道空位） |

**为什么保险格里的不算「捞回来」**：保险柜本来就是「必定保住」的那一份，再捞一次等于同一件东西给两遍；而且业主原话明确「不包含保险箱里的」。

**为什么不给第二个状态所有者**：清单在死亡结算事务里写盘（`BaseData.rescue_cache`），开箱那一刻清空。演出、箱子、台词都只是读它。

## 5. 失败与边界

| 情形 | 行为 |
|---|---|
| 上局什么都没带（空手进图） | 清单里只剩补给 1–2 件，戏照演（他确实捞了补给） |
| 背包 + 装备全在保险格 | 只剩补给；箱子里不会有「物品」档 |
| 箱子位置算不出合法落点 | 不把东西塞回箱心；该件留在待补发账里，下次进房补 |
| 开箱前退出游戏 | 重启后不再演，箱子还在原地；清单不丢 |
| 暂存清空写盘失败 | 内存已清（本次不再发），磁盘仍是旧的 ⇒ 重启可能再给一箱，留 warning |
| 演出中途切场景 | `_exit_tree` 归还输入独占（含鼠标锁），不会把玩家永久钉住 |
| 血量在锁之后被回填 | `set_input_locked()` 在 `hp<=0` 时静默不生效 ⇒ 演出方**逐帧**兜底重锁 |
| 候选段池为空 | 跳过说话直接起身（不因为有内容缺就把人钉在演出里） |
| 台词内容缺失 | 跳过说话直接起身（不因为有内容缺就卡流程） |

## 6. 明确不做

- 不给绿苔加救援/任务面板、不记「救过你几次」的历史（连败计数只做语气，不做成就）
- 不做「用钱换回更多物品」的讨价还价
- 不做箱子里的物品在基地直接可用（仍走正常拾取 → 背包）
- 真实渲染对照（玩家相机下的趴姿、气泡间隙、浅灰箱上色）尚未出图，列为本功能待补验收
