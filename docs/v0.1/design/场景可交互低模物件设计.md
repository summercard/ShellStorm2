# 场景可交互低模物件设计

FeatureID：WORLD-INTERACTIVE-CLUTTER / ASSET-PIPELINE；工程版本：0.1.0；设计修订：r4（2026-10-29 二次修订）。来源：用户指定的五类新组件；状态：**已制作、已接入入口安全房与远征03 随机布置、已按业主反馈放大并重做碎片、已通过运行验收**。

## 目标与范围

罐子、书本堆、花瓶、椅子、木箱各一个独立组件，归入场景交互物件，不属于可拾取道具或大型可破墙。每件导出后不超过 100 三角面、最大边不超过 1 米。完整或破碎状态均不阻挡角色或子弹移动；子弹或角色接触使物件破碎，碎片沿输入方向飞散，落地后保留。

本批不改变枪械、敌人、掉落、房间生成、门、导航或存档规则。不替换既有书本、座椅、大型木箱等资产。

## Owner、输入与状态

- 几何、材质、米制尺寸、底部中心原点：Blender 原始源及独立优化源。
- 完整模型、受击体、角色接触区、破碎反馈和落地碎片：各稳定 PackedScene；共用 `BreakableClutter3D.gd` 状态机。
- 子弹沿现有 `Projectile3D` 命中 `StaticBody3D.take_damage()`，方向取子弹真实飞行向量。受击体只在层值 4；玩家移动只检测层值 1，因此完整物件不会造成移动阻挡。
- 角色由 mask=1 的 Area3D 检测。方向优先取角色接触时的水平速度，静止或数据无效时取从角色指向物件的方向。
- 物件只接受首次有效触发，重复受击与接触幂等。方向无效时使用局部 `-Z`，不得因此产生异常或第六块碎片。
- 房间持有本次实例的细节运行时状态。流送卸载后重建，以稳定组件 ID 恢复为已落地破碎态，不重复播放动画。重新开局、重载场景、读档不扩展本批持久化语义。

## 反馈与残留

1. 完整模型先进行短促缩放/倾斜脉冲，再在约 0.065 秒内退出。
2. 同一套方向破碎动画适用于五个组件：最多五块低模几何碎片沿触发水平方向散开，具有竖直初速度、重力、短促落地缓震及放平动作，约 0.65 秒后停止。
3. 五块是物件碎片，不额外创建粒子发射器、灯光或其他颗粒。碎片不带碰撞，不进入定时回收池。
4. 残留相对组件原点所在的走行面落地，不读取世界 `y=0`；离开房间后仍保持已破碎记录。
5. 缺少视觉资源时保留受击体但不伪造美术完成；无效实例ID不登记状态，正常资源加载失败须记录测试错误。

### 验收发现的三个真实故障（已修）

1. **`process_mode` 未激活时受击体不进物理空间**：`set_stream_state(ACTIVE)` 才会把房间从 `DISABLED` 恢复，直接 `new()` 出来的房间受击体 `body_space = RID(0)`，子弹穿身而过。测试必须走正式流送入口，不能自建捷径。
2. **碎片初版是「刀片带」**：横向散布 0.86m、厚度 1.8cm，五块连成一条比本体还宽的长条。现改为受包络约束的凸块。
3. **房间截图曾全黑**：验收场景没有 `WorldEnvironment`，房间顶灯在无环境光时不足以成像。补环境后同时断言亮度分桶，避免「存了一张全黑图」当通过。

## 随机布置（2026-10-29，r3）

除了入口安全房那五件固定摆位，本批物件还能按**能力段**随机撒进任意关卡房间。

**不是关卡分支**：`level_plan.json` 顶层写 `interactive_clutter` 段，房间就撒点；代码里没有 `expedition_03` 这类字符串。
`check_level_decoupling.py` 巡检 7 个通用机制容器，`violations=0`。

数据流三段，缺一段就静默失效（这是本项目踩过的老坑，所以每段都留了断言）：

```text
level_plan.json  interactive_clutter
  → FloorPlanGenerator  plan["interactive_clutter"]（顶层透传，不进 canonical，不影响 layout_id）
  → TowerDescent3D._append_plan_room_record  record["interactive_clutter"]（按 exclude_room_types 过滤）
  → DungeonRoom3D.configure  interactive_clutter_plan → _build_random_interactive_clutter()
```

| 参数 | 语义 | 远征03 取值 |
|---|---|---|
| `enabled` | 总开关 | true |
| `per_room_min/max` | 每房件数 | 3 / 6 |
| `exclude_room_types` | 不撒的房间类型 | `STAIR_LOBBY`、`BOSS` |
| `min_room_size_m` | 短边小于此值直接跳过 | 8.0 |
| `wall_margin_m` | 离墙留边 | 0.9 |
| `door_clearance_m` | 离门/端口净空 | 2.4 |
| `min_spacing_m` | 彼此最小间距 | 1.1 |

三条实现口径值得记住：

1. **布置必须在 `_build_content()` 末尾执行**（家具、服务点、危害区都落位之后），否则读不到障碍物，会把罐子塞进机柜里。
2. **种子只用 `room_seed` 派生**：`hash([room_seed, "interactive_clutter", room_id])`，不碰玩法随机流，也不受卸载重建影响。
3. **太小的房显式跳过，不靠过滤碰巧归零**：5×5 十字路口四面都是门，门净空会把候选点全清空 —— 那看起来和「没配置」一模一样，属于不可解释行为。

## r4 修订：放大与破碎重做（2026-10-29）

业主反馈两件事：**动画不够明显**（散落范围小、不够高、力道不足），**物件整体太小**。

### 尺寸（v001 → v002）

按业主逐件指定比例整件放大，**纯统一缩放，拓扑与三角面完全不变**：

| 组件 | 比例 | v001 包络(m) | v002 包络(m) | 三角面 |
|---|---|---|---|---|
| 罐子 | **+50%** | 0.44×0.43×0.54 | 0.66×0.65×0.81 | 96 |
| 书本堆 | 不变 | 0.64×0.50×0.31 | 不变 | 84 |
| 花瓶 | 不变（未提及） | 0.43×0.43×0.73 | 不变 | 92 |
| 椅子 | **+50%** | 0.50×0.50×0.86 | 0.75×0.75×**1.29** | 96 |
| 木箱 | **+30%** | 0.65×0.69×0.68 | 0.84×0.90×0.88 | 98 |

🔴 **椅子 1.29m 已超过原「不超过 1 米」的约定**。这是业主 2026-10-29 明确给出的比例（+50%）与旧约定冲突，
按**最新指令优先**处理：椅子单件上限放宽到 **1.30m** 并写进 `component_plan.json` 的
`max_dimension_m`，其余四件仍守 1.0m。验收里按件声明上限，不是全局放宽。

### 破碎动画（0.65s → 0.95s）

| 维度 | v001 | v002 | 为什么 |
|---|---|---|---|
| 抬升弧高 | 固定 0.28m 上限 | 基础 0.42~0.60 + 最长边 ×0.34~0.52，逐块 ±15% 抖动 | 业主嫌「不够高」；逐块抖动避免五块齐平飞 |
| 前抛距离 | 0.10 + 跨度×0.30 | 0.55 + 跨度×0.62~0.88 | 业主嫌「范围小」 |
| 横向散开 | 跨度×0.40 | 0.28 + 窄边×0.55~0.62 | 同上 |
| 碎块间隙 | 无（常落成一撮） | `MIN_REMNANT_GAP_M = 0.30`，落点做 6 轮松弛 | 「黏在一起」看起来就是没散开 |
| 时长 | 0.65s | 0.95s | 0.65s 压不出 1m 级弧线，弧顶会被压成贴地一跳 |
| 落地 | 一次缓震 | 缓震 + 0.055m 小弹跳 | 显得有重量而不是滑到位 |

### 碎片按材质分三类（不是同一套白块换色）

| 材质 | 用于 | 形态 | 面数 | 配色 |
|---|---|---|---|---|
| 陶瓷 | 罐子、花瓶 | 五边不规则片 + 正反各一鼓起中心点（像崩下来的弧面瓦） | 20 | 本体陶色格（罐 6,3 / 瓶 2,6，共 8,4） |
| 木质 | 椅子、木箱 | 一端收窄的长条木板，带真实厚度 | 12 | 木色格 (5,2)(6,2)(7,2)(4,2) |
| 纸张 | 书本堆 | 薄片 + 沿 X 单折卷边 | 12 | 色盘最亮格 (9,9)(9,8)(9,7)，另加书脊灰 (8,7) |

碎块尺寸随本体包络：陶片半径取 `clamp(最长边×0.13~0.18, 0.085, 0.20)`，
木板长 `clamp(最长边×0.30~0.42, 0.24, 0.54)`，书页 `0.055~0.17`。
验收断言「最大碎块最长边 ≥ 本体最长边 12%」，防止又退回小碎屑。
