# 场景可交互低模物件设计

FeatureID：WORLD-INTERACTIVE-CLUTTER / ASSET-PIPELINE；工程版本：0.1.0；设计修订：**r9**（2026-11-02 破碎掉币 10%，已实现；r6=远征03三房设施、r5=场景工坊手摆、r4=放大与破碎重做）。来源：用户指定的五类新组件 + 2026-11-02 掉币指令；状态：**几何/破碎/手摆/远征03布置已验收通过；r7 破碎掉币已实现，探针 `CLUTTER_COIN_DROP_PROBE_OK` 通过，真实渲染观感未验**。

## 目标与范围

罐子、书本堆、花瓶、椅子、木箱各一个独立组件，归入场景交互物件，不属于可拾取道具或大型可破墙。每件导出后不超过 100 三角面、最大边不超过 1 米。完整或破碎状态均不阻挡角色或子弹移动；子弹或角色接触使物件破碎，碎片沿输入方向飞散，落地后保留。

本批不改变枪械、敌人、掉落、房间生成、门、导航或存档规则。不替换既有书本、座椅、大型木箱等资产。（r7 起「破碎按 10% 掉 1 枚 1–10 金币」是有意变更的掉落，见文末 r7；除这一项外本句仍有效。）

## Owner、输入与状态

- 几何、材质、米制尺寸、底部中心原点：Blender 原始源及独立优化源。
- 完整模型、受击体、角色接触区、破碎反馈和落地碎片：各稳定 PackedScene；共用 `BreakableClutter3D.gd` 状态机。
- 子弹沿现有 `Projectile3D` 命中 `StaticBody3D.take_damage()`，方向取子弹真实飞行向量。受击体只在层值 4；玩家移动只检测层值 1，因此完整物件不会造成移动阻挡。
- 角色由 mask=1 的 Area3D 检测。方向优先取角色接触时的水平速度，静止或数据无效时取从角色指向物件的方向。
- 物件只接受首次有效触发，重复受击与接触幂等。方向无效时使用局部 `-Z`，不得因此产生异常或第六块碎片。
- 房间持有本次实例的细节运行时状态。流送卸载后重建，以稳定组件 ID 恢复为已落地破碎态，不重复播放动画。重新开局、重载场景、读档不扩展本批持久化语义。

## 反馈与残留

1. 完整模型先进行短促缩放/倾斜脉冲，再在约 0.065 秒内退出。
2. 同一套方向破碎动画适用于五个组件：最多五块低模几何碎片沿触发水平方向散开，具有竖直初速度、重力、短促落地缓震及放平动作，约 0.65 秒后停止。
3. 五块是物件碎片，不额外创建粒子发射器、灯光或其他颗粒。碎片不带碰撞，不进入定时回收池。
4. 残留相对组件原点所在的走行面落地，不读取世界 `y=0`；离开房间后仍保持已破碎记录。
5. 缺少视觉资源时保留受击体但不伪造美术完成；无效实例ID不登记状态，正常资源加载失败须记录测试错误。

### 验收发现的三个真实故障（已修）

1. **`process_mode` 未激活时受击体不进物理空间**：`set_stream_state(ACTIVE)` 才会把房间从 `DISABLED` 恢复，直接 `new()` 出来的房间受击体 `body_space = RID(0)`，子弹穿身而过。测试必须走正式流送入口，不能自建捷径。
2. **碎片初版是「刀片带」**：横向散布 0.86m、厚度 1.8cm，五块连成一条比本体还宽的长条。现改为受包络约束的凸块。
3. **房间截图曾全黑**：验收场景没有 `WorldEnvironment`，房间顶灯在无环境光时不足以成像。补环境后同时断言亮度分桶，避免「存了一张全黑图」当通过。

## 随机布置（2026-10-29，r3）

除了入口安全房那五件固定摆位，本批物件还能按**能力段**随机撒进任意关卡房间。

**不是关卡分支**：`level_plan.json` 顶层写 `interactive_clutter` 段，房间就撒点；代码里没有 `expedition_03` 这类字符串。
`check_level_decoupling.py` 巡检 7 个通用机制容器，`violations=0`。

数据流三段，缺一段就静默失效（这是本项目踩过的老坑，所以每段都留了断言）：

```text
level_plan.json  interactive_clutter
  → FloorPlanGenerator  plan["interactive_clutter"]（顶层透传，不进 canonical，不影响 layout_id）
  → TowerDescent3D._append_plan_room_record  record["interactive_clutter"]（按 exclude_room_types 过滤）
  → DungeonRoom3D.configure  interactive_clutter_plan → _build_random_interactive_clutter()
```

| 参数 | 语义 | 远征03 取值 |
|---|---|---|
| `enabled` | 总开关 | true |
| `per_room_min/max` | 每房件数 | 3 / 6 |
| `exclude_room_types` | 不撒的房间类型 | `STAIR_LOBBY`、`BOSS` |
| `min_room_size_m` | 短边小于此值直接跳过 | 8.0 |
| `wall_margin_m` | 离墙留边 | 0.9 |
| `door_clearance_m` | 离门/端口净空 | 2.4 |
| `min_spacing_m` | 彼此最小间距 | 1.1 |

三条实现口径值得记住：

1. **布置必须在 `_build_content()` 末尾执行**（家具、服务点、危害区都落位之后），否则读不到障碍物，会把罐子塞进机柜里。
2. **种子只用 `room_seed` 派生**：`hash([room_seed, "interactive_clutter", room_id])`，不碰玩法随机流，也不受卸载重建影响。
3. **太小的房显式跳过，不靠过滤碰巧归零**：5×5 十字路口四面都是门，门净空会把候选点全清空 —— 那看起来和「没配置」一模一样，属于不可解释行为。

## r4 修订：放大与破碎重做（2026-10-29）

业主反馈两件事：**动画不够明显**（散落范围小、不够高、力道不足），**物件整体太小**。

### 尺寸（v001 → v002）

按业主逐件指定比例整件放大，**纯统一缩放，拓扑与三角面完全不变**：

|---|---|---|---|---|
| 罐子 | **+50%** | 0.44×0.43×0.54 | 0.66×0.65×0.81 | 96 |
| 书本堆 | 不变 | 0.64×0.50×0.31 | 不变 | 84 |
| 花瓶 | 不变（未提及） | 0.43×0.43×0.73 | 不变 | 92 |
| 椅子 | **+50%** | 0.50×0.50×0.86 | 0.75×0.75×**1.29** | 96 |
| 木箱 | **+30%** | 0.65×0.69×0.68 | 0.84×0.90×0.88 | 98 |

🔴 **椅子 1.29m 已超过原「不超过 1 米」的约定**。这是业主 2026-10-29 明确给出的比例（+50%）与旧约定冲突，

### 破碎动画（0.65s → 0.95s）

| 维度 | v001 | v002 | 为什么 |
|---|---|---|---|
| 抬升弧高 | 固定 0.28m 上限 | 基础 0.42~0.60 + 最长边 ×0.34~0.52，逐块 ±15% 抖动 | 业主嫌「不够高」；逐块抖动避免五块齐平飞 |
| 前抛距离 | 0.10 + 跨度×0.30 | 0.55 + 跨度×0.62~0.88 | 业主嫌「范围小」 |
| 横向散开 | 跨度×0.40 | 0.28 + 窄边×0.55~0.62 | 同上 |
| 碎块间隙 | 无（常落成一撮） | `MIN_REMNANT_GAP_M = 0.30`，落点做 6 轮松弛 | 「黏在一起」看起来就是没散开 |
| 时长 | 0.65s | 0.95s | 0.65s 压不出 1m 级弧线，弧顶会被压成贴地一跳 |
| 落地 | 一次缓震 | 缓震 + 0.055m 小弹跳 | 显得有重量而不是滑到位 |

### 碎片按材质分三类（不是同一套白块换色）

## r5：作为场景工坊组件手摆（2026-10-30）

业主：「易碎物品是不是也能放进场景编辑器里面，作为那个组件去刷。」

**能。** 五件已注册进共享组件目录，在场景工坊的组件套件里是独立一组：

```text
共享 / 易碎陈设  →  易碎罐子 / 散落书本堆 / 易碎花瓶 / 易碎椅子 / 易碎木箱
```

| 组件 ID | slug | 包络（m） | 碎块材质 |
|---|---|---|---|
| `ENV-SHARED-BREAKABLE-JAR` | `breakable_jar` | 0.66 × 0.81 × 0.645 | 陶瓷 |
| `ENV-SHARED-BREAKABLE-BOOK-STACK` | `breakable_book_stack` | 0.64 × 0.31 × 0.50 | 纸张 |
| `ENV-SHARED-BREAKABLE-VASE` | `breakable_vase` | 0.43 × 0.73 × 0.43 | 陶瓷 |
| `ENV-SHARED-BREAKABLE-CHAIR` | `breakable_chair` | 0.75 × 1.29 × 0.75 | 木质 |
| `ENV-SHARED-BREAKABLE-CRATE` | `breakable_crate` | 0.84 × 0.88 × 0.90 | 木质 |

`slot_role = breakable_clutter`。`collision_policy` 仍是
`projectile_hit_only_no_player_blocking` —— 子弹可打、玩家可穿过，**不挡路**。

### 只注册进目录是不够的

第一版只往 `shell_component_catalog.json` 加了 5 条，摆得出来、打得碎，但：

| 缺陷 | 后果 |
|---|---|
| 没有 `clutter_id` | 房间账没有键可挂，存档里那笔"砸了"无处可写 |
| `broken` 信号没接到房间 | 砸碎不进账 ⇒ 走远再回来 / 存档重进，罐子**自己复原** |
| 不参与随机撒点避让 | 手摆罐子上会再叠一件随机罐子，账上两条 id 抢同一落点 |

三处都在 `DungeonRoom3D` 补齐：

1. **`_adopt_authored_breakable_clutter(root)`** —— 在 `_build_shell()` 静态分支
   （`AuthoredLayoutArtRoot` 装入之后）扫一遍 `BreakableClutter3D`，
   给每件设 `clutter_id = "authored_" + 节点名`、打 `clutter_authored` 标记、
   连 `broken` 信号。节点名由 Godot 保证同布局内唯一（同名自动加序号），
   因此同一份布局每次实例化的 id 逐字一致。
2. **`_restore_interactive_clutter()`** —— 归属判据从「在 `RuntimeDetail` 下」
   放宽到「在本房间下」。手摆件挂在壳体里、随壳体常驻，原判据会把它们跳过。
   恢复函数据 `is_broken()` 幂等，重复调用无副作用。
3. **`_interactive_clutter_candidates()`** —— 生成候选落点时就排掉贴着
   手摆件（间距 < `min_spacing_m`）的点。放在候选阶段而不是选点阶段，
   因为选点阶段只取 3~6 个，抽样验证几乎恒绿（第一版就此踩坑：
   把避让整段删掉，探针照样 PASS）。

### 编辑器侧的两个细节

- **原点契约**：`bottom_center`（底面中心），正面朝 `-Z`。场景工坊的标高
  按本房实际走行面贴地；旧夹具为0，远征03公馆地砖顶面为0.10m。
- **卡片标题**：`caption()` 取 `display_name`，取不到才落到 `category`。
  五件的 `category` 同为「易碎陈设」，不补 `display_name` 会得到五张同名卡片。

### 验收

`tests/verification/probe_authored_breakable_clutter.tscn`，走**真实接入点**
（自建 `DungeonRoom3D` + `static_layout_scene_path` 指向 `tests/fixtures/authored_clutter_room.tscn`，
调 `ensure_shell_built()` 而不是直接调私有函数）：

```text
A1 2 件全部认领 / A2 id 带 authored_ 前缀 / A3 broken 已接线 / A4 id 互不相同
B1 砸碎进房间账
C1 detail 卸载重建后仍是已碎
D0 候选落点非空 / D1 候选落点不贴手摆件 / D2 实际撒点不重叠
E1 回灌存档后恰好 1 件已碎
```

### 边界（不变）

- 手摆件与随机撒点是**两批**：手摆的随壳体常驻、不随 detail 卸载；随机的仍在
  `RuntimeDetail` 下、进出房重建。两者共用同一本 `breakable_clutter` 房间账。
- 手摆件不进 `_interactive_clutter_blocked_centers()` 的家具避让清单 ——
  它们本身不占地面（玩家可穿过），只是打碎后短暂留碎片。

## r7：破碎掉币（2026-11-02，已实现 / 探针通过）

来源（同一天四条业主指令，概率改了三次）：
1. 「我不是有5个易碎陈设吗？帮我增加一个设计，破碎后，原地回掉落一个金币，金币的数值1-10随机。破坏后掉落的概率是8%」
2. 追加「这个掉落的金币需要有个可拾取时间，不然角色碰到就立刻消失了，0.5 秒的可拾取时间或者 1 秒的」
3. 再追加「奇怪为什么我都没掉落金币？概率帮我调成60%」
4. 最后「可以了 调成10%把」→ **当前生效值 10%**

概率演进：`8% → 60%（因未实现被误判为概率太小）→ 10%（上手确认手感后收回）`。
60% 只存活了不到两小时：**存档、资产行、SHA 一概没碰**，仅在《场景账本》变更日志留过一行 v0.1.61，
随后由 v0.1.63 更正为 10% —— 日志允许保留这种「改了又改」的痕迹，不必抹掉。

### ⚠️ 关于「一枚都没掉」

**原因是当时一行代码都没写。** 第一轮只产出了本文档的 r7 契约，按仓库约定
「没有完整契约时先补设计，再实施改变规则的代码」，代码留到下一轮；
运行期概率实际是 **0**，与 8% 无关。本节记录的就是补上的实现。

教训（写给下一次）：**设计写完不等于功能存在。** 业主看到的是游戏里没反应，
不会去读文档。凡是「改一个数字就能看到结果」的需求，设计落地当轮就该把代码一起交。

### 一句话契约

五件易碎陈设任一件**首次**被打碎时，按 **10%** 概率在该件**原地**生成 **1 枚**金币，
金额取 **[1, 10]** 的均匀随机整数；金币落地稳定后再锁 **0.5 秒**才可拾取。
没命中就什么也不掉：不替换、不叠加、不延时补发、不换奖励类型。

### 状态所有者与事件

| 项 | 归属 |
|---|---|
| 是否破碎 / 破碎方向 | `DungeonRoom3D._pending_detail_runtime_state["breakable_clutter"][clutter_id]` |
| 是否掉过币 | 同一字典的可选键 `coin_dropped: bool` |
| 掉率 / 金额 / 掷骰 | `Dungeon3D`（玩法层） |
| 可拾取锁 | `GroundLootPickup3D._post_spawn_lockout_s` + `_pickup_grace_until_msec` |
| 金币实体与落点 | `GroundLootPickup3D` + `segment_runtime_state[room].ground_items` |

新增**一条上行事件**，与既有 `chest_open_requested` 同形：

```text
DungeonRoom3D.clutter_broken(room, world_position, clutter_id)   # 只在 shatter() 成功那一次发
  → Dungeon3D._on_clutter_broken(...)                            # 掷骰 + 发放 + 回写 coin_dropped
```

**掷骰不在 `BreakableClutter3D`。** 它是「几何 + 受击 + 碎片」状态机，`_broken` 幂等是它唯一的
玩法约定；掉率是经济规则，而且只有玩法层拿得到 `run_seed`。房间也只记账与转发，不发钱。

接线有两处，**必须都在**：`Dungeon3D` 房间创建处、`TowerDescent3D` 房间创建处（远征走后者）。
漏一处 = 那批房间里有罐子但永远不掉币，且不打任何日志。

### 数值（一处真源）

```text
P(掉币)  = 0.10                        单件 · 单次 · 独立同分布
金额     = randi_range(1, 10)          均匀整数，期望 5.5，无偏
单件期望 = 0.10 × 5.5 = 0.55 枚
可拾取锁 = 0.81 s（弹跳动画）+ 0.5 s（落地后）= 1.31 s 不可拾取
```

```gdscript
const CLUTTER_COIN_DROP_CHANCE := 0.1
const CLUTTER_COIN_DROP_MIN := 1
const CLUTTER_COIN_DROP_MAX := 10
const CLUTTER_COIN_PICKUP_LOCKOUT_S := 0.5
const CLUTTER_COIN_OFFSET_RADIUS_M := 0.30
```

能力段可覆盖：`interactive_clutter.coin_drop_chance` / `coin_drop_min` / `coin_drop_max` /
`coin_pickup_lockout_s`，缺省即上面五值。这是**能力级配置**，不是关卡 ID 分支。

⚠️ **0.81 不许出现在 `Dungeon3D` 里。** 锁的叠加只发生在
`GroundLootPickup3D._finish_spawn_animation()`；调用侧写 `0.81 + 0.5` 就是第二处真源，
动画常量一改锁就悄悄变形。

### 随机源（决定性，不是 `randf()`）

```text
seed = hash("%d|clutter_coin|%s" % [run_seed, clutter_id])
```

与 `RuntimeRewardCoordinator` 同一口径。三条理由，缺一条就是 bug：

1. **不消耗全局随机流。** 用 `randi()` 会挤动怪物掉落、房间撒点等既有序列。
2. **同一次远征内恒定。** 房间重建后重算同结果，不必为「不重掷」另存掷骰快照。
3. **可测。** 给定 `run_seed + clutter_id` 期望值可复算，否则概率只能靠统计撞运气。

`clutter_id` 用既有稳定 id（手摆件 `authored_<节点名>`、随机撒点由生成器给），不新增 id 体系。

### 落点（原地 = 破碎点，不是散布）

- 原点取 `clutter.global_position`（Prefab 原点契约 `bottom_center`，天然是「原地」）。
- 加一个 **≤ 0.30 m** 的确定性水平偏移，避免金币正压在碎片堆中心被遮住。不读件数、不按 index。
- 仍走 `_resolve_loot_spawn_position()`：贴地 → 净空 → 收缩重试 → 回退到破碎点。
- 生成后走既有 `begin_spawn_animation()`（抛高 1.65 m → 落地 → 弹两下 = **0.81 s**）。

### 可拾取延迟（0.5 s，从落地稳定起算）

玩家走路撞碎罐子（`PlayerContact`）时**人就站在金币正上方**，若落地即解锁，眼睛刚捕捉到
金色就到背包了 —— 观感就是「碎了，什么都没有」。

**0.5 秒不能从生成时刻起算**：现成动画本身已锁 0.81 s，`0.5 < 0.81` 会被完全吞掉，改了等于没改。

| 口径 | 不可拾取总时长 | 判定 |
|---|---|---|
| 生成时刻起算，T = 0.5 | 0.81 s | ❌ 与改前逐帧相同 |
| 生成时刻起算，T = 1.0 | 1.00 s | ⚠️ 只多 0.19 s，感知不到 |
| **落地稳定起算，T = 0.5** | **1.31 s** | ✅ 采用 |
| 落地稳定起算，T = 1.0 | 1.81 s | 偏拖，连撞时原地等太久 |

⛔ **不能复用 `set_pickup_grace_seconds()`**：它把 `_pickup_requires_player_exit` 一起设成 true，
会变成「站在原地永远捡不到，必须先走开 2 m 再回来」。那是丢弃防回包语义。新增独立接口
`lock_pickup_after_spawn(seconds)`，只锁时间、不碰离场标志。

### 发放路径（只走唯一出口）

```text
命中 → _deliver_ground_rewards(room, [{kind:"currency", amount:n}], 破碎点, "clutter:<id>",
                               spread=false, pickup_delay_after_spawn=0.5)
     → RewardSink.apply_ground → _spawn_loot_items → GroundLootPickup3D
```

| 规则 | 口径 | 为什么 |
|---|---|---|
| 零金币房 `_room_zero_currency` | **不产出**（仍记 `coin_dropped=false`） | 诅咒写的是「这房间没有金币」，掉落口开例外会让诅咒不可信 |
| 房间货币倍率 `_room_currency_multipliers` | **生效**，`amount = maxi(0, round(base × m))` | 倍率描述房间，不是掉落来源 |
| `_world_currency_multiplier` | **不乘** | 它只在入账 `_grant_run_currency()` 里乘一次，这里再乘就是双重计价 |
| 散布 | `spread = false` | 单件且「原地」是业主原话；散布会把币甩到 1 m 外 |

`spread` / `pickup_delay_after_spawn` 是 `_deliver_ground_rewards` 新增的两个可选参数；
既有调用方（剧情 / 宝箱 / 击杀）不传即默认 `true` / `0.0`，行为逐帧不变。

### 存档与重建

金币是**地面实体**，不是房间账里的数字：

| 情形 | 读档 / 流送重建后 |
|---|---|
| 碎了 · 出了币 · 没捡 | 原位原值仍在地上（既有 `ground_items` 快照） |
| 碎了 · 出了币 · 已捡 | 不复原、不补发 |
| 碎了 · 没出币 | 永不再掷（`broken=true` + `coin_dropped=false`） |
| 没碎 | 照旧 |

**不新增存档顶层键、不升 schema。** `coin_dropped` 是 `breakable_clutter` 字典里的可选键。
结构上不可能重掷：`restore_broken()` 只置 `_broken=true`、**不发 `broken` 信号** —— 但这条由
探针 B2 钉住，不靠读代码。

### 边界（明确不做）

- 只掉金币，不掉武器 / 弹药 / 钥匙 / 零件。
- 不改 layer4 受击、不改玩家阻挡、不改碎片数量与三类材质。
- 不进房间清空判定、不影响敌人 AI、不进 `furnishing_conflicts()`。
- 不加音效、不加粒子、不加倒计时条 / 「可拾取」提示。
- 不做「连续打碎递增概率」「房间内保底」—— 10% 就是 10%，可复算。
- 不给怪物掉落、宝箱产出、剧情掉落加这段锁：只加在破碎掉币上（延迟默认 0.0）。

### 平衡测算（这条会改经济曲线，必须看）

远征03 现有易碎件 **535 件**（《场景账本》域变更日志 v0.1.59 登记）。单件期望 0.55 枚：

| 假设 | 击碎次数 | 期望金币 | 相对怪物掉落（约 61 枚/层） |
|---|---|---|---|
| 全清 535 件 | 535 | **≈294 枚** | ×4.8 |
| 破击率 25% | 134 | ≈74 枚 | ×1.2 |
| 破击率 15% | 80 | ≈44 枚 | ×0.72 |

远征03 怪物掉落是校准过的（53 只 ≈61 枚/层，商店中位价 113 枚，「攒一层买最便宜一件」）。
**10% 落在「瓦砾能补贴、但不抢主线」这条带里**：破击率 15% 时约 44 枚 = 怪物掉落的 72%，
砸东西有明显回报，但不会比打怪更划算。业主已确认该值，按指令落地。

同一天的概率演进，同一份 535 件模型只换概率：

| 概率 | 全清期望 | 破击率 25% | 判断 |
|---|---|---|---|
| 8%（首次要求） | 235 枚 | 59 枚 | 与怪物掉落同量级，偏多 |
| 60%（未实现期误判为「概率太小」） | 1766 枚 | 442 枚 | 瓦砾变主收入，通胀 |
| **10%（当前）** | **294 枚** | **74 枚** | **补贴而非主线，采用** |

结论：8% 与 10% 实际相差不大（235 vs 294 枚），真正越界的是 60%。当前值不需要再调；
若要微调，`interactive_clutter.coin_drop_chance` 一个字段即可，无需改逻辑。

## r8：公馆书架与盆栽的受击状态

来源：用户2026-11-03指定开放式书架、大/小常绿盆栽及红花插花摆件。工程0.1.0；FeatureID沿用WORLD-INTERACTIVE-CLUTTER，独立状态能力不继承五件小物的接触破碎和金币掉落。

`ReactiveProp3D`拥有单件耐久/受击/倒塌状态；`DungeonRoom3D`拥有以正式布局相对节点路径为键的`reactive_props`房间账；`Dungeon3D`将该可选字段捕获/恢复到既有房间快照。缺字段旧档保持初始状态，不改layout_id。命令为`take_damage(amount, critical, direction, knockback)`（非正伤害、倒塌中、已倒塌/已碎拒绝）；事件`state_changed(prop)`在有效受击、落地发出，查询/恢复为`export_prop_state()`/`restore_prop_state(data)`。恢复不发事件、不重新伤害或掉落。中途倒塌存档恢复为落地态。

书架受击呈阻尼弹性抖动；每两次有效命中掉两本书，最多八本，随后留在地面。累计耐久耗尽或1.25秒连击窗口内达到10次有效命中时倒塌，停止连击不恢复已扣耐久。落下方向取入射方向在书架前后轴的投影，侧向命中默认向背面；绕底边翻倒0.85秒。非均匀放大和房间旋转参与实际可视包络计算。落地结算一次与最终倒下模型同宽同长的定向矩形范围伤害，覆盖碰撞体与该范围重叠的玩家和敌人；存活者优先挤向最近可通行边，阻挡时尝试其他边；不可穿墙。致死由原角色伤害/死亡链路处理，不对死者做存活挤出。残骸阻挡同步到落地范围，原竖直阻挡及受击关闭。

三种盆栽仅受伤害扣耐久并抖动；行走触碰不扣血、不碎裂。耐久耗尽后隐藏完整植株、留下五块陶片及泥土/倒伏叶片；解除本件全部阻挡与受击，无接触破碎Area。书本与陶片为有色几何残留，无拾取奖励、无碰撞。

工程可调初值（用户未指定数值）：书架耐久300；大盆栽90、小盆栽60、红花摆件60；倒塌基础伤害50。全部为Prefab/脚本导出属性，不改武器/生物数值；伤害经过生物既有减伤、无敌和死亡规则。

正式接入：四件稳定Prefab挂载该能力，工坊现有组件与正式远征03布局自动继承；不用重存25份房间。`LayoutCollision`退出碰撞层，由组件自管碰撞，因此流送重新启用shape也不会恢复幽灵阻挡。验收入口`verify_reactive_manor_props.tscn`覆盖真实子弹、耐久/连击、接触不碎、状态回灌、落地范围/仅一次伤害、存活挤出及原生死亡；真实渲染截图独立记录。


## r9：台灯爆裂燃烧与家具震落桌面物件

来源：用户2026-11-03要求暖光黄铜台灯被子弹直接命中时爆开，或从家具上摔落后爆开；两条触发共用周围火焰与伤害，持续5秒后消失。同时要求承载家具连续受击后震落上面物件，且与r8成果一起同步设计/账本。
