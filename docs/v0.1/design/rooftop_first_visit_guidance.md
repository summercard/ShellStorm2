# 100F 首次登顶杂物引导

FeatureID：WORLD-BLOCKS / ASSET-ROOFTOP / ASSET-PIPELINE；关联 NARRATIVE-TIMELINE。版本：0.1.0，设计修订 r3。来源：2026-10-18 用户红线标注图、自然疏密反馈与正式箱货/防洪包/水泥/风摆草要求。状态：正式交互场景美术与阻挡已接入；移动、清除及持久化仍待设计实现。

## 目标与范围

主线首次上屋顶，从西侧出口进入屋面后，以倾倒花盆、错斜花箱、破损花圃、木料及石块形成杂乱边界，引导玩家沿机房西侧向北，再沿机房北侧通道走向跨塔桥，经过现有桥口剧情触发区。红线标注的西侧上/下段、北侧堆场、东侧上下段均设置独立杂物，保持出入口净空。用户绿色标注表示出口；运行时锚点名称为 `rooftop_stair_exit`，实测 (-28,0,2.5)。不凭示意图把它另建成一部电梯。

屋面 X[-50,50]、Z[-35,45]，Y=0；中央房屋 X[-15,15]、Z[-10,20]。现有桥口 (20,0,-32.5)，桥前剧情锚点 (5.4,0,-23.5)、水平半径13.5m，守卫锚点 (20,0,-28)。布局不得封死出口、中央房屋东门、桥入口或剧情站位。基于实物逐件碰撞，不设置跨越空白区域的整片不可见墙。

## 自然堆积轮廓（r2）

布局 v002 保留130个独立内容ID，以几处较厚的密集堆积和零散边缘形成疏密变化。长花箱、破损花圃承担主要阻挡，木料、石块与倾倒花盆围绕局部堆积中心散落；物件间距、朝向与倾角不等，避免等距交替排列。北侧从空心围圈改为多团相连的实心杂物堆，外缘有凹入、突出与留白；东西两侧边界用不规则折转和不同堆积深度形成自然轮廓。

视觉稀疏处仍需保持原引导边界的有效阻挡；出口、机房北侧路径、东门与桥前站位保持可通行。所有倾倒件按实际可视顶点贴地，碰撞随组件姿态变化；不得以整体缩放或跨空白区大碰撞盒补齐阻挡。

## 所有者与正式接入

唯一摆位源：`assets/art/environments/tower_zones/rooftop/runtime/guidance/env_rooftop_guidance_layout_root_top3d.tscn`。在 Godot 中调整各区的独立实例；制作过程清单不是运行时输入，也不得覆盖后续手调。`TowerFloorStage3D` 仅在真正100F天台判据内实例化一次，99F、98F和远征不挂载。布局内所有位置、旋转及实例稳定ID都归该 TSCN。

逐件碰撞归组件自身，layer=1、mask=0，随物件变换；木料和石堆按可视块分段，沙包逐袋碰撞，地面草不设阻挡。现有盆栽和花箱稳定Prefab被引用，包装补独立内容身份及盆体/箱体碰撞，不复制GLB几何。石堆和木料已由正式模型替换，破损花圃白盒在本布局内改用防洪沙包；破损花圃本身的未来设计保留。

## 场景交互与生命周期

### 正式资产深化范围（r3）

2026-10-18 用户要求补充大体量箱类物体，地板长出与花圃同方式摆动的草，并把替代方块制作为防洪包和水泥碎块。沿用已登记沙包、破败木箱A、石块堆A/B/C与木料的稳定AssetID；新增独立篷布货包与地面杂草资产。沙包取代本布局中的破损花圃白盒实例引用，保留实例ID；原破损花圃设计继续保留，不将沙包冒记为花圃。大型木箱约4×3×3m，篷布货包约4.5×3×2.8m，填入现有堆积后方和北侧杂物区，避开出口及桥前路线。沙包适配既有约6m长阻挡位置，使用分袋碰撞；水泥碎块保留三种不同堆积轮廓，木料保留原有逐段阻挡。

全部新增组件按场景交互物件管理；草属于无阻挡的环境交互内容，未来允许条件清除，当前没有采集功能。草根固定在地面，枝叶直接复用 `PlantSway3D` 与共享风摆材质/时钟，跟随暂停状态；不驱动碰撞或新增独立动画时钟。美术源、独立优化源、稳定GLB、Prefab及验收清单逐件对应；正式美术状态与尚未实现的移动/清除玩法分开登记。

全部新增物件属于场景可交互内容，组 `scene_interactive_content`。每个布局实例持有永久 `scene_content_id=roof_clutter_NNN`，复制新实例必须分配新ID。阻挡物初始状态 `blocking`，草为 `growing`，交互状态均为 `planned_locked`。当前具备物理阻挡、风摆和独立编辑，不宣称玩家已能移动、拾取、破坏或清除。

未来动作 `move` / `remove` 的条件由后续场景交互系统设计决定，当前 `move_condition/remove_condition=design_pending`。剧情完成不自动清场；重复进屋顶仍保留初始杂物，直到条件与状态系统正式落地。不可把它们并入永久建筑壳体或无身份MultiMesh。

目标接口（未实现）：以稳定ID发出移动/清除命令，唯一状态Owner为后续场景交互系统；成功后变换或移除该实例及其全部碰撞，发出状态变化事件；按ID记录变换/清除状态。条件不足、无效ID、目标重叠、保存失败均拒绝或恢复原状态；场景卸载后读档复原，重复清除幂等。解锁条件、成本、移动范围和存档schema未冻结，不由资产布局推定。

## 资产登记

场景分账本《资产主表》为登记Owner。`ENV-ROOFTOP-SANDBAG-BARRIER`、`ENV-ROOFTOP-BROKEN-CRATE-A`、`ENV-ROOFTOP-RUBBLE-PILE-A/B/C`、`ENV-ROOFTOP-TIMBER-PILE`、`ENV-ROOFTOP-COVERED-CARGO`、`ENV-ROOFTOP-GRASS-PATCH` 登记为“正式美术已接入”，子类为 `scene_interactive_object`，并登记实际Prefab专页。现有花盆/花箱交互包装与布局沿用各自状态；破损花圃白盒已从本布局撤出但资产设计保留，其他未制作木箱变体、大型杂物堆不受影响。美术状态不代表未来移动、清除功能完成。
