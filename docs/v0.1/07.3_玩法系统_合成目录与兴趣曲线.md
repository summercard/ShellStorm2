# 玩法系统｜合成目录与兴趣曲线 v0.1

功能ID：`RUN-SYNTHESIS`（依附 `RUN-FORGE`）。状态：**[核心已实装]**（`SynthesisCatalog` + `WeaponForge` R0 + `WorkbenchPanel` 双页签；配方行动效/图标未做）。适用游戏工程：`0.1.0`。更新日期：2026-10-18。

武器改造台现在有 R1 重铸、R2 融合、R3 合成三个随机配方，但**玩家无法定向获得某一把枪**。普通怪已不再掉枪（2026-10-18），枪只能来自 Boss/精英掉落、商人、工坊造。玩家"就差一把霰弹枪"的时候，投什么都只能掷骰。

本文给出的是一张**合成目录**：把[道具列表](../../data/ShellStorm2_游戏内容数据库_v010.xlsx)（钥匙）与[武器列表](../../data/ShellStorm2_游戏内容数据库_v010.xlsx)（产物）逐条连起来的九条配方，外加一条可量化、可验收的**兴趣曲线**。它不是新的随机配方，而是 R3 上的一层**定向**：随机仍然存在，但玩家可以选择"我要哪一把"。

> **裁决状态（2026-10-18）：五条已全部收口**，见 §14。产业链上最实质的一条是 **所有产物都能正常出售** —— 我前后写过"全部禁售"和"只 R0 禁售"两版，都被账算翻了：碎片本来就能按商价一半卖，合成再卖反而更亏（§8.3）。另外堵掉了「零价材料当燃料」的口子（§8.5）。

## 1. 这张表要解决的三件事

| 问题 | 现在的表现 | 这张表怎么解 |
|---|---|---|
| **无法定向** | 投一堆材料 → 随机枪身。想配 build 只能反复赌 | 九条配方指向九把可产出武器（十把非初始武器里的第十把是棒球棍，它是链的起点钥匙、基地无限供），每条明确"几号钥匙 → 哪把枪" |
| **没有目标感** | 掉落的蓝图碎片只能"解锁蓝图"，价值感单一 | 碎片变成**合成凭据**：攒够 N 个就能定向换枪。碎片第一次有了"数着攒"的意义 |
| **兴趣曲线是平的** | 三条配方的概率只受投入量影响，第 1 次和第 30 次体验一样 | 五段式曲线：每段解锁一批配方、给一个新维度、配方密度递减 |

### 1.1 为什么钥匙必须是"碎片"而不是任意材料

用户口径是"所有东西都能当材料"。合成目录不与这条冲突 —— 任意材料仍然可以凑燃料门槛，但**要定向到某把枪，必须投对应的钥匙**。

钥匙只选**没有其他用途**的物品：

| 候选 | 有其他用途？ | 能当钥匙吗 |
|---|---|---|
| 治疗药水 | 要喝 | ✗ 玩家会纠结"喝还是熔" |
| 电池 | 要装 | ✗ 同上 |
| 弹药模块 | 要装枪上 | ✗ 同上 |
| 配件 | 要装枪上 | ✗ 同上 |
| **蓝图碎片** | **唯一用途就是解锁** | ✓ 语义天然是"通往某把枪的凭据" |

## 3. 表 A｜合成配方主表

九条配方，产出九把武器。`SYN-` 前缀固定，代码按 `recipe_id` 索引。

**为什么是九条而不是十把。** 除初始的 `weapon_starter_rifle` / `weapon_sprinkler` 外，还有十把武器：七远程 + 三近战。其中**废土棒球棍不做产物** —— 它是近战链的起点，而它在基地自动贩卖机是 `unlimited` 无限供应（`price 45`）。给一个"随时能买 45 块"的东西做配方产出，等于给玩家一条"花 60 金币买空气"的路。所以它是**钥匙**，不是**产出**。

| recipe_id | 曲线段 | 产物 | 产物名 | 钥匙 | 数量 | 燃料门槛 `V` | 金币 | `quality_bonus` | 预装弹种 | 预装配件 |
|---|---|---|---|---|---|---|---|---|---|
| `SYN-PISTOL` | L0 | `weapon_pistol` | 豌豆手枪 | `bp_pistol` | 2 | 6 | 25 | 0 | — | 0 |
| `SYN-SHOTGUN` | L0 | `weapon_shotgun` | 散射喷壶 | `bp_shotgun` | 2 | 6 | 40 | 0 | — | 0 |
| `SYN-GREATBLADE` | L0 | `weapon_greatblade` | 巨型工业断刃 | `weapon_baseball_bat` | 1 | 6 | 60 | 0 | — | 0 |
| `SYN-RIFLE` | L1 | `weapon_rifle` | 步枪 | `bp_rifle` | 3 | 9 | 55 | 2 | `mod_bullet_piercing` | 0 |
| `SYN-MG` | L1 | `weapon_machinegun` | 蜂窝机枪 | `bp_machinegun` | 3 | 9 | 65 | 2 | `mod_bullet_standard` | 0 |

### 3.1 字段字典

| 字段 | 类型 | 含义 | 约束 |
|---|---|---|---|
| `recipe_id` | String | 稳定配方 ID | 大写 `SYN-` 前缀，代码引用，永不改 |
| `curve_tier` | int 0–3 | 所在曲线段（= 工坊蓝图 Tier） | 必须等于产物枪身的 `BlueprintRegistry.tier` |
| `product_id` | String | 产物物品 ID | 必须在 `BlueprintRegistry` 的 gunbody 池里 |
| `key_item_id` | String | 钥匙物品 ID | 必须在 `ItemRegistry` 里；**不得是有其他用途的消耗品** |
| `key_count` | int ≥1 | 需要的钥匙数量 | 远程 2–5 递增；近战固定 1（升级链） |
| `fuel_min` | int ≥6 | 燃料熔炼值门槛 | **必须 ≥ R3 盲盒门槛 6**（定向不能比盲盒便宜） |
| `coin_cost` | int | 金币费用 | 必须 < 产物 `price`（否则不如直接买） |
| `quality_bonus` | int ≥0 | 品质加成，等价于虚拟稀有度分 | 0 / 2 / 4 / 7，按段递增 |
| `preload_bullet` | String | 产物预装弹种（空 = 走随机） | 空串或合法 `WeaponBulletDrop` ID |
| `preload_attachments` | int 0–2 | 产物预装配件数 | 从该枪身实际支持的槽位里抽 |

### 3.2 三条设计取舍

**① 为什么 `quality_bonus` 用 0 / 2 / 4 / 7（而不是 0 / 4 / 8 / 12）。**

这个序列刻意与 `RARITY_POINTS`（0/1/2/4/7）同量级，于是每条配方都能用一句玩家听得懂的话解释：

- L1（+2）= 「合成这把枪，本身相当于白送你 **1 件 rare 材料**」
- L3（+7）= 「合成这把枪，本身相当于白送你 **1 件 legendary 材料**」

用 0/4/8/12 就没有这个锚点，只能解释成"配方自带 8 点数值"，玩家无感。

**② 为什么近战用"武器当钥匙"，远程用"碎片当钥匙"。**

这是数据缺口倒逼的，也是唯一自洽的选择：`BlueprintRegistry` 注册了 3 个近战枪身（`bp_baseball_bat` / `bp_greatblade` / `bp_waraxe`），但 `ItemRegistry` **没有任何近战碎片物品**。近战没有碎片可投。

于是近战落成一条升级链：

```
废土棒球棍(common·45) ──SYN-GREATBLADE──▶ 巨型工业断刃(uncommon·165) ──SYN-WARAXE──▶ 攻城裂甲斧(rare·240)
```

远程则是七条互不相干的碎片配方（`bp_pistol` … `bp_charge`）。

**近战线到此为止（2026-10-18 裁决）。** 裂甲斧之后不再有第三级。理由：再加一级需要新增近战枪身资产（模型 / 动作 / 数值配平），成本远高于收益，而近战链的价值是"给开局捡到的棒球棍一个去处"，不是长线目标。远程七条已经承担了长线。

**③ 为什么近战链每级只要 1 把钥匙，而不是 2 把。**

2 把会撞上 R2 融合（`n ≥ 2` 一律判融合），语义打架。1 把 + 燃料门槛则给出一个**优雅的分岔**：

| 投入 | `V` | 判定 | 结果 |
|---|---|---|---|
| 1 把棒球棍 + 少量材料 | 3–5 | **R1 重铸** | 还是棒球棍，但重掷品质 |
| 1 把棒球棍 + 足量材料 | ≥ 6 | **R0 定向合成** | 变成巨型工业断刃 |

**燃料投多少，决定"赌品质"还是"升级"。** 玩家有明确、可学习的控制权，不需要额外 UI 解释。

## 4. 判定顺序与歧义

定向合成必须插在 R1 之前，否则近战链永远判不到（1 把武器 + `V ≥ 3` 已经被 R1 吃掉）。

```
① R0 定向合成
   若盘上有 ≥1 把武器，且武器数 == key_count，
      且全部是该配方的 key_item_id，
      且 V ≥ fuel_min           → 产出 product_id，品质按 quality_bonus 掷骰
   若盘上 0 把武器，
      且某配方的 key_item_id 数量 ≥ key_count，
      且 V ≥ fuel_min           → 产出 product_id
② R1 重铸        1 枪 + V ≥ 3
③ R2 融合        ≥ 2 枪
④ R3 盲盒合成    0 枪 + V ≥ 6
```

### 4.1 多条配方同时命中：取 `curve_tier` 最高

盘上同时有 `bp_pistol ×2` 和 `bp_rifle ×3` 时，两条都满足。规则是**取 tier 最高的那条**（这里是 `SYN-RIFLE`）。

理由：多投不能降级。玩家往盘里多放了一批稀有货，产出必须更好；若取 tier 最低，等于惩罚"多投"，玩家会学会"精确投料"，而这套系统要的不是精算，是"攒够了就丢进去"。

tier 相同时（理论上不存在，同 tier 配方钥匙不同 ID）按 `recipe_id` 字典序取第一个，保证确定性。

### 4.2 钥匙够了但燃料不够：拒绝，不降级

投了 2 个 `bp_pistol` 但 `V = 2 < 6` 时，**不能**静默降级成 R3 盲盒（那会吞掉碎片还不给对应的枪），也不能降级成 R1。

必须返回稳定拒绝码 `synthesis_fuel_short`，并在状态栏写清"还差 4 点熔炼值才能合成豌豆手枪"。理由：碎片是稀缺凭据，静默降级等于骗玩家烧掉凭据。

### 4.3 新增拒绝码

| 情形 | 拒绝码 | 状态栏文案 |
|---|---|---|
| 钥匙齐全但燃料不足 | `synthesis_fuel_short` | 「还差 N 点熔炼值才能合成{产物名}」 |
| 钥匙数量不足（差 1–2 个） | `synthesis_key_short` | 「{钥匙名}还差 N 个（{有}/{需}）」 |
| 金币不足 | `insufficient_currency` | 「金币不足」 |
| 产物枪身未解锁 | `blueprint_locked` | 「先在工坊解锁{产物名}蓝图」 |

**`synthesis_key_short` 是"软提示"而不是硬拒绝**：钥匙不够时，盘面其实还能走 R1 重铸（如果投了武器）或 R3 盲盒（如果 `V ≥ 6`）。所以这个码只在**玩家明确投了碎片但不够**时出现，用于解释"为什么这次没合成出枪"，而非阻止熔炼。

但提示必须说清去处，否则玩家会以为碎片白烧了：

> 「{钥匙名} 还差 2 个（3/5）· 本次将按随机合成处理」

### 4.4 两个边界：混投与差一点

**边界一：远程配方要求盘面「0 武器」。** 投了 2 个 `bp_pistol` 又顺手扔进 1 把步枪时：

- 不满足「0 武器」→ 远程配方不命中
- 也不满足「武器全等于 key_item_id」→ 近战配方不命中
- 最终走 **R1 重铸**（1 枪 + `V ≥ 3`），那 2 个碎片被当燃料烧掉

这是正确行为（玩家投了武器，意图明显是重铸那把枪），但**必须在 UI 上说清**：

> 「盘内有武器，本次按重铸处理 · 2 个豌豆手枪蓝图碎片将作为燃料」

否则玩家会认为"我明明放了碎片为什么不给我手枪"。这条属于 §12 断言 30。

**边界二：钥匙差 1 个但 `V` 已够。** 投 3 个 `bp_charge`（需 5）+ 足量材料，`V = 16 ≥ 6`：

- 走 R3 盲盒（合法），产出随机枪身
- 提示「蓄力萝卜炮蓝图碎片还差 2 个（3/5）· 本次将按随机合成处理」

**不拒绝**。因为玩家确实满足了 R3 的门槛，拒绝等于剥夺他"我就是要烧掉这批货"的自由。

### 5.1 这张表怎么用

**用途一：查"卡住了是设计问题还是运气问题"。** 若玩家普遍卡在 L2（`bp_sniper` 要 4 个），说明 `boss_floor_2 ×5` 的实际掉落率不够，应调权重而不是降 `key_count`。降数量会让整个曲线前移，L3 就失去"长线"的意义。

**用途二：确认"期望获取"与曲线段的时长匹配。** L3 的 8–12 局是刻意拉长的 —— 它是整条曲线的最高峰，必须够远才够重。

**`bp_charge` 的 8–12 局是设计意图，不是失衡。** 蓄力炮是 epic 级的终局武器（`price 350`，全场最贵），它的合成就该是"跨越多局攒一件"的目标。若缩短到 3 局，L3 段会塌成 L2 的延续，曲线失去最后一峰。

### 5.2 硬保底（只对 `bp_charge`）

8–12 局是**平均值**，而平均值不解决"运气极差"：按 `boss_floor_2 ×4` 的权重，存在连续多局颗粒无收的可能。终局目标的卡死比"长"更伤人 —— 长是期待，卡死是绝望。

**规则**：连续 **3 次**通关 `boss_floor_2` 且未获得任何 `bp_charge` 时，第 **4 次**通关必得 1 个。计数在获得任意 `bp_charge` 时清零，跨局持久保存。

| 项 | 值 |
|---|---|
| 保底计数键 | `synthesis_pity.bp_charge` |
| 触发阈值 | 连续 3 次未见 |
| 保底给量 | 1 个（不是 3 个） |
| 清零条件 | 任意途径获得 `bp_charge` |
| 存档 | 与 `BaseData` 同批写盘，随总档保存 |

**为什么只给 `bp_charge`。** 其余八条配方的钥匙期望都在 1–6 局内，最长的一条（`bp_sniper` / `bp_launcher` 4 个）也够不上"卡死"的量级。给所有配方都加保底，会把它变成"可计划的进度条"，曲线的随机张力就没了。**保底是用来兜住运气的下限，不是用来消灭运气。**

**为什么给 1 个而不是补齐。** 补齐等于"第 4 次直接送 5 个"，玩家会感到被施舍；给 1 个则是"这一局至少没白来"，仍然是攒的过程。

#### 5.2.1 实现口径（2026-10-18 落地）

设计只说"通关 `boss_floor_2`"，落地时必须回答「什么算一次」。下面这张表就是那条边界，改它等于改保底本身。

| 项 | 口径 | 为什么 |
|---|---|---|
| 一次机会的判据 | 本局**击败过至少一个首领**（`Dungeon3D._boss_defeated_rooms` 非空）**且成功撤离** | —— |
| 为什么不是"进过 boss 层就算" | 进图 → 走到撤离点 → 二十秒速撤，就能把计数刷满 | 保底是兜运气下限的，若可刷就退化成"可计划的进度条"，正是 §5.2 要避免的东西 |
| 未见怎么记 | 击败首领 + 成功撤离 + 结算物里没有 `bp_charge` → 计数 +1 | 死亡那局没带出任何东西，不该被记成"白打一次"，但也不该被记成"见过" |
| 本局拿到了 | 计数清零，**哪怕这局没打首领** | 事实优先：已经拿到手了，计数继续留着会让下一次保底提前触发 |
| 补发怎么给 | 撤离路径 → 追加进本局结算物（待领取栏）；**带物返航路径 → 直接进背包**，背包满则退回待领取栏 | 两条路径的"战利品"通道本来就不同，保底必须跟着各走各的，否则一条路径上会凭空消失 |
| 记账与写盘 | `BaseManager.plan_synthesis_pity()` 先记账（内存）→ `commit_run_settlement()` 随行动结算一次性落盘 | 单独写盘会出现"计数推进了但战利品没进来"的中间态 |
| 写盘失败 | 计数**整体退回**记账前 | 不能让一次保存失败白吃玩家一格保底 |
| 同一结算重试 | 返回同一份结论，**不二次记账** | 重试是同一局的同一次机会 |
| 玩家可见 | 工作台目录页 L3 行显示「保底 n/3」；结算状态行出现「保底补给 1 件」 | 看不见的保底救不了绝望 —— 玩家会以为这枪根本刷不出来 |

**`boss_floor_2` 与"任意首领"的差别。** 落地按"任意首领"判，比文档原文更宽。原因：保底的作用是**兜住终局目标的获取下限**，而不是精确复刻某一层的掉落表；把判据绑死到某一层的房间 ID，会让关卡改版（增删 boss 房、调整层号）时保底悄悄失效，而且失效是静默的。放宽到"任意首领"后，最坏情况是玩家在别的 boss 层也攒进度 —— 那仍然是他打来的。

## 6. 表 C｜兴趣曲线分段

横轴用**累计合成次数**而不是游戏时长：玩家节奏差异太大，用时长会把"每局炼 3 次"和"每局炼 1 次"的玩家画到同一条曲线上，失去意义。

纵轴是**情绪强度**（0–100），用于设计评审时对齐"这一段该让玩家多兴奋"，不是运行时数值。

「配方密度」= 本段每多少次给一条**新配方**。它是这条曲线真正的骨架，也是唯一可验收的量。

| 段 | 累计次数 | 本段配方 | 条数 | 配方密度 | 首次体验（这一段唯一的那一次） | 新维度 | 情绪目标 | 强度 |
|---|---|---|---|---|---|---|---|---|
| **L0 Hook** | 1–3 | PISTOL / SHOTGUN / GREATBLADE | 3 | 每 1 次 | **第一次"材料变成了枪"** | 从无到有 | 惊喜 | 72 |
| *L0 谷* | 4–5 | —（T1 钥匙还差） | 0 | — | — | — | 等待 | 45 |
| **L1 Promise** | 6–11 | RIFLE / MG / WARAXE | 3 | 每 2 次 | **第一次"能指定弹种"** | 弹种定向 | 期待 | 75 |
| *L1 谷* | 12–14 | —（rare 钥匙还差） | 0 | — | — | — | 焦躁 | **35** |
| **L2 Payoff** | 15–20 | SNIPER / LAUNCHER | 2 | 每 3 次 | **第一次"能造出 rare 枪"** | 稀有度跨档 | 掌控 | 88 |
| *L2 谷* | 21–23 | —（epic 钥匙还差） | 0 | — | — | — | 执着 | 40 |
| **L3 Chase** | 24–40 | CHARGE | 1 | 每 5 次 | **第一次"能造出 epic 枪"** | epic + 配件预装 | 渴望 | **95** |
| **L4 Completion** | 41+ | 全部完成 | 0 | — | **第一次"这套东西我玩透了"** | 图鉴收束 | 圆满 | 80 |

**表要这样读**：L3 的「配方密度 每 5 次」只覆盖第 24–28 次 —— 5 次之后 `SYN-CHARGE` 就做完了。第 29–40 次这 12 次**没有新配方**，靠"首次见到金"撑（§6.3）。所以「L3 累计 24–40」（17 次）不等于「17 次都有新东西」，这一点设计评审时最容易看错。

### 6.1 曲线形状为什么是这样

四个硬约束：

1. **L0 不能是最高峰（72，不是 95）。** 开场就把强度拉满，后面没有上行空间，玩家会觉得"后面越来越无聊"。开场只负责"教会玩家这套系统怎么用"。
2. **最高峰在 L3（95），不在 L4。** L4 是收束（80），负责"结束得体面"。把最高峰放在结尾会让玩家在"再也没什么可做"的空虚里结束，而不是在高点。
3. **配方密度必须递增（1→2→3→5）。** 这是兴趣曲线区别于"线性投放"的核心：早期密集反馈建立信任，后期稀疏反馈制造期待。间隔恒定的投放会让玩家在第 5 次就摸清套路。
4. **L1 谷必须是最低的（35）。** 这一段玩家已经"会用"了，新鲜感消退，而 rare 还很远。这是整套系统**最可能流失的一段**，所以 L1 段必须给一个额外钩子 —— 就是"弹种定向"。

### 6.2 "弹种定向"为什么放在 L1 而不是 L2

L1 是低谷，需要一根"不是新配方"的钩子。弹种定向正好是**同一条配方上的新自由度**：`SYN-RIFLE` 产出预装穿甲弹的步枪，`SYN-MG` 产出预装标准弹的机枪。

玩家在第 4–7 次会发现「原来我还能控制弹道」，这比"再多一把枪"更能顶住低谷 —— 因为它改变的是**已有的枪怎么打**，而不是**再多一把**。

### 6.3 L3 靠什么撑住 12 次空窗

L3 段跨 17 次，但只有 1 条配方（5 次就做完），剩 **12 次没有任何新配方**。它靠三层叠加撑住：

| 层 | 内容 | 密度 |
|---|---|---|
| 主目标 | `SYN-CHARGE` 需要 5 个 `bp_charge` | 一次性，8–12 局 |
| 次级目标 | 每次合成都有机会首次见到**紫 / 金**（品质里程碑） | 由概率决定，约每 3 次 |
| 资源目标 | 攒够燃料去搏金（`quality_bonus 7` + 自投稀有材料） | 持续 |

**"首次见到金色"是 L3 真正的兴奋点**，`SYN-CHARGE` 只是它的载体。若把这 12 次空窗交给"再发一条新配方"，那 L3 就变成 L2 的延长，曲线失去最后一峰 —— 空窗是刻意的。这也解释了为什么 L3 的 `quality_bonus` 必须是 7（最高）—— 它要让"金概率"在这一段第一次明显高于 5%。

## 8. 经济校验

合成必须同时满足"玩家觉得划算"和"不能印钞"，这两件事要用**两种不同的度量**来看。

### 8.1 金币流（玩家实付）—— 全部正收益

下表「基础净得」按 `产物商价 − 合成金币` 算（蓝品质口径，玩家最容易心算的那笔）；「期望净得」再乘上该段品质期望倍率。

| 配方 | 合成金币 | 产物商价 | 基础净得 | 期望倍率 | 期望净得 |
|---|---|---|---|---|---|
| SYN-PISTOL | 25 | 70 | +45 | 1.032 | **+47.3** |
| SYN-SHOTGUN | 40 | 110 | +70 | 1.032 | **+73.6** |
| SYN-GREATBLADE | 60 | 165 | +105 | 1.032 | **+110.4** |
| SYN-RIFLE | 55 | 150 | +95 | 1.037 | **+100.5** |
| SYN-MG | 65 | 180 | +115 | 1.037 | **+121.6** |
| SYN-WARAXE | 90 | 240 | +150 | 1.037 | **+158.8** |
| SYN-SNIPER | 80 | 220 | +140 | 1.041 | **+148.9** |
| SYN-LAUNCHER | 90 | 250 | +160 | 1.041 | **+170.2** |
| SYN-CHARGE | 125 | 350 | +225 | 1.047 | **+241.3** |

这才是玩家算的账：**「花 125 金币换一把 350 的枪」**。碎片是打出来的凭据，不是买来的商品 —— 它的成本是战斗时间，不是金币。

**注意「期望净得」不随段递增**（`SYN-GREATBLADE` 110.4 > `SYN-RIFLE` 100.5）。这不是配平失误：因为金币占比被锁在 36%，期望净得就等于 `商价 × (E − 0.36)`，**天然跟着商价走而不是跟着段走**。断刃（165）确实比步枪（150）贵。设计上要保证的是"每条都划算"，不是"越晚越划算" —— 后者会变成"只做最后一条"。

### 8.2 凭据流（真实成本）—— 时间

| 配方 | 钥匙消耗 | 期望局数 | 摊到每局 |
|---|---|---|---|
| SYN-PISTOL / SHOTGUN | 2 碎片 | 1–2 局 | 1 局 ≈ 1 把 |
| SYN-RIFLE / MG | 3 碎片 | 2–3 局 | 1 局 ≈ 0.4 把 |
| SYN-SNIPER / LAUNCHER | 4 碎片 | 4–6 局 | 1 局 ≈ 0.2 把 |
| SYN-CHARGE | 5 碎片 | 8–12 局 | 1 局 ≈ 0.1 把 |

**曲线就活在这张表里**：早期一局一把枪，后期十局一把枪。金币流恒定为正，所以玩家不会觉得"亏"；凭据流递增，所以"好东西要攒"。

### 8.3 印钞防护：**全部可卖**（业主 2026-10-18 裁决）

**所有炼金产物都能正常出售**（`base_sell_price = 商价 × 50%`），包括 R0 合成产物。
这一条推翻了我前两版的两条结论（"全部禁售"→"只 R0 禁售"→"全部可卖"），所以必须把账算清。

#### 为什么"可卖"不会变成印钞机

关键在于**碎片本来就能卖钱**。`BaseShopService.get_sell_price()` 只读 `base_sell_price`，
不检查 `base_shop_enabled` —— 也就是说玩家早就可以把 `bp_pistol` 按 25 金币卖掉。

于是"合成再卖"要和"直接卖碎片"比：

| 配方 | 直接卖钥匙 | 合成后再卖（净） | 差 |
|---|---|---|---|
| 手枪 | 2 × 25 = **50** | +11.1 | **−38.9** |
| 喷壶 | 2 × 30 = **60** | +16.8 | **−43.2** |
| 步枪 | 3 × 40 = **120** | +22.7 | **−97.3** |
| 机枪 | 3 × 45 = **135** | +28.3 | **−106.7** |
| 狙击 | 4 × 60 = **240** | +34.5 | **−205.5** |
| 榴弹 | 4 × 65 = **260** | +40.1 | **−219.9** |
| 蓄力炮 | 5 × 100 = **500** | +58.2 | **−441.8** |

**七条碎片链里，合成再卖全部劣于直接卖碎片。** 换句话说：如果玩家想把这批凭据换钱，
他早就有更划算的渠道。合成卖枪不是"新开的口子"，而是**一条更差的兑换路径**。

所以允许出售的净效果是：玩家可以"用凭据换一把枪自己用"，也可以"把枪换成钱止损"，
但**没有任何一条路径能让他把凭据变成更多钱**。

#### 唯一的边际：近战链的断刃

| 配方 | 直接卖钥匙 | 合成后再卖 | 差 |
|---|---|---|---|
| 断刃 | 棒球棍 22.5 | +25.2 | **+2.7** |
| 裂甲斧 | 断刃 82.5 | +34.4 | −48.1 |

断刃有 **+2.7 金币**的边际。这个口子不值得为它设计任何限制：

- 赚 2.7 需要消耗一把棒球棍 + 60 金币的现金流；
- 棒球棍在基地买要 45 金币 ⇒ `45 + 60 = 105` 的支出换 85.2 的回款 ⇒ **买棒球棍去刷是净亏 19.8**；
- 只有"战局里捡到的免费棒球棍"才有这 2.7 的边际，而棒球棍是普通怪最常见的掉落之一 ——
  用一次掉落换 2.7 金币，低于一只普通怪自己的掉落（4–20 金币）。

#### 三条随机配方本来就在亏

作为对照，R1/R2/R3 允许出售也从来不是问题：

| 通路 | 典型投入 | 现金总支出 | 卖出回款 | 净 |
|---|---|---|---|---|
| R1 重铸 | 棒球棍 + 3 标准弹（135） | 176 | 23.2 | −152.8 |
| R1 重铸 | 蓄力炮 + 3 标准弹（440） | 572 | 180.7 | −391.3 |
| R2 融合 | 步枪 ×2（300） | 420 | 79.3 | −340.7 |
| R3 盲盒 | 6 标准弹（180） | 270 | 52~94 | −176 ~ −218 |

它们的投入物是**买得到也卖得掉**的实物，估值已经计入费用基数，所以每做一次都亏。
允许出售只是给玩家一条"赌输了还能拿回一点"的止损路。

#### `alchemy_born` 保留，但不再影响售价

`alchemy_born = true` 仍然写进产出物品字典，它现在只承担一件事：
**标记来源**（图鉴统计、以及未来"炼金产物不可上架商店"这类如需再加的限制）。

UI 不再显示"不可出售"提示 —— 既然能卖，就不该有这行字。

#### 合错了怎么办：两条出口，不做分解

产物全部可卖之后，"合出一把用不上的枪"有两条出口：

| 出口 | 拿回什么 | 代价 |
|---|---|---|
| **卖掉** | 商价 50% | 失去这把枪 |
| **当燃料** | 按 `rarity` 计稀有度分（epic 枪 = +4 分） | 失去这把枪，但抬高下一把的品质 |

**仍然不做"分解回 50% 碎片"。** 三个理由：

1. **会拆掉合成的重量。** 碎片攒够了就合、合错了退回一半、再合 —— 合成从"决定"退化成"重试"，L3 那种"攒了 10 局，现在要按下去了"的紧张感会消失。
2. **碎片是凭据，不是货币。** 能回流的东西迟早被玩家当成可兑换资源，而不是"我在为一把枪攒东西"。
3. **两条出口已经够了。** 卖掉能止损，当燃料能进步，不需要第三条"退货"。

补一条产品判断：如果实测出现"玩家合出重复枪后完全无事可做"，那说明**配方重复产出**才是问题（玩家已经在攒第二把同样的枪），应该调整的是 `key_count` 与目标，而不是加分解。

### 8.4 为什么不用"按投入估值计费"

R1/R2/R3 用的是 `coin_cost = max(min, ceil(投入估值 × rate))` —— 因为它们的投入物不固定。合成不能这么做：**合成配方的投入物是固定的**，按估值算会让"同样两条碎片，因为玩家顺手多丢了几件垃圾而涨价"，玩家会觉得被罚。

合成用**固定金币价**，并在文档里锁定 `coin_cost / product.price ≈ 0.36` 这个比例预算。

### 8.5 零价材料：算 8.3 时发现的第二个口子

费用按"投入估值 × rate"计，而全库有 **3 件 `price = 0` 的物品**（`item_flashlight_*` 手电模块）。它们当燃料时估值为 0，费用只落到最低价：

| 投入 | 估值 | 费用 | tier3 池均值产出 | 卖出 | 净 |
|---|---|---|---|---|---|
| 6 件零价物品 | 0 | 40 | 187.1 | 93.6 | **+53.6** ❌ |

**目前打不通**，因为这三件 `stack = 1`、全库只有 3 件，凑不满 R3 的 6 点熔炼值。但这是**靠数量限制偶然堵住的**，不是靠规则堵住的 —— 一旦后续加一件第四件零价物品，它就通了。

**裁决：两条一起加。**

1. **合成钥匙必须 `price > 0`**（进断言）。钥匙是"稀缺凭据"，凭据不该是零价物。
2. **`WeaponForge.item_value()` 对 `price ≤ 0` 的物品做稀有度兜底**：按 `common 10 / uncommon 15 / rare 25 / epic 40 / legendary 60` 估值。这样零价物当燃料时，费用跟着上来，不再有"0 估值换高价值产出"的路径。

兜底价刻意定得比 `base_sell_price` 更低（售价是商价一半），这样"零价物当燃料"既不划算也不吃亏，只是不再免费。

## 9. 产出规格

### 9.1 品质

```
P(grade) = grade_probabilities(weapon_count = 0, rarity_points = quality_bonus + 燃料稀有度分)
```

- `weapon_count` 恒为 0（合成盘上没有蓝本武器，近战链的钥匙武器被消耗，不参与蓝本计数）。
- `quality_bonus` 作为虚拟稀有度分叠加到玩家自投材料的稀有度分上。
- 蓝权重地板 0.05 照常生效。

实算（不含玩家自投材料）：

| 段 | `quality_bonus` | 蓝 | 紫 | 金 |
|---|---|---|---|---|
| L0 | 0 | 70.0% | 25.0% | 5.0% |
| L1 | 2 | 66.6% | 27.0% | 6.4% |
| L2 | 4 | 63.2% | 29.1% | 7.7% |
| L3 | 7 | 58.3% | 32.0% | 9.7% |

**L3 的 9.7% 是"配方自带"的，玩家再投 3 件 epic（+12 点，合计 R=19）可推到 17.3%。** 这是 L3 段唯一值得反复做的赌局。

### 9.2 弹种

| 配方段 | 规则 |
|---|---|
| 有 `preload_bullet` | 产物**固定**装该弹种，且 `bullet_module_locked = false`（可拆换） |
| 无 `preload_bullet` | 走 `WeaponForge.roll_bullet(投入模块, 枪自带弹种)`，与 R1/R2 一致 |
| 近战 | 恒为空（`melee_weapon` 没有弹药槽） |

**预装弹种必须可拆换。** 若锁死，`SYN-RIFLE` 就变成"只能用穿甲弹的步枪"，玩家会觉得被限制；定向的价值在"默认给你一个合理的弹道"，不是"只能这样"。

### 9.3 配件

`preload_attachments > 0` 时，从该枪身实际支持的槽位（`BlueprintRegistry.ROOT_ATTACHMENT_SUPPORT`）与工坊已解锁配件池的交集中抽，不重复占槽。规则与 R2 融合的随机配件完全相同，复用 `WeaponForge.roll_attachments`。

### 9.4 产出实例

| 字段 | 值 |
|---|---|
| `drop_grade` | 按 §9.1 掷骰 |
| `fate_upgrades` | 空（不继承命运卡） |
| `bullet_module_locked` | `false` |
| `alchemy_born` | `true`（仅作**来源标记**：图鉴统计用。**不影响售价**，产物正常可卖） |
| `created_recipe_id` | 命中的 `recipe_id`，写进物品字典供图鉴统计 |

`created_recipe_id` 是新增字段，用于"图鉴完成度"（§10.3）。没有它就无法区分"我合成过这把"和"我捡到这把"。

## 10. 界面：合成目录

### 10.1 入口与位置

合成目录是武器改造台里的**第二页**（页签：`熔炼` / `合成目录`）。不新建独立面板 —— 玩家在同一个台子上看"能做什么"和"去做"，切换成本最低。

页签位于页头标题下方，用棱镜的 **1px 下划线**标记当前页，不用按钮底色 ——
底色会变成"实心卡片"，那是棱镜明确禁止的（规范 §1.2 铁律 1）。

**页脚随页签切换。** 目录页隐藏「本次熔炼读数」与「熔炼按钮」，状态栏换成一句汇总：

> 「配方 9 条 · 已完成 0 · 盘面钥匙已齐 1 条」

理由：目录页上摆着「定向合成（缺燃料）」的读数是误导，玩家会以为要在这个页面操作。
`ESC 关闭` 保留（它是面板级动作，不属于任何一页）。

**目录页的数据源是盘面，不是背包。** 「有 / 需」统计的是玩家**已经投进去**的钥匙 ——
那才是"现在能不能按下熔炼"的判据。看背包会把"背包里有 5 个但盘上只有 2 个"显示成 5/5，
玩家按下去才发现不够。

⚠️ 读盘面时必须走 `_tray_probe_items()`，不能直接读 `entry.item`：
堆叠数单独存在 entry 的 `count` 字段里，直接读会丢掉它 ——
表现是"盘面上明摆着 x2，目录却说 1 / 2"。这个 bug 在实现时真出现过一次。

### 10.2 每条配方的呈现

```
┌──────────────────────────────────────────────────────────┐
│ L1 · 3 / 9                                               │
│ ┌────┐   步枪蓝图碎片 ×3 / 3                    ✓ 可合成  │
│ │步枪│   ────────────────▶  燃料 9 · 金币 55              │
│ └────┘   步枪 · rare · 预装穿甲弹                          │
└──────────────────────────────────────────────────────────┘
```

| 元素 | 规则 |
|---|---|
| 段标题 | `L0`–`L3` + 本段进度 `已完成 / 本段总数` |
| 产物图标 | 用 `ui_item_model_icon` 的 3D 预览，与背包一致 |
| 钥匙进度 | `有 / 需`。够了显示 `value` 白，不够显示 `faint` 灰 |
| 门槛行 | `燃料 N · 金币 M`，金币不足转 `PRISM_DANGER` |
| 弹种/配件 | 有预装才显示，一行小字 |
| 状态 | `钥匙已齐` / `缺 N 个` / `已完成` |

**不做 `???(未解锁)` 遮罩。** 本项目的配方全是"钥匙够了就能做"，没有前置解锁条件；
遮起来只会让玩家以为漏了什么。全九条从第一次打开就完整可见 —— 这是刻意的：
**目录的价值是"让我知道要攒什么"，藏起来就没有意义。**

### 10.3 已完成标记与图鉴

配方完成后打 ✓，并按 `created_recipe_id` 统计全局完成度。集齐 9 条时，页脚出现一行收束文案（L4）：

> 「炼金的九种可能，你都见过。」

**不做全屏成就弹窗。** 这套系统的收束应该是"安静地承认你做完了"，而不是再发一波奖励 —— 再发奖励会让"做完"显得像"又开了一个任务"。

### 10.4 未解锁的呈现

未解锁配方显示为 `???` + 灰掉的门槛，**但保留钥匙图标轮廓**。让玩家知道"这里有东西，而且它要某种碎片"，比完全隐藏更有牵引力。

## 12. 验收断言

新增 `verify_synthesis_catalog`（与 `verify_weapon_forge` 同批运行）。编号连续，不再用 `6½` 这种插入式编号 —— 引用会随编号漂移。

### 结构与一致性

1. 每条配方的 `key_item_id` 必须存在于 `ItemRegistry`。
2. 每条配方的 `product_id` 必须存在于 `BlueprintRegistry` 的 gunbody 池。
3. `curve_tier` 必须等于产物枪身在 `BlueprintRegistry` 的 `tier`（工坊解锁与曲线段不能错位）。
4. 九条配方的产物集合 = 十把非初始武器 **减去** `weapon_baseball_bat`（它是钥匙不是产出），无遗漏、无重复产物。
5. 钥匙白名单：只允许 `blueprint` 与 `melee_weapon`。不得使用消耗品 / 电池 / 弹种模块 / 可装配件（它们有别处用途，当钥匙会让玩家纠结）。
6. 合成钥匙必须 `price > 0`（零价物不能当凭据，见 §8.5）。
7. 近战配方 `key_count` 必须为 1（≥2 会被 R2 截走）。
8. 近战链单向无环：`weapon_baseball_bat → weapon_greatblade → weapon_waraxe`，任何配方的产物不得反向成为其前置配方的钥匙（图可达性校验，存在环即失败）。

### 经济

9. `coin_cost < product.price`，且 `coin_cost / price` 落在 `0.30–0.40`。
10. `fuel_min ≥ 6`（定向不得比盲盒便宜）。
11. **全部炼金产物都可正常出售**（`base_sell_price = 商价 × 50% > 0`），含 R0 产物；`alchemy_born` 仅作来源标记，**不得把 `base_sell_price` 置 0**。
12. `item_value()` 对 `price ≤ 0` 的物件按 rarity 兜底（`common 10 / uncommon 15 / rare 25 / epic 40 / legendary 60`），且兜底后"零价物当燃料"的费用不再落到最低价。
13. **印钞回归**：按 §8.3 的七行组合逐一复算，`R1/R2/R3` 的"卖出差额"必须全部为负；**且七条碎片链的「合成再卖」必须全部劣于「直接卖钥匙」** —— 这是"可卖"成立的核心依据。近战断刃允许 ≤3 金币的边际，但买棒球棍去刷必须净亏。
14. 金币流净得（`price × E(品质) − coin_cost`）恒为正，且 `净得 / price` 落在 `0.60–0.70`。**不校验"随段递增"** —— 占比恒定时净得必然跟随商价，而商价不随段单调（断刃 165 > 步枪 150）。

### 判定

15. R0 早于 R1：`1 把棒球棍 + V=4` 判 R1 重铸；`+ V=6` 判 R0 合成。
16. 多条命中取 `curve_tier` 最高，且确定性（同投入同结果）。
17. 钥匙够但 `V` 不足返回 `synthesis_fuel_short`，**不降级**成 R3，且盘面与金币逐字节不变。
18. 钥匙不足返回 `synthesis_key_short`，并给出"还差 N 个"。
19. 反向对照：把 `quality_bonus` 全清零，L3 的金概率必须掉回 5%，分布断言变红。

### 保底

20. 结算期三分支（`SynthesisCatalog.resolve_settlement`）：
    - 没击败首领 → 计数**不动**（速撤刷不满保底）；
    - 击败首领、结算物里没有 `bp_charge` → 计数 +1；带出 `bp_rifle` 等其它钥匙**不清零**；
    - 连续 3 次未见 → 第 4 次返回 `granted == "bp_charge"` 并立即清零。
    - 本局带出了 `bp_charge` → 置 `cleared` 并清零，**哪怕这局没打首领**。
21. 保底**只**作用于 `bp_charge`：`PITY_KEYS == ["bp_charge"]`。其余八条配方不得有保底逻辑。
22. **落地验收**（端到端事务）：`plan_synthesis_pity` 必须产出一件**真物品**（`id == "bp_charge"`，不是只报 ID）；同一结算重试拿到同一份结论且不二次记账；`commit_run_settlement` 之后该物品必须进入 `extraction_loot`（待领取栏）、计数清零；反序列化重载后 `synthesis_pity` 仍在 —— 说明它真的进了存档，而不是只在内存里。
23. **存档失败必须整体退回**：`force_save_failure_for_test` 下提交失败，保底计数要回到记账前的值（不能白吃玩家一格）。

### 曲线

24. 每段至少 1 条配方（`L0..L3` 全覆盖）—— 缺一段即曲线断。
25. 配方密度严格递增：`L0` 每 1 次、`L1` 每 2、`L2` 每 3、`L3` 每 5。以表 C 为真源逐值校验。
26. `quality_bonus` 随段单调不减（0 ≤ 2 ≤ 4 ≤ 7）。
27. 钥匙数量随段单调不减（2 ≤ 3 ≤ 4 ≤ 5）；近战链单独校验 1 = 1。

### 界面

28. 合成目录页签存在，且默认停在「熔炼」页。
29. 每条配方行必须同时显示钥匙 `有/需`、燃料门槛、金币、产物名。
30. 未解锁配方显示 `???` 但仍保留钥匙图标轮廓（不得整行隐藏）。
31. 完成后打 ✓，并写 `created_recipe_id` 到产出物品字典。
32. 盘内混投"钥匙碎片 + 武器"时，必须走 R1/R2 且状态栏说明"碎片将作为燃料"，不得静默吞掉。
33. 产物详情**不得**出现「不可出售」提示（全部可卖）；`created_recipe_id` 必须写入产出物品字典供图鉴统计。
34. **端到端事务**：盘上 2 个 `bp_pistol` + 足够燃料，`_execute_forge` 之后必须真的产出 `weapon_pistol`（不是随机枪身）、扣 25 金币固定费、盘面清空、产出带 `created_recipe_id = SYN-PISTOL`、`fate_upgrades` 为空、`base_sell_price > 0`，且该配方进入已完成集合。
35. **目录「有 / 需」必须反映盘面堆叠数**：盘上投 2 个碎片，目录行显示 `2 / 2` 而不是 `1 / 2`（读盘面时必须合并 `count`）。
36. **页脚随页签切换**：目录页下熔炼读数行与熔炼按钮必须隐藏、状态栏显示完成度汇总；回到熔炼页恢复。

## 14. 裁决记录（2026-10-18）

上一版的四条待裁决，业主口径「先按照你的想法来」。以下是结论与依据。

### 14.1 `SYN-CHARGE` 的 8–12 局：保持，加硬保底

**不改 `key_count`。** 8–12 局是 L3 段成峰的必要条件，缩短会让 L3 塌成 L2 的延长。

真正要解决的不是"太长"，是"运气极差时卡死"。加 §5.2 的**硬保底**：连续 3 次通关 `boss_floor_2` 未见碎片，第 4 次必得 1 个。

**为什么不改平均值而改方差**：平均值决定曲线的形状，方差决定玩家的体感。缩短平均值会改形状（不想要），压小方差只会让曲线更可靠（想要的）。

### 14.2 近战第三级：不加，明确终止

近战线就是两级：棒球棍 → 断刃 → 裂甲斧。

不加的理由是**成本结构**：第三级要新增近战枪身（模型 / 动作 / 数值配平），而它带来的曲线增量只有"再多一把"。近战链的定位是"给开局捡到的棒球棍一个去处"，不是长线目标 —— 长线由远程七条承担。

已在 §3.2 写明"近战线到此为止"，避免后来者把它当成"待补的缺口"。

### 14.3 分解出口：不做，卖掉与当燃料已经够

产物可卖之后，"合错了"有两条出口：**卖掉**（拿回商价一半）与**当燃料**（按 `rarity` 计稀有度分，epic 枪 = +4 分）。

不做"分解回 50% 碎片"的理由见 §8.3 末：会把合成从"决定"退化成"重试"，而碎片必须保持"凭据"身份、不能变成可回流货币。

### 14.4 产物可售性：**全部可卖**（业主裁决，推翻我前两版）

这是本次唯一实质改动，而且我在这条上**连错两次**。

| 版本 | 结论 | 错在哪 |
|---|---|---|
| 初稿 | 全部炼金产物禁售，"一致性优先" | 把三条本就巨亏的随机通路也锁死出售 —— 玩家赌输后连残值都拿不回 |
| 第二版 | 只 R0 禁售 | 论证方向对了，但结论仍假设"R0 可卖会印钞" |
| **定稿** | **全部可卖** | —— |

**定稿依据**：碎片**本来就能卖**。`BaseShopService.get_sell_price()` 只读 `base_sell_price`，
不检查 `base_shop_enabled`，所以 `bp_pistol` 早就能按 25 金币出手。于是：

- 2 个 `bp_pistol` 直接卖 = 50 金币
- 合成手枪花 25、卖得 36.1 ⇒ 净 **+11.1**
- **11.1 < 50** ⇒ 合成再卖比直接卖碎片更亏

七条碎片链全部如此（差 −38.9 ~ −472）。**R0 根本不构成印钞口**，
因为它是一条**比现有渠道更差**的变现路径。

近战断刃有 +2.7 的边际，但买棒球棍去刷是净亏 19.8（45 + 60 = 105 支出 vs 85.2 回款），
只有"捡到的免费棒球棍"才有这点边际，低于一只普通怪自己的掉落 —— 不值得为它设计限制。

**代价**：产物不再区分"能卖/不能卖"，`alchemy_born` 退化为纯来源标记。
好处是少一类特例，玩家也不用记"哪种炼金产物能卖"。

### 14.5 顺带发现：零价材料的第二个口子

算 8.3 时发现全库有 3 件 `price = 0` 的手电模块。它们当燃料估值为 0，费用只落到最低价，理论上"0 成本换高价值产出"。

目前靠"全库只有 3 件、凑不满 R3 的 6 点"偶然堵住，不是规则堵住。已加两道：合成钥匙必须 `price > 0`；`item_value()` 对 `price ≤ 0` 按 rarity 兜底（§8.5）。

**这条不是本次需求的一部分**，但它和"能不能印钞"是同一个问题，留着它就是留一个定时炸弹。
