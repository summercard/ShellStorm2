## 二、集合归属

模型集合固定分为 `00_共享骨架`、`01_部件`、`90_预览环境_不导出`。在 `01_部件` 中使用二级集合：

```text
01_部件
├─ 身体
│  └─ 身体__bunny_white
├─ 头部
│  ├─ 头部__bunny_white
│  └─ 头部__chibi_anime
├─ 左手 / 右手 / 左脚 / 右脚
│  └─ 对应部件__bunny_white
├─ 帽子
│  ├─ 帽子__bunny_ears_l
│  └─ 帽子__bunny_ears_r
├─ 眼镜
│  └─ 眼镜__none
└─ 下身配件
   └─ 下身配件__none
```

配件名称必须是 Collection，不得用一个同名 Mesh 冒充文件夹。Collection 的 `slot_id`、`variant_id` 是导出元数据；集合里可放多个 Mesh，共同组成一个配件样式。新增样式复制该样式集合并给予唯一变体 ID。只增加颜色时复用几何与贴图，不重复制作根角色。

当前程序帽子/眼镜仍是已登记的程序占位；`none` 表示没有已制作网格，不代表已经制作完成。后续替换沿用衣柜合法 ID，不能通过美术导入增加玩法槽位。

3. 身体、头、左右手脚、左右耳分别归属对应骨。头部配件跟随 `head`；下身附件挂点继续继承现有 `BodyJoint`。
4. 模型文件保存并关闭编辑事务后，在动作文件重载关联模型；验证骨架签名一致再开始动作制作。

## 四、动作与状态归属

| 动作 ID | 播放方式 | 时间来源 |
|---|---|---|
| idle | 循环 | 表现时钟 |
| moving | 循环，随平面速度调整 | 实际移动速度 |
| dashing | 单次 | 原冲刺表现进度 |
| hurt | 单次 | 原受击恢复进度 |
| locked | 循环 | 已存在的 locked 状态 |
| falling | 播放后保持 | 已存在的 falling 状态 |
| landing | 单次 | 原落地恢复进度 |
| dead | 单次并保持末帧 | 角色死亡进度 |

`Player3D` 状态机输出状态和进度；表现层只选择、采样对应动作。美术动作结束不得发放伤害、结束死亡、解锁角色或切换玩法状态。动作文件禁止 root motion 驱动 `CharacterBody3D`。

瞄准 yaw、武器握持、换弹/射击/蓄力/近战与击飞的实时校正仍是表现约束：其输入来自真实武器与角色数据，不能被离线动画自带的计时器替代。当前基础骨骼动作库与这些约束分别维护；有武器时双手以握持约束为最终结果。灯光/VFX/材质反馈继续读取既有状态。

## 五、导出与严格中转

命名统一为 `chr_<角色>_<部件或用途>_vNNN`、`anim_<角色>_<动作或库>_vNNN`。一个版本包只允许一份模型母版和一份动作母版。生产输出位于 `exports/`，机器账本位于版本包根，资产主账本仍为 `assets/registry/ShellStorm2_美术资产台账_v001.xlsx`。

导出命令（从项目根运行，替换本机 Blender 路径）：

```sh
blender --background --python scripts/blender/export_character_bundle.py -- assets/art/characters/player/chr_player_capsule01_3d/variants/bunny01/production/v009
```

导出器校验骨架签名、绑定和八态完整性，生成模型 GLB、分件 GLB、动作 GLB、动作采样库及 `character_transfer_ledger_v009.json`。其中动作采样库从 Blender 评估后的骨姿势生成；Godot 的刚性节点适配器消费它，标准动作 GLB保留供 Skeleton3D 消费者及跨工具检查。两者必须在同一次导出中生成。

导出后运行 `python3 tools/asset_pipeline/import_character_bundle.py <版本包目录>`。该命令先复算全部源/输出哈希，再生成表现包装；不会自动修改玩家功能场景。对照新旧包围盒与专项通过后，只切换 `Player3D.tscn` 的 Avatar PackedScene 引用。

当前适配器以原程序逻辑计算武器姿势、状态进度和实时反馈，再以导入骨动作确定身体/头/脚/耳和无武器双手的最终姿势。此兼容步骤保留在 `PlayerAvatar3D` 中，尚未将所有武器覆盖动作迁入 Blender；这些覆盖动作仍应列作后续动作制作项，不能把八态基础库当作全部武器动作库。

账本记录：稳定 AssetID、版本、源模型、源动作、骨架 ID/签名、部件与样式、导出文件、每文件 SHA-256、字节数、动作名/时长/循环/帧数、运行时消费者、碰撞所有者、制作尺寸与展示倍率、校验状态。

状态顺序：`authored → exported_pending_godot_validation → validated → active`。未通过签名、哈希、状态/挂点/尺寸验收的包不得标记 active。重新编辑任一源文件，原导出即视为过期；重新导出并验收后再更新台账。不得手工复制导出文件后跳过账本。
