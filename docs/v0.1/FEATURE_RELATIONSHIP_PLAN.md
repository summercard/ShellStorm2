# v0.1 功能关系、文档对齐与解耦跟进计划

工程版本：`0.1.0`；计划修订：r6；建立日期：2026-09-23；本次更新：2026-09-24；新拉取基线：`622d6c4a`；适用范围：当前正式远征主线及已登记的 37 个 FeatureID。

本计划的逐项执行表是[功能关系与解耦跟踪表](FEATURE_RELATIONSHIP_MATRIX.md)。功能身份、状态 Owner、主设计、开发记录和验收入口仍以[模块索引](MODULE_INDEX.md)及[机器注册表](feature_registry.json)为准；本计划记录关系和待办，不另建平行状态源。

## 1. 目标与完成标准

目标是让维护者沿一个 FeatureID 找到：上游输入从哪里来、谁能写权威状态、通过什么命令或事件交给下游、失败由谁收口、正式游戏从哪里进入、哪里验证。允许功能在 Godot 场景或 Autoload 中协作，不要求每项功能都成为完全独立的服务。

一项功能完成本轮治理需同时满足：

1. 跟踪表的关系链、Owner、衔接契约、设计位置和验收入口均可定位；未实现的接口显式标为“目标”。
2. 主设计区分“用户目标设计”“当前实现事实”“尚待裁决”，与当前游戏不一致的**实现描述**按正式运行资产、入口和代码修正；不把未实现的用户设计删掉或默认为已实现。
3. 至少有一个正常路径验收；涉及交易、存档、场景切换的功能还应覆盖拒绝、失败、重试或读档。验收失败记录为红项，不用放宽阈值取得绿灯。
4. 开发记录只写一次交付的事实和证据。历史共享记录可以作为线索，但新改动使用独立交付记录。

## 3. 文档格式与事实对齐规则

已迁移的功能以 `design/` 内设计页为目标规则主源，旧主题页负责施工与实现事实；多个相关功能可共用一页，但须能按 FeatureID 定位。未迁移的旧主题页是临时设计入口，不能称“独立设计已补”。章节统一使用[功能设计模板](../templates/feature_design.md)的字段顺序：`FeatureID/版本/来源/状态 → 玩家目标与范围 → Owner与依赖 → 命令/查询/事件 → 数据与生命周期 → 拒绝与回滚 → 正式接入与验收 → 关联记录`。章节缺某项时写“未实现/待核验”。

本轮文档对齐按以下顺序执行：

1. 从正式入口、当前场景/代码、内容配置和资产台账收集当前实现事实；从现行主设计区分用户目标与工程补充。
2. 建立 `FeatureID → 上游 → Owner → 命令/查询/事件 → 下游 → 存档/资产ID → 验收` 的逐字段对照。一个事实只在其 Owner 的主设计定义，其他文档链接引用。
3. 实现描述与游戏不符时修正实现描述和状态，保留尚未实现的用户设计。若冲突涉及玩法目标或语义不明确，登记“待裁决”，不根据代码自动批准新设计。
4. 使用统一术语：`已核对`、`待核对`、`设计待补`、`契约待补`、`历史记录待定位`；这些是文档治理状态，和 `feature_registry.json` 的实现状态分开。
5. 每次代码、内容或资产变更只更新受影响的主设计、跟踪表、功能注册表和独立开发记录；历史审计保持原时点结论，并在入口提示后续实测。

## 5. 当前基线与限制

- 功能注册表：37 项，其中 complete 2、partial 30、development 3、contract_only 1、source_only 1。这是实现状态，不能直接换算为解耦率。
- 当前可明确独立维护的完整模块为训练场；远征入口是完成的功能级链路。纯楼层计划、换装事务、奖励解析、工坊规则、结算、HUD映射等可局部独立。
- `TowerDescent3D`、`Dungeon3D`、`Player3D`、`BaseManager` 仍是主要编排/状态聚合点；24 个 Autoload 扩大了全局依赖面。现有跨域门禁只覆盖三类已知私有访问。
- 资产账本在新拉取的 `622d6c4a` 上复核为 410 项、9 本分账本、完整性问题 0、拆账漂移 0（敌人账本由12增至13）。此前完整复评的 426/230 和拉取前的 409/0 都是各自时点的结果。
- 上次完整 `aggregate core` 基线为 130 项中 15 项失败；本次战斗与经济交接又注册商人专项 2 项及地面奖励专项 1 项，尚未重新执行整个聚合套件。已知 `verify_full_3d_game_flow` 节点预算及 `verify_3d_parity_core` 邻房流送/节点预算仍红；视觉、目标 GPU、移动端和长测不能由 headless 结果代替。
- 前一修订的5场景批跑为4通过、1失败：剧情历史污染后续开场。现Runner已按场景隔离`user://`；剧情→开场→新档交接3场景批次退出码0。旧失败保留在[当时记录](development/2026-09-23_feature_relationship_pull_alignment.md)，不倒写为历史通过。

本计划仅规定追踪与补全顺序；表中“待补”不意味着立即改动玩法或要求全部功能完全解耦。
