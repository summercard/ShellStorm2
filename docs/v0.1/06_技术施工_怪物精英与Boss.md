- <span style="color:#2E7D32">**[首只正式投放｜2026-08-27]** `elite_rift_boar_armed / 背枪的裂口爬虫` 是当前唯一 `deployed` 精英；每次行动以稳定 `run_seed` 从98F、97F、96F中确定一个目标层，再出现在该层随地图种子随机排布出的首个合法 `ELITE` 房。同一行动不会在三层各刷一只。95F及更深楼层不会从未完成名册生成通用外壳；无可投放精英的精英房降级为普通战斗，Boss房保持Boss单独生成。</span>

### 5.2 精英定义与档案分离

`EliteDefinition` 是数据库内容：名字、基础种类、核心机制、成长方向、夺械转译、投放状态、合法楼层和表现。代码事实源为 `EliteContentCatalog`。`EliteArchiveRecord` 是玩家存档：等级、状态、历史、最近出现、夺取模块、悬赏、成长残留和当前预约，事实源为 `EliteRosterService + BaseData 2.0.elite_archive_records`。

禁止把存档记录直接放在场景节点元数据里；场景节点只保存 `elite_id + encounter_instance_id`。

### 5.3 唯一生成事务

```text
SelectEligibleElite(seed, floor, history)
→ reserve(elite_id, encounter_id)
→ build encounter plan
→ instantiate and bind archive
→ confirm reservation
→ on death/escape/despawn settle archive
→ release reservation
```

同名唯一性以稳定 `elite_id` 为准，不以显示名字符串扫描场景树。游戏崩溃或生成失败后，加载存档时清除没有有效行动事务的陈旧预约。

### 5.4 夺取枪械

1. 记录玩家本次遭遇使用过的枪型内容 ID，以及必要的永久命运槽、子弹和配件能力快照；不取得玩家原始 `weapon_instance_id` 的所有权。
2. 按精英自身转译规则选择可夺取模块。
3. 保存内容 ID、版本和必要数值快照，不保存玩家枪械实例 ID、Node 或 Resource 实例。
4. 下次生成时转换为敌方技能，例如远程弹幕、爆炸区、护盾吸收或召唤武装。
5. UI 和档案展示“夺取来源—转换结果—当前等级”。

<span style="color:#EF6C00">**[Codex补充]** 夺取不应直接复制玩家每秒伤害；以技能模板和强度预算转译，避免高阶玩家制造不可解精英。</span>

### 5.5 首只正式精英内容契约

“背枪的裂口爬虫”仍复用 `melee_chaser` 的生命、导航、碰撞、近战时序与 `armed_rush` 行为，不复制 Brain。`floor_selection_mode=one_per_run_seed` 保证98—96F三选一，楼层规划器继续负责该层精英房位置随机化。正式表现由 `ENM-ELITE-RIFT-BOAR-ARMED-3D` 独立提供：暗红裂口核心、橙色分片甲壳、四爪轮廓、高位双管夺取枪身和青色枪口/裂口能量。GLB只含表现网格与材质，包装场景无碰撞；`EnemyAvatar3D`按 `presentation_scene`加载后关闭通用外壳，`Enemy3D`继续持有原 `melee_chaser` 碰撞事实。

精英头顶条不从 `elite_id` 写死分支，而读取定义中的 `health_bar_profile`：2.05m宽橙框、青色满血/红色低血填充，并在血条上方显示“背枪的裂口爬虫”。普通怪血条与受光文字接口保持不变。后续精英只需扩展 `EliteContentCatalog` 的投放、表现和血条配置，不得复制 `Enemy3D`、`EliteRosterService` 或头顶UI实现。

### 5.6 首只精英成长闭环（2026-08-27）

- “背枪的裂口爬虫”生命降至20%及以下且没有受到致死伤害时进入4.2秒撤离窗；名字变为“背枪的裂口爬虫 · 撤离中”，停止攻击并远离玩家。撤离期间仍可受击和被击杀，不获得锁血或无敌。
- 成功撤离后不产生击杀掉落或精英击杀撤离点，但正常释放精英房清房计数和通路；如果它直接造成玩家死亡，也按成功撤离结算，并记录一次击杀玩家历史。
- 每次成功逃脱只成长一级，上限12级；每级累计生命+8%、接触/技能伤害+4.5%。状态按等级和逃脱次数推进为 `Escaped / Equipped / Growing / RevengeHunter / RegionalBoss / QuasiBoss`。
- `armed_rush` 的副枪追射由内容参数控制：1—4级每3次基础攻击触发，5—8级每2次，9—12级每次触发。该频率成长独立于通用攻击冷却和受光倍率。
- 逃脱时读取玩家当前枪械快照，只保存稳定枪身内容ID、1—3发弹数预算和白名单弹丸特征，最多保留最近3件；不保存玩家 `weapon_instance_id`、Node、Resource或原始DPS。下次遭遇转译为副枪追射弹数与爆炸特征。
- 悬赏按逃脱次数提升至1—5级，对应45/75/115/165/230魂。再次遭遇并击杀后，悬赏作为地面魂掉落，仍需玩家拾取，继续经过当前房间/世界魂倍率。
- 玩家最后伤害来源保存 `elite_id + encounter_instance_id`；只有造成死亡的有效精英来源才获得击杀玩家与逃脱成长，普通怪、环境伤害和过期来源不会误记。

## 7. 怪物与 Boss 三态受光玩法

### 7.1 设计目标与状态契约

所有 `Enemy3D` 实例，包括六种普通怪、唯一精英的 3D 实例和 Boss，都必须拥有独立于 AI 状态、生命阶段和材质表现的受光状态。稳定状态 ID 冻结为：

| 状态 ID | 中文名称 | 判定含义 |
|---|---|---|
| `darkness` | 黑暗中 | 未受到有效太阳直射，也未受到有效人工/随身灯光 |
| `artificial_light` | 受到灯光 | 受到至少一个有效局部灯光照射，且没有太阳直射 |
| `sunlight` | 受到太阳光 | 身体采样点受到主太阳方向光直射 |

状态优先级固定为 `sunlight > artificial_light > darkness`。同一只怪同时处于太阳与灯具照射范围时记为太阳光；太阳被遮挡但仍被灯具照亮时记为受到灯光；两者都无效时记为黑暗中。Boss 的受光状态与 `boss_phase` 正交，切换受光状态不得重置生命阶段、攻击计时或召唤计数。

第一阶段不为三态附加全怪通用伤害、移速或防御倍率，避免未经内容设计就改变全局平衡。受光组件负责给出可靠事实、信号和快照；具体怪物技能按内容表订阅。现有地刺虫显形必须迁移到真实受光事实：受到灯光或太阳直射会显形，完全黑暗时维持伏击；近距离触发和受伤强制显形仍保留。

### 7.2 光源分类

1. **太阳光**：只认关卡显式登记的主 `DirectionalLight3D`，不把 UI 预览灯、资产检查灯、环境色或其他方向补光误判为太阳。
2. **人工/随身灯光**：房间灯、壁灯、路灯、可参与玩法的特殊灯，以及玩家手电筒的环境主聚光与近身环境溢光。玩家手电归入 `artificial_light`，不建立第四种状态。
3. **不参与判定**：`WorldEnvironment` 环境光、背景色、雾光、自发光材质、只照角色层的正面柔光、UI/Viewport 预览灯。它们可以改变画面，但不能改变怪物玩法状态。
4. 每个可参与玩法的灯必须显式加入统一灯光注册组；仅凭节点名称或遍历所有 `Light3D` 猜测类别属于不合格实现。

### 7.3 拟真空间、范围与投影判定

受光判定不得读取屏幕像素、材质颜色或简单的“灯已开启”布尔值，必须使用真实世界空间参数与物理遮挡：

- 每只怪根据当前碰撞体高度建立脚部、躯干、头部三个身体采样点，Boss 和缩放变体随碰撞体同步改变采样高度。
- **太阳直射**：从身体采样点沿主太阳入射方向的反方向发射长距离物理射线。射线在世界静态遮挡层命中屋顶、墙、楼板或其他合格遮挡体时，该采样点处于投影中；没有命中才算太阳直射。不能因为怪物位于“户外房间”就直接判定为太阳光。
- **OmniLight3D**：先检查启用状态、可见性、实际能量、照明层、距离、范围和衰减，再从采样点向灯位发射遮挡射线。
- **SpotLight3D**：除上述条件外，还必须检查光束朝向、锥角、角度衰减和距离衰减。玩家位于怪物附近但手电朝向相反时，不能把怪物判定为受到灯光。
- 局部灯的近身溢光同样必须通过墙体遮挡检测；灯在墙的另一侧不能穿墙改变怪物状态。
- 状态使用身体覆盖率与最低有效照度阈值，不因阴影边缘的单个浮点误差反复跳变。候选状态需连续两次采样一致后提交，死亡或移出场景时停止采样。
- 自身碰撞体必须从射线查询中排除；玩法遮挡层只使用关卡静态世界，不让相邻怪物短暂经过造成整群怪物受光状态闪烁。

可投射视觉阴影但没有物理碰撞的纯装饰网格，无法成为可靠玩法遮挡物。进入正式关卡的屋顶、墙、楼板、遮阳棚和大型实体遮挡物必须同时具备与轮廓匹配的静态物理碰撞；资产验收需要同时检查视觉阴影与玩法射线遮挡。

### 7.4 运行时接口

统一受光组件至少提供：

```text
illumination_state: darkness | artificial_light | sunlight
illumination_state_changed(enemy, previous, current, context)
sun_exposure_ratio
artificial_light_contribution
dominant_light_instance_id
dominant_light_kind: none | sun | omni | spot | flashlight
last_sample_world_position
```

`Enemy3D.get_state_snapshot()` 必须包含这些字段，供自动化、调试 HUD、Boss 行为和后续内容技能使用。存档不保存瞬时受光状态；读档、进房、开门或灯光开关后按当前世界重新计算，避免把旧场景的光照结果带到新场景。

### 7.5 性能与稳定性预算

- 受光采样频率基线为每只怪 8–10 Hz，按实例 ID 错峰，不能让所有怪物在同一帧集中射线。
- 光源列表由注册组缓存；灯具增删时更新，禁止每只怪每次采样递归扫描场景树。
- 局部灯先做距离、锥角、能量和层掩码的廉价粗筛，再按理论贡献排序，只对最可能生效的少量候选发射物理射线。
- 太阳射线和局部灯射线使用固定上限；没有有效灯光候选时不得产生局部灯遮挡射线。
- 灯具关闭、能量归零、移出树、释放或房间卸载后必须安全失效，不保留悬空节点引用。
- 状态切换使用两次采样确认；强制刷新接口用于首次生成、灯光开关和专项测试，避免玩家看到超过一个采样周期的错误状态。

### 7.7 三态战斗效果与临时头顶标识

三态不仅提供事实，还直接进入怪物战斗运行时。效果基线冻结为：

| 受光状态 | 移动速度 | 攻击频率 | 生命效果 | 测试标识 |
|---|---:|---:|---|---|
| `darkness` 黑暗中 | 现有值100% | 现有值100% | 无 | 冷紫色单段标记 |
| `artificial_light` 受到灯光 | 现有值40% | 现有值40% | 无 | 青蓝色双段标记 |
| `sunlight` 受到太阳光 | 现有值100% | 现有值100% | 每秒损失最大生命2% | 暖黄色三段标记 |

“攻击频率40%”按时间频率计算，等价于有效攻击间隔变为原来的 `1 / 0.40`；不能把攻击间隔本身乘0.40，否则会错误加快攻击。移动与攻击修饰只能在计算最终值时应用，禁止反复乘写基础 Profile，避免灯光边缘切换造成永久降速。太阳伤害为独立环境伤害通道，每1秒结算一次、最低1点，可击杀普通怪和 Boss，并正常触发生命条、伤害数字、死亡、掉落和清房事务；不复用武器 DOT，避免覆盖燃烧等持续伤害。

临时验收 UI 挂在现有 `OverheadHealthBar` 根下，并放在血条前方显示中文文字：黑暗为`暗`、人工灯光为`亮`、太阳直射为`太阳`。文字始终面向镜头并随状态立即更新；发布前可由统一调试开关关闭，但测试快照必须保留 `illumination_ui_state / color / text`。

### 7.8 独立怪物 AI 管理器与视野系统

当前 `Enemy3D` 内嵌最近玩家搜索、视线、记忆、搜索和追击判定，不属于合格的独立 AI 管理。正式结构调整为：

```text
MonsterAIManager（全局登记、错峰调度、感知记录、策略选择）
└─ MonsterVisionSystem3D（距离、水平视野角、物理遮挡、目标身体采样）
   └─ Enemy3D（只执行移动、攻击、受击、动画与有限状态切换）
```

`MonsterAIManager` 只返回不可变决策快照，不直接写敌人 Transform、生命或攻击计时；`Enemy3D` 根据快照执行已有 `idle / patrol / alert / chase / search / telegraph / attack`。稳定感知字段至少包含：

```text
awareness: unaware | proximity_contact | sound_contact | visual_contact | flashlight_contact | room_light_search | seek_darkness | lost_contact
engagement: idle | alert | combat
target_instance_id
target_visible
target_position
last_known_target_position
stimulus_position
stimulus_kind
vision_range
vision_angle_degrees
line_of_sight
light_response_policy
decision_age
```

视野水平夹角为120°，动态视距按怪物自身所处环境采用黑暗8.5m、人工灯13.5m、太阳15.5m。4.8m内侧后方接近只产生 `proximity_contact + alert`，仍受墙体遮挡且不授权玩家目标；玩家进入真实视锥并无遮挡后才产生 `visual_contact + combat`。已警觉怪物保留1.15秒最后已知位置记忆；未看见玩家时禁止直接把最近玩家世界坐标写入搜索目标。视野射线排除怪物自身，目标使用躯干采样点，墙体、关闭的门、楼板等静态碰撞可遮挡。

动态进入战斗采用两层模型：房间灯光变化、近距存在、开门与开容器声音只进入 `alert`，怪物先停顿转向并调查事件位置；视觉确认、玩家前向探照灯真实命中或武器实际命中才进入 `combat`。门声半径6.5m、容器声半径8m，实墙后的有效范围缩减到45%；声音事件只传位置，不传玩家引用。未被灯光实际覆盖的怪物不因开灯响应。

玩家武器造成实际命中时，投射物和范围武器必须把攻击者实例传给 `MonsterAIManager`。受击仇恨无视普通视距和视锥，持续8秒并锁定攻击玩家；不能只有伤害数值而丢失攻击来源。房间未激活时继续遵守关卡隔离暂停AI，不允许相邻未进入房间的怪物跨墙追击。

光照刺激规则：

1. 玩家手电主光束或环境溢光真实照到怪物时，AI能追溯该灯光所属玩家。所有怪物先进入警觉；追光型向玩家最后已知位置逼近，避光型短暂朝向来源后优先寻找黑暗。
2. 房间大灯、路灯或信标从关闭变为有效照明时，范围内怪物进入 `room_light_search`，只搜索自身附近和灯具方向，不得因此获得玩家坐标；看见玩家后才转 `visual_contact`。
3. 避光型通过候选方向粗筛与真实受光查询选择可达的黑暗位置；找不到黑暗点时才远离主导灯光，不能直接穿墙或瞬移。
4. 太阳直射不会凭空暴露玩家。避光型会寻找投影，其他类型维持原战斗目标并承受太阳持续伤害。
5. 光源开关、玩家关闭手电、遮挡变化或灯具卸载后，刺激必须按记忆时限自然失效，不能持有悬空光源/玩家引用。

首批策略表：

| 怪物 | 光照反应策略 |
|---|---|
| 小菌猪、壳甲卫兵、炸弹果、Boss | `light_hunter`：手电命中后追向所属玩家；大灯开启后搜索 |
| 孢子射手、蜂巢怪、地刺虫 | `darkness_seeker`：手电命中先警觉来源，随后优先移动到黑暗候选点；大灯/太阳下寻找投影 |

管理器按实例错峰更新感知，普通更新频率8–10Hz；视觉接触、手电命中、灯具开关提供强制刷新。感知系统先做距离和视锥粗筛，只有候选目标才发射视线射线。AI管理记录不进入长期存档，读档后从当前场景重新感知。
