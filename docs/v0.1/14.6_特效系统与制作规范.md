# 14.6 特效系统与制作规范

> 起草人：杰西卡（OpenClaw 主会话）
> 起草日期：2026-09-11
> 状态：**草案 v001 / 等主人拍板**
> 触发：主人要求"特效进行工整的拆分，每个特效作为一个独立的 prefab 文件，prefab 是特效的唯一出口；账本和调用代码读取的是这个 prefab"
> 适用范围：弹壳风暴2 全项目

---

## 0. 一句话原则

**每个特效 = 一个独立 Prefab 文件。Prefab 是特效的唯一出口。**

不论特效内部是脚本生成、动画驱动还是模型嵌入，外部调用代码 **只看见 Prefab**，**不看见**任何 `effect_kind` / `match` 分支或私有枚举。

---

## 1. 三个核心约定

### 1.1 独立 Prefab 原则（硬约束）

- 每个特效的视觉、动画、生命周期、参数配置必须**完整封装在它自己的 `.tscn` 文件里**。
- 禁止使用"一个总脚本 + `match kind` 分支"或"一个空壳 Prefab + 7 套代码逻辑"组织特效——这种结构不允许作为新特效的入口，但允许**逐步重构替换**（详见 §6 迁移计划）。
- 调用代码**只引用**特效 Prefab 的 `.tscn` 路径或 AssetID，**不允许**引用任何特效内部脚本的实现细节。
- 一个特效最多有一个可选的"私有基类"，但基类**不暴露**任何该特效专属的参数入口。

### 1.2 Prefab 是特效的唯一出口（运行时约束）

- 调用方拿到的 API 必须是：`vfx_pool.acquire(VFX-MUZZLE-FLASH-3D, color, size, world_pos)` 这种 **AssetID 路由**形式。
- 禁止 `vfx_pool.acquire("muzzle", color, size, world_pos)` 这种 **字符串枚举分支**形式。
- Prefab 文件可被独立 `preload()`、独立 `instantiate()`、独立池化、独立调参、独立验收。

### 1.3 账本与调用代码读取 Prefab（数据约束）

- **特效账本**（`assets/registry/ledgers/ShellStorm2_特效账本_v001.xlsx`，路径由 `assets/registry/ledger_index.json` 声明）的 **`3D-特效` sheet** 与《资产主表》是特效资产的**唯一登记源**；总目录 `assets/registry/ShellStorm2_美术资产台账_v001.xlsx` 只放索引，不含资产行。
- 每个特效有 **一个且只有一个** AssetID（如 `VFX-MUZZLE-FLASH-3D`）。
- 每个特效有 **一个且只有一个** Prefab 路径（如 `assets/art/vfx/combat_3d/vfx_muzzle_flash_root_top3d.tscn`）。
- 调用代码必须 **从账本登记的 AssetID 或 Prefab 路径读取**，**不允许**重新发明枚举或路径。

## 2. 命名与目录规范

继承 `docs/v0.1/10_资产与内容规范.md` 第 27-36 行的命名约定，特效分类细化如下：

### 2.1 命名

- **AssetID**：`VFX-<SUBSYSTEM>-<EFFECT>-<VIEW>`，**全大写**、**连字符分隔**。
  - `VFX-MUZZLE-FLASH-3D` ✅
  - `VFX-PLAYER-DASH-TRAIL-A` ✅（变体用字母后缀）
  - `VFX-MELEE-IMPACT-3D` ✅
- **Prefab 文件名**：`vfx_<subsystem>_<effect>[_<variant>]_<view>_v<NNN>.tscn`，**全小写**、**下划线分隔**。
  - `vfx_muzzle_flash_root_top3d.tscn` ✅
  - `vfx_player_dash_trail_a_root_top3d.tscn` ✅
- **根节点 class_name**：`Vfx<EffectPascalCase>3D`，**PascalCase**、**不加文件名后缀**。
  - `VfxMuzzleFlash3D` ✅
  - `VfxDamageNumber3D` ✅
- **脚本文件**：`src/vfx/<VfxEffectPascalCase>3D.gd`，**与根节点 class_name 对齐**。
  - `src/vfx/VfxMuzzleFlash3D.gd` ✅

## 3. Prefab 结构标准

每个特效 Prefab 必须包含且仅包含：

```
Prefab root (.tscn)
├── 根节点：Node3D（class_name = VfxEffectBase3D 子类，如 VfxMuzzleFlash3D）
│   ├── @export effect_color: Color
│   ├── @export effect_size: float = 1.0
│   ├── @export lifetime: float = 0.34
│   ├── signal retired(effect: VfxEffectBase3D)
│   ├── func configure(color, size, context) -> void
│   ├── func activate(world_pos, color, size, context) -> void
│   └── func _on_lifetime_expired() -> void
│
└── [可选] 视觉子节点
    ├── SphereMesh / TorusMesh / BoxMesh / SurfaceTool 生成 mesh
    ├── GPUParticles3D（粒子特效）
    ├── AnimationPlayer（关键帧动画特效）
    └── OmniLight3D / SpotLight3D（光照特效，无阴影）
```

### 3.1 根节点契约（VfxEffectBase3D 基类）

所有特效 Prefab 的根节点 **必须继承** `src/vfx/VfxEffectBase3D.gd`：

```gdscript
class_name VfxEffectBase3D
extends Node3D
## 所有 VFX Prefab 的根节点基类。
## 调用方只看见本基类暴露的接口；特效私有逻辑在子类中实现。

signal retired(effect: VfxEffectBase3D)

@export var effect_color: Color = Color(1, 1, 1, 1)
@export_range(0.1, 8.0, 0.1) var effect_size: float = 1.0
@export var lifetime: float = 0.34

var _elapsed := 0.0
var _active := false
var _follow: Node3D = null                    # 可选跟随挂点（context.follow）
var _follow_local_offset := Vector3.ZERO      # 挂点本地空间偏移

func configure(color: Color, size: float = 1.0, context: Dictionary = {}) -> void:
    effect_color = color
    effect_size = size
    _on_configure(context)

func activate(world_position: Vector3, color: Color, size: float, context: Dictionary = {}) -> void:
    _bind_follow(context)                     # 解析 context.follow / follow_local_offset
    configure(color, size, context)
    _active = true
    visible = true
    process_mode = Node.PROCESS_MODE_INHERIT
    global_position = follow_position() if has_follow_target() else world_position
    _on_activate(world_position, color, size, context)
    _elapsed = 0.0

func _process(delta: float) -> void:
    if not _active:
        return
    if has_follow_target():                   # 挂点移动/转身时特效必须贴着它
        global_position = follow_position()
    _elapsed += delta
    _on_tick(_elapsed, lifetime)
    if _elapsed >= lifetime:
        _retire()

func _retire() -> void:
    _active = false
    visible = false
    process_mode = Node.PROCESS_MODE_DISABLED
    _on_lifetime_expired()
    if retired.get_connections().is_empty():
        queue_free()
    else:
        retired.emit(self)

# 子类覆盖点（不要在调用方调用这些方法）
func _on_configure(_context: Dictionary) -> void: pass
func _on_activate(_world_pos: Vector3, _color: Color, _size: float, _context: Dictionary) -> void: pass
func _on_tick(_elapsed: float, _total: float) -> void: pass
func _on_lifetime_expired() -> void: pass
```

### 3.2 私有参数（子类扩展）

子类可在 `extends VfxEffectBase3D` 之后**自由增加**私有 `@export` 参数，但这些参数**对调用方不可见**：

```gdscript
class_name VfxMuzzleFlash3D
extends VfxEffectBase3D

@export_range(0.05, 1.0, 0.01) var _flash_core_radius := 0.18  # 私有，调用方不读
@export_range(0.05, 0.5, 0.005) var _ring_thickness := 0.045

# 调用方依然只看到 effect_color / effect_size / lifetime 三个公共参数
```

### 3.3 context 通用键：挂点跟随（可选）

`context` 是调用方向特效传参的唯一通道。已定义的**通用键**（所有特效都认）：

| 键 | 类型 | 含义 |
|---|---|---|
| `follow` | `Node3D` | 跟随挂点。绑定后特效**每帧**把世界变换贴到该挂点，而不是停在 `activate()` 传入的世界坐标。未绑定、挂点已释放或已移出树时，自动退化为世界锚定（不报错）。 |
| `follow_local_offset` | `Vector3` | 挂点**本地空间**的偏移，缺省 `Vector3.ZERO`（贴着挂点原点）。 |
| 子类私有键 | — | 如枪口的 `forward`、命中爆点的 `normal`，由各子类在 `_on_activate` 中消费，不属通用契约。 |

```gdscript
# 调用方（WeaponModel3D）：枪口花火贴住 muzzle 挂点，角色移动/转向/后坐力时不残留
pool.acquire(
    VfxPool3D.FX01_MUZZLE_FLASH, muzzle.global_position, bullet_color, 0.8,
    {"forward": -global_basis.z, "follow": muzzle}
)
```

三条硬规则（2026-09-21 由业主实机缺陷固化）：

1. **挂点失效不得报错**：`has_follow_target()` 必须同时校验 `is_instance_valid()` 与 `is_inside_tree()`，任一不成立即回落到世界锚定。
2. **跟随目标要选"真正跟着角色动的那个节点"**：枪口花火必须跟 `muzzle` 挂点，**不能跟武器根**。`WeaponModel3D._visual_root` 会被后坐力（`_recoil`）与换弹摆姿逐帧位移，跟根节点会在开火瞬间差一截。
3. **`_follow` 每次 `activate()` 都重置**：池化复借时上一次的绑定绝不泄漏到下一次。

### 3.4 常驻环境特效例外

常驻环境云海由场景拥有，继承 `VfxEffectBase3D`、`lifetime=0`，使用统一 `configure`，随场景释放；不进入瞬时战斗特效池，不因寿命自动回收。静态几何在正式Prefab中冻结，脚本仅驱动材质、时钟和可见性。`VFX-ENV-CLOUD-SEA-3D` 的主场景实例为 `OutdoorClouds`，建筑边界通过context传入；配置时发现布局超出烘焙遮罩，必须用变动建筑的完整包络作保守解析禁云区；最多16区，余量合并，保留其余云可见。离线重烘焙消除旧位置余留空域。目标见[室外云雾设计](design/outdoor_cloud_sea.md)，验收 `verify_outdoor_clouds`。此例外仅适用于场景拥有的常驻环境表现。

### 3.5 宿主持有的持续视觉附件

收音机音符 `VFX-RADIO-MUSIC-NOTES-3D` 由收音机正式 Prefab 的 `MusicNotes` 子实例持有，继承 `VfxEffectBase3D`，`lifetime=0`。附件覆盖自身持续时钟，不使用基类瞬时到期回收，也不进入 `VfxPool3D` 或旧战斗池，避免双生命周期。几何和音符纹理由 Godot 离线生成后冻结在独立 PackedScene；运行时只驱动位置、尺度、透明度及可见性，不拼几何。真实音频 `playing`、收音机状态及楼层有效性共同驱动 `set_emitting`；A/B 切换不重置已有音符，off、离层和退出立即隐藏全部槽位并清空活跃标记。附件禁止碰撞，跟随收音机本地挂点，不依赖世界零高度。专项验收 `verify_base99_radio_music_notes`。

## 4. 注册流程

### 4.1 新建特效 Prefab 的 6 步流程

| 步骤 | 动作 | 文件 |
|---|---|---|
| 1 | 在台账 `3D-特效` sheet 领取 AssetID（参照已有命名） | `.xlsx` |
| 2 | 在 `src/vfx/` 创建根节点类，继承 `VfxEffectBase3D` | `.gd` |
| 3 | 在 `assets/art/vfx/<category>/` 创建 `.tscn` 包装场景，根挂第 2 步脚本 | `.tscn` |
| 4 | 在 `src/vfx/VfxPool3D.gd` 的 `_REGISTRY` 常量中注册AssetID与PackedScene；调用入口为项目Autoload `VfxPool` | `.gd` |
| 5 | 在 `tests/verification/verify_xxx_flow.tscn` 写专项验收测试 | `.tscn` |
| 6 | 在台账登记：Prefab 路径、GLB 路径、Blender 源、功能脚本、碰撞规则、标准尺寸、原点、使用位置、制作状态、版本、备注 | `.xlsx` |

### 4.2 调用约定

调用方代码**只通过** `VfxPool3D` 拿到特效：

```gdscript
# 推荐：AssetID 路由（账本唯一登记源）
vfx_pool.acquire(VfxPool3D.FX01_MUZZLE_FLASH, world_position, color, size)

# 也接受：字符串 AssetID 形式
vfx_pool.acquire("VFX-MUZZLE-FLASH-3D", world_position, color, size)

# 禁止：字符串枚举分支（旧的 effect_kind 形式）
vfx_pool.acquire("muzzle", world_position, color, size)  # ❌ 违规
```

```gdscript
# 直接独立实例化（不在池子里跑）也允许，但仅限一次性 UI 测试场景
var flash := preload("res://assets/art/vfx/combat_3d/vfx_muzzle_flash_root_top3d.tscn").instantiate()
add_child(flash)
flash.activate(world_position, color, size, {})
```

### 3.6 环境鸟群（VFX-POOL / r3）

来源：用户要求每鸟相对上一版放大50%并±10%错落、空中错落飞行和加快振翅、增加桥下塔2上方鸟群、飞行至少10秒且约200米。场景持有三个环境实例，不进瞬时特效池、不持有玩法或存档状态。

`VfxEnvBirdsPlayback` 是裁剪动画与呈现参数的唯一所有者：为每个实例复制并裁剪GLB动画，分别播放7只鸟；每鸟根节点尺寸为导入尺度的0.75倍再乘各鸟0.90–1.10的固定错落系数，重复播放不累乘。地面鸟补偿身根高度，脚底保持屋面接触。空中位移与模型缩放分开，24秒覆盖本地+X 200米，七鸟纵向/横向/高度独立错落并轻微起伏，翼与翼尖以原速度1.35倍采样；不加速整段行程。GLB和Blender母版继续保有原始可编辑动画，运行包装版本v003。

`CrossTowerRoute` 的正式TSCN持有 `FlybyBirdFlock`（20,1.6,-64.5）及 `LowerFlybyBirdFlock`（40,-9,-90），朝向均为Y=0.2rad，自西向东；第二组使用另一编队并延迟5秒。桥下鸟群中心约y=-6.4，屋面约y=-12.3、桥面约y=0。飞行完成时已在中心约100米以外，再隐藏20秒并重播；复位只在隐藏期间执行。100F天台继续持有地面组，24秒演出后隐藏30秒。`play_all/stop_all` 是播放命令，无资源或动画时报告错误；卸载随宿主释放，回滚采用改前逐文件备份。独立入口 `verify_environment_bird_flocks.tscn` 必须检查21只鸟的运动与50%尺度、两组200米/12秒轨迹与135%翼速、错峰与10秒可见性、桥下空域及地面包含性，并以真实渲染复核布局。开发记录见[鸟群细节调整](development/2026-10-12_bird_flock_refinement.md)。


空中200米/24秒（约8.33m/s），为上一版速度50%；整体时间轴延长2倍，但翼轨单独按原135%速度采样，不随平移减速。天台组仅调整尺寸与脚底高度，不拉长落地啄地演出。

### 3.7 枪族弹体几何档位（2026-10-14）

弹体视觉（`VFX-BULLET-*` 全族，含通用弹体 `VFX-BULLET-VISUAL-3D`）的尺寸由**两层**决定：

```
最终尺寸 = 弹种 profile（8 条，见各 VfxBullet<Type>3D._bullet_profile()）
         × 枪身族档位（本节的 4 条，含中性缺省）
```

**为什么分两层**：弹种决定「长什么样」（形状／配色／尾迹构图），枪身决定「多大、多长、有没有生长过程」。同一发穿甲弹装在狙击枪与手枪上，前者更细长；同一把枪换弹种，尺寸档不变。两层正交，互不覆盖。

| 枪身 tags 族标识 | 枪 | scale（各向同性） | axial（沿飞行轴） | grow_from → 1.0 | 观感 |
|---|---|---|---|---|---|
| （中性缺省） | 其余全部枪身 | 1.00 | 1.0 | 1.00（不启用） | 与弹种 profile 基准一致 |
| `shotgun` | 散射喷壶 `bp_shotgun` | **2.00** | 1.0 | 0.42 → 1.0 / 0.30s | 出生 0.84、飞行中线性长到 2.00（「由小变大」的过程） |
| `launcher` | 反胃榴弹筒 `bp_launcher` | 1.55 | 1.0 | 1.00（不启用） | 整体大一圈的重型弹药 |
| `sniper` | 弹弓狙击 `bp_sniper` | 0.95 | 2.0 | 1.00（不启用） | 横向收细 + 轴向拉长 ⇒ 净长 1.90 倍，细长锐利 |

**取值口径**：`axial` 只沿飞行轴拉伸、不放大横向 —— 要的是「长」而不是「大」。狙击档同时把横向收到 0.95，避免拉长后显得臃肿（净长 = 0.95 × 2.0 = 1.90 倍基准）。榴弹档只放大不拉长，保持圆钝。

**霰弹档的第二轮口径（2026-10-14 晚）**：业主「散射喷壶的子弹太小了，出生和结束都增加 2 倍」⇒ `scale: 1.00 → 2.00`，`grow_from` 是**比例**故保持不变 —— 出生 `0.42→0.84`、长满 `1.00→2.00`，两端同步翻倍且过程感（0.42 的相对幅度）不变。副作用需知悉：霰弹枪弹体（2.00）现居八档之最，**大于榴弹档（1.55）**；这是业主要求的直接结果，若需恢复「榴弹最大」的次序，把 `launcher.scale` 调到 `> 2.00` 或回调 `shotgun.scale` 即可。

**真源与链路**（真源单点，不在下游重复判断）：

```
WeaponModel3D.BULLET_GEOMETRY_BY_GUN_TAG   ← 唯一真源，键 = 枪身 tags 的族标识（不是 gun_id）
  → WeaponModel3D._resolve_bullet_geometry(gun_tags)
  → projectile_config["gun_bullet_geometry"]
  → Projectile3D._gun_bullet_geometry（configure 读取；子投射物继承）
  → activate() 的 size 参数（并入 scale）与 context（axial_scale / grow_from / grow_duration）
  → VfxBulletBody3D._apply_geometry_scale() / _growth_factor()
```

**键按「族」而非 `gun_id`**：新增同族枪身只要打对 tag 就自动继承，不必往表里加 id 分支。逐 `gun_id` 硬编码会随枪数增长腐烂（`_apply_gun_behavior_tags()` 与 `_critical_chance` 已是这类历史包袱，新模式不复制它）。

**轴向拉伸只落各件自己的局部长轴**：弹芯／外壳（capsule，局部 Y 为长轴，节点自身绕 X 转 −90°）与尾迹锥段（局部 Y，转 +90°）各自设 `scale.y = axial`，尾迹段距同步乘 `axial`；**不写父级 `_body_root` / `_trail_root` 的 scale**。原因：父级非均匀缩放 × 子级旋转 = **剪切变形**，黑洞弹的 `spin` 尾迹旋转会立刻暴露。弹壳 v002.4 踩过同源问题（§5.5.1 坑 3），此处按同一条纪律处理。

**生长包络是确定性的**：`_growth_factor()` 只读累计飞行时间 `_flight_time`，脚本内不出现 `randf()` —— 与弹壳随机化同一条纪律：**被逐帧断言驱动的视觉对象必须确定**。霰弹以外的枪 `grow_from = 1.0`，包络整体不启用，逐帧外观与改动前一致。

**复位契约**：`configure()` 每次按 context 重算三项并回落中性缺省；`deactivate()` 显式清零 `_axial_scale / _grow_from / _grow_duration / _flight_time` 并回写几何 —— 池化复借的下一发不得继承上一发的枪身档位。`get_presentation_snapshot()` 增补 `axial_scale / core_axis_scale / grow_from / grow_duration / flight_time / growth_factor` 供验收读取。

**纯视觉边界（含一处实现修正）**：本档位不改伤害与射程、不引入碰撞体（§8 反模式）。

⚠️ **碰撞半径与视觉倍率必须分离**：`Projectile3D` 里倍率原只有一个 `_visual_scale_factor()`，碰撞球半径也曾复用它 —— 于是霰弹 ×2 会把判定半径从 `0.12` 悄悄抬到 `0.24`（判定面膨胀 4 倍），**与「纯视觉」的声明不符**。现拆为两个出口，此后不得再合并：

| 出口 | 组成 | 用途 |
|---|---|---|
| `_visual_scale_factor()` | 弹种 × 命运 × **枪身族** | 传给 `VfxBulletBody3D.configure(size)` |
| `_collision_scale_factor()` | 弹种 × 命运（**无枪身族**） | 碰撞球半径 = `0.12 ×` 它 |

为什么碰撞里保留弹种倍率（气球弹 `1.55`）：那是**改动前既有**的口径，动它等于动既有平衡；枪身族倍率是新增维度，不进碰撞。这条分离由验收的正面断言钉住（霰弹 ×2 后 `collision_radius` 必须恒为 `0.12`，反向对照验证过泄漏会变红），不靠注释说明。

弹体视觉仍由 `Projectile3D` 持有、随 `ProjectilePool3D` 回收，**不进 `VfxPool3D`**（§1.2、§3.5）。

**弹体规模与低面数档（2026-10-14 业主：「减面，减到 100 个面以下先」）**

分段参数**不靠估算**，取值依据是实测扫描（探针 `_scratch/probe_mesh_lod_sweep`）：

| 图元 | 配置 | 三角面 | 备注 |
|---|---|---|---|
| `CapsuleMesh` | rings=0 | 24 | = 圆柱 + 2 片平盖扇 |
| `CapsuleMesh` | rings=1 | 48 | 圆头要价 48 面/件 |
| `CylinderMesh` | rings=0 | **16** | 同轮廓下**严格省于** `CapsuleMesh(rings=0)` |
| `CylinderMesh`（锥，`top_radius=0`） | rings=0 | **12** | 尾迹锥 |
| `SphereMesh` | rings=1 | 16 | 最小有效值（rings=0 无效） |
| `BoxMesh` | — | **12** | 全表最省 |

**关键发现**：`CapsuleMesh` 的圆头来自 `rings`，而 `rings=0` 的「胶囊」不过是平盖圆柱再贵 8 面。100 面预算买不起圆头（两件就要 96 面）⇒ **弹芯与外壳一律改用 4 边棱柱**（`CylinderMesh`，径向 4 段），轮廓与 `rings=0` 的胶囊一致但更省。分段常量集中在 `VfxBulletBody3D` 顶部（`MESH_SEGMENTS` / `MESH_RINGS` / `SPHERE_SEGMENTS` / `SPHERE_RINGS`）与 `VfxBulletVisual3D._SEGMENTS`，改一处即全族生效。

|---|---|---|---|---|---|---|
| standard / balloon / shared | 732~792 | **44** | −94% | 3 | 0.560 / 0.518 / 0.600 × 0.150~0.236 | 1.12 / 1.04 / 1.20 |
| piercing | 864 | **56** | −94% | 4 | 1.140 × 0.088 | 2.280 × 0.176 |

八弹种均值 **61.3 面 / 4.44 件**（改前 **819** 面），极值 44~80，**全部 < 100**。**缩放不改变面数**，故上表在任一枪身档位下都成立。**霰弹枪一次 5 发**（`bp_shotgun.projectile_count`）⇒ 标准弹下 `44 × 5 = 220` 面（改前 `732 × 5 = 3660`），是弹体视觉里最重的单次开销。

构件层面的取舍（都写进代码注释，不靠口头约定）：
- **滴珠改 `BoxMesh`**（12 面）。滴珠世界尺寸只有 `0.011~0.018m`，球与立方体在实机上不可分辨，省下的 4 面用来保住尾迹锥的规格。
- **弹芯/外壳的 `capsule` 键在低面数档下按棱柱产出**（兼容旧键，防止误用高价 `CapsuleMesh` 冲破预算）；新声明一律写 `prism`，球核仍写 `sphere`。
- 尾迹锥/滴珠/火星的**件数与构图未动** —— 面数只从「每件多少面」里省，不从「有几件」里省（件数是账本与验收 `EXPECTED_TRAIL_PARTS` 的契约）。

**验收**：`verify_bullet_vfx_profiles`（`samples=69`）—— 9 把枪经真实调用方路径开火后逐把核对三项档位、三条诉求的相对方向判据（霰弹 = 2.00 倍基准 / 榴弹 >1.30 倍基准 / 狙击横向更细）、轴向的几何真值（弹芯局部长轴实测 `2.0` 且横向 `body_scale` 不受影响）、生长包络四时刻步进（出生 / 半程 / 长满 / 封顶）+ 中性档不启用 + 复借复位 + **碰撞半径守卫**（霰弹 ×2 后仍为 `0.12`）+ **面数预算**（绝对上限 `100` 与逐弹种实测值双层钉住，期望值硬编码在验收侧、不引用被测常量）。反向对照八组（`grow_from → 1.0` / 狙击 `axial → 1.0` / 榴弹 `scale → 1.0` / 霰弹 `scale → 1.0` / 碰撞倍率误含枪身档位 / `MESH_SEGMENTS → 12` / `SPHERE_RINGS → 6` / 通用弹体 `_SEGMENTS → 12`）均精准变红且数值对得上（如 `MESH_SEGMENTS → 12` 时 standard 精确报 `132` 面）。

### 3.8 数字飘字（FX02-01 / FX02-02）的字体、样式与随机契约（2026-10-16）

伤害飘字 `VFX-DAMAGE-NUMBER-3D` 与治疗飘字 `VFX-HEAL-NUMBER-3D` 共用一套**字体与样式单一真源** `src/vfx/DamageNumberStyle.gd`。三条链路（池化生效的 `VfxDamageNumber3D`、`VfxHealNumber3D`、独立兜底的 `CombatDamageNumber3D`）一律从这里取字体族、字重、字号分级与描边分级 —— **禁止任何一处自行 `SystemFont.new()` 或再声明字号**。

> **为什么写死这条**：字体口径曾散在两处。2026-08-07 在**兜底链路** `CombatDamageNumber3D` 上定了「SF Mono 等宽终端字体 + 150% 字号」，而 2026-09-11 池化迁移新建的**生效链路** `VfxDamageNumber3D` 从没设过字体（一直是 Label3D 默认内建）⇒ 那套等宽字体从上线起就没生效过，只活在一条跑不到的分支里。两处口径靠人记，必然漂移。

**字体（业主口径：漫画风超粗体）**

| 项 | 值 | 说明 |
|---|---|---|
| 字体链 | `font_families()` | 按序取系统里第一个存在的：`Impact` → `Arial Black` → `Haettenschweiler` → `Franklin Gothic Heavy` → `sans-serif-black` → `Helvetica Neue` → `DejaVu Sans Bold` → `Liberation Sans` → `Noto Sans` → `sans-serif` |
| 字重 | `FONT_WEIGHT = 900` | 对可变字重字体（Helvetica Neue / Noto Sans）才真正生效 |
| 字形 | `MSDF_SIZE = 128` + `multichannel_signed_distance_field = true` | 飘字会被 `effect_size` 与相机距离放大，非 MSDF 会出马赛克边 |
| **距离场宽度** | `MSDF_PIXEL_RANGE = 64` | **不是风格参数，是描边能不能渲染出来的开关**，见下方「MSDF 描边上限」一节 |

⚠️ 字体链**只能是函数、不能是 `const`**：Godot 4 不接受 `PackedStringArray([...])` 作为常量表达式，裸数组字面量赋给 `PackedStringArray` 类型的 const 同样过不了解析期。
⚠️ 链尾必须留一个泛型族名，否则全部落空时 Godot 会**静默**退回内建字体（那正是本次要修的病灶）。本机（Windows）实测命中 `C:/WINDOWS/FONTS/impact.ttf`。

**字号与描边分级**（世界字高 = 字号 × `PIXEL_SIZE`）

| 档位 | 条件 | 字号 | 世界字高 | 描边（勾边） |
|---|---|---|---|---|
| 普通 | 伤害 < 40 | 116 | 0.435 m | 13 |
| 重击 | 伤害 ≥ 40（`HEAVY_AMOUNT_THRESHOLD`） | 134 | 0.503 m | 15 |
| 暴击 | `critical` | 152 | 0.570 m | 17 |

- `PIXEL_SIZE = 0.00375`。迁移后实机的字高是 0.320 m ⇒ 普通档即 **1.36×**，重击 1.57×，暴击 1.78×。
- 描边 ≈ 字高的 11%，色 `OUTLINE_COLOR` 近黑 `Color(0.02, 0.02, 0.03)`（漫画勾线）。屏幕上的描边宽 ≈ 描边像素 ×（屏幕字形高 / 字号）。**改这一节前必须先确认上表的 `MSDF_PIXEL_RANGE` 还够**（见下一节），否则改多少都不会变。
- 描边沿革：2026-10-16 首版按 22% 给（26 / 30 / 34），但那时的描边**从来没渲染出来过**（`msdf_pixel_range` 截断，见下节）；2026-10-17 修好距离场后描边第一次足额显示，业主看实机反馈「**太粗了，缩小一半**」⇒ 定到 **11%（13 / 15 / 17）**。
- 描边色**不许**参与淡出：Label3D 的描边不吃 `modulate` 的 alpha，只淡正文会留下勾边残影 ⇒ 透明度一律走 `transparency`（业主 2026-10-10）。
- 分级读的是 `context.magnitude`（数值本体），**不是**解析 `text_value` —— 后者带 `+` 前缀（治疗）会分错档。

**⚠️ MSDF 描边上限：距离场宽度必须 ≥ 描边尺寸的 2 倍（2026-10-17 修）**

Godot 官方口径（Using Fonts「Font outlines and shadows」+ [issue #70211](https://github.com/godotengine/godot/issues/70211)）：**MSDF 字体下 `msdf_pixel_range` 必须 ≥ 描边尺寸的 2 倍**，否则描边会被**提前截断**；默认值 **16** 只够 outline 到 **8**。

当时的描边是 26 / 30 / 34 ⇒ **远超 8，全部被截成约 1 px 细丝**。症状极具欺骗性：**不报错、不变红、只是"看不清"**，而且 `outline_size` 改成 26 还是 116 **渲染结果逐像素完全相同**（值根本没被用上）—— 2026-10-16 那轮「19% → 22%」的调整因此在视觉上什么都没改变，两版都被截到同一个上限。

换算口径：距离场里 1 纹素 = `font_size / msdf_size` 个字形像素，所以需求 `range = 2 × max(描边 × msdf_size / 字号)`。

- 2026-10-17 定档时描边是 26 / 30 / 34 ⇒ 2 × (34 × 128 / 152) ≈ **57.4** ⇒ 取 **64**。
- 同日描边减半到 **13 / 15 / 17** 之后需求降到 2 × (15 × 128 / 134) ≈ **28.7**。**仍保留 64、不压到 28.7**：64 可支持描边到约 38 @ 字号 152，为后续微调留余量，且远离 96 起的崩坏点（实测 48 对当时的 26 已属轻微截断，对现在的 17 则足额）。

| `MSDF_PIXEL_RANGE` | 声明描边 26 @ 字号 116 的实画宽（近距离定尺实测） |
|---|---|
| 16（Godot 默认） | **6 px** —— 截断，等于没有 |
| 48 | 21 px —— 仍被轻微截断 |
| **64 / 80** | **26 px** —— 足额 ✅ |
| 96 | 出现**左右不对称**，一侧描边整条丢失 ⇒ 距离场精度不够，**过大反而崩** |

⚠️ 因此这条契约**两头都要盯**：够小会截断成细丝，过大会崩成单边。验收里有一条不等式断言专门守它（下界 + 上界），另有一条「字体实例上真的带了这个值」的断言 —— 因为**光有常量对、实例没赋上**也会静默退回默认 16。

**随机化契约（业主：「不要太整齐，带一些随机」）**

随机数**只许活在调用方** `Enemy3D._damage_number_context()`；两个特效脚本对同一 `context` **逐位可复现**，源码内不出现 `randf()` —— 它们被逐帧断言驱动，把随机埋进 `_on_activate` / `_on_tick` 会让验收与视觉探针全部随机变红（同 §5.5.3 弹壳口径）。

| context 键 | 类型 | 含义 | 调用方幅度 |
|---|---|---|---|
| `text_value` | `String` | 显示文本（治疗为 `+N`） | — |
| `magnitude` | `int` | 数值本体，供字号 / 描边分级 | — |
| `critical` | `bool` | 暴击档 | — |
| `spawn_offset` | `Vector3` | 出生点抖动（米） | `±(0.16, 0.06, 0.16)` |
| `rise_scale` | `float` | 上升距离倍率 | `[0.85, 1.30]` |
| `drift` | `Vector3` | 终点水平漂移（米，XZ） | `±(0.22, 0.22)` |
| `pop_scale` | `float` | 出生瞬间弹出缩放 | `[1.28, 1.48]` |
| `duration_scale` | `float` | 时长倍率 | `[0.90, 1.18]` |

**力度**（业主：「飘起的力度感强一些」）：基线上升 `BASE_RISE_DISTANCE = 0.90 m`（原 0.60），位移曲线 `1 − (1−t)³`（ease-out cubic，半程走完 87.5%）；出生瞬间放大到 `pop_scale`、在 `POP_SETTLE_TIME = 0.14 s` 内收到 1.0，之后缓缩到 `SETTLED_SCALE = 0.90`。缓缩进度**必须从 `POP_SETTLE_TIME` 起算** —— 若从 0 起算，收束完成那一帧已被缩掉一截，永远收不到 1.0。

**出生点锚定（P0 历史事故，2026-10-16 修复）**

`_on_tick` 是每帧**重算**姿态（不是增量），位移必须写成 `position = _origin_local + 偏移`，`_origin_local` 在 `_on_activate` 末尾取出生点。2026-09-11 池化迁移起写的是**赋值**（`position.y = rise_t * _rise_distance`），出生坐标在第一帧就被清零 ⇒ 实测实机所有飘字都跑到**世界原点上方不到 1 米**处，与怪物所在楼层毫无关系（塔楼向下建造，98F ≈ −1176 m，实际相差上千米）。这与 §5.5.2 弹壳 `floor_y` 事故同源：**凡是"世界高度 / 绝对坐标"类的量，都必须专造非零高度用例**。

## 8. 反模式（明确禁止）

| 反模式 | 为什么禁止 | 替代方案 |
|---|---|---|
| 一个总脚本 + `match effect_kind` 分支多个特效 | 违反"Prefab 是唯一出口"原则 | 拆为多个 Prefab |
| 把特效逻辑写在战斗脚本里（如 `WeaponModel3D.gd` 内联） | 特效无法独立调参与替换 | 抽到独立 .gd 文件 + Prefab 包装 |
| 不登记 AssetID 直接用路径 `preload("res://.../some.tscn")` | 账本失同步 | 先登记 AssetID，再从账本查路径 |
| 调用方手动 `queue_free()` 特效 | 破坏池化复用 | 用 `pool.retire(asset_id, effect)` |
| 特效 Prefab 内嵌碰撞 | 视觉特效不应参与物理 | 碰撞留在玩法层（Enemy3D / Projectile3D） |
| 用 `match kind` 的字符串拼写来路由特效 | 拼写错误无编译保护 | 用 `VfxPool3D.VFX_MUZZLE_FLASH` 常量 |
