## 1.5 世界观（背景故事）

> **未来世界**：人类和他们的宠物，早已迁离地球，去向无人知晓。整颗星球被当作无人照管的旧居。
> 留在废墟里继续运转的，是一个被遗忘的小机器人。它孤零零地被困在一座失控高塔的**楼顶**，对外界一无所知。
> 一路上，它遭遇的不只是机械哨兵、自动化武器与残骸造物——它们既不解释为什么攻击，也不解释为什么要攻击。
> 小机器人没有救援、没有指令、没有任何承诺。它只有一个自己才知道的目标：
> **一路向下，到达塔的底层，看清世界最后变成了什么样子。**

这个故事不靠旁白解释，而是靠玩家的"看清"来递进：每往下一层，机器人都多看见一点真相；而玩家则决定它能带走什么、付出什么代价、最终是否真的愿意站在最底层看完整。

## 2. 一句话愿景

<span style="color:#2E7D32">**[已实装]** 《弹壳风暴2》是一款顶视角 3D 动作射击游戏:玩家沿一座失控高塔向下探索,在模块化房间中搜刮、战斗、改造枪械、接受命运规则,并在继续深入与带着战利品撤离之间反复做风险选择。</span>

## 3. 核心体验支柱

1. <span style="color:#2E7D32">**[已实装] 操作直接。** 移动、瞄准、射击、换弹、冲刺和交互必须立即响应;状态变化由角色动作、HUD、音效和受击反馈共同说明。</span>
2. <span style="color:#2E7D32">**[已实装] 构筑可见。** 枪身决定基础射击节奏,子弹决定飞行与命中规则,配件和命运卡改变结构或规则;成长不能只表现为无感的百分比累加。</span>
3. <span style="color:#2E7D32">**[已实装] 风险可判断。** 门、房间类型、小地图、钥匙、战利品和撤离倒计时共同构成"继续还是离开"的信息。</span>
4. <span style="color:#1565C0">**[用户设计] 向下爬楼。** 楼层不是菜单编号,而是连贯的垂直空间。玩家通过门、走廊和真实楼梯抵达下一层;上一楼梯间的到达门负责生成并验证本层和下一段楼梯。</span>
5. <span style="color:#1565C0">**[用户设计] 敌人留下记忆。** 全游戏 12 只唯一精英拥有独立身份、成长与存档,能夺取玩家枪械并在之后的行动中再次出现。</span>
6. <span style="color:#EF6C00">**[Codex补充] 系统可追溯。** 每次生成、掉落、精英出现、Boss 门解锁、剧情触发和存档写入都应由稳定 ID 与事件记录解释,避免"结果出现了但无法判断是谁生成的"。</span>

## 4. 游戏主循环

```text
基地确认长期进度、保险与下局准备
→ 楼顶进入塔内
→ 99 层基地准备区
→ 从99→98楼梯间交互98F到达门
→ 门保持关闭,生成并验证98F整层、98→97楼梯及97F安全屋壳体
→ 提交快照后开门进入98F,当前房与已开邻房按需呈现
→ 战斗 / 搜刮 / 事件 / 命运选择 / 枪械组合
→ 获取普通钥匙并选择路线
→ 到达下一楼梯间,交互下一层到达门并逐层重复生成
→ 在收益、生命、弹药与撤离机会之间判断继续或退出
→ 95F击败Boss,取得专用钥匙并打开Boss专用下行门
→ 进入95→94楼梯间,发现全游戏关卡内唯一电梯
→ 进入隔离间前确认“未拾取物永久丢失且无法返回”
→ 隔离间后门关闭后提交区段,卸载98–95F并实例化已验证的94F FloorBundle
→ 进入94F后继续按到达门规则逐层下潜
→ 继续下潜或使用可用撤离路径;失败则执行死亡与保险结算
→ 基地保存带出物、蓝图、设施进度、精英档案和剧情状态
→ 下一局
```

### 4.1 局内节奏目标

| 阶段 | 建议时长 | 玩家目标 | 系统要求 |
|---|---:|---|---|
| 建立构筑 | 0-5 分钟 | 识别路线,获得第一组可用枪械组合 | 至少出现一次有意义的武器或命运选择 |
| 承担风险 | 5-15 分钟 | 选择主路、支路、精英或撤离 | 房间风险、掉落等级和路线成本可读 |
| 阶段高潮 | 15-25 分钟 | 高价值搜刮、Boss、特殊门或撤离防守 | Boss/撤离规则不被普通门锁或空刷怪阻断 |
| 极限深入 | 25 分钟后 | 为稀有内容和极限构筑承担高损失概率 | 收益成长快于重复时长,不无限拖延普通局 |

### 4.2 核心决策

| 决策 | 玩家问题 | 设计回答 |
|---|---|---|
| 战斗 | 这套武器更适合清群、控场还是单体? | 怪物轮廓、攻击前摇、弹道和伤害反馈必须清晰 |
| 构筑 | 强化稳定输出,还是接受会改变规则的命运卡? | 每项改变同时影响行为、数值与表现,禁止只改文案 |
| 探索 | 这把钥匙开主路、资源支路还是撤离路线? | 门记录、地图连接和真实空间必须是一份事实 |
| 精英 | 要现在追杀这个会成长的唯一敌人,还是保留资源撤离? | 精英身份、上次遭遇、携带武器和悬赏可追踪 |
| Boss | 击败 Boss 后从哪条路线进入下一层? | 专用钥匙只解锁本阶段唯一的 Boss 下行门 |
| 区段提交 | 还有未拾取物,现在是否穿过隔离间? | 二次确认永久遗失与不可返回,提交前允许回头搜刮 |
| 撤离 | 当前收益是否值得继续冒险? | 倒计时、范围、追击压力和结算后果提前显示 |

## 6. 核心系统一:玩家状态机与操作系统

### 6.1 系统定位

玩家系统只负责把输入、地形、伤害和交互转换成明确的角色状态与动作意图。它不拥有武器数值、房间生成、剧情条件或存档文件。

### 6.2 当前能力

- <span style="color:#2E7D32">**[已实装]** 正式玩家根为 `Player3D`,顶层状态为 `idle / moving / dashing / hurt / locked / falling / landing / dead`。</span>
- <span style="color:#2E7D32">**[已实装]** 射击、蓄力、换弹、近战连段、低血量、沉默、无敌、击退等作为覆盖层存在,不额外制造互斥顶层状态。近战自身由 `ready / windup / active / recovery` 四态动作子状态机管理，连段编号属于动作上下文。</span>
- <span style="color:#2E7D32">**[已实装]** 键鼠与移动端输入汇合到同一动作语义;角色视觉 `PlayerAvatar3D` 与玩法碰撞分离。</span>
- <span style="color:#2E7D32">**[已实装]** 玩家随身三盏灯与角色自投影隔离;太阳和房间灯仍可让角色、枪械和怪物正常投影。</span>

### 6.3 设计要求

- <span style="color:#1565C0">**[用户设计]** 操作系统必须能独立维护,玩家状态不能散落在门、房间、武器或 UI 脚本里。</span>
- <span style="color:#EF6C00">**[Codex补充]** 所有输入设备只发出 `move / aim / primary_attack / skill / dash / interact / reload / inventory / flashlight / pause` 意图；当前武器将 `primary_attack` 解释为射击、蓄力或近战挥砍，状态机决定是否接受。</span>
- <span style="color:#EF6C00">**[Codex补充]** 每次状态切换携带原因码,便于复盘卡死、重复交互和死亡后仍可输入等问题。</span>
- <span style="color:#1565C0">**[用户设计]** 玩家随身手电筒拥有独立电量：99F基地内始终满电;出基地后开启手电筒会持续降低电量,关闭手电筒时停止耗电;HUD 需常驻显示当前电量与状态;电量耗尽后手电筒自动关闭,需要补充电池类消耗品才能继续使用。详细契约见 [玩家与操作 §10 手电筒与电量契约](03_技术施工_玩家与操作.md#10-手电筒与电量契约)。</span>

## 7. 核心系统二:战斗、构筑与武器系统

### 7.1 系统定位

每一把实际获得的武器都是独立物品。远程枪身定义射击节奏并挂接子弹模块与配件；近战武器定义三段连击、扇区、命中窗口和击退。武器作用域命运卡把永久升级写入该武器自己的线性命运槽；角色作用域和世界作用域命运卡由各自局内规则服务持有。伤害结算接收统一命中上下文，怪物只响应伤害结果，不读取玩家武器树。

### 7.2 当前能力

- <span style="color:#2E7D32">**[已实装]** 当前正式注册内容为 7 种远程枪身、2 种大型近战武器、8 种子弹模块、6 种配件；正式 3D 玩家通过 `BlueprintRegistry + WeaponAssemblyTree + WeaponModel3D` 使用同一实例与表现链，远程分支进入 `Projectile3D`，近战分支进入动作子状态机与扇区命中查询，并在 `active` 同步触发池化挥砍弧光、逐目标冲击特效和去重后的挥砍/命中音频。</span>
- <span style="color:#2E7D32">**[已实装并验收｜2026-08-10]** 巨型工业断刃与攻城裂甲斧均拥有三段挥砍。每段依次经历前摇、单次命中窗口和后摇；输入可缓存下一段，受伤、冲刺、坠落、锁定、死亡或换武器会中断连段，墙体遮挡会阻止隔墙命中。</span>
- <span style="color:#2E7D32">**[当前运行时已验收]** 正式可玩卡池仍为48张：22张星星、12张月亮、14张太阳；在78张塔罗迁移完成前不改变当前可玩卡池。</span>
- <span style="color:#1565C0">**[新设计已冻结｜数据已入表｜部分施工]** 目标牌组为78张：22张大阿尔卡那 + 56张权杖/宝剑/圣杯/星币小阿尔卡那；最终分布为36张星星、21张月亮、21张太阳。每次出场独立50%正位/50%逆位，同名同ID；逆位整张卡面与文字共同倒置，说明内容替换为逆位效果。当前48张运行时已完成，新增30张执行器待施工。完整规则见[命运塔罗牌组](14_技术施工_命运塔罗牌组.md)。</span>
- <span style="color:#2E7D32">**[已实装]** 掉落注册表记录武器、蓝图、模块、配件、消耗品、钥匙的稀有度、价格和多个楼层掉落权重。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 装配树现在是当前 `WeaponInstance` 的运行投影；换枪移动完整实例，构筑、当前弹药、可更换配件和永久命运槽会随原枪进入背包，并在重新装备后恢复。</span>

### 7.3 设计要求

- <span style="color:#1565C0">**[用户设计]** 每把枪拥有永久唯一 `weapon_instance_id`，可以装备、换入背包、丢弃、出售、保险、带出和存档；命运升级与装配必须跟随该实例。</span>
- <span style="color:#1565C0">**[用户设计]** 普通枪械基础拥有 8 个独立命运槽，类型和稀有度可以调整容量；武器命运卡按槽序永久叠加且不可逆，子弹模块与配件可更换且不占命运槽。</span>
- <span style="color:#1565C0">**[用户设计]** 命运卡按 `WEAPON / CHARACTER / WORLD` 分作用域；只有 `WEAPON` 卡写入枪械槽，另外两类不占枪械槽。</span>
- <span style="color:#1565C0">**[用户设计]** 三类命运使用卡面专名：`☀ 太阳命运 = WORLD`、`☾ 月亮命运 = CHARACTER`、`★ 星星命运 = WEAPON`；卡片端必须同时显示符号、专名、中文目标和是否占枪械槽，不能只显示英文枚举或颜色。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 正式卡池新增 10 张月亮命运与 10 张太阳命运；角色牌覆盖生命、移动、冲刺、防御、伤害、房间恢复、精英恢复、首击屏障、保命和补弹，世界牌覆盖宝箱、额外掉落、敌群、地图、钥匙、魂收益、敌人生命、风险试炼、房间赏金和撤离。</span>
- <span style="color:#EF6C00">**[Codex补充]** `weapon_content_id` 定义枪型，`weapon_instance_id` 定义具体物品，攻击/投射物实例 ID 只追踪单次战斗对象；三者不得混用。</span>
- <span style="color:#EF6C00">**[Codex补充]** 卡片描述、效果参数、实际行为和视觉表现需要一项验收用例共同绑定,避免"文案生效但投射物未改变"。</span>
- <span style="color:#1565C0">**[用户设计]** 每项武器功能必须在武器表现页、操作反馈和战斗表现中可被玩家感知；独立实例、永久命运槽、可更换装配和三类命运作用域不能只存在于数据或代码中。</span>
- <span style="color:#1565C0">**[用户设计]** 武器表现页必须显示实例尾号、所有权位置、基础/当前属性及来源、线性命运轨道、可更换装配和触发链；命运选卡必须在确认前显示作用域、目标枪、下一槽与不可逆警告。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 正式 HUD、背包、地面拾取、商店、保险柜和武器表现页已经统一显示实例短 ID、构筑摘要与命运槽；命运选卡已经显示作用域、目标和下一槽，并在满槽时保留页面、拒绝消费。逐内容专属 VFX/音效、完整属性来源拆分和并排比较仍属后续表现增强。</span>
- <span style="color:#2E7D32">**[已实装并完成真实交互验收]** 局内物品界面采用左右双栏：左侧角色装备与属性、右侧工整背包。悬停枪械只显示一张独立构筑详情卡；拖动时显示随鼠标预览、状态条以及蓝色入包/换位、绿色装备、红色丢弃目标。当前装备枪可原子卸回空背包格或丢到地面，短按点击与拖拽互不误触。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 主 HUD 已重新分组生命、弹药、状态和战术地图；生命条固定使用红色生命语义。小地图按真实房间宽高绘制，实时显示玩家在房间中的相对位置与当前房间存活怪物红点。</span>

具体条目见 [游戏内容数据库](data/ShellStorm2_游戏内容数据库_v010.xlsx) 的 `武器`、`命运卡` 工作表。

## 8. 核心系统三:关卡生成、爬楼、怪物刷新与地图产出

### 8.1 系统定位

关卡系统根据种子和楼层规则逐层生成整层拓扑。玩家交互“上一层楼梯间→本层安全屋”的到达门时,系统在门后生成并验证本层、下行楼梯与下一层入口壳体,成功后才开门。房间、墙、地砖、门、走廊、楼梯、碰撞、小地图和生成点必须共享同一组组件坐标;流送只改变加载与激活状态,不得重新随机已经冻结的布局。

### 8.2 当前能力

- <span style="color:#2E7D32">**[已实装]** 正式路线包含楼顶、99 层基地和 98-95 层战斗区;普通战斗房采用 30×25m,空间以 5×5m 组件网格和 9m 标准层高装配。</span>
- <span style="color:#2E7D32">**[已实装]** 房间类型包含战斗、精英、Boss、陷阱、地下室、储藏、搜索、事件、升级、楼梯大厅等语义;小地图读取同一房间记录。</span>
- <span style="color:#2E7D32">**[已实装]** 连接门打开时,已显现邻房的首批怪物实例会立即创建;玩家入房时激活原实例,避免靠近后突然刷出。</span>
- <span style="color:#2E7D32">**[已实装]** 当前版本具有普通房间钥匙、门后命运选择和真实下楼楼梯；普通探索层跳关电梯已移除，99F仅保留基地电梯接口。</span>

### 8.3 楼层随机生成正式设定

- <span style="color:#2E7D32">**[已实装基线]** 98–95F具有上一层楼梯、15×15m安全屋和 `floor_seed_gate` 提交接口；当前触发门仍在安全屋前方，候选Node仍于启动时隐藏预分配。</span>
- <span style="color:#2E7D32">**[已实装]** `floor_seed_gate` 已迁移为楼梯间通往本层安全屋的到达门。初始只实例化楼顶、99F基地和98F入口壳体；打开到达门依次生成本层整层、下一楼梯和下一入口壳体。</span>
- <span style="color:#2E7D32">**[已实装｜首批]** 生成器从250×250m总面积扣外墙、65m核心及楼梯/设施禁建区，并计入房间、0.30m内墙和走廊成本；任意边界多边形仍待扩展。</span>
- <span style="color:#2E7D32">**[已实装]** 内容房不小于30×25m，正式组合标准、宽、深、中、大与90×90 Boss房；15×15m仅作楼梯安全屋。</span>
- <span style="color:#2E7D32">**[已实装]** 普通层面积目标为14个内容房，10房必达主路并挂两条奖励支线，不存在支路下楼捷径。</span>
- <span style="color:#2E7D32">**[已实装｜当前RC范围]** 楼层号为5的整数倍时生成Boss；95F、90F、85F已分别绑定独立Boss内容、三阶段技能袋、正式模型和独立竞技场资产，95F仍为11房预热后不可绕过Boss。</span>
- <span style="color:#1565C0">**[用户设计]** 98–95F构成开局特殊Boss区段；此后94–90F、89–85F按五层构成Boss区段。跨过Boss后的隔离间才提交并卸载上一完整区段。</span>
- <span style="color:#EF6C00">**[Codex补充]** 候选布局在实例化前必须通过面积、重叠、楼梯占位、门/走廊、最短路、钥匙流和可达性验证；失败丢弃整层并确定性重试，最后使用预验证安全模板。</span>

固定12房构建路径及旧私有模板函数已移除，由 `FloorPlanGenerator` 单独维护。场景节点已改为到达门事务成功后创建当前FloorBundle，不再初始化预分配98–95F隐藏Node。现有5m网格、9m层高、组件、门、走廊、流送、开门预刷和小地图继续保留。完整公式和不变量见[关卡生成与爬楼](05_技术施工_关卡生成与爬楼.md)。

### 8.4 Boss 下行门、95→94唯一电梯与隔离间

- <span style="color:#1565C0">**[用户设计]** Boss 楼层通往下一层的路线必须由"击败 Boss 后获得的专用钥匙"解锁;普通房间钥匙不能替代。</span>
- <span style="color:#1565C0">**[用户设计]** 专用门不必紧贴 Boss 房,可以位于随机地图最终指向下一层的门位;它的目标必须是下行楼梯间。</span>
- <span style="color:#1565C0">**[用户设计]** 全游戏关卡内唯一电梯固定在95→94楼梯间,不会生成在楼层房间、安全屋、普通支路或其他Boss后的楼梯间。99F基地电梯接口不属于关卡内下行电梯。</span>
- <span style="color:#1565C0">**[用户设计]** 95→94楼梯之后设置15×15m双门隔离间。进入前必须二次提示“无法返回、旧区段未拾取物永久丢失”;玩家完整入内且后门关闭后,才提交卸载98–95F。</span>
- <span style="color:#EF6C00">**[Codex补充]** 后续90→89、85→84等Boss区段边界沿用相同隔离提交和卸载结构，但不生成电梯；提示中的楼层范围按当前区段动态显示。</span>
- <span style="color:#EF6C00">**[Codex补充]** 95F生成时共同预留并验证 `boss_descent_gate`、95→94楼梯、电梯、隔离间与94F入口壳体；双门互锁，旧区段卸载和下一FloorBundle验证成功后才开前门。</span>
- <span style="color:#EF6C00">**[Codex补充]** Boss 死亡只签发一次专用钥匙;开门事务同时消耗钥匙、写入门状态、更新地图和解锁楼梯,失败时整体回滚。</span>

新循环、95→94唯一电梯和隔离卸载已完成运行时施工；专项已连续生成98—95、94—90、89—85三段并核对95F/90F/85F独立Boss内容及顺序卸载。60分钟三区段真实渲染RC浸泡正在生成报告；行动存档跨重启恢复和完整人工巡检仍按独立门禁跟踪。详细施工见 [关卡生成与爬楼](05_技术施工_关卡生成与爬楼.md)。

## 9. 核心系统四:怪物、唯一精英与 Boss

### 9.1 系统定位

怪物系统管理敌人模板、AI 状态、数值、技能、楼层生态和奖励;关卡只请求一种遭遇,怪物系统返回可验证的生成计划。普通怪提供可读战术组合,精英承担跨局记忆,Boss 负责阶段门槛和路线解锁。

### 9.2 当前能力

- <span style="color:#2E7D32">**[已实装]** 正式 3D 敌人有追击、远程、召唤、护盾、自爆、伏击和 Boss 七个基础模板,共用 `Enemy3D` 状态机与 `EnemyAvatar3D` 表现根。</span>
- <span style="color:#2E7D32">**[已实装]** 怪物来源支持楼层与主题缩放、精英修饰、Boss 阶段、召唤、掉落和房间清理闭环。</span>
- <span style="color:#EF6C00">**[待重建]** 历史精英档案、成长、逃脱与夺械原型随旧 2D 链路退役；正式 3D `EliteRosterService` 尚待实现。</span>

### 9.3 12 只唯一精英正式设定

- <span style="color:#1565C0">**[用户设计]** 全游戏精英名册固定为 12 只;每只拥有稳定 ID、独立名字、独立玩法和独立档案。</span>
- <span style="color:#1565C0">**[用户设计]** 精英随机刷新,但同一时间只能存在一只同名精英;同一精英不能因房间流送或重复生成再次出现。</span>
- <span style="color:#1565C0">**[用户设计]** 精英可以成长、逃脱、记住遭遇,并获取玩家使用过的枪械或模块,把它转换为自己的战斗能力。</span>
- <span style="color:#EF6C00">**[Codex补充]** 唯一性由全局名册服务执行,不由房间自己检查;生成采用"预约-实例化-确认"事务,异常退出会释放预约。</span>
- <span style="color:#EF6C00">**[Codex补充]** 精英获取武器时保存的是稳定内容 ID 与能力快照,不保存场景节点引用;版本升级时通过迁移表恢复。</span>

12 只名册及每只的独立玩法见数据库 `精英怪` 工作表。

## 10. 核心系统五:基地设施

### 10.1 系统定位

基地把单局结果转换为下一局准备。设施只通过 `BaseManager` 暴露的服务读取或提交数据,不直接写存档文件,也不在菜单内部复制一套经济规则。

### 10.2 当前能力

- <span style="color:#2E7D32">**[已实装]** 正式 3D 基地具有远征情报室、训练靶场、枪械工坊、命运占卜屋、保险柜、怪物档案室、命运卡收藏室、基地管理终端和自动贩卖机。</span>
- <span style="color:#2E7D32">**[已实装]** 基地管理总局数、成功撤离、总击杀、资源点、蓝图 Tier、建筑解锁与升级、保险柜、下局带入和待处理战利品。</span>
- <span style="color:#2E7D32">**[已实装]** 基地外有四个独立主题关卡入口;训练场与正式行动的装备和结算隔离。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 九设施使用稳定 `facility_id` 与共享状态快照；3D 设施牌直接显示等级、容量、预兆或待办，管理终端完整列出九项设施且不再出现旧温室/黑市字段。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 设施升级的资源扣除与等级变化只进行一次原子存档，失败时同时回滚。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 自动贩卖机位于基地出口墙边，使用长方体代码模型和背包同源3D商品预览；固定出售3把基础枪、2格背包和药水，并可按数据库卖价回收保险柜物品。</span>

### 10.3 设计要求

- <span style="color:#1565C0">**[用户设计]** 基地每项设施都是独立模块,能够单独维护、替换 UI 和扩展等级,不把所有功能堆在基地场景脚本中。</span>
- <span style="color:#EF6C00">**[Codex补充]** 设施统一实现 `FacilityService` 契约:可用条件、展示状态、交互命令、提交结果和失败原因;场景节点只负责交互与表现。</span>
- <span style="color:#EF6C00">**[Codex补充]** 怪物档案室成为 12 只精英的长期信息中心,展示最后遭遇、成长阶段、夺取武器、悬赏和当前可否出现。</span>

## 11. 核心系统六:剧情触发

### 11.1 系统定位

剧情系统监听七大系统已经发生的事实,用数据条件触发对话、演出、任务状态和世界变化。它不能通过不断扫描场景节点猜测进度,也不能直接控制战斗、生成或存档文件。

### 11.2 当前能力与缺口

- <span style="color:#2E7D32">**[已实装]** 当前 3D 具备可交互 NPC、静态对话展示、房间进入/清理/击杀/开箱等事件信号和若干命运事件效果。</span>
- <span style="color:#2E7D32">**[已实装原型]** 旧事件房定义诅咒、祝福、交易、赌局、地图揭示和增援六类事件,但部分交互仍是简化实现。</span>
- <span style="color:#1565C0">**[用户设计]** 剧情触发是七大核心模块之一,需要独立管理剧情条件、触发结果和跨局进度。</span>
- <span style="color:#EF6C00">**[Codex补充]** 新增数据驱动的 `NarrativeTriggerService`:稳定剧情 ID、条件组、一次性/可重复策略、动作列表、互斥组、冷却、存档键和版本迁移。</span>
- <span style="color:#EF6C00">**[Codex补充]** 剧情只订阅领域事件,例如 `floor_entered`、`boss_defeated`、`elite_escaped`、`item_extracted`;实际对白与镜头演出由表现层执行。</span>

v0.1 先建立触发框架和验收契约,不在本次文档中擅自重写主线剧情。

## 12. 核心系统七:存档、结算与复活

### 12.1 系统定位

该系统区分三种生命周期:单房间运行态、单局行动态、跨局长期态。撤离、死亡、保险、复活和基地写入都通过一次结算事务完成,其他系统不得直接拼 JSON。

### 12.2 当前能力

- <span style="color:#2E7D32">**[已实装]** `AtomicJsonStore` 使用临时文件、上一版备份和原子提升；`BaseData 1.4` 使用带revision、保存原因和SHA-256 payload校验的版本封套，支持1.2/1.3旧档迁移、新手完成标记与checksum失败回退。</span>
- <span style="color:#2E7D32">**[已实装]** 成功撤离可带回背包与保险物;死亡会保留保险格,并按当前规则处理未保险战利品损失。</span>
- <span style="color:#2E7D32">**[已实装]** 长期数据包含局数、撤离、击杀、设施、蓝图、资源、保险柜、下局命运预选、带入物和待处理战利品。</span>
- <span style="color:#2E7D32">**[已实装原型]** 精英档案已有独立文件,但尚未合并到正式 3D 的统一存档清单和迁移流程。</span>
- <span style="color:#2E7D32">**[已实装并验收]** 基地买卖以事务ID幂等提交，资源与物品所有权一次保存；失败整体回滚，购买枪械重启后保持独立物品ID、枪械ID与完整构筑。</span>

### 12.3 正式要求

- <span style="color:#1565C0">**[用户设计]** 存档与复活机制必须作为独立系统设计,与玩家死亡动画、UI 和房间脚本解耦。</span>
- <span style="color:#EF6C00">**[Codex补充]** v0.1 建立可配置 `RevivalPolicy`,默认死亡仍结束本局;只有明确的复活来源才能创建复活请求,且请求必须定义次数、成本、复活点、生命比例、无敌时间和是否保留当前房敌人状态。</span>
- <span style="color:#EF6C00">**[Codex补充]** 在复活内容尚未冻结前,不默认发放免费复活,也不改变当前搜打撤死亡损失;先完成接口和测试桩。</span>
- <span style="color:#EF6C00">**[Codex补充]** 所有存档域写入同一清单,包含 schema 版本、事务 ID、校验结果和迁移记录,杜绝基地档、精英档、剧情档各自悄悄失败。</span>

## 13. 跨系统不可破坏契约

| 契约 | 负责系统 | 其他系统只能做什么 |
|---|---|---|
| 玩家状态事实 | 玩家系统 | 订阅状态变化,不直接写状态字段 |
| 武器与卡片数值 | 战斗系统 + 内容数据库 | 怪物只接收伤害上下文 |
| 房间、门和楼梯坐标 | 关卡系统 | 相机、地图、刷新读取同一布局记录 |
| 楼层生成与区段卸载 | 关卡生命周期服务 | 门/UI只发命令和显示状态,不能自行创建或销毁楼层 |
| 敌人生命周期 | 怪物系统 | 房间请求遭遇并等待结果 |
| 基地长期进度 | 基地服务 + 存档系统 | 设施通过命令提交,不写文件 |
| 剧情触发历史 | 剧情系统 | 其他系统发布领域事件 |
| 撤离、死亡、复活结算 | 存档结算系统 | UI 只显示和提交选择 |

## 16. 2026-08-07体验一致性基线

- 99F基地仅30×30m室内禁射；两侧门外立即恢复开火。门板开关/自动关闭与禁射空间判断是两套独立逻辑。
- 玩家随身手电筒拥有独立电量：基地内满电，离开基地开启时持续耗电、关闭时停止；HUD 常驻显示电量档位与状态；电量耗尽自动关闭，需电池类消耗品恢复。
- 全界面以主HUD为母版，统一深蓝黑、霓虹青、魂金、生命/危险红；角色包裹、贩卖机和保险柜使用正方形物品图标网格。
- 36项正式音效全部落盘并统一引用版本化OGG，WAV仅作母版，不回退旧合成音；手电筒充能、低电量、耗尽三条事件已补齐为44.1kHz双声道OGG，`event_count=36, missing=[], non_ogg=[], mobile_safe=true` 已通过。
- 搜索具有可取消计时进度；容器和怪物每次最多掉1件实体物品且`count=1`，魂只通过地面魂球拾取入账。
- 纯新档首次在100F天台出生，首次进入99F后永久改为基地中心出生；旧进度档自动迁移。
- 死亡先播放受击方向击飞、落地回弹和倒地，再显示必须点击的返基地确认框。

对应规则分别见玩家、战斗、基地、存档、资产与测试文档的2026-08-07章节。

## 17. 2026-08-10统一枪械配件与初级近战基线

- 基地贩卖机固定第一件商品为45魂“废土棒球棍”；它复用三段近战动作机、打击VFX/音频和WeaponInstance所有权链。
- 每把远程枪在主/副装备栏下都显示同一组六个配件位置：瞄具、枪口、弹匣、枪托、战术、特性；枪型只开放兼容子集，未开放位置禁用但不重排。
