## 1. 原则

“已实装”需要代码事实、自动验证和必要的可视检查共同支持。测试不能写正式存档或覆盖正式资产；视觉输出统一写入 `outputs/verification/`。

## 2. 当前测试入口

<span style="color:#2E7D32">**[已实装]** 工程已有 `tests/verification/` 独立 Godot 场景与统一脚本。</span>

```bash

./scripts/run_verification_suite.sh visual
./scripts/run_verification_suite.sh scene verify_tower_descent_flow
```

## 3. 分层测试

| 层级 | 目标 | 典型证据 |
|---|---|---|
| 数据校验 | ID、字段、引用、数值范围、存档 schema | 数据库扫描、公式错误扫描 |
| 领域单测 | 状态、伤害、生成计划、精英唯一性、结算 | 无场景脚本测试 |
| 场景集成 | 玩家、门、房间、敌人、设施、UI | `tests/verification/*.tscn` |
| 生成性质测试 | 多种子、多楼层不变量 | 重叠、可达、组件对齐报告 |
| 可视回归 | Mesh、材质、灯光、相机、动画 | 固定机位 PNG |
| 性能回归 | 节点、Draw Call、对象池、流送 | 性能预算场景 |
| 长时热浸泡 | CPU/GPU帧时间、RSS、物理查询、热状态、进程残留 | 30/60分钟实机报告 |
| 存档破坏测试 | 中断、备份、迁移、幂等 | 临时用户目录与故障注入 |

## 7. 发布门槛

版本可发布必须同时满足：

- `smoke`、`core` 通过；涉及正式场景/资产时 `full` 通过。
- 本次变更对应的专项场景和可视对比通过。
- 游戏内容数据库无重复 ID 和公式错误。
- 新增/变更存档字段具有迁移与回滚测试。
- 没有 P0：卡死、不可达、空气墙、地洞、重复精英、钥匙丢失、物品复制、存档覆盖、到达门后空层、隔离双门同开或已提交区段被读档恢复。
- 文档、数据库、代码与资产台账已经同步更新。
- 测试套件退出后没有孤儿 Godot 进程；性能改动通过真实渲染与至少30分钟热浸泡。
- 任何武器功能只有在规则测试、UI 提示和至少一项可视/听觉证据同时通过后才能标记完成。

## 8. 缺陷优先级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 | 阻断主循环、破坏存档或产生不可恢复结果 | 空刷怪卡死、Boss 无法下楼、重复/丢失物品 |
| P1 | 严重破坏判断或战斗，但有绕行 | 空气墙、门/地图不一致、精英重复出现 |
| P2 | 明显表现/平衡问题 | 高光曝光、远墙条纹、动画错位 |
| P3 | 低影响一致性与整理 | 命名、占位文案、次要台账缺项 |
