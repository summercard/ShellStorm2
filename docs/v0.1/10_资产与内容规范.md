## 1. 目标

场景、角色、武器、道具、怪物、动画、材质和特效均以可复用组件进入正式 3D 运行链。源文件、导出资产、运行场景、内容 ID 和验证预览分离，避免临时 Mesh、隐形碰撞、材质副本和脚本生成占位物长期成为正式资产。

## 2. 状态

- <span style="color:#2E7D32">**[已实装]** 工程已有塔楼 5m 组件、角色分件、武器套件、敌人套件、基地设施、房间道具、VFX 和主题环境资源。</span>
- <span style="color:#1565C0">**[用户设计]** 场景组件必须依靠 Mesh 制成单个可复用组件，再按组件坐标组合关卡。</span>
- <span style="color:#EF6C00">**[Codex补充]** 每项正式资产必须有稳定资产 ID、台账记录、导入场景、碰撞所有者、材质策略、LOD/性能预算和至少一项可视验证。</span>

## 4. 场景组件规范

### 4.1 塔楼组件

- 地砖：5×5×0.30m，局部原点和底面位置统一。
- 实墙：5×0.30×9m，底面贴楼面。
- 门墙：完整占用 5×9m 墙位，门洞、门扇、触发、实体碰撞、相机代理共享局部坐标。
- 拐角：L/T/X 为独立组件，每条墙臂有对应 Mesh/碰撞，不用隐形大盒体补齐。
- 楼梯：9m 层高总成，明确上/下门槽、楼板洞口、落地平台和占位投影。
- 95→94电梯：独立设施组件，只允许装配到95→94楼梯间声明的唯一插槽；资产本身不得自动改楼层或写存档。
- 隔离间：15×15m交通组件，前/后门具有独立门槽、夹区检测和互锁状态表现；不得用透明碰撞代替关闭门。
- 走廊：5m 地面/侧墙模块动态重复；合并碰撞不得超出可视范围。
- 内容房：外轮廓不小于 30×25m，并提供标准 30×25m、宽型 40×25m、纵深型 30×40m、中型 35×30m、大型 40×35m 和竞技场的 5m 网格外框。
- 交通空间：15×15m 只用于入口安全屋、楼梯大厅等非内容房，不参与主路最少 10 房计数。

### 4.2 组件元数据

每个关卡组件声明：`asset_id / module_size / socket_ids / mesh_bounds / collision_bounds / placement_bounds / placement_clearance / collision_profile / camera_wall_profile / nav_profile / material_variant_rule / lifecycle_owner`。其中 `placement_bounds` 必须覆盖墙厚、门扇/交互区、碰撞和需要的检修带；`lifecycle_owner`用于区段卸载时释放本区段资产引用。关卡生成器只通过元数据计算面积和装配，不按 Mesh 名字或可见地面猜外框。

### 4.3 禁止项

- 看不见但阻挡角色或子弹的装饰碰撞。
- 可见墙与碰撞墙尺寸、位置或高度不一致。
- 用拉伸一个 5m Mesh 冒充 20m 通道。
- 用透明材质处理相机遮挡。
- 运行时临时创建 BoxMesh 作为正式墙，却不登记组件资产。

## 5. 角色、怪物与动画

- 玩法根、视觉根、武器插槽、受击盒和交互体分离。
- 主、副武器背部收纳分别使用 `StowedWeaponSocketPrimary / StowedWeaponSocketSecondary`，主武器在角色左背、副武器在右背；挂点负责把枪模 `local -Z` 枪口轴转为世界向下，禁止在玩家脚本中按枪型逐个硬编码旋转。
- <span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 可装备背包使用背部中央 `BackpackSocket`，不复用左右武器挂点。当前2/4/8格代码Mesh以体积、主色和1/2/3个附袋区分；同一工厂供地面物、背包图标与角色背部表现复用，模型无玩法碰撞，不扩大角色碰撞体或挡住门洞。</span>
- 资产台账使用 `CHR-PLY-CAPSULE01-BACKPACK-SOCKET-3D` 登记语义挂点，使用 `ITM-EQUIPMENT-BACKPACK-3D` 登记三档共用模型家族；后者保持“程序占位”，正式美术不得为地面、UI和背部各复制一套身份。
- 角色视觉资产不自带玩法碰撞；必要的布料/附件碰撞属于表现层。
- 骨骼、动画状态和插槽命名稳定；替换 Mesh 不能要求玩家或怪物脚本更换节点路径。
- 动画事件只发出表现时点；伤害、弹药和状态仍由领域规则确认并有超时收口。
- 精英复用普通怪基础骨架/行为时，通过独立材料、附件、轮廓、尺寸和特效保持唯一辨识度；12 只精英最终需要独立资产台账条目。

## 6. 武器、子弹与道具

- 武器表现按枪身、弹匣、枪口、瞄具和外接配件拆分，挂接点与装配槽一一对应。
- 同一枪械实例的手持、地面、背包图标和商店预览共享 `weapon_instance_id` 与构筑快照；不同表现 LOD 不能被当成不同物品。
- 永久命运槽与可更换装配必须有不同的 UI/视觉语言：命运槽显示顺序与不可逆状态，配件槽显示可拆卸和替换状态。
- 武器表现页预览必须由实例快照重建真实枪身与装配；安装预览使用幽灵件，确认后才转为实体，失败时不得留下半套表现。
- 每张武器命运卡至少声明枪身、弹体、尾迹、命中、动画、音频中的适用表现标签；角色卡和世界卡不得伪装成枪械永久刻印。
- 数值变化需要页面差值与来源，高频行为变化需要可辨识图标和触发 VFX；只改文字或只改颜色均不算完成。
- 命运作用域、稀有度和槽状态均使用文字、图标、形状三重编码，保证色弱和低特效设置下仍可辨认。
- <span style="color:#2E7D32">**[已实装基础表现]** 当前手持/地面/背包预览已从同一实例快照重建配件，并以最多 8 个命运纹章表现永久槽；HUD、选卡与武器表现页使用文字加槽位结构补充识别。专属弹道、命中、音频和低特效适配仍需逐内容制作。</span>
- 子弹视觉由内容 ID 映射，不能从材质颜色反推伤害类型。
- 地面拾取、背包模型和手持模型可以使用不同 LOD/场景，但共享物品内容 ID。
- 任务钥匙与普通钥匙必须在轮廓、颜色、图标和拾取提示上可区分；Boss 专钥匙不能复用普通钥匙外观后只改文字。
- <span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 自动贩卖机登记为`PRP-BASE-VENDING-MACHINE-3D`，使用2.5×3.35×1.35m长方体程序网格、独立实体碰撞、正面交互区、货窗/屏幕/灯带；界面登记为`UI-SCREEN-BASE-VENDING`并复用`ItemModelIcon3D`。两项均为可替换组件，不把交易规则写入资产场景。</span>

## 7. 材质、灯光与雾

- <span style="color:#2E7D32">**[已实装]** 墙和地砖具有 A/B 材质，按网格奇偶交替识别装配。</span>
- 地砖和墙使用低金属度、高粗糙度，避免室内灯和太阳造成强反光/曝光。
- 墙材质保持不透明；玩家遮挡通过角色轮廓表现，不改变墙 alpha。
- 太阳和房间灯照亮玩家、怪物、武器和环境并允许正常阴影。
- 玩家随身主聚光、环境溢光、角色柔光不对玩家自身产生阴影，但不能关闭玩家对其他光源的投影。
- 随身主灯当前基线能量 7.2；阴影偏移 0.18、法线偏移 1.6、模糊 1.2，用于减少远墙条纹。调整这些值必须跑光照专项测试。
- 雾表达距离气氛，不代替墙、视野遮挡或单位可见性。

## 8. 资产入库流程

```text
内容数据库建立内容ID
→ 资产台账建立资产ID与用途
→ 源文件制作
→ 导出到组件目录
→ Godot导入场景封装
→ 碰撞/插槽/材质/动画检查
→ 正式系统映射内容ID↔资产ID
→ 自动化与可视验证
→ 台账状态改为正式可用
```

## 10. 音效运行资产与移动端规范（2026-08-07）

- `src/assets/audio/sfx/*.wav`是44.1kHz/16-bit/mono源母版，不作为正式运行引用。
- 正式运行资产统一为版本化`*_v001.ogg`，44.1kHz、Vorbis、stereo；桌面与Android引用完全相同的31个`res://`路径。
- `AudioManager.SFX`不得回退`SynthSfx`或旧WAV。路径缺失时只记录一次明确错误并保持静音，避免Android包在资源缺失时悄悄播放旧音效。
- UI、拾取、门、容器、波次、Boss、购买和既有战斗事件均使用统一事件键；同一状态变化只允许一个所有者播放，防止双响。
- 发布前必须执行`AudioManager.validate_runtime_assets()`：事件数31、`missing=[]`、`non_ogg=[]`且`mobile_safe=true`。

## 11. 道具固有色规范（2026-08-07）

道具类型先决定高辨识度固有色，稀有度再做不超过主要色相识别的偏色。世界拾取、背包图标、贩卖机卡和保险柜必须复用`ItemModelFactory3D`，不得在各UI重新制造深灰材质。六类代表样本最低亮度和互异颜色由专项测试锁定。
