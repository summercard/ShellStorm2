## 1. 目标

场景、角色、武器、道具、怪物、动画、材质和特效均以可复用组件进入正式 3D 运行链。源文件、导出资产、运行场景、内容 ID 和验证预览分离，避免临时 Mesh、隐形碰撞、材质副本和脚本生成占位物长期成为正式资产。

## 2. 状态

- <span style="color:#2E7D32">**[已实装]** 工程已有塔楼 5m 组件、角色分件、武器套件、敌人套件、基地设施、房间道具、VFX 和主题环境资源。</span>
- <span style="color:#1565C0">**[用户设计]** 场景组件必须依靠 Mesh 制成单个可复用组件，再按组件坐标组合关卡。</span>
- <span style="color:#EF6C00">**[Codex补充]** 每项正式资产必须有稳定资产 ID、台账记录、导入场景、碰撞所有者、材质策略、LOD/性能预算和至少一项可视验证。</span>

## 3. 目录与命名

推荐命名：`类别_对象_用途_视角_v###`。

| 前缀 | 内容 | 示例 |
|---|---|---|
| `env_` | 环境与关卡组件 | `env_tower_wall_solid_5m_top3d_v001.glb` |
| `prp_` | 道具、门、设施 | `prp_extraction_beacon_root_top3d_v001.tscn` |
| `chr_` | 玩家/NPC 角色 | `chr_player_capsule01_bunny01_root_top3d_v006.tscn` |
| `enm_` | 普通怪、精英、Boss | `enm_ecosystem_kit_root_top3d_v001.tscn` |
| `wpn_` | 枪身、子弹、配件表现 | `wpn_gun_kit_root_top3d_v001.tscn` |
| `mat_` | 材质资源 | `mat_tower_wall_solid_a_v001.tres` |
| `vfx_` | 视觉特效 | `vfx_combat_kit_root_top3d_v001.tscn` |
| `ui_` | UI 场景/图标 | `ui_inventory_item_model_preview_v001.png` |

`.blend`、导出脚本和原始图位于 `source/`；Godot 运行时只引用 `components/`、`runtime/` 或明确的根场景，禁止直接引用制作缓存。

## 4. 场景组件规范

### 4.1 塔楼组件

- 地砖：5×5×0.30m，局部原点和底面位置统一。
- 实墙：5×0.30×9m，底面贴楼面。
- 门墙：完整占用 5×9m 墙位，门洞、门扇、触发、实体碰撞、相机代理共享局部坐标。
- 拐角：L/T/X 为独立组件，每条墙臂有对应 Mesh/碰撞，不用隐形大盒体补齐。
- 楼梯：9m 层高总成，明确上/下门槽、楼板洞口、落地平台和占位投影。
- 走廊：5m 地面/侧墙模块动态重复；合并碰撞不得超出可视范围。

### 4.2 组件元数据

每个关卡组件声明：`asset_id / module_size / socket_ids / collision_profile / camera_wall_profile / nav_profile / material_variant_rule / bounds`。关卡生成器只通过这些元数据装配，不按 Mesh 名字猜类型。

### 4.3 禁止项

- 看不见但阻挡角色或子弹的装饰碰撞。
- 可见墙与碰撞墙尺寸、位置或高度不一致。
- 用拉伸一个 5m Mesh 冒充 20m 通道。
- 用透明材质处理相机遮挡。
- 运行时临时创建 BoxMesh 作为正式墙，却不登记组件资产。

## 5. 角色、怪物与动画

- 玩法根、视觉根、武器插槽、受击盒和交互体分离。
- 角色视觉资产不自带玩法碰撞；必要的布料/附件碰撞属于表现层。
- 骨骼、动画状态和插槽命名稳定；替换 Mesh 不能要求玩家或怪物脚本更换节点路径。
- 动画事件只发出表现时点；伤害、弹药和状态仍由领域规则确认并有超时收口。
- 精英复用普通怪基础骨架/行为时，通过独立材料、附件、轮廓、尺寸和特效保持唯一辨识度；12 只精英最终需要独立资产台账条目。

## 6. 武器、子弹与道具

- 武器表现按枪身、弹匣、枪口、瞄具和外接配件拆分，挂接点与装配槽一一对应。
- 子弹视觉由内容 ID 映射，不能从材质颜色反推伤害类型。
- 地面拾取、背包模型和手持模型可以使用不同 LOD/场景，但共享物品内容 ID。
- 任务钥匙与普通钥匙必须在轮廓、颜色、图标和拾取提示上可区分；Boss 专钥匙不能复用普通钥匙外观后只改文字。

## 7. 材质、灯光与雾

- <span style="color:#2E7D32">**[已实装]** 墙和地砖具有 A/B 材质，按网格奇偶交替识别装配。</span>
- 地砖和墙使用低金属度、高粗糙度，避免室内灯和太阳造成强反光/曝光。
- 墙材质保持不透明；玩家遮挡通过角色轮廓表现，不改变墙 alpha。
- 太阳和房间灯照亮玩家、怪物、武器和环境并允许正常阴影。
- 玩家随身主聚光、环境溢光、角色柔光不对玩家自身产生阴影，但不能关闭玩家对其他光源的投影。
- 随身主灯当前基线能量 7.2；阴影偏移 0.18、法线偏移 1.6、模糊 1.2，用于减少远墙条纹。调整这些值必须跑光照专项测试。
- 雾表达距离气氛，不代替墙、视野遮挡或单位可见性。

## 8. 资产入库流程

```text
内容数据库建立内容ID
→ 资产台账建立资产ID与用途
→ 源文件制作
→ 导出到组件目录
→ Godot导入场景封装
→ 碰撞/插槽/材质/动画检查
→ 正式系统映射内容ID↔资产ID
→ 自动化与可视验证
→ 台账状态改为正式可用
```

## 9. 验收标准

- [ ] 正式运行资产均能在资产台账找到唯一条目和来源文件。
- [ ] 塔楼墙、地砖、门、拐角、走廊、楼梯以 5m/9m 标准组件装配。
- [ ] 可视 Mesh、角色/子弹碰撞、相机代理和导航边界一致。
- [ ] 场景中不存在无用途的透明阻挡和超出可视范围的碰撞体。
- [ ] 玩家、怪物和武器替换视觉根不改变玩法。
- [ ] 12 只精英和各 Boss 能由轮廓、色彩或附件快速区分。
- [ ] A/B 材质交替能直观看出组件排列且不过度反光。
- [ ] 太阳/室内灯/随身灯的层与阴影契约保持正确。
- [ ] 导入警告、丢失贴图、重复材质和未引用正式资产有检查报告。
- [ ] 每项关键资产至少有一个自动截图或独立预览场景。
