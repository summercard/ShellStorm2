# 关卡区块设计

状态：WORLD-BLOCKS r1，适用工程版本 `0.1.0`。本文件是塔楼场景区块、命名和资产追溯的事实所有者；房间生成、门与区段卸载规则仍由[关卡生成与爬楼](05_技术施工_关卡生成与爬楼.md)定义。

## 1. 目标

塔楼主场景固定按四个区块管理。区块只负责场景树归属、楼层范围和资产追溯，不改变房间生成、碰撞、门、楼梯通行、存档或流送规则。

```text
TowerDescent3D
└─ Blocks
   ├─ Rooftop
   ├─ Base
   ├─ Battle
   └─ Stairs
```

编辑器和运行时使用同一组区块节点。`GeneratedRooms` 与 `GeneratedCorridors` 保留为父类兼容入口，不再作为塔楼主要浏览层级。

## 2. 简化命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 四个区块节点 | 固定英文单词，不附加楼层、版本或用途长句 | `Rooftop`、`Base`、`Battle`、`Stairs` |
| 楼层节点 | `Floor_楼层号` | `Floor_100`、`Floor_99`、`Floor_98` |
| 房间节点 | 直接使用稳定 `room_id` | `start`、`facility`、`floor_01_entry` |
| 水平走廊 | `Corridor_序号` | `Corridor_02` |
| 首两段楼梯 | 固定短名 | `Stair_A`、`Stair_B` |
| 后续楼梯 | `Stair_上层_下层` | `Stair_98_97` |
| 独立电梯位 | `Elevator_楼层F` | `Elevator_98F` |
| Godot 区块资产文件 | `zone_区块_v###.tscn` | `zone_rooftop_v021.tscn` |
| Blender 源文件 | 保留现有生产名称和中文集合 | 不因 Godot 显示名调整而改名 |

名称只用于浏览。稳定身份始终使用 AssetID、`room_id`、`floor_number`、`block_id` 和楼梯端点元数据，禁止从显示名反推玩法逻辑。

## 3. 四区块分布

| block_id | 节点 | 中文显示 | 当前楼层 | 内容边界 |
|---|---|---|---|---|
| `rooftop` | `Blocks/Rooftop` | 天台区 | 100F | 天台楼板、围护、聚落美术、出生房 |
| `base` | `Blocks/Base` | 基地区 | 99F | 基地房、基地美术布局、设施和基地电梯入口 |
| `battle` | `Blocks/Battle` | 首关战斗区 | 98–95F | 首个 Boss 区段的楼层、房间、水平走廊和战斗内容；后续程序生成战斗层沿用该运行区块 |
| `stairs` | `Blocks/Stairs` | 楼梯区 | 100→99、99→98 | 初始两段楼梯及后续运行时生成的垂直连接器 |

初始场景必须能直接看到四个区块。`Stairs` 初始包含两种资产身份：

- `Stair_A`：100F→99F，AssetID `ENV-TOWER-STAIRWELL-ROOFTOP-12M`。
- `Stair_B`：99F→98F，AssetID `ENV-TOWER-STAIRWELL-GENERIC-12M`。

基地内部的东侧过渡楼梯和西北 L 型楼梯属于 `Base` 的结构资产，不计入上述两段层间楼梯。

## 4. 资产与源文件对照

Godot 区块入口统一放在 `assets/art/environments/tower_zones/`：

```text
tower_zones/
├─ rooftop/runtime/
├─ base/runtime/
├─ battle/runtime/
└─ stairs/runtime/
```

各区块目录只承载 Godot 入口和管理说明。Blender 源、已导入 GLB 和组件包继续保留原生产目录，通过下表和资产台账连接；未来需要重新导入时，再按区块逐批迁移组件，禁止为了目录整齐一次性搬动全部 GLB。

| 区块 | AssetID | Godot 入口 | Blender 正式来源 |
|---|---|---|---|
| Rooftop | `ENV-ROOFTOP-SHELTER-90X80` | `assets/art/environments/tower_zones/rooftop/runtime/zone_rooftop_v021.tscn` | `assets/art/environments/rooftop_shelter_3d/source/env_rooftop_shelter_90x80m_top3d_v021.blend` |
| Base | `ENV-BASE99-ART-LAYOUT-3D` | `assets/art/environments/tower_zones/base/runtime/zone_base_v002.tscn` | `source/art/blender/base_facility_layout/source/base_facility_runtime_layout_hq_v026.blend` |
| Battle | `ENV-TOWER-DESCENT-KIT-3D` | `scenes/TowerDescent3D.tscn` + 程序生成 | `assets/art/environments/tower_descent_3d/source/env_tower_descent_kit_top3d_v011.blend` |
| Stairs | `ENV-TOWER-STAIRWELL-ROOFTOP-12M`、`ENV-TOWER-STAIRWELL-GENERIC-12M` | `TowerDescent3D` 运行时包装，现有 GLB 不改名 | `assets/art/environments/tower_descent_3d/source/env_tower_descent_kit_top3d_v011.blend` |

本轮不重新导入模型，因此 `.glb` 和 `.glb.import` 路径保持不变。Godot 包装场景、代码和账本使用上表的短名称；账本中的源路径负责连接到原始 Blender 资产。

## 5. 区块元数据契约

每个区块根至少保存 `block_id`、`display_name`、`floor_range`、`asset_ids`、`runtime_owner`、`source_blends`。楼层节点额外保存 `floor_index / floor_number / block_id`。垂直楼梯额外保存 `upper_floor_index / lower_floor_index / from_room_id / to_room_id / stair_asset_id`。修改节点显示名不得改变这些字段。

## 6. 修改流程

1. 先在本文件更新区块范围和名称。
2. 修改 `TowerDescent3D.tscn` 的四区块根及 Godot 包装文件名。
3. 修改运行时代码的归属和短名，保持玩法 ID 不变。
4. 在 Blender 正式源文件补充 `godot_block`、`godot_runtime` 和命名契约元数据，不改中文集合和几何。
5. 同步资产台账、全局导入账本、模块索引和开发记录。
6. 运行路径残留检查、场景解析和区块结构专项；模型重新导入另行执行。

## 7. 验收

- 主场景存在且仅存在 `Blocks/Rooftop`、`Base`、`Battle`、`Stairs` 四个区块根。
- 100F/99F/战斗楼层分别挂到正确区块；房间节点名等于稳定 `room_id`。
- 初始两段楼梯分别命名为 `Stair_A`、`Stair_B`，AssetID 和端点元数据正确。
- `zone_rooftop_v021.tscn` 与 `zone_base_v002.tscn` 可加载，旧活动路径不再被正式代码、场景、测试或生产工具引用。
- 资产台账能从每个区块的 Godot 入口追溯到原始 Blender 文件。
- Blender 中文集合、几何、材质和导出状态不变；本轮不执行 GLB 重新导入。
