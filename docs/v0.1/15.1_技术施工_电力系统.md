# 技术施工｜电力系统 v0.1

文档状态：**[开发中]**。设计修订：`POWER-SYSTEM r1`。适用工程版本：`0.1.0`。更新日期：**2026-09-12**。

本系统统一管理基地电力和手电电力。当前正式游戏已经具备两条可玩的电力链：手电电量消耗、补充、模块和存档；基地能源恢复、消费和恢复舱事务。基地照明与其他设施的持续用电表现已经进入设计，但尚未接入正式玩法，必须标为待完善。

时间推进由[时间与日夜](15_技术施工_时间日夜与基地能源.md)负责；玩家手电的输入和光照表现由[玩家与操作](03_技术施工_玩家与操作.md)负责；本文件拥有跨场景电力资源、消费规则和未来负载扩展契约。

## 1. 系统边界和状态所有者

| 子域 | 唯一事实所有者 | 当前状态 | 数据生命周期 |
|---|---|---|---|
| 基地电力 `base_power` | `BaseManager.data`，规则由`BaseEnergyService`计算 | 已实现 | 长期存档，跨行动保留 |
| 手电电力 `flashlight_power` | 当前角色的`PlayerFlashlight3D` | 已实现 | 行动运行态；快照保存`flashlight_charge_ratio` |
| 手电模块 | `BaseData.flashlight_module_id`与角色手电实例 | 已实现 | 永久解锁、行动装配 |
| 基地用电负载 | 目标`BasePowerGridService`；当前不存在 | 待完善 | 未来按稳定负载ID登记，不由灯节点持有能源余额 |

基地电力与手电电力属于同一系统，但不共用同一个余额。基地恢复舱可以把基地电力转换为角色生命和手电电量；电池道具只补充手电，不增加基地能源。

## 2. 当前正式玩法

### 2.1 手电电力

- 基础容量用`0.0–1.0`比例保存。基础模块满电持续300秒，加强模块420秒，节能模块600秒。
- `F`键切换整套手电光组。电量耗尽时拒绝开启；开启且不在基地时持续耗电。
- 手电的开关、电量和模块影响真实照明、敌人揭示倍率、作用范围及HUD三格电芯显示。
- 小型电池`item_battery_s`恢复25%，大型电池`item_battery_l`恢复75%，电芯包`item_cell_pack`恢复100%。满电时不消耗道具。
- 基础、加强、节能模块分别使用`item_flashlight_basic / advanced / efficient`。模块只改变倍率，不建立第二套电量。
- 进入基地只暂停耗电，不自动充电；离开基地后沿用已有电量和开关状态。

### 2.2 基地电力

- 基地能源容量100，初始为100，使用世界累计游戏时间按每游戏小时4点恢复。
- 不读取设备时间，不产生离线收益；暂停和倍速都跟随权威游戏时间。
- 状态恢复舱按缺失比例计费：满生命恢复成本25，满手电恢复成本25，两项相加后向上取整。
- 能源不足、角色倒地、接口缺失或存档失败时整笔拒绝。写盘成功后才修改角色生命和手电，不能出现只扣电或只恢复一部分。
- `consume_base_energy`和`add_base_energy`是当前通用入口。调用失败必须保留原余额。

## 3. 命令、查询与事件

### 3.1 当前接口

| 类型 | 接口 | 输入 | 结果与失败 |
|---|---|---|---|
| 查询 | `get_base_energy_snapshot` | 可选累计游戏秒 | `current/capacity/ratio/regen_per_game_hour`；无档案时返回不可用 |
| 命令 | `sync_base_energy_to_game_time` | 累计游戏秒、是否写盘 | 只补足正向时间差；不允许倒放产生电量 |
| 命令 | `consume_base_energy` | 正数、原因 | 余额不足或写盘失败返回`false`并回滚 |
| 命令 | `add_base_energy` | 正数、原因 | 满电、非法输入或写盘失败拒绝并回滚 |
| 命令 | `recover_player_state_at_facility` | 当前玩家 | 返回成功、花费、剩余电量、生命与手电恢复量，失败不产生半笔结果 |
| 查询 | `PlayerFlashlight3D.get_charge_ratio` | 无 | 返回`0.0–1.0` |
| 命令 | `set_light_enabled/restore_charge/set_charge_ratio` | 开关或比例 | 耗尽拒绝开启，比例始终裁剪到有效范围 |

当前事件为手电的`light_enabled_changed / charge_changed / reveal_multiplier_changed / state_changed`。基地能源目前由设施查询刷新，尚无完整领域事件；未来统一事件应由电力所有者发出，灯具和UI只能订阅。

### 3.2 未来扩展接口

基地用电负载接入时使用稳定`power_consumer_id`，登记`category / priority / requested_state / minimum_power / presentation_targets`。目标命令为`request_power_state(consumer_id, enabled)`，目标查询为`get_power_grid_snapshot()`，目标事件为`power_grid_changed(snapshot)`和`consumer_power_changed(consumer_id, powered, reason)`。

任何场景灯、终端或生产设施都不得直接修改`base_energy_current`。负载节点卸载后只移除运行订阅，稳定ID和已提交状态仍由电力服务解释。

## 4. 基地电力表现设计（待完善）

以下内容属于`POWER-SYSTEM r1`的目标设计，当前正式游戏尚未接入，不得标记为已实现或以旧灯光测试冒充通过。

- 基地中央主灯、应急灯带、终端、恢复舱和未来生产设施登记为独立负载。美术自发光可以保留弱待机轮廓，但不能在断电时继续表现为满功率照明。
- 供电正常时保持当前基地灯光效果。进入节能状态后先降低装饰与非关键灯的亮度，再停用非关键设施；应急灯和出口识别保持最低可读性。
- 电量不足时恢复舱明确显示所需电量并拒绝交易。未来设施不得通过负数余额透支。
- UI需要显示基地剩余电量、恢复速度、当前总负载、预计可用时长和被限电的负载；每个提示都来自同一电网快照。
- 未来可以增加发电机、蓄电池组、太阳能、线路故障、分区开关和设施优先级。新增来源与负载只能通过登记接口扩展，不能复制另一套基地能源字段。

首版负载功率、节能阈值、停电持续时间和设施优先级仍待玩法验证，当前不冻结具体数值。接入前必须先补负载数据表和失败矩阵。

## 5. 数据与存档

当前长期字段为`base_energy_current / base_energy_capacity / base_energy_last_synced_game_seconds / flashlight_module_id`。行动快照保存`flashlight_charge_ratio`。电池和模块使用`ItemRegistry`稳定ID。

未来schema新增字段时必须提供缺省迁移：没有电网字段的旧档按“现有基地灯光正常、无已登记持续负载”加载；迁移不能扣除旧档能源。运行时灯节点ID、RID和场景路径不得写入存档。

## 6. 独立开发与正式接入

- `BaseEnergyService`保持无场景依赖，可用`BaseData`替身验证恢复和恢复舱计划。
- `PlayerFlashlight3D`通过公开电量、开关、模块和事件接口接入；电力服务不得访问其私有灯节点。
- 正式接入路径为99F基地恢复舱、基地能源HUD、玩家手电、物品使用器和行动快照。
- 未来`BasePowerGridService`先以纯数据服务和替身负载完成，再接基地灯光；不能先让灯节点直接扣档案余额。
