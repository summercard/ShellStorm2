# 技术施工｜主页面与角色换装 v0.1

更新日期：**2026-08-20**

## 1. 启动主页

启动主页不是独立假场景。`MainEntryScreen3D`覆盖在已加载的`TowerDescent3D`上，引用当前真实`Player3D`与其玩法Camera。展示期间锁定玩家输入并使用33°近景；点击开始后用1.15秒插值恢复原Camera Transform和FOV，再解除输入锁。整个过程不切场景、不复制角色，也不重置库存和世界状态。

塔楼固定相机更新在主页或衣柜持有镜头期间暂停；覆盖层关闭后恢复既有相机链。

## 2. Avatar槽位

当前正式衣柜使用六个纯表现槽：`body / head / hand / feet / hat / glasses`。每个槽至少有3个合法变体；目前使用程序材质变色和现有角色组件验证完整链路。选择外观只调用`PlayerAvatar3D`既有装配入口，不改变角色碰撞、属性、武器、背包或动画所有权。

衣柜界面保持实际角色居中：左侧为当前穿搭，右侧为分类和140×140方形物品框。关闭或每次选择后，将稳定变体ID写入`BaseData.avatar_customization`；再次进入主页面、衣柜或读档时应用同一记录。

## 3. 资产制作合同

角色美术母版位于`assets/art/characters/player/chr_player_avatar_template_3d/source/chr_player_avatar_template_source_v001.blend`。合同为1.50米参考高度、脚底中心原点、Blender前向`-Y`/Godot前向`-Z`、根缩放1，并提供七个制作槽与九个挂点。正式资产可替换视觉组件，但运行时稳定槽ID和挂点名不得变化。

项目内未安装Skill草案位于`skills_drafts/player-avatar-asset-standard/`；在项目验证成熟前不安装到Codex全局目录。

## 4. 基地衣柜设施与脱困

`avatar_wardrobe`通过现有`BaseFacility3D → BaseFacilityCatalog → TowerDescent3D/BaseWorld3D`菜单链打开，不新增第二套交互系统。

ESC返回基地中心是安全脱困，不是战局撤离：仅角色处于99/100层基地安全体积且无过渡事务时可用，目标为既有`facility`中心出生点；战局中按钮禁用并显示原因。

## 5. 验收

- [x] 主页使用真实角色和同一Camera，无场景切换，开始后镜头无缝回位。
- [x] 六类外观均至少3项，方形物品框与当前穿搭区可读。
- [x] 外观只影响表现并进入同一基地存档。
- [x] 衣柜关闭后恢复相机与输入锁。
- [x] 脱困只在基地安全体积内可用，战局中不可使用。
