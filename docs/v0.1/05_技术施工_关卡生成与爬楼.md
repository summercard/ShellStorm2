## 3. 跨层入口、安全屋与逐层生成触发

### 3.1 跨层连续性

<span style="color:#2E7D32">**[已实装基线]** 98–95F 均由上一层下行楼梯连接固定 15×15m 安全屋；安全屋禁用战斗且不刷怪。</span>

<span style="color:#2E7D32">**[已实装｜2026-08-06]** 正式循环已改为“逐层向前生成”：初始场景快照只有楼顶、99F基地与98F入口壳体3个房间节点；到达门提交 N 层完整布局、出口大厅、N→N-1真实楼梯和N-1入口壳体后才放行，不再启动时预建98–95F全部房间节点。</span>

当层计划必须同时提交 `next_floor_entry_anchor`，它定义本层下行楼梯和下一层安全屋的同一组空间接口。下一层不得在加载或开门时重新选择入口；楼梯两端必须有真实门槽、实体门、围护、楼板洞口和可通行落地平台。

### 3.2 `floor_seed_gate` 的正式位置

<span style="color:#777777">**[历史基线｜已取代]** 旧版曾把安全屋通往首个内容房的前门登记为 `floor_seed_gate`，并在场景初始化时预分配隐藏候选节点；该逻辑已不再使用。</span>

<span style="color:#2E7D32">**[已实装｜2026-08-06]** `floor_seed_gate` 已迁移为“上一层下行楼梯间通往本层入口安全屋的到达门”。玩家站在楼梯间侧与该门交互时触发本层生成；生成、验证和行动快照全部成功前，门扇、门碰撞和导航连接保持关闭。成功后才允许开门进入安全屋。</span>

<span style="color:#2E7D32">**[已实装｜2026-08-28 严格房间归属]** 开门、提交FloorBundle和进入房间是三个独立事实。到达门开启只改变门扇、碰撞和路线状态；只有角色中心真正跨过墙体内沿，才能将`current_room_id`切换到安全屋。楼梯平台、门槛和房间外部不属于安全屋。</span>

房间归属统一由`DungeonRoom3D.contains_world_position()`给出严格内部体积，水平边界位于墙体内沿。以下范围不得复用为房间归属：

- 读档位置容错：可在房间外放宽2米，只用于接受旧快照坐标。
- E键交互距离：只用于找门/设施，不代表角色已进房。
- 楼层预加载与流送范围：只决定节点活性，不改`current_room_id`。
- 基地禁射外壳、自动门防夹和楼层高度容差：是各自独立的安全/物理合同，不作为普通房间归属。

```text
玩家在楼梯间侧与 floor_seed_gate 交互
→ 显示生成中状态，门保持实体关闭，并拒绝重复请求
→ FloorGenerationRequest(run_seed, floor_id, entry_anchor, floor_rule_version)
→ 生成并验证 FloorBundle(N层 + N→N-1楼梯 + N-1入口壳体)
→ 原子提交 FloorPlan / VerticalConnector / 下一入口壳体
→ 立即写入行动快照
→ 全部成功后打开到达门
→ 角色真正跨过墙体内沿后才进入本层安全屋
```

- <span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 入层到达门免普通钥匙、免清房条件，且一律不触发命运三选一；命运选择只属于后续内容房推进门。</span>
- 生成失败时不弹卡、不消耗钥匙、不部分开门；丢弃候选计划后确定性重试。
- 已提交楼层再次交互只读取原 `layout_id`，不重随机。
- 楼顶和 99 层长期基地不参与随机楼层生成，作为显式例外。

### 3.2.1 门用途归纳与阻塞条件

| 门类别 | 例子 | 清房/钥匙 | 是否生成楼层 | 失败时行为 |
|---|---|---|---|---|
| `base_transit` | 100F→99F基地 | 否 | 否 | 只报告交通门状态，不读取FloorBundle |
| `floor_arrival` | 99F→98F及后续下端到达门 | 否 | 是 | 验证失败保持关闭，不进入空层 |
| `room_progression` | 普通房间之间 | 是/普通钥匙 | 否 | 明确提示清房、事件或钥匙条件 |
| `boss_descent` | 95F Boss后下行门 | Boss下行权限 | 下一层由下端隔离事务生成 | 没有权限保持关闭 |
| `airlock_exit` | 隔离间→下一安全屋 | 否 | 已在隔离确认时准备 | 先锁后门并卸载旧段，再开前门 |
| `vertical_transit` | 不承担生成职责的普通垂直交通 | 否 | 否 | 只切换楼层/房间 |

<span style="color:#2E7D32">**[2026-08-06修复]** 基地到达门不再按物理层索引盲目提交FloorBundle；只有登记为`floor_arrival`的边才能请求战斗层规划。Boss下行边也不再在楼梯上端开门时提前把下一层标成已生成。专项快照必须覆盖六类用途，避免后续新增门复用错误策略。</span>

### 3.3 98F→95F 首个 Boss 区段

首局入口与逐层循环固定如下：

```text
初始常驻：99→98楼梯 + 98F安全屋壳体 + 98F到达门
打开98F到达门 → 创建98F整层 + 98→97楼梯 + 97F安全屋壳体
打开97F到达门 → 创建97F整层 + 97→96楼梯 + 96F安全屋壳体
打开96F到达门 → 创建96F整层 + 96→95楼梯 + 95F安全屋壳体
打开95F到达门 → 创建95F整层 + Boss路线 + 95→94过渡设施
```

98–95F 是开局特殊 Boss 区段，共 4 个战斗楼层；此后 94–90F、89–85F 等按 5 个战斗楼层组成后续 Boss 区段。Boss 仍固定出现在楼层号为 5 的整数倍的楼层，不能为了名称统一而虚构 99F 战斗层。

#### 3.3.1 98F首门的大循环边界

<span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 99F→98F安全屋到达门同时是98–95F Boss大循环的唯一起点边界。首次开门只负责生成98F，玩家整体进入安全屋后门扇和碰撞必须在身后重新关闭，不得保持常开。</span>

<span style="color:#2E7D32">**[已实装并验收｜更新至2026-08-13]** 从98F安全屋反向开启该门定义为“放弃本次大循环并撤退”，必须显示二次确认。确认后清空背包、两个真实快捷物品槽与主/副装备枪位；保险格仍按其独立保险契约保留，不得复制或遗留已丢失物品。</span>

<span style="color:#2E7D32">**[撤退复位已修复｜2026-08-06]** 确认撤退后必须同时回滚首区段运行世界：销毁首门开启后生成的98–95F房间、走廊、楼层Stage、敌人、掉落、门状态、到达状态和房间缓存；`generated_floor_indices`恢复为仅含楼顶，场景恢复楼顶/99F基地/98F入口壳体3房与2段楼梯。再次从基地前往98F时，下端到达门必须关闭，重新交互并通过FloorBundle校验后才重新生成98F；玩家再次完整进入安全屋后，首门仍须在身后关闭。不得持久化上一次撤退行动的 `_vertical_arrival_open`、首门armed/sealed或已提交楼层状态。撤退后的入口壳体重建必须与正常FloorBundle使用同一施工顺序：先计算连接两端共享的5m门槽，再生成房间壳体、门碰撞和楼梯接驳；禁止使用默认门槽先建墙，否则会出现门已打开但错位墙碰撞仍挡路的空气墙。</span>

<span style="color:#2E7D32">**[二次进入封门事务修复｜2026-08-28]** 安全屋首门关闭由严格房间归属确认后的房间切换事务负责，不得仅依赖可被流送停用的`Area3D.body_entered`。封门必须先于`room_transition`行动快照写入，使实体门、路线`edge_states`、`initial_loop_gate_sealed`与`vertical_arrival_open`保持原子一致；撤退重建后的第二轮进入必须走真实物理跨门验收，禁止直接调用封门回调伪造通过。</span>

#### 3.3.2 普通撤离点成功返航

普通撤离信标、条件撤离点和合法返航设施完成读条后统一进入“成功返航”：保留已拾取战利品、当前 I 键背包、主副武器、装备背包、快捷栏与保险格，清理本轮战斗楼层后将角色放回99层 `facility` 基地房间。不得重新加载塔楼场景或把玩家放到100层天台；不得调用98F反向撤退的清空物品步骤。

### 3.4 开门与生成失败的安全语义

- 禁止“先开门、再生成”。生成时门必须具有实体阻挡，玩家、投射物、AI 和导航均不能提前穿过。
- 同一 `generation_transaction_id` 重复交互只附着到原任务；不得重复创建房间、楼梯、门、怪物或掉落。
- <span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 可装备背包通过现有掉落权重进入搜索容器与怪物战利品：2格包偏浅层/普通搜索，4格包偏中层/精英，8格包偏深层/Boss；地面拾取、主动丢弃和容量缩减溢出均复用同一个 `GroundLootPickup3D`，不得为溢出物创建不可拾取的临时节点。</span>
- FloorBundle 中任一楼梯端门、碰撞、导航、面积或可达性校验失败，整包回滚；当前门保持关闭并允许玩家退回上一层。
- 24 次确定性重试和安全模板均失败时显示明确错误，不得用透明墙、瞬移或假门掩盖残缺布局。

## 4. 先算面积的楼层预算

### 4.1 面积口径

<span style="color:#2E7D32">**[已实装｜首批]** 规划器计算 250×250m 总面积，扣除 0.30m 外墙、65m 核心和 6500m² 楼梯/井道/门前净空/不可规整区，再以 0.42 占用率和约 1450m²参考房成本得到普通层 14 个内容房目标；每个计划同时保存房间、内墙与走廊估算成本。</span>

```text
A_gross = area(floor_boundary_polygon)

A_fixed = union_area(
  perimeter_keepout
  structural_core / columns / shafts
  entry_stair + entry_safe_room
  candidate_exit_stair_reservation
  unique_95_94_elevator_bay
  transition_airlock
  authored_holes / facilities / forbidden_zones
)

A_usable = A_gross - A_fixed
A_play_budget = A_usable × target_occupancy_ratio
```

- `target_occupancy_ratio` 可配范围为 0.35–0.48，当前默认 0.42；剩余面积用于结构留白、绕行、性质检验和后续内容扩展，禁止为塞满面积而贴边硬挤。
- `union_area` 必须去重，重叠的核心/楼梯禁建区不可重复扣除。
- 面积计算使用组件真实 `placement_bounds`，不只用可见地面面积。

### 4.2 墙体、走廊与设施成本

每个候选房间的预算成本为：

```text
C_room = area(expand(max(mesh_bounds, collision_bounds), placement_clearance))
C_corridor = path_length × corridor_outer_width + turn_and_junction_area
C_door = door_leaf + trigger + interaction + projectile_clearance 的联合占位
C_total = ΣC_room + ΣC_corridor + ΣC_door + 楼梯/设施专用占位
```

- 0.30m 墙厚必须包含在 Mesh/碰撞外框中；共墙只有在使用同一墙组件时才允许去重。
- 水平走廊使用 5m 模块外宽，净宽由两侧真实墙厚扣除；楼梯通道使用楼梯资产声明的 6m 通行宽和完整围护外框。
- 楼梯、电梯、结构井、楼板洞口使用资产 `bounds` 再向外扩展至少一个 5m 检修/安全带；普通房间不得占用。
- 转角、T/X 路口、门扇旋转和交互区单独计算，禁止将其当作零面积节点。

### 4.3 房间数估算

使用标准 30×25m 房间、一格外扩安全带和平均 10m 走廊份额定义参考成本 `C_ref`：

```text
C_ref = area((30m + 2×5m) × (25m + 2×5m))
      + 10m × 5m
≈ 1450m²

N_estimated = floor(A_play_budget / C_ref)
N_main = clamp(round(N_estimated × 0.72), 10, floor_rule.main_room_max)
N_branch_budget = max(0, N_estimated - N_main)
```

`floor_rule.main_room_max` 默认为 18。`N_estimated` 只用于初始估算；真正放置每个房间后都必须按其实际外框、走廊和门占位扣减剩余预算。标准 250×250m 楼层的初始目标是约 14–16 个内容房，其中主路不少于 10 个；最终数量以实际占位验证为准。

### 4.4 房型尺寸组合

<span style="color:#2E7D32">**[已实装]** 所有内容房按长边≥30m、短边≥25m校验，并组合标准、宽型、纵深型、中型、大型与 Boss 竞技场；15×15m仅用于楼梯安全屋。</span>

| 房型 | 外轮廓尺寸 | 格数 | 主要用途 |
|---|---:|---:|---|
| `STANDARD` | 30×25m | 6×5 | 基础战斗、普通搜刮、事件 |
| `WIDE` | 40×25m | 8×5 | 横向火线、多入口、阵地战 |
| `DEEP` | 30×40m | 6×8 | 纵深推进、分波、追逐 |
| `MEDIUM` | 35×30m | 7×6 | 精英、储藏、复合事件 |
| `LARGE` | 40×35m | 8×7 | 高密度战斗、多目标房 |
| `ARENA` | 50×40m 以上 | 10×8 以上 | 精英终点、小型 Boss、特殊防守 |
| `BOSS_ARENA` | 当前 90×90m | 18×18 | 阶段 Boss，保留现有口径 |

- 30×25m 是内容房硬下限，不得因布局剩余面积不足而缩小；放不下时应更换出口锚点、路线形状、大房房型或减少支路。
- 房型允许整体旋转 90°；以较长边不小于 30m、较短边不小于 25m 验证下限，因此 25×30m 是 30×25m 的合法旋转，不是小房。
- 15×15m 入口安全屋、楼梯大厅、走廊节点和纯设施间属于交通/设施空间，不计入内容房数，也不允许以“小房”身份代替 10 房主路要求。
- 房型选择使用楼层数据的 `room_shape_weights`，标准层建议约 45%–60% `STANDARD`、20%–30% `WIDE/DEEP`、15%–25% `MEDIUM/LARGE`；`ARENA` 受楼层和房型配额限制。
- 同一主路上不连续放置 3 个完全相同尺寸且同向的房间；宽房、深房、大房和标准房交替，使战斗距离、视线和路线节奏发生可感知变化。
- 房间尺寸只决定空间与遭遇容量上限，不能直接等同于怪物数；怪物数仍由 `EncounterPlan` 在楼层战斗预算内决定。

## 5. 主路、支路与下行楼梯生成

### 5.1 必达主路

<span style="color:#2E7D32">**[已实装]** 普通层从 `floor_seed_gate` 到下行楼梯大厅固定经过 10 个内容房；支路只以树边挂接，不产生下楼捷径。Boss层在90×90 Boss区前经过11个主路/整备内容房。</span>

- 主路是从 `entry_safe_room` 到 `down_stair_lobby` 的简单路径，不允许重复经过同一房间或走廊。
- 任何支路回连或特殊门都不得创造低于 10 房的下楼捷径；验证器按“最短路径”而不是作者标记的主路计数。
- 下行楼梯大厅是最终路线节点，必须实际连接下一层安全屋，不能是地图图标或瞬移假出口。
- 楼梯资产的 `UpperFlight_Walkable / LowerFlight_Walkable` 除了承担角色行走碰撞，还必须分别声明 `camera_stair_slab=upper/lower`。相机只对这两块斜楼板做垂直净高检测；命中时限制在楼板下方，禁止通过隐藏楼板、修改普通楼板碰撞或全局缩短镜头来规避穿模。

### 5.2 几何生成顺序

```text
1. 读取 floor_boundary 与全部结构占位
2. 固定 entry_stair + entry_safe_room + floor_seed_gate
3. 在合法楼梯接口中选择候选 exit_anchor
4. 在 5m 占用网格上生成自避交主路骨架
5. 沿骨架放置 N_main 个实际房间外框
6. 解析两端真实门槽，用正交 5m 通道连接
7. 把剩余面积预算分配给支路
8. 放置下行楼梯大厅、N→N-1楼梯、下一层入口安全屋壳体并写出 next_floor_entry_anchor
9. 分配房型、遭遇槽、掉落槽、门策略和地图元数据
10. 全量验证后一次提交
```

出口候选必须与入口楼梯保持足够的图距离，且其完整楼梯资产、楼板洞口、围护、接驳走廊和下一层安全屋投影都必须在放房前预留。

### 5.3 支路与路线趣味

- 标准层目标生成 2–5 条支路，单条 1–4 房；面积不足时先减支路，不减 10 房主路。
- 支路接入点分布在主路 20%–80% 区间，不得全部挂在同一个枢纽。
- 死胡同末端必须是可读的高价值、事件、升级或精英目标；纯战斗无额外回报的长死路禁止提交。
- 最多一半支路可以回连主路或另一支路形成小环；回连边不得跳过 Boss、专用门或将主路最短房数降到 10 以下。
- 主路不连续出现 3 个以上同类房；入层前 2 房不放 Boss/高压精英，最后 2 房不同时为纯搜刮房。
- 两房门之间的单段直走廊目标不超过 30m；超出时需放置合法中继节点或重排，避免空洞长跑。
- 房型分配服从楼层生态预算，但每个普通层至少有战斗、搜刮/储藏和事件/升级三种决策语义。
- 生成器在放置每个房间时从上表选择合法房型，用真实尺寸计算墙体、门槽、走廊和碰撞外框后再组合，禁止先生成抽象点位、事后强行缩放房间。

### 5.4 钥匙与防卡死

- `floor_seed_gate` 免钥匙；普通主路门继续使用普通房间钥匙与门后命运选择。
- 每个消耗普通钥匙后可进入的房间，必须在清房、完成事件或打开主容器后保底返还 1 把普通钥匙。
- 生成器对主路每个前缀执行钥匙流量验证：保底可获钥匙数不得少于到达下一必经门的必需消耗。
- 可选支路不得永久消耗唯一一把主路钥匙；支路完成保底回补，中途失败可原路退回。
- 房间遭遇、事件或掉落解析失败时使用安全清房/保底钥匙结果，不允许因空刷怪、空事件或空容器永久锁死路线。

## 6. Boss 层、95→94 唯一电梯与区段隔离间

<span style="color:#2E7D32">**[已实装｜规划器与内容]** `floor_number % 5 == 0` 已进入生成规则；95F、90F、85F分别生成不可绕过的Boss区与Boss前整备房，并绑定三套不同的稳定内容ID、Boss模型、三阶段技能袋、竞技场模型和掩体碰撞。后续80F及更深内容按同一合同扩展。</span>

- Boss 房必须在主路上且不能被支路绕过；它位于下行楼梯之前的最后阶段。
- Boss 层仍需满足入口安全屋到下行楼梯之间至少 10 个内容房；Boss 房可计入这 10 个，两个楼梯大厅不计入。
- 保留现有“Boss 前升级/整备房”；整备房和 Boss 房之间不放额外普通钥匙锁，避免战前软锁。
- Boss 死亡只签发一次 `item_boss_descent_key`；它只能打开本阶段唯一 `boss_descent_gate`。
- `boss_descent_gate` 后必须是真实 `post_boss_stairwell`，不能以传送或地图按钮替代。
- <span style="color:#1565C0">**[用户设计｜唯一电梯规则]** 全游戏关卡内的下行电梯只存在于 95→94 楼梯间；普通楼层、普通支路、安全屋、其他 Boss 后楼梯间均不得生成电梯。99F 基地既有接口属于基地设施，不计入本条关卡电梯。</span>
- 95F Boss 房、专用门、95→94 楼梯间、电梯、隔离间和 94F 安全屋壳体的完整占位必须在 95F FloorBundle 提交前共同验证。
- 每个Boss区段结束后都使用同一隔离提交结构以释放上一段：95→94、90→89、85→84……均有双门隔离间；只有95→94额外装配电梯，后续Boss楼梯明确没有电梯。

### 6.1 95→94 固定过渡结构

```text
95F Boss房
→ 95F出口间
→ boss_descent_gate（Boss专钥匙）
→ 95→94真实楼梯间（唯一电梯位于此处）
→ isolation_entry_gate
→ 15×15m隔离间
→ isolation_exit_gate / 94F floor_seed_gate
→ 94F入口安全屋
```

唯一电梯位于不可逆隔离提交点之前。玩家在进入隔离间前仍可返回本区段收集物品或使用电梯；隔离提交后不得通过电梯、楼梯、复活或读档返回已经销毁的 98–95F 运行世界。

后续区段沿用以下无电梯结构：

```text
Boss楼层B出口 → B→B-1真实楼梯间（无电梯）
→ 双门隔离间 → B-1入口安全屋 → 下一Boss区段
```

### 6.2 隔离间双门互锁

隔离间是与安全屋同尺寸、无敌人、无掉落、无命运选择的独立交通设施。两扇门遵循硬互锁：

1. 后门开启时前门保持关闭且有实体碰撞。
2. 玩家全部进入隔离间后，后门自动关闭并锁定。
3. 后门关闭后先纯数据生成并验证下一FloorBundle；验证失败且尚未提交永久遗失时，可以取消过渡并重新打开后门让玩家返回。
4. 下一计划有效后才执行不可逆区段提交、旧区段卸载和下一包实例化；全部成功后前门才允许开启。
5. 任意失败都不能让两门同时开启；不可逆提交后的失败只能让玩家留在隔离间重试或切换已验证安全模板，不能重新打开后门回到已销毁区段。
6. 隔离间必须有恢复/超时策略，门动画或信号丢失时回到“玩家安全留在隔离间、两门关闭”的可重试状态。

### 6.3 永久遗失提示与提交点

<span style="color:#1565C0">**[用户设计]** 玩家跨过区段隔离间后，旧区段中所有未被拾取的物品永久丢失，以便彻底释放旧楼层内存。</span>

- `isolation_entry_gate` 交互必须显示二次确认：“进入后无法返回；{当前区段楼层范围}未拾取物品将永久丢失。”首区段显示98–95F，默认焦点为“暂不进入”。
- 提示可显示“当前区段仍有已发现未拾取物 X 件、玩家主动丢弃物 Y 件”，但不得泄露未探索房间的具体物品名称或品质。
- 永久遗失范围包括自然掉落、容器已生成未拾取物、玩家主动丢在地面的武器/配件/道具和未领取房间奖励；已经进入装备、背包或保险格的物品不受影响。
- 真正提交点不是点击确认，也不是踏上楼梯，而是“玩家完整进入隔离间、后门已关闭锁定且下一FloorBundle纯数据计划已验证”。提交后写入 `segment_commit_id`，销毁旧区段掉落与运行态，并禁止回滚到提交前存档。
- 为避免复制/恢复漏洞，卸载前先冻结拾取与丢弃交互，再用稳定实例 ID 结算“玩家所有”与“世界遗留”集合；同一提交重复执行不得重复销毁、重复保存或复制枪械。
- Boss边界是到达门规则的特殊编排：隔离前门同时是下一楼层的`floor_seed_gate`。玩家确认进入并锁定后门后，系统自动准备下一FloorBundle；无需在狭小隔离间再次点击第二次生成，但前门仍须等提交、卸载和实例化全部成功才开启。

## 7. 生成事务、确定性与回退

```text
FloorGenerationRequest(
  run_seed, floor_id, floor_number, floor_rule_version,
  floor_boundary, entry_anchor, structural_reservations,
  segment_id, generation_transaction_id
)
→ MeasureUsableArea
→ ReserveEntryAndExitStructures
→ BuildCriticalPath(min_content_rooms = 10)
→ AttachBranchesWithinRemainingBudget
→ AssignRoomContent / EncounterSlots / LootSlots
→ ResolveDoorSocketsAndCorridors
→ ValidateFloorPlan
→ BuildVerticalConnectorAndNextEntryShell
→ ValidateFloorBundle
→ CommitFloorBundle
→ PersistPlanSnapshot
→ OpenArrivalGateAndRevealSafeRoom
```

- `layout_id = hash(run_seed + floor_id + floor_rule_version)`；同一输入必须生成完全相同的结果。
- 每个候选使用可追踪 `attempt_salt`，最多进行 24 次确定性尝试；重试时先减少支路和大型房，不降低 10 房主路不变量。
- 24 次失败后加载与当层边界/楼梯接口匹配的预验证安全模板；安全模板仍需 10 房主路和真实下行楼梯。
- 候选计划验证失败时不得实例化任何房间、墙、门、走廊或刷怪节点。
- 连安全模板也无法验证时，门保持关闭、显示开发诊断并允许玩家退回上层；禁止生成残缺地图让玩家进入。
- 生成事务只追加当前层和下一跨层接口，不能顺带预生成整个 Boss 区段；区段生命周期服务只管理已提交 FloorBundle 的所有权和卸载顺序。

## 8. 几何、门与走廊不变量

1. 地砖、实墙、门墙、拐角、楼梯、走廊和设施是独立可复用 Mesh/Scene。
2. 所有 `placement_bounds` 边界对齐 5m 网格；奇数格中心可位于半格。
3. 房间及走廊的 Mesh、实体碰撞、子弹碰撞、导航、相机代理与地图外框必须来自同一组组件记录。
4. 门墙的门扇、触发区、碰撞、相机代理和目标边使用同一门槽局部坐标。
5. 房间硬外框、走廊扫掠外框、门交互外框、楼梯/电梯禁建区两两不重叠，只允许已声明的共墙或门接口相交。
6. 走廊模块数依真实门中心距离计算：`round(door_to_door_distance / 5m)`，所有段长必须是 5m 整数。
7. 入口楼梯、下行楼梯、楼板洞口、围护和落地平台使用同一资产占位，禁止房间占用楼梯预留区或洞口上方。
8. 不得用隐藏大平面、透明墙或超出 Mesh 的不可见碰撞修补生成结果。


- <span style="color:#2E7D32">**[已实装]** 正式 3D 已采用“开门生成、进房激活”的首波逻辑。</span>
- <span style="color:#2E7D32">**[已实装｜2026-08-07]** 99层基地西、东两侧交通门均由 `E` 单独开启；门板、碰撞与提示在玩家越过门槽后自动关闭，但楼梯路线授权仍独立保留，不能因门板回关而让下端到达门失效。基地室内的开火锁定也独立按真实30×30m室内范围判定，门状态、房间进入事件和楼梯交通区均不参与禁射判断。</span>

<span style="color:#2E7D32">**[天台门内侧交互修复｜更新至2026-08-29]** 垂直楼梯采用双端实体门。角色反向上楼时，在完整穿过上端门之前仍保留下层房间上下文，因此交互系统必须额外查询永久基础楼梯或已开放战局路线的上端门，不能只查询当前房间门表。现在99F→天台的上行门可在楼梯内侧显示提示并按 `E` 独立开启；它不会联动重开已经自动关闭的99F基地侧门，也不会消耗钥匙、触发命运或生成FloorBundle。100F↔99F西侧楼梯永久可查询，其他垂直交通继续遵循各自战局开放状态，防止楼梯内部形成单向陷阱。</span>

- 无合法敌人计划时写诊断并使用安全清房结果，禁止永久卡门。

### 9.1 区段生命周期与内存释放

房间流送与区段卸载是两层不同机制：流送只停用远处房间，区段卸载则彻底释放旧区段的 Node、Mesh、碰撞、导航、敌人、掉落、门、VFX、音频、小地图缓存和运行时引用。

```text
玩家确认进入隔离间
→ 玩家完整入内，后门关闭并锁定
→ 纯数据生成并验证下一 FloorBundle / 安全回退模板
→ 失败则取消过渡并允许重新打开后门；尚不产生永久损失
→ 冻结旧区段拾取/丢弃与运行推进
→ 原子保存随身物、销毁清单、区段结果与 segment_commit_id
→ 取消旧区段信号、计时器、对象池借用和导航任务
→ 销毁旧区段未拾取物与全部场景节点
→ 清理小地图/怪物/相机/剧情缓存中的旧引用
→ 按已验证计划实例化下一 FloorBundle
→ 验证节点数、RSS、悬空引用与下一入口通行
→ 打开隔离间前门
```

- 当前Boss区段只能在上述提交点后整体卸载；首段为98–95F，后续为94–90F、89–85F等。不能在Boss死亡、专用门开启、玩家位于下行楼梯间或电梯交互时提前卸载。
- 当前活动区段、当前隔离间和下一入口安全壳体始终保留；更早区段不得继续以隐藏 Node 形式占用内存。
- 区段卸载失败时前门保持关闭并给出可重试提示；不得在旧引用尚活跃时强制放行造成空气墙、幽灵敌人或崩溃。

### 9.2 区段计划与房间表现分离

<span style="color:#1565C0">**[冻结方案｜2026-08-12]** 98–95F仍是允许完整往返的玩法区段，但目标运行结构改为“进入区段时一次生成并验证纯数据 `SegmentPlan`，门按原节奏提交已冻结的 `FloorSlice`，房间场景表现按拓扑距离加载和释放”。流送只释放可重建的Mesh、碰撞、灯光、交互体和AI节点；门、容器、敌人HP/死亡、地面物、灯开关、事件与Boss阶段保存在稳定 `SegmentRuntimeState` 中。返回上层时恢复同一内容，绝不重新抽取随机结果。</span>

该方案的模块所有权、五态房间流送、35m/55m滞回建议、空间注册表、施工顺序和完整验收矩阵统一以[性能优化、长时运行与热管理 §3.8](13_技术施工_性能优化与热管理.md#38-p0boss-区段数据常驻表现流送重构方案2026-08-12冻结)为准。本关卡文档继续拥有玩法边界：95→94隔离提交前可返回98F；区段内表现卸载不产生永久遗失；只有隔离事务可以永久销毁旧区段状态和未拾取物。

EVENT 房不是敌对房，未结算时不得显示“战斗未结束”或“清理怪物”。其必做目标契约为：

```text
首次/再次进入未结算 EVENT
→ 确认 event ServiceStation 存在；丢失则在房间中部安全区自动重建
→ 常驻紫色地标、光柱和“事件目标”标签，近距离显示 [E] 结算房间事件
→ 事件终端只保留交互 Area，不使用角色实体阻挡
→ 非战斗结果立即 cleared；召唤/诅咒结果转入事件敌群清理
→ 已结算非战斗事件若 cleared 丢失，自动修复为已清理
→ 终端实例化仍失败则记录错误并安全解锁，禁止软锁
```

门检查必须先执行房间进度修复，再决定是否阻挡。EVENT 未结算提示“前往紫色光柱按 E”，事件敌群未清提示“清除事件召唤的敌群”；只有真正的敌对房才使用“清理当前房间”。

- 本层生成前，安全屋只显示已知的入层楼梯、安全屋和未开的 `floor_seed_gate`，不泄露候选布局。
- 布局提交后只显示已侦测部分；下行楼梯的实际存在可记录，但未侦测时不提前标出位置。
- 房间使用真实宽高绘制等比矩形；走廊连接门槽边缘，不穿过房间中心。
- 玩家使用实时世界坐标；当前楼层已侦测且存活的敌人使用真实 `Enemy3D` 位置显示红点。
- 95→94 楼梯间在侦测后显示唯一电梯图标；其他楼层和其他 Boss 下行楼梯不得显示电梯占位图标。
- 接近隔离间时，HUD显示“区段离开点”；二次确认必须明确不可返回和未拾取物永久遗失，不能只用普通开门提示。

## 14. 物理楼层权威与基地五米楼中楼（2026-08-20）

楼层显示与空间作用域不得依赖“玩家是否经过指定门”。正式权威由角色世界高度计算：

```text
floor_index = max(0, round(-player.global_position.y / 9.0))
floor_number = 100 - floor_index
```

门、楼梯到达门和隔离间仍负责生成、开关、钥匙与不可逆事务，但不拥有角色当前楼层。角色从基地5米平台走到9米天台、从上一层坠落、传送或读档恢复时，系统按高度刷新楼层；若目标物理层存在包含角色坐标的房间，则同步`current_room_id`、小地图、设施作用域、太阳作用域和存档快照。旧门链仍被调用，不新增旁路功能补丁。

基地局部坐标合同为：99层地面`0m`，楼中楼完成面`5m`，100层地面`9m`。L型楼梯连续连接`0→2.5→5m`；外门小楼梯连接`5→9m`。可见踏步与真实行走碰撞分离：L型楼梯的两段连续坡面与中间平台必须属于同一个`StaticBody3D`，接缝顶面齐平并有最小0.04米重叠；平台和楼梯边缘使用独立栏杆阻挡。低于9米的结构继续标记`camera_stair_slab`供摄像机净空探针使用。

上升坡面与墙面门槛相接时，不能只用门洞中心射线判断通行。角色胶囊会在到达墙面前一个半径处先接触墙体上沿，因此墙体结构碰撞必须在门洞净宽内预留坡面提前接触净空；门洞两侧仍保持完整墙高，门扇碰撞继续由既有`RoomDoor3D`开关。基地东侧100层接口使用2.2米门洞净宽、99层下墙碰撞顶高8.45米，并以真实角色胶囊从内侧走到天台作为回归合同。
