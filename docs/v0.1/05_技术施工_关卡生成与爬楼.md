## 1. 职责与边界

关卡系统拥有整层拓扑、组件坐标、房间类型、连接边、门用途、走廊、楼梯、流送、小地图几何、刷新槽和掉落槽。怪物系统决定刷出什么敌人，掉落系统决定槽位产出什么物品，相机只读取墙组件标记。

| 项目 | 正式值 |

- <span style="color:#2E7D32">**[已实装]** 正式路线由楼顶、99 层基地、98–95 层战斗区域组成。</span>
- <span style="color:#2E7D32">**[已实装]** 组件按 5m 网格装配；整层记录包含房间、边、通道、楼梯占位和楼层流送状态。</span>

## 3. 整层生成事务

<span style="color:#1565C0">**[用户设计]** 当一个楼层首次被触发时，一次生成该层完整随机关卡设计，包含通往下一层的房间、下行楼梯间和所有组件坐标；之后只允许流送，不允许重新随机。</span>

<span style="color:#EF6C00">**[Codex补充]** 采用以下事务阶段。</span>

```text
FloorGenerationRequest(seed, floor_rule)
→ ReserveFootprints（房间/楼梯/电梯/特殊区占位）
→ BuildTopology（主路、支路、终点）
→ PlaceRoomsOn5mGrid
→ ResolveDoorSockets
→ BuildDynamicCorridors
→ AssignRoomContent / SpawnSlots / LootSlots
→ ValidateLayout
→ CommitFloorPlan
→ RevealAndStream
```

提交前任何一步失败都丢弃整个候选计划，不允许在已实例化场景上边生成边挪房间。

## 4. 组件坐标不变量

1. 地砖、实墙、门墙、拐角、楼梯、走廊和设施是独立可复用 Mesh/Scene。
2. 组件边界对齐 5m 网格；奇数格房间中心允许落在半格，判断边界而非强迫节点原点为 5 的整数倍。
3. 所有普通墙从楼面 0m 到 9m；楼顶女儿墙是独立低墙类型。
4. 门墙的墙面、门扇、触发区、实体碰撞、相机代理和目标边使用同一个门组件局部坐标。
5. 拐角两条墙臂拥有各自 Mesh 与碰撞，不用覆盖整个角区的隐形大盒体。
6. A/B 墙材质和地砖材质按网格奇偶交替，只用于识别装配，不改变碰撞与导航。
7. 不得使用隐藏大平面、透明墙或超出 Mesh 的不可见碰撞补洞。

## 5. 动态走廊

门槽确定后，通道长度由两端真实门中心计算：

```text
module_count = round(door_to_door_distance / 5m)
```

- <span style="color:#2E7D32">**[已实装]** 水平通道支持根据真实门距动态增加地砖与两侧墙模块。</span>
- <span style="color:#2E7D32">**[已实装]** 重复地砖和墙可使用 MultiMesh；每个实例仍保持独立 5m 坐标。</span>
- <span style="color:#EF6C00">**[Codex补充]** 通道必须验证可视覆盖、行走碰撞、子弹碰撞、相机墙和导航五种长度一致；合并碰撞只能减少拼缝，不能超出 Mesh 覆盖。</span>
- <span style="color:#EF6C00">**[Codex补充]** 东西向通道的南侧墙是相机交互面；南北向通道的东/西墙不触发抬镜，避免方向逻辑散落。</span>

## 6. 门与钥匙模型

统一门记录至少包含：

```text
door_id
edge_id
from_room_id / to_room_id
socket_a / socket_b
door_kind
required_key_content_id
open_state
fate_choice_policy
camera_wall_proxy
map_visibility
```

### 6.1 普通门

- <span style="color:#2E7D32">**[已实装]** 普通清房可产出 `item_room_key`，用于选择并开启普通房门。</span>
- 普通门允许附带门后命运选择，但基础动线门可以明确免钥匙/免卡片。

### 6.2 Boss 专用下行门

- <span style="color:#1565C0">**[用户设计]** Boss 死亡后掉落或授予 `item_boss_descent_key`。</span>
- <span style="color:#1565C0">**[用户设计]** 该钥匙只能打开本 Boss 阶段的 `boss_descent_gate`；门可以位于随机地图最终指向下一层的位置，而非固定紧邻 Boss 房。</span>
- <span style="color:#1565C0">**[用户设计]** 门后连接真实下行楼梯间，楼梯间再进入下一层。</span>
- <span style="color:#EF6C00">**[Codex补充]** 每层计划只允许一个有效 Boss 下行门；Boss 未死、钥匙来源不匹配或楼梯目标未提交时，门事务必须拒绝。</span>

### 6.3 Boss 后电梯

- <span style="color:#1565C0">**[用户设计]** 电梯间只存在于 Boss 层之后的下行楼梯间，不是普通房间，不是每层支路，也不能提前被小地图标记为可用。</span>
- <span style="color:#EF6C00">**[Codex补充]** `stage_elevator_bay` 是 `post_boss_stairwell` 的可选子组件；只有楼层规则 `is_boss_floor=true` 时预留并实例化。</span>
- <span style="color:#EF6C00">**[Codex补充]** 电梯记录保存阶段锚点而非任意楼层列表；已解锁阶段由存档系统维护。</span>

## 7. 房间流送与刷怪时点

```text
门打开
→ 目标房 reveal
→ 实例化目标房 Mesh/碰撞/内容槽
→ 请求怪物系统创建首批敌人
→ 敌人实例存在但 AI 暂停
→ 玩家进入目标房
→ 激活同一批敌人
```

- <span style="color:#2E7D32">**[已实装]** 正式 3D 已采用“开门生成、进房激活”的首波逻辑。</span>
- <span style="color:#EF6C00">**[Codex补充]** `encounter_spawned` 与 `room_entered` 分离；进房不得再次创建首波。</span>
- <span style="color:#EF6C00">**[Codex补充]** 敌对房无合法敌人计划时写诊断并使用安全清房结果，禁止永久卡门。</span>

## 8. 地图产出

小地图不自行推断房间。它读取已提交楼层计划并叠加运行状态：未知、已发现、已进入、已清理、门锁、Boss 门、楼梯、电梯、撤离和玩家位置。物品与怪物是否显示由视野/侦测规则控制，不修改真实生成状态。

### 8.1 战术小地图重制契约

- 房间不再画成同尺寸圆点；使用 `custom_dimensions` 或 `DungeonRoom3D.ROOM_DIMENSIONS[size_class]` 绘制等比例矩形，并把房间边界纳入投影缩放范围。
- 玩家标记使用实时世界坐标，因此玩家从房间左侧移动到右侧时，地图标记必须在该房间矩形内同步移动；朝向使用独立箭头表达。
- 当前楼层已侦测且仍存活的敌人显示红点。敌人红点读取正式 `Enemy3D` 世界位置，不根据“房间剩余数量”随机摆放；死亡或离开侦测范围后及时移除。
- 走廊连接房间边缘而不是穿过房间中心；未发现楼层、未激活敌人和其他楼层敌人不泄露。
- 小地图快照必须报告房间真实尺寸、玩家实时位置和敌人标记数量，便于自动验收。

## 9. 生成验收标准

- [ ] 同一 `seed + floor + template_version` 生成完全相同布局。
- [ ] 每个房间边界闭合，地面除设计洞口外无缺失。
- [ ] 房间矩形互不重叠，普通房不侵入楼梯和电梯预留区。
- [ ] 每条门边的视觉、触发、碰撞、相机代理和地图目标一致。
- [ ] 所有通道长度是 5m 模块整数，墙/地砖/碰撞/导航覆盖一致。
- [ ] 入口到出口可达，支路不会切断主路。
- [ ] 敌对房开门即创建首波，进房只激活，不二次生成。
- [ ] 无敌人来源或生成失败不会导致房间永久不可清理。
- [x] 小地图房间矩形与正式房间宽高比例一致，玩家位置随房内移动，存活怪物以红点显示且死亡后移除；由 `verify_tactical_inventory_minimap_flow` 验收。
- [ ] Boss 专钥匙只能开启唯一 Boss 下行门，失败不消耗钥匙。
- [ ] 只有 Boss 层下行楼梯间出现电梯，普通楼层电梯接入房数量为 0。
