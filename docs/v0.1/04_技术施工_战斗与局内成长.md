## 1. 核心设计结论

<span style="color:#1565C0">**[用户设计]** 战局中通过武器作用域命运卡、配件、子弹模块或强化道具产生的构筑，只修改当前明确选中的枪械实例，不修改角色本体。</span>

<span style="color:#1565C0">**[用户设计]** 每一把实际获得的枪都是独立物品，拥有永久唯一的 `weapon_instance_id`。枪械可以装备、替换、放回背包、丢弃、出售、保险、带出和存档；永久命运升级、可更换子弹模块与配件始终跟随这把枪，而不是跟随玩家装备栏。</span>

<span style="color:#1565C0">**[用户设计]** 每把枪有独立命运升级槽。普通枪械的基础容量为 8 格；枪械类型和稀有度可以通过数据覆盖容量。武器命运升级按第 1 格、第 2 格依次追加，永久、线性、不可拆卸、不可替换、不可回退。配件与子弹模块属于可更换装配，不占命运升级槽。</span>

<span style="color:#1565C0">**[用户设计]** 命运卡新增 `WEAPON / CHARACTER / WORLD` 三种作用域。作用域与现有“组合、强化、变种、复制、融合、诅咒、规则、视觉”效果类型是两个不同维度。</span>

<span style="color:#1565C0">**[用户设计]** 三种作用域在所有卡面与选择端使用独立天体命名：`WORLD = ☀ 太阳命运`、`CHARACTER = ☾ 月亮命运`、`WEAPON = ★ 星星命运`。英文作用域仅作为数据字段和调试信息，不能成为玩家唯一可见的分类名称。</span>

## 2. 职责与边界

战斗与构筑系统拥有枪械实例、武器装备、可更换装配、永久命运升级、开火节奏、投射物、命中上下文和伤害计算。

- 玩家系统只提交移动、瞄准、开火、换弹和装备意图；角色节点不拥有枪械构筑数据。
- 背包、地面掉落、商店、保险柜和存档系统只转移或保存完整枪械实例，不拆解或重建构筑。
- 角色作用域卡由角色局内规则服务持有；世界作用域卡由行动/关卡规则服务持有。
- UI 只显示枪械实例、槽位和事务结果，不直接修改装配树或存档字典。
- 怪物和玩家生命组件只接收统一伤害结果，不读取武器树。

## 4. 三层身份模型

### 4.1 枪型内容 ID

`weapon_content_id` 表示枪的设计种类，例如 `weapon_rifle`。它用于查找基础数值、模型、稀有度规则和掉落定义；同一类型的多把枪共享该 ID。

### 4.2 枪械实例 ID

`weapon_instance_id` 表示玩家世界中一把真实存在的枪。生成成品掉落、商店库存、初始武器或制造结果时创建，之后永久不变。它用于装备、背包、出售、丢弃、保险、撤离和存档去重。

### 4.3 战斗实例 ID

`attack_instance_id / projectile_instance_id` 只追踪一次攻击或一个投射物，不能代替枪械实例 ID，也不能进入长期物品档案。

任何系统都不得用显示名、背包格索引、节点路径或枪型内容 ID 判断“是否是同一把枪”。

## 5. WeaponInstance 数据契约

```text
weapon_instance_id
weapon_content_id
schema_version
rarity
fate_slot_capacity
fate_upgrades[]
bullet_module_id
attachment_slots{}
durable_modifiers{}
created_transaction_id
```

### 5.1 永久命运升级槽

`fate_upgrades[]` 是按应用顺序保存的线性数组。每项至少包含：

```text
slot_index
stable_card_id
effect_version
effect_params_snapshot
applied_transaction_id
```

规则：

1. 新的武器作用域命运卡只能写入第一个空槽。
2. `slot_index` 从 1 开始连续增长，不允许跳格、排序或覆盖。
3. 已写入升级不可拆卸、替换、回退或转移到另一把枪。
4. 枪械进入背包、地面、商店、保险柜或存档时，数组原样跟随。
5. 枪械满槽时，应用事务拒绝；命运卡选择或消耗品不得被消耗。
6. 普通枪械基础容量为 8；最终容量由枪型和稀有度配置共同决定，未冻结的修正值不能硬编码。

### 5.2 可更换装配

`bullet_module_id` 与 `attachment_slots{}` 不占用 `fate_upgrades[]`。子弹、弹匣、瞄具、枪口、枪托和外接配件按各自槽位安装，可卸下、替换并作为独立物品返回背包。

更换装配只改变这把枪的实例记录；不能自动把旧枪的装配转移给新枪。若玩家需要迁移配件，必须先卸下再安装，并受背包空间和兼容规则约束。

## 6. 内容定义契约

### 6.1 枪身

必填：`weapon_content_id / display_name / tier / rarity / damage / fire_rate / projectile_count / spread / reload_time / magazine_size / fate_slot_base / fate_slot_override / tags`。蓄力枪额外声明 `charge_time` 和蓄力曲线 ID。

### 6.2 子弹模块

必填：`content_id / added_damage / speed_multiplier / behavior_tags / visual_id / compatibility_rules`。追踪、弹跳、爆炸、黑洞等行为由可组合处理器实现，不复制投射物生命周期。

### 6.3 配件

必填：`content_id / slot / stat_modifiers / behavior_modifiers / compatibility_rules`。配件可拆卸、可交易，不占命运升级槽；负扩散等修饰必须在合成后裁剪上下限。

### 6.4 命运卡

必填：`stable_card_id / scope / effect_type / rarity / target_rules / effect_action / effect_params / description / acceptance_case`。

<span style="color:#2E7D32">**[已实装]** 当前 48 张预设已使用数据库稳定 ID，槽位记录和存档桥均保存该 ID；后续内容不得恢复使用 `fate_card_####` 顺序号。</span>

## 7. 命运卡双维度分类

### 7.1 作用域

| 作用域 | 目标与所有者 | 是否占武器槽 | 示例 |
|---|---|---:|---|
| `WEAPON` | 玩家明确选择或当前装备的 `weapon_instance_id` | 是 | 射速、弹道、连锁、融合、枪上加枪、换弹爆炸 |
| `CHARACTER` | 本局角色规则快照 | 否 | 低血量生存奖励、移动、防御或角色资源规则 |
| `WORLD` | 本局行动/房间/掉落规则快照 | 否 | 敌增援、宝箱品质、额外掉落、房间诅咒 |

武器作用域卡不能静默修改角色生命、移动或全局伤害；角色/世界作用域卡不能被写入枪械命运槽。

<span style="color:#2E7D32">**[已实装并验收]** 当前 48 张卡归类为 `★ 星星命运/WEAPON` 22 张、`☾ 月亮命运/CHARACTER` 12 张、`☀ 太阳命运/WORLD` 14 张；运行时按 `scope` 路由，并在应用结果中返回天体专名、作用域、目标实例与槽位信息。</span>

### 7.2 效果类型

现有“组合、强化、变种、复制、融合、诅咒、规则、视觉”继续描述效果怎样执行。它不再代替作用域。例如“诅咒”既可以是武器诅咒，也可以是世界诅咒，必须再读取 `scope` 才能决定所有者。

### 7.3 天体命名与卡面识别

| 数据作用域 | 卡面专名 | 固定符号 | 固定目标提示 | 枪械槽 |
|---|---|---|---|---:|
| `WORLD` | 太阳命运 | `☀` | 影响房间、掉落、敌群或撤离规则 | 不占用 |
| `CHARACTER` | 月亮命运 | `☾` | 影响本局角色状态 | 不占用 |
| `WEAPON` | 星星命运 | `★` | 刻印到当前枪械实例 | 占用 1 格 |

卡面必须同时显示“符号 + 专名 + 中文目标”，不能只用颜色区分。三选一界面标题使用“选择一项命运”，星星牌额外显示目标枪、下一槽和永久不可逆；月亮牌与太阳牌显示“不占武器槽”以及其本局所有者。HUD 或角色装备界面必须常驻汇总已生效的月亮命运和太阳命运，让玩家在选牌界面关闭后仍能观察效果来源。

## 8. 武器命运升级事务

```text
FateApplyRequest(stable_card_id, weapon_instance_id)
→ 验证卡片 scope=WEAPON
→ 验证目标正是当前选定枪械实例
→ 验证稳定ID、容量、下一个slot_index与兼容规则
→ 在 WeaponInstance 副本试算
→ 生成不可变升级记录与派生装配快照
→ 原子提交枪械实例并消费卡片/选择
→ 发出 weapon_instance_changed
```

任一步失败都保留原枪、原配件、原卡片选择和背包状态。UI 必须显示失败原因，例如“枪械命运槽已满”“该卡属于世界作用域”或“目标枪械已不在当前装备位”。

## 9. 装备、背包、丢弃、出售与存档事务

### 9.1 换枪

换枪是两个完整 `WeaponInstance` 在装备位和背包间的移动。旧枪连同永久升级与当前装配整体进入背包，新枪以自己的原有构筑进入装备位。禁止新建枪身后搬运旧树。

### 9.2 丢弃与地面拾取

丢弃时生成携带同一 `weapon_instance_id` 和完整快照的地面物；重新拾取仍是同一把枪。多人或重复加载场景时，同一实例 ID 只能有一个所有权位置。

### 9.3 出售

出售事务以 `weapon_instance_id` 锁定目标，价格可读取枪型、稀有度、命运升级和配件，但公式未冻结前只使用基础价格。成功后完整实例离开玩家所有权；失败不能先拆配件或清升级。

### 9.4 存档与保险

背包、装备位、保险格、保险柜、待带入和撤离战利品都保存完整武器实例。集合转移使用事务 ID；存档恢复后必须保持实例 ID、槽序、卡片参数与配件一致。

## 10. 统一伤害上下文

建议字段：

```text
attack_instance_id
source_actor_id
source_weapon_instance_id
source_weapon_content_id
projectile_instance_id
base_damage / damage_type / critical
hit_position / hit_direction
status_effects / fate_sources[]
room_id / floor_id
```

伤害计算顺序固定为：枪型基础 → 可更换装配 → 枪械永久命运槽（按槽序）→ 角色局内修饰 → 世界临时修饰 → 暴击/命中规则 → 目标防御 → 裁剪 → 结果事件。表现层不能再次修改数值。

## 11. 开火流程

1. 玩家提交开火意图。
2. 装备服务读取当前 `weapon_instance_id` 的不可变战斗快照。
3. 武器检查弹药、射速、换弹和蓄力状态。
4. 对象池分配投射物并注入攻击快照。
5. 投射物命中后创建统一伤害上下文。
6. 目标返回伤害结果，系统触发击杀、状态、掉落与表现事件。

## 13. 武器表现页

武器表现页是同一个可复用详情组件，不为背包、工坊、商店、地面拾取和命运选卡各复制一套武器规则。页面只能读取 `WeaponPresentationSnapshot`，所有装备、拆装、出售和命运应用都提交领域命令。

### 13.1 入口与上下文

| 入口 | 默认对象 | 可执行操作 |
|---|---|---|
| 战斗 HUD 当前武器 | 当前装备的 `weapon_instance_id` | 查看构筑；战斗中不允许高风险管理操作 |
| 背包武器格 | 所选背包实例 | 装备、比较、拆装、丢弃、保险、收藏锁定 |
| 工坊 | 所选装备或背包实例 | 查看、安装/卸下配件与子弹模块 |
| 商店 | 玩家实例或商店实例 | 比较、购买、出售；出售必须二次确认 |
| 地面拾取比较 | 地面实例与当前装备实例 | 拾取、替换或放弃，不允许把两把枪的构筑自动合并 |
| 命运卡选择 | 当前明确选中的装备枪 | 预览下一命运槽及应用结果 |

### 13.2 页面线框

```text
┌ 稀有度｜武器名｜枪型｜装备/背包位置｜实例尾号 #A31F7C｜锁定 ┐
│ 构筑 5/8  [命运永久]    配件 3/5 [可更换]    估值/重量/状态 │
├──────────────────────┬───────────────────────────────┤
│                      │ [总览] [命运轨道] [装配] [触发链] │
│  可旋转真实枪械预览  │ 基础值 → 当前值（差值与来源标签）  │
│  枪身/弹匣/瞄具/枪口 │ 伤害 / 射速 / 弹量 / 换弹 / 扩散  │
│  与已装配件同步显示  │ 行为：弹跳、追踪、爆炸、回返……    │
│                      │ 命运：01◆ 02◆ 03◆ 04◆ 05◆ 06◇… │
├──────────────────────┴───────────────────────────────┤
│ [装备/比较] [管理装配] [保险] [丢弃] [出售]｜失败原因区  │
└──────────────────────────────────────────────────────┘
```

窄屏改为上下布局，但标题、实例尾号、`n/N` 命运槽和当前操作结果不能被折叠隐藏。

### 13.3 页头与身份

- 始终显示武器名、枪型、稀有度、所有权位置和 `weapon_instance_id` 后 6 位；悬停/详情可查看完整 ID。
- 同型枪必须通过实例尾号、命运槽数量、配件角标和实际模型构筑区分，禁止只显示枪型名。
- “已装备”“背包”“地面”“商店”“保险柜”是互斥位置标签；事务进行中显示处理中，不提前切换位置。
- 玩家锁定/收藏的枪禁止被一键出售或丢弃；解除锁定是独立操作，不与出售确认合并。

### 13.4 真实武器预览

- 预览读取当前实例快照，枪身、弹匣、枪口、瞄具、枪托和外接配件与游戏内手持模型一致。
- 安装候选悬停时用半透明幽灵件预览，确认后变为实体；取消或失败必须恢复原模型。
- 永久命运不冒充可拆配件。命运升级通过枪身刻痕、能量线路、异常脉冲或卡槽轨道表现；具体表现由每张卡的 `weapon_visual_tags` 决定。
- 预览支持旋转、缩放和“基础外观/当前构筑”对比；对比只切表现，不改变实例。

### 13.5 总览页签

- 同时显示基础值与当前值，使用 `+/-`、箭头和来源标签表达差值，不能只给一个最终 DPS。
- 每个派生值可以展开来源：枪型基础 → 子弹模块 → 配件 → 命运槽 1…N → 角色 → 世界。
- 行为型效果显示可读标签与触发条件，例如“命中：连锁 3 次”“换弹开始：范围爆炸”“第 7 发：弹跳强化”。
- 数值没有变化但行为改变时，必须仍显示行为标签，避免特殊构筑在页面上看起来“没有提升”。

### 13.6 命运轨道页签

- 以 `01…N` 连续轨道显示全部槽位。已占槽为实心卡标和锁形；唯一的下一个空槽高亮；后续空槽置灰。
- 已占槽显示卡名、应用顺序、冻结参数、作用域和主要效果；不可拖动、删除、替换或跨枪移动。
- 页面顶部持续显示“永久升级，不可拆卸”，不能只在第一次教学中出现。
- 满槽显示“命运槽已满 n/N”，所有武器卡的应用按钮禁用，但仍允许查看角色卡和世界卡。
- 枪型/稀有度造成容量不是 8 时，明确显示来源，例如“基础 8 + 稀有度 2 = 10”，不得让玩家猜测。

### 13.7 装配页签

- 子弹模块与弹匣、瞄具、枪口、枪托、外接配件按真实兼容槽分组，空槽、已安装和不兼容状态一眼可见。
- 每个槽明确显示“可更换，不占命运槽”；拆卸后物品回到背包，背包已满时按钮禁用并显示原因。
- 安装候选提供当前/候选属性与行为对比，预览只影响幽灵模型和差值，不提前写实例。
- 替换是“卸下旧件并装入新件”的一个事务；任一步失败，模型、背包和实例全部回滚。

### 13.8 触发链页签

复杂构筑按因果顺序显示：`开火 → 投射物 → 命中/落地/换弹/击杀 → 派生效果`。每个节点标记来源卡槽或配件，循环和触发上限也必须可读。

战斗中触发时，页面对应节点短暂高亮；HUD 只显示高价值的短提示和图标，不能让连续触发产生文字刷屏。

## 15. 逐内容表现数据契约

每一种枪身、子弹模块、配件和每一张命运卡都必须在内容数据库填写以下字段，空字段视为该内容未完成：

```text
ui_summary                 # 玩家在列表/卡面看到的一句话规则
ui_target_preview          # 目标、槽位、属性/行为差值
ui_success_feedback        # 成功后的槽位、Toast、字段高亮
ui_failure_feedback        # 不兼容、满槽、目标丢失等准确失败文案
weapon_visual_tags[]       # 枪身、挂件、刻痕、能量线路、动作
projectile_visual_tags[]   # 弹体、尾迹、飞行轨迹
impact_visual_tags[]       # 命中、爆炸、状态、连锁
audio_cue_id               # 安装、应用、触发或失败的音频提示
presentation_status        # 未设计 / 已设计未实装 / 已实装待QA / 已验收
```

内容数据库的 `武器` 表逐条记录 7 枪身、8 子弹模块、6 配件的功能 UI 和武器/战斗表现；`命运卡` 表逐条记录 48 张卡的选择/槽位提示和触发表现。通用规则不能代替逐条记录。

## 19. 角色装备与背包交互改造

### 19.1 双栏信息架构

### 19.2 拖拽契约

1. 背包格拖到另一背包格：交换两个完整物品记录；空目标则移动，枪械实例 ID 和构筑不得重建。
2. 枪械拖到主武器槽：执行现有整枪换装事务，旧枪回到来源背包格或可用空格；失败完整回滚。
3. 物品拖到红色丢弃区，或拖出装备/背包面板：从来源集合移除，并在玩家当前房间附近生成同一完整物品的地面拾取。
4. 任何拖拽失败都保留来源物品并显示原因；不得仅改变 UI 排序而不改变背包领域数据。
5. “整理”按物品类型、稀有度、名称和实例 ID 稳定排序；只改变格位，不合并枪械实例。
6. 当前装备位也是合法拖拽来源：拖到空背包格执行原子卸装，拖到红区/面板外执行整枪落地；目标写入或落地失败时必须恢复原装备。占用中的非空背包格不接受卸装覆盖。
7. 正式战术背包只允许一个自定义悬停详情卡；禁用同一格的引擎默认 Tooltip。快速跨格时以最后进入的格为准，退出旧格不得隐藏新格详情，详情卡不得盖住当前悬停格。
