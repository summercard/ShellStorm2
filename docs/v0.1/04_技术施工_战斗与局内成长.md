# 技术施工｜战斗、武器、子弹与命运卡 v0.1

系统编号：2  
上级设计：[游戏设计文档 §7](README.md#7-核心系统二战斗武器子弹与命运卡)  
内容表：[游戏内容数据库](data/ShellStorm2_游戏内容数据库_v010.xlsx) 的 `武器`、`命运卡`

## 1. 职责与边界

本系统拥有武器装配、开火节奏、投射物、命中上下文、伤害计算和单局命运卡效果。玩家只提交操作意图；怪物和玩家生命组件只接收伤害结果；关卡系统只提供空间查询和房间事件。

## 2. 当前正式链路

```text
BlueprintRegistry（内容工厂）
→ WeaponAssemblyTree（装配结构与合成属性）
→ WeaponModel3D（正式3D武器控制/表现桥）
→ Projectile3D / 对象池（飞行与命中）
→ DamageContext（目标响应）
```

- <span style="color:#2E7D32">**[已实装]** 正式注册 7 枪身、8 子弹、6 配件。</span>
- <span style="color:#2E7D32">**[已实装]** 28 张卡片预设通过 `FateCardEngine` 执行装配、强化、变种、融合、规则或地图效果。</span>
- <span style="color:#2E7D32">**[已实装]** `Dungeon3D` 的开门命运三选一调用 `FateCardGameBridge`，正式 3D 玩家可获得卡片效果。</span>
- <span style="color:#2E7D32">**[已实装]** `ItemRegistry` 提供价格、稀有度、商店层级和掉落权重。</span>
- <span style="color:#EF6C00">**[Codex补充]** `WeaponPresets` 等平行配置列入迁移/废弃清单，不能继续作为第二套正式武器数值源。</span>

## 3. 内容定义契约

### 3.1 枪身

必填：`content_id / display_name / tier / damage / fire_rate / projectile_count / spread / reload_time / magazine_size / tags`。蓄力枪额外声明 `charge_time` 和蓄力曲线 ID。

### 3.2 子弹

必填：`content_id / added_damage / speed_multiplier / behavior_tags / visual_id`。追踪、弹跳、爆炸、黑洞等行为由可组合处理器实现，不复制整套投射物脚本。

### 3.3 配件

必填：`content_id / slot / stat_modifiers / behavior_modifiers / compatibility_rules`。负扩散等修饰必须在合成后进行上下限裁剪。

### 3.4 命运卡

必填：`stable_card_id / type / rarity / target_rules / effect_action / effect_params / description / acceptance_case`。

<span style="color:#EF6C00">**[Codex补充]** 当前 `FateCard` 自动生成的 `fate_card_####` 只作运行时实例号；数据库稳定 ID 必须在预设和存档桥中显式写入，这是 P0 数据迁移任务。</span>

## 4. 统一伤害上下文

建议字段：

```text
attack_instance_id
source_actor_id
source_weapon_content_id
projectile_instance_id
base_damage
damage_type
critical
hit_position / hit_direction
status_effects
fate_sources[]
room_id / floor_id
```

伤害计算顺序固定为：基础装配 → 单局永久修饰 → 临时 Buff → 暴击/命中规则 → 目标防御 → 最低/最高裁剪 → 结果事件。表现层不能再次修改最终数值。

## 5. 命运卡执行边界

| 类型 | 允许修改 | 不允许直接修改 |
|---|---|---|
| 组合 | 装配树父子关系、挂载槽 | 房间布局、存档文件 |
| 强化 | 节点数值或计算修饰 | 视觉节点作为数值源 |
| 变种 | 投射物行为处理器 | 复制一套新子弹生命周期 |
| 复制/融合 | 生成受约束的新装配节点 | 绕过槽位和兼容规则 |
| 诅咒/规则 | 单局规则服务 | 基地永久数据 |
| 地图触发 | 请求关卡或掉落服务执行 | 自己生成房间、敌人或物品 |

当前地图命运触发包含击杀、开箱、进入房间、货币、精英击杀和生存时间等计数。正式接入后应订阅统一领域事件，不再只寻找旧 `room_game_mode` 节点。

## 6. 运行时事务

### 6.1 装配变更

1. 验证稳定 ID、目标规则和槽位。
2. 在装配树副本上试算。
3. 检查循环引用、槽位冲突和属性上下限。
4. 提交新树并刷新派生数值。
5. 发出 `weapon_assembly_changed`，表现与 HUD 读取快照。
6. 失败则保留旧树和卡片选择机会。

### 6.2 开火

1. 玩家提交开火意图。
2. 武器检查状态、弹药、射速和蓄力。
3. 对象池分配投射物并注入不可变攻击快照。
4. 投射物命中后创建伤害上下文。
5. 伤害接收者返回结果，系统触发击杀、状态和掉落事件。

## 7. 施工阶段

1. 把数据库稳定 ID 写入正式预设和装配节点。
2. 建立唯一武器内容适配器，标记或移除平行数值源。
3. 为 28 张卡片建立逐卡执行测试与 3D 表现检查。
4. 统一地图命运触发到正式领域事件总线。
5. 把武器、卡片、怪物和掉落的交叉引用加入内容校验。

## 8. 验收标准

- [ ] 7 枪身、8 子弹、6 配件均能由稳定 ID 创建且数值与数据库一致。
- [ ] 起始手枪、首次散射喷壶拾取、装备切换、换弹和蓄力在 3D 主入口可复现。
- [ ] 28 张命运卡每张至少有一次成功用例和一次非法目标用例。
- [ ] 卡片失败不消耗选择、不破坏旧装配树。
- [ ] 同一攻击的伤害只结算一次，投射物回池后不保留上次修饰。
- [ ] 子弹、配件和命运卡视觉变化不改变碰撞层契约。
- [ ] 地图触发卡通过事件/命令请求刷怪或掉落，不直接创建节点。
- [ ] 数据库稳定卡 ID 可跨存档恢复，不依赖生成顺序。
- [ ] 正式 3D 不读取 `WeaponPresets` 作为第二套数值事实源。
- [ ] 压力测试下对象池无持续增长、无无效命中和公式错误。
