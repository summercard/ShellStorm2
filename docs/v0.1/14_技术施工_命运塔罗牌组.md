来源：用户最新规则；状态：三张正式路径已接入，专项与表现证据见[实体构筑开发记录](development/2026-10-16_star_physical_mounts.md)。太阳、月亮本次不变。以下三张规则取代旧的交替射击、命中才开枪与穿盾描述；稳定内容 ID 保留。

| 牌 | 正位 | 逆位 |
|---|---|---|
| 战车 `fate_bullet_carry_gun` | 选随身装备中的真实武器；每发子弹在 BulletWeaponSocket 携带该武器完整装配快照与模型；远程自动按自身节奏开火，近战循环挥击 | 同样携带与攻击，武器朝弹体后方旋转 180°，射弹从实际反向枪口发出 |
| 魔术师 `fate_gun_on_gun` | 枪口旁挂副武器；按卡牌应用顺序增加横向排列挂点；每个点拥有独立模型与枪口；闲置、背负缩小，开火短暂放大 | 挂点位于角色身后，仍随角色移动；相同叠加与缩放规则 |
| 力量 `fate_armor_pierce` | 弹体变为滚石，弹速乘 0.5；射速降低（工程初值乘 0.5，可调）；碰撞和地面高度由物理场景决定 | 同为滚石；命中怪物或障碍后碎裂，半径 3 米内存活敌人受到径向击退（工程初值 6 m/s）；不额外附送范围伤害 |

**所有者与数据**：WeaponInstance 的 assembly_snapshot 和有序 fate_upgrades 是持久化真源；FateCardEngine 只在既有事务副本上改树，WeaponModel3D 投影枪身与挂点，Projectile3D 拥有单发弹体、携枪与碰撞生命周期。来源为选择时冻结的完整装配副本，不消耗或修改来源武器。结构深度仍受现有 MAX_DEPTH 限制，禁止循环引用；超限按失败回滚，不静默截断。魔术师扩展内部挂点槽（原枚举编号不变），不占用公开配件位置。旧存档已写入的效果快照不自动重放成新规则；新应用记录新参数。

**命令与查询**：沿用 FateCardGameBridge 的来源面板→选择→重新校验所有权/当前目标→事务应用链路；取消、资源不足、来源失效、深度或槽位超限不提交快照，沿用购买退款。真实挂点与枪口可由节点树查询。远程携枪复用 WeaponModel3D 发射路径，来源枪弹药不消耗；每个挂载运行副本拥有自己的冷却与构筑状态。默认选取目标时优先当前主枪及其直接子弹，不能误选冻结副枪内的同类型节点。子弹回收必须停止携枪攻击、释放其运行副本，池化复借重建，不残留上一发。

**顺序与叠加**：前序构筑进入后序选择的来源快照（选择已带挂枪的主枪时，其已有嵌套也会复制，受深度5限制），后续修改不反写此前的副本。魔术师最多随武器命运槽容量叠加（内部最多 8 点）；正逆点按各自侧按应用顺序横排。力量的弹速与射速倍率按应用次数相乘，最后一次力量方位决定碎裂行为；不能继续叠加旧力量的穿盾奖励。

**表现资产与验收**：石头弹与碎裂各有独立纯视觉 Prefab、AssetID 和特效分账本登记；石头随弹体生命周期，不进入特效池；碎裂进 VfxPool3D。正式入口覆盖门后购卡和既有来源面板。独立验收需覆盖来源近战/远程、正逆朝向及真实枪口、三副枪横排与闲置/开火尺度、持久化往返、非零楼层滚动、范围击退边界、池化复借和取消；表现另需真实渲染，不以无头通过代替。

## 2. 正位与逆位的硬规则

1. 先抽取 `stable_card_id`，再独立抽取 `orientation`；`UPRIGHT` 和 `REVERSED` 各为 `0.50`。
2. 概率对每个出场卡位独立生效，不因稀有度、作用域、玩家当前生命或枪械构筑动态偷改。
3. 同一次门后购卡的三张卡允许出现0–3张逆位。不做“至少一张正位”的暗保底，否则单卡不再真正50/50。
4. 抽取结果由 `run_seed + fate_offer_id + card_slot_index` 确定；关闭再打开、暂停或读取同一事务不得重投正逆位。
5. 正/逆位共用同一卡名、稀有度、收藏条目和 `stable_card_id`；结算记录额外保存 `orientation / orientation_roll / effect_params_snapshot`。
6. 星星牌无论正位或逆位都占目标枪1个永久命运槽，且都随枪械实例移动；月亮/太阳牌均不占枪槽。
7. 逆位不等于“纯惩罚”。它必须是同一主题的反向策略、节奏交换或风险/回报改写，不允许只把所有正数改成负数。
8. 门后购卡价格只读稀有度，不因正/逆位改变；旧「满槽兑金币价格」已随购卡制下线（见 §7.1）。

## 3. 翻牌与逆位表现

### 3.1 出场时序

```text
0.00s  三张卡背面朝向玩家，不显示名称与效果
0.10s  从左到右每张间隔0.08s开始绕Y轴翻转
0.24s  到90°薄边时替换为已抽取的牌面
0.42s  正位收束为0°；逆位卡框/图案绕Z轴转至180°，文字层反向补偿
0.50s  卡面完成显示；逆位说明内容已替换为逆位效果，全部文字正向可读
0.62s  才开放点击，避免玩家在未看清朝向时误选
```

翻转使用代码创建的 `Control` 变换、透视缩放、遮罩与描边，不依赖预烘焙帧图。开启“减少动效”时改为0.15秒交叉淡入，但最终方位必须与普通动效一致：正位0°、逆位卡框/图案180°，文字的最终屏幕旋转为0°。

### 3.2 可读性和交互

- 逆位中央图案、朝向标记与内外框倒置180°；文字层绕自身中心反向补偿，卡名、天体专名、方位标签、效果文字、数值、目标与槽位信息保持正向，并保留正常阅读布局。门后购卡层、工作台与兼容占卜入口使用同一补偿规则；布局尺寸变化同步更新枢轴。**图卡模式下（见 §3.3）卡面本身就是整张图案，直接绕中心倒置 180°，卡下功能文字层不参与旋转即天然正向**，不再需要反向补偿；两条路径由 `tarot_art_mode` 元数据区分。
- 逆位卡使用同一卡名，但说明内容必须读取 `reversed_description / reversed_effect`，不能把正位说明倒置后继续显示。
- 逆位额外使用向下三角与双线边角，不能只靠倒置或颜色区分。
- 悬停只做轻微亮度变化，不把逆位卡旋回正向。三张卡持续做轻微错相漂浮与透视感旋转，三张卡的相位、幅度和周期不完全同步。点击后不显示额外选中框：被点击卡片放大至约1.10倍，其余两张缩小至约0.90倍，再进入**购买事务**（扣本局金币 → 统一应用/来源选择）或失败反馈。
- **已购买的卡不再有悬停反馈**，也不再放大（2026-10-14 主人要求）：它已经翻回背面并做成**灰阶 + 压暗 + 半透明 + 70%**（形态规格见 §7.1），任何「碰得到」的反馈都是在骗玩家。只掐**视觉反馈**，按钮保持可聚焦 —— 购买制下键盘/手柄的焦点链要经过卡列才回得到底部退出按钮。
- 卡牌完成翻面前禁用点击；Esc可在动画中安全退出，不应用卡牌。

### 3.3 卡面资源与图卡呈现

卡面由程序绘制改为**塔罗图卡**呈现。功能、抽卡概率、正逆位判定与存档字段一律不变，本次只换表现。

| 项 | 约定 |
|---|---|
| 卡面目录 | `assets/art/ui/fate_cards/` |
| 卡面命名 | `ui_fate_card_<stable_card_id 去掉 fate_ 前缀>_v001.png` |
| 卡背 | `ui_fate_card_back_v001.png`（全卡共用，圆角透明背景） |
| 规格 | 卡面统一高 1024px、紧贴卡片本体、卡外透明；卡背 1369×2048 |
| 呈现层 | `src/weapons/FateCardView.gd`（**只做表现**，不读写任何玩法数据） |
| 覆盖入口 | 门后购卡层 `Dungeon3D` / 占卜屋 `DivinationMenu` / 工作台 `WorkbenchPanel` / 收藏室 `FateCardCollectionMenu` |

**卡下只留功能**：卡下显示该方位的效果短说明（`short_description`），品质色描边、作用域标签、方位三角、目标预览、页脚与 emoji 一律不再叠加——卡面本身已带边框与牌名，再叠一层会与牌面重复。门后购卡层在说明下方**另有一行独立的购买价行**（见 §7.1）、顶部**本局金币余额行**与底部**退出按钮**；除此之外的顶部协议提示、底部信息条和标题也不再显示（标题 2026-10-14 按主人要求去掉，其位置由余额行接管）。卡下功能文字按作用域着色：`★ 星星命运`使用紫色、`☀ 太阳命运`使用金色、`☾ 月亮命运`使用浅蓝色，并统一补黑色描边保证可读性。

**逆位**：只把**卡面图案**绕中心旋转 180°，卡下功能文字层不参与旋转，因此保持正向可读；效果内容仍读取逆位快照。卡面层与文字层分离是这条规则的实现前提，不得合并成一个节点。

**缺图回退**：`FateCardView.art_for()` 找不到对应美术时返回 `null`，调用方回退到程序绘制卡面并保留原有文字布局。补图落地后**无需改代码**即自动生效；`FateCardView.has_art()` 可查询单卡是否有图。

**贴图缓存**：卡面按 `stable_card_id` 缓存（含 `null` 结果），避免反复探测磁盘；卡背只探测一次。

> 2026-10-09 **48 张卡面全量覆盖**。首轮接入 30 张 + 18 张按同风格补生成（`gpt-image-2` 图生图，以现有卡面作风格参考）。补生成图做了两步对齐才能与既有卡面同质感：**绿色归一化**（核心绿对齐到 `#02FC8E`）与**线条加粗**（生成图线条密度 0.161 vs 既有 0.389，**细 2.4 倍**；加粗后 0.383，差距 1.6%）。程序卡面回退分支保留为容错。

### 3.4 来源选择面板（2026-10-10 实装）

三张命运在应用前需要指认一个**真实来源**：`fate_gun_on_gun`（魔术师）、`fate_bullet_carry_gun`（战车）、`fate_attachment_parasite`（权杖·三）。判定唯一入口是 `FateCardGameBridge.requires_source_selection(card)`；面板资产为 `UI-PANEL-FATE-SOURCE`。

**为什么重做**：旧面板是一列纯文字按钮，标签由 `root.node_name / source.node_name · #id` 拼成。单枪玩家看到的两个名字恰好相同（`GunBody_Sprinkler / GunBody_Sprinkler · #000493`），且面板内只有标题重复一遍、没有任何说明 —— 玩家无法判断这是报错、警告还是正常流程。现在改为图标卡片，并把「只读、不消耗」写成一句人话。

| 项 | 约定 |
|---|---|
| 实现 | `src/ui/FateSourceSelectionPanel.gd`（`Window` 模态，`popup_centered(620×470)`） |
| 标题 | `<卡名> · 选择来源` |
| 正文说明 | 按卡的用途给出（挂到主枪 / 挂到子弹 / 配件寄生）+ 统一只读语义：来源只被读取一次，不会被消耗、不会被移走，你现在的装备也不变 |
| 候选卡片 | 左 96×96 3D 图标；右三行 = 中文武器名 / 来源位置与实例短号 / 命运槽占用（不可触发的来源改显示警示） |
| 底部 | `取消 · 保留卡片`，默认焦点 |
| 取消键 | Esc / 关闭窗口 / 取消按钮三条路径同义 ⇒ `success=false`，**卡片不消耗、不转移** |

**图标口径（与地面拾取、背包、商人、HUD 共用同一条链）**

- 复用 `UI-ICON-ITEM-MODEL-3D`（`ItemModelIcon3D`）：世界模型由 `ItemModelFactory3D.create_model()` 生成，**本面板不新建模型资产**；取景/居中/视口分辨率全部由该组件自适应，面板不写死相机倍率。
- 候选的 `icon_item` 取自 `WeaponInstance.to_item_dictionary()`，含 `assembly_snapshot` 与 `fate_upgrades` ⇒ 图标反映**该枪此刻的装配与命运改装**，不是裸机型。
- 机型与显示名的唯一来源是内容注册表链（`BlueprintRegistry` → `ItemRegistry`），UI 侧不另抄「枪身名 → gun_id」映射表（`InventoryUI` 里那份是历史遗留）。
- **图标场景必须运行时 `load()`，禁止 `preload`**：本面板由启动期 autoload `FateCardGameBridge` 在编译期引用，而图标场景依赖链一路到 `WeaponModel3D` → autoload `BlueprintRegistry`；编译期提前拉链会在注册表就绪前失败，连带 `Dungeon3D` 的 HUD 武器图标一起变空（2026-10-10 实测启动报 `Failed to instantiate scene state of "", node count is 0`）。同理面板不写 `as ItemModelIcon3D` 强类型，改用鸭子类型调 `configure()`。
- 显示名优先取内容表中文名（`ItemRegistry`，如"花洒机枪"），不再把 `GunBody_*` 内部节点名当玩家文案。
- 图标与卡片描边同色（两侧都按 `rarity` 取色），主副枪一眼可分。

**新增数据契约字段**（`get_source_candidates()` 的每个 entry；旧字段 `source / supported / label` 保持不动）

| 字段 | 类型 | 说明 |
|---|---|---|
| `icon_item` | Dictionary | 交给 `ItemModelIcon3D.configure()` 的物品字典；**缺省时面板回退纯文字行** |
| `title` | String | 主标题（中文武器名） |
| `subtitle` | String | 来源位置 + 实例短号 |
| `badge` | String | 命运槽占用；不可触发的来源改为警示文案 |
| `accent` | Color | 稀有度强调色，与 `ItemModelIcon3D._item_tint` 同色 |

**复用边界**：同一面板也服务「待领命运奖励」（`_open_pending_rewards`）。该路径条目**不带** `icon_item`，面板按纯文字行渲染 —— 两条路径共用一个弹窗资产，不新增第二个面板。

**事务前后置**：面板打开时 `get_tree().paused = true`，面板自身 `PROCESS_MODE_ALWAYS`；选择返回后 `select_card_source()` 重验目标枪实例号未变，变了即拒绝并保留卡片。

## 6. 数据契约

```text
stable_card_id                 # 78张牌各自唯一；正逆位不拆ID
tarot_number                   # 0–XXI，或 ACE/2–10/PAGE/KNIGHT/QUEEN/KING
arcana                         # MAJOR / MINOR
suit                           # MAJOR / WANDS / SWORDS / CUPS / PENTACLES
scope                          # WEAPON / CHARACTER / WORLD
upright_probability            # 0.50
reversed_probability           # 0.50
upright_effect                 # 正位执行器参数
reversed_effect                # 逆位执行器参数
orientation                    # 本次出场结果；不写回卡牌定义
orientation_roll               # 可回放的随机结果
orientation_rule_version       # 平衡迁移用版本
```

不得为逆位复制一个 `*_reversed` 收藏ID，也不得通过改卡名、稀有度或作用域伪装成新卡。

## 7. 抽取与平衡规则

- “每张牌的正逆位概率相同”不等于“78张卡的身份抽取权重全相同”。牌身份仍先按层深、稀有度和卡池条件抽取，方位始终是50/50。
- 门后购卡的三张卡中同一 `stable_card_id` 不重复；同名卡不会同时出现一张正位和一张逆位。
- 新增30张在执行器、UI、存档和自动测试完成前不得进入正式可玩卡池；数据表中必须继续标记“设计完成/待施工”。
- 旧存档中已刻印的48张卡按 `stable_card_id` 迁移为新塔罗名称的正位，不重投逆位，避免已有枪械构筑被暗中改写。

### 7.1 门后购卡价格与支付（2026-10-14）

门后三张命运卡**全部出场**，各自按稀有度明码标价，由玩家用**本局金币**购买；可以全买，也可以一张不买。旧「满槽兑金币」已整体下线。

| 稀有度 | COMMON | RARE | EPIC | LEGENDARY | MYSTIC |
|---|---:|---:|---:|---:|---:|
| 名称 | 普通 | 稀有 | 史诗 | 传说 | 禁忌 |
| 价格（金币） | 30 | 60 | 110 | 180 | 270 |

**公式**：`price = round10(旧满槽兑金币基准 [20, 40, 70, 120, 180] × 1.5)`。买价恒高于旧兑金币值 —— 旧值是「放弃卡换金币」，新值是「花金币买卡」，两者不能同价。数值只写在一处：`Dungeon3D.FATE_PRICE_BY_RARITY`。

- **支付源唯一**：只走 `GameManager.currency`（本局金币，`spend_currency` / `add_currency`）。局外总货币池 `BaseManager.get_extraction_points()` 在任何分支都不得被读写。
- **购买事务**：先扣金币，再走 `FateCardGameBridge.apply_card_with_source_selection()` 这一条统一入口；应用失败必须**原额退金币**，不允许出现「钱花了、卡没刻上」的静默损失。
- **弹窗只在退出时关闭**：底部中央「退 出」按钮与 ESC / 手柄 `ui_cancel` 同义；已买下的卡继续生效，未买的直接放弃，退出时才提交门后流送。
- **退出先退场、不硬切**（2026-10-15）：三张卡（含已购卡）同时窄边翻回背面、缩小到零并淡出；总时长 `FATE_OVERLAY_EXIT_DURATION = 0.42s`，前 `0.16s` 收窄到薄边并换面。尾段余额、退出按钮与遮罩一同淡出，整条动画结束后才回收节点、提交门后流送与释放玩家输入。退场接管当前尺寸，停止原来的进场/购买翻牌与漂浮，不先跳回基准缩放；重复退出与退场中购买无效。减少动效时直接关闭，缺背图时保留原可见层随退场消失。
- **买下的卡当场翻回背面**（2026-10-14 主人要求）：卡位已用掉，露着牌面会被当成「还能再买一次」。手法与出场翻牌对偶（90° 薄边时换面），减少动效时直接换。**不改变可聚焦性** —— 焦点链要经过卡列回退出按钮。
- **已购卡做成灰阶 + 压暗 + 半透明 + 缩到 70%**（2026-10-14 / 10-15 主人要求）：灰阶走 `canvas_item` 灰度 shader（按 `luminance` 去色，挂卡背层），压暗走 `modulate`（`FATE_PURCHASED_DIM_COLOR` = 中性灰 **`0.40`**），半透明走卡背层的 `modulate.a = FATE_PURCHASED_CARD_ALPHA`（**`0.45`**），缩放走 `FATE_PURCHASED_CARD_SCALE = 0.70`。四者职责分开，将来单独调任一项互不影响。
  - 压暗档位是业主两次指定的结果：「暗下去」给了 `0.62`，随后「还要再暗一些」下调到 `0.40`。已购卡文字色取 `FATE_PURCHASED_TEXT_COLOR = 0.72`（比压暗值留余量）—— 整列 modulate 会再乘一次，而「已购买」是这张卡唯一仍需被读到的事实，跟着卡面沉到 0.34 就读不出来了。
  - 🔴 **去色不能只用 `modulate`**：卡背线稿是亮青绿，压暗只得到「暗绿」而非「灰」。
  - 🔴 **0.70 是基准缩放，不是悬停反馈**：`_tween_fate_card_scale()` 的 target 全是「相对基准的倍率」，最终尺寸 = `target × 基准`；否则 `_reset_fate_feedback()` 的「复位到 1.0」会把 0.70 冲掉。
  - 🔴 **压暗色必须 R=G=B**：掺冷调会把「改成灰色」做成「改成灰蓝」。
  - 🔴 **半透明只加在卡背贴图层，不加在整列**（2026-10-15 主人要求「更淡一些」）：整列调 alpha 会把「已购买」压到 `0.72 × 0.40 × α ≈ 0.13` 的有效亮度，直接读不出来。这条**有反向断言盯着**（卡下说明与价格行的 `modulate.a` 必须恒为 `1.0`）。
  - 分档：已购 ⇒ 灰阶 + 压暗 + 半透明 + 70%；买不起 / 槽满 ⇒ 只做轻度压暗（它们是「暂时买不了」，不是「已经没了」）。
- **已购买的卡不再有悬停反馈**：放大与悬停亮边都掐掉（它再点只会弹「已购买」）。只掐视觉反馈，按钮保持可聚焦。
- **不可购买的三态**（都不扣金币、不播选中动画、不关弹窗）：目标枪命运槽已满（星星卡）、本局金币不足、该卡位已购买。
- **反馈落在卡上，而不是只在状态栏**（2026-10-15 主人要求「让人更容易理解和看到反馈」）：
  - 拒绝 ⇒ 卡片**横向抖动** + 价格行**提亮并按一下**。抖动走 `position:x`（三张卡的常驻漂浮占 `position:y` 与 `rotation`，悬停/选中占整列 `scale`，只有这条通道是空的）；基准 x 记在 meta 上复用，否则连点会一轮轮往右漂。
  - 金币不足 ⇒ 余额行**闪红**（只闪红不抖动：抖动是「卡拒绝你」的语义，两者不能共用动作）。
  - 扣款成功 ⇒ 余额行脉冲 + 右侧浮出 `- N 金币` **飘字**（0.9 秒后自毁）。
  - 卡下价格行在金币不足时写 `◈ N 金币 · 还差 M`：**「金币不足」只说了状态，「还差多少」才是下一步信息。**
- **刷新**：`_refresh_door_fate_prices()` 是价格行与余额行的唯一刷新口，扣金币、购买、打开弹窗、拒绝反馈前都必须调用（拒绝反馈要先刷新再闪，否则提亮会被随后的着色覆盖）。
