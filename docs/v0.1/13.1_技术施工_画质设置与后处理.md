# 技术施工｜画质设置与后处理 v0.1

功能ID：`GRAPHICS-POSTFX`；工程版本：`0.1.0`；施工修订：r1（2026-09-24）。来源：正式运行代码反推的**当前实现事实**。状态：**[开发中]**；玩法主设计见[时间日夜与画质](design/时间日夜与画质设计.md)。本文只记实现/接口/差距；上级性能预算见[13](13_技术施工_性能优化与热管理.md)。

## 玩家目标与范围

玩家能在正式游戏中修改全局画质档；开发调参入口能查看和调整后处理，切场与重启后按当前实现恢复。画质不能改变战斗规则、能源状态或存档内的玩法数值。当前 P 键 `FlashlightColorTweaker` 面板是**调试入口**，不是已验收的正式玩家设置页；后续若要发布给玩家，必须另验输入、可达性、真实渲染和性能。

## 所有者与依赖

| 状态/作用 | 当前唯一写者 | 读取者与正式接入 |
|---|---|---|
| 正式画质设置、已注册 `Environment` 与视口质量参数 | autoload `GraphicsSettingsManager` | 画质 UI/运行场景调用 `set_value` 或注册环境；配置保存在 `user://graphics_settings.cfg` |
| 临时 Environment 后处理覆盖 | `GraphicsSettingsManager._debug_postfx` | 玩家场景 `FlashlightColorTweaker` 的 P 键调试页；覆盖不是正式画质档字段 |
| 全屏颗粒、色相的运行参数与 Shader uniform | autoload `PostfxOverlay` | 同一调试页；Shader 为 `assets/shaders/postfx_grain.gdshader` |
| 调试参数持久化文件 | `FlashlightColorTweaker` | `user://postfx_tuning.json`；旧 `postfx_export.json` 只做读取兼容 |

`project.godot` 注册两个 autoload，`scenes/Player3D.tscn` 挂调试面板。它们不属于行动快照或 `BaseData`，也不拥有手电电量。该分层目前**不是完全解耦**：调试面板直接同时写两个 autoload 并负责落盘，尚无统一参数事务/通知服务。

## 命令、查询与事件

| 状态 | 接口 | 当前语义及失败边界 |
|---|---|---|
| 已实现 | `GraphicsSettingsManager.set_value(key, value, save=true) -> bool` | 仅接受 `DEFAULT_SETTINGS` 中的键；不认识的键返回 `false`。抗锯齿、阴影、间接漫反射枚举非法值回退默认；其他键转布尔。变更后应用并可写 cfg。当前写盘无返回结果，`true` **不证明磁盘保存成功**。 |
| 已实现 | `get_settings_snapshot()` / `get_value()` / `settings_changed(snapshot)` | 返回设置副本；信号在应用/尝试保存后发出，不能当作写盘成功事件。 |
| 已实现 | `register_environment(environment)` | 弱引用注册并应用当前画质；切场资源释放后清理引用。`apply_to_environment()` 是即时应用入口。 |
| 已实现 | `set_debug_postfx` / `apply_debug_postfx` / `clear_debug_postfx` | 只接受 `DEBUG_POSTFX_KEYS`；覆盖仅在本进程内存，实际持久化由面板另写 JSON。 |
| 已实现 | `PostfxOverlay.apply_grain(enabled,strength,size,hue)` / `reset_to_defaults()` | 颗粒强度夹在 `0..1`、尺寸 `0.05..3`、色相 `0..1`；无可见效果时关闭叠层。关闭颗粒开关会清零强度，但不清色相。 |
| 未实现的目标 | 统一的 `commit_postfx_settings` 与保存结果事件 | 如将调试参数转为正式玩家设置，应由单一所有者校验、保存并返回明确成功/失败；目前不可宣称具备原子回滚。 |

## 数据与生命周期

正式画质键以 `GraphicsSettingsManager.DEFAULT_SETTINGS` 为准：`anti_aliasing`、`bloom`、`ssao`、`ssil`、`ssr`、`indirect_diffuse_quality`、`volumetric_fog`、`distance_fog`、`shadow_quality`、`color_grading`、`scene_particles`。动态阴影和 SDFGI 没有关闭档；旧 `sdfgi=false` 迁移为低间接漫反射档，而不是关闭。启动加载 cfg，场景注册 `Environment` 后应用；改档立即应用到视口/环境。

调试页的 Environment 覆盖包含辉光方向、亮度/对比度/饱和度和电视漏光参数；`hue_shift`、颗粒启用/强度/尺寸实际由 `PostfxOverlay` 的全屏 Shader 实现，不能按 `Environment` 属性描述。调参静止 0.4 秒后面板写 `postfx_tuning.json`，退出前补写；下次玩家场景面板启动时读回并分别送至两个所有者。`PostfxOverlay` 只保存内存状态，本身不读文件。清空按钮重置两侧并安排写入；导出按钮另写同一调参文件、打印并复制到剪贴板。

## 拒绝、失败与回滚

- 不认识的正式画质键拒绝；非法枚举回退默认。调试覆盖忽略未知键，空字典清空覆盖。Overlay 数值裁剪到允许范围。
- 配置文件缺失时使用默认值；调参 JSON 缺失或无效时不覆盖当前默认。旧导出文件只作兼容读取。
- **当前缺口**：正式 cfg 保存与调参 JSON 写入都没有对外确认/回滚合同；`FlashlightColorTweaker._write_persist_file()` 打开失败仍返回导出文本，面板不能据此声称已保存。异常文件与部分字段的错误报告需补。不得把此功能标为“存档事务已验收”。
- `PostfxOverlay` 叠层为 `CanvasLayer=90`，调参面板为更高层；“只影响 3D、不影响其他 UI”的像素隔离尚未有正式渲染证据，不以节点层级推断通过。

## 正式接入与验收

正式场景经 `project.godot` autoload 与 `Player3D.tscn` 调试面板接入。逻辑专项：`verify_graphics_settings_ui_flow`、`verify_postfx_overlay_runtime`、`verify_postfx_autopersist`；它们分别验证画质 UI、Overlay 状态/uniform 与调参重启恢复，**不替代真实渲染效果或目标 GPU 性能**。视觉入口为 `verify_graphics_settings_visual`，须用真实渲染器记录颜色、颗粒、UI 污染和开关 A/B；当前本轮未执行，不标通过。

后续验收至少补：非法键/坏文件/写盘失败的明确结果，跨场景 Environment 应用，调参页关闭与退出补写，真实画面及性能预算。开发过程与本次核对见[第五项文档补齐记录](development/2026-09-24_design_contract_backfill.md)。
