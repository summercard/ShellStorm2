# 技术架构

## 分层

| 层 | 目录 | 责任 |
|---|---|---|
| 公共契约 | `src/framework/` | 版本、正式场景路径、渲染层、跨系统枚举 |
| 基础设施 | `src/core/` | 全局状态、存储、状态机、音频、通用工具 |
| 领域模块 | `src/game/`、`src/components/` | 背包、撤离、保险、掉落、结算、通用组件 |
| 3D 运行时 | `src/world3d/`、`src/player3d/`、`src/enemy3d/` | 当前正式玩法 |
| 场景适配 | `src/base3d/`、`src/training3d/`、`src/ui/` | 场景编排、菜单与显示 |
| 兼容层 | `src/player/`、`src/enemy/`、部分 `src/game/` | 旧 2D 玩法与迁移参考，只修阻断问题 |

依赖方向应从场景适配指向领域模块和基础设施。领域模块不得反向依赖具体 UI 节点路径；美术资产不得成为玩法状态的唯一来源。

## 当前核心所有权

- `TowerDescent3D`：塔楼层级、楼梯连接和当前层编排。
- `Dungeon3D`：房间图、生成、敌人、掉落、门、撤离与单局结算。
- `DungeonRoom3D`：单房间实例、壳体、灯光和内容挂载。
- `TowerGeometry3D`：5m 网格、房间尺寸、门净空、楼梯接口与层高。
- `Player3D` / `Enemy3D`：实体玩法根。
- `GameUIManager`：现有综合 HUD；v0.1 后不再继续增加跨系统业务逻辑。

## 跨系统通信

优先级从高到低：类型化方法与信号、稳定数据对象、节点组、兼容动态调用。新增代码禁止使用绝对节点路径 `/root/Main/...`；禁止用 `find_child` 和字符串方法名建立新的核心流程。

`GameDesignConfig` 是跨系统稳定常量入口。具体数值平衡留在主题资源、蓝图或所属系统中，避免把所有参数堆入全局配置。

## 场景切换

正式入口、3D 基地和 3D 训练场路径由 `GameDesignConfig` 统一声明。可配置入口仍通过导出字段传入，但切换前必须验证 PackedScene 存在，并处理错误码。

## 兼容策略

旧 2D 栈不会在 v0.1 立即删除，因为部分 UI、蓝图和专项测试仍复用其行为。它被视为只读兼容边界：不新增 2D 内容；新功能先进入 3D 领域模块；完成依赖迁移和专项回归后再整组删除。
