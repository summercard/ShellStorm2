# 技术施工｜剧情触发 v0.1

系统编号：6  
上级设计：[游戏设计文档 §11](README.md#11-核心系统六剧情触发)  
相关系统：玩家、关卡、怪物/精英、基地、存档

## 1. 职责与边界

剧情系统根据已发生的游戏事实判断是否触发叙事内容，并记录触发历史。它不生成关卡、不杀死怪物、不直接发物品、不写其他系统私有字段；所有游戏效果通过对应系统命令执行。

## 2. 当前能力

- <span style="color:#2E7D32">**[已实装]** `ThemedNPC3D` 支持稳定 NPC 配置、范围交互和静态对话显示。</span>
- <span style="color:#2E7D32">**[已实装]** 正式 3D 已产生进入房间、开门、清房、击杀、Boss 阶段、掉落、撤离等可利用事件。</span>
- <span style="color:#2E7D32">**[已实装原型]** `RoomEventHandler` 定义诅咒、祝福、交易、赌局、揭图和增援；部分仍是旧 2D 或简化交互。</span>
- <span style="color:#2E7D32">**[已实装原型]** `MapFateTriggers` 具有计数、阈值、冷却和每局一次规则，但仍带有旧 `RoomGameMode` 查找逻辑。</span>
- <span style="color:#1565C0">**[用户设计]** 剧情触发必须成为独立核心系统并可跨局保存。</span>

## 3. 目标数据模型

<span style="color:#EF6C00">**[Codex补充]** 使用数据驱动的 `NarrativeTriggerDefinition`。</span>

```text
narrative_id
chapter_id / sequence
conditions[]
trigger_mode (once / repeatable / cooldown / mutually_exclusive)
actions[]
priority
interrupt_policy
save_keys[]
presentation_id
version
```

条件只读取只读快照：楼层、房间、Boss、精英档案、带出物、设施等级、累计次数和已触发剧情。动作通过适配器执行：显示对话、播放演出、更新任务状态、请求掉落、请求门状态或请求世界标记。

## 4. 触发流程

```text
领域事件进入 NarrativeEventQueue
→ 用稳定事件ID去重
→ 查找候选剧情
→ 读取不可变条件快照
→ 解析优先级、互斥与中断策略
→ 预约触发事务
→ 表现层播放
→ 游戏效果通过系统命令提交
→ 成功后写触发历史
→ 失败回滚预约并记录原因
```

剧情历史只在动作成功或明确允许“看过即完成”时提交，不能在对话还没出现前提前标记完成。

## 5. 与七系统的事件接口

| 事件 | 可用于的剧情条件 |
|---|---|
| `player_state_changed` | 首次受伤、濒死、复活 |
| `fate_card_applied` | 首次获得禁忌卡、特定组合 |
| `floor_entered / room_revealed` | 楼层章节、特殊房间、楼梯间 |
| `floor_bundle_committed` | 首次生成98F、到达门开启、跨层连续性 |
| `segment_commit_requested / segment_committed` | 隔离间警告、不可逆下潜节点、旧区段告别 |
| `monster_killed / boss_defeated` | 首杀、Boss 结算、专钥匙剧情 |
| `elite_encountered / escaped / killed` | 12 精英个人故事和复仇关系 |
| `facility_upgraded` | 基地角色、设施剧情 |
| `run_extracted / run_failed / revived` | 撤离、失败、复活后果 |

## 6. 内容边界

- <span style="color:#1565C0">**[用户设计]** 本次建立系统，不擅自改写主线剧情。</span>
- <span style="color:#EF6C00">**[Codex补充]** v0.1 先准备剧情表结构与三条垂直切片：首次进入 98 层、首次击败 Boss 并获得专钥匙、首次遇见/再次遇见同一精英。</span>
- 对话文本、角色关系、章节和结局由后续主设计内容冻结；技术层不得把占位文本当成最终故事。
- 隔离间“无法返回、未拾取物永久丢失”属于关卡强制系统提示，不得等待剧情队列、被剧情跳过或因剧情系统故障而消失；剧情只能在其前后追加氛围内容。

## 7. 施工阶段

1. 建立 `NarrativeTriggerService` 和领域事件适配器。
2. 给事件与剧情定义稳定 ID，加入每局去重和跨局历史。
3. 把 NPC 表现改为消费 `DialoguePresentation`，不自行判断进度。
4. 迁移命运/事件房原型，区分玩法事件与剧情事件。
5. 完成三条垂直切片并验证跳过、中断、重载和重复触发。

## 8. 验收标准

- [ ] 剧情系统可在不加载具体 NPC 场景时完成条件判定测试。
- [ ] 同一领域事件重复发送不会重复完成一次性剧情。
- [ ] 同时满足多条剧情时按优先级和互斥组稳定选择。
- [ ] 对话被暂停、跳过、离开范围或场景卸载时有明确中断结果。
- [ ] 剧情奖励通过物品/关卡/基地命令发放，失败不会写已完成。
- [ ] 剧情存档包含版本并可从上一版迁移。
- [ ] 首入 98 层、Boss 专钥匙、唯一精英三条切片可复现。
- [ ] 区段隔离警告即使剧情系统停用也必然显示；`segment_committed`剧情重复发送不会重复卸载或重复统计损失。
- [ ] 静态 NPC 文本和正式剧情文本来源区分明确。
- [ ] 旧事件房不再直接修改正式 3D 私有状态。
- [ ] 主线剧情内容未冻结时，占位内容不会被标为最终完成。
