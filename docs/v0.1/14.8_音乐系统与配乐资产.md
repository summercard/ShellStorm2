# 音乐系统与配乐资产 · v0.1

> 本文档描述 ShellStorm2 的音乐架构、当前已生成的配乐、触发点与扩展方式。

---

## 1. 架构总览

音乐系统由三个核心模块组成，全部解耦于场景代码：

```
src/audio/
├── MusicCatalog.gd   # 静态注册表：music_id → 资产 / 音量 / 淡入淡出 / 选曲模式
├── MusicManager.gd   # autoload 单例：play / push_and_play / restore / pause / stop
└── MusicTrigger.gd   # 触发点组件（class_name）：可挂场景任意节点
```

**调用流程**：

```
场景代码 / MusicTrigger     MusicManager (autoload)      AudioStreamPlayer
   │                          │                              │
   ├─ push_and_play("boss") ──►│                              │
   │                          ├─ push 上一个 music_id 到栈      │
   │                          ├─ 选 A/B (random)               │
   │                          ├─ fade out 旧曲                 │
   │                          ├─ load(track_path) ──────────────►│
   │                          ├─ fade in 新曲                   │
   │                          ├─ 监听 finished → 循环（按模式选下一首）│
   │                          │                              │
   │ restore() ──────────────►│                              │
   │                          ├─ pop 栈 → 上一首                │
```

**关键设计原则**：
1. **解耦**：场景代码只发"我要播什么"（music_id 字符串），不持有 AudioStreamPlayer / 不管 fade / 不选 A 或 B
2. **可管理**：新增曲目只需在 `MusicCatalog.ENTRIES` 加一行，**不动 MusicManager**
3. **跨场景持久**：MusicManager 是 autoload，切换 TowerDescent3D ↔ BaseWorld3D 不重置
4. **栈式历史**：`push_and_play` / `restore` 让 Boss 房"进入→离开"自动恢复进入前的曲子（descent_suspense）

## 3. 触发点

| 触发点位置 | 触发条件 | 行为 | music_id |
|---|---|---|---|
| `BaseWorld3D._ready()` | 进入基地 | `play()` | `base_passion` |
| `TowerAtmosphere3D.set_floor_number(>=100)` | 楼顶 | `play()` | `rooftop_relax` |
| `TowerAtmosphere3D.set_floor_number(<100, %5!=0)` | 进入关卡层 | `play()` | `descent_suspense` |
| `TowerAtmosphere3D.set_floor_number(>0, %5==0)` | Boss 房（95/90/85F）| `push_and_play()` | `boss_intense` |

**返回机制**：Boss 房逻辑压栈——进入 95F Boss → `push_and_play("boss_intense")`；离开 95F 回到 96F → `set_floor_number(96)` → 走非 Boss 分支 → `play("descent_suspense")`（注意当前实现用 `play()` 直接覆盖，未显式 `restore()`，如需严格"恢复进入前曲目"需要追踪上一次非 Boss music_id）。

## 4. Audio 总线

- **bus 名称**：`Music`（默认挂在 Master 下）
- **总音量**：`AudioServer.set_bus_volume_db(Music)`（运行时调节）
- **当前 MusicManager 不实现总音量持久化**——如需主人面板音量控制，需在 `GraphicsSettingsManager` 或 `PauseMenu3D` 增加 slider → `MusicManager.set_volume_db()`

## 5. 如何添加新曲目

**步骤**：
1. **生成音乐**：用 Suno.cn API 或内置 music_generate，下载 mp3
2. **放入**：`assets/audio/music/<scene_name>/<music_id>_<version>.mp3`
3. **触发 Godot 自动 import**：用编辑器运行一次，或 `godot --headless --editor --quit` 让 importer 扫描
4. **注册到 Catalog**：编辑 `src/audio/MusicCatalog.gd` 的 `ENTRIES` 加一项：
   ```gdscript
   {
       "music_id": "my_new_music",
       "title": "我的新曲",
       "scene": "BaseWorld3D",
       "description": "...",
       "tracks": [
           "res://assets/audio/music/my_new_music/track_a.mp3",
           "res://assets/audio/music/my_new_music/track_b.mp3",
       ],
       "selection_mode": "random", # random | sequential | first
       "loop": true,
       "default_volume_db": -2.0,
       "fade_in_seconds": 1.2,
       "fade_out_seconds": 1.2,
       "bus": "Music",
   },
   ```
5. **触发点**：在场景 `_ready()` 或流程节点调 `MusicManager.play("my_new_music")` / `push_and_play("my_new_music")`

**MusicManager / MusicTrigger 不需要任何改动**——所有曲目通过 music_id 字符串寻址。

## 6. 临时静音 / 调试

- **暂停**：`MusicManager.pause()`
- **恢复**：`MusicManager.resume()`
- **停止**：`MusicManager.stop()`（不弹栈）
- **当前音乐**：`MusicManager.get_current_music_id()` / `get_current_track_path()`
- **是否在播**：`MusicManager.is_playing()` / `is_playing("base_passion")`

## 9. Bug 修复记录

### 修复 1：fade-out tween 杀死新曲音量
- **症状**：连续两次 `play()` 会让新曲音量被上一曲的 fade-out 拉到 -80，几乎听不见
- **原因**：`_fade_out_current()` 创建 tween 异步淡出，但下一帧 `play()` 又 `_play_track()` 立刻 play() 新曲；旧 tween 仍把 `_stream_player.volume_db` 拉到 -80
- **修复**：`_play_track()` 起始处强制 `kill()` 现有 tween；移除 `_fade_out_current()` 在 `_play_track()` 内的调用（不再做 cross-fade，由 fade-in 单独负责）。重复 play() 也不再创建额外 stream / 不再 stop()

### 修复 2：场景切换时序抢断基地音乐
- **症状**：从塔撤离回基地后 `base_passion` 没播
- **原因**：`BaseWorld3D._ready()` 在场景树里第一帧就 `play("base_passion")`，但 Dungeon3D._exit_tree() 内某些异步操作（checkpoint flush / AudioServer 状态写回）仍在进行，可能影响 MusicManager 状态
- **修复**：`BaseWorld3D._ready()` 改为延迟 0.1s 再 play（`_start_base_music_with_delay()`），保证上一场景退场完全结束

### 修复 3：`stop()` 不清栈
- **症状**：反复 push → stop → restore() 会恢复到错误曲目
- **修复**：`stop()` 调用时同时清空 `_previous_stack`；新增 `hard_reset()` 立刻 kill tween + stop + 清栈
