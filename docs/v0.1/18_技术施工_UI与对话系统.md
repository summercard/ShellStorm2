## 1. 职责与边界

本模块只拥有**一件事**：屏幕上"谁在说话、说了什么、说到哪了"。

| 拥有 | 不拥有 |
|---|---|
| 当前对话行的显示与打字进度 | 该不该说话（[剧情触发](08_技术施工_剧情触发.md) 判定） |
| 对话框的布局、层级、输入消费 | 文本内容与台词（内容数据，见 §4） |
| 当前单路播放与推进/整场跳过/关闭的生命周期；多请求排队未实现 | 发奖励、开门、改数值（[架构总则 §8](02_技术架构总则.md) 明确禁止 UI 做这些） |

<span style="color:#1565C0">**[用户设计]** 对话 UI 必须独立成系统，能被任何系统调用，不只是剧情系统的私有组件。</span>

<span style="color:#EF6C00">**[Codex补充]** 三条硬边界：① 不持有剧情状态，不查询剧情进度；② 不 import 剧情系统的任何类；③ 调用方向单向 —— 剧情 → 对话 UI，反向依赖即为架构错误。</span>

### 1.1 两种对话载体（2026-09-21 用户确认）

本系统的对话**不是一种表现，是两种**，分工明确：

| 载体 | 说话人 | 呈现方式 | 状态 |
|---|---|---|---|
| **屏幕底栏对话框** | **系统 / 画外音**（无实体说话人） | 2D `CanvasLayer` 底部字幕条 | **已实装**（`src/ui/dialogue/DialogueUI.gd`，autoload） |
| **3D 头顶气泡** | **场景中的具体角色** | 角色头顶正上方的漫画式气泡 | **已实装**（`src/ui/bubble/SpeechBubble3D.gd`） |

选哪种由**调用方**决定，对话 UI 不自作主张：

- 说话人**有实体**（玩家 / NPC / 敌人）→ 头顶气泡
- 说话人**无实体**（旁白、系统提示、区域播报）→ 屏幕底栏

**[当前实现事实]** 两种载体目前**不是同一运行 schema/事件**：底栏 `DialogueUI.show_lines()` 消费五字段行并发 `dialogue_shown/line_finished/dialogue_finished`；角色气泡由 `CharacterBark3D.say_bark(bark_id)` 读取 `BarkCatalog`，或由 `say_text(text)` 直接播放，`SpeechBubble3D` 只发 `bubble_shown(text)/bubble_hidden()`。当前没有 `DialogueRequest.carrier` 路由器，也没有共享的 `dialogue_finished` 气泡回执。**[方向一致但未实现的目标]** 内容作者应能以稳定台词/短句 ID 追溯两种载体，未来若做统一请求层再定义映射，不能先假装已有同一份表。

## 4. 数据模型

目标是让正式剧情台词由内容数据提供，不在 UI 内硬编码；当前 `show_message()` / `announce()` 也接受调用方的即时字符串（例如基地提示），不能把“全项目无台词字面量”写成已实现事实。内容来源与台词ID由调用方负责，详见[剧情触发](08_技术施工_剧情触发.md)。

### 4.1 底栏当前行字段（旧稿称 `DialogueLine`）

| 字段 | 类型 | 说明 |
|---|---|---|
| `line_id` | 字符串 | 当前仅用于 `dialogue_shown/line_finished` 关联；缺省为 `inline`，UI 不保证全局唯一。正式剧情台词的稳定 ID 由内容侧保证 |
| `speaker` | 字符串 | 当前显示名；底栏无独立 `speaker_id`/`speaker_name` 双字段 |
| `text` | 字符串 | 正文，以普通 `Label` 显示；**不解析 BBCode** |
| `chars_per_sec` | 浮点 | 打字速度；0 = 立即全显 |
| `auto_advance_sec` | 浮点 | 0 = 等玩家推进；>0 = 打完字后自动进下一行 |

以上五项是 `DialogueUI._normalize_line()` 当前保留的字段。原稿的 `role_tag / portrait_id / voice_id / locale` 可作为方向一致的**未实现扩展**保留，但不得传入后期待当前 UI 使用；`skippable` 与当前整场 `skip()` 语义冲突，原逐行跳过规则不再是 v0.1 当前契约。正式剧情时间轴的内容载体由剧情系统管理；即时系统提示仍可由调用方提供文字。

### 4.2 播放请求 `DialogueRequest`

调用方（剧情/教程/提示）构造一次播放请求：

```gdscript
{
  "lines": Array,            # DialogueLine 数组，按序播放
  "interrupt": bool          # true/缺省 = 替换当前播放；false 且当前活跃 = 返回空 run_id
}
```

旧稿的 `queue_id`、`on_finished` 当前未使用，不是幂等键或回执字段。若调用方需要关联一次播放，必须保存返回的临时 `run_id` 并与 `dialogue_finished(run_id,outcome)` 比对；当前 `NarrativeAdapter3D.ui.dialogue` 尚未检查这个返回值。`run_id` 不进存档。当前 `interrupt=true` 替换播放时**不会给被替换的旧 run 发 `aborted`**，这是待补的生命周期缺口，不能把抢占回执写成已实现。

## 5. 接口契约

### 5.1 命令

| 命令 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `show_lines(request)` | `DialogueRequest` | `String` run_id | 空 `lines` 返回空串；当前活跃且 `interrupt=false` 也返回空串，**不排队** |
| `advance()` | 无 | `bool` | 打字中 → 立即全显；已全显 → 下一行；无活跃播放返回 `false` |
| `skip()` | 无 | `bool` | 结束**整场**并发 `skipped`；无活跃播放返回 `false` |
| `close()` | 无 | `void` | 结束整场并发 `aborted`；无活跃播放无动作 |
| `is_active()` | — | `bool` | 查询：是否有对话在播 |
| `current_speaker()` | — | `String` | 查询：当前 `speaker` 显示字符串，非独立演员 ID |
| `set_paused(paused)` / `is_paused()` | 布尔/无 | `void`/`bool` | 已实现：显式冻结打字、自动推进和输入处理；调用方负责在暂停切换时同步 |

### 5.2 事件

| 事件 | payload | 产生时机 |
|---|---|---|
| `dialogue_shown(run_id, line_id)` | — | 一行开始显示 |
| `line_finished(run_id, line_id)` | — | 打字完成（全显） |
| `dialogue_finished(run_id, outcome)` | `outcome ∈ completed / skipped / aborted` | 当前播放自然播完、`skip()` 或 `close()`；`show_lines(interrupt=true)` 替换旧 run 不发旧回执 |

<span style="color:#EF6C00">**[Codex补充]** 调用方通过 `dialogue_finished` 的 `outcome` 判断下一步，**不得**靠轮询节点状态猜测。`aborted` 与 `completed` 必须区分：剧情被中断时不能当成正常播完。</span>

## 6. 层级与输入

### 6.1 层级

现有 CanvasLayer 层级分配（实测）：主 HUD `20`、`PostfxOverlay` `90`、设施菜单 `100`、`MainEntryScreen3D` `110`、`MobileInput` `128`。

<span style="color:#EF6C00">**[Codex补充]** 对话 UI 取 **`layer = 100`**（模态层，与设施菜单同档，低于移动端输入层 128，保证触屏按钮仍可见可点）。数值集中在本文定义，不得在场景里另写一个。

### 6.2 输入

| 行为 | 键位 | 依据 |
|---|---|---|
| 推进 / 立即全显 | `ui_accept` | `project.godot` L96（回车 / 小键盘回车） |
| 跳过 | **需新增 InputMap 动作**，建议 `Space` 或 `Tab` | 见下方警告 |

<div style="color:#633806;background:#FAEEDA;padding:8px 12px;border-radius:8px">

**⚠️ 跳过键不能复用 `ui_cancel`。** `project.godot` L102 的 `ui_cancel` 绑定 ESC / 退格，而 ESC 是暂停菜单键（`PauseMenu3D.try_consume_pause_input()` L64）。若对话用 ESC 跳过，玩家会在"跳过对话"和"打开暂停"之间二选一，必然打架。

**⚠️ `ui_accept` 没有绑空格**（L96-101 只有两个回车键）。玩家用 WASD 移动时，回车推进手感可用但不理想。施工时确认是否补绑。

</div>

<span style="color:#EF6C00">**[Codex补充]** 对话激活期间，用 `_unhandled_input` + `get_viewport().set_input_as_handled()` 吃掉推进/跳过键，阻止其穿透到玩法（射击、交互）。这是项目既有模态 UI 的统一写法，不另发明。</span>

## 7. 失败收口

| 情况 | 收口 |
|---|---|
| `show_message` 文本为空白 / `show_lines` 空数组 | 返回空 `run_id`，不开始播放；数组内空行当前可显示为空，尚无占位错误诊断 |
| `text` 含 BBCode | 作为普通文字呈现，不解析标签；若需要富文本另立修订 |
| 活跃时 `interrupt=false` | 拒绝新请求并返回空串，不排队；`interrupt=true` 替换当前播放但旧 run 不发回执 |
| 播放中场景卸载 | autoload 自身跨场景；调用方需要主动 `close()` 才得到 `aborted`，自动卸载收口未实现 |
| 调用方在播完后才订阅事件 | 事件为一次性；调用方须在 `show_lines` 前完成订阅 |
| 立绘 / 语音资产缺失 | **未实现扩展的目标**：将来接入时降级为无头像 / 静音，不中断对话；当前 UI 不读取这些 ID |

**总原则**：对话 UI 的失败不得阻断玩法。最坏情况是"这句话没显示好"，绝不能是"游戏卡住"。

## 8. 施工阶段

1. 建 `DialogueUI`（CanvasLayer + 面板 + 说话人 + 逐字），用静态文本跑通显示与推进。
2. 接 `DialogueLine` 数据，支持立绘占位与自动播放。
3. 当前单路播放、`interrupt`、整场 `skip` 与三种 `outcome`；多请求队列若需要另立修订。
4. 输入仲裁与层级接入正式 HUD。
5. 补 `dialogue_shown / line_finished / dialogue_finished` 事件与调用方对接。

<span style="color:#EF6C00">**[Codex补充]** 本系统可**完全独立施工与验证**：它不认识剧情系统，验收场景里手动构造 `DialogueRequest` 即可跑通全部用例。这正是它被切出来的价值。</span>

## 9. 验收标准

- [ ] 不加载剧情系统时，直接调用 `show_lines()` 能正常显示、打字、推进、关闭。
- [ ] 打字机按 `chars_per_sec` 逐字，`chars_per_sec=0` 时立即全显。
- [ ] `advance()` 在打字中立即全显，已全显时进入下一行。
- [ ] `skip()` 整场结束并产生 `skipped`；独立跳过键仍未实现，不把逐行 `skippable` 当作当前验收目标。
- [ ] `dialogue_finished` 的 `outcome` 能区分 `completed / skipped / aborted`。
- [ ] 对话激活时推进键不穿透到玩法（不触发射击/交互）。
- [ ] 对话关闭后输入恢复正常，无残留的输入吞噬。
- [ ] 场景卸载时无节点泄漏（退出码 4 类检查）。
- [ ] 文字可见性用**真实渲染 A/B 像素差**判定，不用"节点存在"冒充渲染成功。
- [ ] **未来扩展验收**：立绘/语音接入后，缺失资源降级且不中断；当前无该能力，不计入 v0.1 主链通过率。
- [ ] 正式剧情台词来源可追溯；即时系统提示可由调用方传入，不能以“代码内零字面量”误判现状。
- [ ] **用户数据一致**：使用 `scripts/run_verification_suite.sh` 时，runner 在 Autoload 启动前建立独立项目与 `user://`；直接手工启动测试场景不具备该隔离保证，必须另设隔离目录，不能污染正式档。

## 10. 与剧情触发系统的连接

<div style="color:#04342C;background:#E1F5EE;padding:8px 12px;border-radius:8px">

**连接方式：剧情系统持有对话 UI 的引用并按 §5.1 发命令，对话 UI 不反向认识剧情系统。**

剧情脚本中的一个 `dialogue` 步骤：

```json
{ "kind": "dialogue", "line_id": "dlg_room03_warning", "wait_for": "finish" }
```

展开为一次调用：

```text
NarrativeAdapter3D.ui.dialogue → DialogueUI.show_lines({lines: [完整行数据], interrupt: true})
对话 UI → 显示 / 打字 / 等推进
对话 UI → dialogue_finished(run_id, "completed")
剧情系统 → 收到后执行下一步
```

契约要点：
1. 当前适配器传入 `lines` 完整行数据；对话 UI 不按 `line_id` 自行查内容。稳定台词来源和时间轴等待语义由[剧情触发](08_技术施工_剧情触发.md)管理。
2. `ui.subtitle` 调 `show_message(text,speaker,auto)`，`ui.hint` 调 `announce(text,auto)`；`ui.dialogue` 调 `show_lines({lines,interrupt})`。当前适配器未检查 `show_lines()` 的空返回，`interrupt=false` 且已有播放时可能报告已接受而未展示；这是待补失败回执，不写作已闭环。
3. 剧情中断要调用无参 `close()` 才会发当前 run 的 `aborted`；不能把场景卸载等同于自动关闭。`DialogueUI` 不感知剧情进度，也不写剧情历史。

</div>

## 11. 3D 头顶气泡实现口径（已实装 2026-09-21）

### 11.1 为什么不使用贴图与自定义 shader

本工程全仓 `.gdshader` 与 `ShaderMaterial` **零命中**，材质一律由 `StandardMaterial3D` 程序化构造。而气泡尺寸必须随文字变化，固定贴图会把圆角拉变形。因此气泡底板**程序生成几何**：圆角矩形是**凸多边形**，从中心做三角扇即可精确三角化，零贴图、零拉伸、形状可任意缩放。

### 11.2 "对着摄像机且不随角色转动"的两条保证

| 侧面 | 保证方式 | 验收判据 |
|---|---|---|
| **朝向** | 气泡节点每帧把 `global_transform.basis` 覆盖为**相机的 basis**；底板与文字都用默认朝向，**必须关闭 `BILLBOARD_ENABLED`** | 用真实 `Camera3D` 断言气泡 basis 等于相机 basis；并断言两个材质的 billboard 是 `DISABLED` |
| **位置** | 挂载偏移**只含垂直分量**（`head_height`）。因偏移无水平分量，角色绕 Y 轴转身不产生位移 | 断言角色转 90° 前后气泡 `global_position` 不变 |

<div style="color:#791F1F;background:#FCEBEB;padding:8px 12px;border-radius:8px">

**⛔ 为什么不能用 `BILLBOARD_ENABLED`（2026-09-21 实拍踩坑）**

初版让底板材质与 `Label3D` **各自**开 billboard。结果**玩家走路时文字与底板重影**。

成因：`Label3D` 的内置 billboard 与 `StandardMaterial3D` 的 billboard 在**不同阶段**求解，物体移动时两者差一帧 —— 静止时看不出来，一动就错位。

修正：**朝向改由气泡节点这一个变换统一驱动**（每帧复制相机 basis），底板与文字必然同步；又因为直接覆盖为相机 basis，依然不继承角色旋转。

**朝向必须在局部空间折算**：`wanted = 父节点basis.inverse() * 相机basis`，然后**只覆盖 `transform.basis`，`origin` 绝不动**。若写成 `global_transform = Transform3D(basis, global_position)`，会因读 `global_position` 的时机早于父节点变换刷新，而每帧把气泡反算回旧位置 —— 等于自己抵消掉父节点位移。

</div>

<div style="color:#791F1F;background:#FCEBEB;padding:8px 12px;border-radius:8px">

**⛔ 为什么气泡必须走"不透明"管线（2026-09-21 第二次实拍踩坑）**

修完朝向**仍能看到残影**，主人描述为"**感觉每帧都在原地刷新，然后拖一条尾**" —— 这是 **TAA 拖影**的典型形态。

成因：项目默认启用 TAA。**TAA 对透明物体不写运动矢量**，于是把它当成静止物体、把历史帧混进来，移动时拖出一串原地淡影。气泡底板（alpha 混合）与文字（alpha 混合）正好双双中招。

修正：

- 底板材质 `transparency = TRANSPARENCY_DISABLED` —— 气泡本来就是盖在场景上的实心 UI，不需要混合（`fill_color` 的 alpha 同步从 0.96 提到 1.0，观感无变化）
- `Label3D.alpha_cut = ALPHA_CUT_DISCARD` —— 用 alpha **裁剪**取代 **混合**，让文字同样进入不透明管线、拿到正确的运动矢量

两条都加了验收断言，防止以后被改回去。

**通用结论**：会移动、又要正对相机的 3D UI（气泡、血条、标记、指示器），材质应走**不透明管线 + alpha 裁剪**；否则在启用 TAA 的项目里必然拖影。

</div>

### 11.3 描边必须是"环带"，不能是"垫在下面的整块"

<span style="color:#791F1F">**这是一次实拍踩坑的结论，必须保留：**</span>

初版把描边做成"放大一圈的实心圆角矩形 + 缩小一圈的填充 + Z 偏移分层"。实拍结果：**青色描边整块盖住深色填充，气泡变成一团纯色块**。原因不是偏移量不够，而是 —— 两个 surface 在**同一 mesh、同一 AABB**，透明材质的渲染顺序在距离相等时并不可靠，`render_priority` 也救不了同 mesh 内部的 surface 顺序。

修正：描边改为**外轮廓与内轮廓之间的环带**，与填充**在几何上互不重叠**。于是任何渲染顺序都得到正确结果。两者共享内轮廓顶点（同源计算），不会出现接缝。

### 11.4 关键参数

| 参数 | 值 | 说明 |
|---|---|---|
| `font_size` / `pixel_size` | 48 / 0.0055 | 文字像素尺寸 → 世界尺寸（1px ≈ 5.5mm） |
| `TEXT_PAD_X` / `TEXT_PAD_Y` | 34 / 24 | 文本与内轮廓的间距（像素） |
| `CORNER_RADIUS` | 22 | 倒角半径（像素） |
| `BORDER_WIDTH` | 2.5 | 描边宽度（像素）。**必须小** —— 描边是硬边轮廓不是色块，过粗会在短句气泡上把填充整块吃掉 |
| `CORNER_SEGMENTS` | 6 | 每角细分段数（每角 7 点，共 28 点） |
| `fill_color` | `(0.010, 0.032, 0.045, 0.96)` | 深蓝黑，近似 `UIPalette.BG_*` 但更不透明（气泡要保证文字对比度） |
| `border_color` | `(0.12, 0.66, 0.76, 1.0)` | `UIPalette.BORDER_NORMAL`（霓虹青） |
| `hold_seconds` | 3.4 | 自动消失时长 |

材质统一 `SHADING_MODE_UNSHADED`（叙事 UI 不该随房间灯光明暗）+ `TRANSPARENCY_ALPHA` + `CULL_DISABLED`。

### 11.5 短句目录的纪律

台词集中在 `BarkCatalog`（本工程既有的"内容目录"写法，与 `MusicCatalog` / `EliteContentCatalog` 同规格）。调用方只传 `bark_id`，**逻辑侧不出现文本字面量**。随机抽取带"不连续重复"策略，并另提供 `pick_at(bark_id, index)` 确定性取句给验收用（避免随机导致断言不稳定）。

> 迁移标记：`BarkCatalog` 当前是内容表的代码投影，尚未与 xlsx 对表。

### 11.6 已知影响面

- 玩家侧新增 `CharacterBark3D` + `SpeechBubble` 共 4 个节点（惰性挂载，首次说话时才建），需留意 `verify_3d_performance_budget` 的节点余量。
- 验收会触发 autoload 写 `user://`（`GameTimeManager` 定时刷档），**跑验收前须快照用户目录，跑完还原**（§9 末条）。

## 12. 底栏对话系统实现口径（已实装 2026-09-21）

### 12.1 为什么做成 autoload

对话是**跨场景**能力（基地 / 塔楼 / 远征 / 训练场都要用）。项目现有 UI 都是"各场景自行 `instantiate()`"，没有一个能在三处都部署的宿主，所以注册为 autoload `DialogueUI`。

注意：该脚本**不声明 `class_name`** —— Godot 中 autoload 单例名与同类名会冲突。

### 12.2 层级与输入

| 项 | 取值 | 理由 |
|---|---|---|
| `layer` | **100** | 与设施菜单同档（模态层）；`MobileInput` 是 128，必须在其**下方**，否则触屏按钮会被底栏盖住点不到 |
| 输入消费 | `_unhandled_input` + `get_viewport().set_input_as_handled()` | 项目既有模态 UI 的统一写法（`VaultMenu.gd:27` 等） |
| 推进键 | `ui_accept` | `project.godot` L96（回车 / 小键盘回车） |

<div style="color:#633806;background:#FAEEDA;padding:8px 12px;border-radius:8px">

**⚠️ 跳过键仍未实现。** `ui_cancel` 绑的是 ESC，而 ESC 是暂停键（`PauseMenu3D.try_consume_pause_input()` L64），**不能复用**。跳过需要新增一个 InputMap 动作（建议 Space 或 Tab）。

</div>

### 12.3 推进语义

| 情形 | 行为 |
|---|---|
| 打字中按推进 | **立即全显**（不跳过本行） |
| 已全显按推进 | 下一行；已是最后一行则结束 |
| `auto_advance_sec > 0` | 打字完成后倒计时自动进下一行（系统提示用，不打断玩家） |
| `auto_advance_sec == 0` | 停在屏幕上等玩家推进，右下角显示提示 |
| `close()` | 立即结束，`outcome = aborted` |

### 12.4 outcome 三态必须区分

`completed` / `skipped` / `aborted`。调用方据此判断"是否真的播完"——**被中断的绝不能当成正常播完**，否则剧情会在没演完时记成已完成。

### 12.5 首个接入：基地欢迎语

```text
玩家从基地两侧门进来（门关的那一刻玩家在基地内侧）
→ RoomDoor3D.motion_finished(false)          # 门扇动画真正落到底
→ TowerDescent3D._on_facility_door_motion_finished(is_open = false)
→ 校验：facility.contains_world_position(player) —— 不在基地内则直接返回
→ DialogueUI.announce(BARK_BASE_WELCOME 对应文案)   # 3.2s 后自动消失
```

三个设计取舍：

1. **触发时刻取"动画结束"而不是"开始关闭"** —— 门是缓缓降下的，玩家走进来之后门才关；等门真正关上再播报，节奏才对。
2. **用 `announce()` 自动消失，而不是等按键** —— 系统提示不该打断玩家操作。玩家可能正在跑去设施，卡一个"请按回车"是负体验。
3. **必须校验"玩家在基地内侧"** —— <span style="color:#791F1F">出门时门同样会自动关上</span>，不校验就会在离开基地时误报"欢迎回到基地"（2026-09-21 主人实测反馈）。判据用 `DungeonRoom3D.contains_world_position()`，y 范围与 `_build_trigger` 对 FACILITY 的口径一致。
   配套：`TowerDescent3D` 用局部常量 `BARK_BASE_WELCOME` 持有短句 ID（ID 是调用方与内容目录之间的契约），并由 `verify_speech_bubble_3d` 断言该条目确实存在。

<span style="color:#EF6C00">**[Codex补充]**</span> 气泡挂高常量在 `Dungeon3D.PLAYER_BARK_HEIGHT_M`。2026-09-21 主人反馈"太低、挡住角色"后从 `1.95` 提到 **`2.55`**：俯视角下原高度让气泡底边压在角色身上。

### 12.6 与其它系统的关系

- **调用方向单向**：任何系统 → `DialogueUI`，它不认识调用方。
- **越权保护**：`TowerDescent3D` 的订阅里用 `DialogueUI.has_method("announce")` 做存在性检查 —— **对话 UI 缺失时静默跳过，绝不因播报失败影响玩法**。
- **零持久化**：本系统不写任何存档字段。

### 12.7 文档对齐结论（2026-09-24）

原稿六处口径差异已在 §1、§4、§5、§7、§8、§9 按正式 `DialogueUI.gd` 收敛：不排队；`advance/skip/close` 无参；整场跳过；当前只保留五项行字段；普通 `Label` 无 BBCode；`queue_id/on_finished` 不生效。原稿中方向仍合理但未实现的立绘、语音、多语言等保留为**未实现扩展**，不因当前代码缺失而删除未来可能性。

`set_paused(paused)` 已存在并会冻结打字、自动推进和输入处理，但暂停调用方接线须按剧情链单独验收。当前仍需明确修复/验收的生命周期缺口：抢占旧 run 不发 `aborted`、场景卸载不自动 `close()`、跳过键未绑定；真实渲染文字、层级与输入穿透也不能由纯逻辑测试代签。文档补齐只校正契约，不表示这些缺口已经修复。
