# 玩法系统｜局内商人 v0.1

功能ID：`RUN-MERCHANT`。状态：**[开发中]**。适用游戏工程：`0.1.0`。更新日期：2026-09-12。

局内商人是行动内消费玩法。玩家进入商人服务点后，用本局魂购买当前会话生成的商品；成交物直接进入当前背包，首次成功交易可解锁交易条件撤离。本文先固定现有运行行为，再定义尚未完成的事务与验收边界。

## 1. 当前功能

- 商人服务点由`Dungeon3D`打开动态`MerchantUI`，名称随当前玩法主题变化。
- `LootModule.generate_merchant_goods(tier, 6)`从`ItemRegistry`读取符合商人层级且价格为正的内容，再按蓝图Tier过滤。
- 每次会话最多显示6件商品，基础价格应用随机±10%浮动；武器先转换为具有唯一`weapon_instance_id`的完整实例。
- UI显示商品名、价格、魂余额、武器实例尾号与命运槽摘要；可购买和不可购买状态具有不同样式。
- 购买前检查背包容量和魂；成功后物品进入当前`InventoryModule`并从本次货架移除，不能重复购买同一实例。
- 背包写入失败时返还刚扣除的魂；魂不足或背包已满时不改变商品和背包。
- 成功交易发出`purchase_requested`，`Dungeon3D`据此解锁`TRADE`条件撤离；关闭面板后恢复玩家输入。

## 2. 所有者与数据链

| 状态 | 当前所有者 |
|---|---|
| 本局魂 | `GameManager.currency`，`Dungeon3D`同步行动价值与自动快照 |
| 当前背包 | 行动`InventoryModule` |
| 商品候选 | `ItemRegistry`与`LootModule` |
| 本次货架 | 当前`MerchantUI._items`会话 |
| 交易撤离条件 | `Dungeon3D._trade_extraction_unlocked` |

正式链路为`ServiceStation3D → Dungeon3D → LootModule → MerchantUI → GameManager/InventoryModule → 行动快照与撤离条件`。商品视觉和UI不得另建物品定义或价格表。

## 3. 当前命令、事件和失败语义

| 类型 | 接口 | 当前语义 |
|---|---|---|
| 命令 | `show_merchant(goods)` | 建立当前最多6件货架并打开模态界面 |
| 命令 | 点击商品 | 容量检查→扣魂→写背包→失败返魂→移除货架 |
| 事件 | `purchase_requested(item, slot_index)` | 成交后通知世界解锁交易撤离条件 |
| 事件 | `merchant_closed()` | 关闭会话并恢复输入 |
| 查询 | `ItemRegistry.get_merchant_goods(tier)` | 返回层级允许、价格为正的候选 |

现阶段退款只处理同一帧背包写入失败；货币、背包、会话货架、行动快照和撤离条件尚未形成带`transaction_id`的单次领域提交。场景中断或保存失败时的恢复边界尚无独立专项，因此状态保持开发中。

## 4. 目标事务

```text
purchase_run_merchant_item(session_id, offer_id, inventory_revision)
→ 校验会话、货架实例、价格、余额和容量
→ 在副本中扣魂、转移完整物品实例、移除offer并设置交易条件
→ 提交一次行动快照
→ 成功后发run_merchant_purchase_committed
```

失败码固定为`session_closed / offer_missing / stale_offer / insufficient_currency / inventory_full / inventory_rejected / save_failed`。任何失败都必须保持原魂、原背包、原货架和原撤离条件。
