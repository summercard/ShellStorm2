# 玩法系统｜局内商人 v0.1

交易与存档的跨功能目标规则先读[基地经济与存档结算设计](design/基地经济与存档结算设计.md)；本页保留局内商人专属玩法、现行r3货架与事务接口。两页冲突时区分已确定玩法与当前实现事实，不以施工现状自动改写目标。

功能ID：`RUN-MERCHANT`。状态：**[部分完成]**。适用游戏工程：`0.1.0`。设计修订：r3。更新日期：2026-09-24。

局内商人是行动内消费玩法。玩家进入商人服务点后，用本局魂购买该房间首次访问时确定的商品；成交物直接进入当前背包，首次成功交易可解锁交易条件撤离。本文区分当前运行行为与后续契约。

## 1. 当前功能

- 商人服务点由`Dungeon3D`打开动态`MerchantUI`，名称随当前玩法主题变化。
- `LootModule.generate_merchant_goods(tier, 6)`从`ItemRegistry`读取符合商人层级且价格为正的内容，再按蓝图Tier过滤。
- 每个商人房间本局最多生成6件商品，基础价格应用随机±10%浮动；武器先转换为具有唯一`weapon_instance_id`的完整实例。首开同步落档；关窗与读档不刷新未售货架。
- UI显示商品名、价格、魂余额、武器实例尾号与命运槽摘要；只发购买命令，不直接写魂或背包。
- `RunMerchantService`检查会话、offer、武器实例、背包容量和魂；成功后完整物品入包并移除 offer，同步行动快照失败则回滚。
- 成功交易由`Dungeon3D`解锁`TRADE`条件撤离；关闭面板后会话失效并恢复玩家输入。

## 2. 所有者与数据链

| 状态 | 当前所有者 |
|---|---|
| 本局魂 | `GameManager.currency`，`Dungeon3D`同步行动价值与自动快照 |
| 当前背包 | 行动`InventoryModule` |
| 商品候选 | `ItemRegistry`与`LootModule` |
| 本局商人货架 | `RunMerchantService._stocks[merchant_id]`；当前会话的`_offers`为可购买副本，`MerchantUI`只保存展示快照 |
| 交易撤离条件 | `Dungeon3D._trade_extraction_unlocked` |

正式链路为`ServiceStation3D → Dungeon3D → LootModule → RunMerchantService → GameManager/InventoryModule → 同步行动快照与撤离条件 → MerchantUI展示`。商品视觉和UI不得另建物品定义或价格表。

## 3. 当前命令、事件和失败语义

| 类型 | 接口 | 当前语义 |
|---|---|---|
| 命令 | `RunMerchantService.open_session(session_id, merchant_id, goods)` | 首开建立并保存最多6件货架；重开读取原货架，返回只读快照 |
| 命令 | `purchase(session_id, offer_id, weapon_instance_id, ...)` | 校验→扣魂→入包→移除报价→同步保存；失败回滚 |
| 事件 | `MerchantUI.purchase_command_requested(...)` | 只提交购买意图，场景消费成功结果后刷新 UI |
| 事件 | `merchant_closed()` | 关闭会话并恢复输入 |
| 查询 | `ItemRegistry.get_merchant_goods(tier)` | 返回层级允许、价格为正的候选 |

购买由服务协调并同步提交行动快照；失败或重复请求不会二次扣款，武器实例对当前背包、保险、快捷栏、装备位及地面物做所有权检查。r3 已把同一局货架扩展为按房间持久化的行动状态；旧档缺货架字段可首次生成，坏货架字段拒绝交易。

## 4. 目标事务

```text
purchase_run_merchant_item(session_id, offer_id, inventory_revision)
→ 校验会话、货架实例、价格、余额和容量
→ 在副本中扣魂、转移完整物品实例、移除offer并设置交易条件
→ 提交一次行动快照
→ 成功后发run_merchant_purchase_committed
```

失败码固定为`session_closed / offer_missing / stale_offer / insufficient_currency / inventory_full / inventory_rejected / save_failed`。任何失败都必须保持原魂、原背包、原货架和原撤离条件。

### 4.1 当前施工接口（RUN-MERCHANT r2）

`RunMerchantService` 是会话货架的唯一写者；`MerchantUI` 只展示 `get_offers_snapshot()` 与发出 `purchase_command_requested(session_id, offer_id, weapon_instance_id)`。`Dungeon3D` 持有服务并注入本局 `InventoryModule`、`GameManager` 和同步存档回调，成功后设置交易撤离条件并刷新 UI。货币余额的唯一写者仍是 `GameManager`，格位的唯一写者仍是 `InventoryModule`；服务只协调一次跨域转移。

| 字段 | 规则 |
|---|---|
| `session_id` / `offer_id` | 一次打开生成一个临时会话；`offer_id`以房间ID和货位编号稳定标识报价。关窗后旧会话命令失效，重开/重载不改变未售报价。 |
| `weapon_instance_id` | 武器报价和成交必须使用同一完整实例；调用方提交预期 ID，若与货架不符返回 `stale_offer`。普通物品为空。 |
| `purchase(...)` | 先校验会话、报价、价格、余额、格位/已有堆叠空间与实例唯一性；再扣魂、完整入包、移出 offer、同步提交行动快照。成功返回 `{success, code, item, offer_id, session_id}`；失败返回 `{success:false, code}`。 |
| 回滚 | `inventory_rejected` 或 `save_failed` 时恢复原格位、魂、offer 和撤离条件；失败不发成交事件。`Dungeon3D` 的同步回调负责在保存前暂置撤离条件，保存失败时恢复。 |

r2 的行动快照曾不保存未购买货架；r3 已由下节规则替换，不能再按旧行为实现。

### 4.2 同一局货架持久化（RUN-MERCHANT r3）

参考同类局内商店的“商店是本局关卡状态”口径：Shattered Pixel Dungeon 在关卡生成时加入商店房，并将关卡物品堆保存到关卡存档；本项目据此选择“同一局同一商人货架不因关窗或重载刷新”，而不照搬其具体关卡结构。来源：[商店房生成](https://github.com/00-Evan/shattered-pixel-dungeon/blob/master/core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/levels/RegularLevel.java)、[关卡物品堆保存](https://github.com/00-Evan/shattered-pixel-dungeon/blob/master/core/src/main/java/com/shatteredpixel/shatteredpixeldungeon/levels/Level.java)。这是本项目对用户“参考其他游戏”的工程裁决，不声称所有同类游戏都这样实现。

| 契约 | r3 规则 |
|---|---|
| 货架所有权 | `RunMerchantService` 按稳定 `merchant_id = room_id` 持有本局各商人货架；同一房间当前只有一个商人站。UI会话是临时命令通道，关窗只关闭会话，不清货架。 |
| 首次生成 | 首次打开该房商人时抽商品、计算浮动价格、生成武器实例和稳定 `offer_id`，在展示/允许购买前同步保存整份行动快照。首次写盘失败则恢复未开货架状态并拒绝打开，不能靠重进刷新已展示报价。 |
| 后续打开/重载 | 关窗重开或读档后展示同一批未成交报价、同一价格和 `weapon_instance_id`。已售 `offer_id` 保持缺席；售罄后显示空货架，不再抽新货。只有新的行动/新 `run_id` 才有新货架。 |
| 存档 schema | 行动快照新增 `merchant_stock = {schema:"run_merchant_stock_v1", stocks:{merchant_id:[{offer_id,item}]}}`；每个 offer 保留完整物品实例。旧档缺字段视为该行动尚未见过商人，可首次生成；字段存在但 schema/实例/报价无效时拒绝本行动的商人交易，不静默重抽。 |
| 成交与幂等 | 临时 `session_id` 每次打开都不同，旧会话命令无效；稳定 `offer_id` 从货架移除，和扣魂、入包、交易撤离条件在同一行动快照写盘。失败时恢复四者；重载后重复旧命令因旧会话或已售 offer 被拒绝，不能复制物品。 |
| 验收 | 首开写盘失败、关窗重开不刷新、未买报价跨重载相同、买后重载缺席且所有权仅一份、购买写盘失败可重试、错误库存快照拒绝、旧档首次打开可生成。 |
