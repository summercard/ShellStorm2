## 1. 职责与边界

玩家系统拥有输入意图、移动、生命、顶层状态、临时覆盖状态、交互许可和武器操作桥。武器数值属于战斗系统；墙、地砖和门坐标属于关卡系统；存档和死亡结算属于系统 7。

<span style="color:#1565C0">**[用户设计]** 玩家只持有当前装备枪械的实例引用，不拥有枪械构筑。角色作用域命运卡可以改变本局角色规则，但武器作用域卡、配件和强化道具不得把构筑写入玩家属性。</span>

<span style="color:#2E7D32">**[已实装并验收]** 正式 `Player3D` 与兼容 `Player` 均通过完整物品字典装备 `WeaponInstance`，运行时装配树只从实例投影；卸装前会同步弹药与装配快照，武器命运升级写回实例，角色/世界命运状态不占枪槽。</span>

## 2. 当前结构

- <span style="color:#2E7D32">**[已实装]** `Player3D` 是正式玩法根，`PlayerAvatar3D` 是视觉装配根，独立胶囊负责角色碰撞。</span>
- <span style="color:#2E7D32">**[已实装]** 顶层状态：`idle / moving / dashing / hurt / locked / falling / landing / dead`。</span>
- <span style="color:#2E7D32">**[已实装]** 覆盖状态：`low_health / silenced / invincible / reloading / firing / charging / knockback`。</span>
- <span style="color:#2E7D32">**[已实装]** 基线：移动 5.0m/s；冲刺 16.5m/s、0.204s、冷却 2.2s；冲刺无敌 0.24s；生命 100。</span>
- <span style="color:#2E7D32">**[已实装]** 玩家前向主灯、环境溢光和角色柔光不对玩家自身产生阴影；太阳与室内灯正常照射玩家并投影。</span>

## 3. 输入动作契约

| 动作 | 默认输入 | 发送意图 | 拒绝条件示例 |
|---|---|---|---|
| 移动 | WASD / 方向键 / 移动摇杆 | `move(Vector2)` | `locked`、`dead` |
| 瞄准 | 鼠标 / 右摇杆 | `aim(Vector2/Vector3)` | `dead` |
| 开火 | 鼠标左键 / 射击按钮 | `fire_pressed/released` | `silenced`、`locked`、`dead` |
| 技能 | 鼠标右键 / 技能按钮 | `skill` | 冷却、`locked`、`dead` |
| 冲刺 | Shift / 冲刺按钮 | `dash` | 冷却、`hurt`、`locked`、`dead` |
| 交互 | E / Space | `interact` | 无目标、模态 UI、`dead` |
| 换弹 | R | `reload` | 满弹、正在换弹、`dead` |
| 背包 | I / Tab | `inventory` | 不允许打开的过渡状态 |
| 主/副武器 | 1 / 2 | `select_weapon_slot(0/1)` | 目标槽空、死亡、独占模态 UI |
| 快捷物品 | 3 / 4 | `use_quick_item(0/1)` | 未绑定、数量为0、当前状态不允许使用 |
| 楼层大地图 | M | `toggle_floor_map` | 其他独占模态 UI |
| 探照灯 | F | `toggle_flashlight` | `dead` 或场景禁用 |
| 暂停 | Esc | `pause` | 由全局暂停栈裁决 |

<span style="color:#EF6C00">**[Codex补充]** 键鼠和触屏适配器不得直接调用冲刺、开火或交互实现，只能提交上表意图；这样回放、AI 控制、无障碍映射和自动测试可以复用同一入口。</span>

### 3.1 双武器与快捷物品新契约（2026-08-06）

<span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 玩家拥有主武器与副武器两个独立实例槽；左槽为主武器、右槽为副武器。只有当前激活槽投影到运行时装配树，另一把枪保持完整 `WeaponInstance`、弹药和命运槽数据。背部收纳使用两个独立语义挂点：主武器槽0固定在角色背部左侧，副武器槽1固定在右侧；切枪后未激活枪回到所属挂点，枪模 `local -Z` 枪口轴统一朝向世界下方。</span>

<span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 快捷物品槽只绑定可主动使用的物品 ID，不把物品移出背包。整理、堆叠或换位不会失效；按3/4时从背包消耗1个对应物品，只有效果成功后才扣除数量。空槽不创建3D预览，绑定后才复用背包的同源模型图标。</span>

### 3.2 背包快捷键与模态状态契约（2026-08-06回归修复）

<span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** `I` 是正式背包主快捷键，塔楼场景同时接受 `Tab`。一次有效按下只允许切换一次；键盘长按产生的 `echo` 重复事件必须忽略，不能造成“刚打开又关闭”。打开后 `InventoryUI.inventory_open_changed(true)` 锁定玩家移动、开火和场景交互；再次按 `I/Tab` 或关闭界面后发出 `false` 并只解除背包来源的输入锁。</span>

<span style="color:#EF6C00">**[Codex补充]** 背包专项不得再直接调用 `set_inventory_panel_open(true)` 代替输入验收；必须通过真实 `InputEventKey` 覆盖按下、长按重复、释放、二次关闭及玩家锁恢复。物品格点击同样必须走按下+释放完整生命周期，避免拖拽协议变化后出现“自动化通过、玩家点不动”。</span>

### 3.3 背包装备位与背部表现（2026-08-06）

<span style="color:#1565C0">**[用户设计]** 角色装备栏增加独立背包槽，只接受 `type=equipment / subtype=backpack`。背包物品从普通格左键或拖入即装备；装备中的背包可拖回空格、拖入丢弃区或拖出界面。容量降低造成的溢出物必须落在角色当前房间，而不是被删除。</span>

角色视觉根增加稳定语义挂点 `BackpackSocket`，位于背部中央并与左右 `StowedWeaponSocketPrimary/Secondary` 分离。装备状态通过 `backpack_equipment_changed` 同步到该挂点；2/4/8格背包使用同源内容ID但不同体积、配色和附袋数量的代码Mesh占位。替换正式美术时只替换挂点子场景，不改变背包容量与物品事务代码。

<span style="color:#2E7D32">**[已实装并验收｜2026-08-06]** 正式角色与备用角色视觉场景均已增加 `BackpackSocket`；装备背包后由 `Player3D` 在该挂点生成同源代码Mesh，卸下时移除。装备页背包槽、左键/拖拽装备、拖回基础格、拖到地面、12+2/4/8动态容量和扩展格异色边框均已接入。</span>

## 4. 状态机施工约束

1. 每帧只有一个顶层状态拥有移动决策权。
2. 状态转换使用 `request_transition(target, reason, context)`；转换成功发出 `player_state_changed`。
3. `dead` 只能由生命系统进入，由结算/复活系统批准退出。
4. `locked` 必须携带锁来源；同一来源解除时不能清除其他模态锁。
5. `falling → landing` 只处理落地动作，不执行死亡、楼层切换或存档。
6. 换弹和蓄力是覆盖状态；冲刺是否取消它们由战斗策略明确返回。

## 5. 与其他系统的接口

| 接口 | 方向 | 内容 |
|---|---|---|
| `WeaponCommandPort` | 玩家 → 战斗 | 瞄准、开火、蓄力、换弹 |
| `InteractionQuery` | 玩家 → 场景 | 当前候选、距离、优先级、提示文本 |
| `DamageReceiver` | 战斗/环境 → 玩家 | 伤害、来源、方向、类型、击退 |
| `PlayerPresentationState` | 玩家 → UI/动画 | 顶层状态、覆盖层、生命、弹药摘要 |
| `DeathRequest` | 玩家 → 结算 | 死亡原因、位置、行动快照 ID |
| `RevivalResult` | 结算 → 玩家 | 是否复活、位置、生命比例、无敌时间 |
| `TransitionOccupancySnapshot` | 玩家 → 关卡生命周期 | 角色完整碰撞体是否已离开门夹区并进入隔离间；只报告位置事实，不开门或卸载楼层 |

到达门生成和隔离区段提交期间，玩家可以在安全侧移动，但同一门的重复交互、拾取/丢弃和跨门冲刺由关卡事务明确锁定。不得把玩家设为无碰撞或瞬移穿门来掩盖生成等待。

## 6. 相机、墙体与灯光边界

- <span style="color:#2E7D32">**[已实装]** 塔内固定斜俯视相机使用墙体专用查询层检测角色与镜头后方的满高墙。</span>
- <span style="color:#2E7D32">**[已实装]** 玩家贴近需要交互的水平墙时，相机会抬升和向墙内侧收回；墙体 Mesh 本身保持不透明。</span>
- <span style="color:#EF6C00">**[Codex补充]** 玩家系统只提供位置、朝向和遮挡目标，不识别“南墙/门墙/楼梯墙”；是否属于相机墙由关卡组件元数据决定。</span>
- <span style="color:#EF6C00">**[Codex补充]** 随身灯的自投影隔离必须基于渲染层，而不是运行时关闭玩家 Mesh 阴影；否则太阳和室内灯也会失去玩家投影。</span>

## 7. 施工阶段

1. 固定输入意图接口，清除 UI 和场景对玩家内部方法的直接调用。
2. 为状态转换增加原因码与调试快照。
3. 将交互候选选择收敛为一个查询服务，解决门、灯开关和设施抢输入。
4. 将死亡退出与复活入口交给系统 7。
5. 为键鼠、移动端、暂停、贴墙相机和三灯掩码建立回归测试。

## 8. 验收标准

- [ ] 八个顶层状态均有合法进入、退出和非法转换测试。
- [ ] 键鼠与移动端对相同意图产生相同状态结果。
- [ ] 门和灯开关同时在范围内时，只执行优先级最高的一项。
- [ ] 冲刺无敌、受击、击退、换弹和蓄力不会制造双顶层状态。
- [ ] 死亡后移动、开火、交互全部失效，结算只触发一次。
- [ ] 复活接口未启用时，当前死亡规则完全不变。
- [ ] 玩家随身三灯不产生玩家自身阴影，太阳和房间灯仍产生正常玩家阴影。
- [ ] 普通墙、拐角墙、门墙、楼梯墙的相机行为由组件标签统一驱动。
- [ ] 角色完全贴墙时相机不穿过墙体，离开后平滑恢复。
- [ ] 替换 `PlayerAvatar3D` Mesh 不改变碰撞、移动和武器命中。
- [ ] 隔离间只在玩家完整碰撞体进入且离开门夹区后关闭后门；冲刺、击退、死亡或暂停不会造成双门同开或角色夹门。
- [x] I/Tab真实按键打开背包，长按重复事件不反向关闭；打开/关闭与玩家输入锁成对恢复。
