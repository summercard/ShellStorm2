# 参考文档区

> **这里放的是"外部作品的公开资料整理"，不是本工程的设计。**
> 本区的任何文字都**不构成** ShellStorm2 的设计依据或验收标准；
> 它只在写设计页时作为**对照样本**被引用（例如"这个数字来自哪"）。
> 一旦与本工程设计页冲突，**一律以设计页为准**。

## 归属与红线

| 项 | 规则 |
|---|---|
| 目录性质 | 只读资料区。文件进来之后**不再随本工程演进修改**，修的是"引用它的设计页" |
| 权威性 | **无**。本区无任何 FeatureID，不进 `MODULE_INDEX`，不参与 `feature_registry.json` |
| 可执行性 | **无**。不含代码、不含数据源、不被 `data/` 或 `src/` 引用 |
| 与账本的关系 | 与本工程的资产账本**完全无关**，不得用于登记任何 AssetID |
| 收录标准 | 要么是**公开可核的原始来源**，要么是标注了"哪几条待核"的整理稿 |

## 为什么不放 `docs/art/` 也不放 `audits/`

- `docs/art/` 是**本工程资产批次的验收证据**，每一条都要能追到自己的 AssetID；外部作品的资料进去会污染这条链。
- `docs/v0.1/audits/` 是**本工程某一时点的自检结论**，带日期、带结论；参考资料的定位相反 —— 它不评判本工程。
- 因此单开 `reference/`：**只被引用，不被引用为证据。**

## 原始抓取存档不放这里

网页原文、PDF 原件、转码中间产物属于**过程产物**，按[工作区与目录规范](../../WORKSPACE_LAYOUT.md) §4 放工程外。
本区只收**已整理成可读形态**的成品页；需要复核原文时，按成品页里记的来源地址回去找。

## 为什么这里有个 `.gdignore`

本区加了 `.gdignore`，Godot **不会**导入这里的任何文件。理由不是洁癖，是实测后果：

| 不加会怎样 | 实测 |
|---|---|
| 28 张 PNG 各生成一个 `.import` | 29 个文件 + 约 2.4 MB 纹理缓存进 `.godot/imported/` |
| **CSV 被当成翻译表** | 生成 12 个 `flow清单.<列名>.translation`（`BOSS系列` / `HUB` / `NORMAL` …） |

第二条是陷阱：**往项目里丢一个中文列名的 CSV，Godot 会无声地给工程塞进一批翻译资源**。
而这些图片与 CSV 运行时永远不会被加载（图集是浏览器直接打开的 HTML）。

代价是本目录的图片在 Godot 资源面板里看不到 —— 属预期，用文本编辑器或浏览器查看即可。
