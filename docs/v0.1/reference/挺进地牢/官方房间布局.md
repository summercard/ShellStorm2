### 2.1 一个关键判断：为什么"越全"有硬上限

官方从未公开房间模板本体。能公开的只有**玩家截图**，而截图有两个天然限制：

1. **只有"值得截图"的房间**才会被拍 —— 普通战斗房没人一张张截。
2. **没人知道总数**。Boris 反编译看到的是 "nearly 300 for the first stage"，**他自己也没列清单**。

所以"越全越好"的正确理解是：**把公开渠道挖到底，然后如实报告缺口**，而不是拼凑一个看起来完整的假清单。

## 3. 缺什么（明确列，不含糊）

| 缺什么 | 影响 |
|---|---|
| 第一层 ~300 个模板的**绝大多数** | 只有 16 间有图（约 5%） |
| 第二~五层的**任何**布局图 | 一层都没有 |
| 每个房间的**格数尺寸** | 无。截图带 UI 裁切，格宽换算不整除，无法反推 |
| 每个房间的**门朝向集合** | 无。图上能看门在哪面，但无法确证是模板固有还是这一局开的 |
| **模板 ↔ 骨架节点**的对应关系 | 无。不知道哪张骨架用了哪些模板 |

> 前两项是**资料不存在**；后三项是**资料存在但没公开**。两种缺口的处理方式不同：
> 前者只能自己做（这也是远征03 要自己出 9 份 TSCN 的原因），后者只能猜或不猜。

## 4. 这批图的实际用途

### 4.1 能用的：隐藏房那 11 张

它们是**全分辨率**，能读出四件事：

1. **房间的构图套路** —— 中央岛 + 环绕坑 + 四周陈设，这套语言在 001/002/003/006/007 里高度一致
2. **地砖与墙面的接法** —— 墙内侧一圈深色石砖、地板分块、坑是绿色岩浆质感
3. **陈设密度** —— 角落放桶/罐，中央放宝箱或拾取物，**留出大片空地**
4. **陷阱的摆法** —— 006/007 的火焰陷阱按棋盘格交替，不是随机撒

### 4.2 不能用的：第一层那 28 张

分辨率太低。硬要放大只会得到马赛克，**不要**拿它去推"这个房间有几格"。

## 5. 对远征03 的直接结论

**这批图不能替代自己做房间，只能当视觉参考。**

| 要做的 9 份 TSCN | 能不能照这批图做 |
|---|---|
| `rt_safe_15x15` 入口 | ❌ 无对应图 |
| `rt_extraction_25x25` 撤离 | ❌ 无对应图 |
| `rt_boss_50x40` 首领 | 🟨 有 3 张 Boss 房缩略图，只能看轮廓 |
| `rt_std_25x25` 前厅/连接房/战斗房 | 🟨 有普通房缩略图，看不清做法 |
| `rt_db_70x50` 宝箱房 ×2 | 🟨 有 3 张宝箱房缩略图（棕/蓝/绿），构图可参考 |
| `rt_office_60x70` 商店 | ❌ 无 |
| `rt_corridor_45x40` 枢纽 ×2 | 🟨 有走廊缩略图，只能确认"窄长" |

**结论**：这批资料的价值是**校准风格**（配色、陈设密度、墙地关系），不是**提供几何**。
9 份 TSCN 仍然必须按 ShellStorm2 自己的组件体系手工做。
