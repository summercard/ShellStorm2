# 挺进地牢 · 房型种类（56 种）

本页回答一个具体问题：**官方的房间谱到底有多少「种」**，以及这 56 种白盒是怎么定出来的。

配套：[EGT房型种类.csv](EGT房型种类.csv)（551 个房间位逐条）、
[房型白盒图集](../../../art/egt_room_types/index.html)（56 张俯视图）。

---

## 1. 「种」的口径：房型 × 门面组合

房间的「种类」不能只按房型名分，因为同一个房型会有不同的开口方式。本页的口径是：

> **一种 = (房型 kind, 门开在哪几面 + 每面几扇)**

按这个口径，官方 5 层共 **56 种**。

### 1.1 数据来源

`scripts/extract_egt_room_types.py` 读官方 flow 骨架图 PDF：

| 项 | 值 |
|---|---|
| PDF 张数 | **28**（第一层 6、第二层 8、第三层 5、第四层 4、第五层 5） |
| 覆盖楼层 | 1~5 层**全部** |
| 房间位 | **551** |
| 提取方式 | 矩形图元 = 房间框；贝塞尔曲线首尾 = 连线；12pt 内配对 |
| 门面判定 | 比较两房矩形中心，\|dx\|≥\|dy\| 为东西向，否则南北向 |

### 1.2 自检：28/28 通过

每张骨架都验了一条硬约束：**门面总数必须等于该房的边数**（一个门面一扇门）。
28 张全部通过，且有 `unmatched=0`（没有配不上房间的连线）。

> 第一版这里报过 28 张全红。原因不是数据错，是我的统计错：**同一面墙可以有两扇门**
> （一间房南墙接两个子房），我用 `set` 存门面，把重复的门面吃掉了。
> 改成按「每面几扇」计数（`Counter`）后自检全绿。这是真实房型，不能丢。

## 2. 56 种的分布

| 房型 | 种数 | 实测房间位 | 尺寸区间 | 门数区间 |
|---|---:|---:|---|---|
| 战斗房 `NORMAL` | **18** | 273 | 25×20 | 1~4 |
| 枢纽房 `HUB` | **11** | 44 | 30×25 | 3~5 |
| 商店 `SHOP` | 6 | 23 | 20×15 | 1~2 |
| 宝箱房 `REWARD` | 5 | 58 | 15×15 / 20×15 | 1~2 |
| 连接房 `CONNECTOR` | 4 | 30 | 10×20 | 2~3 |
| 入口 `ENTRANCE` | 4 | 28 | 15×15 / 20×15 | 1~3 |
| 特殊房 `SPECIAL` | 3 | 11 | 15×15 | 1~2 |
| 首领前厅 `BOSS_FOYER` | 2 | 28 | 25×20 | 2 |
| 出口 `EXIT` | 2 | 28 | 15×15 | 1~2 |
| 首领房 `BOSS` | 1 | 28 | 50×40 | 2 |
| **合计** | **56** | **551** | | |

**两条值得注意的分布事实：**

- **战斗房 18 种占了一半种类**（273/551 = 50% 的房间位）。要做「每局不重样」，
  优先扩的就是这一档。
- **首领房只有 1 种**：`N1S1`，28 次出现（每层 1 次，5 层合计 28 次跨 flow）。
  也就是说首领房永远是「南北各一门、正对」。

## 3. 尺寸是推定值 —— 这条必须说清楚

**我拿不到 EGT 的真实格数。** 试过三条路都不成立（详见 CHANGELOG 2026-10-27）：

1. Wiki 布局页：wiki.gg 那页 100% 是 `Example` 占位；
2. 从截图反推：公开截图是**带透视的渲染图**，自相关测出 30/48/60/63 四个互相矛盾的周期，
   格点拟合不收敛；
3. 官方房间模板本体：从未公开。

所以白盒尺寸由**规则**推出，不是从 EGT 量的：

### 3.1 规则

```
宽 = 从房型基准宽起，逐格 +1，直到 该墙的合法门槽数 >= 该面门的最大数
深 = 同理
```

其中 `合法门槽数(格数)` 与 `RoomDoorLane.lane_offsets()` 同源：
**首尾各留一格不贴角** ⇒ 格数 ≥3 时槽数 = 格数 − 2，否则等于格数。

### 3.2 这里有个坑：`slot_count` 不是单调的

| 格数 | 槽数 |
|---:|---:|
| 2 | **2** |
| 3 | **1** |
| 4 | 2 |
| 5 | 3 |
| 7 | 5 |

**3 格反而比 2 格少一个槽。** 所以不能用「按公式反解最小格数」，必须逐格往上搜。

生成器第一版就是按公式反解写的，产出了「宝箱房 3 格北墙放 2 扇门」的坏房，
被生成期断言拦下来了：

```
AssertionError: REWARD/N2: 宽 3 格只有 1 槽，放不下 north 的 2 门
```

这条断言留在代码里，以后改基准尺寸会再拦一次。

### 3.3 房型基准尺寸

只有三条有原文依据，其余是**用途推定**：

| 房型 | 基准 | 依据 |
|---|---|---|
| `HUB` | 6×5 格 | 原文："**larger** rooms with more exits" |
| `CONNECTOR` | 2×4 格 | 原文："**long, thin** rooms, so picking one with a sensible orientation is vital" |
| `BOSS` | 10×8 格 | 每层唯一、尺寸最大 |
| 其余 | 3×3 ~ 5×4 | 按用途给最小合理值（**推定**） |

每份 TSCN 的 `metadata/size_basis` 都写了这份房型的实际推导过程
（`base=… slots(w)=… slots(d)=… need=(…)`），可逐份复核。

## 4. 同侧多门：56 种里最容易被漏掉的一类

原版 EGT 的房型谱里，**97 处（17.6%）是「同一面墙开多扇门」**：

| 门面组合 | 次数 | 读作 |
|---|---:|---|
| `N1S2` | 35 | 北 1 扇、南 2 扇 |
| `N2` | 28 | 北 2 扇（宝箱房常见） |
| `S2` | 8 | 南 2 扇（入口/出口常见） |
| `N1S2W1` | 6 | 北 1、南 2、西 1 |
| `N2S1` / `N1S2E1` / `S2E1` / `S2W1` | 各 3 | 一侧双门 + 另一侧 |
| … | | |

这类房间如果按「门数分桶」做，会全部塌成 `2门` / `3门`，
**然后在对齐时发现放不进去** —— 因为 2 扇门要占 2 个槽，而墙只有 1 个槽。

白盒里它们的做法：在地面铺完后，按 `lane_offsets` 逐槽选位（优先靠中心、
相邻槽至少隔一个门洞），所以 `N2` 的门会分别落在 `-2.5` 和 `+2.5`（20m 墙）。

## 5. 与远征03 现有模板的关系

两套东西**不是替代关系**：

| | `room_instances/expedition_03/rt_*` | `room_instances/egt_room_types/egt_*` |
|---|---|---|
| 来源 | ShellStorm2 自己的 8 个模板 | EGT 实测房型谱 |
| 数量 | 10（含 4 个非矩形变体） | 56（全部矩形） |
| 轮廓 | 有 L 形 / 凹形 / 缺角 / 工字 | 全矩形 |
| 用途 | 远征03 实际要用的壳 | 房型谱原型 / 美术与布局参考 |

非矩形轮廓是 ShellStorm2 自己的设计（远征01/02 已接入），EGT 的房间本身是矩形 ——
所以两套并存，不合并。
