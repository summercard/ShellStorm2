# 挺进地牢 · 小地图实现方式

整理时间：2026-10-28
状态：**外部作品资料整理**，不是本工程设计。与本工程设计冲突时以设计页为准。

---

## 0. 一句话

> **它不画图。每间房有一张自己的小地图贴图，游戏按世界坐标把贴图摆到固定缩放的平面上。**
> 玩家不动地图，地图不动玩家。房间是"贴上去"的，不是"算出来"的。

---

## 1. 三条结论先摆出来

| # | 结论 | 证据等级 |
|---|---|---|
| 1 | 房间在小地图上是**预制的位图贴图**，不是矢量绘制 | **高**（素材文件 + 实机像素级测量） |
| 2 | 缩放是**全局固定值**，不随探索范围自适应；有两个独立缩放参数（角落小图 / 全屏大图） | **高**（游戏控制台变量名被公开） |
| 3 | 地图**不跟随玩家居中**，是固定版图视图；已探索房间逐间出现在绝对坐标上 | **高**（多张实机截图复核） |

## 3. 呈现方法：位图拼图

### 3.1 每间房一张贴图

本地有 3 张原始贴图，尺寸互不相同：

| 文件 | 像素 | 内容 |
|---|---|---|
| `Room_One_mini.png` | 116 × 49 | 宽扁普通房，南北各 1 门 |
| `Green_Chest_Room_One_Chamber_One_minimap.png` | 79 × 65 | 近方宝箱房，北 1 门 |
| `POst_Boss_Room_Chamber_One_minimap.png` | 92 × 82 | Boss 房，南北各 1 门 |

**三张尺寸都不一样，长宽比也不同** —— 这一条就排除了"统一模板 + 拉伸"的做法：每张贴图是按房间真实长宽比单独出的。

### 3.2 配色（逐像素取色）

| 元素 | RGB | 说明 |
|---|---|---|
| 房间填充 | `(44, 50, 88)` ≈ `#2C3258` | 深蓝底，全房间统一 |
| 墙体描边 | `(192, 194, 192)` ≈ `#C0C2C0` | 浅灰白，**1px** |
| 未探索标记 `?` | 洋红 `#E838C8` | 只在已侦测但没进过的房间上 |
| 已清理 / 可传送 | 亮绿 `#7CE03C` | 弹夹状图标 |
| 锁定门 | 红 `#C81E28` | 横向 1px 红线压在两房之间 |
| Boss 房 | 金色骷髅 | 见 §4 |

> 底色只有一种，**没有任何房间类型着色** —— 房间类型完全靠图标区分，不靠底色。
> 这条和我们现在的做法相反：我们靠颜色区分房型，它靠图标。

### 3.3 几何规格（实机 480×270 原生测量）

用一张 2560×1600 的实机截图（Steam 社区 `s15`）降采样 5× 回到 480×270 后逐像素测量：

| 元素 | 实测值 | 备注 |
|---|---|---|
| 普通房 | **约 21–24 宽 × 22–28 高 px** | 含 1px 描边；长宽比跟房间真实尺寸走 |
| 宽房 | **约 40 × 20 px** | 横向大房 |
| Boss 房 | 约 36 × 35 px | 明显大于普通房 |
| 细长连接房 | 约 11 × 8 px / 14 × 28 px | `CONNECTOR` 那一类 |
| 房间间隙 | **约 4–6 px** | 这就是走廊的可见长度 |
| 走廊 / 连接线 | **1 px** 同色填充线 | 不是通道房间，就是一根线 |
| 门洞 | **2 px** 缺口 | 墙上直接断开，不画门扇 |
| 门角标 | 2 × 2 px 白色小方块，缺口两侧各一对 | "能连通"的视觉提示 |
| 图标 | **5–7 px** | 极小的像素图 |
| 地图右上锚点 | 距屏幕右边缘 **约 4 px**、上边缘约 4 px | 贴边 |
| 部分探索的地图（6 间房） | 约 **64 × 66 px** | 满层尺寸见待核项 |

> **量级参照**：一个普通房只有屏幕宽度的约 **4.5%**（21 / 480）。
> 整张地图最多占屏幕右上角一小块，远小于我们现在的 M 键全层地图。

> ⚠️ 这批数字来自**单张截图 + 逐像素判读**，精度约 ±1px，且受 JPEG 压缩影响。
> 它们的用途是给出**比例与观感基准**，不是可以直接当契约写死的常量。
> 想定精确值，必须实机调 `s_map_view_scale` 对比。

### 3.4 缩放：固定值，不自适应

游戏里有两个控制台变量，这是最硬的证据：

```
s_map_view_scale        ← 角落小地图缩放
s_map_view_scale_big    ← 全屏大地图缩放
s_minimap_path_density_small   ← 小图走廊点的疏密
s_minimap_path_density_big     ← 大图走廊点的疏密
```

可以得出四件事：

1. **角落小图和全屏大图是两个独立的缩放**，不是一套放大。
2. 缩放值**全局固定**，不因为"这层房间多"就缩小。
3. 存在 `path_density` 说明**走廊是画成点线的**，而密度可调。
4. 版本日志里有一条 `v1.0.6：Map zoom level will no longer reset each floor` —— 说明玩家改过的缩放会**跨层保留**。

### 3.5 地图不开跟随

实机截图复核：玩家站在地图左下那间房时，地图上其他房间的位置**没有移动**，玩家标记只是在那间房里移动。

所以它是**固定版图视图**：一张绝对坐标的平面图，房间逐间"点亮"。

## 4. 信息层：图标全表

### 4.3 NPCs —— 13 个

咀嚼者、铁匠、迷路冒险家、Cursula、枪王与仆从、Old Red、Trorc、Flynt、Winchester、Patches & Mendy、女巫、Synergrace、通用 NPC 图标。

### 4.4 Misc（杂项）

| 图标 | 含义 |
|---|---|
| 神龛 | 任意神龛 |
| 牢房 | 关着 NPC 的上锁牢房 |

### 4.5 图标的设计原则（读出来的，不是抄的）

1. **能用实物就用实物**：宝箱画箱子、钥匙画钥匙、弹药画弹药。玩家不需要图例。
2. **NPC 画脸**，不画感叹号。认脸比认符号快。
3. **一个房间可以叠多个图标** —— 有宝箱又有 NPC 就并排画。
4. **未探索只画问号**，不给任何提前信息。

## 5. 显示设置：三档

游戏提供 `Minimap Style` 三选一（字符串表已确认）：

| 选项 | 行为 |
|---|---|
| **Always**（总是显示） | 一直显示 |
| **Non-Combat**（战斗之外） | 战斗中隐藏，**房间清完自动恢复** |
| **Never**（从不显示） | 完全不画 |

> 默认档是 Non-Combat。所以"清完房间小地图重新出现"本身是一个**战斗结束的反馈信号**，
> 这一点被官方攻略和设计分析文都单独点出来过。

按 TAB（手柄是 Select/Touchpad）打开全屏地图：可悬停查看图标详情、悬停传送器高亮目的地连线。

## 6. 与本工程的差异

我们现在的 `src/ui/DungeonMinimap3D.gd` 是**矢量实时绘制**：

| 维度 | 挺进地牢 | 本工程现状 |
|---|---|---|
| 房间表示 | 每间一张预制位图贴图 | 读 `FloorPlan` 的矩形，实时画 4 条线段 |
| 走廊 | 1px 点线，密度可调 | 沿门槽画线段 |
| 房间类型 | **靠图标**，底色统一 | 靠线段颜色 / 高亮 |
| 缩放 | 全局固定，两个独立值 | 雷达模式按楼层 AABB 自适应；全图模式 fit-to-bounds |
| 跟随 | 不跟随 | 雷达模式跟随并居中（已隐藏） |
| 图标 | 20+ 种，见 §4 | 红点（敌人）+ 少量类型色 |

**不能照抄的地方（写清楚，避免后人误抄）**：

- 它的贴图是**美术资产**。我们 ~56 种房型 × 变体，如果每间出一张贴图，美术量按房间数线性膨胀，且模板一改贴图就过期。**我们只能矢量画，但可以把"每间房一个矩形 + 1px 描边 + 门缺口"的观感做到一模一样**。
- 它的图标是**逐物品类型**的。我们要先有稳定的图标资产表，才能上这一层。
- `path_density` 这类参数属于调参细节，不必第一天就做。

**可以而且应该照抄的**：

1. 底色统一、类型靠图标 —— 信息密度更高，且不会让整张图变成色块拼盘。
2. **固定缩放 + 右上贴边锚点 + 不跟随玩家**。
3. **三档显示设置**，默认"战斗之外"。
4. 房间用**真实长宽比**画（这条我们已有，见 05 §10）。
5. 未探索只给问号。

### 样张是怎么画的（供实现时对照）

```
画布        480 × 270（游戏原生逻辑分辨率）
锚点        右上角，距边 4px，整张图向左下生长
缩放        1:1 —— 1px 描边必须落在整像素上，不能用 0.88 这类小数
房间        填充 #2C3258 → 四边 1px #C0C2C0 → 门洞处断开 2px
门角标      缺口两侧各一个 2px 白块
走廊        1px 正交折线，两端落在门槽中心
图标        5–6px 点阵，居中偏下 6px（给玩家小像让位）
未探索      只画一个洋红问号，不画房间轮廓
```

> 样张里房间间隙取 5px、普通房取 21×28 —— 都是本文实测区间的中值。
> 它证明的是**这套规格画出来确实像**，不代表这些数字就是最终契约值。
