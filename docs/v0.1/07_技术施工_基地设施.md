## 1. 职责与边界

基地系统负责长期成长的操作入口：准备行动、处理带出物、解锁蓝图、管理保险、选择命运预兆、查看精英档案和进入训练/远征。设施场景只显示与交互，业务规则由独立服务处理，最终写入由存档系统执行。

## 3. 设施统一契约

99 层基地的美术摆放使用独立子场景 `assets/art/environments/base_facility_3d/runtime/env_base_facility_art_layout_top3d_v001.tscn`，并作为 `美术可编辑层/基地99层_美术布置层` 实例直接挂在 `scenes/TowerDescent3D.tscn` 中。美术人员打开塔楼主场景即可调整设施位置、装饰、局部灯光、阴影与 99 层电梯锚点；运行时 `TowerDescent3D` 隐藏编辑层并把实例桥接到生成的设施房间，稳定 `facility_id`、激活信号、电梯玩法、菜单和存档契约保持在原有代码层。

<span style="color:#1565C0">**[用户美术权威规则｜2026-08-13]** 塔楼主场景中每个基地设施手工保存的放大/缩小、旋转和位移均为最终摆放结果。运行时桥接只允许连接功能信号、刷新交互区和读取锚点；禁止恢复资产默认Transform、禁止自动朝向房间中心、禁止因导入前向轴判断而旋转模型。即使自动朝向检查认为设施背向房间，也必须保留作者值，由美术人员在主场景中决定正面。</span>

<span style="color:#EF6C00">**[Codex补充]** 每项设施实现以下领域接口。</span>

```text
FacilityDefinition
  facility_id
  display_name
  description
  action_kind(menu / scene / info)
  action_path
  legacy_building_type(optional)
  color

FacilityQuery
  get_availability(facility_id, profile_snapshot)
  get_summary(facility_id, profile_snapshot)
  get_snapshot(facility_id, profile_snapshot)

FacilityCommand
  validate(command, profile_snapshot)
  execute(command, transaction_context)
  return FacilityResult(success, changes, reason)
```

`BaseFacility3D` 只向`PlayerInteractionController3D`提供候选，并在被选中执行时发出设施 ID 和交互请求。`BaseWorld3D` 只打开对应 UI/场景并刷新摘要；它不能实现工坊、保险或精英档案规则。

基地普通设施的表现、实体阻挡和交互入口属于常驻场景合同：房间流送不得关闭设施根节点、`InteractionShape`或`StaticBody3D`。角色未进入Area时设施不提供候选；进入多个Area时由统一控制器按优先级和距离只选一个目标。阁楼与一楼之间的垂直距离由各设施自身交互盒自然隔离，不再增加全局“设施激活”状态。电梯因服务多个楼层，可继续依据访问房间启停其面板。

设施快照至少包含 `facility_id / display_name / description / available / availability_reason / action_kind / action_path / level / summary / attention`。管理终端与 3D 设施牌必须读取同一快照，不能分别维护名称和状态。

升级命令按“校验设施 → 校验资源 → 内存变更 → 单次原子存档”执行。若存档失败，资源和等级一起回滚并返回明确原因。

## 5. 设施专项要求

### 5.1 枪械工坊

读取 `武器` 表的蓝图 Tier 和资源成本。解锁后只改变长期蓝图许可；实际局内掉落由掉落服务根据许可过滤。

### 5.2 命运占卜屋

保存稳定命运卡 ID，而不是当前运行时 `fate_card_####`。行动开始消费预选后，要么成功注入本局，要么回滚到基地档。

78张塔罗迁移后，收藏数仍计78而不是156；每个收藏条目共用同一卡名与稳定ID，内部分别记录“正位已见 / 逆位已见”和对应解读。

### 5.3 保险柜

区分长期保险柜、单局保险格、下局待带入和撤离待处理四种集合。移动物品使用事务 ID，避免重复领取或同时存在于两个集合。

保险柜界面固定采用左右两组格子：左侧为长期保险柜；在99层行动基地，右侧必须直接绑定 I 键正在使用的同一个 `InventoryModule`，名称显示“当前背包（与I键一致）”，容量包含已装备背包扩展；只有独立主基地不存在行动库存时，右侧才回退为 `12` 格“下局带入”。每个物品必须占据可见格子，格子展示同源 3D 物品预览、名称、数量及实例摘要；空格也保留边框和序号。

<span style="color:#2E7D32">**[2026-08-31 容量修订]** 长期保险柜基础容量由2格提升为20格，设施等级仍在20格基础上追加；容量是运行时派生值，不改变`BaseData.vault_items`存档结构，旧档直接获得新基础容量。左栏改为4列滚动网格并明确显示“基础20格”。</span>

- 单击已占用格：自动转移至另一侧首个可用格；消耗品优先合并同 ID 未满堆叠。
- 拖拽已占用格到另一栏任意格：执行同一套转移规则；拖拽预览显示物品名称和来源。
- 目标容量不足时原物品保持原位并显示原因；同一集合内拖放不会复制物品。
- 99层当前背包的改变必须立即反映到 I 键界面；独立主基地“下局带入”中的物品在下一局开始时进入局内背包。保险柜物品跨局保存且不会自动带入。
- 枪械、背包等独立物品始终保留实例 ID 和完整构筑；药品等堆叠物品按 `stack_max` 合并，转移整组数量。

<span style="color:#2E7D32">**[已实装并验收]** 枪械已作为完整 `WeaponInstance` 在保险柜、下局待带入、撤离战利品与局内集合间移动；深拷贝与实例 ID 唯一性校验防止永久命运槽、弹药、子弹模块和配件丢失或复制。</span>

枪械工坊、保险柜和商店展示武器时必须同时显示枪型、实例短 ID、命运槽占用和当前装配，出售或丢弃前以实例 ID 二次确认。

<span style="color:#2E7D32">**[已实装基础表现]** 保险柜和商店已经显示实例短 ID、命运槽与装配摘要；保险柜出售采用同一实例二次点击确认。工坊并排比较、主动丢弃确认和更完整的来源拆分仍待增强。</span>

#### 商店界面

- 左栏“购买”：显示商品 3D 预览、名称、类型、购买价、`∞ 无限库存` 和购买去向；图标复用背包的 `ItemModelIcon3D`。每次点击购买一个，但成交后商品不会售罄，魂充足时可连续购买。
- 右栏“出售”：同时显示随身背包和保险柜中的可出售物品、来源、实例短 ID/数量、命运槽与装配摘要、出售价；枪械第一次点击进入确认，第二次才成交。
- 顶部固定显示购买货币“魂”和真实目标容量；99层购买直接进入当前 I 键背包，独立主基地购买进入下局带入，消耗品优先堆叠。容量不足时不扣魂，也不会静默改存保险柜。
- 主基地 HUD、99 层/战斗主 HUD 与贩卖机界面统一使用“魂”。局内拾取的魂在成功撤离后写入同一持久化余额；`extraction_points` 仅保留为旧档兼容字段名。
- `Esc` 或关闭按钮退出。成功交易后同时刷新资源、容量、两栏和设施牌摘要。
- 货架由数据库的 `基地商店上架 + 基地货架顺序` 决定；未上架、价格非法或内容 ID 缺失的条目必须隐藏并报告诊断。

#### 3D表现与空间约束

- 长方体机柜具有实体碰撞、深色金属外壳、青色发光顶牌、正面货窗/屏幕和橙色交互灯带。

## 9. 全界面统一设计语言（2026-08-07）

正式界面以主战斗HUD为唯一视觉母版，基地设施不得各自使用灰色默认控件。共享语言如下：

- 背景使用近黑深蓝分层；主要边框/标题使用霓虹青，交互成功使用薄荷绿，魂与价格使用金色，生命和丢弃/危险使用红色。
- 面板使用细描边、小圆角和克制外发光；按钮必须有同体系的正常、悬停、按下、禁用状态，并统一接入`ui_hover/ui_click`。
- 角色包裹采用左角色装备、右背包网格；主/副武器、背包装备、快捷物、普通物品和保险格均保持正方形图标格，格内只放模型、数量、短ID和必要状态。
- 自动贩卖机左右仍为购买/出售语义，但商品和当前背包都使用3列正方形图标商品卡；每张卡显示来源、类型、短摘要和单一主操作，购买目标始终明确为当前I键背包。
- 保险柜、工坊、工作台、占卜、命运收藏、怪物档案、关卡选择、暂停、商人、撤离等界面统一通过`UIPalette`和`UIStyleFactory`应用同一配色与控件状态，不复制颜色常量。
- <span style="color:#2E7D32">**[2026-08-31]** 通用面板、按钮、槽位以及保险柜遮罩的背景透明度统一约50%；边框、文字、物品模型与状态色不随底板一起变淡。</span>
