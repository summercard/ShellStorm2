## 1. 职责与边界

基地系统负责长期成长的操作入口：准备行动、处理带出物、解锁蓝图、管理保险、选择命运预兆、查看精英档案和进入训练/远征。设施场景只显示与交互，业务规则由独立服务处理，最终写入由存档系统执行。

## 3. 设施统一契约

<span style="color:#EF6C00">**[Codex补充]** 每项设施实现以下领域接口。</span>

```text
FacilityDefinition
  facility_id
  display_name
  description
  action_kind(menu / scene / info)
  action_path
  legacy_building_type(optional)
  color

FacilityQuery
  get_availability(facility_id, profile_snapshot)
  get_summary(facility_id, profile_snapshot)
  get_snapshot(facility_id, profile_snapshot)

FacilityCommand
  validate(command, profile_snapshot)
  execute(command, transaction_context)
  return FacilityResult(success, changes, reason)
```

`BaseFacility3D` 只发出设施 ID 和交互请求。`BaseWorld3D` 只打开对应 UI/场景并刷新摘要；它不能实现工坊、保险或精英档案规则。

设施快照至少包含 `facility_id / display_name / description / available / availability_reason / action_kind / action_path / level / summary / attention`。管理终端与 3D 设施牌必须读取同一快照，不能分别维护名称和状态。

升级命令按“校验设施 → 校验资源 → 内存变更 → 单次原子存档”执行。若存档失败，资源和等级一起回滚并返回明确原因。

## 5. 设施专项要求

### 5.1 枪械工坊

读取 `武器` 表的蓝图 Tier 和资源成本。解锁后只改变长期蓝图许可；实际局内掉落由掉落服务根据许可过滤。

### 5.2 命运占卜屋

保存稳定命运卡 ID，而不是当前运行时 `fate_card_####`。行动开始消费预选后，要么成功注入本局，要么回滚到基地档。

78张塔罗迁移后，收藏数仍计78而不是156；每个收藏条目共用同一卡名与稳定ID，内部分别记录“正位已见 / 逆位已见”和对应解读。

### 5.3 保险柜

区分长期保险柜、单局保险格、下局待带入和撤离待处理四种集合。移动物品使用事务 ID，避免重复领取或同时存在于两个集合。

保险柜界面固定采用左右两组格子：左侧为长期保险柜；在99层行动基地，右侧必须直接绑定 I 键正在使用的同一个 `InventoryModule`，名称显示“当前背包（与I键一致）”，容量包含已装备背包扩展；只有独立主基地不存在行动库存时，右侧才回退为 `12` 格“下局带入”。每个物品必须占据可见格子，格子展示同源 3D 物品预览、名称、数量及实例摘要；空格也保留边框和序号。

- 单击已占用格：自动转移至另一侧首个可用格；消耗品优先合并同 ID 未满堆叠。
- 拖拽已占用格到另一栏任意格：执行同一套转移规则；拖拽预览显示物品名称和来源。
- 目标容量不足时原物品保持原位并显示原因；同一集合内拖放不会复制物品。
- 99层当前背包的改变必须立即反映到 I 键界面；独立主基地“下局带入”中的物品在下一局开始时进入局内背包。保险柜物品跨局保存且不会自动带入。
- 枪械、背包等独立物品始终保留实例 ID 和完整构筑；药品等堆叠物品按 `stack_max` 合并，转移整组数量。

<span style="color:#2E7D32">**[已实装并验收]** 枪械已作为完整 `WeaponInstance` 在保险柜、下局待带入、撤离战利品与局内集合间移动；深拷贝与实例 ID 唯一性校验防止永久命运槽、弹药、子弹模块和配件丢失或复制。</span>

枪械工坊、保险柜和商店展示武器时必须同时显示枪型、实例短 ID、命运槽占用和当前装配，出售或丢弃前以实例 ID 二次确认。

<span style="color:#2E7D32">**[已实装基础表现]** 保险柜和商店已经显示实例短 ID、命运槽与装配摘要；保险柜出售采用同一实例二次点击确认。工坊并排比较、主动丢弃确认和更完整的来源拆分仍待增强。</span>

### 5.6 自动贩卖机

<span style="color:#1565C0">**[用户设计]** 自动贩卖机是正式基地设施，配套独立商店界面。机器采用基础网格和代码材质搭建的长方体，不使用图片；放在基地出口一侧墙边，正面朝向可行走区域，不阻挡出口、道路或其他设施交互范围。</span>

#### 商品与数据库对应

| `shop_entry_id` | `item_id` | 商品 | 基地购买价 | 基地出售价 | 库存 |
|---|---|---|---:|---:|---|
| `base_stock_pistol` | `weapon_pistol` | 豌豆手枪 | 70 | 35 | 无限 |
| `base_stock_shotgun` | `weapon_shotgun` | 散射喷壶 | 110 | 55 | 无限 |
| `base_stock_rifle` | `weapon_rifle` | 步枪 | 150 | 75 | 无限 |
| `base_stock_backpack_2` | `equipment_backpack_2` | 轻型腰包（+2格） | 55 | 28 | 无限 |
| `base_stock_health_potion` | `item_health_potion` | 治疗药水 | 40 | 20 | 无限 |

正式对应链为：`基地商店.shop_entry_id → 物品ID → ItemRegistry 静态定义 → item_instance_id → BaseData 所有权集合`。枪械在实例化时额外生成 `weapon_instance_id`，命运槽、弹药与配件跟随该枪保存。代码中的初始货架只能复刻数据库条目，不能另定价格。

#### 商店界面

- 左栏“购买”：显示商品 3D 预览、名称、类型、购买价、`∞ 无限库存` 和购买去向；图标复用背包的 `ItemModelIcon3D`。每次点击购买一个，但成交后商品不会售罄，基地币充足时可连续购买。
- 右栏“出售”：同时显示随身背包和保险柜中的可出售物品、来源、实例短 ID/数量、命运槽与装配摘要、出售价；枪械第一次点击进入确认，第二次才成交。
- 顶部固定显示购买货币“基地币”和真实目标容量；99层购买直接进入当前 I 键背包，独立主基地购买进入下局带入，消耗品优先堆叠。容量不足时不扣基地币，也不会静默改存保险柜。
- 主基地 HUD、99 层/战斗主 HUD 与贩卖机界面使用同一“基地币”名称和实时数值；局内临时“魂”仍为独立资源。
- `Esc` 或关闭按钮退出。成功交易后同时刷新资源、容量、两栏和设施牌摘要。
- 货架由数据库的 `基地商店上架 + 基地货架顺序` 决定；未上架、价格非法或内容 ID 缺失的条目必须隐藏并报告诊断。

#### 3D表现与空间约束

- 长方体机柜具有实体碰撞、深色金属外壳、青色发光顶牌、正面货窗/屏幕和橙色交互灯带。
- 模型根遵循 `BaseFacility3D` 契约，业务仍只通过 `facility_id=base_vending` 进入，不把交易逻辑写进模型脚本。
- 基地世界部署在出口墙边，机器包围盒与墙保持可见间距，交互区仅覆盖正面；导航验证保证玩家可以站在正面并顺利离开基地。
