# 暗门破板：木块飞溅特效（FX01-33）

**日期**：2026-10-19
**业主口径**：「做一个门被打碎的木头飞出来的特效，**大块一点**的，做完带入然后更新账本」

---

## 1. 要解决的是什么

暗门木板被打掉时，原来的表现只有一条 `Tween`：整体放大 4% 再缩到 0.01 —— 板子「瘪掉消失」，没有「被打碎」的力道。玩家读完 60+ 血的木板后，得到的反馈是一块板默默缩小。

要的是：**木板崩成几大块飞出来，砸在地上**。

「大块一点」是这条诉求的关键约束 —— 不是加一堆小粒子，而是**少量、体积明显**的木片。

## 3. 件数与尺寸（「大块」的量化）

| 类 | 数量 | 尺寸（米） |
|---|---|---|
| 大碎片 `Chunk*` | 8 | `0.36~0.58`（长）× `0.16~0.26`（宽）× `0.07~0.10`（厚） |
| 小碎屑 `Splinter*` | 5 | `0.045~0.085` 边长，长宽比 1.6 |

参照物：门板 `2.38 × 2.51m`、木板厚 `0.139m` ⇒ 单片最长边是门宽的 **1/6 ~ 1/4**，读作「这块板被砸断了」。

**为什么是双向断言**：第一版验收只写了「最大单片 ≥ 0.30m」。而把尺寸乘错、13 片全变成 1m 大方块（比门板还大）时，`1.0 ≥ 0.30` 照样绿 —— 是后来补的**上限 0.65m** 把它抓出来的（见 §6 坑 1）。**凡是「尺寸落在某区间」的定档，断言必须双向。**

## 4. 运动与灯

**抛出物同族**（与 §5.5 弹壳一致）：一次性取得初速度后自己积分，**不绑 `context.follow`**（绑了就永远跟着门不落地）、Prefab 无碰撞体、落地用**解析式越线**判定、不接物理引擎。

```
props 出生（门板内 x∈±0.85、y∈0.30~2.10）
  → 抛物飞行（前向 1.7~3.4 m/s，抬升 1.3~2.9 m/s，侧向 ±1.5）
  → 触地：法向 ×0.26、切向 ×0.52、自旋 ×0.62，最多弹 1 次
  → 贴地滑行：v(t) = v0·e^(−5.2t)
  → 放平静止（长轴投到水平面）
寿命 2.85s
```

实测：最后一枚约 `1.15s` 静止 ⇒ 停放约 `1.7s`。

**灯 `DebrisLight`**：峰值 `1.5`、范围 `3.6m × size`、无阴影、**0.55s 归零**。塔内是夜间光（`room_03` 子树里 `Light3D` 数量 = 0），不带灯碎块一出框就是全黑。0.55s 后保持 0 到寿命结束，回收时显式再置 0（池复借不留长明灯）。

**材质**：木质 `metallic=0.0` / `roughness=0.86`（PER_PIXEL 受光）+ **自发光 0.38**。两档色阶（板面深 / 断口浅 `+0.18`）逐片交替，一排碎片有「新断口与旧板面」的层次。

## 5. 接线

```gdscript
# SecretDoor3D._break_open() 里，拆木板之前
pool.acquire(
    VfxPool3D.FX01_BOARD_DEBRIS,
    global_position,
    panel_color,
    BOARD_DEBRIS_EFFECT_SIZE,
    {
        "forward": -global_basis.z,      # 门局部 -Z = 房间侧
        "floor_y": global_position.y,    # 门原点契约 = 墙底地面点
        "seed": Time.get_ticks_usec() & 0x7FFFFFFF,
    }
)
```

三条约定：

1. **`floor_y` 取门自己的世界 y，绝不以 0 兜底** —— 塔楼楼层向下建（98F ≈ −1176m），给 0 会让碎块第一帧就「触地」并被夹到世界原点附近，看起来像「特效没出来」。这与 14.6 §5.5.2 弹壳那个 P0 同源。
2. **随机化只活在调用方** —— 脚本内没有 `randf()`，每一片的尺寸/出生点/初速/自旋/初始姿态都由 `context.seed` 经确定性散列派生。同 seed 逐位可复现（验收靠它做重放对照），每次破板不同 seed 就散得不一样。
3. **只在真打破时播** —— `_break_open()` 播；`open_silently()`（读档恢复、从子图穿回主图时同源木板门一起打开）**不播**。否则进游戏时门早就破了，看到的是「墙自己炸了」。

## 6. 真渲染后才发现的三个问题

### 6.1 尺寸被 `basis` setter 抹成 1m

```gdscript
# 错：先设 scale 再设 basis
piece.scale = size_vec
piece.basis = Basis(axis, angle).orthonormalized()   # ← 整矩阵覆盖，scale 变回 1

# 对：尺寸乘进 basis
piece.basis = Basis(axis, angle).scaled(size_vec)
```

同理，落地放平时 `piece.basis = Basis(side, up, flat)` 也必须 `.scaled(piece.scale)`。

第一版截图里 13 片全是 1m 大方块。**验收当时是绿的**（只有下限 0.30m）—— 补上限后才红：`A4 最大碎片最长边 1.000m（> 0.65m）—— 比门板还大，读作「一面墙在飞」`。

### 6.2 暗房里是黑剪影

不加补光实拍（真实玩家观感）：碎块是纯黑轮廓，只靠门内绿光勾边。深木色 + 塔内无灯 ⇒ 玩家看不出「木头」。

补**自发光 0.38**（保留 PER_PIXEL 受光，不吃掉高光与阴影）。补后同一机位能看出木片的大小与朝向。

### 6.3 相机站错侧，一整天看不到碎块

第一版截图里什么都看不到，一度以为是「碎片飞反了」。加了诊断输出才定位：探针把相机放在 `target - room_side * 7`，而 `room_side = -basis.z` 已经是房间侧 ⇒ 相机跑到**墙外**，碎块全飞进房间里被墙挡住。

诊断输出（`_report_geometry`）现在会直接打印：门三轴、位点 normal、房间中心在门法线的哪一侧（点积）。**别靠猜** —— 这类「图里没东西」的问题，先打印几何关系。

## 10. 没做的事

- **没有真的「板片掉落的物理碎片」**：飞出去的是独立视觉件，门板本体仍然是缩放消失。如果业主要「门板上少一块、缺口留着」，那要改门板美术与碰撞，是另一件事。
- **S2/S4 那两扇门不在本次范围**：它们在转角壳体上，A23 的凸出量判据对它们仍是估计值（既有遗留限制）。
- **音效未接**：破板没有木头断裂/落地声，属音效域，本次未动。
