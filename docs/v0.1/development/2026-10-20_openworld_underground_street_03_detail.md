## 本版为什么存在

v002 只把**药店楼**做到了参考图颗粒度（3 859 面），同一条街上另外三栋主体楼还是 200 面上下的"抽象盒子"：

| 对象 | v002 面数 | 远看是什么 |
|---|---|---|
| 酒店楼 `hotel_brick_tower_core_10x12_01` | 234 | 一个红方块 + 一排贴片 |
| 酒吧楼 `industrial_bar_building_10x12_01` | 240 | 一个深灰方块 + 几道竖线 |
| 背景楼 `backdrop_tower_block_10x7_01`（3 实例） | 194 | 一个光板 |
| HOTEL / BAR 竖招牌 | 156 / 126 | 色块 |

在近景机位里，药店是"有细节的建筑"，旁边三栋是"纸板"。这个落差比"整体都粗糙"更明显。

## 做法（全部按 v1.1 模版的硬约束）

### 1. 三栋主体楼：带洞外壳 + 真开洞

三栋都改成 **0.38~0.50m 厚表皮 + 内退暗核**，用 `_wall_panel(g, axis, ...)` 按洞的 z 边切横带、再按横向跨度切竖段，**真正开洞**。每个洞自带同厚度进深侧壁，斜俯视有阴影，正面看有厚度。

- 酒店：一层门头洞 + 正立面 5 层 × 3 列拱窗洞 + 南立面 3 层 × 2 列 + 背立面 8 个小窗洞。
- 酒吧：入口洞 + 正立面 3 层 × 4 列窄缝窗 + 南立面 2 列。
- 背景楼：正立面 8 层 × 3 列 + 侧立面 6 层。

### 2. 窗的层叠顺序固定

`_win()` 统一处理：暗背板 → 玻璃或发光面 → 竖梃/横档 → 外框 → 窗台两级 → 过梁/阶梯拱 → 窗下降雨痕。所有内层都比外层更靠里，**绝不会被下一层包住**。

拱券用六级阶梯（`arch=0.85` / `0.80`），阶梯之间填 `E_DIM` 弱发光，远看是一道拱而不是一排台阶。

### 3. 招牌改几何笔画

`STROKES` 表定义 H/O/T/E/L/B/A/R 等 12 个字母的归一化笔画（横竖矩形），`_text()` 按字距铺到平面上。字宽 1.26 / 字高 1.86，面板宽 2.10 → **四周留 0.42 边距**。

两条踩坑：
- **整串要居中**。上一版按 `(i+1)*(lh+gap)` 累加，第 5 个字母顶出面板上沿，H 被裁掉半个。改为先算 `total = 5*lh + 4*gap` 再定位。
- **笔画色要降**。用 `E_ICE #5D6E82` 而不是 `E_COLD #C5CED8`：材质自发光强度是全局 2.4，纯冷白在 1.86m 高的字母上会溢光糊掉笔画边缘。

### 4. 配色：一族一色相列，只动亮度

| 对象 | 色族 | 亮度跨度 |
|---|---|---|
| 酒店 | R1 砖红列 `#29070E→#724A4F` | 15 → 83 |
| 酒吧 | R5 青绿列 `#041A1A→#2E6870` | 21 → 92 |
| 背景楼 | R6 蓝紫列 `#051128→#425972` | 16 → 86 |
| 药店 | R6 蓝紫列（v002 已定） | 9 → 86 |

**上一版酒吧用 R7 紫列，整面立面在渲染里泛紫** —— 业主明确不要大面积紫。改 R5 青绿后与药店/背景楼的 R6 互为邻近色：能区分三栋楼，又不冒出第三种色相。

酒店拱券原来借 `B_D6`（紫），渲染里读成"一块紫台阶"。改砖族 `H_D4` 后落到正确色相，同时把拱券压暗一档，不再抢窗。

### 8. 招牌字左右反写的根因（字形朝向）

招牌挂在**东侧立面**时，观察者在街心（−X 侧）看向 +X：上方是 +Z，但**右手边是 −Y**。
`_text()` 原来按「u 增大 = +Y」铺字，等于从背面写字，B 的竖画跑到右边。

试过两条弯路，都记在这里免得再走：

- **弯路一：实例 `rz=180`**。它把局部 +X 与 +Y 同时翻转，字确实"面对"街心了，但 +Y 也跟着反，
  结果还是反写。渲染里 BAR 的 B 上半截像 P，就是这么来的。
- **弯路二：给 `_text()` 加 `mirror` 开关**。本质是把镜像再镜像一次，能对，但一旦改字形表就二次出错，
  而且把"朝向错误"藏进了一个布尔参数里。

**正解**：`_text(..., u_sign=-1)` —— 让 u 轴跟观察者的右手方向对齐；同时把 BAR 招牌**直接按 −X 构建**
（`c_bar_sign_detail` 内部用局部 `x∈[-D, 0]`，实例 `rz=0`），不靠实例旋转去凑朝向。

## 组件预算

`46 − 3（并入宿主）+ 4（新组件）= 47 ≤ 50`，同族最大 2 ≤ 3（40 族）。

并入宿主的三件（v002 里是独立组件，v003 变成建筑本体的一部分）：

- `hotel_arch_window_bay_02`（15 樘拱窗 → 酒店外壳真洞口）

- `metal_fire_stair_walkway_03`（2 段消防梯 → 酒店与酒吧各自按层高做齐）

## 摆位与机位踩过的坑

1. **墙挂空调挡窗**：`z0 = 5.20 / 9.60 / 14.00 / 18.40` 全部落在窗洞里（窗从 4.30 起），渲染里空调机挂在拱窗中间把窗劈成两半。改到层间实墙带（窗顶 6.85 与腰线 8.40 之间）。
2. **暗窗冷反射读成灯带**：反射条放在 `z0+0.10`（窗底），远看是"每扇窗下面一条青色灯带"，节奏太齐。改到窗高 70~78% 处，宽度只占窗宽 55%。
3. **酒吧肋板读成栅栏**：步距 0.72 时 12m 面宽塞 17 根通高肋板 + 通高暗缝 = 铁栅栏。改 1.05 步距并**分段**（8.30–9.40 留实墙），才读成"板墙 + 加劲肋"。
4. **屋顶拍不到**：穹顶底 28.6m、酒店屋面 27.1m，中间只有 1.5m，任何平视镜位都被吊顶桁架挡死（实测整幅是桁架）。改成从街面仰视檐口与女儿墙。
5. **机位必须投影反算**：`detail_backdrop` 第一版机位落在楼后，画面上半是墙、下半全黑。全部机位改为把目标点投到 NDC 后确认落在 0.45~0.55 才出图。`world_to_camera_view` 前必须 `bpy.context.view_layer.update()`。
6. **BAR 招牌挂错面**：原来挂南立面（朝 −Y），主镜头在南侧勉强能看正面，一有角度就被楼体挡掉一半。改挂正立面（朝街 −X）后与 HOTEL 同一读法。
7. **环境变量守卫泄漏**：v003 需要 import v001/v002 的生成器，用 `UG_STREET_BUILD_LIB_ONLY=1` 让它们的 `main()` 不执行；但这个变量如果留在进程里，v003 自己的 `main()` 也会被跳过 —— 第一次运行只打印了 Blender 版本，什么都没建。改为 import 期间设置、`finally` 恢复。

## 已知取舍

- **仍是纯 Blender 源**：无 GLB、无 PackedScene、无碰撞、无导航，因此**不写入《3D-场景通用》**（该页一行 = 一个真实存在的 PackedScene）。
- 屋顶细节（水箱 / 楼梯间 / 风机 / 天线）在**当前主镜头下几乎不可见**，保留它们是为了后续俯视或贴近镜位，也是"这栋楼是完整的"的证据。若后续确认永不俯视，这批可以删，能省约 600 面。
- 背景楼 3 个实例共用同一组件，其中 2 个在主镜头里只露一个侧角；这是同族复用该付的代价（多建两份定义不划算）。
- 路面标线与人行道细节是**覆盖层**（z 0.004~0.256），叠在既有车道砖/面砖之上，不改原组件。好处是零回归风险，代价是多一层共面几何（已用 0.004 以上间距避开 z-fighting）。
