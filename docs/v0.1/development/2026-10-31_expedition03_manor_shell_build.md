# 远征03 公馆壳体铺装：17 间房全部换成公馆墙与地板

日期：2026-10-31。功能：WORLD-PLAN。业主：「使用03的组件，把03的房间的墙和地板先做好，审美你自己决定，差异性你也自行设计」。

## 一、结果

17 间真房间全部铺装完成，运行时 17/17 接管。

```
VERIFY_ROOM boss    size=50x40  art=true floor=true sides=4 doors=2 leaves=2 manor=232
VERIFY_DONE ok=17 / 17  door_leaves=24 door_ports=35
VERIFY_OK failures=0
```

`combat_25x25` 为例：25 块地砖 + 20 段墙，其中 2 段门墙、8 段窗墙、10 段实心墙。

## 二、审美方案（本次唯一的设计判断）

用**光与材质**区分「危险」与「安全」，而不是每间房一样：

| 房型 | 地板 | 窗 | 意图 |
|---|---|---|---|
| 战斗 / Boss / 陷阱 | 深灰石材 | 无 | 冷、封闭、边界不清 —— 要打的地方 |
| 准备 / 宝箱 / 商店 | 人字木地板 | 每面一对 | 暖、有光、有归属感 |
| 枢纽（hub_01/02） | 人字木地板 | 每面一对 | 虽然是 COMBAT，但多门交汇要「大堂」气质 |
| 撤离 / 入口 | 人字木地板 | 无窗 | 暖但封闭，方向明确不留恋 |

枢纽这一条是刻意的例外：它 room_type 是 COMBAT，但**玩家要在这里认路**。亮的是通道，暗的是要打的地方 —— 这是给玩家的方向感，读表即可，不需要小地图。

开窗规则：每面挑「关于房间中心对称、且两端都不是门位」的一对格子，取最靠中心的那对。对称求视觉平衡，靠近中心避开墙角挤碰。找不到对称对就取最近中心的单格；连这个都没有就不开窗。

## 三、必须引入的机制：门位指纹

铺装前实测发现一个硬冲突：**复用键不含门位，但结构件必须跟门位**。

`manor_wall_door` 洞口固定 2.2m 居中，只能摆在本局门位那一格。而同一复用键下：

```
combat_25x25_38083aa33b1a ← n02(东-5,北0,南0) / n04(北5,西0)
                             n05(东-5,北-5) / n06(北0,南0) / fireplace(西0)
combat_45x40_6351962d84c2 ← hub_01 / hub_02 / n07
```

5 间房 5 种门位。若共用一份含门墙的场景，**4 间的门会被实心护墙堵死**。

解法：**门位不进签名，但进文件名**。

```
runtime_rooms/<template>_<签名前12>_<门位指纹前6>.tscn
```

门位指纹 = 每个端口 `side@lane` 排序后的 sha256 前 6 位。实测 17 间 → 17 份文件，冲突归零。

这是复用键的**第三次语义演进**，三次都是设计变更不是修 bug：

| 阶段 | 签名含门位 | 文件名含门位 | 后果 |
|---|---|---|---|
| ① 10-31 之前 | 是 | — | 每房一键，美术做一次只有一局能用 |
| ② 10-31 中 | 否 | 否 | 一局收敛到十几份，但墙跟着美术走、门位一变就错位 |
| ③ 10-31 晚（当前） | 否 | **是** | 结构件跟门位，装饰仍可跨种子共享（门位恰好相同时命中） |

**代价（必须知道）**：结构层与装饰层在同一份场景里，所以装饰也随门位分文件。实测膨胀比 **1.55**（17 文件 / 11 个复用键）。要让装饰独立复用，得把两层拆成两份文件分别匹配 —— 未做。

## 五、顺带修的三个缺陷

**1. `geometry` 存成转义字符串，门禁读不到。** builder 第一版用 `JSON.stringify(geometry)` 写 meta，TSCN 序列化把 `{` 转义成 `\"{\"`，而门禁 `extract_braced()` 按未转义括号配对找 —— 结果是「字段存在却读不到」，报「缺 size」。改成直接存 Dictionary，Godot 写成多行 `{ ... }`，与采集器一致。

**2. `_exp03_manor_art_probe` 会覆盖正式美术。** 它往 `CONTRACT.art_path()` 写临时场景来测两条分支，之前正式目录是空的所以无害。铺装落地后，同样的代码会**直接覆盖**那 17 份中的一份。改为先读入内存、结束写回（实测 MD5 未变）。

**3. 探针判据依赖 `Wall_north`，铺满后静默 SKIP。** 铺装覆盖四面后程序化墙被跳过，`Wall_north` 不存在，探针「找不到 25×25 房间」直接退出 —— 不报错也不生效。改用 `procedural_shell` + 尺寸。

## 七、没做的事

- **没摆家具**。本次只做墙 + 地板（业主原话「墙和地板先做好」）。34 件陈设在面板「远征03 / 复古公馆·陈设」里可随时刷。
- **没做批量铺装工具**。铺装器已经存在，但它按房型风格表全自动；没有「在工坊里按网格批量刷」的交互。想手工微调目前只能逐件拖。
- **装饰跨门位不再复用**（见第三节代价）。
- **没做视觉验收标准**。出图是给人看的，没有断言「看起来对不对」——那需要人判断。
- **`combat_25x25` 被拆成 5 份**。这是门位多样性造成的，想在工坊里只维护一份，得先让结构层与装饰层分开。
