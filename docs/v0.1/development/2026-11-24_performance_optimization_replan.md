## 1. 计划结论

当前工程已经具备房间流送、RuntimeDetail 生命周期、读取页资源预读、VFX/投射物/战斗特效池、部分 MultiMesh/ArrayMesh 和空间查询复用。性能问题不是“没有优化”，而是几类优化没有形成同一套可量化的批次和生命周期闭环。

本轮重做遵循以下总顺序：

```text
文档冻结
→ 当前工作区无新增插桩基线
→ 跨门进房成本分段归因
→ 空间/数据批处理复用
→ 预加载覆盖补缺
→ 运行期主线程提交分批
→ 局部静态几何合批
→ 全地图真实渲染与长测签署
```

**不先做全地图渲染合批。** 当前最需要确认的是阻挡物收集、RuntimeDetail 创建、首波 Enemy3D 装配、检查点快照和导航/物理同步的进房成本。只有证据证明 GPU 几何或 Draw Call 是主要瓶颈，才进入局部几何合批。

## 2. 不改变的逻辑边界

优化前后必须保持以下结果和时序不变：

- 房间拓扑、房间稳定 ID、门状态、楼梯连接和地图种子不变。
- 敌人数量、身份、刷怪盒语义、出生位置裁决、安全距离和出现时机不变。
- 掉落、宝箱、Boss 阶段、撤离条件、命运结算和奖励归属不变。
- 存档 schema、revision、原子替换、`.bak` 回退、失败重试和退出等待不变。
- 结构楼板、生成墙、门框、外圈墙、遮光结构、承重碰撞和必要投影不关闭。
- `SegmentPlan`、`SegmentRuntimeState` 与房间稳定 ID 的所有权不改变。
- 预加载只提前准备资源或无副作用表现，不提前触发 AI、交互、奖励、存档、清房或正式刷怪。
- 读取页仍保持“预热 A → 预热 B → 交接等待 → 恢复玩家输入”的顺序。
- 优化失败时回到原有保守路径，不使用旧缓存冒充当前几何、导航或运行状态。

以下内容本轮明确不做：

- 不为了跑分删怪、降安全距离、隐藏结构、关闭手电或降低默认画质。
- 不把 `visible=false` 当成 RuntimeDetail 卸载。
- 不把后台写盘耗时写成主线程快照零成本。
- 不把历史 Compatibility 结果、headless 结果或单次短路线结果当作当前 Forward+ 发布签署。

## 3. “合批”的四类定义

本计划不再把“合批”作为一个模糊总称。每类单独记录输入、提交边界、收益、失效条件和回退路径。

| 类型 | 当前已知状态 | 本计划处理顺序 |
|---|---|---:|
| 渲染几何合批 | 塔楼地砖、外墙、部分走廊模块、远景城市已有 `MultiMesh`；部分幕墙使用 `ArrayMesh`。没有覆盖所有地图动态陈设的统一合批器 | 最后 |
| 实例池 / 批量实例化 | VFX、投射物、战斗短特效已有池；敌人和 RuntimeDetail 没有通用池。敌人整批生成仍是玩法事务，不可直接改成延迟刷怪 | 第二阶段之后，按证据补缺 |
| 空间查询 / 数据批处理 | 有空间注册表、碰撞索引、Concave faces/bounds 缓存、刷怪盒静态候选和部分批内复用，但仍可能重复收集 | 第一施工重点 |
| 加载提交批处理 | 读取页有线程预读和逐帧预热，FloorBundle 有分段提交；没有统一的运行期目标房优先级、取消、主线程预算队列 | 先测量，再局部补齐 |

6. 标记当前工作区既有未提交改动，后续报告必须带代码指纹，不能把不同工作树的结果混在一起。

### 阶段 1：跨门事件分段归因

**目标：** 把“进房卡顿”拆成可施工的成本，不先猜答案。

每次首次进房和折返至少分开记录：

```text
旧房状态回写
→ 检查点捕获
→ 快照深复制 / payload
→ 流送状态解析与提交
→ RuntimeDetail 创建
→ 阻挡物来源收集
→ 刷怪盒候选与动态裁决
→ Enemy3D 入树与配置
→ AI / 灯光 / 注册表登记
→ 幕墙或房间专属表现
→ 导航构建与后续物理帧同步
→ 帧末释放
→ 首次可操作窗口
```

必须区分嵌套总时间和自身时间，避免把 `ensure_detail_built()` 的早退重复计算。

**阶段门槛：** 得到每个候选段的 P50/P95/P99/max、样本数和超阈值数；能确认至少一个首要贡献项；不能把旧版 259/326ms 冷载数字直接套到当前版本。

### 阶段 2：空间与数据批处理

**目标：** 优先减少同一同步选择窗口内的重复准备，不改变最终裁决。

优先检查：

- `_collect_spawn_blockers()` 的来源列表、几何展开和实时变换是否重复构建。
- `spawn_point_for_index()` 的可达性初始化和随后收集是否重复读取同一静态输入。
- `RuntimeCollisionIndex`、Concave faces/bounds、刷怪盒静态候选的缓存命中和失效原因。
- 同一房间的授权导航输入是否能在读条/预取阶段准备。
- 空间注册表查询是否保持原桶顺序、过滤条件和有效节点完整性。

可复用的内容只限于纯数据或无副作用准备。玩家安全距离、动态障碍、实体占位、门状态和最终入树仍保留在原有边界内。

**阶段门槛：** 同种子、同房间、同操作序列下，候选顺序、落点、碰撞结果、导航可达性、敌人身份/数量和事件 tick 一致；几何或成员状态变化后缓存能失效；收益超过重复测量波动；否则回滚该批处理。

### 阶段 3：预加载和预热覆盖补缺

**目标：** 只补证据确认存在的冷加载、首绘或池 miss，不扩大无意义常驻内存。

资源分层：

1. **进程级共享资源**：VFX、普通怪表现基类、共享材质、音频和池对象。
2. **本局读取页资源**：已确定房间壳体、静态几何、首触发表现、已确定的导航纯数据。
3. **当前房 / 一跳邻房**：安全壳、可取消的资源准备和原有门边界。
4. **二跳及远房**：保留纯数据和结构事实，不提前提交玩法节点、AI、交互或正式敌人。

资产预热账必须区分：

```text
requested
loaded
instantiated
drawn
reused
pool_miss
failed
skipped
released
```

当前代码与旧文档存在数量漂移：实际源码是 4 个怪物表现基类、14 个 VFX 预热项；后续报告以当前代码和实际报告字段为准，不能继续引用旧的 3/12 作为覆盖证明。

**阶段门槛：** 必需资源有实际加载、实例化和真实首绘证据；预热没有触发玩法、奖励、存档或 AI；读取页新增等待和 RSS/显存成本在预算内；失败时保守路径可用。

### 阶段 4：运行期主线程提交批处理

**目标：** 在不拆改变玩法事务的前提下，把已证实的准备工作移出事件帧。

允许考虑：

- 把纯资源引用、几何准备、授权导航面和静态刷怪候选放入可取消的优先队列。
- 当前目标房优先，其次已开放一跳，再考虑可达二跳。
- 门、结构碰撞、动态障碍和最终玩法实体仍在原安全边界提交。
- 记录排队、等待、挂树、物理同步、首绘和释放的完整生命周期。

禁止：

- 为了达标把首波敌人延迟到改变手感的时机。
- 用 `call_deferred` 冒充后台线程。
- 让后台线程访问实时场景节点。
- 取消存档检查点、revision 冲突检查、原子替换或失败回滚。

**阶段门槛：** 流送主线程 P95 ≤ 2ms、单帧最大 ≤ 8ms；事件帧 P99 ≤ 33.3ms、无单帧 > 50ms；后续两物理帧导航成本不得漏报；A→B→A、同 ID 新节点、下一帧重试和存档恢复均保持正确。

### 阶段 5：局部静态几何合批

**目标：** 只对已经确认的 GPU/Draw Call 热点做小范围、可回退的合批。

试点条件：

- 同 Mesh、同材质、同投影策略。
- 同一房间或明确同一可见范围。
- 无独立交互、无独立破坏状态、无独立碰撞。
- 不跨房间、不跨门洞、不传播到结构代理或碰撞。

先验收：

- 房间地砖重复件。
- 不参与交互的静态装饰。
- 已有明确变体分组的幕墙或远景件。

暂不处理：

- 动态家具、可破坏物、门、灯具、敌人、VFX。
- 需要单独碰撞、导航、受光或状态恢复的对象。
- 跨房间大块网格。

**阶段门槛：** 真实 Forward+ 下主通道和阴影通道的 Draw Call、图元、CPU/GPU、显存均有可复现实测收益；门洞、遮光、碰撞、导航、材质变体和可见性一致；收益不能被首绘、裁剪或内存回退抵消。

### 阶段 6：全地图回归与发布签署

覆盖：

- 远征 01/02/03。
- 测试关卡 99 单列。
- 旧四张主题地图代表样本。
- 塔楼楼层流送和隔离提交。
- 续档、返航、失败重试、秘密支线、动态家具、首枪、首箱、Boss 和撤离。

保留原验收门槛：

| 指标 | 门槛 |
|---|---:|
| 事件帧 P99 | ≤ 33.3ms |
| 事件帧最大值 | < 50ms |
| 流送主线程 P95 | ≤ 2ms |
| 流送单帧最大值 | ≤ 8ms |
| 稳态 CPU P95 | ≤ 8ms |
| 稳态 GPU P95 | ≤ 12ms |
| 稳态实例化房间 | ≤ 5 |
| 完整 ACTIVE 房间 | ≤ 3 |
| 往返后节点/注册表增长 | ≤ 2% |
| 隔离提交后旧区段节点 | 0 |
| 测试结束残留 Godot | 0 |

60 FPS 单帧预算公式为：

```text
frame_budget_ms = 1000 / 60 = 16.667ms
remaining_budget_ms = 16.667 - other_measured_cost_ms
```

事件帧可以使用 33.3ms 统计门槛，但不能用统计门槛掩盖单帧超过 50ms 的尖峰。

## 7. 停止条件

出现任意一项，停止当前批次，不继续扩大优化范围：

- 地图拓扑、房间 ID、门状态或敌人结果改变。
- 存档回读出现丢失、复制、复活或 revision 冲突未收口。
- 预加载引入正式玩法副作用。
- 缓存失效条件无法证明，或旧导航/旧碰撞数据被当作当前数据使用。
- 真实渲染结果无法区分收益和测量噪声。
- GPU 时间戳缺失却试图签署 GPU 通过。
- 发现远征 02 终局缺口、远征 04 场景缺失等地图完整性问题时，把它们改写成性能问题。
- 任何为了全绿而放宽原阈值、关闭结构事实、删减敌人或降低画质的方案。
