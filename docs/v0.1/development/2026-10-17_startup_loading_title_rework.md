# 启动加载页：撑满画幅的斜置标题 + 赛博色散

**日期**：2026-10-17
**范围**：`scenes/StartupLoadingScreen.gd`、`scenes/StartupLoadingSplash.png`、`project.godot`
**不改**：`StartupLoadingScreen.tscn`、启动时序、后台预加载路径、`TARGET_SCENE`、存档相关逻辑、**`ExpeditionLoadingScreen`（远征读条，明确不动）**

## 业主原话（五轮迭代）

**第一轮**：
> 打开游戏这个界面，帮我设计成这种的，名字是大号的字体，放大，斜着富有张力。然后下面是进度条。其它信息不要。

**第二轮（纠偏）**：
> 我的红线不是要装饰的东西 而是告诉你logo名称要斜着摆放

⇒ 红线是**标注**，不是画面元素。

**第三轮**：
> 装修一下 和主面板hud的风格一致，然后进度条也要歪的， 要加上粉色和蓝色的赛博干扰的边缘效果

**第四轮**：
> 画面边缘的效果不用，然后字要再大，撑爆整个画面， 可以有些切掉在画面外的。

**第五轮（本轮）**：
> 游戏开始的时候，还有一个读条界面， 那个界面的内容只保留一个进度条 ，其它不要了
> 是点击游戏开始后，先前还有一个画面，然后才进入新改的这个斜着的字体的画面。远征那个别给我改啦

⇒ 目标**不是**远征读条页（那一版已回滚）。真正要改的是**引擎级前置画面 `boot_splash`** ——
   它由 `project.godot` 的 `boot_splash/image` 指定，早于任何脚本绘制，所以在斜字体页之前。

## 追加（同日）：名字加朋克律动

`StartupLoadingScreen` 的斜置名字从静止改为**跟着 138 BPM 虚拟鼓点抖动**：

| 层 | 参数 | 作用 |
| --- | --- | --- |
| 常驻微颤 | 0.5 px / 0.10°，73·113·97·149 Hz 正弦叠加 | 设备通电的嗡鸣底噪 |
| 节拍冲击 | 2.4 px / 0.45°，`pow(1-phase, 2.8)` 衰减 | 每拍被顶一下 |
| 强拍重音 | 额外 4.2 px / 0.75°，每小节第一拍 | 一小节一次重击 |
| 入场冲击 | 0.30 s 内 1.09 → 1.0 缩放 | 砸进正位 |
| 色散律动 | 3.6 → 8.1 px，强拍时方向翻转 | 信号被打断又接回 |

**三条实现约束（改动前必读）**：

1. **抖动方向每拍重掷、拍内保持不变** —— 用确定性哈希 `_hash_unit(beat_seed)`，
   不用每帧 `randf()`。每帧随机会让字变成噪点闪烁，"在震"和"在闪"是两种完全不同的观感。
2. **三层频率必须互不约**（73/113/97/149 是质数邻近值）。取成 2 的倍数就会合成一条
   规律波浪，立刻从"颤动"退化成"呼吸"。
3. **进度条不吃抖动**，走干净坐标系。条是读进度的功能件，跟着鼓点跳会让读数发飘。
   字抖条不抖，动感与准确同时成立。

律动时钟用独立的 `_fx_time`，**不能复用 `_elapsed`** —— 后者在 `_advanced` 之后停止累加
（它管"最短展示时长"）。且 `_process` 里的重绘必须**无条件执行**，否则加载卡在末段时字会突然僵住。

实测采样（`_scratch/preview_startup_loading.tscn` 按相位冻结，6 帧对照图见
`ShellStorm2-work/probes/startup_loading/rhythm/_contact_sheet.png`）：

| 相位 | 角度 | 缩放 | 位移(px) | 色散(px) |
| --- | --- | --- | --- | --- |
| 入场 t=0.05 | -12.90° | 1.073 | (1.59, 1.24) | 7.15 |
| 强拍砸下 t=1.755 | -12.79° | 1.025 | (-3.49, -1.03) | 8.11 |
| 普通拍 t=2.190 | -13.20° | 1.014 | (0.91, -0.21) | 5.58 |
| 拍间（基准） t=2.570 | -13.07° | 1.000 | (-0.09, -0.25) | 3.60 |

抖动幅度先按 5.5 px 试过一版，实测横向甩得太远会让「壳」字出画过多，收到 4.2 px。

## 追加（同日）：背景改「黑底 + 多方向碎切」

> 业主第四、五轮原话：
> 主要颜色还是黑色，平面切割使用斜着切，30%的鲜艳色彩+5%的撞色， 出现时间控制在0.3-0.5秒
> 斜切不要跟着字的方向 要不一样的方向 多一些 不同方向 看起来不是速度点而是絮乱的感觉

纯黑底换成**色块构成背景**：玫红 `#FF2D7E` / 绿 `#02E676` / 蓝 `#1D6AFF` / 黑 `#06080B`。
**黑是主角，彩色是刀口** —— 不铺满、不加边框、不做渐变。

### 面积：八帧逐帧不同，不是每帧 30%

> 业主第六轮原话：
> 持续的太久了，每个在0.1-0.2之间，部分画面的比例可以鲜艳色彩降到10%以下，比例可以多一些

| 帧 | 鲜艳 | 黑 | 说明 |
| --- | --- | --- | --- |
| f0 | 25.05% | 70.00% | 最满的一帧 |
| f1 | **8.33%** | 87.85% | 低于 10% |
| f2 | 15.37% | 83.49% | |
| f3 | **6.66%** | 88.38% | 低于 10% |
| f4 | 19.44% | 76.74% | |
| f5 | 12.58% | 83.61% | |
| f6 | 11.79% | 87.07% | |
| f7 | 0.00% | 98.86% | 黑场 |

**黑每帧都在 70% 以上** —— 这是"主要颜色还是黑色"的可核对定义，不是形容词。

实测由 `measure_area_share()` 用鞋带公式逐帧算，探针每次运行打印 `AREA f0..f7`。
**改任一顶点或索引都必须重跑核对。**

### 几何：十个方向互相打架

| 形状 | 角度 | 单独面积 |
| --- | --- | --- |
| 0 | ~72° 陡竖切 | 9.77% |
| 1 | ~-32° 缓横 | 8.33% |
| 2 | ~-62° 陡对角 | 2.66% |
| 3 | ~+38° 反斜 | 1.60% |
| 4 | ~-48° 三角 | 1.45% |
| 5 | ~-20° 小块 | 1.24% |
| 6 | ~+15° 扁条 | 1.35% |
| 7 | ~-55° 尖条 | 0.74% |
| 8 | ~+80° 小方 | 0.57% |
| 9 | ~-38° 斜块 | 0.66% |
| 10（撞色） | ~-17° 长条 | 3.82% |
| 11（撞色） | ~+72° 陡块 | 1.14% |

**关键：所有角度都离开名字的 -13°。** 上一版让切线与名字同角度，全部平行 →
读成「速度线」，是冲刺感。这一版要的是**紊乱**：角度互相打断、大小悬殊、位置不构成韵律。

形状做成**池 + 每帧挑子集**，不是每帧手写顶点：加帧是加一行索引，不是复制一套坐标。

### 节奏：0.15 s 一帧，八帧一轮

`FLASH_SECONDS = 0.15`，落在业主指定的 **0.1–0.2 s** 区间，八帧一轮 1.2 s。

八帧靠 `FRAME_FLIPS` 镜像换落点：镜像不改变任何碎片面积，所以配额逐帧恒定；
但同一组碎片的落点全变，观感是"每次切法都不同"。手写八套顶点迟早有一套面积对不上。

**⚠ 闪切已与律动解耦。** 字仍按 138 BPM（每拍 0.435 s）抖动，背景按 0.15 s 换帧。
这是必然的：138 BPM 一拍就是 0.435 s，物理上不可能既锁拍又做到 0.1–0.2 s。
现在观感是"字按鼓点震、背景在更快的频率上闪"，两套节奏叠在一起更躁。

观感对照见 `ShellStorm2-work/probes/startup_loading/frames/_frames_contact_sheet.png`。

### 三条实现约束（都有实测教训）

1. **白字必须加近黑描边。**
   背景变多色后，白主体压在亮绿 `#02E676` 上会直接糊掉。加了 8 方向 5 px 近黑描边
   （`#030406`）才读得清。这层不是装饰，是背景改色的连带刚需。

2. **进度条空槽从"10% 半透明白底"改成"不透明近黑衬底 88% + 2 px 白描边"。**
   半透明白底是给纯黑背景设计的，在亮色块上直接消失 —— 读不出"还剩多少"，条就废了。

3. **探针只刷 `TitleArt` 会让背景永远停在首帧配色。**
   六张截图完全一样（踩过一次）。两层都要 `queue_redraw()`：`TitleArt` + `SchemeArt`。

### 演进过程（为什么前三版被推翻）

- **v1（已删）**：6 条斜带 + 3 块正交贯色块，四套配色轮转。
  问题：彩色铺满全屏，黑不再是主角；正交块让画面变成"构成主义海报"而不是"刀切"。
- **v2（已删）**：四套配色换主导色（玫红/绿/蓝/暗场）。
  问题同上（彩色仍占 60%+），且四套之间的位置差异只是"平移色块"，闪切感偏弱。
- **v3（已删）**：黑底 + 按配额切色，但**切线与名字同角度**。
  问题：所有线平行 → 读成「速度线」，是冲刺感而不是紊乱感（业主当场指出）。
- **v4（已删）**：黑底 + 六块不同方向的碎片 + 撞色两块 + 四拍镜像（每拍 0.435 s）。
  问题：每帧时长 0.435 s 太长（业主："持续的太久了"）；且四帧比例完全相同，缺少疏密变化。
- **v5（现行）**：形状池化 + **八帧**、每帧 0.15 s、每帧挑不同子集 → 比例逐帧不同（0%~25%），
  含两帧低于 10% 和一帧黑场。这才同时满足"黑是主色"、"切割感"、"紊乱感"、"快且疏密有致"。

新图的进度槽参数刻意与游戏内同源：**槽宽 34% 屏宽、内底 12% 白、描边 42% 白**，
底色与 `StartupLoadingScreen.BACKDROP_COLOR` 同为 `#06080B`。
于是「splash → 斜字体页」是一次**同色同语法**的过渡，不会先亮一下再变黑。

## 为什么这个画面不能靠改代码解决

`boot_splash` 是**引擎在脚本运行前**画的静态贴图，没有节点、没有 `_draw()`、没有脚本钩子：
- 改文字 → 只能改图；
- 改位置 → 只能改图；
- 改底色 → 改 `project.godot` 的 `boot_splash/bg_color`（贴图底色要同时改，否则窗口比例不匹配时边缘会露色）。

所以这一屏的"内容"完全由那张 PNG 决定。要再调节，重生成那张图即可（参数见上表）。
