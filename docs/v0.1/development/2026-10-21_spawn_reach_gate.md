# 刷怪可达性闸门：怪不再刷进玩家走不到的空腔

- **日期**：2026-10-21
- **FeatureID**：`WORLD-PLAN`（房间落点）＋ `EXPEDITION-COMBAT`（远征01 战斗房清场）
- **业主口径**：*「room03 手动调整了布局、把四个角落围起来了，但中间还有一些我角色去不了的地方，
  刷怪会刷在这个位置。帮我在里头增加怪物不会刷的区域。」*
- **结论**：不新增「禁刷矩形」这种要人肉维护的数据，而是在落点判据里补上**玩家可达性**一条：
  `DungeonRoom3D._ensure_spawn_reach()` 从门内侧做 0.5 m 网格洪泛，只保留玩家胶囊
  （r=0.34）走得到的格；由 `_spawn_floor_contains()` 一处收口，三条刷怪路径同时生效。

---

## 1. 为什么旧判据拦不住

| 判据 | 它回答什么 | 对「家具围出来的封闭空腔」 |
|---|---|---|
| `_spawn_floor_contains()` | 这个点的占地是否被主层地砖**满铺** | 放行 —— 地砖是按房型铺的，不随家具走 |
| `_spawn_obstacle_free()` | 这个点有没有压在家具 AABB 上 | 放行 —— 家具是**障碍**不是**围墙**，腔体内部仍有空地 |
| `_spawn_clearance()` = 1.15 m | 离墙/离障碍留多少净距 | 只保证不嵌进家具，不保证连得通 |

三条都成立，怪就合法地刷在腔体中央，而玩家在墙外打不到 ⇒ 战斗房清不完 ⇒ 门永远不开。

## 2. 实现

```
_ensure_spawn_reach()
├─ 前置：_detail_built（家具碰撞没进树时不算，且不落锁 —— 下次重试）
├─ 跳过：room_type ∈ {BOSS, EXTRACTION}（多级房，0.5m 单层网格不适用）
├─ 0.5 m 网格；障碍 AABB 在 XZ 上膨胀玩家半径 0.34
│   └─ 底面 ≥ 1.55 m 的构件（头顶横梁/吊管）不算挡路
├─ 种子：每个 connection_port 内侧 2 m（门洞格常被门扇占着）
│   └─ 一个门都给不出种子 ⇒ 取最大连通分量
├─ 4 邻接洪泛 → _spawn_reach_cells
└─ 覆盖率 < 35% ⇒ 判定自己算错，停用并 return（绝不整房判死）
```

收口点唯一：`_spawn_floor_contains()` 开头。

三条落点路径全部经过它：

| 路径 | 调用方 |
|---|---|
| 索引落点 | `spawn_point_for_index()`（房型公式 / `enemy_spawn_plan` / 编成外增援） |
| 盒内采样 | `spawn_points_in_box()` → `_box_sample_points()` |
| 剧情落点 | `resolve_narrative_floor_positions()` / `is_narrative_floor_position_valid()` |

闸门首次生效时 `_build_spawn_points()` 重算候选池（`_ready()` 那次家具还没建）。
同一 `room_seed` ⇒ 除被剔掉的点外逐点不变。

## 4. 边界与代价

- **几何可达 ≠ 导航可行**：只回答「走不走得到」，不回答「好不好走」。
- AABB 是绕 Y 旋转后的保守盒（带倾斜的家具尤其大）⇒ 闸门比物理实测略保守
  （room_03 可达格 1597 vs 物理 1931）。方向安全：宁可少刷一只。
- 安全阀 35%：低于此值停用闸门并 `push_warning`，防止「算错 ⇒ 全房不刷 ⇒ 门不开」。
- Boss 房强开会导致盒心漂移（实测 20.8 m）⇒ 显式排除，写进代码注释。
