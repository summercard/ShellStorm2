# 南墙收镜与鼠标前瞻交接稳定性修复

日期：2026-11-10。工程0.1.0；FeatureID：PLAYER-STATE，整体状态仍为partial。来源：用户再次反馈贴南墙抬镜时，鼠标向下触发镜头打架/闪屏，要求仅屏蔽向南前瞻、保留其他方向并注意操作体感。开始HEAD：`d4cc5a2178f4007f2919234dbfedd77434d3e924`；保留已有并行工作区修改，未提交或推送。

设计主源：[玩家与操作§6.1，PLAYER-STATE r6](../03_技术施工_玩家与操作.md#61-光标前视与受伤震屏player-state-r6)。既往尝试：[11月6日修复](2026-11-06_camera_lower_wall_mouse_look.md)。

## 1. 诊断边界与改动

11月6日已实现角色锚定探针及`set_look_blocked_direction()`，本轮没有再复制一套“禁止南向”逻辑。改前模型17项通过；固定贴墙0.35m、实际相机basis及角色身体投影的持续南向输入也未复现原位闪屏。因此不能声称已完整重现用户当时的房间画面。

本轮新增回归确实检出三个联动缺口：

- 原收镜只有一个距离阈值。输入距离在阈值两侧±3cm变化时，120帧只有60帧保持收镜，目标每帧交替收回/展开。
- 同步发布的前瞻限制每次跟随目标解除，南向偏移会在间隙漏出。
- 一旦离开收镜阈值，基础镜头尚未展开完毕，南向前瞻就已经恢复，两个运动叠加。

`TowerDescent3D`仍是基础机位/墙体约束唯一Owner；`PlayerCameraFeedback3D`仍唯一拥有临时前瞻偏移，后者本轮未改。修复：

1. 收镜进入距离保持`D_in = CAMERA_DEFAULT_TRAILING_M = 4.914455m`；退出距离`D_out = D_in + 0.20m = 5.114455m`。额外20cm只作滞回，不改首次触发距离。
2. 收镜期间持续禁止后墙方向的前瞻。退出后，保持限制直至基础后移距默认值≤0.05m、抬升距目标值≤0.01m，再由既有7.5/s前瞻平滑恢复。最大收镜后的基础展开约`ln((4.914455-0.15)/0.05)/4.5 = 1.01s`达到释放范围；这是已有4.5/s展开速度的结果，不另加固定计时器。
3. 保留左右、向上和斜下横向分量；不改死区、最大1.65m、FOV、移动/瞄准、受伤震动、墙体标签、存档或资产。flow关卡继续不抬镜、不额外禁南向；剧情接管清理新增临时状态。
4. 快照新增`camera_lower_wall_retract_active / camera_lower_wall_retract_exit_m / camera_wall_look_blocked_direction`，只供运行时查询。

## 2. 验收入口与隔离

复用已登记的`verify_player_camera_defeat_feedback`，默认在完整关卡前执行轻量Owner夹具；新增`--wall-fixture-only`独立入口。夹具从`Dungeon3D.tscn`保留必须节点，以测试派生类跳过整关生成，调用正式墙探针/收镜/基础机位/反馈函数，使用真实物理标签墙、相机basis和角色身体屏幕投影。没有复制正式镜头算法。

新增覆盖：0.35m墙距、持续南向240tick、稳定段位置及朝向、左右/斜下/向上、±3cm边界噪声120tick、20cm退出带、退出首帧不漏南向、30/60/144Hz恢复时序、旋转后方轴与flow清理。保留旧17项模型回归。

真实渲染使用Godot4.7.2、Vulkan/Forward+、RTX4060Ti；真实窗口指针按视口最终变换换算并注入，逐方向检查焦点、指针位置和实际`_physics_process()`输入门。每方向同步推进90个1/60s模拟tick后截图；这是窗口输入/渲染夹具，不等于完整关卡实际持续90显示帧或人工手感。

启动前使用独立`project.godot`的custom_user_dir及独立APPDATA/LOCALAPPDATA/XDG_DATA_HOME。夹具运行时断言用户数据位于工程外隔离APPDATA，未使用正式档。共享只读导入缓存目录链接，不复制整项目。临时runner已改为原子替换隔离配置，避免并行写配置时读到半文件。
