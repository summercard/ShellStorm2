## 1. 素材来源与拆版

原图是 7 张 5×2 的塔罗牌阵合集（1536×1024 / 1312×1199），共 70 张单卡。拆分口径：

- **定位**：绿色掩膜 → 连通域 → bbox 合并（卡内图形碎片先合并成整卡）。列间隙最窄仅 10px，其中「霓虹兔机塔罗牌阵-6」第 3 列带在列投影上与前两列连成一片，靠连通域而非投影带才分得开。
- **抠图**：闭运算闭环边框 → 边界泛洪判定外部 → 保留最大连通域 → 填内部孔洞 → 1px 高斯羽化。卡内图形完整保留、卡外像素全透明、圆角与抗锯齿边缘无损。
- **验收**：70 张全部通过自动校验（四角透明、中心实心、不透明占比 0.94 属正常圆角比例），无一张有内部空洞或误切。

## 2. 48 张可玩卡 → 30 张牌面

游戏内可玩命运卡是 48 张（星星 22 / 月亮 12 / 太阳 14），与 70 张图**不是一一对应**：去重后只有 30 个不同牌面，其余是同牌的多风格版本。

**选版规则**（主人选定「每张牌挑最统一的一版」）：按中文标签系优先 `07 → 06 → 04 → 03 → 01`，全息套 `05` 兜底。理由：第 7 套卡面直接印中文牌名（「魔术师 / 战车 / 力量」），与需求"卡上只保留功能"的中文界面语境一致；第 5 套虽是英文标签，但恰好是唯一覆盖月亮/圣杯系的套系，且画风比第 1 套更贴近主流。

选版分布：`07→10 张、01→8 张、05→7 张、04→2 张、03→2 张、06→1 张`。

**18 张缺图**（权杖·二/三/六/七/八/九/十/侍从/骑士、星币·王牌/二/三/四/五/六、愚者、隐者、正义）走程序卡面回退，见 §4。

## 4. 呈现层：`src/weapons/FateCardView.gd`

新建一个**只做表现**的静态工具类，四个入口共用，避免同一套绘制代码抄四遍：

| 接口 | 作用 |
|---|---|
| `art_for(card)` | 卡面贴图；**无图返回 null** |
| `back_texture()` | 卡背贴图（只探测一次） |
| `has_art(card)` | 单卡是否有图 |
| `build_art_layer(...)` | 铺卡面层（逆位时绕中心 180°） |
| `build_back_layer(...)` | 铺卡背层 |
| `reveal(face, back, is_reversed)` | 翻面揭示 |
| `build_caption(card, ...)` | 卡下功能文字 |

**缺图回退**是这套设计的关键：`art_for()` 返回 null 时，调用方回退到原来的程序绘制卡面（保留原有文字布局）。好处是补图落地后**无需改代码**即自动生效，且 18 张缺图期间功能与画面都不崩。

**贴图缓存**：按 `stable_card_id` 缓存结果（含 null），避免每次开卡池都探测磁盘。

### 逆位

只把**卡面图案**绕中心旋转 180°，卡下功能文字层**不参与旋转**，因此天然保持正向可读；效果内容仍读逆位快照。卡面层与文字层分离是实现这条规则的前提，不得合并成一个节点。两条路径（图卡 / 程序回退）由 `tarot_art_mode` 元数据区分。

### 去掉的 UI

品质色描边、作用域标签（★星星/☾月亮/☀太阳）、方位三角 `▲/▽`、目标预览（"当前枪 #XXXX · 下一槽 1/3"）、页脚（"永久刻印 · 不可逆"）、类型/品质角标、emoji 图标。**卡面本身已带边框与牌名，再叠一层与之重复**。这些信息仍保留在 tooltip 与选择后的状态提示里，不丢功能。

## 5. 修掉的一个真实 bug

首次渲染探针出图后发现**逆位卡面绕错误轴心旋转、飞出容器**。

根因：`FateCardView.build_art_layer()` 里用 `host.resized.connect(_center_pivot.bind(rect))`，而 `_center_pivot` 是**静态方法** —— Godot 对静态方法 Callable 按底层函数指针做去重，把不同 `rect` 的 `bind` 结果判成"同一连接"而拒绝连接，于是只有首帧 `call()` 设对了枢轴，之后布局变化仍绕旧轴心转。

修法：枢轴同步改用 **lambda**（每个 lambda 是独立对象，不会被误判）。同一问题的同类写法在 `Dungeon3D` 里也用 lambda 修掉。这个坑值得记：**静态方法 + bind 的组合在"多个控件各连一次"场景下会静默只生效一次。**

## 8. 补图完成（2026-10-09 追加）

上一轮图片生成服务持续 429，18 张缺口由本轮补齐。改用项目内的 `gpt-image-2`（图生图，以现有卡面作风格参考）**串行**生成，30 分钟跑完 18 张、零失败。

生成后做**两步对齐**，这是本轮的关键——直接生成的图**不能**直接用：

| 处理 | 问题 | 依据 / 结果 |
|---|---|---|
| **绿色归一化** | 生成图核心绿 `(4,237,122)` vs 既有卡面 `(2,252,142)`，B 通道偏低 20、整体偏暗 | 以 G 通道为亮度权重重映射到基准色 `#02FC8E`；黑仍黑、线稿层次保留 |
| **线条加粗**（亮度最大值滤波 size=2） | 生成图线条**细 2.4 倍**：密度 0.161 vs 既有 0.389 | 加粗后 **0.383**，与既有差距 **1.6%** |

> 线宽这一步如果不做，48 张里有 18 张会明显"发虚"——密度差 2.4 倍是肉眼可辨的量级。`size` 取 2 是逐档实测出来的（1→0.255、2→0.363、3→0.450），2 档最接近 0.389 且目视与旧图同质感。

**顺带修掉一个命名 bug**：生成脚本输出的文件名缺 `_v001` 后缀（如 `ui_fate_card_overclock.png`），而游戏按 `ui_fate_card_<id>_v001.png` 加载 —— 18 张会全部加载失败而静默回退程序卡面，表现为"补了图却没用"。已批量重命名修正。

最终：**48/48 全量覆盖，零缺图、无孤儿文件**。缺图回退分支保留为容错（将来新增卡牌若无美术仍能降级运行）。

## 10. 🔴 补跑真实游戏流程验收，发现并修复一个功能 bug（2026-10-09 追加）

主人追问「游戏内是否已经带入？出现命运卡片的时候是新的资产？」——这个追问是对的。**此前两轮我都没有在真实游戏流程里验证过接线**，只用独立探针验证了 `FateCardView` 的渲染。补跑 `verify_reference_hud_fate_visual`（它真实实例化 `Dungeon3D` 并打开三选一覆盖层）后，**48 项失败**。

### 10.1 根因：meta 挂错节点 → 卡片永远点不动

`_create_reference_fate_card_view()` 把 `tarot_button` 挂在**按钮**上就返回了「卡片列」容器，而调用处却从**列容器**上读这个 meta：

```gdscript
# 函数内
button.set_meta("tarot_button", button)
return column                      # ← 返回的是列，不是按钮

# 调用处
var card_button := card_view.get_meta("tarot_button") as Button   # ← 从列上读 → null
if card_button != null:            # ← 永远不成立
    _play_reference_tarot_flip(...)  # ← 翻牌动画整个不执行
```

三个入口（`Dungeon3D` / `DivinationMenu` / `WorkbenchPanel`）**全部中招**。后果不是"少个动画"，而是：

`button.disabled = true` 在卡片创建时设置，**只有翻牌动画完成时的回调才会解除**。动画不执行 ⇒ `disabled` 永远为 true ⇒ **卡片在游戏里根本点不动，翻不出正面**，玩家看到的是一排无法交互的卡背。

这是静默失败——不报错、不崩溃，功能直接不可用。

### 10.2 修法

meta 同时挂到返回的列容器上（按钮上保留一份供动画内部使用）。

### 10.3 连带发现的两个坑

| 坑 | 现象 | 正解 |
|---|---|---|
| **`get_meta(key, null)` 仍报错** | 默认值本身是 `null` 时，Godot 仍打 `The object does not have any 'meta' values with the key ...`。C++ 里以 `p_default != Variant()` 判有无默认值，nil Variant 不满足 | 用 `has_meta()` 守卫，或传非 null 默认值 |
| **卡尺寸漏乘 `HUD_UI_SCALE`** | 按设计值给了 326×508，但 `_hud_size()` 会再乘 `HUD_UI_SCALE = 0.80` ⇒ 实际 260.8×406.4，比验收基线（高度 ≥420）小 | 设计值给到 346×546，实际 276.8×436.8 |

### 10.4 验收脚本按新契约重写并**加严**

删掉了与新设计冲突的断言（要求无 `TextureRect`、要求文字层含作用域/方位/卡名），换成新契约，且比原来更严：

| 新断言 | 查什么 |
|---|---|
| `_check_fate_card_art()` | 卡面层存在且可见；**贴图路径必须与这张牌 identity 对上**（`ui_fate_card_<stable_id>_v001.png`）——防"图装错牌"，光看"有没有 TextureRect"是查不出来的 |
| | 不得回退到程序卡面（有图却走了回退 = 加载失败） |
| | 卡背层存在且翻面后隐藏 |
| `_check_tarot_caption_upright()` | 卡下功能文字存在、非空、**正向可读** |
| 逆位 | **只**卡面图案层倒置（180°），按钮与文字都不旋转 |

为支撑"图不能装错牌"这条，三个入口的卡片按钮新增 meta `tarot_stable_card_id`。
