## 三个真缺口（都不是"加功能"，是原来就漏了）

### ① 子图房间四面封闭，玩家进第一间就走不动

`_build_box_room` 建的是地板 + 四面实墙，注释写着「子图房间之间靠传送走」。但代码里只有「入口门 → 第 1 间房」和「出口门」两个传送区 —— **房间之间一个都没有**。

后果：玩家打破入口木板 → 传送到第 1 间房 → 卡住。房数、位点、配对、存档全部正常，没有任何断言能发现。

修法：`_build_chain_gates` 给第 i 间房东墙内侧放一道门，目标 = 第 i+1 间房中心。

### ② 出口门在主图那侧，玩家进了子图够不到

`exit_gate` 挂 `exit_door` 上，而 `exit_door` 在主图出口房间的墙上。玩家在子图里根本碰不到那块门板 ⇒ **进了出不来**。

修法：`_build_return_gate` 在最后一间房东墙内侧放一道门，目标 = 主图出口房间内侧。

### ③ 门的朝向反了：木板朝墙外凸

```
错误：rotation.y = atan2(-normal.x, -normal.z)   # asset -Z 对齐 outward
```
`-normal` 是**指向房间外**，所以木板凸到墙外、门腔反而插进房间 —— 玩家在房里看到的是那扇半掩门，看不到钉死的木板。

正确：`rotation.y = atan2(normal.x, normal.z)`，让 asset `-Z` 对齐「指向房间内」。

这个错**资产包围盒看不出来**（它只报尺寸不报朝向），第一阶段靠 AABB 数值验收时是绿的，只有进游戏看才会发现。

## 一个隐性口径偏差

`_count_cleared_content_rooms` 原排除表：`START / EXTRACTION / ELEVATOR / FACILITY`。

但运行时 `room_type` 是**语义类型**（`COMBAT` / `SCAVENGE` / `STORAGE` / `EVENT` / `BOSS` / `STAIR_LOBBY` / `EXTRACTION`），设计源里的 `COMMON_ROOM` 到这里已经不存在。实测：

```
start       type=STAIR_LOBBY   cleared=true   ← 被算成内容房
extraction  type=EXTRACTION    cleared=false  ← 正确排除
```

于是：
- 内容房总数虚高到 **12**（实际 11）
- 已清数**开局就是 1** ⇒ 所有木板白送 20 血（HP 80 而不是 60）、撤离门白送 1 点进度

补 `STAIR_LOBBY` 与 `SAFE_ROOM` 后：总数 **11**、开局 **0**、阈值 `ceil(11×0.4)=5`。

设计文档里原写的 `ceil(10×0.4)=4` 是旧数据（当时 7 房版），已按实测改为 5。

## 实现要点

**锁定态**（`SecretDoor3D`）

- `set_locked(v)` / `is_locked()`；锁定只拦 `take_damage`，**木板照常显示** —— 玩家知道「这里有东西」，但打不开。
- 锁定受击发 `hit_locked(site_id)` 而不做提亮：提亮会让玩家以为快打穿了，而它一点没掉。
- `export_state` 带 `locked`。少了它，读档后入口木板会在入口房还没清的时候变成可破。

**解锁时机**（`Dungeon3D`）

`_mark_room_cleared` 在 `not was_cleared` 分支里调 `_refresh_secret_locks_after_clear()`，只做解锁、不做重锁。放在这里而不是每帧轮询 —— 这两个值只会随清房变化。

**撤离门**（`SecretBranch3D`）

- 装在**第一间房北墙**（不是随便挂一个 `Area3D`）：`_build_extraction_room` 现在建「门 + 门后房间 + 门后传送区」，与入口同一套语义。
- 门坐标按该房自己的尺寸算，不写死 12.5 —— 房型池有 25×25 / 30×25 / 25×30，按固定半深会在 25×30 上把门放到墙外。
- `total <= 0` 时保守判锁：宁可锁着，也不要在错误进度上开门。

## 一个差点写假绿的地方

A11 最初写成「锁定态 == 应该解锁」。它**抓不到阈值失效**：装配时房间还没建完，`_extraction_unlocked()` 先走 `total <= 0` 分支直接 `return false`，阈值比较压根没执行，所以「锁着」这个结论是对的、但原因是错的。

第一次注入 `>= 0` 时 A11 仍然是绿的 —— 因为这个假绿。

改成**主动驱动行为**才抓到：进度不足时调一次 `refresh_extraction_locks()`，断言门必须仍然锁着。这条会真正经过阈值比较。

教训：**断言要打在行为上，不要打在状态上**。状态可以因为别的路径碰巧正确。
