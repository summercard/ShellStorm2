# 战局房间美术制成与导入链路

状态：`BATTLE-ROOM-ART-PIPELINE r2`（2026-09-30 文档修订，工程 0.1.0）。
适用范围：塔楼战斗区与独立远征的房型组件、房间变体、具体房间和 Godot 视觉装配。

本页保留 2026-09-18 链路的交接与替代记录；现行生产规则归[10.1 场景美术生产流程](../10.1_3D场景美术生产流程.md)，关卡结构归[05.2](../05.2_关卡版图白盒与生成规范.md)，远征01目标与接入状态归[主设计](../design/远征关卡01设计.md)。本次只修订文档，不代表工具或运行资产已实现新目标。

## 1. 总原则与旧规则替代

```text
关卡设计 / 白盒：房型、房号、尺寸、端口、连接、净空
  -> 02 建模前冻结组件计划
  -> 01 用组件母版与实例制作 Blender 房型源
  -> 组件 GLB / 稳定 Godot PackedScene 导入与验收
  -> 03 选择：直接继承 / Godot 房间变体 / Blender 差异布局
  -> 04 首次装配与接入
  -> 正式模块化房间 TSCN：在 Godot 维护布局、灯光、启用和实例参数
  -> 分阶段登记、运行验收、关卡调用
```

编号表示职责，不表示必须依次做完 01 整屋再执行 02。**02 的组件计划必须先于 01 正式建模**；03 可直接继承，不能强制为每个房号重建 Blender 整屋。

| 编号 | Skill | 当前职责 |
|---:|---|---|
| 00 | `00-battle-room-layout-assembler` | 总入口，识别已有产物并路由 |
| 01 | `01-battle-room-type-art-authoring` | 依冻结计划制作组件母版与房型默认实例 |
| 02 | `02-battle-room-component-decomposer` | 建模前规划、组件归并与实例清单；兼容历史整屋整理 |
| 03 | `03-battle-room-instance-layout-authoring` | 直接继承，或选择 Godot 房间变体 / Blender 差异布局 |
| 04 | `04-battle-room-runtime-assembler` | 组件导入衔接、房间首次装配与正式接入，不覆盖房间编辑权 |

| 2026-09-18 旧口径（保留追溯） | 已替代为 |
|---|---|
| 先做房间种类整屋，再拆共享组件 | 建模前冻结组件计划，房型源由组件母版与实例拼装 |
| 具体房间必须新建 Blender 布局 | 可直接继承默认或在 Godot 维护房间变体/具体房间；Blender 差异源可选 |
| Blender 布局唯一，Godot 不得手摆 | 正式房间 TSCN 拥有房内编辑权；JSON 负责初始化与来源追溯 |

| `block_id` 仅塔楼四区块 | 塔楼四区块继续兼容；远征使用 `expedition` 与 `Blocks/Expedition` |

组件只生产一次。禁止每房复制墙、地板、门、设施网格或整屋 GLB；手调房间实例不等于复制组件几何。

## 1.1 过程产物与运行资产目录

过程源留在工程内，`outputs/` 只作临时报告、预览和验收输出；运行路径不含版本号。

source/art/whitebox/tower_zones/<level_id>/v###/

远征01现有 13 份正式房间场景集中在上面的 `room_instances/expedition_01/`；旧 `runtime/room_instances/f00_<room>/` 的 manifest/acceptance 是历史来源与验收记录，不因此成为房内布局唯一真源。通用变体登记目录/schema 尚未实现，不虚构已经存在的注册表。

| 产物 | 所有权 / 消费方式 |
|---|---|
| L1/L2/L3、白盒 `.blend` | 关卡结构契约与过程输入，不作为运行模型导入 |

## 2. 房间数据层与三层复用

**房型 → 房间变体 → 具体房间**是复用目标，和关卡版图 L1/L2/L3 是两组不同层次：

- 房型定义结构接口、组件集合与默认布局，不绑定具体房号。
- 房间变体复用同一套组件，只改变允许的布局、灯光、启用或实例参数；可直接继承默认，也可在 Godot 维护，不要求制作新的整屋 Blender。
- 具体房间选择房型/变体并接受关卡位置、连接与玩法身份；固定选择合法，不要求每局随机。
- 新目标是通过数据登记选择关系与正式场景，由通用解析器消费。**当前 `FloorPlanGenerator.ROOM_INSTANCE_LAYOUT_SOURCES` 对 `room_03` / `room_04` 仍是硬编码字典**，不是已完成的通用变体系统；不得把新增更多房号分支当作目标方案。

2026-09-18 的塔楼目标表（2 安全房 / 14 通用房 / 1 Boss 房 / 1 个 30×30 撤离房）仅作历史，不再套到远征01。远征01为安全屋 + 10 内容房 + Boss + 撤离屋，共13房；8个模板、尺寸和端口以主设计与现有 L1/L2/L3 为准。撤离屋当前尺寸25×25，不采用旧30×30默认值。

撤离信标仍是固定设施视觉组件，唯一且不可拾取；激活、撤离判定、计时、结算归玩法层。房间壳体接入不能证明信标及完整周界碰撞已经验收。

## 3. 五类阶段职责

### 阶段一：房型组件规划（02，先于建模）

输入房型、白盒、尺寸/端口/净空、概念图与可复用组件。冻结不超过50个组件的计划；同族常规最多3个，有明确状态轴最多5个。输出组件职责、AssetID、原点、方向、包络、碰撞责任和默认实例计划。历史整屋可按此归并，但新生产不先做整屋再拆。

### 阶段二：组件母版与房型默认实例（01 + 02交接）

按冻结计划建立组件母版，房型 `.blend` 只用母版与链接实例拼装；输出组件源、catalog、manifest、默认 `component_instances.json` 和美术验收。不得从具体房号反推伪通用件，组件不携带房间世界坐标。

### 阶段三：房间继承与差异（03，可选）

默认直接继承房型。需要差异时选择在 Godot 维护房间变体/正式房间，或制作只含链接实例的 Blender 差异布局与 `room_layout.json`。不用为默认房间新增 Blender 文件，不生成房间专用几何；门洞、尺寸、连接与净空变化必须回关卡结构契约审查。

### 阶段四：Godot 组件导入

将验收合格的组件逐件导出稳定 GLB / PackedScene，完成碰撞、材料、独立加载和账本登记；使用 `godot-model-asset-import-standard`。资产域由 `assets/registry/ledger_index.json` 路由，不另造台账。组件转正后可以供多个房型/变体/房间复用，但不能据此把所有引用房间自动标为已接入。

### 阶段五：首次装配与正式房间维护（04）

首次装配可以重放房型默认 `component_instances.json`、Blender 差异 `room_layout.json`，也可以按白盒用已转正组件直装；已有正式 Godot 房间则直接维护其 TSCN。历史路由名 `room_type_layout_replay` / `blender_layout_replay` / `whitebox_direct_assembly` 继续作为来源追溯，不限制后续 Godot 手调。

房间只拥有顶层 PackedScene 实例根，保留组件内部封装。JSON 不是唯一运行布局源；运行时加载正式 TSCN 后不再构建第二套静态布局。门状态机、触发器、刷怪、导航、流送、存档、交互与撤离继续由代码负责。

## 4. 所有权与更新保护

| 内容 | 所有者 |
|---|---|
| 房间身份、尺寸、门洞、连接、净空 | 关卡/白盒结构契约 |
| 组件几何、材质、原点、包络与接口 | Blender 组件源 |
| 房型默认实例 JSON / 房间差异 JSON | 初始化与来源追溯，不覆盖正式房间手调 |
| 房内布局、灯光、启用、实例参数 | Godot 正式房间 TSCN |
| 游戏中灯开关、门、敌人、掉落、存档、撤离状态 | 玩法/规则层 |

**规范要求：组件更新不覆盖房间编辑。** 通常仅替换稳定组件资源并保留房间实例变换与覆写；涉及原点、包络、插槽等接口变更时先核对受影响房间。不要为更新一个组件顺手重生成整房。

**工具现状：尚无自动合并保护。** `scripts/generate_expedition01_room_static_scenes.gd` 会关闭静态 TSCN 加载、从动态装配重建，再 `ResourceSaver.save` 到原路径；`SS_STATIC_ROOMS` 只限制房号，选中的房间手调仍会被覆盖。禁止未审查重生成正式 TSCN。确需重建时必须先保全现有文件与差异、审阅候选、人工合并房间编辑，并重新检查组件引用、灯光、启用、碰撞与端口；这是人工流程约束，不是已经实现的自动三方合并。

## 5. 状态与失败门禁

源完成、组件转正、房间接入必须分别记录，不因其中一项完成自动提升另外两项。标准房 `std_25x25` 的82实例源（25地砖 + 18实墙 + 2门墙 + 37陈设）已完成；复用组件可有各自验收，但该82实例布局尚未转正为正式房间，当前 `room_07` 是通用壳体 TSCN 接入。

遇到以下情况停止相应生产/接入操作：

- 房型、变体与具体房号混用，或把硬编码字典宣称为数据登记完成；
- 美术改写结构端口、尺寸、净空而没有同步结构契约；
- 房间复制共享网格、展开组件内部 owner 或输出整屋 GLB；
- 组件缺稳定 AssetID、路径、原点、包络、方向或碰撞责任；
- 用非单位缩放掩盖接口不匹配；
- 撤离信标缺失/重复，或用壳体接入冒充完整设施验收；
- 源文件完成却把旧运行资产算成已替换；
- 未审查重生成正式房间 TSCN，或组件更新覆盖房间手调；
- 账本未按 `ledger_index.json` 路由，或验收不能证明实际组件来源。

## 6. 调用与范围

用户可要求制作房型、建模前规划组件、整理历史整屋、直接继承房型、在 Godot 调整房间变体/实例，或首次接入。交付说明实际采用的路径与来源，不能为了满足旧路由名强制新建 Blender 整屋。

本链路只涉及场景美术与组件/房间装配；角色、武器、道具、敌人、战斗、任务、存档、结算、导航与玩法规则仍由各自流程负责。
