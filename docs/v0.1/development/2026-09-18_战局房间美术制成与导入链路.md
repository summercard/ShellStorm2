# 战局房间美术制成与导入链路

状态：`BATTLE-ROOM-ART-PIPELINE r1`
适用范围：ShellStorm2 战斗区块的房间种类美术、房间组件拆解、具体房间布局、Godot 视觉装配。

## 1. 总原则

```text
关卡数据定义房间实例
  -> 房间种类美术源                       [01-battle-room-type-art-authoring]
  -> 房间种类源拆解为可复用组件             [02-battle-room-component-decomposer]
  -> 分支 A：具体房间 Blender 布局          [03-battle-room-instance-layout-authoring]
  -> 分支 B：组件 GLB / Godot PackedScene 导入  [godot-model-asset-import-standard]
  -> 第五阶段分支 1：Blender 布局 + Godot 组件重放  [04-battle-room-runtime-assembler]
  -> 第五阶段分支 2：白盒 + Godot 组件直装          [04-battle-room-runtime-assembler]
  -> 具体房间运行时美术装配
  -> 关卡调用
```

Skill 顺序与编号一一对应，编号即执行顺序：

| 编号 | Skill | 职责 |
|---:|---|---|
| 00 | `00-battle-room-layout-assembler` | 兼容总入口，按用户意图路由到 01–04 |
| 01 | `01-battle-room-type-art-authoring` | 房间种类 Blender 美术源 |
| 02 | `02-battle-room-component-decomposer` | 房间种类源拆解为共享组件源 |
| 03 | `03-battle-room-instance-layout-authoring` | 具体房间编号 Blender 布局 |
| 04 | `04-battle-room-runtime-assembler` | Godot 最终装配双分支路由 |

原则：组件只生产一次；房间种类定义可复用美术；具体房间只保存布局；Godot 只实例化稳定组件并重放布局。禁止每个房间复制一套墙、地板、门、设施或整屋 GLB。

## 1.1 过程产物统一目录契约

战局场景美术过程产物统一放在 `ShellStorm2` 工程内，按“白盒 / 房间种类源 / 共享组件源 / 具体房间编号源 / Godot运行资产”分层。不要把过程源文件放进 `outputs/`，`outputs/` 只用于对话交付的报告、预览图、验收 JSON 和 Skill 压缩包。

```text
ShellStorm2/
├─ source/art/whitebox/tower_zones/<level_id>/v###/
│  ├─ data/                         # 白盒 JSON、房间清单、校验输入
│  ├─ blender/                      # 与 data 同版本的白盒 Blender 源
│  ├─ renders/                      # 顶视图、立面、剖面、无文字图
│  └─ validation/                   # 白盒尺寸、连接、碰撞、导航验收
│
├─ assets/art/environments/tower_zones/<block_id>/source/
│  ├─ room_types/<room_type>/v###/  # 房间种类 Blender 源：COMMON/SAFE/BOSS/EXTRACTION
│  │  ├─ *.blend                    # 房间种类源文件
│  │  ├─ renders/                   # 房间种类美术预览
│  │  ├─ qa/                        # 范围锁定、材质、UV、包络验收
│  │  └─ room_type_manifest.json    # 房间种类定位和拆解清单
│  │
│  ├─ common_components/v###/      # 从房间种类源拆解出的共享组件源
│  │  ├─ *.blend                    # 组件库母版
│  │  ├─ component_catalog.json
│  │  ├─ component_packages/        # 各组件 manifest 与树
│  │  ├─ renders/
│  │  └─ qa/
│  │
│  └─ room_instances/<room_id>/v###/ # 具体关卡编号的布局源
│     ├─ *.blend                    # 只含链接组件/Collection Instance 的布局源
│     ├─ room_layout.json            # Blender → Godot 共同布局清单
│     ├─ renders/
│     └─ qa/
│
├─ assets/art/environments/tower_zones/<block_id>/components/
│  └─ <component_slug>/<component_slug>_visual_top3d.glb
│
└─ assets/art/environments/tower_zones/<block_id>/runtime/
   ├─ common_components/<component_slug>/<component_slug>_root_top3d.tscn
   └─ room_instances/<room_id>/       # 只放运行时房间装配登记/验收，不放整屋视觉 GLB
```

目录职责必须保持不变：

| 产物 | 唯一归属 | 是否进入 Godot 导入 |
|---|---|---:|
| 白盒 JSON / 白盒 `.blend` | `source/art/whitebox/...` | 否 |
| 房间种类 Blender 源 | `source/.../room_types/...` | 否 |
| 共享组件 Blender 源 | `source/.../common_components/...` | 否 |
| 具体房间编号布局 `.blend` / `room_layout.json` | `source/.../room_instances/<room_id>/...` | 否，Godot读取布局清单 |
| 组件 GLB | `components/...` | 是 |
| 组件 PackedScene | `runtime/common_components/...` | 是 |
| 房间运行时装配登记和验收 | `runtime/room_instances/<room_id>/...` | 由运行时装配器读取 |

统一定位字段必须出现在白盒、房间种类 manifest、组件 manifest、`room_layout.json` 和运行时登记中：`block_id`、`level_id`、`room_type`、`room_id`、`AssetID`、`source_version`、白盒源路径、组件源路径和 `asset_ledger`。

已迁移的历史资产：入口安全房位于 `source/room_instances/entry_safe_room/v006/`、`v007/`，主路内容房02位于 `source/room_instances/main_room_02/v003/`；通用组件库继续位于 `source/common_components/v###/`。三类源文件的正式文件名统一为英文 `snake_case` 加 `_vNNN`：`env_battle_l01_safe_entry_layout_source_v007.blend`、`env_battle_l01_main_02_data_room_layout_source_v003.blend`、`env_battle_common_components_source_v006.blend`。旧的 `source/entry_safe_room/` 与 `source/main_room_02/` 路径已不再作为正式引用；新任务继续按上面的 `room_types/`、`common_components/`、`room_instances/` 目录创建。迁移资产必须同步更新 manifest、catalog、台账、Godot 引用和验收记录，不能只移动文件。

## 2. 房间数据层

局内关卡01的目标房间集：

| 房间种类 | 数量 | 说明 |
|---|---:|---|
| `SAFE_ROOM` | 2 | 已有安全房方向样板 |
| `COMMON_ROOM` | 14 | 通用房，具体实例由 `room_id` 区分 |
| `BOSS_ROOM` | 1 | BOSS 房，尺寸按白模与关卡设计 |
| `EXTRACTION_ROOM` | 1 | 新增撤离房，默认 30×30m，必须有 1 个撤离信标 |

本表是场景美术链路必须支持的房间类型目标。真正修改 `FloorPlanGenerator`、房间拓扑、撤离条件、结算或存档，必须另开关卡/玩法任务；本链路只消费已确认的白模和关卡数据。

### 撤离房最低契约

```text
room_type = EXTRACTION_ROOM
nominal_dimensions_m = [30.0, 30.0]
required_facility = extraction_beacon
beacon_count = 1
beacon_pickup = false
```

撤离信标是固定场景组件，不是可拾取道具。视觉组件只提供模型、原点、包络和可选激活挂点；激活、撤离判定、条件、计时和结算由玩法层负责。

## 3. 五个阶段与专用 Skill

### 阶段一：房间种类 Blender 美术源

输入：房间种类、白模、尺寸/门洞/净空、效果图和视觉需求。

输出：版本化房间种类 `.blend`、房间种类 manifest、渲染验收图和可拆解对象清单。

使用：`01-battle-room-type-art-authoring`，内部沿用 `blender-game-prop-standard`。

示例：

```text
使用 blender-game-prop-standard，按撤离房白模制作 30×30m 撤离房种类，包含撤离信标视觉组件。
```

### 阶段二：房间种类源拆解

输入：阶段一已通过验收的房间种类 Blender 源。

输出：按墙、地、门、固定设施、装饰、环境支持、撤离信标分类的组件 Blender 源、catalog 和 manifest。

使用：`02-battle-room-component-decomposer`。

硬约束：不能从具体房间编号反推伪通用组件；组件不能携带具体房间世界坐标；所有组件必须有稳定 AssetID、原点、包络、方向、旋转和碰撞责任。

### 阶段三：具体房间 Blender 布局

输入：具体房间编号白模、对应房间种类组件源、房间需求/效果图。

输出：具体房间 Blender 布局源和 `room_layout.json`。

使用：`03-battle-room-instance-layout-authoring`。

示例：

```text
按 main_02 白模和通用房组件，制作通用房02的 Blender 布局。
```

硬约束：房间文件只保存链接组件实例和布局，不生成房间专用组件；不得把房间整屋导出成 Godot 视觉资产。

### 阶段四：Godot 组件导入

输入：阶段二的组件 Blender 源。

输出：稳定路径 GLB、Godot PackedScene、导入清单、资产账本登记和独立加载验收。

使用：`godot-model-asset-import-standard`。

目录契约：

```text
source/       版本化 Blender 源
components/   稳定路径 GLB，不带版本号
runtime/      稳定路径 PackedScene，不带版本号
```

Godot 组件导入必须通过资产分账本和 `assets/registry/ledger_index.json` 定位，不得重新建立第二份台账。

### 阶段五：具体房间最终运行装配

使用：`04-battle-room-runtime-assembler`。

#### 分支 1：Blender 布局重放

条件：具体房间存在合格的 `room_layout.json`，且布局引用的所有组件已经导入 Godot。

```text
room_layout.json
  + 组件 AssetID 注册表
  + 稳定 PackedScene
  -> Godot 按实例位置/旋转/单位缩放重放
  -> 具体房间运行时美术
```

Blender 布局是视觉摆放事实源，Godot 不得再次手工摆一套。

#### 分支 2：白盒直装

条件：具体房间还没有 Blender 布局，但有白盒和完整的房间种类组件运行资产。

```text
白盒尺寸/门洞/连接
  + 组件 catalog / PackedScene
  -> Godot 生成基础结构布局
  -> 文字/效果图用于选择和排序视觉组件
  -> 生成或暂存 room_layout.json
  -> 运行时验收
```

白盒直装只保证白盒结构和组件契约；如果需要精确构图、密度、遮挡和效果图还原，必须回到阶段三生成 Blender 布局，再切到分支 1。

## 4. 资产所有权边界

| 内容 | 所有者 |
|---|---|
| 房间尺寸、门洞、连接、净空 | 白盒/关卡数据 |
| 房间种类造型 | 房间种类 Blender 源 |
| 可复用几何、材质、原点、包络 | 组件 Blender 源 |
| 具体房间的实例位置 | 具体房间 Blender 布局 |
| GLB / PackedScene | Godot 导入链路 |
| 视觉运行时重放 | 通用房间装配器 |
| 敌人、战斗、掉落、存档、撤离判定 | 玩法/规则层，不属于本链路 |

## 5. 失败门禁

任何阶段遇到以下情况停止：

- 房间种类和具体房间编号混用；
- 白模尺寸、门洞、净空被美术源改变；
- 房间源复制共享 Mesh 或输出整屋 GLB；
- 组件缺少 AssetID、原点、包络、方向或稳定路径；
- Blender 源版本高于 Godot 已接入版本却继续用旧资产冒充完成；
- 组件或布局使用非单位缩放掩盖接口不匹配；
- 撤离房缺失或重复撤离信标；
- Godot 需要新增具体房间专用拼装函数；
- 任务尝试修改玩法/规则/存档/战斗文件；
- 账本没有通过 `ledger_index.json` 路由；
- 运行时验收无法证明实际实例来自对应组件。

## 6. 用户调用方式

### 制作房间种类

```text
使用 blender-game-prop-standard，制作通用房种类，按这个白模和效果图深化。
使用 blender-game-prop-standard，制作 30×30m 撤离房种类，必须包含撤离信标。
```

### 拆解组件

```text
把这个撤离房种类 Blender 源拆成可复用组件。
把通用房种类拆解成组件文件，准备导入 Godot。
```

### 制作具体房间布局

```text
用通用房组件拼装通用房02的 Blender 源。
按撤离房白模制作 exit_01 的 Blender 布局。
```

### 最终接入 Godot

```text
把通用房02接入 Godot。
用白盒直装 branch_03。
拼装撤离房 exit_01。
```

Skill 必须在回复中明确实际走的是：

```text
blender_layout_replay
```

或：

```text
whitebox_direct_assembly
```

## 7. 不污染其他流程

本链路只允许触碰场景美术资产、组件导入、布局清单、场景账本、通用视觉装配器和验收测试。角色、武器、道具、敌人、战斗、任务、存档、结算、导航和规则类流程继续由各自 Skill 与代码负责。
