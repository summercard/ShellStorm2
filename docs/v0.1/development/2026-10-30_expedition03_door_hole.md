# 远征03 门洞处的黑幕（2026-10-30）

## 1. 业主报单（原文）

> 「想办法把门的位置不要有黑幕」

前置状态：2026-10-29 为了修"进门能看见外面房间"，把幕墙**整圈密闭**了 ——
门洞也被一起封上，镜头夹取保留。于是门洞里是一块黑。

## 2. 定位：那块黑其实有两层

先把"门的位置有黑幕"拆成两种可能，各用一次取证：

| 假设 | 判据 | 结果 |
|---|---|---|
| 门后本来就没光（连通小间无灯） | 数 `WastelandLight3D` / `OmniLight3D` | 5×5 的 `cr*` 里 8/9 间计数为 0 ⇒ 成立，但不是主因 |
| 幕墙盖在门洞上 | 把四面幕墙逐片隐藏后看像素 | 黑块**不消失** ⇒ 不成立（这次的逐片隐藏测法有帧刷新问题，见 §5） |

真正定位靠**三角形屏幕投影**：把南片幕墙的每个三角形投到屏幕上，
发现 `y = [2.50 .. 26.00]` 那一段正好压在黑块上（屏幕 y 197..348）。

**结论：那块黑是门洞上方的"过梁段"幕墙** —— 从门洞净高 2.5m 一直拉到幕墙上沿 26m。
相机在 10.26m 斜俯视它，屏幕上就是门洞正上方一大片黑。

于是两件事都得做：

1. 幕墙在门洞处开口（含上方，不留过梁段）；
2. 门后那间补光，否则洞开了也是看进没光的盒子。

## 3. 改法

### 3.1 洞的位置：读门扇实际几何，不读 `lane_m`

第一版按 `wall_door_lane_<side>` / `wall_door_openings_<side>` 切洞。实测那间
25×25 的 `boss_foyer`：

```text
DIAG lanes=[0.0]                      ← 声明：墙面中心
DIAG door_panel DoorPanel      pos=(-1.71, 1.25, 0.0)  gp=(70.79, 1.25, -70.0)
DIAG door_panel DoorPanelRight pos=( 1.71, 1.25, 0.01) gp=(74.21, 1.25, -69.99)
DIAG node FlowViewWallsSouth holes=[(75.8, 79.2)]     ← 洞开在 +5m，门在 ±1.7m
```

洞开在空心，门洞正对的那块幕墙原封不动 —— 白改一轮。

改成 `DungeonRoom3D.get_wall_door_lanes(side)` 直接量 `RoomDoor3D.global_position()`：

```text
DIAG lanes=[-5.0]                     ← 实测：中心偏 −5m
DIAG node FlowViewWallsSouth holes=[(70.8, 74.2)]     ← 对上
```

同侧多门（EGT 枢纽）也天然覆盖（全树扫描拿全部门扇）；只有在门扇还没建出来时
（装配早期）才退回声明值。

### 3.2 洞的上沿：三个边界试了两遍才定在墙顶

```text
2.5m（门洞净高）  门洞上方 2.5→26m 是一堵悬空黑墙，比墙顶低 0.3m      ❌ 悬空黑块
26m（幕墙上沿）   洞上方的口子通到天，越过 2.8m 墙顶的视线从洞里穿出  ❌ 漏斗状亮梯形
2.8m（房间墙顶）  洞只开到"门洞→自己房间墙顶"，以上与其他三面同判据   ✅ 当前
```

第三轮（业主「为什么上面有一块」的截图）暴露的就是 26m 那一版：红框里的梯形正是
**门后那间的墙面**，被俯视视线越过自己房间的 2.8m 墙顶、从门洞上方的口子看穿。

为什么开到墙顶仍能看见门后（这就是"洞不用开到顶"的定量依据）：相机 10.26m、
门洞净高 2.5m，穿过门洞的视线在幕墙平面（墙外 0.16m）上的高度最大约

```text
2.5 − (10.26 − 2.5) × 0.16 / 5.5 ≈ 2.28m
```

远低于 2.8m 的洞上沿 —— 门洞方向不会被幕墙挡，而墙顶以上照挡。

实测像素级漏光从 `65`（挖到顶）降到 **`2`**（收到墙顶）。

### 3.3 洞宽：视差余量 0.60m 是算出来的

幕墙贴在墙外表面外 `off = 0.14 + 0.02 = 0.16m`，即比墙中心面再远 0.30m。
门洞开口在幕墙平面上的投影以镜头为中心放大，放大率 `(d + 0.30) / d`，d = 镜头到墙中心面的水平距离。
镜头被夹取保证不超过房间内缩 0.55m，最近可贴到 `d = 0.55`：

```text
半宽 1.1m × (0.55 + 0.30) / 0.55 = 1.70m  ⇒ 每侧要多让 0.60m
```

洞**偏大无害**：幕墙贴在墙垛外侧，穿过"洞内、但墙中心面落在门洞外"的视线会先撞上墙垛
（实体墙，不透明），看不到那块幕墙。洞**偏小就是一条黑边**。

### 3.4 门后小间补光

`_ensure_flow_passage_lighting()`，判据用几何（`max(x,y) ≤ 8m` + flow 开关），不认 room_id：

| 项 | 值 | 依据 |
|---|---|---|
| 范围 | 4.5m | 5×5 小间半对角 3.54m，刚好照满自身、不外溢到隔壁大房 |
| 能量 | 3.0 | 小间 25㎡，与房间地面同档亮度 |
| 高度 | 2.35m | 低于门洞净高 2.5m，从隔壁看进来是平铺环境光 |

⚠️ 范围不能放大：`gl_compatibility` 每物体最多 8 盏灯，9m 范围会让九盏灯盖住隔壁
战斗房、把房间顶灯挤出预算，房间反而更暗（上一轮实测过）。

## 4. 验收

```text
PLAYABLE camera_clamp cases=104 outside=0 height_drift=0.000
PLAYABLE curtain rect=[P:(69.84,-70.16) S:(5.32,5.32)] y=[-1.00..26.00] cam_y=10.26
PLAYABLE curtain_door_holes=2 lanes=2 covered_bad=0
PLAYABLE curtain_area=853.3 expect=853.3 (full=879.1 hole=25.8)
PLAYABLE curtain_always_on cam_outside_visible=true
PLAYABLE wall_leak=2 limit=500
PLAYABLE_OK
```

三条新断言，缺任一条都会让"门的位置还有黑"能偷偷过：

| 断言 | 判据 |
|---|---|
| `curtain_door_holes == lanes` | 门洞数 == 墙体门洞数（该开的地方开了没有） |
| `covered_bad == 0` | 每个洞覆盖「门中心 ± 门洞净宽/2」（开够宽，不是一条缝） |
| `curtain_area == 整面 − 门洞` | 两边都要对：开小了是黑块，开大了是漏 |

面积判据特意**两边都查**：上一轮只查"是否等于整面"，改动后若只查"小于"会漏掉
"洞开过头、把该挡的地方也挖掉"。

## 5. 踩的坑（都是诊断方法本身的坑）

| 坑 | 表现 | 处理 |
|---|---|---|
| 逐片隐藏幕墙看像素 | 四面都返回同一个亮度（0.44），看起来"四面都没变" | 截图取图与帧刷新不同步，隐藏不生效。改用**光线 × 三角形求交**做确定性判定 |
| 近黑材质反查 | 黑块坐标落在幕墙 AABB 里，但 AABB 覆盖整面，无法定位到三角形 | 改为把每个三角形投影到屏幕、判断是否包含目标像素 |
| 按 `lane_m` 切洞 | 洞与门差 5m，且探针 `covered_bad=0` 误通过（探针当时读的是同一份 lane） | 洞位置改读门扇几何；探针覆盖判据改为读幕墙 meta 里的洞区间 |
| 面积判据硬编码 `DOOR_CLEAR_HEIGHT_M` | 洞挖到顶后面积对不上（695.5 vs 855.3） | 洞顶由幕墙写进 meta（`view_wall_hole_top`），探针读 meta |
