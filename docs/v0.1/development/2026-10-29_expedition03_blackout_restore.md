# 远征03：黑色覆盖还原 + 镜头改为瞬时夹取（2026-10-29 晚）

> 本文承接同一天的 [过门镜头不再弹 / 幕墙门洞留口](2026-10-29_expedition03_door_curtain.md)。
> **那一版被推翻了一半**：门洞留口与"镜头出门收起"都要回退。这里记录为什么、以及最终形态。

## 1. 业主报单（原文）

> 「进门的时候会看到外边的房间。这个也不合理啊。黑色覆盖的时间还是先还原吧。」

随后**更正了范围**：

> 「我只要你把黑幕的出现时机还原……你怎么都还原了……摄像机镜头碰撞这个怎么也给我加回来了。」
>
> 「别改了。这个黑幕是垂直的啊 摄像机碰撞这个别改了。保留。」

**只还原幕墙。镜头夹取保留。** 第一版我把相机侧的夹取也一并恢复，是过度还原。

附两张截图：一张是进门瞬间，画面里能看到当前房间之外的地面与墙体；另一张是房间内视角，
门外那一片没有被遮住。

## 2. 为什么上一版必错

上一版（同日早晨）做了两件事，都把"房间边界"打开了：

| 改动 | 当时的理由 | 后果 |
|---|---|---|
| 幕墙在门洞处切口 | 「过门直接看到下一个房间的东西」 | 洞口对着的正是外面那间 ⇒ 门洞里直接漏 |
| 镜头离开房间足迹就整圈收起 | 「镜头在门外时，黑墙会挡在镜头与房间之间」 | 收起后**没有任何遮挡**，镜头看到哪算哪 |

两条叠加，等于过门时完全没有遮挡。而镜头跟在角色后 `CAMERA_DEFAULT_TRAILING_M = 4.914m`，
玩家跨门时它必然还在旧房间 —— 所以在门外那几帧，看到的就是隔壁房间与墙外地面，
和业主截图完全一致。

**这不是概率问题，是每次过门都发生。**

## 3. 取舍（为什么镜头必须夹，为什么不能留口）

幕墙只围**当前房间**一圈。于是：

- 镜头必须在圈内 → 否则黑墙横在镜头与房间之间；
- 镜头跟角色后 4.9m → 过门那一帧，它一定还在旧房间的圈里；
- 所以过门时必须把镜头整体搬进新房间的圈 → **约 4.9m 的位移**。

「不弹」与「不露」在这一套几何下互斥。三种落点都试过：

| 方案 | 结果 |
|---|---|
| 不夹（早晨版） | 镜头自由跟出去，看到外面房间（业主截图） |
| 阻尼夹（0.5s 收敛，速率 6/s） | 更糟：那 0.5s 里镜头在**圈外**，黑墙挡在镜头与房间之间，整屏全黑。实测 6 个过门用例镜头全在圈外 |
| **瞬时夹**（保留） | 过门那一帧直接切到新房间，观感等价于 EGT 的"跨门即换场"，没有中间态 |

业主最终确认第三种。**夹取的定位**：它不是"撞墙避让"，是"一次只有一间房是舞台"的构图边界；
与 2026-10-28 否掉的「墙进镜头通道就抬高 0.30m + 距离收到 0.15m 再弹回」完全两回事。

> 业主对"弹一下"的原话是针对**墙碰撞自动抬升/收拢**（镜头抬高 0.30m + 距离 3.1m→0.15m
> 再弹回）。那条早已关掉，本次没有恢复。房间边界切换是另一回事，它只在跨门那一帧发生。

```text
镜头 `_clamp_flow_camera_into_room()`：瞬时夹在「当前房间足迹内缩 0.55m」内，只动 x/z（保留）
```

## 5. 验收

```
PLAYABLE camera lift=0.000 trailing=4.914 base=4.914 wall_detected=false
PLAYABLE camera_clamp cases=104 outside=0 height_drift=0.000
PLAYABLE curtain rect=[P:(-5.16,-5.16) S:(15.32,15.32)] y=[-1.00..26.00] cam_y=10.26
PLAYABLE curtain_drift=0.160
PLAYABLE curtain_area=609.1 expect=609.1
PLAYABLE curtain_always_on cam_outside_visible=true
PLAYABLE wall_leak=84 limit=500
PLAYABLE_OK
```

- `camera_clamp`：每间房 × 四角内缩 1.5m（本轮 104 个站位），镜头**一个都没出圈**
  （判据取"越出半墙厚 0.14m 即算越界"），高度漂移 **0.000m**（只动 x/z 得到验证）。
- `curtain_area`：每面三角形面积合计 == 整面（长×高），**有缺口直接红**。
- 真实渲染取证：六档取景（房里远端 / 房中部 / 门前 1.5m / 站在门洞 / 跨过后 0.6m / 1.5m）
  全部 `cam_in_room=true`，没有一帧看到房间外。

### 5.1 一个被修正的判据（不是放宽阈值）

恢复夹取后 `wall_leak` 从 90 跳到 **1847**（上限 500）直接假红。查下来不是真漏：

- 直接拍"贴墙站位 + 幕墙开启"的图，用 PNG 采样：幕墙面本体是纯 `(0,0,0)`，
  1600×1000 图上占 80% 的采样点；
- 1847 那些像素亮度 **0.090**，是幕墙**边缘**与亮面交界的抗锯齿过渡带；
- 相机被夹到贴墙时幕墙在屏幕上占掉大半，这条边在屏幕里很长 —— 过渡像素自然从几十涨到上千；
- 真漏光像素的亮度是 **0.40~0.50**（显示的是墙外地面，与房间地面同档）。

原阈值 `<0.06` 判黑太严，把 0.06~0.12 这段肉眼即黑的过渡带算成了漏光。
改成 `<0.12`，两端余量都≥3 倍。**这是修判据，不是放宽验收**：
真漏光（0.40+）仍然会被抓到，实测上一版的门洞留口缺陷就是 5000+ 量级。

## 6. 留给下一次的口子

如果以后还想要"过门能看到下一间"，**不要动幕墙**。可行方向只有一个：
让"当前房间"在跨门槛之前就切换（预切换），使镜头在旧房间的最后几帧里，
新房间已经是舞台。那是换房时机的问题，不是遮挡的问题。
