# 战斗与经济交接第4项：奖励边界、实例归属与局内商人

日期：2026-09-24；功能ID：`REWARD-SERVICE`、`WORLD-LOOT`、`WEAPON-OWNERSHIP`、`RUN-MERCHANT`；工程版本：0.1.0。设计依据：`04` §9/§22、`04.1` §4 r2→r3；代码基线：`66093dc2`；交付提交：当前工作区。

## 变更与原因

- 奖励协调器不再复制 `grants[]` 为第二份 `items[]`。`RewardService` 不再负责旧物品字典转换；仅 `RewardSink.materialize_ground_items()` 在地面拾取节点入口转换，保留完整 `weapon_instance_id`。固定奖励的多把武器按一把一 grant 生成不同实例 ID；直接进包的备弹/剧情奖励读取 grant 本体，不经地面字典桥。击杀奖励的“单个实物 + 合并魂球”直接对 `grants[]` 处理。地面生成返回实际数量，剧情刷物不再按请求数虚报成功。
- `RewardSink.apply()` 按宿主返回的实际数量填写 `granted/deferred/rejected`；宿主返回0或缺失时不伪报成功。背包溢出只有地面宿主确认生成后才记 `deferred`。
- `RewardSink.apply_ground(grants, spawn_ground)` 提供不缓存房间/坐标的一次性地面回调；剧情按 ID 刷物、清房、搜索和击杀均接入该出口，失败按 `rejected[]` 报告。搜索品质/额外候选先在 grant 层选择并裁成一件，只有实际生成后才显示成功；击杀在 currency grant 层应用房间倍率，延迟生成后读取拒绝报告。旧 item 字典仅留在地面实体内部。
- 换装事务增加同一格同枪型、不同 `weapon_instance_id` 的过期命令拒绝，阻断 UI 快照过期后误转移另一把枪。
- `RunMerchantService` 作为会话货架写者，`MerchantUI` 只读展示并发购买命令。购买按会话、offer、预期武器实例、余额、格位/已有堆叠空间及当前行动其他所有权位置校验；成功移交完整实例并同步提交行动快照，失败回滚魂、精确格位、报价和交易撤离状态。交易撤离状态与房间ID进入行动快照，重载时恢复对应信标。
- 新增商人纯事务和正式 3D 场景接线专项；两场景均进入 `core`。
- 用户授权按同类游戏作商人库存裁决后，r3 采用“同一局同房间货架首开冻结、成交移除、关窗和读档保持”。`RunMerchantService` 保存按 `merchant_id=room_id` 的完整报价；首开在展示前同步写盘，失败恢复未开状态；成交移除报价与魂/背包/交易撤离状态一同提交，失败整体回滚。行动快照新增 `merchant_stock`，临时会话ID不落档。设计推导来源见[04.1 §4.2](../04.1_玩法系统_局内商人.md)。

## 遗留与状态更新

- `RUN-MERCHANT` 为**部分完成**：r3 货架报价、未售完整实例及已售缺席状态进行动快照；临时会话 ID 不进存档。首开和成交写盘故障、重试、关窗重开及重载专项已通过；正式表现未验，跨重载全局武器所有权账本另列。
- 地面节点内部仍消费 item 字典，`RewardSink` 是唯一转换边界；四条主地面链已核对实际发放，实体直传、全部地面内容逐项核签和真渲染数量/颜色证据未完成（表现验收本轮按用户要求暂缓）。七个 deprecated 池不在本次裁决范围。
- 当前行动多位置武器实例检查覆盖背包、保险、快捷栏、主副装备及地面；没有跨重载全局所有权账本。综合节点预算失败沿原性能债务继续跟踪，不调整阈值。
- 本批逻辑收口后的文档补齐排期已并入[功能关系计划 §6](../FEATURE_RELATIONSHIP_PLAN.md)，按 D0 交接事实→D1 主线资源事务→D2 战斗到奖励→D3 剧情展示→D4 维护发布推进；该排期不是已完成证明。商人未成交货架跨重载规则已定为同局保持。
