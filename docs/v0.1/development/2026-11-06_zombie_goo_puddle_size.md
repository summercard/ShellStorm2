# 2026-11-06 僵尸死亡地面液体：放大 2 倍 + 每块 1.5~2.0 随机尺寸

上一轮（2026-11-05）把地面液体从纯色方块换成了贴图面片。这一轮改尺寸。

## 业主口径

> 「贴图太小了，放大到现在的 2 倍，然后要在 1.5-2 之间做随机值缩放。」
>
> 追加：「可以接收两块贴图有重叠。」

## 公式

```
side = size × PUDDLE_SIDE_BASE × PUDDLE_SIDE_SCALE × roll
     = size × 0.72 × 2.0 × roll
roll = lerp(1.5, 2.0, hash01(出生点, 下标))       // 每块一个
```

| size | 边长 | 说明 |
|---|---|---|
| 1.0（小僵尸 / 警察僵尸） | **2.16 ~ 2.88 m** | 预览机位实测 2.38 / 2.63 / 2.81 / 2.86 |
| 2.0（胖子僵尸） | **4.32 ~ 5.76 m** | 共用同一段基类身体，自动跟随 |

对照：改之前是 0.62 ~ 0.84 m。

**删掉了什么**：原来的 `0.86 + 0.30 × i/span` 逐块递增。它和随机系数是**两套干同一件事的机制**
（都是「四块别一样大」）。留着会让最大块变成 `1.16 × 2.0 × 2.0 = 4.64` 倍 —— 那不是业主
要的「2 倍然后再随机」，是 4.6 倍。

## 「随机」为什么不是 randf()

三条硬约束，任何一条都足以否掉真随机：

1. **池化复借**。本件走 `VfxPool3D`，`_tick_puddle` 的停留段要求 `scale` 是 `elapsed` 的纯函数。
   验收会扫描「`scale` / `y` / `alpha` 三者同时冻结 0.50s」并逐位比对。
2. **真渲染基线**。`0.50s` 与 `0.85s` 两帧的像素差已被定成渲染噪声量级。真随机每次播放都不一样，
   这条基线立刻失效。
3. **业主的目标不是「每次不同」，是「四块不一样大」**。不同位置取到不同值就能达成。

所以用**确定性伪随机**：`_hash01(出生点, 下标)`，murmur3 的 `fmix32` 整数哈希，纯函数，
不触碰引擎 RNG 状态。**同一位置永远同一形状，换位置就换形状。**

### 踩过的坑：初版哈希质量不够

初版是 64 位乘法后直接取低 16 位：

```gdscript
h = h ^ (h >> 13)
h = (h * 1274126177) & 0x7FFFFFFF
```

**低位只依赖低位** —— 雪崩不够。实测四块挤成 `1.575 / 1.608 / 1.624 / 1.919`，前三块几乎同大，
读起来就是「没随机」。

换 `fmix32` 三步混合后：四块极差 `0.26 ~ 0.47`（可用区间 0.5），1600 次抽样均值 `0.498`、min 0 / max 0.999。

### 刻意不把 y 纳入哈希

`y` 是楼层高度（塔楼向下建造，98F ≈ −1176m）。同一层的同一位置应当是同一摊。纳入 `y` 会让
「同一房间不同楼层」的形状无谓漂移，也会让任何改出生高度的用例莫名其妙变红。

`x / z` 按 `× 16` 量化（0.0625m 以内视为同一落点），避免浮点尾数把「同一位置」打散。

## 关于重叠（业主已接受）

四块液体落在**飞溅粒子的真实落点**上，这四个点的中心距只有 **1.17 ~ 1.95 m**（解析式复算，
与 `size` 无关）。放大后边长 2.16 ~ 2.88m，而两块相切需要间距 ≥ 边长 ⇒ **相邻两块必然重叠近一半**。

中途我试过「落点径向外扩」，用实拍连通域量化（绿色区域分成几个独立块 / 最大块占比）：

| 落点外扩 | 独立块数 | 最大块占比 |
|---|---|---|
| ×1.00 | 4 | 33% |
| ×1.30 | 4 | 30% |
| ×1.50 | 4 | 31% |
| ×1.75 | 4 | 33% |
| ×2.00 | 4 | 35% |

数据上 ×1.5 最均衡。**但业主明确说「可以接收两块贴图有重叠」⇒ 已撤销外扩，落点回到原值。**
理由：业主这轮只要求改尺寸，挪落点等于顺手改了飞溅的落点关系，那是另一件事。

为了防以后有人以「为了不重叠」为由偷偷推开，**加了一条断言钉死它**（见下 ⑦）。

## 验收

`verify_zombie_goo_death_vfx` 新增 `_check_puddle_size_roll`，`samples` **17 → 20**。

| # | 判据 | 防的是什么 |
|---|---|---|
| ① | 逻辑常量 = 2.0 倍 / 区间 [1.5, 2.0] | 文档写 2 倍、代码实际 1.5 倍 |
| ② | 四块**每一块**都在 [1.5, 2.0] 内 | 只有第 0 块生效 |
| ③ | 四块极差 ≥ 0.10 | 随机退化成常量表 |
| ④ | 停留段边长 = `size × 0.72 × 2.0 × 该块系数`，且 ≥ `0.72 × 3.0` | 公式没被真消费；放大或随机有一头没吃上 |
| ⑤ | 同一出生点重复激活 → 系数**逐位相同** | 每次重算都变 ⇒ 停留段抖、基线失效 |
| ⑥ | 换出生点 → 系数不同 | 写死一张常量表（等于没随机） |
| ⑦ | 四块中心与飞溅落点偏差 < 0.001m | 有人为了消重叠把落点推开 |

⑤ 与 ⑥ 必须成对：只验 ⑤ 会漏掉「永远同一套值」；只验 ⑥ 会漏掉「每次重算都变」。

### 反向对照

把落点偷偷 `× 1.5` ⇒ 精准红 1 条：

```
液体落点被推开了 0.518 m（最大偏差）：业主已接受重叠，落点必须保持飞溅原落点
```

还原后复绿。

### 尺寸线性必须仍然绿

`_check_size_linearity` 要求同出生点上 `size=1.0` 与 `0.8` 的 `puddle_scale_x` 比值恰为 `1.25`。
**随机系数刻意不消费 `size`** —— 若把 `size` 混进哈希，两个实例会取到不同 `roll`，比值就不是 1.25。

## 遗留

- 现在四块是一整团。业主接受了。若以后嫌「看不出是四块」，改的应该是**落点外扩**
  （即把 `plate.position` 的 `source.x/z` 乘一个系数，并同步改验收 ⑦），
  **不是**继续缩尺寸 —— 尺寸是业主点名要 2 倍的，别动。
- 想让随机更极端，改 `PUDDLE_SIZE_ROLL_MIN/MAX`；想整体调大小，改 `PUDDLE_SIDE_SCALE`
  （`PUDDLE_SIDE_BASE = 0.72` 是 v001 规格值，不要改它，否则「原规格」与「业主加的放大」就混在一起了）。
