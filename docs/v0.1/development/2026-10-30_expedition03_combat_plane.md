# 远征03 双向打不中：怪在玩家头顶 0.4m 的「空气墙」

**日期**：2026-10-30（第二轮）
**范围**：`Enemy3D` 战斗高度面 / `hover` 悬停 / 敌方弹道起点 / `blink` 冷却与前摇 / 拟态怪超时 / `Dungeon3D` 读档注入
**起因**：业主第二次报单 —— 「这只怪物无法打中人。玩家子弹也打不中。**特别是释放技能瞬间移动后**。
这个怪物的大小缩小一点 到现在的 70%，并且需要冷却时间，不然会一直闪。冷却和技能数据参考挺进地牢的资料。
然后其它怪物也深度检查一下，有没有会产生 bug 的地方。」

## 1. 上一轮的结论只对了一半

`2026-10-30_expedition03_blink_out_of_room.md` 把「双向都打不中」判给了**瞬移出房**：
落点用「以出生点为圆心、半径随当前位置自增」的圆形近似，实测 84% 落在房外。
那是真 bug，修完症状**却仍然复现**。

业主这次多给了一句关键限定：「**特别是释放技能瞬间移动后**」。
"特别是"意味着**瞬移之前也打不中，只是瞬移让它更明显**。上一轮把"更明显"当成了"全部"。

于是本轮换判据：不问"它在哪"，问"**它和玩家在不在同一个高度上**"。

## 2. 根因：射击没有俯仰，而浮空怪在头顶之上

### 2.1 先确认"子弹是一条水平线"

| 环节 | 代码 | 事实 |
|---|---|---|
| 玩家瞄准 | `Player3D._update_aim_from_mouse()` | `flat_direction.y = 0.0` —— 只在水平面选方向 |
| 敌方齐射 | `Enemy3D._tick_pending_volleys()` | `direction.y = 0.0` |
| 子弹推进 | `Projectile3D` | `move_and_collide`，**无重力、无下坠** |

⇒ 能不能打中，**只由高度决定**。

### 2.2 再量真实的三个高度

`tools/_egt_combat_plane_probe.gd`（本轮新建，读真实节点，不写死）：

```
玩家胶囊带        y ∈ [0.00, 1.20]   （0.8 缩放后的实际值；场景里写的是 1.5）
玩家枪口高度      y = 0.44 m          （读 WeaponModel3D._muzzle 世界 y）
⇒ 玩家子弹高度带  y ∈ [0.26, 0.62]
```

### 2.3 然后量 33 只怪，结果是一条直线上的惨案

修前实测（节选）：

| 怪 | 碰撞柱世界 y | 与玩家带重叠 | 枪口线上打得到？ | 弹道起点 |
|---|---|---|---|---|
| `egt_hollowpoint` | [1.60, 3.04] | **0.00m** | **打空** | 1.60（在玩家头顶 0.40m） |
| `egt_bookllet` | [1.60, 3.06] | 0.00m | 打空 | 1.60 |
| `egt_blue_bookllet` | [1.60, 3.11] | 0.00m | 打空 | 1.60 |
| `egt_green_bookllet` | [1.60, 3.16] | 0.00m | 打空 | 1.60 |
| `egt_gunjurer` | [1.60, 3.20] | 0.00m | 打空 | 1.60 |
| `egt_gun_fairy` | [1.60, 2.66] | 0.00m | 打空 | 1.60 |
| `egt_gripmaster` | **[4.20, 5.38]** | 0.00m | 打空 | 1.05 |

`hover: true` 的怪被 `_pin_hover_height()` 抬到 `出生点 + 1.60m`，整只落在
**[1.60, 3.04]** —— 比玩家头顶（1.20）还高 0.40m。它开火的弹道起点也是 1.60m。

**双向零重叠。** 不是"难打"，是**在数学上永远打不中**，与瞬移无关；
瞬移只是让玩家的准星重新找一次目标，于是"更明显"。

> 4.2m 的抓握大师还有个附带问题：房间墙高只有 2.8m，俯视相机能越过墙顶，
> 玩家会看到它飘在屋外。

## 3. 修法

### 3.1 浮空高度写进常量并夹紧

```gdscript
const HOVER_HEIGHT_M := 0.22        # 缺省悬停
const HOVER_BOTTOM_MAX_M := 0.22    # 硬上限 = 枪口带下沿 0.26 − 0.04 余量
const GRIP_HOVER_MAX_M := 2.20      # 抓握大师：低于墙顶 2.8m
const ENEMY_SHOT_MIN_Y_M := 0.45    # 敌方弹道起点下限
const ENEMY_SHOT_MAX_Y_M := 1.05    # 上限（玩家头顶 1.20 之下）
```

| 取舍 | 理由 |
|---|---|
| 压到 0.22m 而不是"让模型飘高、碰撞柱留在地上" | 后者会让玩家"打空气也掉血"，比不浮空更糟 |
| 写成常量 + `clampf`，不留在 profile 里 | 这条不是手感，是**能不能被攻击到**；留成可调项迟早被人调回 1.6 |
| 抓握大师单独给 2.2m | 它 `invulnerable_while_others_alive`，**按设计不需要被打到**，但必须还在屋里 |

### 3.2 必须同时关掉贴地吸附

`floor_snap_length = 0.32` 是给地面怪走坡用的。而悬停只有 0.22m ——
**吸附距离大于悬停高度**，每帧 `move_and_slide` 都会把它按回地面。

这个坑不会报错、位置也合法、血量照掉，只是"浮空"静默消失。
所以 `apply_profile()` 里按 `hover` / `grab` 决定 `0.0` 还是 `0.32`，探针同时断言这两个值。

### 3.3 敌方弹道起点从"脚底"改到"躯干"

```gdscript
# 旧：origin = global_position（脚底）
# 新：
func egt_projectile_origin_y() -> float:
    var floor_y := _home_position.y if _home_initialized else global_position.y
    var torso := global_position.y + get_world_body_height() * 0.55
    return clampf(torso, floor_y + ENEMY_SHOT_MIN_Y_M, floor_y + ENEMY_SHOT_MAX_Y_M)
```

修前 19 只开火怪里有 19 只的弹道起点**在玩家胶囊之外**（地面怪 0.00m = 胶囊底切点，
浮空怪 1.60m = 头顶之上）。夹进 `[0.45, 1.05]` 之后，**任何身高、任何悬停高度**的怪
弹道起点都必然落在玩家体内。

### 3.4 瞬移：冷却 + 前摇 + 落点合法 + 补 `on_attack`

业主「不然会一直闪」是**节拍**问题，落点正确解决不了它。

| 旋钮 | 值 | 依据 |
|---|---|---|
| `interval` | 2.8 → **5.0s** | 两只空尖弹同场（`box_egt_hollow_line`），旧值平均 1.4s 就有一只消失。按本工程击杀节奏（250 血 ÷ 50 伤 ≈ 5 发 ≈ 2.5s），5.0s ⇒ 一只怪整个生命周期只闪 0~1 次，正是原作「周期性」的量 |
| `cooldown` | **2.5s** | 周期通道与出手通道**共用**这道闸门；不设就会叠加成连闪 |
| `telegraph_sec` | **0.35s** | 瞬移是直接改 transform、没有轨迹；不给前摇就只是"凭空消失" |
| `radius_m` | 9.0 → **7.0** | 9.0 在 25×25 房里一次跨半个房间，玩家彻底丢失目标 |

另外补了两件事：

1. **`on_attack` 从死键变成真实现**。2026-10-29 就写进 `egt_gunjurer` 的 profile，
   而 `_tick_egt_blink()` 开头是 `if on_attack: return` —— 枪法师从上线起只会站着连射。
   现在由 `request_blink_after_attack()` 在**这一轮弹幕打完**之后触发。
2. **落点要过几何查询**。矩形 clamp 只管四面墙，管不了房间里的箱子柱子；
   闪进掩体会被下一帧挤出（"抖一下"），闪进厚掩体会卡死。
   现在用自身碰撞柱 85% 做形状查询，最多重抽 4 次（半径 ×0.55），全失败就**原地不动**。

### 3.5 顺带修掉的两个「会卡住房间」的坑

| 坑 | 症状 | 修法 |
|---|---|---|
| 读档恢复的怪没有 `set_room_bounds` | 只有**读档之后**才会再次出现"瞬移出房" | `_restore_room_runtime_state` 补同一条注入 |
| 拟态怪没人靠近就永不现形 | 房间要"所有怪都死"才开门 ⇒ **敌方信号永远剩 1，门永远不开** | `disguise.max_sec = 12.0` 超时自动现形 |

### 4.3 踩到的三次「探针自己错」

记下来，因为三次都长得像"游戏有问题"：

| 假红 / 假绿 | 现象 | 真因 |
|---|---|---|
| 假红 | 33 只全部"枪口线打空" | 射线查询把**被测目标自己**放进了 `exclude` |
| 假红 | 33 只全部"弹道起点在玩家带外" | 把**点**当零长度**区间**算重叠，必然为 0 |
| 假绿（上一轮遗留） | 浮空怪"房内中心可命中 ✓" | 射线高度取的是**怪自己的高度**，等于"在它所在的高度上打它当然打得中" |

第三条最值得记：判据的**参照系站错了**，会把一整类 bug 测成绿的。
玩家的枪口高度是恒定的，所以射线高度必须由**玩家**决定。

## 5. 空尖弹体型 ×0.7（业主点名）

`tools/retune_egt_body_sizes.py`（唯一真源）：

```
egt_hollowpoint  TARGET_HEIGHT 1.44m → 1.01m    BODY_SCALE 1.217 → 0.891
                 世界高 1.44m → 1.01m           血条 1.75 → 1.23
```

1.01m 仍高于 `_egt_enemy_size_probe` 的 0.55× 下限（玩家 1.20m 的 0.56×）。

**副作用要知悉**：它在「子弹族」里变成体型最小的，而血量 250 是族内最高 ——
族内"体型随血量同序"这条规则被打破。按上一轮定下的规矩，
**不让判据偷偷放宽**，而是在 `_egt_variant_visual_probe` 里登记显式豁免：

```gdscript
const SIZE_EXEMPT := {
    "egt_hollowpoint": "业主点名缩到 70%；该族改用弹道形状 + 瞬移行为区分",
}
```

替代的区分维度成立：它是族内**唯一会瞬移**的，弹型是 4 连发。

## 6. 本轮**没有**改的

| 项 | 为什么不动 |
|---|---|
| 玩家瞄准仍然只有水平方向（无俯仰） | 这是整套战斗的地基，改它等于重做射击手感。本轮的取舍是"让怪进子弹带"，不是"让子弹会拐弯" |
| 原生怪（`melee_chaser` / `ranged_caster` / `fat_zombie03` / `boss`）的弹道高度 0.92m | 那是既有口径，`verify_strong_variant_monsters` 有断言；本轮只改 `egt_*` 的齐射通道 |
| `egt_chain_gunner` 的链会被墙挡 | 既有已知差异，与高度无关 |
| 宝箱拟态（`_reveal_chest_mimic`） | 已有 `reveal_disguise_now()`，本轮只补了"没人管它时也会现形"的超时 |
