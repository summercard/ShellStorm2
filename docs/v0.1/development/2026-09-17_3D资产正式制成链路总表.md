# ShellStorm2 3D资产正式制成链路总表

> 建立日期：2026-09-17
> 适用范围：玩家角色、敌人、武器、道具、场景、设施与 VFX
> 目的：明确每类 3D 资产从源文件到运行时的正式链路，并区分已经成立、正在使用、需要补齐的部分。

## 1. 状态定义

| 状态 | 含义 |
|---|---|
| 已成立并使用 | 正式资产链路完整，运行时已经引用。 |
| 部分成立并使用 | 已进入运行时，但模型、动作、Prefab 或统一包装仍缺一段。 |
| 正式资产待加入 | 当前主要使用代码生成或程序占位，需要建立正式资产链路。 |
| 已制作待接入 | 资产文件已存在，但当前玩法或场景尚未引用。 |

## 2. 统一正式链路

### 2.1 场景与设施

```text
白模/设计数据
  → Blender正式源文件
  → 视觉GLB
  → runtime PackedScene
  → 场景/关卡装配
  → Godot运行时验收
  → 资产台账登记
```

### 2.2 玩家角色与敌人

```text
模型源文件
  → 角色GLB
  → 角色runtime PackedScene
  → 动作文件/动作库
  → 状态机动作映射
  → 运行时角色实例
  → 模型、动作与状态验收
```

### 2.3 武器

```text
模型源文件
  → 武器GLB
  → 武器runtime PackedScene
  → 标准挂点
  → 玩家持握/战斗系统
  → 枪口、握点、碰撞与展示验收
```

### 2.4 道具与家具

```text
模型源文件
  → 道具/家具GLB
  → runtime PackedScene
  → GroundPivot/GripSocket/交互挂点
  → 物品或房间系统
  → 掉落、摆放、拾取与交互验收
```

### 2.5 VFX

```text
粒子/网格/材质源文件
  → VFX资源
  → VFX PackedScene
  → AssetID注册
  → 对象池
  → 战斗或环境挂点
  → 生命周期与视觉验收
```

## 5. 必须补齐的资产链路

| 优先级 | 类别 | 补齐目标 |
|---|---|---|
| P0 | 普通怪物 | 建立第一只标准怪物：模型、动作库、Prefab、FSM动作映射、验收用例；通过后批量迁移其他普通怪。 |
| P0 | Boss与精英 | 统一使用角色/敌人资产契约，禁止只加载裸GLB；补齐动作文件与挂点。 |
| P1 | 近战武器 | 清除三把程序模型，建立握点、命中点、拖尾起止点。 |
| P1 | 可拾取道具 | 优先资产化钥匙、治疗品、弹药、背包、蓝图、货币和配件。 |
| P1 | 通用家具 | 用 `furniture_type → runtime PackedScene` 替换 RoomFurniture3D 的程序网格。 |
| P2 | 普通房间 | 将Prefab内部的BoxMesh逐步替换为正式场景组件。 |
| P2 | 固定设施 | 统一新旧基地映射，一个 `facility_id` 只对应一套正式视觉资产。 |
| P2 | VFX | 将程序生成视觉迁入VFX Prefab，统一对象池和生命周期。 |

## 6. 统一判定原则

1. 有GLB文件，不代表运行时已经接入；必须有实际代码或场景引用。
2. 有Prefab文件，不代表内部已经是正式模型；必须检查Prefab是否引用正式GLB。
3. 有动作文件，不代表状态机已经使用；必须存在状态到动作的明确映射。
4. 有资产台账，不代表链路已完成；以运行时实际装配和验收结果为准。
5. 正式运行资产统一采用 `source / components / runtime` 三段结构。
6. 版本号只用于源文件、清单、节点元数据和台账追溯；运行时资产路径使用稳定路径，替换采用覆盖方式。
7. 功能逻辑、碰撞、交互和状态机不写进纯视觉GLB，由Prefab与外部脚本负责。

## 7. 结论

当前项目已经有四条成熟或较成熟的正式链路：玩家角色、枪械、场景通用组件、基地主要设施。

当前最大缺口是普通敌人。普通敌人仍然缺少“正式模型 + 动作文件 + Prefab + 状态机动作映射”完整链路，应作为统一资产标准的第一批实施对象。

近战武器、可拾取道具和通用家具属于第二批资产化对象。Boss、精英、天台、VFX和旧基地设施属于已有基础但需要统一包装、映射和验收的对象。
