# 2026-10-18 传送支线位点改成固定槽位（暗门不再压主路门洞）

## 业主口径

> 「我的每个房间的门扇和门墙都是固定的， 暗门的出口和入口也做成固定的位置就好了。
> 这个位置是用来做入口还是出口，哪条路可以自由控制。这样永远都不会有堵路的情况。」

拆成三条要求：

1. 位点用**固定位置**表达（不用运行时动态找墙，也不用世界坐标硬写）；
2. 位点跟着房间的固定门墙走，房间怎么摆都不用重新量；
3. **入口/出口可以自由配** —— 位置只决定「在哪儿」，角色由数据决定。

## 问题：S3 把主路钉死了

实测（新探针 `probe_secret_door_vs_main_doors`，seed 77001199）：

```
SecretDoor_S3  world=(137.50, 0.00, -180.00)  最近=Door_North（父=room_06，north→room_07）距离=0.00m  ★重合
SecretDoor_S1  → 27.04m    SecretDoor_S2 → 2.50m    SecretDoor_S4 → 16.77m
```

`S3` 的 2.2m 木板正好钉在 `room_06 → room_07` 的主路门洞上（板宽 2.2m = 门宽 2.2m），
木板层带碰撞 ⇒ 破板前主路走不通；破板后按 E 不是进第 7 间，而是被传到 1320m 外的子图。

静态断言 A1/A2/A3 当时**全绿** —— 因为它们看的是设计源坐标，而运行时房位由
`FloorPlanGenerator` 重排（`room_03` 设计源 `(-45, 50)`、实机 `(90, -40)`；
`room_07` 设计源 `(-17.5, -87.5)`、实机 `(137.5, -192.5)`），设计源坐标不能代替运行时坐标。

## 根因：位点没跟房间一起转

`connection_ports` 会经历**两道**刚体旋转，`secret_site` 一道都没走：

| 旋转 | 端口 | 位点（改前） |
|---|---|---|
| 落位姿态 `placed_room.rotation_deg`（桥房族转置：40×30 摆成 30×40） | 转 | **不转** |
| 整层旋转 `_apply_final_global_rotation`（远征01 恒 180°） | 转 | **不转** |

代码里还写着一条错注释：「位点用 `wall` 而不是世界坐标表达，所以不需要随
global_rotation 旋转」—— 错在把 `wall` 当成**世界轴**方位。`wall` 表达的是
房间自己的墙，房间翻了它就得跟着翻。

## 改法

### 1. 数据：`secret_site` 补 `lane`（沿墙固定槽位）

```json
"secret_site": {
  "site_id": "S3", "pair_id": 1, "role": "entry",
  "wall": "north", "lane": 5.0, "door_width_m": 2.2
}
```

- `wall` / `lane` 都在**房间自己的坐标系**里，与 `connection_ports.position_m` 同一局部系；
- `lane` = 沿墙偏移（南北墙沿 x、东西墙沿 z），`0` = 墙中点，缺省 0（向后兼容）；
- 与模板 `wall_lane_table` 同一套槽位语言 —— 门扇/门墙本来就是这么表达的。

### 2. 代码：两道旋转都补上

`FloorPlanGenerator` 新增 `_rotated_secret_site()`，在
`_constrained_floor_from`（落位姿态）与 `_apply_final_global_rotation`（整层旋转）
各调一次，与 `connection_ports` 同一次变换。旋转口径复用 `_rotate_port_vector`：
法线转完定新墙，沿墙切向转完与新切向同向则 `lane` 保号、反向取负（180° 与 90°/270° 同式）。

`SecretBranch3D._collect_sites()` 增 `_wall_tangent()`，位点 =
墙中点 + 沿墙切向 × `lane`。

### 3. 角色仍然自由

`role` 与位置解耦：同一对的两个槽互换入口/出口不需要动几何、不需要重算坐标。
现状：`S1`/`S3` = 入口，`S2`/`S4` = 出口。

## 落点（设计源声明 → 实机）

| 位点 | 房间 | 设计源声明 | 实机世界坐标 | 实机所在墙 / lane | 离最近主路门 |
|---|---|---|---|---|---|
| `S1` | `room_03` | `south` `+2.5` | `(92.50, 0, -20.00)` | 南墙 `+2.5` | 25.74 m |
| `S2` | `room_06` | `north` `+7.5` | `(125.00, 0, -167.50)` | 西墙 `-7.5` | 17.68 m |
| `S3` | `room_07` | `north` `+5.0` | `(125.00, 0, -197.50)` | 西墙 `-5.0` | 14.58 m |
| `S4` | `room_10` | `north` `+2.5` | `(70.00, 0, -247.50)` | 东墙 `+2.5` | 10.00 m |

设计源声明的墙与实机落墙**故意不同**（落位姿态 + 整层旋转叠加），这正是
「必须跟房旋转、不能写世界坐标」的直接证据。

## 仍未解决 / 需要知道

- **A3 只能判设计源**：它比对的是设计源房间矩形，而实机房位是重排过的。
  「位点在房间外墙」这条设计意图**没有**运行时保证；有运行时保证的只有
  「不撞主路门洞」（A20）。若将来要强约束外墙，得在运行时按 `_records` 做邻接判定。
- **`S2` 现在落在 `room_06` 西墙**（设计源声明 `north`）。设计源与实机的对应关系
  由落位姿态决定，改 `generation_policy` 后实机落墙会变，但**离门距离由 A20 兜住**。
- **一墙多门是合法的**：本次把 A1 从「墙面不许有端口」放宽为「离端口 ≥ 2.3m」，
  否则 `room_10` 这种东墙 + 北墙各一门的合法布局会被误判。
- `probe_secret_door_vs_main_doors` 是常驻探针（不进套件），改位点逻辑后跑一次即可
  复核四个位点的落点与最少离门距离。
