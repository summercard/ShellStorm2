# 暗门看不见：木板被墙体包住（2026-10-18）

## 业主反馈

> 我测试了两次，进入远征关卡01 打到第四个房间，完全找不到隐藏房间的支线入口。

第二局同样没找到。不是运气问题。

## 实测：门都在，只是被墙盖住了

新写探针 `tests/verification/probe_secret_door_visibility.gd`，直接进运行时量：

```
S1 木板：厚 0.142m，向房间里凸出 0.142m
   room_03 南墙墙体可视面：-20.465 ~ -19.850  → 朝房间内凸出 0.465m
   视线射线：首个命中 room_03/.../wall_south_0
S2 门前 1.02m：「ENV-EXPEDITION-L01-DB-WORKBENCH_L_EAST」工作台
S3 / S4 视线直接命中木板 —— 这两处本来就看得见
```

木板只往外冒 14 厘米，墙却往外冒 46 厘米。木板整个在墙里，玩家看到的就是一整面平整的墙。

另外两个事实：

- 业主打的**第 4 间**（`room_04`）本来就没有位点。入口在第 3 间（`room_03`）；
- pair 0 恒定刷（S1 + S2），pair 1 只有 50% 概率（S3 + S4，在第 7、10 间）。所以「打到第 4 间找不到」是必然结果，与种子无关。

## 根因

房间墙体只认 `connection_ports`：只有主路门槽那一条 lane 会被换成门洞墙件。`secret_site` 从头到尾没参与墙体生成，所以暗门位置生成的是**完整实墙**。

设计里写的「门洞被木板钉死、板缝里透出暖光」，实际做出来是「实心墙表面贴了一块板，板还埋在墙里」。缝后面是墙，自然也不透光。

## 修法（业主定：把整樘门推到墙外）

> 把隐藏门的模型和木板都推到墙外 能看到 是墙壁凸出出来的

`src/world3d/SecretBranch3D.gd`：

| 函数 | 作用 |
|---|---|
| `_push_site_out_of_wall()` | 取该点附近（3.2m）名字/来源含 `wall` 的网格，按包围盒沿法线的**最小**投影算墙面最内面，把位点整体移出墙外（+3cm） |
| `settle_sites()` | 房间齐了之后再补做一次，幂等（`wall_push_m` 已置则跳过） |
| `_shift_door()` | 门节点与它自带的传送落点一起平移 —— 只挪门不挪落点，按 E 会落在门框里 |
| `_measure_site_blocker()` | 门前 2.4m 打一条射线，把挡路件名字写进 `sites[].blocker` |

只认 `wall` 网格、不认家具：工作台、货架也贴墙摆，但它们不是「看得见门」的基准面，算进来会把门推到家具外面。

结果：

```
S1 外推 0.50m   视线首个命中 SecretDoor_S1
S2 外推 0.00m   视线首个命中 SecretDoor_S2
S3 外推 0.35m   视线首个命中 SecretDoor_S3
S4 外推 0.00m   视线首个命中 SecretDoor_S4
```

## 数据：S2 换槽

`room_06` 西墙（`north +7.5`，运行时落在西墙）正好被工作台挡在 1.02m 外，玩家绕过去也看不见。换到东墙：设计源 `south +2.5` → 运行时 `east -2.5`，落点 `(155.0, -162.5)`，离最近主路门 24.7m，朝外 3m 无障碍。

## 四个坑（都是踩出来的）

1. **房间节点在 bootstrap 阶段还没建。** `_create_secret_branches()` 先被 bootstrap 调一次，那时房间索引只有 1 个，`find_children` 拿不到墙件。`_finish_layout_connections()` 会再调一次（幂等分支），外推必须在那里补做。`build()` 末尾的 `call_deferred` 是同帧兜底。
2. **`normal` 是外法线，要用最小投影。** 第一版取 `max`，算出来「墙只凸 0.15m」，只推了 0.18m，等于没修。
3. **位点带 lane，不能拿 `pos - center` 当法线。** S1 的 lane=2.5 会让法线歪约 7°，墙面和射线起点全错。
4. **A21 必须在破板用例之前跑。** A9/A14 会把 S1 打碎，木板碰撞层随即关闭，再打射线什么也命中不了。第一版放在 A20 后面，结果 A21 对 S1 报「没打到任何东西」。

## 验收

新增两条运行时断言（`verify_secret_branch_flow`）：

- **A21**：从房间内 4m、人眼高度朝门中心打射线，第一个命中的必须是这扇门本身；
- **A22**：`sites` 里不得有 `blocker`（门前 2.4m 被家具挡住）。

不采用「木板 AABB 在墙面外」这种纯几何判据：墙件不是规则盒子（L 形凹口、门垛、装饰带），AABB 会把整面墙的包络算进来，判不准。射线问的是「玩家眼睛走过去先看到谁」，与真实观感一致。

**A3 降级为 NOTE**：它是拿设计源坐标算「朝外撞房」，而设计源是重排前的示例版图 —— `room_10` 设计 `(50,-45)`、实机 `(55,-250)`，差 200m 量级。S2 改成东墙后，设计源上它的南邻正好是 `room_05`，A3 报红，但实机离隔壁 3m 以上。运行时的保证交给 A20（不压门洞）与 A21（可见）。


- 位点在**设计源**上是否撞隔壁（A3）现在只记录不判红，见上。

## 追加（2026-10-19）：拍图核对，抓出 S2 其实还埋在墙里

### 为什么 A21 没抓到

A21 打的是**碰撞射线**，而墙体外壳的**碰撞代理盒往往比美术面薄**（有的只在墙平面留一层壳）。
S2 所在的 `room_06` 东墙上压着一个转角壳体：

```
Imported_CornerL5M_GenericShell_CORNER_ROOM_06_NE_2/ImportedModel/ENV_TOWER_CORNER_L_5M
AABB pos=(150.00, 0.00, -165.15) size=(5.15, 11.90, 5.15)
```

5.15×5.15×11.9 的实心块，把 x=155 那面墙连同门一起包进了肚子里。射线从房间里穿过去，
在 3.84m 处命中 `SecretDoor_S2/` → A21 判「可见」；玩家眼睛里只有墙。
**这和业主两次反馈的是同一类坑：碰撞说能到，眼睛看不见。**

反向对照：把该件 `visible = false` 再拍同一机位，木板立刻出现在画面正中 → 归因确定。

### 修法：加「可视遮挡」判据，并换槽

外推救不了它 —— 要推出这个壳得挪 5m，门就飘在房间当中。所以这类位点**不修正、只报错**。

`SecretBranch3D._measure_visual_cover()`：

- 遍历房间内 `VisualInstance3D` 的**可视**世界包围盒（`MultiMeshInstance3D` 也要认，
  只扫 `MeshInstance3D` 会把整片用 MultiMesh 铺出来的墙漏掉）；
- 竖直方向必须盖住门高主体（`box.end.y >= 1.2` 且 `box.position.y <= 2.0`），地脚线/屋檐不算；
- **沿墙方向必须真压过门宽**（重叠 ≥ `0.9 × 1.2`），只擦到门边不算 —— 这一条把
  `room_10` 的 `RoomLightSwitch3D`（凸出 0.45m，但在门宽之外）挡在误报之外；
- 往房间内凸出 > 0.05m 才算盖住；结果写 `sites[].covered_by` / `cover_m`，装配期 `push_warning`。

A22 一并对 `covered_by` 判红。反向对照（把 S2 改回 `south +2.5`）：

`south -7.5`（实机东墙 `+7.5`，`(155.0, -152.5)`），离那面转角壳 7.5m，`covered_by` 清空。

### 修法：给暗门一盏"板缝透光"

设计 §4.1 原本就写了"门后有人，板缝透光"。之前因为没有开墙洞、也没做光，这条表现一直
是空的。补的就是它：

```gdscript
# src/world3d/SecretDoor3D.gd
const LEAK_LIGHT_ENERGY := 1.6
const LEAK_LIGHT_RANGE_M := 4.2
const LEAK_LIGHT_COLOR := Color(0.62, 1.0, 0.82)
const LEAK_LIGHT_OFFSET := Vector3(0.0, 1.05, -0.62)   # 门局部 -Z = 房间侧
```

- 只在**有木板的谜题门**上建（`configure_portal` 的返程/撤离门不建，那些不是谜题）。
- 低能量 + 短射程 + 偏绿冷色：门前一小圈把门板与墙的落差照出轮廓，同时在地面留一小片
  光斑；走远仍只是一个暗暗的暖点，不当路标。
- 不投射阴影（`shadow_enabled = false`），4 盏门灯的代价可以忽略。

### 结论：门在，但在**北墙**，而且只凸 3cm

`room_03`（30×40m，中心 `(90, -45)`）实机数据：

| 项 | 实测 |
|---|---|
| 位点 `S1` | `wall = north`，`lane = -2.5`，世界 `(87.5, -64.5)` |
| 房间标称北墙 | `z = -65`（沿外法线投影 65.000） |
| 墙面**可视面** | 64.535（墙皮往房间里凸 0.465m） |
| 门心 | 64.505 |
| 门比墙面凸出 | **0.030 m** |

**真因 1：我之前一直让人去看南墙。** 设计源 `floor_00.json` 写 `south`，但远征 01
整层按 `rotation = 180` 生成（`_expedition_rotation_for_checkpoint`，新战局固定 180），
`FloorPlanGenerator._rotated_secret_site()` 会把墙向一起转 —— 设计源 `south` = 实机 `north`。
所以「3 号房南墙」永远找不到，门在**对面那面墙**上。

**真因 2：凸出量只有 3cm。** `WALL_FACE_CLEARANCE_M` 当初取 `0.03`，理由是
"够让木板与墙面出现一道缝，又不至于悬空"。这是**穿模判据**，不是**可见判据**：
门框前表面离墙 3cm，在塔内夜间光下与齐平没有区别，手电扫过去只会看到一整面墙。

### 修法

1. `WALL_FACE_CLEARANCE_M`：`0.03` → **`0.40`**。四个位点实测统一：
   `S1=0.40 S2=0.40 S3=0.40 S4=0.40`（此前 S2/S4 只凸 0.25，见下条）。
2. 墙件识别从 `MeshInstance3D` 改成 `VisualInstance3D` + `_visual_world_box()`。
   远征有一部分墙是用 `MultiMeshInstance3D` 铺的，只扫 `MeshInstance3D` 会漏掉整面墙，
   位点以为"没找到墙"，于是只吃到最小量（S2/S4 就是这样）。
3. `SecretDoor3D.set_mount_depth()`：门被推出墙面后，在门框背后补一个同色
   **安装箱** `MountBox`（2.40 × 2.60，厚 = 推出量 + 2cm），填住"门框 ↔ 墙面"的空当。
   否则从侧面看是一块悬空的板。外观正是业主说的「墙壁凸出来一块」。
4. 新增断言 **A23**：`protrude_m ≥ 0.25m`。`protrude_m` 由装配时按
   `墙面可视面 − 门心投影` 算出，写进 `sites[]`，验收与探针都读同一份数。

  （由房间几何推导），但**墙件拼法与旁边家具随种子变**，且 test_mode 不是玩家的存档分支。
- 更关键的是判据本身：A21 只问"射线首个命中是不是门"，门比墙面凸 0.03m 时射线照样命中门
  —— 判据全绿，人眼全黑。**"能打到"和"看得见"是两件事**，A23 补的就是这中间那段。
