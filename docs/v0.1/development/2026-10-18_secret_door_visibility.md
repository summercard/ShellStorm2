# 暗门看不见：木板被墙体包住（2026-10-18）

## 业主反馈

> 我测试了两次，进入远征关卡01 打到第四个房间，完全找不到隐藏房间的支线入口。

第二局同样没找到。不是运气问题。

## 实测：门都在，只是被墙盖住了

新写探针 `tests/verification/probe_secret_door_visibility.gd`，直接进运行时量：

```
S1 木板：厚 0.142m，向房间里凸出 0.142m
   room_03 南墙墙体可视面：-20.465 ~ -19.850  → 朝房间内凸出 0.465m
   视线射线：首个命中 room_03/.../wall_south_0
S2 门前 1.02m：「ENV-EXPEDITION-L01-DB-WORKBENCH_L_EAST」工作台
S3 / S4 视线直接命中木板 —— 这两处本来就看得见
```

木板只往外冒 14 厘米，墙却往外冒 46 厘米。木板整个在墙里，玩家看到的就是一整面平整的墙。

另外两个事实：

- 业主打的**第 4 间**（`room_04`）本来就没有位点。入口在第 3 间（`room_03`）；
- pair 0 恒定刷（S1 + S2），pair 1 只有 50% 概率（S3 + S4，在第 7、10 间）。所以「打到第 4 间找不到」是必然结果，与种子无关。

## 根因

房间墙体只认 `connection_ports`：只有主路门槽那一条 lane 会被换成门洞墙件。`secret_site` 从头到尾没参与墙体生成，所以暗门位置生成的是**完整实墙**。

设计里写的「门洞被木板钉死、板缝里透出暖光」，实际做出来是「实心墙表面贴了一块板，板还埋在墙里」。缝后面是墙，自然也不透光。

## 修法（业主定：把整樘门推到墙外）

> 把隐藏门的模型和木板都推到墙外 能看到 是墙壁凸出出来的

`src/world3d/SecretBranch3D.gd`：

| 函数 | 作用 |
|---|---|
| `_push_site_out_of_wall()` | 取该点附近（3.2m）名字/来源含 `wall` 的网格，按包围盒沿法线的**最小**投影算墙面最内面，把位点整体移出墙外（+3cm） |
| `settle_sites()` | 房间齐了之后再补做一次，幂等（`wall_push_m` 已置则跳过） |
| `_shift_door()` | 门节点与它自带的传送落点一起平移 —— 只挪门不挪落点，按 E 会落在门框里 |
| `_measure_site_blocker()` | 门前 2.4m 打一条射线，把挡路件名字写进 `sites[].blocker` |

只认 `wall` 网格、不认家具：工作台、货架也贴墙摆，但它们不是「看得见门」的基准面，算进来会把门推到家具外面。

结果：

```
S1 外推 0.50m   视线首个命中 SecretDoor_S1
S2 外推 0.00m   视线首个命中 SecretDoor_S2
S3 外推 0.35m   视线首个命中 SecretDoor_S3
S4 外推 0.00m   视线首个命中 SecretDoor_S4
```

## 数据：S2 换槽

`room_06` 西墙（`north +7.5`，运行时落在西墙）正好被工作台挡在 1.02m 外，玩家绕过去也看不见。换到东墙：设计源 `south +2.5` → 运行时 `east -2.5`，落点 `(155.0, -162.5)`，离最近主路门 24.7m，朝外 3m 无障碍。

## 四个坑（都是踩出来的）

1. **房间节点在 bootstrap 阶段还没建。** `_create_secret_branches()` 先被 bootstrap 调一次，那时房间索引只有 1 个，`find_children` 拿不到墙件。`_finish_layout_connections()` 会再调一次（幂等分支），外推必须在那里补做。`build()` 末尾的 `call_deferred` 是同帧兜底。
2. **`normal` 是外法线，要用最小投影。** 第一版取 `max`，算出来「墙只凸 0.15m」，只推了 0.18m，等于没修。
3. **位点带 lane，不能拿 `pos - center` 当法线。** S1 的 lane=2.5 会让法线歪约 7°，墙面和射线起点全错。
4. **A21 必须在破板用例之前跑。** A9/A14 会把 S1 打碎，木板碰撞层随即关闭，再打射线什么也命中不了。第一版放在 A20 后面，结果 A21 对 S1 报「没打到任何东西」。

## 验收

新增两条运行时断言（`verify_secret_branch_flow`）：

- **A21**：从房间内 4m、人眼高度朝门中心打射线，第一个命中的必须是这扇门本身；
- **A22**：`sites` 里不得有 `blocker`（门前 2.4m 被家具挡住）。

不采用「木板 AABB 在墙面外」这种纯几何判据：墙件不是规则盒子（L 形凹口、门垛、装饰带），AABB 会把整面墙的包络算进来，判不准。射线问的是「玩家眼睛走过去先看到谁」，与真实观感一致。

**A3 降级为 NOTE**：它是拿设计源坐标算「朝外撞房」，而设计源是重排前的示例版图 —— `room_10` 设计 `(50,-45)`、实机 `(55,-250)`，差 200m 量级。S2 改成东墙后，设计源上它的南邻正好是 `room_05`，A3 报红，但实机离隔壁 3m 以上。运行时的保证交给 A20（不压门洞）与 A21（可见）。

## 结果

```
SECRET_BRANCH_FLOW_OK 位点=4 槽位固定 门洞不重合 门板可见 生成规则=确定 传送=可达 隔离=通过 编成=5强化+2普通 存档=往返一致
```

断言 20 → 22 条（A21/A22 新增，A3 转 NOTE），4 个位点全部实测射线可见。

## 仍未做

- **没有开洞**：这版是「门凸出墙面」，破板后后面仍是实墙，看不到设计里的门腔与透光。要那层表现必须让墙体生成支持 `secret_site` 开洞，属于另一件事。
- 位点在**设计源**上是否撞隔壁（A3）现在只记录不判红，见上。
