# 远征01 3.2 Boss 分镜：末句后还镜回角色视角 + 1.5 秒停顿

日期：2026-11-18
归属：NARRATIVE-TRIGGER / BOSS-STAGES
状态：剧本与文档已改；真实渲染验收结果见文末回填

## 1. 业主指令

> 「boss对话的镜头移动这块。到了这里都是系统说话。这句话完了以后。变回原来的角色视角。变回视角后，需要停顿一下，大概1.5秒，然后主角才说这句话。」

截图对应：

- 第 1 张：`nar_main_032_monitor_audience` 最后一句系统台词「加入我们，一起成为这个世界的霸权。」（原 `at=54.016`，`auto=2.663`，即 **56.679 念完**）。
- 第 2 张：主角底栏「你一句我也没听懂...」（原 `at=57.497`，`actor.say`）。

问题：原时间轴在 57.497 插了一台 `camera.shot`（`central_screen_pressure`，中央屏低机位压迫镜头），正好压在主角这句上。所以「系统讲完 → 回角色视角 → 停顿」这两件事都没有发生。

## 2. 改法

### 2.1 让反打镜头停在系统末句

| cue | 改前 | 改后 |
|---|---|---|
| 53.0 `camera.shot` `player_reverse_reaction` | `duration 4.497`（到 57.497） | `duration 3.679`（到 **56.679**） |

反打镜头现在正好在「加入我们…」念完那一刻收尾，后面紧接着还镜，不会出现「台词结束但镜头还挂在主角身上 0.8 秒」的拖尾。

### 2.2 把中央屏压迫镜头换成还镜

删除整条 `at=57.497 camera.shot central_screen_pressure`（`duration 3.252`、`fov 48`），替换为：

```json
{
  "at": 56.68,
  "do": "camera.restore",
  "duration": 1.0
}
```

`camera.restore` 是共用 Adapter 既有能力（08 文档 §5.2 指令表 ✅）：把距离、方位、俯角、枢轴一起平滑带回**接管前位姿**，再放权给玩法镜头。这里只用到它「还回原角色视角」这一半，整段结束仍由导演统一 `release_camera_override`。

### 2.3 停顿 1.5 秒后主角才说话

| cue | 改前 | 改后 |
|---|---|---|
| `actor.say`「你一句我也没听懂…」 | 57.497 | **59.18** |

还镜 56.68 起、1.0 秒完成于 57.68；57.68 → 59.18 = **1.5 秒**，区间内**没有任何 cue**（不加旁白、不切镜、不震屏），冷场完全落在角色视角上。

### 2.4 后续整体平移

主角这句从 57.497 移到 59.18（+1.683 秒），其后所有 cue 保持原有相对间距整体后移：

| cue | 改前 | 改后 |
|---|---|---|
| 系统「………」 | 60.749 | 62.432 |
| 怒吼 `camera.shot` `boss_roar_front_close` | 62.0 | 63.683 |
| 系统「啊啊啊啊！」 | 64.001 | 65.684 |
| `camera.shake` | 66.6 | 68.283 |
| `story.boss.control_hold` | 67.253 | 68.936 |
| `story.boss.activate` | 67.253 | 68.936 |
| `flow.end` | 67.5 | 69.183 |
| 剧本 `duration` | 67.5 | **69.183** |

`duration` 与最后一条 cue 相等，满足 `NarrativeScript3D` 的「duration ≥ last_at」校验。

### 2.5 镜头数量

`camera.shot` 由 9 组变为 **8 组**（26.2 / 30.7 / 35.2 / 39.751 / 44.3 / 48.8 / 53.0 / 63.683），另加 1 次 `camera.restore`。怒吼镜头仍是近距离低机位，只是起点从 62.0 推到 63.683。

结论：**系统末句念完后回到角色视角，视角停住约 1.5 秒，主角才开口**，与业主描述一致；原中央屏压迫镜头已不再出现。

`camera.shot` 采样点为 8×3 = 24 帧（`shot_01`…`shot_24`），怒吼镜头仍在（`shot_22`—`shot_24`）。

两处需如实说明的细节：

**① 头顶示意框提前淡入。** `t_058.60` 这张停顿帧上，主角头顶已能看到三点示意框的浅色外形，但底栏没有任何文字。停顿期间读不到台词，观感上仍是「停住不说话」；框体提前淡入约 0.5 秒，属共用 DialogueUI 的进入动画，不是本事务改的，也没有在这轮动它。

**② 还镜完成后到下一台镜头之间，相机是静态位姿而不是实时跟随。** `NarrativeAdapter3D._advance_camera_return()` 在 `weight>=1` 时把相机落到目标位姿，但**不清空 `_camera_return_channel`**，所以只要该通道非空，每帧都不会再走 `_apply_camera_pose()`。因此 57.68—63.683 这段（约 6 秒）里，相机停在刚好还回的那一刻的位姿上。本段角色被 `player.lock_input` 锁死、站在 `boss_listening` 不动，静态位姿与跟随视角在画面上等价，三张关键帧完全一致即为证据；63.683 的 `camera.shot` 会清空该通道并重新接管，之后到结束按原逻辑走。

这是**既有行为**，本轮没有改它，也不属于主线 3.2 的必要修复。若以后这段要允许角色移动，需要单独给 `_advance_camera_return` 补「到点后放权」的收尾。
