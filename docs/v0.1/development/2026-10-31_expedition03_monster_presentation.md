### 2.1 四个必须知道的技术坑（都实测踩过）

**① 不能用身高百分比定位。**
第一版用 `FORMAL_NORMAL_HEIGHTS`（1.857 / 1.857 / 3.143）当比例基准，
结果护目镜飘在帽檐上、布洛布的「肚子鼓包」长到脸颊两侧。
三个模型的头身比差得远：小僵尸的头占一半身高、胖子只占 15%。

**② 不能挂骨骼。**
`Head` 骨在 y≈0.85（胸口位置），而网格的头在 1.1+ —— 骨空间与网格**不同源**
（`MonsterVariants.EYE_SOCKETS` 那套眼位就是靠顶点反算的，同一个原因）。

**③ 不能用 `MeshInstance3D.get_aabb()`。**
那是**绑定姿势**的盒子：保安僵尸给 1.399，而顶点实测是 1.857 —— 差 30%。
照它摆零件会整只离体。

**④ 锚点只能按顶点实测。**
`tools/_egt_anchor_probe`（临时，已删）分层扫描顶点得到：

| 模型 | 顶点 | 实高 | 头所在 | 脸的表面 z | 备注 |
|---|---|---|---|---|---|
| 保安僵尸 | 16468 | 1.857 | y 1.08~1.86 | −0.42~−0.48 | 手里有枪，横向被撑到 ±1.45 |
| 小僵尸 | 853 | 1.894 | y 0.95~1.89 | −0.44 | 头极大，肚子在 0.65 |
| 胖子 | 1513 | 3.143 | y 2.62~3.14 | −0.47 | 肚子前凸到 z=−1.02，手臂撑到 ±2.62 |

横向尺寸只能用**躯干层**，绝不能用整体 AABB（手臂 / 枪会污染）。

### 2.2 尺寸与配色

- **零件尺寸封顶**：`part = min(body_half, head_half, 0.42)`。
  胖子体宽半宽 1.05 m 是头的 2.7 倍，按体宽缩放会做出 0.9 m 宽的「挡板」
  （实测：链枪手背后两块板、枪坚果肩甲甩出体侧 1 m）。
  **零件是装备，尺寸跟人形比例，体宽只影响摆在哪。**
- **肩线单独建锚点** `shoulder_x`：胖子体宽 ±1.16 而肩关节只在 ±0.62。
- **对比度是算出来的，不是手挑的**：33 只里 **20 只**原色与身体距离 < 0.35，
  书怪三只只有 0.06~0.09（渲染完全看不出有零件）。
  `resolve_albedo()` 的优先级：原色 → 同色相提饱和（≤0.75）→ 高对比调色板。
  **色相差 < 0.06 时直接进调色板** —— 链枪手身体与标识件色相相同，
  提饱和只会得到一个荧光版的同一种蓝。
- **自发光必须基于求解后的 albedo**，且强度只有 0.30。
  0.85 会把形体信息抹平（0.235 m 的罐被看成 0.47 m 平板）。

## 3. 受击不漂移（三道闸门）

`melee_chaser` / `ranged_caster` / `fat_zombie03` 三份 formal_visual 同口径：

| 闸门 | 判据 | 挡的是什么 |
|---|---|---|
| ① `_hurt_pose_allowed` | 太阳伤害传 `false` | 环境结算不该播受击姿态 |
| ② `HURT_POSE_MAX_SPEED` 0.45 m/s | 实际水平速度 | 在跑的怪只闪白 |
| ③ `HURT_POSE_STATES` | `idle` / `alert` / `patrol` | 只有本来不推进位移的才能踉跄 |

受击姿态时长从 **0.8 s 降到 0.28 s**。
旧实现只判状态名，`chase` 不在排除表里 ⇒ hurt 段整段盖掉 running，
而位移照旧按 chase 推进 = **原地扑咬的动画被平移**，这就是业主看到的「漂移」。

太阳伤害那条同时去掉了 `Enemy3D._tick_illumination_effects` 里的 `avatar.flash_hit()`：
它不是「被打了一下」，是每秒一次的环境消耗。

## 4. 移动动画（按速度，不按状态名）

`CLIP_BY_STATE` 把 `chase` 映射成 running，这对塔楼老怪够用 ——
它们的位移只有「巡逻慢走」和「追击全速」两种。
但复刻怪多出一批**位移由外推接管**的形态：冲撞（11 m/s）、逃跑（×1.45）、
游荡、瞬移重定位、抓取下压抛人。这些形态的 `ai_state` 往往还是 `patrol` 甚至 `idle`
⇒ **以 11 m/s 突进却播走路段**。

判据换成「实际速度 ÷ 满速」：

| 比例 | 段 |
|---|---|
| ≥ 62% | running / running_armed |
| 30~62% | walking / walking_armed |
| < 30% | 保留状态名给的段 |

`Enemy3D.sync_presentation()` 多了一个 `base_speed` 参数
（传 `get_effective_move_speed()`），表现层据此换算。

**老怪逐字不变**：追击 ≈100%、巡逻 = 50%，改判后与原来一致。

## 5. 死亡表现（按资产判，不按 kind）

`uses_no_corpse_death()` / `uses_goo_death_burst()` / `uses_goo_hit_burst()`
三个判定都改成走新的 `_asset_kind()`：

```gdscript
func _asset_kind() -> String:
    var proxied := EnemyAvatar3D.resolve_asset_kind(enemy_kind)
    var base := MonsterVariants.base_of(proxied)
    return base if not base.is_empty() else proxied
```

**为什么必须这样**：那张 `ZOMBIE_KINDS` 名单本来就存在，但它按 `enemy_kind` 判，
而 egt 怪的 kind 是 `egt_*` ⇒ 全部漏掉，每只 egt 怪死亡仍播 2.4~2.6 s 倒地段、
还留一具尸体。**长得像僵尸的，就该按僵尸的规矩死。**

结果：33 只里 19 只无尸体、16 只走绿方块爆开（其余借炸弹果/召唤师壳的走爆炸表现）。

## 6. 不绕圈（远程走位三段）

旧写法 `tangent * 0.78 + radial * radial_weight`，其中
`radial_weight = clamp((distance - ideal) / ideal, -1, 1)`。
问题在**站位附近 `radial_weight ≈ 0`** ⇒ 切向项 0.78 成了唯一分量
⇒ 归一化后就是**纯切向满速绕圈**，而且比靠近时还快。

改成三段：

| 区间 | 行为 |
|---|---|
| > 站位 + 容差（18%，最少 0.9 m） | **直线逼近**，无侧移 |
| < 站位 − 容差 | 后撤（94%）+ 30% 侧移，避免和同伴撞 |
| 带内 | 偏差 < 容差 1/4 就**站住**，否则 35% 速度归位 |

## 6.5 朝向不再横着（同日第二轮，业主："有些怪物会横着移动，怪物没有向着自己的移动方向"）

旧实现每帧**无条件朝玩家转**（只有 `telegraph` 慢转算是例外）。
这对直线追击没问题，但复刻怪里有一大批「位移方向与朝玩家方向无关」的形态：

| 形态 | 位移方向 | 旧表现 |
|---|---|---|
| 逃跑（钥匙 / 运气小子） | `away.rotated(±90°)` 沿墙溜 | **纯 90° 横移** |
| 游荡（枪精灵） | 玩家周围随机点 | 随机角度横移 |
| 远程后撤 | 背离玩家 | 倒退走 |
| 搜索 / 归家 / 巡逻 | 朝失踪点 / 家 / 巡逻点 | 横移（这几条根本不进转向代码）|

这和上一节「高速移动却播走路动画」是同一类毛病：**位移由 A 决定、表现由 B 决定，中间没对齐**。

### 6.5.1 做法：记真实位移方向，按夹角分模式（带迟滞）

- `_commit_motion()` 在 `move_and_slide()` **之后**用位置差记 `_last_move_direction` /
  `_last_move_speed`。**不能用 `velocity`**：撞墙时它仍指墙外，实际位移是零或沿墙。
- 新函数 `_update_facing(to_target, delta)`：

| 条件 | 结果 |
|---|---|
| 夹角 > 55° 且本帧真的在走 | 转身朝**移动方向**（速率 14/s）|
| 夹角 < 40° | 退回朝玩家（两阈值差 15° 构成迟滞，防边界抖动）|
| 模式切换后 0.28 s 内 | 不许翻回去 |
| 位移方向超过 0.12 s 没更新 | 视为没在走，朝玩家 |
| 实际速度 < 0.40 m/s | 视为站定，朝玩家 |
| `telegraph` / `attack` / `recovery` / `stagger` / `dead` / `dormant` | **永远朝玩家**（枪口要对准弹道）|

**夹角 < 55° 的侧移刻意保留朝玩家**：那是弹幕游戏里"边瞄边挪"的标准姿态，
幅度小、看起来是原地微调，不是平移。全转身反而会让人读不出它在瞄哪。

### 6.5.2 两条容易漏的接线

1. **无目标分支根本不进转向代码**：`_physics_process` 在 `_target == null` 时提前 `return`，
   到不了末尾那次转身 ⇒ `_tick_search` / `_tick_return` / `_tick_patrol` 内部各补一次
   `_update_facing(Vector3.ZERO, delta)`。不补的话怪会**沿上一次的朝向一直横着走**。
2. **时间在 `_update_facing` 内部推**，不在 `_physics_process` 里 ——
   这样"每帧恰好一次"只有一个真源，验收直接调本函数就能量到与实机相同的时序。

### 6.5.3 验收 `tools/_egt_facing_probe.gd`

| 样本 | 期望 | 实测 |
|---|---|---|
| 纯横移 90° | forward ≈ 位移方向 | 偏位移 0.0° |
| 后退 180° | 同上 | 偏位移 0.0° |
| 小侧移 30° | **仍朝玩家** | 偏玩家 0.0° |
| 位移方向过期 | **仍朝玩家** | 偏玩家 0.0° |
| 举枪 + 横移 | **仍朝玩家** | 偏玩家 0.0° |

三只样本（远程 / 逃跑 / 游荡）× 五种情境。

**负控已验证**：把 `FACE_MOVEMENT_DEG` 改成 200（永不进入 movement），6 项立刻红
（90°/180° 全部回落到 90°/180°）。这条证明探针能抓到这个 bug，不是假绿。

**另一个假绿陷阱**：第一版用 `move_and_slide()` 造位移，12 个样本全测出 0.0° ——
因为它在 `set_physics_process(false)` 的 `_ready` 同步循环里**根本不推进位置**
（实测 `global_position` 8 帧纹丝不动），于是 `_last_move_direction` 恒为 ZERO。
⇒ 现在直接注入位移方向，只验决策逻辑；位移来源的正确性归 `verify_3d_enemy_behavior_flow`。

### 7.1 探针断言的三件事（都能被数值证伪）

- **受击**：站定挨打播、**追击中挨打不播**、太阳伤害不播。
  用「同状态两种速度」对比，这是唯一能把「按速度判」和「按状态名判」分开的形状。
- **移动段**：`patrol` + 满速 ⇒ running；`patrol` + 25% ⇒ walking；
  `idle` + 满速 ⇒ 不能是站立段。
- **走位**：远处速度方向 · 指向玩家 ≥ 0.85；站位速度 ≤ 0.30 m/s；贴脸 · 方向 ≤ −0.55。
- **对比度**：33 只逐只算「解算后色差 ≥ 0.35」，并断言容器里至少有一件零件。

### 7.2 目视验收

`tools/_egt_distinction_views` 出 5 视角 × 12 只（正 / 右 / 背 / 3-4 / **俯视 45°**）。
俯视档不是凑数：**水平环（头巾 / 光环 / 尖冠）从水平视角看永远是线**，
只凭正/侧/背三视会误判成「环没做出来」。

### 7.3 未执行 / 已知道的缺口

- **真实跑局未验**：探针只验到「状态与速度给出的段正确」「给定位移方向时的转身正确」，
  没有目视确认 11 m/s 突进时动作是否真的跟得上、以及被同伴推挤时朝向会不会抖
  （需要真机跑一局）。
- **ID 与模型的对应仍不唯一**：三个 GLB 服务 19~22 只怪，
  只能保证「同族内不撞」，跨族仍会出现两只共用同一模型的情况
  （子弹族借保安、分裂族借小僵尸）。要彻底「不混用」需要新美术。
- **拟态怪仍摘除在编成之外**（宝箱没做正式设计），它的标识设计保留着。
