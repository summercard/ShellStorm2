# 2026-11-23 支线回退隐藏门与常开入口

归属 WORLD-SECRET。设计与验收契约见[支线秘密房间设计](../design/支线秘密房间设计.md)（§4.1–4.3、§5.2、§5.5、§11.1）。

## 本轮改动

- **主线入口 `S1–S4` 改为常开无板门。** 装配走 `configure_portal()`，直接呈现破板后的 45° 半掩门叶，不再创建木板层与板体碰撞，也不用等入口房清完。`SecretDoor3D` 新增 `_is_open_portal`，让旧快照即使缺 `broken` 字段也不会把常开门恢复成「字段锁定但实际可传送」的假状态；不能只判 `_has_teleport`，`S*`/`X*` 谜题门同样有传送目标。
- **新增首间回退门 `E0/E1`。** 每条已生成支线的首间房，在入口落点附近、真实地砖边缘的实体背墙前装一扇无板隐藏门，按 E 回到本支线原主线入口房的有效站位。末端 `R0/R1` 保留，分别服务「回入口」和「走到出口」两种选择。墙始终封闭，不为暗门开门洞，也不注册普通门或走廊。
- **`R0/R1` 不再按房间尺寸写死东墙中点。** 改为在真实地砖边缘按「外侧无砖 + 射线确认是实体墙」挑候选，再按门前可达性排序；门腔留 1.72 m，避免门叶埋墙。找不到实体墙时退回落点旁的交互，并 push_warning 记录。
- **落点改就近可站面。** `_inside_point()` 先取门前 1.2 m，若不在房内或站不住，就在房内按 0.5 m 步长与横向偏移找最近的可走面；主线远端暗门可能装在房壳凹边，门前不一定属于房间。
- **子图房态按玩家脚点判定。** 普通门是步行过界，胶囊先碰 `RoomTrigger` 时脚点可能还在房外，单次 `body_entered` 被拒后不再补发。改由 `_physics_process` 用脚点所在房间确认变更，只上报房态与首访，编成、共享存活账和掉落仍归 `Dungeon3D`。
- **`settle_sites()` 末尾刷新两端回退门落点。** 晚到的手摆门或墙面外推会改主图 `S*` 的 position/normal，回退门目标必须跟最终位点走，门自身位置不跟着主图移动。
- **房壳只换真门。** 子图房壳里只有实际连走廊的普通门才把实墙换成门墙，传送门不改房壳。

## 账本

场景账本《域变更日志》新增 `v0.1.103`（2026-11-22，支线回退隐藏门／既有资产复用）。复用既有门叶 `ENV-EXPEDITION-SECRET-DOOR-LEAF` 与板体 `ENV-EXPEDITION-SECRET-DOOR-BOARDS`（《资产主表》967–968、《3D-场景通用》789–790），资产本体、AssetID、版本、路径与 SHA-256 均未变，不新增资产行，未改 `ledger_split_baseline.json`。

另修一处工具层问题：该账本被表格软件重存后，把《资产主表》派生列「查重结果」写成了逐格 CSE 数组公式（1030 格）。`verify_ledger_split.py` 用 `str(cell.value)` 比对公式文本，读到的是 `ArrayFormula` 对象，于是整表报 `dedupe_result_formula_wrong`（1054 条）。已把该列还原成普通公式文本，取值与判定逻辑一个没动；同一轮里被修的 12 个 `==COUNTA(...)` 前缀错误（旧版 openpyxl 往返留下）保留修复结果。
