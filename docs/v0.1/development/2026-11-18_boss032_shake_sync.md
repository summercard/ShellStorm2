# 远征01 3.2：怒吼震屏与「啊啊啊啊！」同帧

日期：2026-11-18
归属：NARRATIVE-TRIGGER / BOSS-STAGES
状态：剧本与文档已改；真实渲染已取得证据

## 1. 业主指令

> 「boss剧情那块 一个屏幕震动的时机 要和系统：“啊啊啊啊啊啊”这段对话同时出现，目前迟了一些。」

## 2. 问题

3.2 结尾原本是「先喊完、再震」：

| cue | 改前时刻 | 说明 |
|---|---|---|
| `ui.subtitle`「啊啊啊啊！」 | 65.684 | `auto=2.834`，念到 68.518 |
| `camera.shake` | **68.283** | duration 0.65、amplitude 0.12 |

震屏起点 68.283 比出字起点 65.684 晚 **2.599 秒**，落在台词尾部；观感是「喊完了才晃」。

## 3. 改法

把 `camera.shake` 整条移到「啊啊啊啊！」这条 `ui.subtitle` 之后，`at` 改成与出字完全相同的 `65.684`：

```json
{ "at": 65.684, "do": "ui.subtitle", "speaker": "系统", "speaker_id": "boss_monitor002",
  "text": "啊啊啊啊！", "auto": 2.834 },
{ "at": 65.684, "do": "camera.shake", "duration": 0.65, "amplitude": 0.12 }
```

三点说明：

1. **同帧同秒**：两条 cue 的 `at` 都是 65.684，导演按 `at` 升序派发，数组顺序保证字幕先于震屏，不会出现「震了但没有字」的一帧。
2. **不是「喊完才震」**：震屏覆盖 65.684—66.334，正好压在台词开头 0.65 秒，与嘶吼的爆发点对齐；台词后续 2.18 秒不再有震动。
3. **参数没动**：`duration 0.65`、`amplitude 0.12` 保持原值，只改时机。

不动的部分：`camera.shot boss_roar_front_close` 仍在 63.683 切怒吼特写；`story.boss.activate` 仍在 68.936；`flow.end` 与 `duration` 仍是 69.183。
