### 20.5 实装与验收记录

- `CodeHUDGlyph` 统一绘制机器人、枪械、换弹、冲刺、护盾/探照、交互、暂停等图标；`NeonFrameControl` 统一绘制切角、扫描线和多层辉光。两者均可独立复用，不读取任何图片。
- `Dungeon3D` 使用独立 `ReferenceCombatHUD`；生命、弹药、实例尾号、命运槽、房间、钥匙、魂、计时与状态提示全部由现有信号/运行时快照更新，不再保留旧 2D 节点路径。
- `DungeonMinimap3D` 使用玩家中心固定的圆形雷达：地图、通道和敌点相对玩家移动；房间矩形只在完整位于雷达内容圆内时绘制，通道裁切到圆边，敌点越界隐藏。
- `verify_reference_hud_fate_visual` 在 Metal/OpenGL 真实渲染器中输出 `reference_combat_hud.png` 与 `reference_fate_three_choice.png`，并检查三张竖卡、三种天体专名、圆形地图和零 `TextureRect` 位图依赖。
- `verify_tactical_inventory_minimap_flow` 与 `verify_tactical_inventory_minimap_visual` 复验通过，装备卸下、单悬停卡、真实拖拽、地面丢弃及地图红点未退化。
- 性能预算按永久结构代理、动态流送细节、固定 UI 壳和 3D 物品预览分账；2026-08-13最新实测为初始总节点/世界节点`2376/2229`（含全部已生成房间墙/地面/门框代理）、完全探索`2458/2306`、物品预览`11`，60FPS墙钟节拍`16.67ms/18ms`。结构代理增加不允许放宽完全探索、ACTIVE房、灯或帧节拍门禁；1800秒历史长测与本次结构改动后的短程专项分开记录，详见[性能优化与热管理](../../13_技术施工_性能优化与热管理.md)。
