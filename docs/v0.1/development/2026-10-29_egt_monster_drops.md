# 远征03 怪物掉落对齐《挺进地牢》第一层

**日期**：2026-10-29
**范围**：远征03 的 33 只复刻怪 + 清房结算
**起因**：业主问「掉落呢？」——此前三轮只对齐了怪物本身（种类 / 数值 / 弹速 / 行为），掉落从未核对。

## 1. 先实测，再改

读代码只能看到"走哪条覆盖链"，看不到「通用公式 × 池权重」叠出来的真实产出。
所以先写 `tools/_egt_drop_probe.gd`，直接调 `RuntimeRewardCoordinator.resolve_kill()`，
每只怪跑 4000 次。

**改前的数字（33 只逐只相同，因为它们全走同一条通用公式）：**

| 项 | 实测 | 原作 |
|---|---|---|
| 掉装备 | 16%（含蓝图 `bp_pistol`、模块、配件） | **0** |
| 掉弹药 | 35% 每只，30–50 发 | 清房一次 6% |
| 铸币 | 100% 每只 3 个 | 概率掉，自爆族不掉 |
| 清房结算 | **不存在**（房间无 `reward_plan`） | 20% 拾取物 + 6% 弹药 |

一层 ~68 只怪 × 16% ≈ 11 件白送的装备，而原作一层是「2 宝箱 + 1 商店」。
**这一层的装备密度是原作的 4 倍**，且不需要钥匙、不赌品质。

## 2. 原作事实（单独成文）

→ [普通怪掉落](../reference/挺进地牢/普通怪掉落.md)

三条硬规则：普通怪不掉装备 / 自爆怪不掉铸币 / 弹药是清房结算（20% 拾取物、6% 弹药）。
还有两只逃跑怪的招牌掉落：Keybullet Kin 必掉钥匙、Chance Kin 必掉随机拾取物。
**具体掉率百分比 wiki 没有**（只写 "often"），所以「铸币概率」这项我们按项目裁定走，没有假装对齐。

## 3. 改了什么

### 3.1 新增 `legacy_fallback`（MonsterDropTable）

掉落表原本的语义是「表只登记部分怪，没登记的走通用公式兜底」。这个兜底正是问题所在：
只要有一只怪没写进表，它就会拿到 16% 装备 + 34% 备弹 —— 与本关口径完全相反，**而且是静默的**。

改法：表级 `legacy_fallback`（默认 `true`，远征01 行为逐字不变）。置 `false` 时本表即
**全量清单**：未列出的普通怪明确不掉物品。`compile()` 输出 `full_coverage`，
`RewardService._monster_spec_for()` 在 `full_coverage` 时直接返回空 spec。

顺带的好处：将来往远征03 加新怪时，它默认「不掉物品」，而不是静默继承一套错误规则。

### 3.2 铸币分档 + 自爆族为零

`monster_rules.currency.per_kind`，按血量档给 base（1/2/3/5/8）。自爆族 6 只 **base = 0**：
`_resolve_currency_entry()` 在 `amount <= 0` 时直接 return，不生成 grant ——
地上不会出现"0 元的金币球"这种半成品状态。

### 3.3 清房结算走 `clear_rewards` → `room.reward_plan.clear`

没有给 `Dungeon3D` 加任何分支。清房那段代码（`_mark_room_cleared` → `resolve_clear`）
本来就存在，远征03 只是第一次有房间声明 `clear` 槽位。

`FloorPlanGenerator._clear_reward_spec_for()` 在生成期把 `clear_rewards` 编译成内联 spec，
写进房间记录的 `reward_plan`。判据与 `spawn_roster` 那段刻意相同：
只有"有怪的房"（非走廊、非和平区）才结算。

### 3.4 两只逃跑怪

`monster_drop_table` 只有 2 行：

- `egt_keybullet_kin` → `item_room_key` ×1，chance 1.0
- `egt_chance_kin` → `@pool:loot_floor_1_2`（随机拾取物），chance 1.0

## 4. 踩到的三个坑

**① 内联 spec 不能带 `spec_id`。**
`RewardSpec.normalize_ref()` **先**看 `spec_id`，有它就去命名规格表里查 ——
内联 spec 必然查不到，于是整条清房掉落以 `UNKNOWN_SPEC` 静默作废。
症状极具误导性：`_clear_reward_spec_for()` 返回的 spec 单独校验是**通过**的，
探针也"没报错"，只是 `resolve_clear()` 回来空的（实测拾取物率 0.0%）。

**② 探针自己的判据也得改口径。**
第一版判据写的是「金币必掉率 > 45% 就报错」，那是照原作「概率掉」写的。
但项目在 2026-10-14 已裁定「所有被击败的怪 100% 必掉货币」——探针按错的那一版判，
改完反而全红。最终把判据拆成两层：原作规则（不掉装备 / 不掉弹药 / 自爆族不掉）
+ 项目裁定（非自爆族 100% 必掉货币）。

**③ `configure_level_currency` 漏了会假死。**
探针一开始只装了掉落表没装货币分档，结果 33 只怪全部"空手 100%"——
看起来像掉落表配错了，实际是货币通道没接上。这类"两个独立通道只接了一个"的
症状，只能靠实测数字发现，读代码不会报错。

## 5. 改后实测

```
egt_bullet_kin        物品 0.0%  弹药 0.0%  货币 100.0%  均 3.00
egt_gun_nut           物品 0.0%  弹药 0.0%  货币 100.0%  均 9.00
egt_pinhead           物品 0.0%  弹药 0.0%  货币   0.0%  均 0.00   ← 自爆族
egt_keybullet_kin     物品 100.0% (item_room_key 100%)  货币 100.0%
egt_chance_kin        物品  93.3%  弹药 6.7%  货币 100.0%          ← 随机拾取物抽到弹药
清房：拾取物 17.1%（配 20%）｜弹药 7.3%（配 6%）
     构成 血瓶 57.2% / 钥匙 33.1% / 货币 9.7%
```

清房两项与配置有 2~3 个百分点的偏差（拾取物偏低、弹药偏高），来自
「拾取物抽到弹药时同时计进弹药率」这条统计口径 —— 是**统计方式**的偏差，
不是掉落配置错。判据容差设 ±3%，趋势方向是保守（略少给），保留。

## 7. 这次没解决的

**装备来源断了一条。**
普通怪不再掉装备之后，这一层的装备应该来自宝箱房 —— 但远征03 的 `REWARD` 房
在运行时**没有任何处理**（`content_type` 为空，归入 `FLOW_PEACEFUL_KINDS`，
是纯空房间）。所以现在这一层除怪物掉落外**没有第二个装备来源**。

本次的缓解：保留 Chance Kin 的随机拾取物（抽 `loot_floor_1_2`，含装备），
但它是「一层 1 只、11 秒内没打死就传送消失」，量级远低于原来的每只 16%。

真正的补法是**做宝箱房**：开箱交互、钥匙消耗、品质分级、2.25% 拟态。
这是一整套新功能，不在本次范围。**在它做出来之前，这一层的装备产出会明显低于远征01。**

其余仍欠的掉落项（原作有、我们没有）：

| 项 | 说明 |
|---|---|
| Coolness 保底累积 | 原作清房掉落有保底（1% 起，每次落空累加，上限 80%）。我们无 Coolness，不做 |
| 铸币面额 1/5/50 | 我们只有单一 `extraction_points` |
| 陷阱击杀减铸币 | 我们没有"玩家触发陷阱击杀"这条链路 |
| 坑杀不掉钥匙 | 我们没有坑 |
