# 小僵尸/警察僵尸：手电扫到时走路段被误判成跑步段（"走路抽一下"）

日期：2026-11-01；记录ID：ENEMY-AI-20261101-GAIT-LIGHT-STEP；功能ID：`ENEMY-AI`、`ASSET-PIPELINE`；工程版本：0.1.0。
代码基线：`7120c0ca7` 加本会话未提交的表现层修正；交付提交：工作区。

## 来源与复现条件

业主义务描述两段，第一轮只给了"走路动画为什么会向着一个方向抽搐一下"，第二轮补了关键条件：
**"好像是在阴影下，受到手电光照的情况下，表现会有异常"**。

这个补充把范围从"动画数据坏了"直接改判成"光照改变了表现层判断"，两者修法完全不同。
第二轮按光照路径定位，确认前一轮找到的骨骼曲线锯齿（髋部单帧 +1.9~2.9cm）是**同一症状的另一处**，
不是根因。

## 根因

三段串联：

1. `Enemy3D.get_effective_move_speed()` 在 `STATE_ARTIFICIAL_LIGHT` 下乘
   `ARTIFICIAL_LIGHT_MOVE_MULTIPLIER = 0.40`（手电照到怪会减速 60%，是玩法设计）。
2. `Enemy3D._process()` **每帧**把这个值当 `base_speed` 传给
   `EnemyAvatar3D.sync_presentation()`，表现层用它当归一化分母：
   `_locomotion_clip()` 判 `实际速度 / base_speed >= RUN_SPEED_RATIO(0.62)` 就改播跑步段。
3. 分母是**阶跃**的，分子（`get_real_velocity()`）由 `_steer_planar()` 以
   `delta*3.2`（巡逻）/ `delta*5.5`（追击）的权重**指数衰减**。两者不同步 ⇒
   手电扫到的那几帧里比值冲过 0.62 再落回 0.61。

比值越过阈值 → 段名 `walking → running`；8 帧后落回 → `running → walking`。
而换段时 `_sample = fmod(_clock, 段长)`，1.6s 的走路段与 0.8s 的跑步段把同一绝对时刻
映射到**完全不同的姿势**，且 `play()` + `seek()` 没有混合 ⇒ **一帧内骨骼被硬拽**。

## 实测（改前）

手电每 1.5s 扫一次、两只怪自然巡逻 15 秒，逐帧记骨姿态（60fps，单帧跳变中位 1.6°）：

| 怪物 | 段切换次数 | 单帧最大跳变 | 其中 >12° |
|---|---|---|---|
| 小僵尸（melee_chaser） | 8 | 69.4°（L_Thigh） | 8 |
| 警察僵尸（ranged_caster） | 8 | 82.6°（L_Thigh） | 8 |

- 8 次全部落在手电扫到的那一刻（f=91/271/451/811）及其后 8 帧（f=99/279/459/819）；
- 越过阈值时的比值稳定在 **0.77**，回落时稳定在 **0.61**（阈值 0.62）；
- 相对中位帧 43~50 倍 ⇒ 肉眼就是"走路走着突然抽一下"，且因为是从走路切到跑步，
  每次都是同一个方向（腿抬得更高、摆得更快）。

同一条件对胖子僵尸不成立：它的 `walking` 是独立动作源，且它的巡逻速度分档与光照惩罚
不构成同样的瞬时穿越（本轮未改动它）。

## 修法

只改表现层，把**分母平滑成和分子一样的指数跟随**：

- 两个表现脚本各加 `BASE_SPEED_SMOOTH_SEC := 0.30` 与 `_smooth_base_speed()`；
- 用 `_clock` 差分算步长，`weight = 1 - exp(-step / 0.30)`，只在首次（`_base_speed <= 0`）直接取初值；
- `sync_state()` 里原来的 `if base_speed > 0.0: _base_speed = base_speed` 换成调用它。

时间常数 0.30s 的推导：巡逻的 `_steer_planar` 权重是 `delta*3.2` ⇒ 时间常数 1/3.2 = 0.3125s；
两者取同量级，比值在过渡期稳定等于真实档位（0.32 / 1.0），不再穿越阈值。
追击（`delta*5.5`）衰减更快，平滑后的分母略高于分子，比值只会**偏高**（仍判跑步），无害。

**为什么不改成"分母用不含光照惩罚的 move_speed"**：那样数学上彻底没有过渡期，但被手电照着的
追击怪（真实移速只剩 0.4×满速，与巡逻走路几乎同速）会改播走路段 —— 这是观感取舍，
属于业主判断，本轮不擅自改；稳态读数保持与改前逐字相同。

`get_presentation_snapshot()` 增加 `base_speed` / `speed_ratio` 两个只读字段，
让"手电扫到时比值不冲阈值"这件事可以被断言，而不是只能靠肉眼。

## 新增判据的位置与两条坑

判据放在 `verify_enemy_illumination_states` 的末尾，直接驱动**表现层预制体**
（`enm_melee_fungboar01_root_top3d.tscn`），不走整只 `Enemy3D`：

1. 走 `Enemy3D.force_refresh_illumination()` 会在被照亮时 `set_runtime_active(true)`
   重建 Avatar，缓存下来的 `Skeleton3D` 指针变成已释放实例 —— headless 实测 **signal 11**；
2. 这条用例要连跑 90 个物理帧，而该场景的怪**没有地面**。放在前面会让主用例那只怪
   自由落体 1.5s 被判落地失败回收，后面依赖它的用例全打空（`previously freed`）。
   所以既把它排到最后，也在 `remove_child + free()` 时立刻释放视觉件而不是 `queue_free()`。

## 第二轮：第一轮没修好，真因是「换段硬切」而不是比值门限

业主反馈 "还是会这样啊, 受到光照正常来说只会缩短角色的移动速度,和动画播放速度. 不会这样吧."
这句话把判据从"比值要不要平滑"改成了"**根本不该换段**"。重查后确实找到三条独立原因，
第一轮只碰到其中一条（分母平滑），所以现象仍在。

### ① 换段时相位被重置（主因）

`_sample = fmod(_clock, length)` 用的是**绝对时钟**。走路段 1.6 s、跑步段 0.8 s
⇒ 同一个 `_clock` 在兩段里落在完全不同的姿势上（实测同刻差 35~67°，中位帧 1.6° 的 22~42 倍），
而 `play() + seek()` 没有混合 ⇒ **只要换段就抽一下**。

改成归一化相位 `_phase ∈ [0,1)` 跨段保留后，剩 35~67°（`L/R_Upperarm`）——
因为走路手臂自然垂摆、跑步抬起，**这部分相位对齐消不掉**，必须靠淡入。

### ② `AnimationPlayer.play(name, custom_blend)` 才是解

实测：直接换段 60.4°，`play("running", 0.20)` + seek 当帧 **0.0°**。
于是循环移动段之间走 `CLIP_BLEND_SEC = 0.16 s` 交叉淡化（走路周期的 1/10）；
攻击/受击/死亡**不参与**——它们有判定帧，靠 `seek` 钉死，混进去前摇就读不出来了。

三个实现坑（都实测踩过）：
- **同段时不能再调 `play()`**：每次调用都会重启动画并打断淡化，跳变从 60° 变成 64°；
- **淡化期不能 `seek()`**：seek 会把姿势直接钉到新段，淡化白做；
- **淡化期必须 `advance(delta)`**：`callback_mode_process = MANUAL` 下引擎不会自己推进，
  不 advance 就等于冻结 0.16 s。

### ③ 警察僵尸的动画根本没在循环（顺带修）

它的 GLB **没有 post-import 脚本**（`import_script/path=""`），导入后全部 10 段
`loop_mode = LOOP_NONE`。表现层靠 `_looping` 决定是否推进相位，判成 false ⇒ 相位恒为 0
⇒ 画面定格在某一帧。现在两个表现脚本都在 `_ready()` 里把循环段的 `loop_mode` 钉成
`LOOP_LINEAR`，不再依赖导入配置。

### ④ 播放速度随移动速度变化（业主的期望）

新增 `_playback_rate() = 实际速度 ÷ 该段标称速度`（进段时记录，钳制 0.25~2.0），
`_phase` 按它推进。手电照到减速时动画同步放慢（实测稳态 0.42×），不再靠换段表达速度。

### ⑤ 迟滞

`RUN_EXIT_RATIO = 0.50`（退出）与 `RUN_SPEED_RATIO = 0.62`（进入）构成 0.12 的迟滞带，
瞬态减速（手电、击退、贴墙推挤）不会去碰段名。

### 第二轮实测

| 场景 | 改前 | 改后 |
|---|---|---|
| 手电阶跃（巡逻，15 s 内多次扫射） | 8 次换段 / 单帧 69.4° | **0 次换段 / 2.48°** |
| 强制 walking↔running 来回切 | 67.2° | **11.7°** |
| 播放速率（被照稳态） | 恒 1.00 | **0.42（跟着减速）** |
| 真渲染逐帧像素差（排除开关灯帧） | — | 中位 0.85 / 最大 4.4×，无单帧尖峰；开灯后 10 帧为平滑过渡 |

警察僵尸同口径：0 次换段 / 5.73°。

### 第二轮验收

`verify_enemy_illumination_states` 里把两件事都固化成断言：
- 阶跃期不许出现跑步段 + 单帧 < 12°（第一轮就有的）；
- **换段本身不许抽**：来回切 walking↔running，单帧 < 12°。
判定间隔必须长于 `CLIP_BLEND_SEC`（用 20 帧 / 0.33 s），否则量到的是"上一段淡化被打断"的叠加态（12 帧时测出 21.3°，是假红）。

改后 `exit 0`；只把 melee 表现脚本回退到 HEAD，三条同时红：
`走路段被切成跑步段 8 帧`、`手电扫到时单帧骨骼跳变 56.4°`、`走路/跑步换段时单帧骨骼跳变 63.7°`。

`_egt_presentation_probe` 全绿（满速=running / 慢速=walking / 站立高速=running 三档读数不变）。
`verify_melee_zombie_presentation` / `verify_security_zombie_presentation` 与改前**逐项同红**（既有债务）。

### 第二轮新增的两条坑（下次直接照做）

- **`callback_mode_process = MANUAL` 下单独 `seek()` 不驱动骨架**：必须 `play() + seek()` 成对，
  或者 `advance()`。本轮踩过：以为已经改好，实际画面定格，髋部高度恒定 `0.3980` 才发现。
- 交叉淡化的间隔判据要 > `CLIP_BLEND_SEC`，否则量到叠加态。
