# 2026-10-18 武器改造台改为 6×6 炼金盘（炼金抽卡）

功能ID：`RUN-FORGE`。设计主源：[07.2 玩法系统｜武器改造台](../07.2_玩法系统_武器改造台.md)。

## 业主口径

> 武器改造台改成用来升级武器用的。打开后是一个 6×6 的物品格子（包裹里的存放方式），可以把武器、物品丢进去炼金，用来产出不一样属性的武器、品质和属性。枪械品质有蓝、紫、金，同时还有随机的弹药模块。主要先从这些地方随机，主要是用来抽卡用的。如果里头放了武器，会以这个武器为蓝本进行抽卡；如果里头是武器模块，一定数量后也能组合出武器；如果是 2 把武器，会产生更加随机的效果。

## 规则实现

新增 `src/weapons/WeaponForge.gd`（纯规则层，无场景依赖）：

- **入场**：任意非空物品都能当材料（2026-10-18 第三轮裁决）。盘内只分**蓝本**（武器）与**材料**（其余一切）两种角色。
- **熔炼值**：按 `rarity` 折算，common 1 / uncommon 2 / rare 3 / epic 4 / legendary 6。用于 R1 燃料门槛（≥3）与 R3 产出数量。
- **稀有度分**：按 `rarity` 折算，common **0** / uncommon 1 / rare 2 / epic 4 / legendary 7，品质另加 紫 +1 / 金 +2。**这是品质概率的唯一驱动项**。
- **R1 重铸**：1 把武器 + 材料熔炼值 ≥3。蓝本 = 该武器，产出 1 把。
- **R2 融合**：≥2 把武器。蓝本 = **等概率随机**（`pick_blueprint(weapons, rng)`，两把各 50%）；弹种从「投入模块 ∪ 各枪自带绑定弹种」加权随机；`n=2` 额外附 1 个随机配件、`n≥3` 附 2 个。
- **R3 合成**：0 武器 + 熔炼值 ≥6。`floor(V/6)` 把，上限 3，枪身从工坊 tier 可用池随机。品质同样吃稀有度分。
- **品质权重**（公式见 07.2 §4.1）：以 `WeaponDropGrade.ROLL_WEIGHTS` 为基线，武器数按 0.55/1.35/1.75 逐把放大，**材料稀有度分**按 −0.015/+0.011/+0.007 每点倾斜，蓝权重有 0.05 地板。三条配方共用一条式子（n=0 时幂取 0），R3 也吃稀有度分。
- **弹种**：两层候选 —— 投入模块按堆叠数量计票 + 每把投入武器自带绑定弹种各计 1 票；候选全空才回落 `WeaponBulletDrop.roll`。
- **金币费用**：`cost = max(min, ceil(投入估值×rate))`，估值 = Σ(物品表 `price` × 数量)。费率 R1 0.30 / R2 0.40 / R3 0.50，最低价 20/40/40。
- **产出实例**：新实例 ID、`drop_grade` 落盘、命运槽走 `apply_to_item`（只加一次）、`fate_upgrades` 为空、`bullet_module_locked = false`（锁定是野生掉落专属）。

### 为什么 R1 必须有燃料

单把枪单独重铸时，品质池只有上升档没有下降档（产出永远 ≥ 蓝），玩家可以拿同一把枪反复掷而只承担"枪还是枪"的风险 —— 纯套利。把成本钉在消耗品上，赌局才成立。经济核算见 07.2 §4.3：投 1 枪 + 1 标准弹，成本 30，期望数值增益折合约 4.9，净亏约 25；博金的期望成本约 600 金币。

### R2 的"更随机"落在哪

不能只靠概率数字变大，否则玩家感觉不到。落成三件可验证的事：

1. **蓝本随机**：两把枪各 50%，出来的是哪把不可预知。
2. **弹种随机（含枪的属性）**：两把枪各自自带的绑定弹种也参与抽取，所以「步枪带穿透 + 霰弹枪带爆炸」不投任何模块也能随机出其中之一。
3. **随机附带配件**：`n=2` 一个、`n≥3` 两个，从该枪身实际支持的槽位与已解锁配件池交集里抽，不重复占槽。R1 出来的枪永远光板，R2 出来的枪可能自带瞄具或大弹匣。

### 材料稀有度为什么能提品质却不崩

三道互相独立的堵口：

1. **common 稀有度分 = 0** —— 白装能凑数量（熔炼值 1），但拉不动品质。堆 36 格白装，金概率仍停在 5%。
2. **蓝权重地板 0.05** —— 稀有材料再多也留 5% 基础池，概率上行但不会 100%。
3. **金币费用按投入估值计** —— 烧稀有材料本身就贵。加 1 件 epic（R=4）把金概率 5.0% → 8.0%，费用同时从 72 涨到 90+。

实测梯度（n=1）：R=0 → 70/25/5；R=3 → 64.9/28.0/7.0；R=10 → 53.4/35.0/11.7；R=20 → 37.7/44.3/17.9；R=40 → 8.9/61.6/29.5。

### 金币费用为什么这样定

| 配方 | rate | min | 例 |
|---|---|---|---|
| R1 重铸 | 0.30 | 20 | 步枪 150 + 标准弹 30 = 180 ⇒ **54** |
| R2 融合 | 0.40 | 40 | 步枪 150 + 手枪 70 = 220 ⇒ **88** |
| R3 合成 | 0.50 | 40 | 标准弹 ×6 = 180 ⇒ **90** |

- **按投入估值而不是固定价**：固定价会让「熔 350 的蓄力炮」和「熔 45 的球棒」同价，等于鼓励拿最便宜的垃圾反复刷。
- **R3 费率最高**：R2 已经牺牲一把枪（实物成本很重），R3 只烧模块，不加价就会变成比 R1/R2 更划算的稳定套利。
- 对照单局金币产出（普通怪 4–12 / 精英 50+ / Boss 200+），保底搏一把金枪 ≈ 清两三个精英。

## 界面

`WorkbenchPanel` 全代码构建（`scenes/WorkbenchPanel.tscn` 只留空根节点）：

- 左栏 6×6 炼金盘（`GridInventoryBoard`，`slot_kind = "alchemy"`，36 格）。
- 右栏玩家背包棋盘（与 I 键同一 `InventoryModule` 数据源，可拖入）。
- 投入解析行实时显示：武器数 / 模块数 / 熔炼值 / 配方 / 三档品质概率。
- 盘内含武器时点「熔炼」先弹二次确认（写明销毁几把枪）。
- 关面板时盘内物品原样退回背包；放不下则整笔回滚并拒绝关闭。

`ItemSlot` 只加了一条拖拽反馈分支（`target_kind == "alchemy"`），拖放判定复用 `GridInventoryBoard.drop_validator`，没有新增第二条拖拽通路。
