## 1. 先做体检器，再动数值

没有"逐只检查"的工具就没有微调的依据。原有两条探针在这件事上都不够用：

| 探针 | 问题 |
|---|---|
| `tools/_egt_cadence_probe.gd` | 走真实关卡生成，本机实测 **hub_02 刷出 0 只怪**，探针仍打印 `EGT_CADENCE_DONE` —— 结论不可用 |
| `tools/_egt_enemy_motion_probe.gd` | 12 个房**全部「无怪（跳过）」**，仍然打印 `EGT_ENEMY_MOTION_PROBE_OK` —— 典型的假绿 |

所以新写 `tools/_egt_ai_flow_probe.gd`：自建 18×18 场地（四面墙 + 偏侧柱），
逐只加载**正式 prefab**、跑真实 `_physics_process`、站桩目标、6 秒采样。逐只输出：

| 指标 | 定义 | "不流畅"长什么样 |
|---|---|---|
| 出手次数 / 周期 | 相邻两次进入 `attack` 的间隔（墙钟） | 与配置冷却对不上 |
| 前摇 / 后摇 | `_telegraph_duration()` / `_recovery_duration()` 实际值 | 每轮有一段纯静止 |
| 静帧占比 | 水平速度 < 12% 移速 的帧占比 | 木桩感 |
| 路程 / 卡住 / 航向反转 | 位移累计 / 顶墙事件 / 航向 120° 反转次数 | 打转、抽搐 |

### 写这个探针踩的四个坑（都会产出"看起来很正常的假数据"）

1. **裸 `Enemy3D.new()` 没有碰撞体**。正式怪都从
   `assets/art/enemies/enemy_3d/enm_ecosystem_kit_root_top3d_v001.tscn` 实例化，
   裸 new 缺 `CollisionShape3D` / `Avatar` 两个子节点 ⇒ `apply_profile()` 里
   `if collision_shape != null` 整段跳过 ⇒ 怪直接穿过地板、自由落体到 `FALL_DEATH_DROP_M`
   以下 ⇒ `_die_from_fall_out()` 把它搬回出生点判死。**每只只跑 26 帧就 dead，
   而血量满、位置就在出生点** —— 最难查的一种。
2. **假玩家必须有 `current_hp`**，否则 `MonsterAIManager._target_is_legal()` 抛
   `Nonexistent 'float' constructor`，目标恒非法 ⇒ 33 只全部"静止 100%"。
3. **柱子不能摆在视线中间、怪必须朝向目标**。第一版把 2×2×3 的柱子放在 (0,0)，
   正好挡住怪→玩家的射线；又因为默认 basis 朝 -Z 而目标在 +X，视野锥判不中 ⇒ 全空转。
4. **周期只能用墙钟算**。原来每 `await physics_frame` 给计时器加 `1/30`，
   而 `physics_frame` 是 60 Hz ⇒ 计时走得比真实快一倍，「周期 2.77 s」其实是 1.39 s。
   我第一轮就是按这个错误读数得出"周期膨胀 2~3 倍"的结论，差点照着错误前提调数值。

## 2. 体检结果：问题不在"打得太快"，在"每轮有一半时间站着"

33 只逐只跑完（基线 `/tmp/ai_before.log`）：

- **33 只复刻怪没有一只声明 `telegraph` / `recovery`** ⇒ 全部落到通用缺省 **0.38 / 0.34**。
  按 `周期 = telegraph + max(cooldown, recovery)`，每轮有 **0.72 s 完全不动**。
- 静帧占比：**全体 27.6%，远程组 32.6%**（最高的子弹头巾 58%、空尖弹 51%）。
- 出手合计（30 只可比怪 × 6 秒）：**34 次**。
- 逃跑型（钥匙小子 / 运气小子）6 秒内**航向反转 6 次** —— 贴墙来回抽。
- 枪精灵 6 秒里只有 **52/360 帧**看得到玩家，45% 静止 —— 游荡跑丢目标。
- 周期本身**并没有膨胀**（还原真实时间后，与配置冷却的偏差都在 ±jitter 内）。

⇒ 所以业主说的"节奏不好"不是频率太高或太低，而是**每一拍里有一大段死的**，
加上"滑行急刹 → 定住 → 开枪 → 再起跑"的断点。

## 3. 六条微调（每条只对 `egt_*` 生效，塔楼怪零变化）

### M1 前摇 / 后摇按族定档（最主要的一条）

`_egt_telegraph_seconds()` / `_egt_recovery_seconds()`，表里声明仍优先：

| 骨架 | 前摇 | 后摇 | 依据 |
|---|---:|---:|---|
| volley 单发 | 0.20 | 0.12（射程 ≤7 的霰弹族 0.18） | 0.15 是"人眼读得起手"的下限；按信息量加：+0.02/发、宽扇形 +0.02 |
| volley 3 连 / 5 扇形 | 0.24 / 0.28~0.30 | 同上 | 连发与扇形要在前摇结束才看得出覆盖范围 |
| contact | 0.14 | 0.10 | 贴上来，不需要长预警 |
| explode / rush | 0.26 | 0.08 | "要炸了/要冲了"必须留够后退窗口；后摇只会拖慢这个信号 |
| support / orbit | 0.24 / 0.22 | 0.16 / 0.10 | |
| chance | 0.18 | 0.12 | |

每轮死时间 **0.72 → 0.32 s**（volley 单发）。这是静帧占比下降的主要来源。

### M2 远程绕圈站位 0.78 → 0.70

开火判据是 `distance <= attack_range`，而绕圈是切向运动、径向只被弱拉回。
站位贴着射程边缘时，绕半圈就飘出去 —— 那 1~2 秒里冷却早就好了。
8.2 m 射程的站位从 6.4 m 收到 5.7 m，留 ~30% 余量。塔楼老怪仍是 0.78（召唤师 0.86）。

### M3 前摇不再急刹，且慢转

- 位移：`_brake_planar(delta * 18)`（0.1 s 内归零）→ `_tick_egt_windup()` 压到 **35% 速度**继续踱步。
  前摇 0.2 s × 0.35 × 2.5 m/s ≈ 0.18 m，既是"边举枪边走半步"，又不会甩掉玩家算好的躲避点。
- 转向：前摇期间 `delta * 8.0` → **`delta * 2.6`**（≈150°/s，0.22 s 只转 33°）。
  否则怪会平滑跟着玩家转，"前摇"就失去"它瞄的是刚才那个点"的可读性 ——
  而那段错位正是玩家唯一的绕侧窗口。

### M4 丢目标后不再僵 2.2 秒

`_idle_patrol_delay()`：塔楼保持 2.2 s（守卫的驻守感），复刻怪 **0.9 s**。
实测逃跑型 / 冲撞型有 38~53% 的帧卡在 `idle`，其中 2.2 s 一段是纯静止。

### M5 逃跑型加方向粘性

`_tick_egt_flee()` 原来每帧取 `位置 − 玩家` 当方向：玩家小幅横移 + 自己贴墙停住，
方向就在两个值之间翻 —— **6 秒反转 6 次**，画面上是贴着墙抽搐。
现在：朝向最多每 0.30 s 更新一次；连续 0.25 s「有指令但没位移」判为顶墙 ⇒
沿墙 90° 侧向溜（拐向固定按实例 id 取，避免两侧来回换手）。

### M6 游荡型改绕玩家飞

`wander` 圆心从 `_home_position`（常在房角）改为**当前目标**，半径 8.0 → **4.5**。
枪精灵 6 秒内看得到玩家的帧数 **52/360 → 103/360**，静帧 43% → 7%。

### M7 逃跑型不再白吃房间攻击窗口

`_perform_egt_attack()` 的 `flee` 分支是空实现，但调用前 `_attack_timer` 已经设好、
节拍器窗口也已经取走 —— 每 1.2 s 一只逃跑怪白吃一个 470 ms 档位。
新增 `_egt_skips_attack_window()`，逃跑型直接不请求。

### M8 房间节拍器改轮转（**唯一影响全关卡的改动**）

原实现是"先到先得"，而 `_tick_chase` 每帧重试 ⇒ 同帧内谁先跑 `_physics_process`
谁拿，也就是**节点树顺序**。结果是树里靠前的怪反复吃窗口、靠后的整场开不了一枪 ——
业主读到的"有的怪一直打、有的怪不打"就是这个。

改为：同一只怪**不得连续吃两个窗口**（房里还有别的活怪时最多连挡 1 次，
挡下不推进 `_room_next_slot_msec`，所以别的怪下一帧立刻能拿，总密度不变）。

> ⚠ 这条对塔楼同样生效（改善方向一致），回归靠 `verify_monster_ai_system_complete`
> 的令牌预算段 + `verify_3d_enemy_behavior_flow`。

### 4.1 顺带挖出的真 bug：外推速度被放大 ~11 倍

体检时枪精灵 `gun_fairy` 6 秒跑出 **90.4 m**（≈15 m/s，而它 `move_speed` 只有 4.29）。
查下去是两处速度算术，都在 `chase` 的"位移完全由外推决定"那四个骨架（`flee` / `grab` / `wander` / `immobile`）上：

| 位置 | 旧写法 | 后果 |
|---|---|---|
| `_tick_chase` 的四骨架分支 | `_steer_planar(ZERO, delta × 5.5)` 再 `_push_planar(_external_velocity)` | 每帧衰减 ~9%、却每帧**加一次完整外推** ⇒ 稳态 ≈ 外推 ÷ 0.09 ≈ **11 倍**。枪精灵跑到 15 m/s、逃跑型贴墙乱窜 |
| `_tick_egt_windup`（我新写的） | `keep = clampf(len, floor, max(floor, len))` —— 这个 clamp 恒等于当前速度 | `_steer_planar` 变成"保持原速"，再加外推 ⇒ **每帧 +3.6 m/s，永不收敛** |

两处都改成"速度有独立上限、外推直接赋值而非叠加"：

```gdscript
# _tick_chase 的四骨架分支
velocity.x = _external_velocity.x
velocity.z = _external_velocity.z
# _tick_egt_windup
var cap := get_effective_move_speed() * EGT_WINDUP_SPEED_RATIO
_steer_planar(planar.normalized() * minf(planar.length(), cap), ...)
```

修完：枪精灵路程 **90.4 → 22.0 m**（3.7 m/s，正好是 `4.29 × 0.85` 的游荡速度），
目标可见帧 **14% → 98%**，静帧 **43% → 0%**。逃跑型两只见 §4 的表。

> 这两处都不是本轮引入的（第一处是既有实现），但**只有逐只量路程才会暴露** ——
> 之前所有探针都只看"有没有动"、"有没有出弹"，没有任何一条量"动得多快"。

## 6. 未做 / 已知

- **`_egt_cadence_probe` 与 `_egt_enemy_motion_probe` 目前跑不出怪**（真实关卡生成在本机
  该种子下刷 0 只），两者都**不会因此报错**。前者我已经在文档里标为"结论不可用"，
  后者更应该补一条"至少测到 N 只怪否则判红"的哨兵 —— 属独立一件事，本轮没动它
  （它可能被每日自动化引用，改判据要单独确认）。
- **rush / explode 型冲出去后仍会丢目标站一会儿**（静帧 28~36%）。它们 cd=99、一次性，
  冲不到人就只剩等自毁。要改得动 `suicide_rush.max_lifetime`（4.0 s），
  那会改变清房速度，属玩法决定，留给业主。
- **抓握大师单只测不到**：它的 `die_when_others_dead` 在"房里没有别的怪"时立刻自毁
  （原作行为），单只探针永远满足这个条件。要测它得让探针同时放一只同伴怪，本轮没做，
  探针汇总里已显式打印"另有 1 只测不到"。
- **前摇/后摇的数值是自拟的**（原作 `§T2.5` 已记录：速度类字段公开渠道全无）。
  能保证的是**序关系与可读性下限**，不是数值对齐。
