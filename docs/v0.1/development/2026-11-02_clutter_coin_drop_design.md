# 易碎陈设破碎掉币 · 实现记录（10% · 1–10 金币 · 落地后锁 0.5 秒）

日期：2026-11-02；FeatureID：WORLD-INTERACTIVE-CLUTTER；设计修订：r7（[正文](../design/场景可交互低模物件设计.md)）。

## 业主指令（三轮）

1. 「我不是有5个易碎陈设吗？帮我增加一个设计，破碎后，原地回掉落一个金币，金币的数值1-10随机。破坏后掉落的概率是8%，完成后更新设计文档和账本」
2. 「这个掉落的金币需要有个可拾取时间，不然角色碰到就立刻消失了，0.5 秒的可拾取时间或者 1 秒的」
3. 「奇怪为什么我都没掉落金币？概率帮我调成60%」
4. 「可以了 调成10%把」← **定稿值**

概率演进：`8% → 60% → 10%`。60% 是因为第 3 轮把「没实现」误判成「概率太小」，
补完代码上手确认后当轮收回；它没活过两小时，存档与资产行一概没碰，只在账本变更日志留过 v0.1.61 一行（v0.1.63 更正）。

## 第 3 轮暴露的真实问题：设计写完 ≠ 功能存在

前两轮只出了设计（按 `AGENTS.md`「没有完整契约时先补设计，再实施改变规则的代码」），
代码一行没写。**运行期概率实际是 0**，业主看到「一枚都没掉」不是 8% 太小，是根本没有这条逻辑。

这条要记住：业主的检验方式是**进游戏看**，不是读文档。凡是「调个数字就能看到结果」的需求，
当轮就该把代码一起交，否则下一轮必然收到「为什么没有效果」。

### 数值

```text
P(掉币)  = 0.10          金额 = randi_range(1, 10)      单件期望 = 0.55 枚
seed     = hash(run_seed | "clutter_coin" | clutter_id)
落点     = 破碎点 + ≤0.30 m 确定性偏移 → 既有贴地/净空校位
拾取锁   = 弹跳动画 0.81 s（GroundLootPickup3D 内部实算）+ 落地后 0.5 s = 1.31 s
```

### 三个坑（都写进代码注释了）

1. **0.5 秒不能从生成时刻起算**：`0.5 < 0.81`，会被动画完全吞掉，改了等于没改。
2. **不能复用 `set_pickup_grace_seconds()`**：它连带设 `_pickup_requires_player_exit = true`，
   会变成「站在金币上永远捡不到，必须先走开 2 m」。新增独立接口，只锁时间。
3. **接线有两处**：`Dungeon3D` 与 `TowerDescent3D` 的房间创建处。漏一处 = 那批房间永远不掉币，
   而且**不打任何日志** —— 属于最难查的一类静默失效。

## 平衡（必须说清）

535 件 × 10% × 5.5 ≈ **294 枚/全清**，是同层怪物掉落（约 61 枚）的 **4.8 倍**；
破击率 25% ≈ 74 枚（×1.2）、15% ≈ 44 枚（×0.72）。

对照同日三个候选：8% = 235 枚 / 60% = 1766 枚 / **10% = 294 枚（采用）**。
8% 与 10% 实际差别不大，真正越界的是 60%。当前值落在「瓦砾能补贴、不抢主线」这条带里，
不需要再调；要微调只改 `CLUTTER_COIN_DROP_CHANCE` 或关卡 `interactive_clutter.coin_drop_chance`。

## 探针为什么改成读常量

概率一天改了三次。硬编码阈值的测试每次都得跟着改，而「测试自己写错阈值」是最容易
把真故障放过去的一种绿 —— 于是：

- `CHANCE` / `MIN_AMOUNT` / `MAX_AMOUNT` 全部取 `Dungeon3D` 的 const；
- 命中率容差按二项分布 `3σ = 3·sqrt(p(1-p)/n)` 现算，不写死区间；
- 金额档位阈值取「期望值 × 60%」，不写死 400；
- 端到端不再赌「5 件至少中一件」（10% 下 5 件全不中还有 59%），改为先扫 `run_seed`
  找到必中种子，再断言**枚数精确相等** —— 少一枚是发放丢了，多一枚是重复掷骰。
