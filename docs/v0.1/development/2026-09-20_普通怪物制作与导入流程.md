> 版本 v2 · 2026-09-20（v1 → v2：账本转正闭环 + 5 处未闭合项已处理，详见第 8 节）
> 依据：首只标准普通怪「小僵尸」（AssetID `ENM-MELEE-FUNGBOAR01`，逻辑 ID `melee_chaser`）已走通的全链路
> 定位：`2026-09-17_3D资产正式制成链路总表.md` 中 P0「建立第一只标准怪物」的固化版；其余 6 类普通怪照此复制
> 上游标准：`docs/v0.1/16.1_角色美术制作与动作导入流程.md`（模型 / 动作双 blend 口径，怪物同源）
> 技能分工：Blender / GLB / PackedScene 段 = `game-character-model-pipeline`；
> **本文件全链路已固化为独立 skill `normal-enemy-model-pipeline`**（第 6 节「玩法侧接线」是其独有内容）
> 资产包自述：`assets/art/enemies/normal_enemy_3d/melee_chaser/README.md`

## 0. 一句话链路

```text
设计位「7 类普通怪之一」
  → 母版 / Tripo 源入库
  → 尺寸归一（源高 = 展示高 / 0.70）
  → 朝向归正（数据层，Blender +Y 前向）
  → 源级预览（六机位 + 倍率 + 玩家参照）
  → 动作专用 blend（6 段剪辑）
  → 视觉 GLB（无版本号）
  → runtime PackedScene（表现包装 + 表现脚本）
  → 表现脚本（12 个 AI 状态 → 6 段剪辑）
  → 代码挂载点（EnemyAvatar3D 正式普通怪分支）
  → 验收场景（含反向对照）
  → 账本转正
```

与 `16.1` 的角色链路相比，怪物链路**多两段**，这两段也最容易漏：

1. **AI 状态 → 剪辑映射**。角色是「动作库 + 状态机」，怪物是「12 态 AI 状态机 + 表现适配器」，两套 ID 不同名，不能照抄玩家的动作表。
2. **玩法侧接线**。`EnemyAvatar3D` / `Enemy3D` / `MonsterInjector` / `FOOTPRINT_PROFILES` 这一层角色没有对应物；漏一处就是**静默失效**（模型不挂载 / 血量条错位 / 死亡不回收）。

## 2. 目录与命名契约（三段式）

```text
assets/art/enemies/normal_enemy_3d/<logic_id>/
├── source/                     ← Blender 原始文件（唯一允许出现 _vNNN 的地方）
│   ├── .gdignore               ← 内容 = 单个 CRLF 空行，阻止 Godot 导入 .blend
│   ├── model/                  ← 模型 blend（几何 / UV / 绑定）
│   │   └── textures/           ← 贴图源文件
│   └── animation/              ← 动作 blend（与模型共享骨架 ID）
├── components/                 ← 视觉 GLB（运行路径，不带版本号）
├── runtime/                    ← PackedScene + 表现脚本 + 中转 JSON
└── previews/                   ← 源级核对渲染图（PNG，不受命名门禁约束）
```

| 段 | 文件名示例 | 带 `_vNNN`？ |
|---|---|---|
| 模型源 | `source/model/enm_melee_fungboar01_model_v002.blend` | ✅ |
| 贴图源 | `source/model/textures/enm_melee_fungboar01_basecolor_v002.png` | ✅ |
| 动作源 | `source/animation/enm_melee_fungboar01_animation_v003.blend` | ✅ |
| 视觉 GLB | `components/enm_melee_fungboar01_visual_top3d.glb` | ❌ |
| runtime Prefab | `runtime/enm_melee_fungboar01_root_top3d.tscn` | ❌ |
| 表现脚本 | `runtime/melee_chaser_formal_visual.gd` | ❌ |

**运行资产替换 = 覆盖同路径同名文件**，`.import` / `.uid` 留原位。
门禁：`python scripts/check_asset_runtime_naming.py`（`source/**` 整体豁免）。

目录结构移植自同域先例 `elite_3d/rift_boar_armed/`，但**普通怪包比精英包多两件**：`source/animation/`（独立动作 blend）与 `previews/`（源级预览）。精英包只有单 blend、无动作层、无独立 `.gdignore`。

## 3. 必须一次记死的四个数字

| 项 | 值 | 出处 |
|---|---|---|
| 全局展示倍率 | **0.70** | `Enemy3D.gd:26` `DEFAULT_BASE_SIZE_MULTIPLIER` |
| 源文件高 | **1.857143 m** | = 1.300 / 0.70，由目标反推 |
| 游戏内高 | **1.300 m** | 比玩家 1.20 m 高 8.3% |
| 玩家参照 | 1.500 m × 0.80 = **1.200 m** | `verify_player3d_avatar_bounds.gd` |

**游戏内尺寸 = 源尺寸 × 0.70 × kind 倍率 × variant 倍率**（`melee_chaser` 的 kind 倍率 = 1.0，普通怪 variant = 1.0 ⇒ 只吃 0.70）。
`Avatar` 与 `CollisionShape3D` 都是 `Enemy3D` 的直接子节点（`Enemy3D.gd:162-163`），**两者一起吃这个倍率**。

⚠️ 直接把源文件做成 1.3 m 会得到游戏内 0.91 m，**比玩家还小**，方向反了。

朝向契约（`16.1` 第 147 行）：面罩朝 Blender **+Y**，Z 向上，脚底 Z ≈ 0；运行时前向 **-Z**，不额外加偏航补偿。

## 4. 阶段明细

每段格式：**做什么 / 产物 / 门禁 / 坑**。

### S0 定位与身份

- **做什么**：从《资产主表》取该怪既有 AssetID / 逻辑 ID / 子类，确认是「升级既有行」而非新增。
- **产物**：第 1 节的身份表。
- **坑**：逻辑 ID 是隐形契约，同时被 `Enemy3D.PROFILES`、`FOOTPRINT_PROFILES`、`COLORS`、`MonsterInjector.BASE_ENEMY_TYPES`、`EliteContentCatalog.base_enemy_id` 引用，改名前必须全库搜一遍。

### S1 源入库

- **做什么**：把母版 / Tripo 交付的 `.blend` + 贴图落到 `source/model/`，并做**内部改名**（Armature / Mesh / 材质 / 贴图 image 全部改成 `<前缀>_*`），删掉 0 引用的空壳材质；Tripo 的中间 `.fbx` **不纳入**（与 blend 同源，无独立信息）。
- **产物**：`source/model/<前缀>_model_v001.blend`、`source/model/textures/<前缀>_basecolor_v001.*`。
- **坑**：Tripo 原件名可能是错的（本例拼写 `Moster`），**只改入库副本，不动桌面原件**。

### S2 尺寸归一

- **做什么**：等比缩放**网格顶点 + 骨架编辑骨**（绕世界原点），**不写对象级 scale**，让导出后源文件即真实尺寸。
- **产物**：源高 = 目标展示高 / 0.70。
- **判据**：脚底 `min Z = 0`；对象级 `rot = 0`、`scale = 1.0`（无隐藏缩放）。
- **坑**：缩放前先存快照到 res:// 外（本例 `_scratch/xiaojunzhu_intake/pre_scale/`），回滚即覆盖。

### S3 朝向归正

- **做什么**：绕世界 **Z 轴 +90°**（`Rz(+90°)` 把 +X 映射到 +Y），作用在**数据层** —— 网格顶点 + 骨架编辑骨（先快照 `edit_bone.matrix` 再整体左乘 R，`bone roll` 随之更正）。
- **判据**：六个机位渲染图 —— 从 **+Y** 看是完整正脸，从 **-Y** 是后脑勺，从 **±X** 是侧脸。
- **坑**：① 判据只能是**渲染图肉眼判**，不要用旋转表反推；② 若 blend 里已有 Action，转骨必须先做动画重定向，本例当时无任何 Action 才敢直接转。

### S4 源级预览

- **做什么**：渲染正 / 侧 / 顶 / 三分之四 + **朝向前后六机位对照**。
- **产物**：`previews/<前缀>_*_v001.png`。
- **判据**：按 `Enemy3D` 的 0.70 展示倍率渲染，画面里放一根玩家游戏内 1.20 m 参照柱，用于肉眼校尺寸。

### S5 动作源（6 段剪辑）

- **做什么**：新建 `source/animation/<前缀>_animation_vNNN.blend`，与模型**共享骨架 ID / 骨名 / 父子关系 / 静止姿势 / 单位**；导出前重新计算两文件骨架签名，差异必须先修。
- **产物**：30 fps，六段 —— `idle 3.2s` / `walking 1.6s` / `running 0.8s` / `attack 1.7s` / `hurt 0.8s` / `dead 2.4s`；前三段循环，后三段单次末帧保持。
- **坑**：① 源模型通常**不含任何动画数据**（本例 `bpy.data.actions` 总数 = 0，纯静态 T-pose），动作必须从零做；② **不能把时间轴自动回到开头误认作死亡循环**；③ 顶部场景选择器切段，Root 静止、Hip 只作表现位移。

### S6 导出视觉 GLB

- **做什么**：导出**二进制 `.glb`** 到 `components/`，只含视觉网格 + 经验证的骨架 + 动画；展示地面 / 相机 / 灯光 / 碰撞体不进包。
- **判据**：Godot 导入后核对**骨骼数（本例 36）与动画数（6）**，以及每段时长与循环标记。
- **坑**：导出文件名**不带版本号**；换版本 = 覆盖同路径同名文件。

### S7 runtime PackedScene

- **做什么**：建立 `runtime/<前缀>_root_top3d.tscn`，根 = `Node3D` + 表现脚本，子节点 = 一个 `ImportedModel`（= 视觉 GLB 实例）。**不含碰撞、不含逻辑** —— 碰撞归 `Enemy3D`，逻辑归 AI。
- **产物**：Prefab + 表现脚本 + `character_transfer_ledger.json`（中转记录：模型/动作源路径、骨架签名、各剪辑时长/循环、输出 SHA-256、回滚位置）。
- **门禁**：`python scripts/asset_guard.py <版本包目录> --classify <reuse|replacement|version_increment|child_variant>`。
- **坑**：中转 JSON 的状态必须按 `authored → exported_pending_godot_validation → validated → active` 推进；**源或输出哈希一变就得退回重验**。

### S8 表现脚本（12 态 → 6 剪辑）

- **做什么**：写 `<logic_id>_formal_visual.gd`，把 `Enemy3D.VALID_STATES` 的 12 个状态映射到 6 段剪辑，并提供 `sync_state()` / `flash_hit()` / `get_presentation_snapshot()` 三个接口。
- **选段规则（普通怪口径）**：见第 5 节。
- **坑**：① `AnimationPlayer` 要设 `callback_mode_process = MANUAL`，由 `seek` 驱动，避免与玩法状态机抢时序；② 受击闪白要**复制材质**再改 `emission`，不能直接改共享材质；③ 非硬直受击只覆盖表现，**不延迟攻击与伤害事件**。

### S9 代码挂载

见第 6 节（6 处，逐条）。

### S10 验收

- **做什么**：新建 `tests/verification/verify_<logic_id>_presentation.gd/.tscn`，用**通用 Enemy 预制体**（`enm_ecosystem_kit_root_top3d_v001.tscn`）+ `configure_from_enemy_data({"enemy_type": "<logic_id>"})` 驱动，断言：
  - 正式包装已挂载（`has_formal_normal()`）且 `component_count == 2`；
  - **碰撞未变**（`collision_shape.shape.height` 仍为原值）—— 这条是「美术接入不动玩法」的证据；
  - 六段剪辑齐全 + 时长误差 < 0.04 s；
  - 遍历 12 个状态逐个 `sync_presentation`，状态透传正确；
  - **结构性断言**：走路剪辑只能出现在 `patrol`；
  - **反向对照**：低速追击仍必须是跑步、高速巡逻仍必须是走路；
  - 攻击前摇 → 命中边界采样**连续**；`recovery` 末帧对齐 `attack` 时长；
  - 死亡：立即退组、不被压扁、2.4 s 后回收；
  - 精英带 `is_elite` 时**不叠加**普通怪表现。
- **跑法**：`--headless --path . res://tests/verification/<场景>.tscn`，再 grep `*_OK` + `ERROR`；**不看裸退出码**。
- **纪律**：新断言必须做一次**反向对照**（改坏 → 变红 → 还原）；「字段透传 / 行为」类断言必须能真的失败。
- **坑**：语义失败标记多由 `printerr()` 打、**无 `ERROR:` 前缀**，`grep '^ERROR'` 会漏 —— 先找自打标记，再数 ERROR。

### S11 账本转正

- **做什么**：①《资产主表》该怪行从 **2D 口径迁到 3D 口径**；②《敌人动画与状态》分页补「循环 / 挂点 / 首版实现」三列；③ 中转 JSON 状态推进到 `validated` / `active`。
- **3D 口径怎么改**：照精英行 r17 —— 组件槽 `root` → `root_3d`、变体父 ID → `ENM-ECOSYSTEM-KIT-3D`、视角 → `Top3D / local -Z 正面`、规格 → 真实包围盒、文件路径 → runtime tscn。
- **写完必查**：`python scripts/check_asset_registry.py --ledger <域>`（结构 + 跨文件契约：每个 AssetID 全库恰好出现一次）。
- **坑**：`assets/registry/ledger_index.json` 是域 / 大类 / 文件 / 分页映射的**唯一真源**，不得写死账本文件名。

## 5. 状态 → 剪辑映射（普通怪口径）

12 态逐字取自 `src/enemy3d/Enemy3D.gd` 的 `VALID_STATES`：

| # | 状态 | 剪辑 | 说明 |
|---|---|---|---|
| 1 | `dormant` | `idle` | 采样钉在 0 |
| 2 | `idle` | `idle` | 循环 |
| 3 | `patrol` | **`walking`** | **唯一使用走路的移动状态** |
| 4 | `alert` | `idle` | |
| 5 | `chase` | **`running`** | 朝玩家接近 |
| 6 | `search` | **`running`** | 朝最后已知位置 |
| 7 | `return` | **`running`** | 归巡逻点 |
| 8 | `telegraph` | `attack` | 采样到 `length × 0.48 × 进度` |
| 9 | `attack` | `attack` | 钉在 `length × 0.48`（判定帧） |
| 10 | `recovery` | `attack` | 从 0.48 → 1.0 线性 |
| 11 | `stagger` | `hurt` | 按 0.16 s 硬直采样 |
| 12 | `dead` | `dead` | 按 `state_time` 采样，上限 = 剪辑长 |

**两条硬规则**：

1. **走路只服务巡逻**。只要朝玩家方向移动（追击 / 搜寻 / 归位）**一律跑步**。
2. **选段由状态唯一决定，不按实际速度切档**。早期按平面速度在 idle→walking→running 之间切档，会让同一状态在快慢档之间抖动。

`sync_state()` 的 `speed` 形参仍按契约保留在参数位（调用方按顺序传），但**不参与选段**。

## 6. 代码侧接线（本链路独有，漏一处即静默失效）

三条挂载路径的关键差异：**精英 / Boss 有 `configure_elite_content()` / `configure_boss_content()` 显式函数；普通怪没有对应函数**，是 `_rebuild()` 里的常量分支自动加载。

| # | 位置 | 作用 | 漏了会怎样 |
|---|---|---|---|
| 1 | `EnemyAvatar3D.FORMAL_MELEE_KIND` / `FORMAL_MELEE_SCENE_PATH` / `FORMAL_MELEE_VISUAL_HEIGHT` | 逻辑 ID、Prefab 路径、视觉高度常量 | 找不到包 |
| 2 | `EnemyAvatar3D._rebuild()` 末尾 `if enemy_kind == FORMAL_MELEE_KIND` → `_load_formal_normal_model()` | 挂载正式包装并隐藏旧程序化壳 / 核 / 附肢 | 仍显示程序化网格 |
| 3 | `EnemyAvatar3D.sync_presentation()` | 把状态转发给表现脚本 | 模型静止不动 |
| 4 | `EnemyAvatar3D.get_component_snapshot()` | 报 2 组件（`skeletal_model` + `state_vfx`）| 验收数量对不上 |
| 5 | `Enemy3D.configure_from_enemy_data()` | 显示名迁移（旧存档「小菌猪」→「小僵尸」）+ 精英互斥 | 旧存档名字错、精英叠双模型 |
| 6 | `Enemy3D._die()` | 正式普通怪走 2.4 s 表现回收；否则走 0.34 s 压扁 | 死亡立刻压扁，看不到倒地动画 |

配套还需同步（**改外观不改这两处 = 静默出错**）：

- `EnemyAvatar3D.FOOTPRINT_PROFILES` → `Enemy3D` 直接读它生成受击 / 物理 `CylinderShape3D`，还用于算头顶血条高度、导航半径、出生点高度；
- `EnemyAvatar3D.COLORS` → 程序网格回落色。

⚠️ **换模型必须同一批改 `FOOTPRINT_PROFILES` + `COLORS`**，且更换模型时该表是**局部值**（还要再 × 0.70 才是世界尺寸）。

另：`_spawn_room_enemies()` 是刷怪唯一入口，敌人挂 `$ActiveEnemies`；`MonsterInjector.BASE_ENEMY_TYPES` 是 2D 侧名称 / 数值表，也是同名逻辑 ID 的消费者。

### 已闭合（2026-09-20 同一批次）
