# Boss002 显示器：动画受击体积（子弹打在模型实体上）

FeatureID：BOSS-STAGES / ENEMY-AI。游戏 0.1.0。日期 2026-10-14。
来源：业主第一轮「检查一下 boss 显示器的受击范围判断盒子，因为动画让角色的身体会歪出碰撞盒子，
所以角色击中显示器的时候，会感觉隔空击中，没有击中实体的感觉，帮我进行调整，让我的子弹能直接打在模型上，
模型就算动也不会有问题」；第二轮「**还是离着非常远**，能不能给显示器身体专门做一个跟随显示器走的
用来接收子弹碰撞的碰撞盒，不和其它功能影响」。

结论：显示器 Boss 的**接子弹职责整份从根节点那个固定圆柱挪到一组跟着骨骼走的受击盒上**。
实测瞄准可见屏幕点射击的落点误差 **中位 0.351 m**（理论地板 0.17 m = 子弹半径）；
A/B 证明：开受击盒 → 落在模型上（0.229 m），关掉 → 子弹整条穿过去（16.44 m）。
`verify_monitor_boss_flow` **591 项 0 失败**。

> **两轮才修对，第一轮修的是错的那一头。** 第一轮只补了跟骨走的受击盒，没动圆柱 ——
> 结果子弹仍然被圆柱拦在模型外面（下面 §1 的实测）。**主因是圆柱太胖，不是盒子太小。**

---

## 1. 现象与根因

显示器 Boss 的玩法碰撞只有根节点上一个**固定圆柱**（`Enemy3D.apply_profile` 从
`EnemyAvatar3D.FOOTPRINT_PROFILES["boss"]` 取 `radius 1.92 / height 2.30`，局部 `y=0.15`，
再乘根倍率 1.05 ⇒ 世界半径 **2.016**、顶面 `y=2.415`）。它**不随动画动**，而且**比可见模型宽得多**：
屏幕半宽只有 0.85 m、整机厚度只有 0.62 m。于是有两个方向的错：

**(a) 子弹被拦在模型前面 —— 这是「还是离着非常远」的主因。**
一发明确定位：从正前方平射屏幕中心，子弹撞到的 collider **名字就叫 `Enemy3D`**（圆柱），
停点在屏幕**前方 1.0–1.3 m** 的空气里。命中特效因此出现在模型前面。

| 姿态 | 子弹实际停在（gap 到模型） | 拦住它的是谁 |
|---|---|---|
| `idle` | **1.047 m** | `Enemy3D`（圆柱） |
| `move` | **1.285 m** | `Enemy3D` |
| `melee_cable` | **1.313 m** | `Enemy3D` |
| `stun_loop` | **1.255 m** | `Enemy3D` |
| `heavy_spin_slam` 砸地帧 | 0.489 m | 受击盒 |

**(b) 屏幕在动画里甩出圆柱之外。**
材质母版实测（30 Hz 逐帧求变形网格包络）：

| 剪辑 | 本体（屏幕总成/后轴/底座/支撑）世界包络 | 与圆柱的关系 |
|---|---|---|
| `idle` | X[-1.11,1.14] Y[-0.10,2.92] Z[-1.35,0.92] | 顶部高出圆柱 **0.51 m** |
| `move` | X[-1.79,2.00] Y[0,3.30] Z[-1.64,0.63] | 顶部高出 **0.89 m** |
| `heavy_spin_slam` | X[-1.48,1.48] Y[-0.05,4.22] Z[-3.83,1.20] | 前向甩出 **1.81 m**、顶部高出 **1.81 m** |
| `melee_keyboard` | X[-1.09,1.10] Y[0,3.84] Z[-1.99,1.20] | 顶部高出 **1.43 m** |

量化：**只靠那个圆柱时，10 个探针姿态中最差的一个只覆盖本体顶点的 34.77%**。
(a)(b) 合起来，就是业主看到的「隔空击中、没有打在实体上」。

## 2. 方案：圆柱让出子弹层，接子弹整份交给跟骨走的受击盒

**只有动画受击盒留在子弹层（第 3 层），根节点圆柱退出。** 这是第二轮的关键一行：

```gdscript
	# Enemy3D._ensure_monitor_hit_volumes()
	body.collision_layer = MONITOR_BULLET_LAYER   # 4
	body.collision_mask = 0                       # 自己不检测任何东西
	# 圆柱退出子弹层：它半径 2.016 m、比可见屏幕宽 1 m 以上，留着会把子弹拦在屏幕前 1 m 处。
	# 自身移动只看 `collision_mask`，所以这一步不改变走位、阻挡或任何别的口径。
	collision_layer = 0
```

**圆柱的移动/阻挡口径一字未改**（自身移动只看 `collision_mask = 1`；玩家掩码 1 从不与敌人层相交），
所以走位、贴墙、被玩家穿过的手感全部不变。已核对：全工程只有**玩家子弹**（掩码 5）与
**回旋镖返航**（掩码 4）会扫第 3 层，两者现在都打到受击盒上；没有任何逻辑读敌人的 `collision_layer`。

**8 个盒子**（骨局部中心/尺寸见 `MonitorBossPresentation.HIT_VOLUMES`）：
屏幕总成 `monitor_spin`、后轴 `rear_axle`、底座 `pedestal_motion`、三段弹簧支撑 `support_01..03`、
两只手 `hand.L/R`。逐帧由对应骨的世界姿态定位，挂在独立被动碰撞体 `EnemyHitVolume3D` 上。

### 盒子怎么量的（两条硬规矩，都是踩出来的）

1. **只用「刚性顶点」定盒子** —— 即单骨、权重恰为 1.0 的顶点。它们在该骨局部空间里是常量，
   盒子因此精确贴合。若把「权重被混合（如 0.6/0.4）」的顶点也算进来，它们在骨局部空间里会随手臂弯曲
   漂移，把盒子撑胖：实测 `hand.L` 的体积会胀到几何的 **9.5 倍**（`monitor_spin` 1.39 倍），
   玩家打手部时就会命中盒子的空腔。**三段弹簧支撑是唯一例外** —— 它们的顶点本来就沿骨轴伸缩，
   取全动画并集才是真实占位（`support_02` 甚至没有刚性顶点）。
2. **每根轴外扩 3 cm**。盒子若恰好等于实测 AABB，表面顶点就落在边界上，浮点舍入会把它们判到盒外
   （实测残余 1.85%）；外扩后归零，且 3 cm 在 2.7 m 高的屏幕上不可见。

附带教训：首版按每剪辑抽 11 帧取样，抽漏了极值（盒子偏小）—— 必须**逐帧**求包络（17 剪辑 / 911 帧）。

### 盒子为什么必须挂在**独立被动碰撞体**上

第一版把形状直接加在 `Enemy3D`（`CharacterBody3D`）自己身上。结果受击盒伸进地面/墙里时，
`move_and_slide` 把它们当承重面，**把怪物顶起来/推开**：

| 剪辑 | 挂在本体上：Y 抬升 | 挂在本体上：水平推开 | 改挂独立体后 |
|---|---|---|---|
| `stun_loop`（坐地） | **0.4170 m** | 0.0000 | 0.0000 |
| `stun_enter` / `stun_exit` / `dead` | **0.4098 m** | 0.0000 | 0.0000 |
| `idle` | 0.1612 m | 0.0000 | 0.0000 |
| `heavy_spin_slam` | 0.0856 m | **0.2615 m** | 0.0000 |
| `melee_keyboard` | 0.0271 m | **0.4852 m** | 0.0000 |

坐地被抬高 0.42 m 是肉眼可见的「飘」。代理体 `EnemyHitVolume3D`：`collision_layer = 4`、
`collision_mask = 0`（不检测任何东西、不参与任何移动），命中后把伤害转交本体。
它挂在 `Enemy3D` 下、名字 `MonitorHitVolumes`，逐帧跟骨姿态；本体死亡变 `layer 0` 时它一起失效
（`ai_state == "dead"` 时置 0 —— **不能读 `collision_layer`**，它已被置 0 让出子弹层）。

**只转发这 9 个伤害入口**（子弹拿到的 `collider` 是代理，不转发就会静默不掉血）：
`take_projectile_damage` / `take_damage` / `notify_attacked_by` / `can_absorb_projectile` /
`on_projectile_absorbed` / `apply_slow` / `apply_damage_over_time` / `apply_pull` / `apply_fate_element`。
`verify_monitor_boss_flow` 逐条断言它们存在。

**刻意不覆盖**（都有实测理由，不是漏做）：

- **数据线、弹簧臂细段、手指**：把盒子套在十几厘米粗的线圈上，得到的盒子会比可视几何粗一大圈，
  「打在空气里」的假命中反而更严重 —— 那正是本次要消灭的手感。数据线实测只有 0.11 m 粗。
- **五官平面贴片**（`Texture large_eye / round_eye / mouth`）：设计规定它们**保持角色 root 朝向、
  不跟随屏幕局部旋转**，所以屏幕自转三圈时它们在屏幕骨空间里扫出的范围（X±1.83、Z±1.82）
  比屏幕本体（X±0.85、Z±1.37）还大 —— 给它做盒子只会得到一圈巨大的假体积。
  它们本身没有厚度，真正该保证的是「固体屏幕总在它正后方」：实测最大间隙 **0.266 m**。

## 3. 验收

`verify_monitor_boss_flow`（`tests/verification/verify_monitor_boss_flow.gd`），
**591 项检查、0 失败、退出 0**。落盘实测值见
`assets/art/enemies/bosses/enm_boss_monitor002/previews/runtime/flow_report.json` 的 `monitor_hit_volume`：

| 指标 | 实测 |
|---|---|
| 盒子数量 | 8 |
| 本体顶点样本（10 个探针姿态） | 16,473 |
| 最差姿态本体覆盖率（受击盒） | **100%** |
| 最差姿态本体覆盖率（**只有圆柱**） | **34.77%** |
| 瞄准可见屏幕点射击的落点误差 | 中位 **0.351 m** / p75 0.533 / 均值 0.875 / 最坏 2.99 |
| A/B：开受击盒（`idle`，打屏幕中部） | 落点误差 **0.229 m**（打在模型上） |
| A/B：关受击盒 | 子弹**整条穿过去**，落点误差 **16.44 m** |
| 受击盒存在时的 40 帧本体位移（`stun_enter`） | **0.0 m**（守卫阈值 0.05 m） |
| 五官贴片到屏幕盒的最大间隙 | 0.266 m |

用例覆盖：
① 盒子建在独立体上、层/掩码正确、转发面齐全，且**圆柱已退出子弹层**；
② 盒子位置逐帧等于「骨姿态 × 骨局部中心」（用骨架独立重算，不复用表现层函数）；
③ 10 个探针姿态下本体顶点覆盖率 ≥ 99%（实测 100%），且**只有圆柱时 < 90%**（实测 34.77%）；
④ 五官贴片始终在屏幕盒正前方 0.45 m 内；
⑤ 受击盒不抬升本体（`stun_enter` 40 帧位移 0.0 m；**反证**：把形状挂回本体后立刻报 **0.43 m**，4 条断言一起红）；
⑥ **按玩家视角打真子弹**：8 个姿态 × 屏幕模型顶点，全部命中（无穿模），中位误差 < 0.40 m；
⑦ **A/B**：同一发子弹，开盒子打在模型上（0.229 m）、关盒子整条穿过（16.44 m）——
   这就是「圆柱不再拦子弹」的直接证据；同时断言伤害**确实**经代理转交到 `Enemy3D`。

**判据为什么用中位数**：误差的理论地板是 **0.17 m**（子弹是半径 0.12 m 的球 + `safe_margin` 0.035 m，
球心天然停在表面外那么远），中位 0.351 m 已经贴着地板。尾部（p95 ~3 m）有两个都**不属缺陷**的来源：

- **屏幕最边缘的角点**：受击盒是骨局部 AABB，角落天然比几何多出一段。
- **挥出去的手臂/键盘先接住**：`melee_keyboard` 命中帧左手把键盘砸到身前 3.2 m，
  那截胳膊**真的挡在屏幕前面**，打中它才是对的（验收里已把「被手盒接住」的样本剔除后再统计）。

真回归会**整体位移**（圆柱回来 ⇒ 全体提前 1 m 停下；盒子丢了 ⇒ 穿模），中位数必炸 —— 门禁压中位数足够灵敏。

回归（均绿）：`verify_3d_enemy_behavior_flow`（含其自身的 hit volume 契约）、
`verify_unique_boss_content_flow`（95/90/85 三个旧 Boss 不受影响）。

## 4. 验收过程中自己踩的坑（探针侧的，值得记住）

- **Boss 必须冻结**。`set_runtime_active(true)` 内部会 `set_physics_process(active)`，
  把 `_physics_process` **重新打开** —— Boss 于是每帧 `move_and_slide` 走位，受击盒跟着走，
  子弹飞到一半盒子已经挪走，量出来的误差能到 3 m 以上（假红）。
- **不能瞄「盒中心」**。倾斜姿态下盒中心可能悬在空中，那是过度悲观的测法。
  正确的测法是「瞄一个**看得见的模型顶点**」。
- **要换到空地量**，否则前面用例留在原点的临时碰撞体会把子弹拦在半路。
- 拦截物识别要留够容差（子弹球心停在盒面外 0.155 m），否则会把「被手接住」误判成「隔空」。
