# 开发日志：2026-07

## PH15 核心闭环与视觉可读性重构（2026-07-10）

### 解决的问题

- Boss 房此前没有实体碰撞体，且子弹给 Boss 传入三参命中数据时接口不兼容；实战子弹无法击败 Boss。
- Boss 实体扣血、地图进度、奖励和撤离解锁之前没有同一条可靠的运行时桥接。
- 局内生命同时存在 `GameManager` 与 `Player` 两套来源，导致濒死祝福无法根据真实受伤触发。
- 纯黑 `CanvasModulate` 吞没了低照度环境中的地面和轮廓；玩家组件仍在展示 emoji/色块占位资产。

### 本次交付

- 将 Boss 的碰撞、伤害、死亡和 Boss 撤离收敛为可回归测试的闭环；新增 `verify_boss_completion_flow.tscn`。
- `VisionSystem` 与命运卡改为 `RefCounted` 数据/计算服务；武器装配树在换枪和结束局时递归释放未进入 SceneTree 的数据节点。
- 新增独立的程序化 `PlayerAvatarRenderer` 与 `BossAvatarRenderer`；它们是语义化的 `AvatarRenderer` 挂点，可直接被正式精灵或动画替换。
- HUD 改为统一的深色指挥台表现：生命数值、弹匣、机动、火力、战绩和深度的信息层级更清晰，且在迷雾上方渲染。
- 降低环境暗角至蓝灰基调，修复 Boss 击败闪屏非法层级。

### 验证

- Godot 无头编辑器扫描通过。
- 21 个场景流程验证与命运卡池验证通过。
- 新增 Boss 回归确认“玩家子弹 → BossActor → BossRoomDirector → BOSS_KILL 撤离”完整通过。

## PH16 大地图末日氛围垂直切片（2026-07-11）

### 设计判断

启动后的固定大地图是玩家对成品质感的第一判断。原地图已有连续基地—荒野结构，但大块纯色地面和矩形设施让功能感强于世界感，因此本轮先建立可替换的末日氛围层，再进入训练靶场和怪物表现循环。

### 交付

- 新增 `src/base/BaseWorldAtmosphere.gd`：固定种子道路破损、废墟、残骸、路障、枯树、分区色彩、13 盏故障灯、屏幕尘雾和暗角。
- 新增 `BaseFacilityRenderer.gd` 与 `DungeonEntranceRenderer.gd`，将基地设施和副本入口包装为破败装甲掩体/地堡，并保留单一可替换渲染节点。
- 出生广场加入维护标记、裂纹、线缆与电力箱；基地玩家外观只在表现层放大，不改变碰撞。
- 基地 HUD 提升到 CanvasLayer 20，始终位于氛围覆盖层之上。

### 验证

- `verify_base_world_flow.tscn`：通过，节点数 183/220。
- 全部 21 个场景验证与命运卡池验证：通过且无错误日志。
- Godot 实机 1280×720 检查：氛围色、稀疏照明、设施轮廓和 HUD 可读性符合本轮方向。

### 下一轮

建立独立训练靶场：基地入口、装备隔离、全枪身/弹药选择、组合开关、可重置靶标与实时伤害统计，退出时不写入任何局外物品。

## PH17 独立训练靶场（2026-07-11）

### 设计判断

### 交付

- 基地新增“地下训练靶场”设施与独立场景；进场空装，离场前销毁临时装配。

- 新增标准、装甲、移动三类靶标，包含伤害飘字、命中反应、减伤结算、命中率和会话 DPS。
- `WeaponAssemblyTree` 清空契约同步重置弹药/射击参数，`WeaponDisplay` 对换枪与空装立即刷新。
- 以破损工业射击廊、低能冷青灯、远端红色警示、消毒门与深蓝黑终端建立可替换的专业视觉基线。

### 验证

- `verify_base_world_flow.tscn`：基地 8 设施、训练入口路由与 191/220 节点预算通过。
- Godot 4.6.2 全工程扫描、主场景启动与 22 个场景验证无报错。
- 实机 1280×720 检查：空装、选中、装配、灯光和侧栏信息层级可读。

### 下一轮

建立基础怪物的体型、轮廓、运动节奏、攻击蓄力和受击反应差异，把“怪物类型”从数值标签提升为玩家无需文字即可识别的战斗语言。

## PH20 最终成品验收与生命周期收口（2026-07-11）

### 解决的问题

- 严格退出日志发现若在动画、刷怪或陷阱计时中切场景，`SceneTreeTimer` 与 `await tween.finished` 可能短暂持有协程资源。
- Boss 阶段 Director 在 Idle 也会自主处理，并可能在激活首帧同时触发多个定时技能。
- 相邻增援批次共享可变敌人池，快速触发时存在后批配置覆盖前批队列的风险。

### 收口

- 波次、增援和陷阱均改为场景节点自有 Timer；增援数据在入队时冻结。
- Boss Director 只在 Combat 运行，初始技能错峰并加入全局技能间隔；Dead/Idle 均停止处理。
- 白闪、飘字、Boss 胜利动画与演示转场改为 Tween 回调链，场景销毁不再悬挂协程。
- 建立 `VerificationClock` 与 `VerificationQuitter`，让专项测试延迟由节点拥有，并在异步入口完全退栈后退出。

### 最终证据

- Godot 全工程扫描干净。
- 24/24 验证场景严格无警告、无错误。
- 5/5 核心场景持续 600 帧无警告、无错误。
- 基地、靶场、战斗 HUD、怪物生态板与玩家六态板完成 1280×720 当前版本复核。

## PH17B 靶场实体陈列与数据驱动扩展（2026-07-16）

### 设计判断

训练靶场已有完整枪弹矩阵和隔离测试契约，但全枪械只显示为终端按钮，空间本身没有“武器实验室”的可感知选择过程。本轮把目录数据转成场景内实体陈列，同时保留终端作为精确组合工具。

### 交付

- 靶场扩建为 2600×1500 的独立实验室，西侧为全枪械陈列与弹药实验墙，东侧为四条实弹测试道。
- 新增数据驱动 `TrainingRackItem`：自动读取蓝图 ID、名称、Tier、标签与枪身轮廓，生成有唯一交互区的整齐四列货架。
- 靠近实体陈列位按 `E` 即可取用；枪身与弹药互相沿用当前选择，缺省时自动补齐另一半组合。
- 终端与实体货架共享唯一选择状态；`Tab` 可收起终端，方便观察远端靶标。
- 专项验证增加实体枪架/弹药墙数量、ID 唯一、位置不重叠和实体取用装配正确性检查。

### 验证

- 靶场专项验证通过：15 个实体陈列位、56 组枪弹组合、靶标行为、会话统计和局外隔离全部成立。
- 23/23 场景回归通过；主场景持续 300 帧无错误。
- 1280×720 实机帧检查确认全枪械与全弹药在出生视野中整齐可读。
