# 系统设计

## 玩家

玩家顶层状态固定为 `idle / moving / dashing / hurt / locked / falling / landing / dead`。射击、换弹、蓄力、低血量、沉默、无敌和击退是覆盖层，不创建互斥顶层状态。

`Player3D` 负责输入、移动、生命与武器桥接；`PlayerAvatar3D` 只负责组件装配和动作表现；碰撞使用独立虚拟胶囊，视觉模型内禁止带玩法碰撞体。

## 武器与投射物

武器由枪身、子弹模块和可选修饰组成。枪身定义开火节奏，子弹定义飞行与命中行为，修饰器只处理附加规则。视觉模型挂在 `WeaponSocket`，不能成为命中、射线或数值的事实源。

现有对象池继续负责投射物和高频特效。新增武器不得复制一套独立子弹实现；需要新行为时扩展共享上下文或组合节点。

## 怪物

`Enemy3D` 是玩法根，`EnemyAvatar3D` 是视觉根。普通、远程、召唤、护盾、自爆、伏击、精英和 Boss 通过配置与状态组合形成差异。房间只持有敌人来源和生成策略，不直接嵌入怪物私有逻辑。

所有敌对房间必须满足以下闭环：存在有效生成来源、至少一次生成尝试、清房条件可达、敌人意外生成失败时有安全收口。空生成不得让门永久锁死。

基础数值、词缀、楼层缩放和刷新路径详见 [09_怪物图鉴.md](09_怪物图鉴.md)。

## 房间与门

房间数据决定类型、主题、敌人、掉落和连接关系；`DungeonRoom3D` 负责实例化表现。门的表现、触发体、阻挡碰撞和目标边必须共享同一个门记录，禁止各自重新计算坐标。

普通敌对房间类型统一来自 `GameDesignConfig.ROOM_TYPES_WITH_HOSTILES`。房间生成失败或敌人列表为空时，系统应记录诊断并允许房间进入可清理状态。

## 撤离

STANDARD、条件撤离和紧急撤离使用相同信标接口。开始撤离后玩家仍可移动和射击；普通受击不取消 30 秒倒计时。撤离成功、主动中断、死亡和离开范围必须各自只有一条状态转换路径。

## 局外进度

`BaseManager` 与相关数据对象拥有长期进度。训练场只能使用临时装备快照，离场时不得写入背包、资源、局数或长期统计。局内模块通过结算接口提交结果，不直接修改存档文件。
