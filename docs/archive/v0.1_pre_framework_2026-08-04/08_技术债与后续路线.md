# 技术债与后续路线

本页记录仍然存在的结构风险，不把“已有功能可运行”等同于“架构已经完成”。

## P0：阻断生产稳定性

- `Dungeon3D`、`TowerDescent3D`、`DungeonRoom3D` 仍承担过多生成、流程和表现责任。下一步按关卡图、生成器、遭遇、撤离和表示层拆分，且每次只迁移一条有测试保护的路径。
- `GameUIManager` 同时处理 HUD、背包、结算和场景返回。先提取只读 ViewModel，再迁移业务调用。
- 房间生成与清房安全网已存在，但仍需把所有房型改为数据驱动的“生成结果”对象，统一处理空生成和失败诊断。

## P1：降低耦合

- 清理核心流程中的 `has_method`、字符串 `call`、`find_child` 和绝对节点路径。
- 将场景切换统一到小型导航服务，并保留可测试错误结果。
- 将运行时创建的长期材质迁移为共享 `.tres`；临时闪烁、受击和瞄准效果除外。
- 为武器、怪物、道具补齐配置资源，减少脚本内大型字典。

## P2：内容生产能力

- 建立正式动画资源管线；当前多数动作仍是 Tween/程序变换。
- 补齐 `assets/art/items/`、正式怪物变体、武器套件、UI 组件和音频事件资产。
- 将资产台账中的占位资产、缺负责人、缺哈希和缺许可逐项收口。
- 旧 2D 兼容层在依赖清零后整组删除，不做零散删改。

## 完成定义

技术债只有在新边界被当前 3D 主线实际使用、旧路径没有引用、对应回归通过后才算关闭。仅新增文件夹、接口或文档不算完成。
