# 测试与发布

## 测试结构

所有回归场景位于 `tests/verification/`。测试公共计时、退出和视觉输出工具位于 `src/testing/`。视觉结果统一写入被忽略的 `outputs/verification/`，禁止覆盖正式资产。

## 执行

```bash
./scripts/run_verification_suite.sh smoke
./scripts/run_verification_suite.sh core
./scripts/run_verification_suite.sh full
./scripts/run_verification_suite.sh visual
./scripts/run_verification_suite.sh scene verify_tower_grid_component_alignment
```

也可通过 `GODOT_BIN=/path/to/godot` 指定 Godot 可执行文件。

## 合并门禁

- Godot 编辑器无脚本解析错误。
- `smoke` 全通过，退出码为 0。
- 修改对应的专项回归通过。
- 关卡与灯光修改必须通过塔楼网格、门通行、灯光/墙体/战斗综合回归；塔楼布局还必须验证整层计划冻结、房间矩形互斥以及真实楼梯 Mesh 与非接口房间零重叠。
- 任意水平通道必须回归 `N = 长度 / 5m`：地砖实例为 `N`、墙体实例为 `2N`、模块坐标全部落在 5m 轴线上，且两条连续侧墙碰撞长度与可视覆盖严格一致。完整塔楼流程节点峰值仍不得超过 3500。
- 角色修改必须通过状态、边界、碰撞、握持和灯光层回归。
- 随身主聚光必须同时验证自身投影隔离、固定阴影偏移参数，并在近 25m 距离的斜角墙面完成真 GPU 画面采样，确认无规则横纹且接触阴影仍存在。
- 刷怪时序必须验证：开门前邻房无实例，开门显现后首波立即存在且 AI 暂停，进房后实例数和 instance ID 不变、AI 激活，不得重复首波。
- `git diff --check` 无空白错误。
- 新增或变更美术已更新资产台账。

## 发布检查

1. `project.godot` 正式入口仍为 `TowerDescent3D.tscn`。
2. 不存在指向被删除资产、阶段文档或临时输出的 `res://` 引用。
3. 运行一次从楼顶到 95 层撤离/失败结算的人工流程。
4. 检查楼顶、基地、普通房、楼梯和 Boss 房的灯光、门、地面和小地图。
5. 导出预设、签名和平台构建文件只在发布环境保存，不提交敏感配置。
