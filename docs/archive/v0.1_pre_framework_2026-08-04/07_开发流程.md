# 开发流程

## 开始任务

1. 明确玩家问题、目标体验和不可改变的现有契约。
2. 找到唯一事实源：代码、资源、资产台账或本套游戏设计文档。
3. 先运行最接近问题的验证场景，确认基线和复现条件。
4. 涉及资产时先查重，不创建临时同义资产。

## 实现原则

- 让规则归拥有它的系统，不把业务逻辑塞进 UI 或场景装饰节点。
- 优先扩展现有组件、数据资源和信号，不复制一套平行系统。
- 关卡生成以 5m 组件坐标为事实源，表现、碰撞、触发和小地图共用记录。
- 所有失败路径必须可收口：生成失败不能锁门，场景加载失败不能静默，存档失败不能覆盖有效数据。
- 临时诊断可以存在于工作区，但不得成为正式入口、文档或资产。

## 完成任务

1. 更新或新增回归测试。
2. 运行 `smoke` 与受影响专项；高风险改动运行 `core` 或 `full`。
3. 检查新路径、删除路径和资产台账一致。
4. 只更新当前文档，不新增按日期或阶段编号命名的说明文件。
5. 删除工作输出；保留必要证据时放入被忽略的 `outputs/`。

## 文档规则

本目录按主题维护，不按开发轮次追加文件。设计变化直接修改对应章节，并在 `CHANGELOG.md` 记录对 v0.1 基线有影响的变化。工作日志、聊天摘要和一次性修补说明不进入仓库。
