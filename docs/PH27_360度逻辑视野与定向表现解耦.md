# PH27｜360°逻辑视野与定向表现解耦

## 为什么现在调整

ShellStorm2 是顶视角射击游戏。玩家能从俯视镜头直接读取角色四周的信息，如果身后无遮挡的敌人或掉落仅因为不在准星前锥内突然消失，画面会与玩家对顶视角空间的直觉矛盾，也会削弱房间开灯后的价值。前方扇形仍然有用，但它更适合表达角色主要目光、瞄准方向和探照灯覆盖，而不是作为目标是否存在的唯一逻辑边界。

## 新视野契约

1. `PlayerVision3D` 继续是目标显隐的唯一玩法真值，但逻辑视野改为角色周围 360°、最远 21m。
2. 21m 内的敌人、地面掉落、钥匙、危险区和交互设施只受实体遮挡影响；目标位于角色身后不能单独构成隐藏理由。
3. 墙、关闭的门和有实体碰撞的家具在任意方向都能遮挡目标。身后无遮挡目标可见，身后隔墙目标不可见。
4. 当前 96° 柔边射线扇形、2.4m 近身表现圈、朝向平滑和地板深度豁免全部保留。扇形只表达主要目光方向与探照灯方向，不宣称它之外没有目标。
5. `PlayerFlashlight3D` 继续跟随准星并提供真实材质受光；房间灯和探照灯均不参与目标显隐计算。开灯的价值来自空间、角色、家具和目标的真实可读性，而不是绕过墙体显隐。

## 实现边界

- `is_position_visible()` 只检查距离与物理射线遮挡，不再计算目标相对准星的夹角。
- 表现网格仍只采样原 49 条前锥射线和 28 条近身射线，不建立 360°地面网格，不增加稳定帧网格重绘。
- 快照必须同时报告 `gameplay_angle_degrees=360` 与 `presentation_angle_degrees=96`，避免后续功能再次混淆逻辑角度和表现角度。
- 现有目标组、射线遮挡层、流送禁用和死亡目标处理保持不变。

## 验收标准

- 准星朝前时，角色身后 21m 内无遮挡点与实际地面掉落仍然可见。
- 在角色身后放置实体墙后，墙后的点与掉落不可见；移到墙前立即恢复。
- 正前方实体墙仍能截断目标显隐和当前96°扇形边界。
- 当前柔边扇形外观、探照灯方向、阴影、亮度和开灯表现不变。
- 强光不能显示墙后目标；灭灯不能隐藏无遮挡目标。
- 视野专项、玩法等价、完整3D流程和性能预算回归通过，稳定状态网格重绘仍为0。

## 设计风险

360°逻辑视野会提高玩家周边信息量，部分伏击压力将更多依赖墙体、门、家具布局、暗室材质可读性和怪物行动，而不再依赖“站在角色身后自动隐身”。这是符合顶视角类型直觉的取舍；伏击怪自身的潜伏状态仍由怪物逻辑负责，不由视野角度伪造。

## 2026-07-22 验收结果

- `verify_3d_vision_input_flow.tscn`：身后无遮挡点与真实 `ground_loot_3d` 目标可见；加入身后实体墙后两者均被遮挡；正面墙体、强灯不能透墙、96°扇形裁切与双灯表现继续通过。
- `verify_3d_parity_core.tscn` 与 `verify_full_3d_game_flow.tscn`：钥匙门、背包保险、共享枪械树、四主题、七怪、56 枪弹组合、战斗和撤离无回归。
- `verify_3d_performance_budget.tscn`：生成约 104.2ms，新房构建峰值约 6.9ms，持续帧段约 6.90ms，稳定视野网格重绘 0 次。
- `verify_full_3d_visual.tscn`：实际 GPU 画面继续只显示定向柔边扇形与准星探照灯，未生成 360°地面网格；角色身后无遮挡敌人在顶视角画面中保持可读。
