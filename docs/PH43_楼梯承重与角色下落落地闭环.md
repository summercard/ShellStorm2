# PH43｜楼梯承重与角色下落落地闭环

## 一、目标

修复塔楼楼梯洞口、楼梯平台和坡段存在的掉落、卡边与自动下滑问题，并让角色从
离地、下落到落地恢复形成完整的物理和状态机闭环。楼梯高度仍为每层 9 米，角色
碰撞高度仍为 1.5 米；本阶段不通过传送或每帧改写角色世界 Y 坐标模拟楼梯。

## 二、承重碰撞契约

1. 两套 Blender 楼梯资产已经包含 `UpperFlight_Walkable`、
   `TurnLanding_Walkable`、`LowerFlight_Walkable`、上下门厅和核心连接板等
   六块实际可走网格；Godot 直接为这些 Walkable 网格生成 `StaticBody3D`
   三角网格碰撞，不再另造一套路径楼板。
2. Walkable 碰撞与画面中的楼梯坡段、折角平台和门厅使用同一份网格及变换，
   消除“看得见楼板但实际没有碰撞”以及程序楼板端面卡住角色的问题；这些承重
   碰撞在楼层流送隐藏表现时仍保持启用。
3. 楼层楼板继续按楼梯洞口剔除，但洞口中所有设计为可走区域必须由 Walkable
   网格碰撞覆盖；楼梯未显示或房间流送时，承重碰撞仍保留。
4. 禁止 `TowerDescent3D` 根据角色 XZ 投影每帧强制写入 Y。上下层关系由真实
   坡面、重力、`move_and_slide()` 和楼层碰撞共同决定。
5. 地面掉落物与房间钥匙生成时向下探测承重面；探测失败时回退到房间安全点，
   不允许生成在楼梯洞口或悬空位置。

## 三、角色垂直物理

1. 地面状态只写入 XZ 速度；Y 速度由重力和接触结果统一维护。站立斜坡时
   `floor_stop_on_slope` 必须阻止无输入下滑。
2. 楼梯下降时依靠地面吸附保持连续接触；短暂接缝容错不进入下落状态。
3. 离地超过短暂容错时间且垂直速度低于阈值后进入 `falling`。下落期间保留有限
   空中转向，但不能冲刺，也不能被楼梯路径强制吸回。
4. 重新接触地面后进入 `landing`。落地停顿时长由冲击速度映射并限制在短区间，
   轻微台阶落差不触发明显硬直；落地结束后回到 `idle`、`moving` 或 `locked`。
5. 记录最近安全地面位置。角色落到塔楼有效层以下或持续坠落越界时，恢复到最近
   安全点并清零垂直速度，避免无限坠落和坐标失控。

## 四、八态状态机与表现

顶层互斥状态扩展为：

`idle / moving / dashing / hurt / locked / falling / landing / dead`

- `falling`：身体轻微拉长、头部与耳朵后扬、双脚收起，动作强度随下落速度增加。
- `landing`：先保持短暂低姿态，再以压缩—回弹曲线恢复；落地硬直由状态计时，
  不使用额外动画计时器决定玩法。
- 射击、换弹、蓄力、击飞、低血和无敌仍是叠加表现，不扩张顶层状态。
- `dead` 仍为终态；受伤、锁定和输入恢复必须尊重当前是否离地。

## 五、屋顶光照与摄像机验收

1. 继续使用 PH42 的单太阳与真实遮光体系，不按楼层切换太阳参数。
2. 楼顶需要模拟天空散射形成最低可读阴影，但不能把室内环境底光整体抬亮；
   Compatibility 渲染器用一盏仅在楼顶活动、带阴影的局部天空反弹光照亮特殊
   楼梯入口。它不是第二个太阳，楼板与墙仍会阻止光线泄漏到室内。
3. 摄像机固定为角色相对坐标 `(0, 8, 5.5)`、FOV 55°和既定斜俯视目标，不再
   响应墙体、家具或楼梯围护体的碰撞，不收镜、不侧移、不左右旋转。墙前局部
   可视区作为后续独立显示功能，不通过推动摄像机解决。
4. 屋顶、楼梯门口、折角平台、坡段和上下层出口分别截图验收；角色不可被大面积
   纯黑近墙遮住，室内暗室仍需依靠灯具和探照灯。
5. 楼顶露天区域继续关闭角色探照灯；角色进入楼顶特殊楼梯的围护体后立即按室内
   处理并开启探照灯，不等待抵达 99 层的房间进入信号。

## 六、验收标准

1. 角色可连续往返所有 9 米楼梯，不能从平台接缝或坡面边缘意外漏下。
2. 角色在斜坡上松开输入后保持静止，不自动向下移动。
3. 普通走下楼梯不进入 `falling`；真正离开楼板后进入 `falling`，落地后进入
   `landing` 并短暂停顿，再正确恢复移动。
4. 下落和落地动作使用现有 bunny01 v006 组件骨架，无新增重复角色资产。
5. 地面掉落物、钥匙和角色安全恢复点都落在有效承重面上。
6. 楼顶阴影侧可读，摄像机靠近特殊楼梯墙时不会出现大面积纯黑遮屏；战斗层暗室
   与开灯效果不回退。
7. 状态机、楼梯双向通行、五层流送、门/命运卡、怪物、掉落和性能专项全部通过。

## 七、实现与验收结果

- `Player3D` 已改用高 1.5 米、半径 0.34 米的胶囊碰撞体；地面状态不再固定写入
  负 Y 速度，重力、终端速度、0.10 秒离地容错、空中控制、冲击时长与最近安全
  地面恢复由统一垂直物理入口维护。
- 顶层状态机已扩展为八态，新增 `falling` 与 `landing`；现有 bunny01 v006
  通过程序关节完成收腿、耳朵后扬、落地压缩和回弹，不新增重复 GLB 或贴图。
- 每套楼梯的门口平台、折角平台和梯跑直接使用 Blender Walkable 网格碰撞，
  取消程序路径承重面和按 XZ 投影强制改写玩家 Y；导入
  楼梯的围护墙补充同形碰撞，流送隐藏表现时楼板碰撞仍常驻。
- 四向楼板洞口从过大的约 25×35 米收紧到约 15×30 米；地面掉落物和清房钥匙
  生成前向下探测承重面，失败时回退到房间安全点。
- 楼顶天空反弹光移到特殊高墙顶部以上并保留阴影；角色进入特殊楼梯围护体后
  自动开启探照灯。摄像机固定在 `(0, 8, 5.5)`，删除碰撞驱动的收镜、侧移与
  水平绕墙；墙体显示本轮保持不变。
- 自动验收通过：垂直物理与斜坡静止、1.5 米碰撞、八态画廊、换弹、枪械姿势、
  完整战局、视野输入、命运武器和运行安全；塔楼真实双向通行到 95 层并返回，
  节点数 3343。性能专项为生成 270.7ms、最重房间 10.8ms、全探索 2950 节点、
  持续段 6.90ms。
- Apple M1 Compatibility 实机截图通过：楼顶特殊楼梯、连续坡段、下落姿势和
  落地姿势均可读；资产台账更新至 v1.25，稳定 AssetID 不变。
