## 1 边界

**管什么**
- 存档 schema：字段、类型、默认值、版本号
- 内容表：卡池、道具、怪物、关卡的数据文件
- 账本三层：清单 / 迁移账 / 债务表
- 迁移：旧存档怎么读进新版本

**不管什么**
- 数值该不该是 100 → 归 [功能](玩法-01_功能.md) 的规则
- 资产长什么样 → 归 [美术](包装-01_美术.md)，账本只记路径与版本

**判据**：数据管"存在哪、叫什么、什么格式"，不管"该是多少"。数值的合理性归功能，格式的合法性归数据。

**这是玩法与包装的唯一交点**：包装侧引用资产一律走 `asset_id`，不写死路径。

## 3 制作流程（流程文档 + 交付标准文档）

### 3.1 六步

| 步 | 输入 | 动作 | 工具 | 产物 | 判据 |
|---|---|---|---|---|---|
| 01 定 schema | 功能规则文档 | 定字段、类型、默认值、**版本号** | 手写 md | `schema_<模块>_v<n>.md` | 每个字段有类型和默认值 |
| 02 建内容表 | schema | 建 JSON 表，填初始数据 | 编辑器 | `data/*.json` | 表能过 JSON 校验 |
| 03 写迁移 | 旧 schema + 新 schema | 写迁移函数：旧字段 → 新字段，缺的补默认 | GDScript / Python | 迁移脚本 | 拿真实旧存档跑一遍不报错 |
| 04 巡检 | 内容表 + 账本 | 跑一致性检查：字段齐全、引用存在、命名合规 | `scripts/*.py` · pytest | 巡检报告 | 全绿，异常逐条列 |
| 05 记账本 | 资产 + 数据 | 更新清单 / 迁移账 / 债务表 | 手写 + 脚本 | `asset_manifest.json` 等 | 账本条目和实际文件对得上 |
| 06 归档 | 全部 | 写交付记录，更新完成度清单 | 手写 md | `development/` | 记录写明动了哪个 schema 版本 |

**04 步是这套链的价值所在**：账本的价值不在"有记录"，在"能查出错"。

| “存档只有 `BaseManager` 一个写入口” | `MODULE_PIPELINE_INDEX.md` 3.7 | 业务侧只有一个写入口 |

**我的读法**：两者不矛盾，是**两层**——`BaseManager` 管“哪些数据能变”，`ProfileSaveService` 管“怎么落盘”。卡片按两层写，不再叫“唯一写入口”。如果主人本意是单层，告诉我，我改回去。

## 8 常见坑

| 坑 | 后果 | 怎么防 |
|---|---|---|
| 直接改字段名不迁移 | 所有旧存档全废 | 01 步强制版本号，03 步强制迁移 |
| schema 无版本号 | 不知道这份存档是哪版 | 每份存档自带 `schema_version` |
| 账本和实际文件不一致 | 查"谁在用这个资产"查不准 | 04 步巡检必查引用存在性 |
| 数值写死在内容表又写在代码 | 两处不一致，谁生效说不清 | 数值只在 `data/`，代码只读 |
| 存档写入绕过 `ProfileSaveService` | 多处写入，冲突无法判 | 全局唯一写入口 |
| 删资产不查引用 | 一删就崩一片 | 先查反向引用再删 |
