## 1 边界

**管什么**
- 界面结构：信息分区、层级、导航
- 信息密度：一屏放多少、优先看什么
- 可读性：字号、对比、留白、缩放下不溢出
- 反馈：点了有没有反应、反应够不够快、成功/失败怎么表达

**不管什么**
- 数据从哪来 → 归 [数据](玩法-05_数据.md)
- 按键怎么映射 → 归 [3C](玩法-02_3C.md)
- 界面里的插画/图标 → 归 [美术](包装-01_美术.md)

**判据**：玩家说"看不懂该点哪"是交互体验问题；说"点了没反应"先查 [3C](玩法-02_3C.md) 的输入，再查本模块的反馈。

## 3 制作流程（流程文档 + 交付标准文档）

### 3.1 六步

| 步 | 输入 | 动作 | 工具 | 产物 | 判据 |
|---|---|---|---|---|---|
| 01 列界面清单 | `UI与UX全局设计及全界面清单` | 逐屏列出：用途、入口、出口、必含信息 | 手写 md | `界面清单表.md` | 每屏有入口和出口，没有"孤岛界面" |
| 02 做最坏情况 | 界面清单表 | **先做小屏 + 密集信息 + 长文本**这三种最坏状态 | Godot Control | 最坏状态稿 | 最坏状态不溢出、不遮挡 |
| 03 定结构 | 最坏状态稿 | 分区、层级、导航路径 | Godot Control | 界面结构稿 | 主操作 3 秒内能找到 |
| 04 过可读性 | 结构稿 | 字号、对比、留白逐项检查 | Godot + 截图 | 可读版 | 最远距离也能看清 |
| 05 统一风格 | 可读版 | 按 `UI风格规范_棱镜线框` 统一 | Godot | 正式版 | 与规范一致，无例外项 |
| 06 逐屏验收 | 正式版 | 每屏单独截图 + 勾验收表 | 截图比对 | 验收表 | 每屏一行，全部勾完 |

**02 步是这套链的核心**：只在理想状态验界面，上线必崩。先做最坏情况，剩下的都是加法。

### 4.3 插件 / 扩展

- **Godot**：工程内**没有** `addons/` 目录，无第三方插件，纯原生 4.6。导出只靠 `export_presets.cfg` 的三个 preset，不依赖插件。
- **Blender**：`tools/blender_addons/install_shellstorm_level_builder.ps1` 装自定义插件 `shellstorm_level_builder`。脚本默认 `-BlenderVersion "4.5"`，**与 3 号机实际的 5.2.2 不一致，装之前必须手动传 `-BlenderVersion 5.2`**。
- **Blender MCP**：`blender-mcp-bridge`（`.codex/skills/blender-mcp-bridge/SKILL.md`，12455 B）负责把 Blender 挂成可被 AI 调用的服务；不用 MCP 时一律 `blender --background --python`。
- **版本纪律**：所有 `tools/blender/` 脚本按 `v001…v025` 递增命名，**不覆盖旧版本**；`validate_*` / `audit_*` / `register_*` 三类脚本必须同版本号配套出现。

## 8 常见坑

| 坑 | 后果 | 怎么防 |
|---|---|---|
| 只在理想状态验 | 小屏或长文本一放就崩 | 02 步强制三态最坏情况 |
| 先求美观后求可读 | 漂亮但看不清 | 04 步可读性先过 |
| 没有逐屏验收表 | 漏掉的屏永远没人发现 | 01 步建表，06 步逐屏勾 |
| 界面里写死数据 | 数据变了界面不变 | 数据只从 [数据](玩法-05_数据.md) 读 |
| 每个界面单独定风格 | 全游戏像拼接的 | 05 步统一按规范 |
| 点了没反馈 | 玩家以为卡了 | 所有点击都要有 0.1 秒内可见反馈 |
