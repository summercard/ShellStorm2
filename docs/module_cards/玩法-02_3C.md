## 1 边界

**管什么**
- Character：移动速度、加速度、转身、跳跃、碰撞体
- Camera：跟随、遮挡、视角、调试模式
- Control：输入映射、按键响应、鼠标灵敏度
- 手感：上面三项合起来给玩家的"顺不顺手"

**不管什么**
- 动作怎么 K 出来 → 归 [动画](包装-02_动画.md)（3C 只调播放与过渡参数）
- 相机看到什么画面 → 归 [美术](包装-01_美术.md) 与 [特效](包装-03_特效.md)
- 输入设备的驱动 → 归系统层

**判据**：玩家觉得"走路像在滑冰"是 3C 问题；觉得"动作像木偶"是动画问题。这两个经常被混着报。

## 3 制作流程（流程文档 + 交付标准文档）

### 3.1 六步

| 步 | 输入 | 动作 | 工具 | 产物 | 判据 |
|---|---|---|---|---|---|
| 01 列参数 | 参考游戏 / 主人一句话手感要求 | 把移动/相机/输入拆成可调的独立参数 | 手写 md | `3C参数表.md`（每个参数名+范围+默认值） | 每个参数单独可调，互不耦合 |
| 02 冻基线 | 当前版本 | 记录所有参数的当前值 + 录一段基准走位 | Godot + ffmpeg | `baseline_v1.md` + 基准视频 | 下次调完能对比 |
| 03 单参数调 | 参数表 | **一次只改一个参数**，改完单独看 | Godot 运行时 + debug 键 | 参数改动记录 | 一次只动一个，否则不知道谁背锅 |
| 04 录屏取证 | 调完的版本 | 录 30–90 秒单一内容（走路/转身/跳跃/视角） | `drive.py` + ffmpeg | `~/Desktop/录制/*.mov` | 画面能看清变化，不是静止 |
| 05 写回文档 | 录屏 + 数字 | 把最终值写进参数表，附判断理由 | 手写 md | 参数表更新 + 交付记录 | 别人照表能复现同一手感 |
| 06 回归 | 参数表 | 跑受影响的探针，看有没有影响别的模块 | 探针 | 结果记录 | 移动类探针全绿 |

**本模块特殊要求**：03 步必须一次一个变量。这是全项目最容易违反、也最容易导致返工的一条。

**调试键（注入键盘事件时只认这些）**
- `;` `'` `[` `]` `F12` `=` `-`；键码：`[`=33、`]`=30、`;`=41、`'`=39、`=`=24、`-`=27、`f12`=111

**战斗手感**
- 近战顿帧：`request_melee_hit_stop(frames:=1)`，clamp 1..4，**无通用 hitstop 字段**
- 动画播放保留用户指定的 1.25 倍速
- 晃动/后坐类参数改动必须一次只改一个，否则无法归因

**为什么写这些**：这些都是“模型自己想不到、改错了也看不出来”的数值，必须原样给。

## 8 常见坑

| 坑 | 后果 | 怎么防 |
|---|---|---|
| 一次改三个参数 | 出问题不知道谁背锅，只能全部回退 | 03 步强制单变量 |
| 手感靠"感觉"，不留数字 | 下周想再调回来，调不回来 | 01 步建参数表 |
| 只测直线走，不测转身与上下坡 | 上线才发现贴墙卡住 | L2 必须含转身 + 上下楼 |
| 把"动作难看"报成 3C 问题 | 白调一堆参数 | 先分清是移动问题还是动画问题 |
| 用鼠标注入测视角 | 测不出来，误判代码坏了 | 记住注入限制，改用 debug 键 |
| 相机遮挡只在开阔地测 | 进小房间后视野全废 | L2 要含狭窄空间 |
