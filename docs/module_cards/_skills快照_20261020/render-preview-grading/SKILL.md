# Grade a Preview Render Against Its Reference

## When
- "按参考图还原，改到像为止" — a preview loop where each round returns one image and a self-report.
- A report says "七维自评 4.5" but the image reads wrong; or a worker claims its render "几乎重合" the reference.
- Several failing items must be turned into one brief for the next round.
- Preview images live on a remote host and the user wants to see them in chat.

## Steps
1. **Fix the frame before judging.** A reference screenshot often contains letterbox bars: measure the valid picture area (here 1280×720 with bars → 1280×470, ≈2.72:1) and make preview/final render that aspect. Do not grade, and do not let the worker build, inside the bar region.
2. **Measure both images with the same script, and derive thresholds from the reference.** Never hardcode "meanL 54" as a universal law — run the script on the reference, take its numbers as the target, then require the render to land inside them. Verified failure: a render at meanL 128.6 against a reference at 54.0 (2.38× too bright), warm 93.4% vs 63.0%, midtone 77.5% vs 27.8% — while the worker's own seven-dimension self-score called it close. Metrics, script and report table: `references/pixel-stats.md`.
3. **Grade objective numbers first, then art, then structure.** Order matters: exposure and colour cast mask everything else. Objective: mean/percentiles, warm/cool/white/midtone shares, per-region means within ±10 of the reference. Art: the user's standing checks — minority colour temperature must occupy one coherent ~30% region (not scattered, never a single-temperature frame), foreground must be depth-of-field blurred with a real foreground object 1–2.5 m out. Structure: countable claims only — steps in the staircase, percent margin from each frame edge, percent of frame a carpet covers, whether three handrail points are collinear.
4. **A worker's colour claim is not evidence.** If a worker says "参考图没有冷色", measure it: in that reference cyan was indeed ~0%, and the cool read as near-white highlights plus neutral dark-brown shadow. Do not instruct a cyan block into a frame whose reference has none, and do not accept "冷色 0%" as a reason to stain everything orange.
5. **The first hand-off is a task book, not a plan.** Say only what to build, to what standard, and what to deliver: the reference and its valid frame, an itemized list of what must appear, the measured brightness/colour targets, key dimensions with tolerance, hex base colours, animated elements, deliverables (scene file with `BUILD_MAP` and `SCALE_REPORT` text blocks, one preview at a stated size, the five-section self-report, path + bytes + resolution), and the fixed appendices (modelling rules: pixel style, boxes only, no curves, 0.10–1.20 m grain, ≤3× size ratio per component, ≤6° per stepped increment; delivery; machine limits). The worker never needs to know how many rounds the reviewer plans.
6. **Every later hand-off is a revision order: deltas only.** Each item as `component → what it is now → the target value → how to check it` (e.g. "左拱四边 ≥6% 且落地在画内"), plus an explicit "these must not move" list (camera, already-passing dimensions, all keyframes) and "one preview, no final render". Forbid deletion-and-rebuild: edits are parameters, vertex positions, materials, light values and small props only; the one exception is an object that exists only because it was misread (a checkerboard strip the reference never had, invented signage). Require a backup copy before the round starts.
7. **Push the order to the host, then have the host execute it — by its own CLI agent or by a script you wrote.** Two working paths, one decision rule:
   - **Host CLI agent (default for a scene-editing round).** Write the revision order locally, push it as a file, then start the agent on a one-line instruction to read and execute it: `ssh <host> 'cat > <ROOT>/修改单_Rn.md' < local.md`, then `ssh <host> 'cd <ROOT> && ~/.pi/agent/bin/pi -p "读 修改单_Rn.md 并严格按它执行"'`. Verified across six consecutive rounds (jukebox → sofa → bar → three props → sofa scale → lighting): every round returned a changed scene file and a new preview (207–239 KB) with no intervention beyond pulling the image and writing the next order. The agent writes the patch scripts itself, so your brief must be complete enough to execute without questions — deltas with numbers, the do-not-touch list, one preview, no final render.
   - **Your own step script (fallback / mechanical change).** Use it when the host agent is missing or unconfigured, when a round is a parameter or numeric edit you can state exactly, or when an agent round failed at its own model layer. Push with `ssh <host> 'cat > scripts/sN.py' < local.py`, run through a runner that backs up once per step, forces `taskset`/`nice` isolation, and **passes `--python-exit-code 1`** (Blender exits 0 through a Python traceback otherwise), then read `state/sN.json` and the log.
   - **A round that produced no artifact did not happen.** A delegated run killed by its LLM layer (`ENOTFOUND`, provider failure) leaves no file and does not count as a revision — re-dispatch with a suffixed task name, do not subtract it from the budget. The earlier "no LLM in the loop" rule came from exactly those deaths plus one agent that spent ~50 min on exposure-only patches; the verifiable fault was the chat-side model link and an underspecified brief, not delegation itself. Either way the proof is the same: preview pulled, image read, file bytes and mtime changed.
   Full runner, probe-first pattern, node lookup by type, idempotent rebuild-by-prefix and transfer fallbacks: `references/remote-step-pipeline.md`.
8. **Keep the round ledger yourself — never write it into the brief.** No "第 X 次修改 / 共 N 次", no "接下来三轮会…", no round budget in either document; the worker does the current job only. A worker that spent five self-reported rounds fixing its own bugs (wrong wall, typo, rebuild) has produced a **baseline**, not five revisions — reset the count silently. A worker cannot extend or define its own budget.
9. **Re-grade the returned image, not the returned report.** Re-run the script on the delivered file, re-count the structural claims, then keep or reject. Where the worker's self-score and the measurement disagree, the measurement decides; record the divergence.
10. **Deliver the image, verified.** Check bytes and pixel dimensions on the copy you actually send (transfer truncation is common), then send one image per message. Mechanism and pitfalls: `references/media-handoff.md`.

## Decision rules
- A round that only restates the previous brief without changed numbers is a wasted round; refuse to open it.
- Fixing exposure outranks fixing detail: an image 2× too bright cannot be judged for detail, and "结构不对" complaints often start as an exposure/colour-cast error.
- Structural fidelity is judged by countable differences, not adjectives: "不像同一栋楼" becomes arch steps 12–16 → 28–32, arch ring 0.46 → 0.55 m, chandelier 1.50 → 1.95–2.10 m.
- Art rules are constraints, not suggestions: a frame with a single colour temperature or a sharp foreground fails regardless of element completeness.
- Keep working files on the render host; retrieve a single preview to a temp path for the user and delete it after sending.
- **Hand off to the user at >3.5 average, not 4.0.** The user reviews and gives the second pass; chasing another half point burns the worker's time for a decision that is theirs. If one dimension is ≤2, name it in the grading note even when the average passes, so the user can decide whether to spend another round.
- A dimension that failed twice with different approaches is not worth a third: drop it into the unresolved list and let the user judge.
- **Check the scene is rebuildable before calling it delivered.** A build script left at 0 bytes means the scene survives only as a `.blend` and every later change is hand-editing: verified, `build_q8.py` was 0 B while the scene passed. State it as a known gap in the hand-off (and in the asset card) instead of assuming the `BUILD_MAP` blocks make it reproducible.

## Done when
The latest preview measures inside the reference-derived thresholds, every structural item on the revision order has its stated number met, and the image has been delivered with its path, byte size, resolution and sampling stated — or the seven-dimension average is above 3.5 and the grading note has been handed to the user for the second pass.
