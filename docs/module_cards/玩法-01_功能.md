## 1 边界

**管什么**
- 系统规则：什么条件触发什么结果
- 状态机：状态怎么进、怎么出、卡住怎么收口
- 数据流：谁读、谁写、读不到怎么办
- 失败收口：输入无效、资源不足、写盘失败的退路

**不管什么**
- 数值平衡的最终数字 → 归 [数据](玩法-05_数据.md)
- 界面怎么画 → 归 [交互体验](包装-06_交互体验.md)
- 资产长什么样 → 归 [美术](包装-01_美术.md)
- 输入怎么映射成动作 → 归 [3C](玩法-02_3C.md)

**判据**：如果一个改动需要同时改规则和界面才能生效，那它至少有半个属于交互体验，先拆。

## 3 制作流程（流程文档 + 交付标准文档）

### 3.1 六步

| 步 | 输入 | 动作 | 工具 | 产物 | 判据 |
|---|---|---|---|---|---|
| 01 定身份 | 创意中心一句话 + 现有 `MODULE_INDEX.md` | 分配 `feature_id` / `module_id`，指定**唯一事实所有者** | 手写 md | `MODULE_INDEX.md` 新条目 | ID 全库唯一，所有者只有一个 |
| 02 写规则 | 需求原话 + 已有同类功能文档 | 写四类路径：正常 / 拒绝 / 重试 / 读档 | 设计文档模板 | `design/<功能名>.md` | 四类路径都写全，失败分支不写"暂不处理" |
| 03 立入口 | 规则文档 | 建独立探针或最小场景，不依赖主流程 | Godot 场景 / `probe_*.gd` | `tests/verification/` 新探针 | 不启动主流程也能跑出结果 |
| 04 实现 | 规则文档 + 探针 | 在 `src/<module>/` 内实现 | Godot 4.6 · Codex CLI（2 号机） | `src/` 下代码 | 不跨模块写别人字段；数值不写死在脚本 |
| 05 取证 | 实现完成 | L1 探针 + L2 真实截图 | 探针 + 截图 | `development/YYYY-MM-DD_*.md` | 探针全绿 + 截图与参考对得上 |
| 06 归档 | 证据 | 写交付记录 + 账本条目 + 更新完成度清单 | 手写 md | `development/` + `12_全游戏完成度清单.md` | 记录含基线 commit、改了什么、剩什么 |

**最少六步。** 少一步就意味着有人要在没有任何依据的情况下接手。

### 4.3 插件 / 扩展

- **Godot**：工程内**没有** `addons/` 目录，无第三方插件，纯原生 4.6。导出只靠 `export_presets.cfg` 的三个 preset，不依赖插件。
- **Blender**：`tools/blender_addons/install_shellstorm_level_builder.ps1` 装自定义插件 `shellstorm_level_builder`。脚本默认 `-BlenderVersion "4.5"`，**与 3 号机实际的 5.2.2 不一致，装之前必须手动传 `-BlenderVersion 5.2`**。
- **Blender MCP**：`blender-mcp-bridge`（`.codex/skills/blender-mcp-bridge/SKILL.md`，12455 B）负责把 Blender 挂成可被 AI 调用的服务；不用 MCP 时一律 `blender --background --python`。
- **版本纪律**：所有 `tools/blender/` 脚本按 `v001…v025` 递增命名，**不覆盖旧版本**；`validate_*` / `audit_*` / `register_*` 三类脚本必须同版本号配套出现。

### 4.4 落在哪台机器、哪个模型

| 问题类型 | 模型 | 例子 |

| 常规增删改查、单文件改动 | **DeepSeek** | 改一个奖励公式、加一个字段 |

#### 原 11.3 AI 关键词与硬数字（写提示词时直接抄）

**命运卡**
- 六关累计投放 `21 / 33 / 45 / 57 / 69 / 78` 个 `stable_card_id`；01、02 仅正位，03 起少量逆位，06 全开
- `SCHEMA_VERSION 3`、价格带 `0.85–1.15`、`MIN_CARD_PRICE 40`、`fate_sun_bounty` 上限 100
- 报价只由「门序号 + 该门基准房收益 + 种子」决定，**与玩家钱包无关**；同一次三张不重复；旧局快照不重掷
- `level_pools.json` 只配了 `expedition_01`，其余关卡策略缺失时 **fail-closed 不投放**

**枪械**
- 最终伤害 = `damage` + `bullet_damage`，两项同时乘 `WeaponDropGrade.damage_multiplier(drop_grade)`；root 为空返回 `{}`
- `WeaponForge` 三配方：R1 `remelt`（1 武器 + ≥1 弹药模块）、R2 `fusion`（≥2 武器取最高伤害为蓝本）、R3 `synthesis`（熔炼值 ≥6，产 `floor(V/6)` 把，上限 3）
- 常量：`MELT_THRESHOLD 6`、`MAX_MELT_OUTPUT 3`、`MELT_VALUES`（common1/uncommon2/rare3/epic4/legendary6）、托盘 `5×5 = 25`
- **注释陷阱**：`WeaponForge.gd` 文件头写“6×6=36 格”，实际常量是 5×5=25。以常量为准

**为什么这些数字必须写进提示词**：模型不知道你的价格带和 fail-closed 习惯，不写就会自己发明一套，且看上去很合理。

## 8 常见坑

| 坑 | 后果 | 怎么防 |
|---|---|---|
| 只做 happy path | 异常一来就崩，且崩得莫名其妙 | 02 步强制写拒绝/重试/读档 |
| 跨模块直接改别人字段 | 改一处，全项目要回归 | 04 步检查：写入权是否在自己模块 |
| 改动不留基线 commit | 出问题不知道回哪 | 06 步记录必带 commit |
| 数值写死在脚本里 | 调平衡要改代码 | 走 `data/` 下的表 |
| 探针只写正向不写负向 | 探针永远绿，等于没测 | L1 要求"故意改坏要变红" |
| 交付记录写"已完成" | 无法判断完成到哪一级 | 必须写"L2 通过"这种带级别的表述 |
