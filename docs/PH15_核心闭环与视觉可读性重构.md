# PH15 核心闭环与视觉可读性重构

**状态：已完成**  
**日期：2026-07-10**

## 本轮决策

当前最大的风险不是内容量，而是玩家无法稳定读懂、完成并相信一局游戏：Boss 的受击与结算未形成同一条链路，生命状态存在多个来源，战斗画面则被纯黑遮蔽和临时视觉削弱。

本轮将“可完成的一局”收敛成一条可验证的契约：

```text
玩家命中 Boss → BossActor 反馈并确认伤害 → BossRoomDirector 结算进度
→ 解锁 Boss 撤离/更新 HUD → 玩家完成撤离
```

## 玩家体验目标

1. Boss 必须有清晰、可命中的实体轮廓；击败后应立即产生可读的胜利反馈与撤离资格。
2. 玩家、武器、敌人与可交互物必须在低照度场景中保持可辨识轮廓，而不是只剩黑色剪影。
3. HUD 应按“生存（生命/弹药/闪避）—目标（房间/风险）—导航（小地图）”组织；同一组信息采用统一语言和颜色。
4. 程序化视觉不得绑定玩法数据：正式 Sprite、动画与主题资源将来可替换显示节点，不改变战斗、背包或地图契约。

## 运行时契约

### 状态权威

- `Player` 是局内生命值的唯一权威；`GameManager` 只保留货币和旧模式兼容接口，不再驱动 `RoomGameMode` 的生命逻辑。
- `BossActor` 是战斗中的命中、受击冷却、表现和死亡实体；它通过信号报告已经确认的伤害。
- `BossRoomDirector` 是地图进度、奖励与撤离条件的唯一权威。它只消费 `BossActor` 已确认的伤害，不再维护一套与实体不同步的 Boss HP。
- `VisionSystem`、命运卡和武器装配节点均使用与其真实所有权匹配的生命周期；不再以未挂树的 `Node` 形式遗留。

### 表现权威

- 环境只保留低亮度蓝黑基调，不能以纯黑吞掉可行走地面。
- 玩家与 Boss 分别由 `PlayerAvatarRenderer`、`BossAvatarRenderer` 承担程序化外观；碰撞、武器树和组件接口保持不变。
- HUD 的颜色、描边、间距与进度条由集中样式工具提供，未来可替换皮肤或图集而不改业务 UI。

## 实施结果

- `RoomBoss.tscn` 为 Boss 补齐圆形碰撞体；`BossActor.take_damage` 与普通敌人统一为三参命中契约，真实 `Bullet.body_entered` 现在可完成伤害与死亡。
- Boss 运行时伤害通过 `RoomGameMode` 进入 `BossRoomDirector`；最终 HP、奖励、Boss 击败状态与 `BOSS_KILL` 撤离由同一条链路结算。
- `Player` HP 成为局内唯一生命来源；HUD 与 `BLESS_DEAD` 都消费 `Player.hp_changed`。`VisionSystem` 改为 `RefCounted` 纯计算服务，退出时重置。
- 武器装配树在换枪和退出时递归释放数据节点；命运卡改为 `RefCounted` 数据对象，消除了卡池和装配树的孤立 Node/脚本资源泄漏。
- 新增可替换的程序化玩家和 Boss 渲染节点，隐藏原有 emoji/色块占位资产；替换为 Sprite 或动画时只需替换 `AvatarRenderer` 子节点。
- 低照度调色从纯黑改为蓝灰环境光，HUD 放在独立高 CanvasLayer 并统一生存信息、数字读数与中文标签。
- 修复 Boss 击败全屏闪光使用非法 `z_index = 9999` 的引擎错误，改为有效上限内的 `4095`。

## 验收标准

1. Boss 场景拥有随体型缩放的碰撞体；玩家子弹可命中该实体。
2. 造成致命伤害后：`BossActor`、`BossRoomDirector`、地图击败状态与 Boss 撤离条件在同一帧链路内一致。
3. `BLESS_DEAD` 直接监听 `Player.hp_changed` 并能在低生命时启动计时。
4. 框架验证退出时不再保留 `VisionSystem` 的孤立 Node/脚本资源。
5. 在 1280×720 下，玩家、目标提示、生命/弹药/闪避和小地图均能在低照度环境中保持可读。
6. 新增 Boss 完成验证；现有框架、主循环和 UI 验证保持通过。

## 验证记录

- 新增 `verify_boss_completion_flow.tscn`：真实玩家子弹命中 Boss，验证碰撞体、战斗激活、BossDirector 击败结算和 Boss 撤离解锁。
- 21 个场景流程验证与独立命运卡池验证全部通过；编辑器无头扫描通过。
- `verify_vision_system_flow.tscn` 通过，确认锥形视野、半径与墙体遮挡仍一致。

## 本轮刻意延后

- 不把 `RoomGameMode` 与 `GameUIManager` 做一次性大拆分；本轮只建立更明确的边界与清理点。
- 不引入最终美术资产或外部图集；程序化节点会保留语义化名称和可替换挂点。
