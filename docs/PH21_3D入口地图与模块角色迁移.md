# PH21：3D 入口地图与模块角色迁移

**状态：首个垂直切片已接入；已由 PH22 扩展为全游戏 3D 原型**  
**日期：2026-07-21**

> 后续演进：四张副本、独立靶场、枪械、敌人、家具、灯光、战斗与撤离已经在 `PH22_全游戏3D高质量原型.md` 完成 3D 化。本文件保留首个迁移切片的历史边界与决策依据。

## 本轮方向

把玩家启动游戏后看到的固定基地—荒野地图先迁移为 3D，同时保留现有 2D 战斗副本、数值、存档、菜单与资产，验证项目能否在不推倒玩法系统的前提下逐步转向 3D。

这个方向优先于一次性全项目重做，因为入口地图承担第一视觉承诺，并且已经拥有稳定的设施、道路、副本入口和返回点契约。先让这条完整流程进入 3D，能够尽早验证镜头、操作、比例、交互和资产生产成本。

## 玩家可感知变化

- 项目入口改为 `scenes/BaseWorld3D.tscn`，原 `BaseWorld.tscn` 继续保留为 2D 基线和回退参照。
- 基地、广场、荒野公路、支路、四个污染区、废墟、路障和 13 盏导航灯转换为具有高度、材质、阴影和透视关系的 3D 模块。
- 8 个基地设施和 4 个副本入口保持原有名称、位置关系、菜单/地图路径与返回 ID。
- 玩家改用 `CharacterBody3D` 在 XZ 平面移动；固定俯视摄像机跟随玩家，鼠标射线与地面求交得到瞄准方向。
- 角色仍是非人胶囊防护体：无腿、无脚、无手臂、单传感器、单手、独立红围巾；不是重新设计成普通人形。
- `idle / moving / dashing / hurt / locked / dead` 六态继续互斥；Low HP 与无敌仍是叠加表现。状态变化直接驱动 3D 组件压缩、弹性、尾迹、红闪、锁定环和倾倒。

## 技术与资产边界

```text
BaseWorld3D
├── EnvironmentKit              # 3D 地面、道路、废墟、灯光、静态碰撞
├── Facilities                  # 8 × BaseFacility3D
├── DungeonEntrances            # 4 × DungeonEntrance3D
├── Player3D                    # 逻辑、碰撞、六态状态机
│   ├── Camera3D                # 不随角色瞄准旋转
│   └── Avatar3D
│       └── VisualRoot          # 单独读取鼠标瞄准 yaw
│           ├── Body
│           ├── Head
│           ├── Scarf
│           ├── Hand            # 单可见手，无手臂
│           └── WeaponSocket    # 独立枪械挂点
└── HUD                         # 继续使用 CanvasLayer
```

- 世界比例采用原 2D 坐标的约 `0.01`：原有设施和入口空间关系可追溯，未来可以逐模块替换而不改变玩法 ID。
- 3D 模型目前使用代码原生 PrimitiveMesh，是已接入的程序占位，不冒充正式模型资产。
- 3D 表现作为 `base_world` 和 `player_capsule01` 的子变体登记；2D 表现没有被覆盖或删除。
- 角色碰撞、移动和状态机位于 `Player3D`；组件网格和状态动态位于 `PlayerAvatar3D`，两者互不反向持有玩法规则。
- 返回基地的训练靶场、基地菜单与战斗 HUD 路径统一改为 `BaseWorld3D.tscn`。

## 验收标准与结果

1. 项目入口为 3D 场景，能在真实窗口中显示透视镜头、灯光、阴影、设施与模块化玩家。——通过。
2. 地图保留 8 个设施、4 个入口、训练靶场路径和副本返回点。——通过。
3. 玩家拥有四个独立视觉组件、一个可见手和独立 `Marker3D` 枪械挂点。——通过。
4. 六态使用显式转移白名单；Dead 为终态，非法回到 Idle 会被拒绝。——通过。
5. Moving、Dashing、Hurt、Locked、Dead 均能驱动独立 3D 状态表现。——通过。
6. 3D 世界节点量保持在 340 以下；当前专项验收为 310 个节点。——通过。
7. 1280×720 真实渲染预览能够生成，玩家、道路和设施在游戏镜头中可辨。——通过。

## 刻意延后

- 四张战斗副本仍是 2D；当前只迁移用户指定的启动地图。进入副本后仍按原流程加载独立 2D 场景，撤离或离场回到 3D 基地。
- 枪械射击、子弹、敌人、导航网格和战斗 HUD 的完整 3D 化不在本切片内。
- 当前 PrimitiveMesh 设施与角色属于可运行灰盒；下一轮应优先制作统一低多边形材质规范，再替换模型，不应先堆叠更多临时形状。

## 下一步建议

下一轮最有价值的是把独立训练靶场迁移为 3D 战斗验证房：只接一把枪、一种弹丸和一个训练靶，用来验证 3D 射线/实体弹道、枪口、命中反馈、后坐力与敌人受击，再决定四张正式副本的迁移顺序。
