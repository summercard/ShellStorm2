## 一、怪物技能增强

### 问题
- 6种基础怪物只有简单timer行为，无独立技能节点
- 精英词缀系统存在但没有怪物主动技能组件
- 怪物之间技能差异主要靠数值（速度、血量），而非行为

### 改进方案
为每种怪物设计2-3个**主动/被动技能**，通过 EnemySkillComponent 注入，不修改 EnemyBase 本体。

| 怪物类型 | 技能1（主动） | 技能2（被动/触发） | 技能3（触发型） |
|---|---|---|---|
| Chaser | 冲刺猛击：短距离突进，接触伤害×1.5 | 狂暴化：低血量时移速+40% | — |
| Ranged | 散射弹幕：同时发射3颗角度偏移的子弹 | 侧翼机动：保持310px最优距，离开时后撤 | 警戒射击：被近身时立即后退并反击 |
| Summoner | 召唤小怪：每5秒生成2只小怪 | 母巢光环：附近小怪移速+25% | 亡崽继承：召唤的小怪继承30%攻击 |
| Tank | 盾击：持盾冲锋，眩晕玩家0.5s | 钢铁意志：每次受击有15%几率完全抵挡 | 铁壁防御：护盾激活时，碰撞伤害×2 |
| Bomber | 自爆：接近玩家3m内自爆 | 引线燃烧：自爆前3秒引线燃尽音效+发光 | 碎片飞溅：爆炸后散射8颗碎片 |
| Trapper | 地刺陷阱：地面生成陷阱区域，持续4s | 潜伏突袭：静止3秒后下次攻击必定暴击 | 诱捕孢子：被攻击时释放减速区域 |

### EnemySkillComponent 实现
新建 `src/enemy/components/EnemySkillComponent.gd`，提供技能注册和执行接口：
```gdscript
# 技能注册
func register_active_skill(skill_id: String, config: Dictionary)
func register_passive_skill(skill_id: String, config: Dictionary)
# 触发
func try_trigger_active() -> bool
func evaluate_passives()
```

## 二、武器伤害差异性调整

### 问题
- 霰弹枪单发伤害仅12，但多弹丸机制下DPS实际很高（5×12=60）
- 狙击枪58伤害 vs 步枪22 — 狙击枪单发优势明确，但当前狙击枪射速1.8导致DPS 58*1.8=104，远超步枪的132
- 冲锋枪15伤害×9射速=135DPS，和步枪的132几乎相同，差异化不足
- 子弹只有5种，缺少元素伤害类型

### 调整方案

#### 枪身伤害梯度重新校准
| 枪身 | 调整前伤害 | 调整后伤害 | 变化 | 原因 |
|---|---|---|---|---|
| 豌豆手枪 | 18 | 20 | +2 | 副武器定位，手感提升 |
| 步枪 | 22 | 22 | ±0 | 基准不变 |
| 霰弹枪 | 12×5弹丸 | 15×5弹丸 | +3 | 近距爆发定位 |
| 冲锋枪 | 15 | 12 | -3 | DPS过高但单发太弱，调整单发使连射才有意义 |
| 狙击枪 | 58 | 65 | +7 | 单发王者，爆头快感强化 |
| 轻机枪 | 12 | 10 | -2 | 60发高DPS（600/4.2=142），削弱单发 |
| 榴弹发射器 | 42 | 50 | +8 | 范围伤害，爆炸半径80px，定位高风险高回报 |

#### 新增子弹类型：剧毒弹
```json
{
  "id": "bullet_poison",
  "name": "毒液弹",
  "type": "Bullet",
  "tags": ["bullet", "poison", "dot"],
  "bullet_damage": 5,
  "bullet_speed": 0.9,
  "dot_dps": 8.0,
  "dot_duration": 3.0,
  "dot_type": "poison"
}
```
- 设计：命中后附着目标，持续3秒每秒8点伤害
- 与黏黏弹区分：黏黏弹减速，毒液弹持续掉血
- 克制：对付Tank类怪物（护盾格挡不了DOT）

- 进度 33%~66% → MEDIUM
- 进度 > 66% → DEEP

#### 2.2 怪物类型可用池按实际楼层差异化（MonsterInjector._get_available_types_for_level）
`floor_level` + `floor` 双参数判断：

- `floor>=2` + `SHALLOW` → 开放全部6种怪物（第二关开始难度和丰富度提升）

#### 2.3 怪物生成数量随楼层增加（MonsterInjector._generate_random_enemies）
第一层：2-3只 → 第二层：3-4只 → 第三层：4-5只 → 第四层：5-6只

## 本轮改进 — FateCardUIController 输入阻塞修复（循环 428）
**日期：** 2026-05-30
**循环：** 427 → 428

---

### 一、问题
轮次427终验复查发现命卡选择系统存在输入阻塞 Bug：

- 玩家在房间清理后看到"按 Tab 选择命运卡片"提示
- 按 Tab 后游戏暂停（`get_tree().paused = true`），但 FateCardUIController 继承默认 `process_mode = inherited`
- 当游戏暂停时，`_input` 方法不再被调用
- 玩家按 Tab/ESC 完全没有反应，必须强制结束进程
- Tab 关闭按钮（`ui_cancel`）也因为同样原因失效

### 二、改进方案

#### FateCardUIController.gd — `_ready()` 添加 `process_mode = ALWAYS`
```gdscript
func _ready() -> void:
    # 必须设置为 ALWAYS，保证游戏暂停时也能接收 Tab 输入
    process_mode = Node.PROCESS_MODE_ALWAYS
    # ... 其余查找节点逻辑不变
```

**原因**：
- FateCardUIController 在显示卡片时执行 `get_tree().paused = true`（暂停游戏逻辑）
- 默认 `PROCESS_MODE_INHERITED` 会导致节点在父节点暂停时也暂停
- `PROCESS_MODE_ALWAYS` 确保节点始终处理输入事件，即使游戏暂停

### 三、涉及代码
- `src/ui/FateCardUIController.gd`：在 `_ready()` 开头添加 `process_mode = Node.PROCESS_MODE_ALWAYS`

### 四、验收标准
1. ✅ Godot headless 编译通过（EXIT 0）
2. 游戏暂停时 FateCardUIController 仍能接收 `ui_tab` 和 `ui_cancel` 输入
3. 命卡选择界面可以通过 Tab 打开和关闭

### 五、风险
- `PROCESS_MODE_ALWAYS` 意味着该节点永远不会因游戏暂停而停止处理 — 这是预期行为，因为该节点就是专门在暂停状态下处理选卡 UI 的
- 未来如果场景中有其他暂停状态 UI（不是命卡），需要确保它们也设置了 `PROCESS_MODE_ALWAYS`
