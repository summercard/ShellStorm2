# Phase 9：搜打撤深化

## 目标
实现完整的撤离系统——带入带出规则、背包格子、保险格、死亡结算。

---

## 带入与带出
| 类型 | 内容 |
|---|---|
| 可带入 | 初始枪身、少量基础子弹模块、一个低阶配件、消耗品、撤离信标、基地解锁的祝福 |
| 可带出 | 未消耗资源、蓝图碎片、模块样本、命运卡片残页、Boss材料、可用于基地升级的货币 |

---

## 死亡损失规则（轻度搜打撤）
- 局内临时组合全部丢失
- 背包中未保险的资源部分丢失
- 带入装备不永久丢失，或仅损失耐久
- 稀有资源可通过保险格保留

---

## 撤离方式
| 撤离方式 | 条件 | 风险 |
|---|---|---|
| 固定撤离点 | 地图生成时存在 | 位置较远，可能被怪物围堵 |
| 随机撤离门 | 清理房间后概率出现 | 开启时间短 |
| 信标撤离 | 消耗道具召唤 | 读条期间刷怪 |
| Boss撤离 | 击败Boss后出现 | 需要先打Boss |
| 交易撤离 | 向NPC支付资源 | 牺牲收益换安全 |

---

## 解耦结构
| 模块 | 职责 |
|---|---|
| InventoryModule | 背包格子、容量管理 |
| ExtractionModule | 撤离读条、结算逻辑 |
| InsuranceModule | 保险格管理 |
| Death结算Module | 死亡掉落计算 |

## 搜打撤与肉鸽的关系
- **肉鸽**负责"当前局内变强"
- **搜打撤**负责"当前收益能不能安全带走"
- **基地养成**负责"长期解锁更多组合可能"

## 2026-05-23 修复记录

## 2026-05-24 局内竖切闭环

当前主入口 `scenes/Main.tscn` 使用 `CoreCombatMode` 承载全代码战斗循环。本轮先在该模式内补齐一条可玩的搜打撤 + 肉鸽射击闭环，后续再逐步与完整房间图、容器和基地系统合并。

### 战局节奏
| 阶段 | 触发 | 玩家选择 | 设计目的 |
|---|---|---|---|
| 开局 | 进入主战斗场景 | 移动、射击、闪避 | 先给出即时操作反馈 |
| 波次战斗 | 每波开始 | 清怪、拾取魂 | 建立基础射击和收益反馈 |
| 命运介入 | 每 2 波清理后 | 三选一阶段强化 | 形成肉鸽局内成长 |
| 撤离窗口 | 每 3 波清理后 | 立刻撤离 / 继续深入 / 整备后深入 | 形成搜打撤风险决策 |
| 深入压力 | 选择继续后 | 敌人生命和伤害提升，魂收益提升 | 让贪收益承担明确代价 |
| 撤离结算 | 选择撤离或触发撤离读条 | 展示波次、击杀、魂、风险层级 | 给“带走收益”一个清晰终点 |

### 当前实现规则
- 魂奖励现在通过 `SoulOrb` 拾取到账，不再“击杀即时到账 + 掉魂”重复结算。
- `CoreCombatMode.run_risk` 表示局内深入风险；风险会提高敌人生命和伤害。
- `_reward_multiplier` 表示收益倍率；继续深入或风险命运会提高后续魂收益。
- 命运卡牌先以轻量运行时选择实现，直接作用于武器树或玩家属性：
  - 穿甲誓约：提升子弹伤害。
  - 急速脉冲：提升射速并降低换弹时间。
  - 分裂枪膛：增加投射物并提高扩散。
  - 战地缝合：提升生命上限并治疗。
  - 血契赏金：立即获得魂、提升伤害，同时提高风险。
- `GameUIManager.show_run_choice_panel()` 负责统一显示命运/撤离选择，战斗模式只发送结构化选项，保持 UI 与战斗逻辑解耦。

### 后续接入方向
- 将运行时命运选择替换或桥接到 `FateCardPresets` / `FateCardGameBridge`，保留当前三选一 UI。
- 将撤离成功从简化统计扩展到真实背包、保险格、基地持久化。
- 将 `run_risk` 显示到 HUD，让玩家在继续深入前能感知当前风险层级。
- 将撤离窗口与地图撤离点系统合并，支持固定撤离点、信标撤离、Boss/精英撤离。

## 2026-05-24 房间钥匙与撤离房闭环

本轮将主战局入口切回 `RoomGameMode`，让局内体验从单房间波次推进为多房间探索。

### 当前房间推进规则
| 步骤 | 规则 | 体验目的 |
|---|---|---|
| 进入房间 | 房间由 `MapGenerator` 生成，含普通战斗、事件、陷阱、Boss、撤离等节点 | 形成关卡路径和方向选择 |
| 房内搜索 | `RoomFactory` 会在主要探索房内生成可搜索容器 | 让每个房间都有搜刮动作 |
| 清理房间 | 战斗房清完波次、非战斗房完成事件后标记清理 | 让“打完房间”成为开门前置 |
| 掉落钥匙 | 非出生/撤离房清理后生成 `RoomKeyPickup` | 给玩家明确的开门奖励 |
| 选择门 | 拾取钥匙后显示当前房间可开启的方向门 | 一把钥匙只开一扇门，保留路线取舍 |
| 进入下房 | `RoomDoorInteraction` 消耗钥匙、打开选中连接并切换房间 | 多房间连续探索 |
| 撤离房 | 地图每层保证至少一个 `EXTRACTION` 房，进入后启动撤离读条 | 成功撤离后背包/保险格物品带出 |

### 实现边界
- `scenes/Main.tscn` 当前挂载 `RoomGameMode` 作为主战局入口。
- `MapManager.enter_room()` 不再自动打开所有门，门由钥匙交互打开。
- `RoomFactory` 对战斗/精英/搜刮/藏储/陷阱/Boss/撤离房生成搜索容器，并改用本地坐标放置，避免容器偏出房间。
- `MapGenerator` 保证每层有一个撤离房，默认连接在 Boss 前节点附近。
- 撤离成功沿用 `RoomGameMode._on_extraction_completed()`，会执行背包/保险格结算和基地保险库持久化。

### 下一步建议
- 将门交互的视觉与 `RoomDoorVisualizer` 合并，让门在未开启、可开启、已开启三个状态下都有更强表现。
- 撤离房应从“进入自动读条”升级为房内撤离点交互，允许玩家先搜索再撤离。
- 钥匙可以升级为真实背包物品或局内临时资源，并在 HUD 显示当前数量。

## 2026-05-25 物理房间门闭环修订

房间推进从“按 E 传送到下一房”改为“物理地图逐步展开”。

### 新规则
| 步骤 | 规则 | 体验目的 |
|---|---|---|
| 地图生成 | 房间按 800×600 网格排布，主路径横向延展，分支/撤离房上下接入 | 房间在世界里真实相邻 |
| 开门 | 玩家清房拿钥匙后，在门口按 E 只消耗钥匙并打开连接 | 门是物理门，不是传送门 |
| 打通墙体 | 打开的连接会在当前房和目标房的边界墙上生成门洞 | 玩家可以直接走过去 |
| 揭示房间 | 目标房在开门后显示，地图视觉上越开越大 | 强化探索扩张感 |
| 进入房间 | 玩家身体走入目标房范围后，才切换当前房间并触发该房间战斗/事件 | 房间切换来自位置，而非按钮传送 |

### 实现说明
- `MapGenerator` 现在生成正交网格房间，避免斜向/重叠连接导致门洞对不上。
- `NodeGraph.add_node()` 会把节点位置同步写入 `RoomData.position`，保证房间实例真实落在地图坐标上。
- `RoomVisualizer` 与 `RoomTileMapInitializer` 根据开启门方向重建边界碰撞，为已开门方向留出缺口。
- `RoomDoorInteraction` 只请求开门，不再进入目标房。
- `RoomGameMode` 根据玩家世界坐标检测进入哪个已揭示房间，并在进入时启动对应房间逻辑。
