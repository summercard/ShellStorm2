# PH38｜八米层内摄像机与纯物理遮挡

## 一、改造目的

PH37 使用摄像机—角色射线、楼梯下降进度和当前房间状态动态隐藏上层楼板、
房间墙与楼梯墙。该方案虽然能维持旧高位斜视镜头，但显示状态较多，楼梯过渡也容易
出现一帧切换差异。

PH38 改为更直接的空间规则：

- 塔楼层高继续保持9米；
- 摄像机放在角色正上方8米，位于上一层楼板下方；
- 摄像机改为垂直俯视，避免15米房间内镜头偏到墙外；
- 不再按摄像机射线或楼梯进度隐藏任何楼板、房间墙、楼梯墙或已流送房间；
- 楼层之间依靠实体楼板、满高墙和楼梯洞口自然遮挡。

本轮不修改角色模型、碰撞体或动画缩放；角色大小将在后续单独调整。

## 二、运行规则

1. 摄像机相对角色位置固定为 `(0, 8, 0)`，俯角为 `-90°`。
2. 当前流送窗口内的楼板和外墙全部正常渲染；窗口外才因性能流送整体停用。
3. 已构建且处于房间流送范围的房间保持可见，不再因楼层编号或过渡比例强制隐藏。
4. 上下楼时摄像机垂直跟随角色，视线通过楼梯实际洞口观察角色，不删除上层楼板。
5. 楼板承重、墙、门和楼梯护栏碰撞保持不变；关闭门继续阻挡角色与逻辑视野。
6. 楼层加载数量仍不得超过5层，房间模拟仍只运行当前房及已开启邻房。

## 三、验收条件

- 摄像机运行时高度严格为8米，水平偏移为0，垂直俯视。
- 塔楼代码中不存在房间墙、楼梯墙或楼板的摄像机射线剖切调用。
- 楼梯中段的上下层楼板都保持渲染，不再按12%/22%进度切换。
- 角色能完整下楼和回爬，摄像机视线穿过真实楼梯洞口。
- 鼠标瞄准仍投影到角色当前楼层，不回到世界Y=0。
- 楼层流送窗口仍不超过5层，性能预算和既有门禁/命运/电梯/Boss流程不回退。

## 四、实施与验收结果

- `TowerDescent3D` 摄像机已改为相对角色 `(0, 8, 0)`，旋转为
  `(-90°, 0°, 0°)`；FOV仍沿用既有设置。
- 已删除楼梯网格标记、摄像机—角色网格相交检测、楼梯墙剖切、房间墙方向剖切，
  以及按楼梯12%/22%进度切换楼板显示的代码。
- 所有流送窗口内楼层都同时保留楼板和外墙；所有已流送房间保持可见。
  窗口外楼层仍整体停用，加载数量不超过5层。
- 塔楼专项通过：摄像机8米、纯物理遮挡、上下层楼板同时渲染、真实下楼与回爬、
  鼠标当前层瞄准、门禁、命运、电梯和95层Boss均成立；节点总数3252。
- Apple M1 OpenGL已重新采样楼顶、99层、98层和楼梯四个画面，镜头没有被上层
  楼板或满高墙覆盖。角色视觉尺寸本轮未修改。
- 性能回归通过：生成133.0ms、最重房构建7.8ms、持续帧段6.89ms、
  稳定视野重绘0次；360°逻辑视野与运行安全回归通过。
