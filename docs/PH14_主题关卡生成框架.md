# Phase 14：主题关卡生成框架

## 目标

固定大世界与战斗副本彻底分层：

```text
固定基地 + 固定野外 BaseWorld.tscn
  -> 道路旁副本入口建筑 DungeonEntrance.tscn
  -> 独立关卡场景 scenes/levels/*.tscn
  -> 关卡引用 MapThemeProfile.tres
  -> 主题规则驱动地图、怪物、内容与 NPC 生成
```

随机生成不等于无约束随机。每张关卡必须有明确主题、路径节奏、必出节点、生态与风险收益规律。

## 第一批独立关卡

| 独立场景 | 主题资源 | 主要规律 |
|---|---|---|
| `IronFrontier.tscn` | `iron_frontier.tres` | 稳定巡逻主路，商人与改造支线必出 |
| `RustFoundry.tscn` | `rust_foundry.tres` | 战斗与陷阱交替，改造与库存支线必出 |
| `SporeDepths.tscn` | `spore_depths.tres` | 搜刮网络密集，召唤与伏击生态 |
| `AbyssArchive.tscn` | `abyss_archive.tres` | 精英连战，终局构筑机会有限 |

每张场景都是轻量 `ThemedLevelEntry`，拥有自己的主题资源引用，并在启动时实例化共享 `Main.tscn` 战局运行壳。这样既可独立打开、运行和测试，又不会复制四套相同运行节点。独立场景仍可继续添加专属节点与控制器。

## MapThemeProfile 契约

主题资源位于 `data/map_themes/`，负责配置：

- `layout_rules`：主路径长度、路径节奏、分支率、上下层概率、垂直房间权重。
- `path_room_weights`：主题主路允许出现的房间类型及权重。
- `branch_room_weights`：主题支线房间类型及权重。
- `required_branch_types`：必须出现的设计节点，避免纯随机破坏关卡意图。
- `enemy_rules`：怪物池、主题前缀、属性倍率、Boss 名称。
- `content_rules`：容器奖励倾向与事件池。
- `npc_rules`：NPC 身份、职责、出现房间、概率、位置和文本。

主题资源本身不承载战斗代码。它只描述规则，使策划调整不需要修改生成器。

## 生成管线

1. 独立关卡场景把 `MapThemeProfile` 交给 `RoomGameMode`。
2. `RoomGameMode` 调用 `MapManager.generate_themed_map()`。
3. `MapGenerator` 按主题路径序列与权重生成房间图，并补齐必出房间。
4. `ContentInjector` 注入主题事件、奖励条件和 NPC 计划。
5. `MonsterInjector` 按主题生态生成敌人，并保留固定种子复现能力。
6. `RoomFactory` 实例化房间、容器、商人、工作台和主题 NPC。

## 随机设计原则

- 主路径有节奏序列，例如“战斗 → 陷阱 → 战斗 → 精英”，只允许少量变奏。
- 关键功能房通过 `required_branch_types` 保底，而不是依赖概率碰运气。
- 普通怪、伏击、守卫、精英和随从都必须服从主题生态池；Boss 使用主题名称和属性倍率。
- NPC 是主题内容计划的一部分，不是全局无差别生成。
- 固定种子必须复现布局和敌人计划，便于测试、分享和调平衡。
- 独立关卡场景可以继续添加只属于该地图的专属 Boss、环境控制器或剧情节点。

## 后续扩展

框架下一阶段应优先增加：

1. 主题专属房间预制件集合与环境机关。
2. 主题色资源直接驱动 TileSet，而不是暂时复用楼层色板。
3. NPC 对话、任务和阵营数据。
4. 关卡解锁、入口门视觉和基地空间叙事。
5. 对每个主题进行多种子统计，校验房间比例、战斗时长和收益曲线。
