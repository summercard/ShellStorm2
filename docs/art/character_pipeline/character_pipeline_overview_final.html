NPC 六个格子全空 不是「还没做」

assets/art/ 下无 npc 目录；角色账本 36 行无一条 npc_*； ThemedNPC3D.gd 用 CapsuleMesh 等程序网格现搭；2026-09-17《3D资产正式制成链路总表》列了 15 类资产，NPC 一行都没有—— 它从没进过链路。另有一处悬挂产物：scenes/ThemedNPC.tscn 指向不存在的 res://src/game/ThemedNPC.gd，全库无引用。

怪物不是「没登记」 是登记得很诚实

敌人账本 12 条的「骨架/动作库」列全部写着「无 Blender 动作母版（程序驱动）」。 EnemyAvatar3D.gd 只做 bob 起伏、scale 压扁、自转与 emission 脉冲——它把 ai_state 存下来却从不采样动作。 缺的不是资产，是接口。

03

命名与存放路径规范

路径与命名是账本的派生：先有 AssetID 与逻辑名，才有目录，才有文件名，才有运行时引用。方向不可逆。

FORM A
规范三段式
新增资产默认形态 · NPC 与怪物一律用它
<域根>/<slug>/
├─ source/     <slug>_source_v001.blend
├─ components/ <slug>_visual_top3d.glb
└─ runtime/    <slug>_root_top3d.tscn

版本号只出现在 source/
components 与 runtime 路径恒定
样板：enemies/elite_3d/rift_boar_armed/
FORM B
角色 production 版本形态
玩家专用 · D3 已冻结
characters/player/…_3d/variants/<变体>/
└─ production/v021/
   ├─ source/model/     _model_v021.blend
   ├─ source/animation/ _animation_v021.blend
   ├─ exports/          _<部件>_v021.glb
   ├─ runtime/          _root_v021.tscn
   └─ character_transfer_ledger_v021.json
NPC 与怪物不得套用此形态
FORM C
共享套件 + 变体
怪物族 · 父子关系写在账本
enemies/<族根>/
├─ enm_ecosystem_kit_3d/   父
│   ENM-ECOSYSTEM-KIT-3D
└─ <怪 slug>/              子
    变体父ID → 指向套件

不为子怪建 variants/ 子目录
（那是玩家形态 B 的写法）
父子关系由《资产主表》「变体父ID」表达

AssetID 格式 版本升级不变

<域前缀>-<子类码>-<逻辑名大写>-<形态后缀>
例：CHR-NPC-VENDOR01 · ENM-ELITE-RIFT-BOAR-ARMED-3D · 骨架 SKEL-NPC01-001

逻辑名 slug 目录名 = slug

小写 snake_case，<域缩写>_<子域>_<逻辑名>
例：chr_npc_vendor01 · enm_melee_fungboar01。目录名不含版本号（新增资产硬性）

版本号只有 4 个落点 白名单

① source/** 文件名与目录　② asset_manifest.json　③ 账本「版本」列　④ Prefab 根节点 metadata/asset_version
GLB 去版本后，这 4 处是唯一溯源入口，缺一即视为丢失溯源。

D3 冻结 存量不追改，只禁新增

2026-09-17 起，存量带版本名视为正式命名，不再追改；门禁只保证「不新增」。 characters/player(144) · enemies(16) · weapons(130) 三处冻结。 新增必须合规，存量照原样引用——两者并存是正确的。

04

跨域硬约束

六段全程有效。前两条决定这条链路能不能活过两个月。

源改动即过期 生命周期

重新编辑任一源文件，原导出立即视为过期；状态回退，validated 结论作废。 没有这条，「重新整理链路」过两个月就会烂掉。

状态不可跳级 状态机

design_only → authored → exported_pending_godot_validation → validated → active。 每一级都有对应段的产物；跳级即失去可追溯性。

状态机是消费者 箭头方向

状态机输出状态与进度，表现层只选择、采样动作。把状态机打包进 Prefab， Prefab 就退化成「一个角色配一个专属状态机」——复用与换装立刻崩。

三套状态集不通用 不可套用

玩家 8 态 + 4 变体 · 怪物 12 态 · NPC 2 态。状态 ID 逐字取自代码， 美术侧不得另起名字。16.1 已写死「各自建立骨架 ID、动作表和适配器」。

账本是路径真源 账本先行

未登记的资产不得落盘。文档、skill、脚本不得各自维护一份路径表， 一律经 ledger_registry.py 解析；禁止硬编码账本文件名。

替换只有覆盖 路径契约

运行资产路径恒定，替换=覆盖同名文件。不派生 _v002.tscn、不新建版本目录、不并存旧版； .import 与 .uid 留原位。回滚靠 git，工作区不留 .bak_*。

禁止裸 GLB 直载 P0 违规

运行时只能引用 runtime/ 的 PackedScene。当前 3 只 Boss 由 BossContentCatalog.gd 的 presentation_scene 直指 .glb 裸文件，需改造。

GLB 只负责表现 职责边界

碰撞、脚本、交互、门逻辑、状态机不写进 GLB。包装层持挂点与元数据； 碰撞归属必须明确登记（Prefab自身 / 外部脚本 / 混合 / 无）。
