# PH17 独立训练靶场

**状态：已完成**

**日期：2026-07-11**

**实体陈列扩展：2026-07-16**

## 为什么本轮先做靶场

大地图已建立了末日基地的第一视觉承诺，但当前缺少一个能安全、可重复地验证所有枪弹组合的玩家场所。训练靶场是后续打磨枪械手感、怪物反应、角色状态和 HUD 的基础设施，也是本项目从“功能可用”走向“可调试的成品”的关键一步。

## 玩家体验

- 基地新增可步行进入的“地下训练靶场”设施，进入后切换到独立房间。
- 进场时玩家是空装状态；射击和枪械外观都不会伪装出默认武器。
- 右侧装配终端列出 `BlueprintRegistry` 当前注册的全部枪身与弹药，不受基地蓝图等级限制。
- 点选枪身和弹药后可手动“装配测试组合”；开启“自动组合”开关后，任一选择变更都立即重建临时武器。
- 房间提供标准、装甲和移动三类靶标，即时显示扣除防护后伤害、命中数、投射物命中率和会话 DPS。
- 可随时清空武器、重置测试数据或退回基地。

## 隔离契约

1. 靶场只操作场景内 `Player` 持有的临时 `WeaponAssemblyTree`。
2. 进入、装配、清空和退出全流程不调用 `BaseManager` 的蓝图解锁、背包、保险库、待出击装备或存档写入接口。
3. 退出前先销毁临时装配树，再返回 `BaseWorld`；基地新建的玩家仍由正常局外系统接管。
4. 靶标只是测试接收器：不死亡、不掉落、不记录击杀、不产生货币或局外成长。

## 表现方向

- 空间是基地下方的破败工业射击廊：冷青应急灯提供基础轮廓，每条靶道只保留一盏低亮导航灯，最远端使用弱红警示色。
- 地面裂缝、磨损轨道、危险斑驳和射击损伤由程序化矢量绘制，日后可独立替换成 TileMap 或正式美术资产。
- UI 使用与战斗 HUD 一致的深蓝黑面板、钢青边框、琥珀交互色和短时间缓动；选中、装配、命中、重置均有可见反馈。

## 验收标准

1. `BaseWorld` 可数出第八个基地设施，训练靶场指向可加载的独立场景。
2. 靶场启动后玩家可移动但武器根节点为空，弹药显示为 `0 / 0`。
3. 选择器数量与 `BlueprintRegistry.get_available_gunbodies(99)` / `get_available_bullets(99)` 严格一致。
4. 任意注册枪身和弹药均能装配成正确根节点与子弹槽，切换枪身后角色枪械轮廓立即刷新。
5. 实际子弹可命中三类靶标，装甲靶的结算伤害低于原始伤害，移动靶会周期位移，重置会话清零全部数据。
6. 从进入前到退出请求，`BaseData._to_dict()` 深度快照保持一致。
7. 专项验证、主场景启动和全量回归均不出现 `ERROR` / `SCRIPT ERROR` / `Parse Error`。

## 本轮暂不做

- 配件与命运卡的自由沙盒将在基础枪弹矩阵稳定后再加入，避免一次引入过多变量。
- 本轮不用训练靶标代替正式怪物 AI 和受击调试；它们的表现垂直切片会在下一循环单独验收。

## 实施结果

- 基地新增第八个设施“地下训练靶场”，使用 `LOAD_SCENE` 进入独立 `TrainingRange.tscn`。
- 靶场进场后主动清空场景玩家的临时武器树；`WeaponAssemblyTree.clear_assembly()` 现在同步重置弹药、射速与投射物数，并派发空装变更信号。
- `WeaponDisplay` 已改为每次武器树变更都立即切换枪身轮廓；清空时隐藏枪身和命运挂件，不再残留旧外观。
- 装配终端动态读取 7 种枪身和 8 种弹药，支持手动装配、自动组合开关、清空、会话重置和消毒离场。
- 新增标准、装甲与往复移动靶标；命中反馈包含数值飘字、短时高亮、防护后伤害、投射物命中率与会话 DPS。
- 场景使用程序化破损射击廊、分道线、弹痕、消毒门、导航标识和 5 盏低能稀疏灯；右侧固定终端在 1280×720 下不遮挡出口与近距靶标。

## 验证证据

- `verify_training_range_flow.tscn` 通过：空装进入、56 组枪弹矩阵、三类靶标、减伤、移动、统计、重置、局外快照不变和退出清理全部成立。
- `verify_base_world_flow.tscn` 通过：基地共 8 个功能设施，靶场场景路径可加载；场景节点数 191/220。
- Godot 4.6.2 全工程类扫描、主场景 300 帧启动和 22 个场景回归全部无 `ERROR` / `SCRIPT ERROR` / `Parse Error`。
- 重载长期打开的 Godot 编辑器后，新全局类注册正常；实机检查空装、选中、装配、稀疏灯光和侧栏信息层级均可读。

## 2026-07-16 实体陈列与可扩展交互升级

### 设计判断

原版本已经能在终端里覆盖全部枪弹矩阵，但“所有枪械整齐排列”只存在于按钮列表中，玩家缺少进入真实武器实验室、沿货架挑选装备的空间体验。本次升级保留终端的精确操作，同时把枪械与弹药都变成场景内可行走、可交互的实体陈列。

### 玩家体验变化

- 靶场扩建为西侧装备区与东侧实弹射击道；枪械陈列架、弹药实验墙和靶道具有明确分区。
- 所有 `BlueprintRegistry` 枪身按 Tier、名称稳定排序后自动排成四列货架；每个陈列位使用实际枪身轮廓。
- 所有弹药模块自动生成独立弹药箱，爆炸、穿甲、黑洞、追踪、黏性等类型具有不同识别色。
- 靠近陈列位会出现 `[E]` 取用提示；取枪时自动沿用当前弹药，取弹时自动沿用当前枪身，若另一侧为空则补入目录首项，保证一次交互即可开火。
- 右侧组合终端继续支持任意精确组合，并可用 `Tab` 收起，为远距离射击释放完整视野。

### 扩展契约

1. 陈列内容只读取 `BlueprintRegistry` 公开目录，不维护第二份枪械或弹药清单。
2. 新注册的枪身或弹药会自动获得终端按钮和实体陈列位；四列布局按数量继续向下扩展。
3. 枪身陈列复用 `WeaponDisplay.GUN_SHAPES`，未知枪型自动使用默认轮廓，不阻断测试流程。
4. 实体货架只负责选择，实际装配仍统一经过 `assemble_combination()`，隔离、统计与离场清理契约不分叉。

### 新增验收

- 实体枪架数与注册枪身数一致，弹药墙数与注册弹药数一致，所有 ID 唯一且陈列位不重叠。
- 从实体枪架取枪会形成可射击组合；随后从弹药墙取弹只替换弹药且装配正确。
- 终端、实体货架和玩家武器外观保持同一选中状态。

### 验证结果

- `verify_training_range_flow.tscn` 通过：15 个实体陈列位均有玩家交互区，实体取枪/换弹和 56 组枪弹矩阵全部正确。
- 23/23 个 `verify_*.tscn` 场景回归通过，基地入口、战斗闭环、Boss、撤离、UI 与运行时安全无回归。
- 主场景持续 300 帧无 `ERROR` / `SCRIPT ERROR` / `Parse Error`。
- 1280×720 实机帧检查确认 7 把枪和 8 种弹药在出生画面中完整可读，终端与陈列区层级清晰。
