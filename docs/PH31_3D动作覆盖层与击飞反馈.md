# PH31 · 3D 动作覆盖层与击飞反馈

## 目标

补齐 3D 玩家在六态状态机之上的射击、蓄力、蓄力释放与受击击飞表现。它们必须使用已经运行的 `WeaponModel3D` 和 `Player3D` 数据，不能另建展示状态机、独立武器计时器或重复角色资产。

## 状态契约

- 顶层状态仍严格为 `idle / moving / dashing / hurt / locked / dead`；`firing / charging / knockback` 是可验证的动作覆盖层。
- `firing` 仅由 `WeaponModel3D.shot_fired` 信号开启，按短促的压缩、前探和回弹表现后坐；不因 UI 按钮伪造状态。
- `charging` 读取同一把 `WeaponModel3D` 的 `charge_active / charge_ratio`。禁用玩家输入只停止输入采样，不能取消由预览场、脚本或 AI 发起的真实蓄力。
- `knockback` 记录命中方向、强度和时长，向 `hurt` 状态注入递减 XZ 冲量并延长受击回收；模型同步做后仰、位移、压缩和弹性回正。
- 唯一的 `Hand` 与 `WeaponSocket` 始终叠加完全相同的换弹、射击、蓄力、击飞局部变换；枪的朝向继续只由 `VisualRoot` 的瞄准 Y 轴旋转决定。

## 预览与验收

- `Player3DStateGallery` 新增“射击 / 开始蓄力 / 释放蓄力 / 受击击飞”四个按钮，分别驱动真实枪械事件与 `Player3D.apply_knockback()`。
- 换枪会清除枪械剩余冷却、后坐与蓄力，避免新枪继承旧枪的不可射击窗口。
- `verify_player3d_state_gallery_flow.tscn` 覆盖六态数量不膨胀、真实射击事件、蓄力启动与释放、击飞进入 `hurt`、阿凡达覆盖层，以及手/枪挂点相对向量不变。
- `verify_player3d_state_gallery_visual.tscn` 用真实蓄力层渲染预览；Apple M1 OpenGL 1280×720 画面见 `outputs/019f8417-e7f4-7bc3-aded-c62dfd1d1462/PH30_3D角色与遭遇预览场.png`。

## 资产影响

没有新增美术根、贴图或模型。全部动作由 `CHR-PLY-CAPSULE01-3D` 已登记的角色组件与既有枪械模型程序组合完成；资产台账只扩展状态/验收字段，后续若新增逐帧或 VFX，必须先登记新的 `AssetID`、模块归属和复用关系。
