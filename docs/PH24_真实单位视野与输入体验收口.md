# PH24｜真实单位视野与输入体验收口

## 为什么现在优先处理

上一阶段把敌人显隐射线与 `SpotLight3D` 绑定在同一个节点中，视觉上像手电筒，但玩家无法确认“单位实际看得到哪里”；同时 3D 背包缺少可靠的 `ui_inventory / I` 真实输入闭环，根 Control 也没有铺满视口，导致真实试玩中功能不可发现、甚至可能显示在屏幕外。测试覆盖了数据模块，却没有覆盖真实输入事件、视野网格和暂停恢复。

## 玩家可感知的规则

1. 玩家单位拥有独立于场景灯光的真实视野：前方 96°、最远 21m，身边 2.4m 为近身感知区。
2. 墙、关闭的门和实体家具会截断视野；场景灯只能改变明暗，不能让逻辑上不可见的单位透视出现。
3. 地面显示与射线判定使用同一批采样结果：半透明区域就是当前可见范围，边缘自然虚化、没有硬描边，并始终绘制在地板之上。
4. 敌人、钥匙、地面掉落、危险区和服务装置按同一视野服务控制可见性；房间墙体仍保留空间阅读，不以黑屏代替探索。
5. `I` 是背包主快捷键，`Tab` 作为 3D 行动区兼容快捷键；打开背包后移动、冲刺、射击和交互均被锁定。
6. `Esc` 优先关闭当前背包/商店/工作台；没有模态界面时才打开暂停层。暂停层必须可见并能再次按 Esc 恢复。

## 技术边界

- `PlayerVision3D` 是唯一玩法判定源；不读取 `SpotLight3D`、房间灯开关或材质亮度。真实照明由独立的 `PlayerFlashlight3D` 负责，避免视野规则和灯光参数互相污染。
- 视野填充与边界使用两个可复用的 `ImmediateMesh`，固定频率批量刷新，不在每个目标上重建网格或材质。
- 遮挡射线只查询物理层 1；目标单位不参与遮挡，避免命中目标自身被误判为墙。
- 背包公开 `set_inventory_panel_open`、`toggle_inventory_panel`、`is_inventory_open` 和显隐信号；关卡统一计算输入锁，避免一个界面关闭时错误解锁另一个界面。
- 暂停输入由 `PROCESS_MODE_ALWAYS` 的独立 HUD 控件负责，避免整个关卡继承 Always 后仍在暂停中运行。
- 地下城、基地、靶场复用 `UI-SCREEN-PAUSE-3D`；基地设施菜单与地下城背包/商店/工作台都实现 Esc 模态优先关闭。
- 合成音效按声音配置缓存 `AudioStreamWAV`，射击、命中、受伤、冲刺、换弹和撤离不再在每次播放时重新生成波形。

## 验收标准

- 实际 `InputEventAction(ui_inventory)`、物理 I 键和 Tab 都能打开/关闭背包。
- 背包打开时玩家处于 `locked`，关闭后仅在没有其他模态状态时恢复。
- 玩家照明独立为 1 盏投影聚光灯和 1 盏无阴影近身补光；快照明确报告 `presentation_light_count=2`、`spotlight_count=1`、`spill_light_count=1`、`shadow_light_count=1` 与 `gameplay_light_dependent=false`。
- 正前方无遮挡点可见，角度外点不可见，墙后点不可见；近身区与前锥网格均存在且被墙截断。
- 实际渲染截图能看到自然虚化、无硬描边且不会沉入地板的视野区域。
- Esc 暂停、显示暂停层、再次 Esc 恢复；商店/背包关闭不会误触暂停。
- 新专项、核心等价、完整流程、性能预算与运行安全回归全部通过。

## 2026-07-22 验收结果

- `verify_3d_vision_input_flow.tscn`：真实 I、`ui_inventory`、Tab、Esc 关闭背包优先、可见暂停/恢复、柔边射线视野、表现探照灯与强灯独立性通过。
- `verify_base_world_flow.tscn` / `verify_training_range_3d_flow.tscn`：两张外围地图复用暂停资产，实际按键提示与 Shift 冲刺契约一致。

- 2D 原体验回归覆盖地图、命运门、灯光、怪物生态、Boss、撤离、背包 UI、玩家状态机、靶场和视野，未因 3D 收口被破坏。
