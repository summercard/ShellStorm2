# Phase 13：固定大世界与独立副本架构

> 2026-07-21 更新：正式入口已迁移到 `scenes/BaseWorld3D.tscn`，但本阶段定义的“固定基地 + 连续荒野 + 独立副本 + 原入口返回”生命周期保持不变。原 `BaseWorld.tscn` 作为 2D 基线保留；3D 迁移细节见 `PH21_3D入口地图与模块角色迁移.md`。

## 设计决定

游戏入口由纯 UI 大厅改为可自由行走、可交互、可在 Godot 编辑器中直接编辑的固定大世界。基地与野外道路属于同一张连续地图：

```text
BaseWorld.tscn
  -> 基地设施
  -> 连续野外道路
  -> 道路旁的 DungeonEntrance 建筑门
  -> 独立战局 PackedScene
  -> 撤离或死亡后返回进入时的建筑门外
```

这里的“开放世界”定义为固定基地和固定野外组成的连续可探索大地图。副本不会常驻在大世界中，只有玩家走到对应建筑门口并交互后才独立加载。

## 当前场景边界

| 场景 | 职责 | 生命周期 |
|---|---|---|
| `scenes/BaseWorld.tscn` | 固定基地、连续野外道路、副本入口建筑、长期数据总览 | 游戏启动及每局结束后加载 |
| `scenes/BaseFacility.tscn` | 可复用设施交互体，配置菜单或目标地图 | 随基地场景加载 |
| `scenes/DungeonEntrance.tscn` | 可复用野外副本入口建筑，配置入口 ID、门后场景和返回点 | 随大世界场景加载 |
| `scenes/BaseMenu.tscn` | 基地管理终端兼容界面，处理升级与战利品 | 玩家与管理终端交互时临时加载 |
| `scenes/levels/*.tscn` | 各主题独立战局场景，引用自己的主题生成资源 | 玩家进入对应任务后加载 |
| `scenes/Main.tscn` | 无主题兼容与开发验证场景 | 仅供旧测试和通用验证 |

四个野外建筑入口分别指向四个独立场景。每个场景引用自己的 `MapThemeProfile.tres`，由主题资源规定路径节奏、房间权重、怪物生态、事件与 NPC。`LevelSelectMenu` 仅保留为旧兼容界面，不属于正式玩家流程。

## 基地设施

第一版基地提供七个可交互设施，覆盖原大厅已有功能：

1. 远征情报室：说明野外路线与副本情报，不直接加载副本。
2. 枪械工坊：蓝图解锁。
3. 命运占卜屋：局前命运卡准备。
4. 保险柜：撤离物资与下局带入。
5. 怪物档案室：精英怪与悬赏记录。
6. 命运卡牌收藏室：卡牌图鉴。
7. 基地管理终端：建筑升级、战利品处理与原大厅兼容功能。

所有设施都是 `BaseFacility.tscn` 实例，可在 `BaseWorld.tscn` 中移动、复制、删除和修改导出配置。

## 引擎负担判断

当前方案不会造成明显 Godot 引擎负担：

- 基地仅包含静态多边形、边界碰撞、七个轻量 Area2D 设施、一个玩家和 HUD。
- 基地不会实例化 `MapManager`、战斗房间、敌人、子弹或 Boss。
- 固定野外只包含道路、区域底色和四个轻量入口建筑，不模拟副本内容。
- 进入任务使用 `change_scene_to_file()`，基地 SceneTree 会在战局加载前释放。
- 自动验证限制当前固定大世界不超过 220 个节点。

禁止把所有战斗地图作为隐藏子节点挂在基地中。这会让房间、敌人、碰撞和资源同时常驻，才是实际的性能风险。

只有当基地扩展到大量动态 NPC、数千节点、大型 TileMap 或多个持续模拟区域时，才需要增加分区流式加载。当前阶段保持单个可编辑 `BaseWorld.tscn` 更简单可靠。

## 地图扩展规则

新增地图时优先遵守以下契约：

1. 每张特殊地图使用独立根场景，或使用共享战局外壳加独立配置。
2. 地图只在玩家通过基地入口后加载，不与基地同时模拟。
3. 撤离、死亡和主动返回统一切换到 `BaseWorld.tscn`。
4. 地图内房间可以继续由 `MapManager` 动态生成；手工地图也可以直接编辑为 `.tscn`。
5. 地图选择、解锁状态和场景路径由野外入口配置持有，不在大世界脚本中硬编码战斗逻辑。
6. 正式流程不允许从基地菜单直接选择副本；必须到达野外建筑入口。
7. 副本返回时恢复到原入口门外，并立即重置相机位置，避免从基地跨地图平滑滑动。
