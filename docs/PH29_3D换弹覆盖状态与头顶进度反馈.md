# PH29 · 3D 换弹覆盖状态与头顶进度反馈

## 目标体验

玩家按下换弹或弹匣打空后，角色应立即出现清晰但不打断移动的换弹动作；角色头顶显示与真实装填时间一致的进度条。玩家可以一眼判断“正在换弹、还要多久”，而枪械逻辑、动画和 UI 不各自维护计时器。

## 状态机规则

- 保留玩家六个互斥顶层状态：`idle / moving / dashing / hurt / locked / dead`。
- 新增 `reloading` 覆盖状态，与 `low_health / silenced / invincible` 同层；它可与 `idle`、`moving`、`dashing` 和短暂 `hurt` 并存，不增加第七个顶层状态。
- `WeaponModel3D` 是换弹生命周期的唯一计时源，发布开始、连续进度和结束/取消信号；`Player3D.get_state_machine_snapshot()` 只投影该事实，不复制倒计时。
- 换枪、清空武器或即时补满弹药时，正在进行的换弹必须显式取消并清除动画/进度条；正常倒计时结束时才补满弹匣。
- 换弹期间不能射击，但移动、瞄准、受击与冲刺仍沿用当前玩法规则。

## 动画规则

- 继续只显示一只悬浮握持手；不增加手臂或第二只手。
- `hand` 与 `weapon_socket` 在换弹覆盖层中使用完全相同的局部位移与旋转，使手、枪始终作为一个握持单元运动。
- 动作分为下压拆卸、短促操作、回位锁定三个阶段，并叠加在现有 idle/moving/dashing/hurt 动态之上。
- 枪械模型可在挂点动作上增加轻微局部俯仰/侧滚，但不可脱离握持手，也不可改变瞄准根 `VisualRoot` 的 Y 轴朝向。
- 动画进度直接使用 `1 - reload_remaining / reload_duration`，不同枪身的装填时间自然改变动作速度。

## 头顶进度条规则

- 进度条作为 `CHR-PLY-CAPSULE01-3D` 根资产内的可复用状态 UI 子组件，不建立新的角色或整屏 UI AssetID。
- 节点位于 `VisualRoot` 外，随玩家位移但不随瞄准方向旋转；使用相机 billboard、无光照材质和固定世界尺寸。
- 只在 `reloading` 为真且角色存活时显示；左端固定、填充从左到右推进，结束或取消后立即隐藏。
- 进度条不参与碰撞、视野、灯光揭示或输入，只消费玩家状态快照。

## 性能与复用边界

- 不创建 SubViewport、逐帧纹理、粒子或 Tween；每帧只更新现有节点的变换、可见性和一项 X 缩放。
- 复用现有 `CHR-PLY-CAPSULE01-3D`、`WPN-GUN-KIT-3D` 和玩家状态机身份；台账只更新组件/状态契约与既有资产记录。
- 所有七种枪身与八种弹药共用同一换弹生命周期和表现，不为 56 种组合复制动画。

## 验收标准

1. 非满弹匣请求换弹后，`reloading` 覆盖状态立即为真，顶层状态仍可从 idle 进入 moving。
2. 进度从 0 单调推进到 1，剩余时间单调下降；正常完成后弹匣补满，覆盖状态和进度条同时清除。
3. 换弹中换枪/补满弹药会取消旧换弹，不能延迟覆盖新弹匣或残留进度条。
4. 换弹中手与枪械挂点的相对向量保持不变；动画中至少出现可测的位移和旋转，结束后回到基准位。
5. 头顶条在换弹中可见、填充宽度与真实进度一致，结束后隐藏；节点不位于 `VisualRoot` 下且不随瞄准旋转。
6. 六态白名单、56 组枪弹组合、背包装备、命运换弹效果、基地/靶场/副本玩家复用和性能预算全部回归通过。

## 实施与验收结果

- `WeaponModel3D` 已成为唯一装填计时源，新增开始、连续进度、正常完成/取消生命周期；换枪、补弹、清空或死亡会取消旧装填，不会延迟覆盖新弹匣。
- `Player3D` 状态快照新增 `reloading` 覆盖层和真实 reload 快照；六个顶层状态及白名单未改变。
- 胶囊角色的一只握持手与 `weapon_socket` 已接入同相下压、操作、回位动作，枪模只有小幅局部俯仰/侧滚；移动状态可继续运行。
- `ReloadProgress3D` 已作为现有角色根内的 billboard 双 QuadMesh 子组件接入，固定左端并直接读取装填进度，结束/取消后隐藏。
- `verify_3d_reload_state_flow.tscn` 覆盖移动并存、射击锁定、真实计时、握持向量、UI 填充、正常完成、补弹取消和换枪取消。
- 基地、命运换弹、实际背包装备、钥匙/战斗进程、敌人、视野、玩法等价、四主题完整流程、独立靶场和性能预算回归通过；完整流程峰值 689 节点，性能专项持续段约 6.91ms。
