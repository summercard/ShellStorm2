# PH26｜真实探照灯、枪械装备与 3D 背包投影

## 玩家问题

当前柔边视野已经能准确表达玩法可见范围，但照明仍有三个直接阻断体验的问题：探照灯源点过低且缺少角色补光，前方材质受光很弱；背包格子的真实点击信号参数失配，导致拾取后的枪械看似无法装备；背包使用文字缩写代替道具形体，无法建立“地面物品—背包物品—装备模型”的视觉对应。

## 本轮契约

1. 玩法视野与真实光照继续解耦。`PlayerVision3D` 只做射线视野，独立的 `PlayerFlashlight3D` 负责真实光源。
2. 探照灯由一盏可投影 `SpotLight3D` 和一盏不投影的近身 `OmniLight3D` 组成：前者照亮前方地面、墙和家具，后者模拟灯具溢光，让角色与手持枪在暗室中可读。
3. 光照参数必须可在独立场景 Inspector 中控制，包括颜色、能量、范围、锥角、衰减、安装高度与近身补光；灯光不能改变敌人和掉落的玩法显隐。
4. 暗室保留压迫感，但环境基线、雾反射和曝光不得把未照亮区域压成纯黑；房间中央顶灯开启后必须明显高于暗室基线。
5. 地面枪械进入背包后，左键真实点击必须调用装备链；装备成功后枪械树、角色枪模、弹药 HUD 与背包“已装备”标记同时更新。
6. 背包与保险格不再使用 `GUN / BUL / HP` 文字替代图标。所有物品使用同一个 `ItemModelFactory3D` 构建世界模型，再由低成本、只渲染一次的 3D 图标视口投射到格子中。

## 性能边界

- 玩家光源只创建一次；只有聚光灯投影，近身补光不投影。
- 每个图标视口尺寸为 96×96，配置完成后使用 `UPDATE_ONCE`，不持续刷新或旋转。
- 枪械图标直接复用 `WeaponModel3D` 的显示模式；其他物品复用世界拾取模型工厂，不维护第二套图标网格。

## 验收标准

- 探照灯实际节点为 `SpotLight3D + OmniLight3D`，方向与玩家准星一致，能量、范围和锥角可配置。
- 暗室截图中角色、手持枪和前方场景均有真实材质受光；墙和家具产生可读阴影。
- 中央顶灯关闭时仍可导航，开启后房间主体清晰可见且不曝光。
- 实际 `ItemSlot.slot_clicked` 信号可装备拾取到的霰弹枪；枪模、枪械树和弹药状态同步。
- 背包至少验证枪械、子弹、治疗物、钥匙和信标五类 3D 投影，空格无残留视口。
- 视野遮挡、56 枪弹组合、原 2D 背包/状态机与性能预算回归继续通过。

## 2026-07-22 实施与验收结果

- 新增独立 `PlayerFlashlight3D` 场景：主灯为能量 15.5、范围 25m、66° 的真实投影聚光灯，近身补光能量 2.15、范围 4.8m；全部颜色、能量、范围、角度、衰减和安装点均为导出参数，并提供运行时重应用入口。
- 暗室环境基线调整为 0.16–0.22，曝光 1.18；房间中央顶灯按房间尺度扩大范围，开启后能量下限与覆盖范围进入自动验收。
- 修复 `ItemSlot.slot_clicked` 参数重复绑定；实测拾取霰弹枪后，真实槽位左键可同步装配树、角色枪模和旧枪回包。
- 新增共享 `ItemModelFactory3D` 与 96×96 单次渲染投影；枪械、弹丸、治疗物、钥匙、信标均在 56px 槽位中使用同一个世界模型来源，并扩大镜头占比以保证轮廓可读。
- `verify_3d_vision_input_flow.tscn`、`verify_3d_inventory_weapon_flow.tscn`、`verify_full_3d_game_flow.tscn`、`verify_3d_parity_core.tscn`、`verify_3d_performance_budget.tscn` 与 `verify_inventory_equipment_ui.tscn` 全部通过。
- GPU 实机预览通过：暗室主灯照亮角色/枪/前方实体并产生阴影；中央顶灯开启前后层级明确；背包五类 3D 投影可辨识。
