## 强制生产门禁

1. **需求归一化**：写明逻辑 ID、用途、复用范围、视角、状态和关键词/别名。
2. **四重查重**：核对 AssetID、台账查重键、文件名和 SHA-256；发现同义或同哈希时先复用、合并或建立变体父子关系。
3. **分类与领取 ID**：只从台账“分类与编码”选择大类；找不到分类时先扩展码表，不能临时随意建目录。
4. **组件化制作**：角色、枪械、场景套件和 UI 都按可替换边界拆分，禁止把可复用部件烘焙进整图。
5. **游戏内验收**：检查最近邻像素、透明边缘、比例、挂点、翻转和状态矩阵，不能只看生成母版。
6. **回填台账**：填写路径、尺寸、状态、版本、哈希、日期、来源/许可和备注后才算完成。

## 命名规则

- AssetID：大写、连字符分段且创建后稳定，例如 `CHR-PLY-CAPSULE01-HAND-R-SIDE`。
- 文件名：小写 snake_case，末尾保留三位版本，例如 `chr_player_capsule01_hand_r_side_v001.png`。
- 文件名正则：`^[a-z0-9]+(?:_[a-z0-9]+)*_v[0-9]{3}\.(png|webp|svg|wav|ogg)$`。
- 禁止中文文件名、空格、`final_final`、`new`、`copy` 等不稳定后缀。
- 新版本只递增 `_v002`；不要因为换色、受伤态或 UI 派生图重新发明根名称。

## 角色组件契约

角色表现层与碰撞、移动、武器逻辑解耦。标准槽位为：

| 槽位 | 责任 | 是否可独立动画/替换 |
|---|---|---|
| `body` | 主轮廓、防护服或躯干 | 是 |
| `head` | 头壳、传感器、表情 | 是 |
| `hand` / `hand_r` | 单手角色随身体朝向镜像的握持位；双手角色的主手槽 | 是 |
| `hand_l` | 仅在角色设计明确需要第二只手时启用 | 是 |
| `scarf` / `accessory_*` | 身份识别和换装 | 是 |
| `weapon_socket` | 逻辑挂枪点，无纹理 | 是 |

当前首个角色 `player_capsule01` 的硬约束：抽象非人胶囊防护体、侧面朝右并支持水平翻转、无腿、无脚、无手臂、单传感器而非五官、只显示一只较大的握持手、红围巾独立。握持手随身体左右朝向在局部 `x=±19` 镜像换边，枪械挂点同步使用 `x=±24`；手不得随准星连续旋转或绕角色移动，只有枪械视觉跟随完整准星角度。接近正上/正下瞄准时沿用上一次左右朝向，避免换边抖动。

## 状态机与美术状态

顶层六态互斥：`idle / moving / dashing / hurt / locked / dead`；`low_health / silenced / invincible` 是叠加层。Dead 是终态，不允许返回存活态。首版优先用组件位移、旋转、压缩、翻转和程序 VFX 表达状态；只有代码变换无法清晰表达时才新增逐帧图，并先在台账“动画与状态”登记。

状态机逻辑位于 `src/core/StateMachine.gd`，玩家白名单位于 `src/player/Player.gd`；资产挂载位于 `src/player/PlayerAvatarRenderer.gd`。美术替换不得改动碰撞体、移速、伤害和输入契约。
