## 强制生产门禁

1. **需求归一化**：写明逻辑 ID、用途、复用范围、视角、状态和关键词/别名。
2. **四重查重**：核对 AssetID、台账查重键、文件名和 SHA-256；发现同义或同哈希时先复用、合并或建立变体父子关系。
3. **分类与领取 ID**：只从台账“分类与编码”选择大类；找不到分类时先扩展码表，不能临时随意建目录。
4. **组件化制作**：角色、枪械、场景套件和 UI 都按可替换边界拆分，禁止把可复用部件烘焙进整图。
5. **游戏内验收**：检查最近邻像素、透明边缘、比例、挂点、翻转、状态机、玩法逻辑与性能，不能只看生成母版。
6. **回填台账**：填写路径、尺寸、状态、版本、哈希、日期、来源/许可和备注后才算完成。

## 命名规则

- AssetID：大写、连字符分段且创建后稳定，例如 `CHR-PLY-CAPSULE01-HAND-R-SIDE`。
- 文件名：小写 snake_case，末尾保留三位版本，例如 `chr_player_capsule01_hand_r_side_v001.png`。
- 文件名正则：`^[a-z0-9]+(?:_[a-z0-9]+)*_v[0-9]{3}\.(png|webp|svg|wav|ogg)$`。
- 禁止中文文件名、空格、`final_final`、`new`、`copy` 等不稳定后缀。
- 新版本只递增 `_v002`；不要因为换色、受伤态或 UI 派生图重新发明根名称。

## 角色组件契约

角色表现层与碰撞、移动、武器逻辑解耦。标准槽位为：

| 槽位 | 责任 | 是否可独立动画/替换 |
|---|---|---|
| `body` | 主轮廓、防护服或躯干 | 是 |
| `head` | 头壳、传感器、表情 | 是 |
| `hand` / `hand_r` | 单手角色随身体朝向镜像的握持位；双手角色的主手槽 | 是 |
| `hand_l` | 仅在角色设计明确需要第二只手时启用 | 是 |
| `scarf` / `accessory_*` | 身份识别和换装 | 是 |
| `weapon_socket` | 逻辑挂枪点，无纹理 | 是 |

当前首个角色 `player_capsule01` 的硬约束：抽象非人胶囊防护体、侧面朝右并支持水平翻转、无腿、无脚、无手臂、单传感器而非五官、只显示一只较大的握持手、红围巾独立。握持手随身体左右朝向在局部 `x=±19` 镜像换边，枪械挂点同步使用 `x=±24`；手不得随准星连续旋转或绕角色移动，只有枪械视觉跟随完整准星角度。接近正上/正下瞄准时沿用上一次左右朝向，避免换边抖动。

## 状态机与美术状态

顶层六态互斥：`idle / moving / dashing / hurt / locked / dead`；`low_health / silenced / invincible / reloading` 是叠加层。Dead 是终态，不允许返回存活态。`reloading` 不得成为第七个互斥态：它读取武器唯一换弹计时，可与移动和短暂受击并存；3D 握持手与 `weapon_socket` 使用完全相同的下压、操作、回位变换，角色头顶 billboard 进度条位于瞄准 `VisualRoot` 外并随完成、换枪、补弹、清空或死亡清除。首版优先用组件位移、旋转、压缩、翻转和程序 VFX 表达状态；只有代码变换无法清晰表达时才新增逐帧图，并先在台账“动画与状态”登记。

状态机逻辑位于 `src/core/StateMachine.gd`，玩家白名单位于 `src/player/Player.gd`；资产挂载位于 `src/player/PlayerAvatarRenderer.gd`。美术替换不得改动碰撞体、移速、伤害和输入契约。

## 3D 视野、灯光与 HUD 契约

- `PlayerVision3D` 是唯一单位可见性真值：角色周围 360°、最远 21m，只由墙、关闭门和实体家具的物理遮挡隐藏目标；目标在角色身后不是隐藏理由。
- 灯具、雾、曝光和材质只表达废土氛围；玩家使用独立三层 `PlayerFlashlight3D`：环境 layer 1 上是一盏跟随准星并投影的主 `SpotLight3D` 和一盏不投影的近身 `OmniLight3D`，角色/手持枪 layer 2 上只有一盏从正面照入的微弱无阴影 `SpotLight3D`。环境溢光不得从头顶照亮角色，且任何灯光或画面亮度都不得作为玩法判定。
- 当前 96°/21m 柔边扇形与 2.4m 近身圈仅表达主要目光和探照灯方向，固定频率采样且不得扩成 360°地面网格；它必须无硬描边、不会沉入地板。敌人、钥匙、掉落、危险区、服务装置和撤离信标均读取独立的 360°遮挡显隐规则。
- 室内房间默认无中央照明，只允许一盏正中央顶灯与一个墙面开关；禁止在室内复制路灯杆、悬臂或假地面光池。
- 怪物模型替换必须同时校准同源轮廓碰撞；弹丸本地 `-Z` 为飞行前向、`+Z` 为尾迹方向。
- 背包主键为 `I`，3D 行动区兼容 Tab；HUD 必须教会快捷键。背包打开时必须锁住移动、冲刺、射击和交互。
- 3D 换弹头顶条必须直接读取 `WeaponModel3D` 的 0→1 进度，固定左端、相机 billboard、无独立计时器或 SubViewport；它只表达状态，不参与视野、灯光和输入判定。
- 地面拾取和背包图标必须复用 `ItemModelFactory3D` 的同一模型来源；背包以固定 96×96 的 `SubViewport` 单次投射到槽位，不为每种物品维护第二套静态图标或持续旋转视口。枪械验收必须经过真实 `ItemSlot.slot_clicked` 信号，不允许只直调装备函数。
- 地面物品与房间钥匙逻辑接受后统一播放 0.25–0.40 秒上弹、旋转、缩小动画，先关闭碰撞再回收；满包拒绝时不得播放成功动画。非出生/撤离房清理后只生成一把钥匙，位置在玩家附近并限制在房间安全边界，返回已清房间时必须能补发遗漏奖励。
- `UI-SCREEN-PAUSE-3D` 在地下城、基地与靶场共用；Esc 先关闭最上层模态界面，再进入真正暂停。
