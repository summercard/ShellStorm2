# 资产规划与模块解耦规范

> 弹壳风暴2 开发基础文档 v1.0
> 最后更新：2026-05-22

---

## 核心理念

每个功能模块独立管理，包含 **代码(.gd)** + **场景(.tscn)** + **文档** 三部分。
表现层和逻辑层分离，美术资源可替换系统图标，不影响功能。

## 模块规范

### 1. 每个模块必须包含

| 组成部分 | 说明 |
|---|---|
| **核心脚本** | 纯逻辑，不含场景引用 |
| **场景文件** | 使用占位图形（ColorRect/CircleShape2D等）|
| **信号定义** | 模块间通信必须通过 signal |
| **文档注释** | 每个方法和类必须注释 |

### 2. 模块依赖规则

```
core (Global, GameManager) ← 所有人都依赖
     ↑
player ← 依赖 core
     ↑
weapon ← 依赖 core, player
     ↑
bullet ← 依赖 core, enemy（碰撞）
     ↑
enemy ← 依赖 core, player（追击）
```

### 3. 表现层占位规则

| 资源类型 | 占位方案 |
|---|---|
| 玩家角色 | ColorRect 蓝色方块 |
| 敌人 | ColorRect 红色方块 |
| 子弹 | ColorRect 黄色矩形 |
| 瞄准线 | Line2D 黄色线 |
| 图标 | Godot 内置 ThemeIcon 或空白 Label |
| UI 背景 | StyleBoxFlat 单色面板 |
| 血条 | ProgressBar 带填充色 |

### 4. 美术资源替换流程

1. 在 `assets/sprites/` 放置图片
2. 在对应 `.tscn` 中替换 `ColorRect` → `Sprite2D`
3. 在脚本中确保 `@export var texture: Texture2D` 可配置
4. 不修改任何逻辑代码

### 5. 信号通信规范

模块间通信必须通过 `signal`，禁止直接 `get_node()` 跨模块访问。

```gdscript
# 正确：发射信号
enemy_died.emit()

# 错误：直接调用
# other_node.take_damage()  # 禁止跨模块直接调用
```

### 6. 预制体规范

每个可复用实体必须有独立 `.tscn` 文件，包含：
- 碰撞体（CollisionShape2D）
- 可见图形（占位或正式美术）
- 挂载脚本
- 必要的子节点

## 开发检查清单

每个 PR 或提交必须满足：

- [ ] 新功能有对应的 `.tscn` 预制体
- [ ] 场景中有可见的占位图形
- [ ] 模块间通信使用 signal
- [ ] 每个脚本有文档注释
- [ ] `godot --headless --quit` 无错误
- [ ] 美术资源使用外部可替换方案（`@export` 或独立节点）
