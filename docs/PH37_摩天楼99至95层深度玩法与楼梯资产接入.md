# PH37｜摩天楼99—95层深度玩法与楼梯资产接入

> PH37 在 PH36 可运行框架上修正楼梯与首层门禁，再把98—95层从固定十字样板升级为可复现的楼层探索。原有 `Dungeon3D` 战斗、钥匙、命运、掉落、背包、Boss 和撤离仍是唯一玩法实现。
>
> PH38 已将本文件中的摄像机射线剖切、12%/22%楼板切换规则替换为8米层内垂直镜头与纯物理遮挡；楼梯、门禁和关卡规则继续有效。

## 一、本轮玩家价值

目前最优先的问题不是增加更多楼层，而是让第一次“从楼顶进入大楼”完整可信：

- 楼梯必须是用户在 Blender v006 中调整过的真实模型，而不是 Godot 重新拼出的相似盒体。
- 固定交通门不能把玩家锁在楼顶或基地。
- 进入98层后才开始命运与清房节奏。
- 每个战斗层要有可辨别的空间变化，不能四层都只是同一十字图旋转。

验收以玩家能够从楼顶无钥匙抵达98层、看到正确楼梯、进入第一战斗房并获得一次命运选择为第一道硬门槛。

## 二、Blender楼梯资产契约

| AssetID | Blender根节点 | 用途 |
|---|---|---|
| `ENV-TOWER-STAIRWELL-ROOFTOP-9M` | `Stair_Special_Rooftop_ROOT` | 楼顶→99层；保留用户手调特殊墙高 |
| `ENV-TOWER-STAIRWELL-GENERIC-9M` | `Stair_Generic_Rotatable_ROOT` | 99层以下通用；允许按90°旋转 |

两份 GLB 都以“上层门轴”为局部原点，局部 `+X` 朝65m核心外侧，上层标高为0m，下层为-9m。Godot只为它们补充不可见碰撞、连续高度吸附、摄像机剖切和楼层流送，不再绘制第二套程序踏步、平台或墙。

Blender v006 测得的共用中心线：

1. 上层门轴与核心边界；
2. 上层梯跑中心距外侧边界11.501m；
3. 梯跑从3.1203m开始，长度15m；
4. 折角平台中心位于21.0071m；
5. 两跑中心距8m；
6. 下层门厅回到同一核心边界；
7. 楼板洞口按楼梯实际约15×27m占地扩展，不得再沿错误短轴开洞。

## 三、前三段门禁与命运规则

| 边 | 清房要求 | 钥匙 | 命运卡 | 设计原因 |
|---|---|---|---|---|
| 楼顶→99层基地 | 无 | 不消耗 | 不触发 | 固定交通，不得软锁开局 |
| 99层基地→98层入口 | 无 | 不消耗 | 不触发 | 基地到战局的固定交通 |
| 98层入口→98层枢纽 | 入口房已确认安全 | 不消耗 | 触发一次 | 进入正式探索时确定本层构筑方向 |
| 其他未开启房间边 | 当前房肃清 | 消耗一把 | 触发一次 | 维持原清房—钥匙—命运循环 |

实体门在免费状态下仍必须阻挡角色、子弹和逻辑视野；只有交互开启后才释放通行。返回路线永久免费且不重复触发命运。

## 四、98—95层种子化布局

每层固定包含入口、战斗枢纽、两个内容房、出口和一个电梯房，但从以下可通行模板中按楼层种子选择：

- **十字枢纽**：短主路、双支路，适合98层教学。
- **北侧回形**：主路径沿北侧绕行，出口藏在回形末端。
- **南侧回形**：北侧模板镜像，改变镜头和窗光方向。
- **折线推进**：主路两次转折，电梯成为中段隐藏支路。

约束：

- 上行入口与下行出口仍固定在65m核心相对两侧的中心门轴，保证通用楼梯旋转复用。
- 所有相邻房间只通过5m正交走廊连接，禁止对角走廊穿墙。
- 同种子必须得到相同模板、房型和怪物配置；不同种子至少改变一个楼层模板和支路内容分配。
- 电梯房始终存在，但只有亲自进入并点亮终端后才进入99层按钮列表。
- 未访问的出口房和未开启边不在小地图上提前暴露完整路线。

楼层内容曲线：

- 98层：普通战斗、搜刮、储藏，承担规则建立。
- 97层：事件与多波普通战斗，提高路线选择。
- 96层：精英、搜刮与陷阱混合。
- 95层：精英/陷阱支路，出口为Boss与阶段撤离。

## 五、显示、灯光与性能

- 楼顶保留日光、城市远景、女儿墙下完整楼体外立面。
- 99层以下使用密闭曝光；只有靠外房间按种子获得窗光。
- 摄像机只剖切真实遮挡角色的当前房间墙、楼梯墙或斜坡表面；碰撞和逻辑视野不随视觉隐藏。
- 房间内仅运行当前房和已开启相邻房；楼梯中仅运行相邻两层外壳与当前楼梯。
- 物理楼层流送窗口始终不超过当前层上下各两层，共最多5层。
- 楼板承重与渲染分离，任何隐藏动作都不能让角色、掉落或冻结实体坠落。

## 六、PH37验收

1. 两份楼梯 GLB 来自 Blender v006 对应根节点，Godot场景中不再存在程序踏步视觉。
2. 楼梯洞口、中心线、上下门轴和9m标高一致；楼顶→99层可真实下行并回爬。
3. 楼顶门和基地→98层门不耗钥匙、不触发命运且能够正常开启。
4. 98层入口门不耗钥匙，但必须出现且只能出现一次命运选择。
5. 98—95层各有六个房间和固定电梯房；同种子复现、不同种子产生拓扑变化。
6. 每个探索层均能完成进入、清怪、钥匙、开门、搜刮、点亮电梯和继续下行。
7. 95层Boss、Boss解锁撤离及返回流程保持可用。
8. 上下楼梯时不泄露非相邻层室内，不被上一层楼板闪现遮挡。
9. UI显示真实楼层、HP、目标和已点亮电梯层。
10. 塔楼专项、3D核心等价、命运、视野、背包、Boss、运行安全与性能预算全部通过。

## 七、实施结果

- Blender v006 的两套楼梯已分别导出为
  `env_tower_stairwell_rooftop_9m_top3d_v001.glb` 与
  `env_tower_stairwell_generic_9m_top3d_v001.glb`。Godot 每段连接只实例化一份
  Blender 楼梯视觉；程序层只保留不可见碰撞和连续高度路径，没有第二套踏步。
- 楼梯路径改为 Blender 实测的11节点中心线，整层洞口扩为对应的15×27m方向格；
  角色已经真实完成楼顶→99层下行和99层→楼顶回爬，不再在门厅、折角或高低接缝卡住。
- `RoomDoor3D` 现在明确区分清房、钥匙和命运三个策略。楼顶→99层与99层→98层
  均免费无命运；98层入口门免费并触发一次命运；之后才进入原钥匙门循环。
- 98—95层由四类模板按种子选择，每层六个互不重叠的15m房间，中心落在20m网格，
  因而房间之间严格保留5m正交走廊。相同种子拓扑/房型一致，不同种子至少改变一层。
- 当前层房间、门、怪物、灯和交互按“当前房+已开启邻房”运行；物理楼层以当前层为
  中心加载，上下合计最多5层。所有6层承重碰撞常驻，视觉隐藏不会让遗留物坠落。
- 楼梯中段仅显示相邻两层外墙与落脚面；上层楼板在下降22%前后完成剖切，
  下层楼板从12%进度提前接入。房间墙和楼梯墙只在真实阻挡摄像机—角色射线时隐藏，
  碰撞、门遮挡和逻辑视野始终保留。
