# PH25｜3D 暗室照明与战斗生态收口

## 目标

本轮不是继续做 3D 表面替换，而是修正真实试玩中暴露出的视野、照明、枪弹和怪物行为缺口。原 2D 玩法仍是规则真值；3D 只负责把同一规则变成稳定、可读且有空间感的表现。

## 视野与照明双层契约

1. `PlayerVision3D` 仍是唯一玩法可见性判定源：96° 前锥、21m 距离、2.4m 近身感知和墙体遮挡均不读取任何灯光状态。
2. 地面视野只作为判定反馈：取消硬描边，边缘使用透明羽化；遮挡缩短时立即收回、空间打开时平滑舒展，转向连续更新，避免固定频率重建造成抖动。
3. 视野反馈必须稳定绘制在地面上方，不能被房间地板覆盖；墙、门和大型家具仍负责截断形状。
4. 玩家使用与视野方向一致、但节点独立的真实灯光组件：一盏投影 `SpotLight3D` 负责前方材质受光和阴影，一盏不投影 `OmniLight3D` 负责角色/手持枪近身补光；开关、能量和阴影永远不能改变敌人或掉落的玩法显隐。
5. 房间进入时中央顶灯默认关闭。每个房间只保留一组中央顶灯与一个墙面开关，移除室内路灯杆和伪造地面光池；靠近开关按 `E` 可切换真实房间灯。

## 枪弹与起始补给契约

1. 7 种枪身、8 种弹药和装配配件继续由 `BlueprintRegistry + WeaponAssemblyTree` 单一数据源驱动，不建立 3D 专用玩法数值表。
2. 起始房提供一把明确可见、可拾取的异枪补给；默认手枪之外至少可取得霰弹枪。背包满时物品必须留在地面。
3. 装备新枪必须保留当前弹药/配件规则，换下枪身与被替换模块必须原子回包，空间不足时整次操作拒绝。
4. 子弹视觉的前向轴必须与实际 `direction` 一致；普通、反弹、追踪和敌方弹在每次方向改变后同步旋转，尾迹位于飞行反方向。

## 怪物生态契约

1. 六类基础怪和 Boss 都使用各自模型占地生成碰撞体；受击范围、物理挤占和模型最大横向轮廓保持同源，精英/Boss 缩放同时作用于模型与碰撞。
2. 近战追击、远程侧移弹幕、召唤支援、护盾正面格挡、爆炸怪近身蓄爆、伏击怪潜伏破土必须是实际可观察的不同战斗行为，不能只靠颜色和数值区分。
3. 九态 AI 契约保留：`idle / patrol / alert / chase / search / telegraph / attack / stagger / dead`。类型特性在这些状态内扩展，不复制生命、掉落和死亡管线。
4. 所有怪物继续读取 `MonsterInjector` 的主题池、楼层缩放、精英词缀和原掉落表；3D 不维护第二份掉落配置。

## 性能边界

- 视野射线和目标显隐固定频率更新，视觉朝向逐帧平滑；不为每帧创建网格、材质或灯光。
- 玩家探照灯组件只创建一次，且仅主聚光灯投影；房间只保留一个局部灯，远房流送时关闭渲染、碰撞与光源。
- 投射物继续复用对象池，方向同步不触发网格重建。
- 怪物类型碰撞参数为静态 Profile，状态切换只更新必要的形状和表现，不每帧复制 Shape。

## 验收标准

- 连续绕鼠标瞄准时视野不跳步、无硬描边，墙边不漏视，地板不会盖住视野反馈。
- 房间默认暗；玩家探照灯产生真实受光与阴影；中央顶灯可由墙面开关切换，室内不存在路灯杆。
- 起始异枪可实际拾取、入包、装备并射击；56 个枪弹基础组合仍全部成立。
- 子弹的模型前向、尾迹和位移方向一致，反弹与追踪后也即时一致。
- 六类基础怪均能生成、碰撞体与模型匹配，且至少一种核心行为可由自动化测试和实机画面共同确认。
- 原钥匙、门、背包、掉落、撤离、命运、随机房和性能预算回归保持通过。
