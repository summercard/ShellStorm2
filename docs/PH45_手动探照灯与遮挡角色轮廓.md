# PH45｜手动探照灯与遮挡角色轮廓

> 镜头运动更新：PH46 在本方案上增加了仅响应画面下方墙体的 Y 轴平滑抬升。
> 墙体不隐藏、角色轮廓和手动探照灯规则继续有效；镜头基准高度仍为 8 米。

## 一、问题

### 1. 探照灯

PH44 仍会根据楼顶、室内房间和楼梯围护体自动开关探照灯。这个逻辑会让照明状态
随着房间信号或楼梯判定变化，玩家无法决定何时照明，也不利于后续手电电量、潜行
和灯光风险玩法。

### 2. 固定摄像机遮挡

PH44 从镜头向角色发射射线，并把命中的整段墙体渲染隐藏。虽然碰撞仍保留，但它
会造成墙突然消失、相邻房间泄露、墙段跳变和楼梯围护缺口；这不是合格的建筑透视
表达，应当删除。

## 二、探照灯规则

- 新增 `toggle_flashlight` 输入动作，桌面默认快捷键为 `F`。
- 探照灯进入战局时默认关闭，只能由玩家手动切换。
- 进入室内、楼梯、基地或楼顶时均不得自动改变当前开关状态。
- 打开背包、独占交互或角色输入锁定时，不响应探照灯快捷键。
- 探照灯只影响真实照明表现，360° 玩法视野仍只取决于距离和实体遮挡。
- HUD 必须明确显示 `F 探照灯开关`。

## 三、遮挡表达方案评估

| 方案 | 结论 | 原因 |
|---|---|---|
| 摄像机碰撞收镜/绕墙 | 不采用 | 会移动固定视角，楼梯和家具附近容易抖动 |
| 隐藏整段墙体 | 删除 | 建筑结构突然消失，并泄露相邻空间 |
| 整墙透明或淡出 | 暂不采用 | 多层透明排序、阴影、MultiMesh 和门模块状态难以稳定统一 |
| 墙上圆形洞口/裁切 Shader | 后续可选 | 需要所有墙材质统一支持裁切参数，当前导入模块和批渲染改造成本高 |
| 遮挡角色轮廓 | 本阶段采用 | 墙体、阴影、碰撞和房间完整保留，只在角色确实被遮挡时显示角色轮廓 |

## 四、遮挡角色轮廓规则

1. 摄像机继续固定在角色相对 `(0,8,5.5)`，FOV 55°，不碰撞、不旋转、不位移。
2. 从摄像机向角色身体轮廓发出少量射线；至少两条射线被实体遮挡时，判定角色被
   建筑或大型物件遮挡。
3. 遮挡期间给角色与手持武器叠加半透明青色无深度轮廓材质；墙、门、楼板和楼梯
   仍完整渲染。
4. 轮廓只用于玩家自身，不显示怪物、掉落、家具或隔壁房间内容。
5. 遮挡解除后立即移除轮廓材质，并恢复各网格原有的叠加材质。
6. 射线只读取物理世界，不修改任何碰撞层、门状态、逻辑视野或流送状态。

## 五、验收

1. `F` 可以连续切换探照灯开/关，初始状态为关闭。
2. 进入楼梯和不同楼层不会改变玩家选择的灯光状态。
3. HUD 显示探照灯快捷键；玩法视野在灯关闭时仍保持 360° 距离与物理遮挡规则。
4. 镜头前放置 9 米墙后，墙体视觉与碰撞均保持启用。
5. 角色被墙遮挡时出现轮廓；移除墙后轮廓立即消失。
6. 不再有任何摄像机逻辑把墙、门或楼梯围护网格设为不可见。
7. 塔楼、视野输入、完整 3D 战局、垂直物理和性能专项全部通过。

## 六、实现与验收结果

- `project.godot` 已登记 `toggle_flashlight`，默认物理键为 `F`；探照灯默认关闭。
- 楼顶、基地、战斗房和楼梯间切换均不再调用自动开关。专项验证确认：玩家打开
  探照灯后往返楼顶与基地，状态保持不变。
- HUD 控制提示和视野提示均已加入 `F` 手动开关说明；背包或独占交互锁定角色
  输入时，灯光快捷键不响应。
- PH44 的墙体查找、相邻墙段扩展、设为不可见和恢复显示代码已全部删除。
- 固定镜头遮挡测试确认：9 米测试墙视觉保持显示、碰撞保持启用、隐藏墙体计数
  恒为 0；四条身体射线中至少两条受阻时，角色与武器显示青色穿墙轮廓。
- 遮挡墙移除后，角色原始叠加材质立即恢复；摄像机仍固定为 `(0,8,5.5)`、
  FOV 55°。
- 塔楼、360° 视野与输入、完整 3D 战局、垂直物理、运行安全和性能专项全部
  通过。塔楼完整探索节点数 2783；性能专项记录生成 368.3ms、最重房间
  61.6ms、探索节点 2950、持续段 6.90ms，均在现有预算内。
